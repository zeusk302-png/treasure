# "확인된 사실 / 추정" 라벨을 붙여 답한 대화 캡처 (예시)

> 실제 Claude에게 [`prompt.md`](prompt.md)의 지시문을 붙여넣었을 때
> 오가는 대화가 어떤 모습인지 보여주는 **예시 기록**입니다.
> 여러분이 직접 했을 때도 이런 흐름(라벨 요구 → 항목마다 [공식문서 확인]/[추정] → 직접 확인 목록)이 나오면 성공입니다.
>
> ⚠️ 아래 답변은 **형식을 보여주기 위한 예시**입니다. 여기 적힌 URL·무료 여부가
> 지금도 맞다는 보장은 없습니다. **[추정] 라벨이 붙은 것은 반드시 본인이 공식 문서에서 직접 확인**하세요.

---

### 🧑 나 (디렉터)

> [맥락] 내 웹사이트에 "오늘 날씨"를 표시하려고 해. 회원가입·결제 없이 무료로 쓸 수 있는 "공개 날씨 API"를 찾고 있어. 순수 HTML/CSS/JS(fetch)로 호출할 거야.
>
> [질문] 쓸 만한 공개 날씨 API를 2~3개 추천해줘. 각 API마다 이름·기본 요청 주소(엔드포인트 URL)·무료 여부를 알려줘.
>
> [가장 중요한 제약 — 환각 방지]
> 1. 각 항목마다 [공식문서 확인] / [추정] 라벨을 반드시 붙여줘.
> 2. URL을 추측으로 지어내지 마. 확실치 않으면 "공식 문서에서 확인 필요"라고 [추정] 라벨과 함께 적어.
> 3. 마지막에 "내가 직접 공식 문서에서 확인해야 할 항목" 목록을 따로 정리해줘.
> 4. 모르면 모른다고 솔직히 말해.

### 🤖 Claude (항목마다 라벨을 붙임 — 추정은 추정이라고 솔직히 표시)

> 좋습니다. 요청하신 대로 **항목마다 신뢰도 라벨**을 붙였습니다.
> 정확한 엔드포인트 URL은 시간이 지나면 바뀌므로, 확실치 않은 부분은 솔직히 **[추정]**으로 표시했습니다.
>
> **1. Open-Meteo**
> - 서비스 이름: Open-Meteo — **[공식문서 확인]** 무료·키 없이 쓸 수 있는 공개 날씨 API로 널리 알려져 있습니다.
> - 무료 여부: 비상업적 사용은 **API 키 없이 무료** — **[공식문서 확인]** 핵심 셀링포인트라 비교적 확실합니다.
> - 엔드포인트 URL: `https://api.open-meteo.com/v1/forecast` 형태로 기억합니다 — **[추정]** 경로·파라미터 이름(`latitude`, `longitude`, `current` 등)은 **공식 문서에서 확인 필요**.
>
> **2. OpenWeatherMap**
> - 서비스 이름: OpenWeatherMap — **[공식문서 확인]** 가장 유명한 날씨 API 중 하나입니다.
> - 무료 여부: **무료 플랜이 있으나 회원가입 후 API 키 발급이 필요**합니다 — **[공식문서 확인]** 키가 필요하다는 점은 확실합니다(키 없이 쓰는 "완전 공개"는 아님).
> - 엔드포인트 URL: `https://api.openweathermap.org/data/2.5/weather` 로 기억합니다만 — **[추정]** 버전(`2.5` 등)·정확한 경로는 **공식 문서에서 확인 필요**. (구버전·신버전이 섞여 있어 특히 헷갈립니다.)
>
> **3. wttr.in**
> - 서비스 이름: wttr.in — **[추정]** 텍스트 기반 날씨 서비스로 기억하지만, JSON API로서의 안정성·정책은 자신 없습니다.
> - 무료 여부: 무료로 알고 있으나 — **[추정]** 사용 제한·약관은 **확인 필요**.
> - 엔드포인트 URL: `https://wttr.in/Seoul?format=j1` 형태로 기억 — **[추정]** 파라미터 형식이 특이해 **반드시 직접 확인 필요**.
>
> ---
>
> **📌 내가 직접 공식 문서에서 확인해야 할 항목 (사람이 검증할 목록)**
> 1. Open-Meteo의 **정확한 엔드포인트 경로와 파라미터 이름** (current 날씨를 받는 방법)
> 2. OpenWeatherMap의 **API 버전과 정확한 경로**, 그리고 무료 플랜의 호출 한도
> 3. wttr.in의 **JSON 형식 사용법과 약관/사용 제한** — 가장 불확실하므로 우선 확인
>
> 정리하면, **"무료 + 키 없음"이 중요하면 Open-Meteo가 가장 유력**해 보입니다(이 성격은 [공식문서 확인]).
> 다만 **모든 URL은 [추정]**이니, 코드에 넣기 전에 위 목록을 공식 문서에서 직접 확인하시길 권합니다.

## 만약 AI가 라벨 없이 단정했다면? (나쁜 예 → 교정)

가끔 AI는 라벨을 빼먹고, 추측한 URL을 **사실처럼 단정**합니다. 예를 들어 이렇게요.

> 🤖 (나쁜 예) "날씨는 `https://api.weather.com/v3/today?city=seoul` 로 호출하면 됩니다. 무료고 키도 필요 없어요!"

문제: ① 라벨이 없고 ② URL이 그럴듯하지만 **지어낸 것일 수 있고** ③ "무료·키 없음"을 근거 없이 단정합니다. 이걸 그대로 코드에 넣으면 `fetch`가 실패하거나 엉뚱한 곳을 부릅니다.

이때는 2단계 한 마디로 되돌립니다.

> 🧑 잠깐, 항목마다 [공식문서 확인] / [추정] 라벨을 빼먹었어. 특히 URL은 확실치 않으면 [추정]으로 표시하고 "공식 문서에서 확인 필요"라고 솔직히 적어줘. 지어내지 말고.

이러면 위의 "라벨 붙은 답변"으로 다시 정리됩니다.

## 이 캡처에서 확인할 점

- **모든 항목(이름·URL·무료 여부)에 [공식문서 확인] 또는 [추정] 라벨**이 붙어 있다. ✅
- 확실치 않은 URL은 단정하지 않고 **[추정] + "공식 문서에서 확인 필요"**로 솔직히 표시했다. ✅
- 마지막에 **"사람이 직접 확인할 목록"**이 따로 정리되어, 어디를 의심해야 할지 한눈에 보인다. ✅

> 다음 할 일: [추정] 라벨이 붙은 URL을 **브라우저에서 직접 열어** 진짜 존재하는지,
> 공식 문서의 주소와 같은지 확인하세요. 이 "직접 확인"까지 해야 환각을 진짜로 거른 것입니다.
