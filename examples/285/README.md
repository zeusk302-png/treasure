# 실습 285 — == 때문에 어긋난 조건문 고치기 ('0개'가 비어있다고 안 뜨는 화면)

> **디버깅 챌린지 (난이도 3)** · 분류: 디버깅 챌린지 · 개념: ==/=== 비교, 타입 강제변환

이 폴더에는 **일부러 고장 낸 파일**(`broken.html`)과 **고친 정답 파일**(`index.html`),
그리고 함정을 표로 직접 확인하는 **작은 JS 데모**(`compare.js`)가 들어 있습니다.
먼저 `broken.html`을 열어 무엇이 이상한지 직접 찾아보고, 그다음 `index.html`과 비교하세요.

> **한 줄 메모(원인):** 화면에서 읽은 상품 수는 숫자 `0`이 아니라 **글자 `"0"`** 입니다. 그런데 코드가 느슨한 비교 `==`와 `if(count)` 진위 판정에 기대다 보니, **0개일 때도 "담겨 있어요"** 로 잘못 흘러가고 **빈 값(`""`)과 0개가 한데 섞여** 버렸습니다. → 빈 값은 `===` 로 먼저 거르고, 숫자로 **명시적으로 변환(`Number()`)** 한 뒤 `count === 0` 으로 비교하면 해결됩니다.

## 목표
- 화면·입력칸·API 에서 들어오는 값은 보기에 숫자여도 **대부분 "문자열"** 이라는 사실을 이해한다.
- 느슨한 비교 `==` 가 비교 전에 **타입을 멋대로 바꿔(강제변환)** `"" == 0` 같은 함정을 만든다는 것을 눈으로 확인한다.
- 빈 글자 `""` 는 거짓이지만 **글자 `"0"` 은 "참"** 이라는, 비전공자가 가장 많이 걸려 넘어지는 지점을 체감한다.
- 해결 공식 **"빈 값은 `===` 로 먼저 거르고 → 다룰 타입으로 변환 → `===` 로 비교"** 를 손에 익힌다.

### 비유로 이해하기
`==` 는 "대충 비슷하면 같다고 쳐줘" 라고 말하는 **눈치 빠른(그래서 실수하는) 판정관**입니다.
숫자 `0` 과 빈 글자 `""` 를 보고 "둘 다 비어 있네, 같은 거야!" 라고 멋대로 합쳐버립니다.
반면 `===` 는 "**값도 같고 종류(타입)도 같아야** 같다고 인정한다" 는 **꼼꼼한 판정관**입니다.
그리고 글자 `"0"` 은 "0" 이라고 적힌 **빈 봉투가 아니라 내용물이 든 봉투** 라서, `if(봉투)` 로 물으면 "있다(참)" 고 답합니다. 그래서 0개인데도 "담겨 있어요" 로 새는 것입니다.

## 따라하는 단계
1. `broken.html`을 **더블클릭**해서 브라우저로 엽니다.
2. 첫 화면(상품 0개)을 봅니다. → "비어 있어요" 가 떠야 하는데 **"0개의 상품이 담겨 있어요."** 라고 잘못 뜹니다.
3. `+` 버튼으로 1, 2개로 올렸다가 다시 `−` 로 0개로 내려도, 0개에서 여전히 **"담겨 있어요"** 라고 나오는 것을 확인합니다.
4. 원인을 표로 직접 보고 싶으면 터미널에서 `node compare.js` 를 실행합니다. (또는 F12 콘솔에 `compare.js` 내용을 붙여넣기)
   - `"0"` 입력에 대해 **나쁨(==)** 칸은 `담겨있음`, **좋음(===)** 칸은 `비었음` 으로 갈리는 것을 봅니다.
   - 맨 아래 `"" == 0 → true`, `Boolean("0") → true` 두 줄이 함정의 핵심입니다.
5. `broken.html`을 메모장이나 VS Code로 열어 맨 아래 `<script>` 의 `render()` 함수를 봅니다. 두 가지 버그가 있습니다.
   ```js
   if (count == "") {            // BUG: == 는 "" 와 0 을 같다고 봄
     ... "비어 있어요" ...
   } else if (count) {           // BUG: 글자 "0" 은 '참'이라 여기로 잘못 들어옴
     ... count + "개 담겨 있어요" ...
   }
   ```
6. 아래 **고치는 공식 3단계** 로 바꿉니다.
   ```js
   const raw = qtyEl.textContent.trim();   // 읽은 값은 문자열

   if (raw === "") {                       // ① 빈 값은 ===(엄격)로 먼저 거른다
     ... "값이 없어요" ...
     return;
   }
   const count = Number(raw);              // ② 다룰 타입(숫자)으로 명시적 변환
   if (count === 0) {                      // ③ 숫자끼리 ===(엄격) 비교
     ... "비어 있어요" ...
   } else {
     ... count + "개 담겨 있어요" ...
   }
   ```
7. 저장하고 브라우저에서 **새로고침(F5)** → 0개일 때 **"비어 있어요"**, 1개 이상일 때 **"N개의 상품이 담겨 있어요"** 로 정확히 갈리면 성공입니다.
8. 정답이 궁금하면 같은 폴더의 `index.html`을 열어 내 수정과 비교합니다.
9. AI에게 검토 시켜 보기:
   > "이 JS에서 == 로 비교하다가 문자열 '0' 이나 빈 문자열이 숫자 0 과 헷갈리는 곳이 있는지 찾아줘. === 와 명시적 타입 변환으로 안전하게 고쳐줘."

## 검증법
- 새로고침 후 첫 화면(0개)에서 **"비어 있어요"** 가 뜨는가? ("담겨 있어요" 가 뜨면 아직 안 고쳐진 것)
- 상품을 1개 이상 담으면 **"N개의 상품이 담겨 있어요"**, 다시 0개로 내리면 **"비어 있어요"** 로 정확히 바뀌는가?
- `node compare.js` 결과에서 입력 `"0"` 과 `"  0 "` 가 모두 **`비었음`** 으로 잡히는가?
- 코드에 비교 연산자가 **`===` (또는 `!==`)** 만 남고, 숫자로 다룰 값은 `Number()` 로 **명시적으로 변환** 한 뒤 비교하는가?
- (개념 확인) `"" == 0` 은 `true`, `"" === 0` 은 `false` 인 이유를 설명할 수 있는가?
