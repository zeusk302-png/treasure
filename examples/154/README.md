# 실습 154 — 내 위치(Geolocation)로 현재 지역 날씨 자동 표시하기

페이지를 열면 브라우저가 **"위치를 알려줘도 될까요?"**라고 물어봅니다.
**허용**하면, 지금 있는 곳의 **좌표(위도·경도)**를 받아 그 좌표로 **무료 공개 날씨 API**를 불러
**현재 날씨**(기온·날씨 상태·아이콘)를 한 장짜리 위젯으로 보여 주는 페이지입니다.
**API 키(열쇠) 없이** 누구나 쓸 수 있는 공개 날씨 API(Open-Meteo)를 사용합니다.

> 비유: 날씨 안내소(날씨 API)는 **'좌표(위도·경도)'로만 날씨를 알려줍니다.**
> 그런데 실습 153에서는 "부산이 어디?"를 글자로 물어 좌표를 얻었다면(=도시 이름 입력),
> 이번 154에서는 **내 폰/노트북이 직접 "나 지금 여기 있어"라고 좌표를 알려줍니다**(=위치 권한).
> 단, 위치는 민감한 정보라서 **브라우저가 사용자에게 직접 "허용/거부"를 물어봅니다.**
> 그래서 이번 실습의 한 줄 핵심은 **"위치 권한을 요청하고, 허용/거부를 친절히 처리한 뒤, 받은 좌표로 날씨를 부르는 두 단계 연결"** 입니다.

## 목표
- **Geolocation API**가 무엇인지 체감한다. (`navigator.geolocation.getCurrentPosition`으로 내 좌표를 받는다)
- **권한 요청·거부 처리**를 익힌다. 사용자가 위치를 **허용**하면 좌표를, **거부**하면 에러를 받는다. 코드는 거부/시간초과/미지원을 각각 **친절한 안내 문구**로 바꿔야 한다.
  - `error.code` 의미: `1`=권한 거부, `2`=위치 못 얻음, `3`=시간 초과.
- 두 단계로 이어지는 **호출 연쇄**를 익힌다: ① 브라우저 위치 권한 → 좌표 → ② 좌표 → 날씨.
- 콜백 방식의 옛 API(`getCurrentPosition`)를 **Promise로 감싸** `async/await`로 깔끔하게 쓰는 패턴을 익힌다.
- API가 준 **숫자 코드(WMO 코드)**를 미리 만든 표(`WEATHER_CODE`)로 **한국어 설명 + 이모지**로 바꾸는 패턴을 익힌다. (153과 동일)

> 실습 153과의 차이: 153은 **사용자가 '도시 이름'을 입력**해 지오코딩으로 좌표를 얻는 것이 시작점이었습니다.
> 154는 **사용자 입력 없이 '브라우저 위치 권한'**으로 좌표를 직접 얻는 것이 시작점입니다.
> 그래서 새로 배우는 핵심은 **"위치 권한을 물어보고 허용/거부를 처리하는 법"** 입니다.

## 따라하는 단계
1. 이 폴더의 `index.html`을 더블클릭 → 브라우저에서 열린다. (인터넷 연결 필요)
2. 페이지가 열리면 브라우저가 **"이 사이트에서 사용자의 위치에 접근하려고 합니다"** 같은 팝업을 띄운다 → **[허용]**을 누른다.
3. 잠시 후 **검은 칸 ①**에 `위도 ..., 경도 ...`로 내 좌표가 보이고, **검은 칸 ②**에 "좌표 → 날씨 받기" 요청 주소가 채워지며, **현재 위치의 날씨 카드**가 나타난다.
4. 일부러 **거부**해 보기: 브라우저 주소창 왼쪽의 **자물쇠(또는 ⓘ) 아이콘 → 사이트 설정 → 위치**를 '차단'으로 바꾸고 페이지를 새로고침한다 → **"위치 권한이 거부되었어요…"** 안내가 뜨고, ②번 날씨 요청은 **일어나지 않는다**(②번 칸에 "좌표를 못 받아 요청 안 함").
5. 다시 **[📍 내 위치로 날씨 보기]** 버튼을 누른다 → 권한을 다시 허용하면 날씨가 표시된다. (버튼으로 언제든 다시 시도 가능)
6. `script.js`에서 `getMyLocation()`(1단계)와 `getWeather(lat, lon)`(2단계) 두 함수를 찾는다 → **위치 → 날씨 두 요청을 연결**하는 핵심이다.
7. 같은 파일의 `describeGeoError(error)`를 본다 → `error.code`(`1`/`2`/`3`)를 보고 **거부·실패·시간초과**를 각각 다른 한국어 안내로 바꾸는 부분이다.
8. `getMyLocation()`이 `new Promise(...)`로 콜백 API를 감싼 모습을 본다 → 옛 방식 API를 `await`로 쓰게 만드는 패턴이다.
9. 같은 파일 위쪽 `WEATHER_CODE` 표와 `describeWeather(code)`를 본다 → 숫자 코드를 한국어+이모지로 바꾸는 매핑이다. (153과 동일)
10. AI에게 시켜 보기:
    > "이 `script.js`에서, 위치 권한이 **거부된 경우**에는 자동으로 **'부산'의 좌표(위도 35.18, 경도 129.08)로 대신 날씨를 보여주는** 백업(fallback)을 추가해줘. 그리고 화면에는 '내 위치 대신 부산 날씨를 보여드려요'라는 안내 문구를 함께 띄워줘."

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. (한 번에 다 시키지 말고, 1단계 → 2단계 순서로 나눠 시키면 결과가 훨씬 좋습니다.)

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 비전공자에게 친절한 웹 강사야. 키(API 키) 없이 쓰는 공개 날씨 API인 Open-Meteo로,
  '내 위치의 현재 날씨'를 보여주는 한 장짜리 웹페이지를 만들어줘. 제약과 산출물은 이렇게:
  - 파일은 index.html, style.css, script.js 세 개로 분리.
  - 페이지를 열면 브라우저 Geolocation으로 내 좌표(위도·경도)를 요청한다.
    navigator.geolocation.getCurrentPosition을 Promise로 감싸 async/await로 쓰는 패턴을 사용해줘.
  - 받은 좌표로 https://api.open-meteo.com/v1/forecast 를 fetch 해서 현재 기온과 날씨 상태를 보여줘.
  - 날씨는 숫자(WMO weather_code)로 오니, 한국어 설명 + 이모지로 바꾸는 표(WEATHER_CODE)를 만들어줘.
  - 비전공자가 읽을 수 있게 한국어 주석을 충분히 달고, 변수·함수 이름만 영어로 해줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  좋아. 이제 '권한 거부 처리'와 '다시 시도'를 더해줘.
  - 사용자가 위치를 거부/실패/시간초과(error.code 1/2/3)했을 때 각각 다른 한국어 안내 문구를 보여줘.
  - 거부한 경우엔 날씨 요청을 하지 말고, "좌표를 못 받아 요청 안 함"이라고 화면에 표시해줘.
  - [내 위치로 날씨 보기] 버튼을 추가해, 거부한 뒤에도 다시 시도할 수 있게 해줘.
    (요청 중에는 버튼을 disabled로 잠가 중복 클릭을 막아줘.)
  - 추가로, 거부했을 때 자동으로 부산(위도 35.18, 경도 129.08) 날씨를 대신 보여주는 백업(fallback)도 넣고,
    "내 위치 대신 부산 날씨를 보여드려요" 안내를 함께 띄워줘.
  - 새로 넣은 부분은 왜 그렇게 했는지 주석으로 한 줄씩 설명해줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  위치 권한 팝업이 안 뜨거나, 콘솔(F12)에 이런 에러/증상이 떠. 아래 내용을 붙여넣을게.
  [여기에 에러 메시지나 화면 증상을 그대로 붙여넣기]
  이게 무슨 뜻인지 비전공자가 이해하게 풀어서 설명하고, 가능한 원인을 가능성 높은 순서로 나열한 뒤,
  내가 한 단계씩 확인할 수 있는 체크리스트(예: https인지, 권한을 차단해 둔 건 아닌지, 인터넷 연결)로 알려줘.
  코드를 고쳐야 하면 바뀐 부분만 보여주고, 왜 그렇게 고쳤는지도 설명해줘.
  ```

## 검증법
- 페이지를 열면 **위치 권한 팝업**이 뜨는가? **[허용]** 누르면 내 위치 날씨가 표시되는가? (좌표·기온·날씨 글자·이모지가 모두 채워졌는가)
- 검은 칸 **①에 좌표(위도·경도)**가, **②에 날씨 요청 주소**가 채워지는가?
- 위치를 **거부**하면 **"위치 권한이 거부되었어요…"** 안내가 뜨고, ②번 날씨 요청은 **일어나지 않는가**? (②번 칸에 "좌표를 못 받아 요청 안 함"이 보임)
- **[📍 내 위치로 날씨 보기]** 버튼을 누르면 위치 요청을 **다시** 시도하는가? (요청 중에는 버튼이 잠시 흐려지며 눌리지 않음)
- `F12`(개발자 도구) → **Network 탭**을 켜고 허용하면, `forecast`(날씨) 요청이 보이는가? (위치 좌표 ①번은 브라우저 내장 기능이라 Network에 외부 요청으로 잡히지 않는다 — 좌표는 외부 API가 아님)
- Network 탭에서 `forecast` 응답을 열어 `current.weather_code` 숫자를 확인하고, 화면의 **한국어 날씨 설명**이 표(`WEATHER_CODE`)대로 일치하는지 확인한다.

> 참고: 위치 기능은 보안 주소(`https://`)·`localhost`·로컬 파일(`file://` 더블클릭)에서 동작합니다.
> 일부 브라우저는 `http://`로 된 원격 주소에서는 위치를 막으니, 배포 시에는 **https**로 여세요.
> (Vercel로 배포하면 자동으로 https가 적용됩니다.)

## 공개 API와 비밀값 — 보안 메모
이 실습이 쓰는 **Open-Meteo**(`open-meteo.com`)는 **누구나 열쇠(API 키) 없이** 부를 수 있는 **공개 API**입니다.
그래서 이 코드에는 **넣을 비밀값이 아예 없습니다.** 또한 ①번 좌표는 **외부 API가 아니라 브라우저 내장 기능**으로 얻으므로, 여기에도 키가 필요 없습니다. 브라우저 코드는 누구나 들여다볼 수 있으니, 비밀값이 없다는 점이 안전합니다.

나중에 **키가 필요한** 날씨 API(예: OpenWeatherMap)를 쓰게 되면, 값의 성격을 반드시 구분해야 합니다.

- **공개되어도 되는 값**(예: Supabase의 `anon`(공개) 키): 브라우저 코드에 들어가도 괜찮습니다. 단, 데이터 보호는 **RLS(행 수준 보안)** 가 책임집니다.
- **절대 노출하면 안 되는 비밀값**(예: Supabase의 `service_role` 키, 유료 날씨 API 키): **브라우저 코드에 절대 넣지 않습니다.** 비밀값은 서버(또는 n8n 같은 자동화 도구의 자격 증명 저장소)에서만 다룹니다.
- 키가 있는 API를 예제로 적을 때는, 코드에 진짜 키 대신 `YOUR_API_KEY` 같은 **자리표시자**만 두는 것이 원칙입니다.

```js
// 키가 필요한 API를 '브라우저에서 직접' 부르는 것은 키 노출 위험이 있습니다.
// 예시로 적을 때조차 진짜 키는 넣지 말고 자리표시자만 둡니다.
const WEATHER_API_KEY = "YOUR_API_KEY"; // ← 자리표시자. 실제 비밀키는 절대 코드에 넣지 않는다.
// 실제로는 이런 비밀키 호출은 서버(또는 n8n)에서 처리하고, 브라우저는 그 서버를 부릅니다.
```

> 위치 정보 자체도 '민감 정보'입니다. 이번 실습은 좌표를 **화면 표시와 날씨 조회에만** 쓰고 어디에도 저장하지 않습니다.
> 실제 서비스에서 사용자 위치를 **저장**해야 한다면, 반드시 동의를 받고 Supabase의 **RLS로 본인만 자기 위치를 볼 수 있게** 보호해야 합니다.
