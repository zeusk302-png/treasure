# 165 — 토큰·요청 한도와 비용을 점검하는 '안전 호출' 점검표 만들기

AI(Claude) API를 부를 때마다 **얼마나 썼는지(토큰)**, **돈이 얼마 나가는지(예상 비용)** 를 기록하고, **정해 둔 한도를 넘으면 호출을 자동으로 막는** 점검 대시보드를 만듭니다.

"AI에게 시키면 코드는 나오는데, 실수로 비용이 폭탄처럼 나오면 어떡하지?" — 이 걱정을 **디렉터(여러분)가 먼저 검증하는 안전장치**로 바꾸는 실습입니다.

- 카테고리: API·외부연동 (코드 G)
- 난이도: 5 / 5
- 개념: 토큰·비용 관리, rate limit 가드, 사용량 로깅
- 결과물: 호출별 토큰·비용을 보여주고 한도를 넘으면 차단하는 점검 대시보드(서버 함수 + 페이지)

> 이 폴더의 파일들
> - `index.html` / `style.css` / `script.js` — 화면(대시보드). **비밀 키가 전혀 없습니다.**
> - `api/safe-call.js` — 서버 함수(Vercel). **비밀 키는 여기서만** 환경변수로 씁니다.
> - `package.json` — 서버 함수가 쓰는 AI SDK 목록.
> - `.env.example` — 환경변수 예시(자리표시자). 실제 키가 든 `.env`는 올리지 않습니다.

---

## 목표

API를 부르는 일은 "남의 주방에 음식을 주문하는 것"과 같습니다. 그런데 AI API에는 두 가지 함정이 있습니다.

1. **토큰만큼 돈이 나간다.** 글자가 길수록 토큰이 늘고, 토큰이 늘수록 비용이 늘어납니다.
2. **무한정 부를 수 있다.** 버그 한 줄, 무한 반복 한 번이면 요청이 수천 번 나가 '요금폭탄'이 됩니다.

그래서 이번 실습의 목표는 단순히 "AI를 부르는 것"이 아니라, **부르기 전에 한도를 먼저 검사하고, 부른 다음엔 사용량을 기록하는 '안전 루틴'** 을 직접 만들어 보는 것입니다.

핵심 단어 3개만 기억하세요.

- **토큰(token)**: AI가 글을 잘게 쪼갠 조각. 입력 토큰 + 출력 토큰을 합쳐 요금을 매깁니다.
- **비용(cost)**: `토큰 수 × 토큰당 단가`. 이 실습은 Claude Opus 4.8 기준 **입력 100만 토큰당 $5, 출력 100만 토큰당 $25** 로 계산합니다.
- **한도 가드(rate limit / budget guard)**: "오늘 N번까지, $M까지만" 정해 두고 넘으면 **호출을 아예 막는** 문지기.

> 비유: 가드는 놀이공원 자유이용권과 같습니다. 입장(호출) 전에 "오늘 탈 수 있는 횟수가 남았나?"를 먼저 확인하고, 다 쓰면 들여보내지 않습니다. 디렉터는 이 문지기를 **AI를 부르기 전에** 세워 둡니다.

### 보안 한 줄 정리 (꼭 짚고 넘어가기)

AI API 키는 **service_role(비밀) 급** 입니다. 공개되면 누구나 내 돈으로 AI를 부를 수 있습니다.

- **화면 코드(`script.js`)에는 키가 1도 없습니다.** 브라우저 코드는 누구나 열어볼 수 있으니까요. (anon, 즉 공개 영역)
- **키는 서버 함수(`api/safe-call.js`)에서만** `process.env.ANTHROPIC_API_KEY`로 읽습니다. (비밀 영역)
- 실제 키 값은 코드가 아니라 **Vercel 환경변수**에 넣고, 이 저장소엔 **자리표시자**(`sk-ant-여기에-진짜-키-넣기-자리표시자`)만 둡니다.

## 따라하는 단계

1. **이 폴더의 파일들을 살펴봅니다.** 화면 파일(`index.html`, `script.js`)을 열어 "여기 어디에도 키가 없다"는 걸 눈으로 확인하세요. 그다음 `api/safe-call.js`를 열어, 키가 `process.env.ANTHROPIC_API_KEY`로만 들어오는 것을 확인합니다.

2. **한도 숫자를 찾습니다.** `api/safe-call.js` 위쪽의 두 줄이 이번 실습의 '문지기 기준'입니다.
   ```js
   const REQUEST_LIMIT = 20;   // 하루 최대 호출 횟수
   const COST_LIMIT_USD = 0.5; // 하루 최대 누적 비용(USD)
   ```
   숫자를 `REQUEST_LIMIT = 2` 처럼 작게 바꿔 보면, 검증 단계에서 차단을 더 빨리 볼 수 있습니다.

3. **비밀 키를 환경변수로 준비합니다.** 실제 키 값은 코드에 적지 말고:
   - 로컬 테스트라면: `.env.example`을 복사해 `.env`로 만들고, 자리표시자를 진짜 키로 바꿉니다. (`.env`는 `.gitignore`에 들어 있어 공개되지 않습니다.)
   - Vercel 배포라면: **Vercel > 프로젝트 > Settings > Environment Variables** 에 `ANTHROPIC_API_KEY` 이름으로 진짜 키를 등록합니다.

4. **서버 함수와 함께 띄웁니다.** 이 결과물은 서버 함수가 있어서 `index.html`을 더블클릭만 하면 작동하지 않습니다. 둘 중 하나로 실행하세요.
   - **가장 쉬운 길(권장):** 이 폴더를 GitHub에 올리고 Vercel에 연결하면, Vercel이 `api/` 폴더를 자동으로 서버 함수로 만들어 줍니다. (155~168번대 배포 실습과 동일한 흐름)
   - **로컬에서:** `npm install` 후 `npx vercel dev`를 실행하면 같은 환경이 로컬에 뜹니다.

5. **대시보드를 사용해 봅니다.** 화면이 열리면:
   - 위쪽 "오늘의 한도 현황" 막대가 채워지는 것을 봅니다(상태만 조회, 호출 아님).
   - 질문을 한 줄 적고 **"안전하게 호출하기"** 를 누릅니다.
   - 답이 뜨고, 아래 로그 표에 **입력 토큰 / 출력 토큰 / 이 호출 비용**이 한 줄 추가됩니다.

6. **일부러 한도를 넘겨 봅니다.** 2단계에서 `REQUEST_LIMIT`을 2로 낮췄다면, 3번째 호출에서 답 대신 **"한도를 초과해 호출이 차단되었습니다"** 가 뜨는지 확인합니다. 이때 로그에는 토큰 0, 비용 0으로 **'차단'** 이 기록됩니다 — AI를 부르지 않았다는 증거입니다.

7. **(AI 디렉터 연습)** AI에게 이렇게 지시해 한 단계 키워 보세요.
   > "이 `api/safe-call.js`에서 한도를 넘기 직전(예: 80%)이면 차단은 하지 않되 경고 메시지를 같이 돌려주도록 고쳐줘. 단, 비밀 키는 계속 환경변수에서만 읽어야 해."

## 검증법

아래가 모두 맞으면 성공입니다.

- **키 노출 없음:** 브라우저에서 `F12 > 소스(Sources)`로 `script.js`를 열어도 `sk-ant-...` 같은 키가 **보이지 않는다.** (키는 서버 함수에만 있음)
- **호출 성공:** 질문 후 답이 뜨고, 로그 표에 입력/출력 토큰과 비용이 **숫자로** 기록된다.
- **비용 누적:** 호출을 반복하면 "누적 비용(USD)" 막대가 조금씩 차오른다.
- **한도 차단 작동:** 한도를 낮춘 뒤 한계를 넘기면, 답 대신 차단 안내가 뜨고 로그에 '차단'(토큰 0)이 남는다 → **AI를 부르기 전에 막혔다는 증거.**
- **네트워크 확인:** `F12 > Network` 탭에서, 차단된 호출은 `/api/safe-call` 응답 상태코드가 **429**(한도 초과)인 것을 볼 수 있다. 성공 호출은 **200**이다.
- **키가 없을 때:** 환경변수를 비워 두면 "서버 환경변수(ANTHROPIC_API_KEY)를 확인하세요" 안내가 뜬다(키 값이 화면에 노출되지 않음).

> 흔한 실수
> - **`index.html`만 더블클릭함:** 서버 함수가 안 떠서 호출이 실패합니다. `npx vercel dev` 또는 Vercel 배포로 실행하세요.
> - **키를 코드에 직접 적음:** `new Anthropic({ apiKey: "sk-ant-..." })`처럼 적으면 공개 시 그대로 유출됩니다. 반드시 `process.env`로만 읽으세요.
> - **메모리 저장의 한계:** 이 실습의 사용량(`usage`)은 서버 함수 메모리에 잠깐 담깁니다. 서버 함수가 새로 뜨면 0으로 돌아갈 수 있어요. 영구 기록은 아래 '한 단계 더'를 참고하세요.

### 한 단계 더 (영구 저장으로 키우기)

진짜 서비스라면 사용량을 메모리가 아니라 **Supabase 테이블**에 기록해, 서버가 꺼졌다 켜져도 한도가 유지되게 합니다. `api/safe-call.js`의 `usage` 변수를 Supabase의 `usage_log` 테이블 읽기/쓰기로 바꾸면 됩니다. (이때 Supabase 키도 anon/service_role 구분과 RLS를 똑같이 지켜야 합니다.)
