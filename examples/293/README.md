# 실습 293 — 돈 계산에서 부동소수점 오차 잡기

장바구니 합계를 더했더니, 값을 깎은 적도 없는데 1원이 모자라거나 소수점이 이상하게 붙어 나옵니다. 이 실습은 그 "유령 오차"의 정체(부동소수점)를 직접 눈으로 보고, **정수(가장 작은 단위)로 바꿔 더하는** 정석 해법으로 고치는 과정을 다룹니다.

```
[ 소수로 더함 ]  6666.66 + 6666.66 + 6666.67  →  19999.989999...  (오차)
[ 정수로 더함 ]  666666 + 666666 + 666667(전) →  1999999전 → 19,999.99원  (정확)
```

> 비유: 1cm 자로 0.333cm를 재려 하면 매번 조금씩 어긋나지만, mm 단위(정수)로 바꿔서 재면 딱 떨어집니다. 돈도 "원(소수)" 말고 "전(정수)"으로 다루면 오차가 사라집니다.

## 목표
- 컴퓨터가 소수(0.1, 0.2 같은 값)를 정확히 저장하지 못해 오차가 생긴다는 사실을 체감한다.
- `0.1 + 0.2 === 0.3` 이 `false`인 이유를 콘솔로 직접 확인한다.
- 돈 계산을 **정수(전 = 1/100원) 단위**로 바꿔 오차 없이 더하는 방법을 익힌다.
- "계산은 정수로, 반올림(표시)은 마지막 한 번만"이라는 원칙을 안다.

## 따라하는 단계
1. `broken.html`을 더블클릭해 브라우저로 연다. 합계가 깔끔하지 않게 나오는 걸 확인한다.
2. `F12`를 눌러 개발자도구 콘솔을 열고, `합계 === 19999.99` 가 `false`로 찍히는 걸 본다.
3. `index.html`(정답 버전)을 열어 합계가 `19,999.99원`으로 깔끔하게 나오는 걸 비교한다.
4. 터미널에서 `node compare.js`를 실행해, 나쁜 방식과 좋은 방식의 결과를 표로 한 번에 비교한다.
5. 두 HTML의 `<script>`를 나란히 읽으며 `price`(소수)와 `priceJeon`(정수 전) 차이를 찾는다.

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 자바스크립트 초보를 가르치는 선생님이야.
  소수점 가격이 섞인 장바구니 합계를 보여주는 단일 HTML 파일을 만들어줘.
  - 상품 3개(예: 6666.66원, 6666.66원, 6666.67원)를 배열로 두고 for문으로 합계를 구해 화면에 표시
  - 카드 형태의 간단한 CSS 포함, 외부 라이브러리 없이 순수 HTML/CSS/JS
  - 일부러 소수(float)끼리 그대로 더해서 부동소수점 오차가 드러나게 만들어줘
  - 콘솔에 합계와 (합계 === 19999.99) 결과도 찍어줘
  비전공자가 읽을 수 있게 한국어 주석을 한 줄씩 달고, 왜 그렇게 했는지 이유도 적어줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 "오차 나는 버전"을 정답 버전으로 고친 새 HTML을 만들어줘.
  - 가격을 처음부터 정수 '전'(1/100원) 단위로 저장(예: 6666.66원 → 666666전)
  - 정수끼리만 더하고, 화면에 보여줄 때만 100으로 나눠 "19,999.99원" 형식으로 표시
  - toLocaleString으로 천 단위 콤마, 소수 두 자리는 padStart로 채워줘
  - 합계가 정확함을 보여주는 콘솔 로그(합계 === 1999999 → true)도 추가
  바꾼 곳마다 "왜 정수로 바꾸면 오차가 사라지는지" 주석으로 설명해줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  돈 합계가 19999.99가 아니라 19999.989999999998 처럼 나와.
  내 코드(아래에 붙여넣기)에서 왜 이런 오차가 생기는지 한 줄씩 짚어주고,
  정수 단위 계산으로 고치는 방법을 단계별로 알려줘. toFixed/반올림으로 "표시만"
  고치는 방법과, 계산 자체를 정수로 바꾸는 방법의 차이와 장단점도 비전공자가 이해하게 설명해줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법
- `broken.html` 콘솔에서 `합계 === 19999.99` 가 `false`, `index.html` 콘솔에서 `합계전 === 1999999` 가 `true`로 나오는지 본다.
- `index.html` 화면의 합계가 정확히 `19,999.99원`(소수점 오차 없음)으로 표시되는지 확인한다.
- `node compare.js` 출력에서 "나쁨"은 `=== 19999.99 ? false`, "좋음"은 `=== 1999999 ? true`로 갈리는지 본다.
- 콘솔에 `0.1 + 0.2` 가 `0.30000000000000004`로 찍히는지 확인한다(오차의 본질).

## 파일 구성
- `broken.html` — 소수로 그대로 더해 오차가 나는 "고장난" 버전(문제 체험용)
- `index.html` — 정수(전) 단위로 더해 오차를 없앤 "정답" 버전
- `compare.js` — 나쁜 방식 vs 좋은 방식을 콘솔 표로 비교하는 데모(`node compare.js`)
