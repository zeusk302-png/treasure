# 실습 255 — 예약을 Supabase에 저장하고 이미 찬 시간대는 비활성화하기

날짜와 시간대를 골라 예약을 **저장**하고, 같은 날짜에 **이미 찬 시간대**는
드롭다운에서 자동으로 **'예약 마감'**으로 막는 미니 예약 폼을 만듭니다.
"DB를 조회한 결과로 화면(선택지)을 켜고 끄는" **조건부 UI** 패턴을 한 번에 체험하는 것이 목표입니다.

> 비유: 식당 예약 같습니다. 손님이 **날짜**를 말하면, 점원이 **예약 장부(Supabase)**를 펴서
> 그 날의 빈 시간만 알려 줍니다. 누군가 7시를 이미 잡았다면 **7시는 줄을 그어** 못 고르게 하고,
> 혹시 같은 순간에 두 사람이 7시를 부르면 **장부의 규칙(중복 방지)**이 한 명만 받아 줍니다.

이 폴더에 있는 파일:

- `README.md` — 이 안내문
- `index.html` — 이름·날짜·시간대 입력 폼 (시간대는 처음엔 비어 있다가 JS가 채움)
- `style.css` — 입력 카드 + 비활성(마감) 선택지의 회색 처리 디자인
- `script.js` — **핵심.** 날짜로 찬 시간대를 `select` 해 마감 처리하고, 예약을 `insert` 하며 중복 에러를 처리
- `schema.sql` — 표 만들기 + **(날짜+시간대) 중복 방지 제약** + RLS 켜기 + 읽기·저장 정책

## 목표

- 폼에서 받은 값(`날짜`, `시간대`)을 `from("reservations").insert({...})`로 **Supabase에 저장**하는 법을 익힌다.
- 선택한 날짜의 예약을 `.eq("slot_date", date).select("slot_time")`로 조회해, **이미 찬 시간대를 `disabled`로 막는** 조건부 UI를 만든다.
- 중복 예약을 **두 겹**으로 막는 원리를 이해한다 — (a) 화면에서 회색 비활성화(친절), (b) DB의 `UNIQUE(slot_date, slot_time)` 제약(진짜 방어, 동시 클릭까지 차단).
- **anon(공개) 키**가 브라우저에 박혀 있어도 안전한 이유(= RLS로 SELECT·INSERT만 허락, 수정·삭제는 막음)를 확인한다.

## 따라하는 단계

1. **Supabase 표·보안·중복 방지를 만든다.**
   Supabase 대시보드 → **SQL Editor → New query** 에 이 폴더의 `schema.sql` **전체**를 붙여넣고 **[Run]** 한다.
   (표 `reservations` 생성 + **`(slot_date, slot_time)` UNIQUE 제약** + RLS 켜기 + 읽기/저장 정책 + 샘플 예약 1건이 한 번에 만들어집니다.)
2. **내 프로젝트 값을 코드에 넣는다.**
   Supabase 대시보드 → **Settings(톱니바퀴) → API** 에서 값을 복사해 `script.js` 맨 위 두 줄의 **자리표시자**를 바꾼다.
   ```js
   const SUPABASE_URL = "https://여기에-내-프로젝트-ID.supabase.co";        // ← Project URL
   const SUPABASE_ANON_KEY = "sb_publishable_여기에-내-anon-공개키-붙여넣기"; // ← anon public 키
   ```
   ⚠️ **`service_role` / `sb_secret_...` 키는 절대 넣지 마세요.** 그 키는 RLS를 통째로 무시하는 마스터 키라, 브라우저에 두면 누구나 모든 예약을 마음대로 지우거나 고칠 수 있게 됩니다.
3. **`index.html`을 브라우저로 연다.** (그냥 더블클릭해도 됩니다.)
4. **날짜를 고른다.** 날짜를 고르면 JS가 그 날짜의 예약을 조회해, 빈 시간대만 고를 수 있게 채웁니다.
   `schema.sql` 5단계 샘플을 그대로 두었다면, **2026-06-20** 을 고르면 **10:00 이 '(예약 마감)'으로 회색** 처리됩니다.
5. **빈 시간대를 골라 [예약하기]를 누른다.** "예약 완료: …" 메시지가 뜨고, 방금 잡은 시간대가 곧바로 마감으로 바뀝니다.
6. **중복을 직접 확인한다.** 방금 예약한 그 시간대를 다시 잡으려 해도 화면에서 이미 막혀 있고(회색), 혹시 두 창에서 동시에 같은 시간을 눌러도 한 명만 성공합니다.

## 🤖 바이브코딩 프롬프트

이 실습(예약 저장 + 이미 찬 시간대 비활성화 + 중복 방지)을 AI에게 시켜 만들 때, 아래 프롬프트를 그대로 복사해 쓰세요. 한 번에 다 시키지 말고 **단계별로** 시키면 결과를 검증하기 쉽습니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 바닐라 자바스크립트와 Supabase에 익숙한 프론트엔드 멘토야.
  비전공자도 그대로 따라 할 수 있는 "미니 예약 폼" 한 장을 만들어 줘.

  [산출물] index.html, style.css, script.js, schema.sql 네 파일.
  [요구사항]
  - 폼: 이름(text), 날짜(date), 시간대(select) + [예약하기] 버튼.
  - Supabase 테이블 reservations(id, name, slot_date, slot_time, created_at).
  - 시간대 후보는 ["10:00","11:00","13:00","14:00","15:00","16:00","17:00"].
  - 날짜를 고르면 그 날짜의 예약을 SELECT 해서, 빈 시간대만 select 에 채워 줘.
  - 예약하기를 누르면 reservations 에 INSERT 하고 결과 메시지를 보여 줘.
  [제약]
  - 프레임워크 없이 순수 HTML/CSS/JS. Supabase는 CDN(@supabase/supabase-js@2).
  - 키 값은 코드에 직접 박지 말고 "자리표시자"로 두고, 주석으로 어디서 복사하는지 알려 줘.
  - 사용자 입력은 textContent 로 출력해서 XSS를 피해 줘.
  - 코드만 주지 말고, 왜 그렇게 했는지 한국어 주석으로 줄마다 풀어서 설명해 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  좋아. 이제 "중복 예약"을 두 겹으로 막아 줘.
  (a) 화면: 이미 찬 시간대는 select 의 option 을 disabled 로 막고 글자에 '(예약 마감)'을 붙여 줘.
  (b) DB: schema.sql 에 (slot_date, slot_time) 묶음 UNIQUE 제약을 추가해 줘.
      → 두 사람이 동시에 같은 시간을 눌러도 한 명만 성공하게.
  그리고 보안도 같이 잡아 줘.
  - reservations 에 RLS(행 수준 보안)를 켜고, SELECT 와 INSERT 만 허용하는 정책을 만들어 줘.
  - UPDATE/DELETE 정책은 일부러 만들지 말고, 왜 안 만드는지(anon 키로 남의 예약을 못 고치게) 주석으로 설명해 줘.
  - 예약 성공 후에는 방금 잡은 시간대가 즉시 '예약 마감'으로 바뀌게 화면을 다시 그려 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  예약을 눌렀더니 콘솔에 이런 에러가 떠. 원인과 해결을 초보가 알아듣게 단계별로 알려 줘.
  내가 직접 고칠 수 있게, 어느 파일 몇 번째 줄을 어떻게 바꾸는지 짚어 줘.

  (여기에 콘솔에 빨갛게 뜬 에러 메시지를 그대로 붙여넣기)

  특히 아래 중 무엇인지 먼저 구분해 줘:
  - "relation ... does not exist" (schema.sql 미실행)
  - "row-level security policy" (INSERT 정책 누락)
  - "duplicate key" / 코드 23505 (중복 예약 — UNIQUE 제약 정상 동작)
  - "Invalid API key" / "Failed to fetch" (키·URL 오타)
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면, 결과물을 읽고 직접 검증하는 '디렉터' 실력이 같이 늡니다.

## 검증법

- **저장 성공:** 빈 시간대로 예약하면 초록색 "예약 완료: 날짜 시간 (이름님)" 메시지가 뜨는가? Supabase **Table editor → reservations** 에 새 줄이 들어왔는가?
- **조건부 UI(핵심):** 날짜를 고르면 **이미 찬 시간대만** '(예약 마감)' 회색으로 보이고 고를 수 없는가? 방금 예약한 시간대가 **즉시** 마감으로 바뀌는가?
- **중복 방지(핵심):** 이미 잡힌 시간대(예: 샘플의 2026-06-20 10:00)는 화면에서 고를 수 없는가? 두 개의 브라우저 창에서 같은 시간대를 거의 동시에 누르면 **한 쪽만 성공하고 다른 쪽은 "방금 다른 분이…" 안내**가 나오는가? (= DB의 UNIQUE 제약 동작)
- **브라우저 개발자 도구 → Console**(윈도우 `F12`):
  - 성공: `✅ 예약 저장 성공: {name, date, time}`
  - 중복: `❌ 예약 저장 실패: duplicate key …` → 화면엔 친절한 안내로 바뀜
- **anon 키만 썼는지(중요):** `script.js`의 키가 **`sb_publishable_`(anon)** 로 시작하는가? **`sb_secret_`(service_role)** 가 **아닌가?**
- **수정/삭제 차단 확인(보안):** 콘솔에서
  `await supabase.createClient(SUPABASE_URL, SUPABASE_ANON_KEY).from("reservations").delete().eq("id", 1)`
  를 해보면 줄이 지워지지 않는다(삭제 정책이 없어 막힘). 즉 anon 키로는 **예약 등록만 되고 남의 예약 삭제는 막힙니다.**
- **자주 나는 에러:**
  - `relation "public.reservations" does not exist` → 1단계 `schema.sql`을 안 돌림. SQL Editor에서 실행하세요.
  - `new row violates row-level security policy` → INSERT 정책(4단계)이 빠짐. `schema.sql` 전체를 다시 실행하세요.
  - `Invalid API key` → anon 키 오타. / `Failed to fetch` → `SUPABASE_URL` 철자·`https://` 확인.
