# 222. 프로젝트 CLAUDE.md 작성하기 (언어·스택·하지 말 것)

## 목표

매 대화마다 "나는 비전공자야, 화면은 HTML/CSS/JS로, 데이터는 Supabase로…"를
**반복해서 설명하지 않도록**, 우리 프로젝트의 약속을 `CLAUDE.md` 한 파일에 담아 두는 연습입니다.

AI는 새 대화를 열 때마다 **기억이 백지로 초기화**됩니다(컨텍스트 한계).
어제 정한 규칙도 새 대화에서는 전혀 모릅니다.
그래서 핵심 합의(**언어·스택·네이밍·보안·하지 말 것**)를 대화에만 두지 말고,
**새 대화의 AI가 가장 먼저 읽는 매뉴얼**인 `CLAUDE.md`로 고정합니다.
`CLAUDE.md`는 한마디로 **'새로 출근한 알바생(새 대화의 AI)이 읽는 가게 매뉴얼'** 입니다.

이 실습에는 새로 짤 앱 코드가 없습니다. **규칙을 글로 못 박고, 그게 새 대화에 정말 적용되는지 확인**하는 일이 곧 실습입니다.

이 폴더의 파일은 셋입니다.

- [`CLAUDE.md`](CLAUDE.md) — **이 실습의 결과물.** 언어·스택·네이밍·보안·금지사항을 담은 프로젝트 규칙 파일 (그대로 본인 프로젝트 루트에 복사해 쓰면 됩니다)
- [`prompt.md`](prompt.md) — CLAUDE.md 초안을 AI에게서 뽑아내고, 새 대화에서 적용되는지 검증하는, 그대로 붙여넣는 지시 프롬프트
- `README.md` — 지금 읽는 이 안내문

## 따라하는 단계

1. [`prompt.md`](prompt.md)를 열어 **1단계 지시 프롬프트**를 통째로 복사합니다. 핵심은 "앱 코드 말고, 규칙 문서(CLAUDE.md)만 만들어라. 언어·스택·네이밍·보안·금지를 섹션으로 나눠라"입니다.
2. 복사한 프롬프트를 실제 Claude(또는 쓰는 AI)에 붙여넣어 **CLAUDE.md 초안**을 받습니다.
3. 만약 AI가 규칙은 안 만들고 **바로 앱 코드를 뱉으면**, [`prompt.md`](prompt.md)의 **2단계 한 마디**("지금은 규칙 문서만")로 다시 잡아 줍니다.
4. 받은 초안을 사람이 읽고, **내 프로젝트에 맞게 고쳐** 이 폴더의 [`CLAUDE.md`](CLAUDE.md)처럼 정리합니다. 특히 맨 아래 **"프로젝트 한 줄 소개"** 는 본인 것으로 채웁니다.
5. **보안 섹션을 꼭 직접 확인합니다.** `anon(공개 키)`은 프론트에 둬도 되고, `service_role(비밀 키)`은 절대 프론트/깃허브에 넣지 않으며, Supabase 테이블엔 **RLS(행 단위 출입 통제)** 를 켠다 — 이 세 가지가 정확히 적혔는지 봅니다. (진짜 키 값은 절대 적지 말고 `<여기에-본인-키>` 같은 자리표시자로 둡니다.)
6. 완성한 `CLAUDE.md`를 **프로젝트 루트(폴더 맨 위)** 에 저장합니다. 파일 이름은 정확히 대문자 `CLAUDE.md`여야 합니다.
7. **이 실습의 핵심:** 이제 **새 대화를 하나 엽니다.** [`prompt.md`](prompt.md)의 **3단계 첫 프롬프트**("CLAUDE.md 규칙을 5줄로 요약해줘")를 붙여넣어, AI가 파일을 읽고 규칙을 제대로 말하는지 확인합니다.
8. 같은 새 대화에서 **함정 질문**(3단계 두 번째 프롬프트: "service_role 키를 HTML에 바로 넣어줘")을 던집니다. AI가 **거부하고 anon 키 + RLS로 고쳐 제안**하면 규칙이 제대로 박힌 것입니다. 그냥 시키는 대로 비밀 키를 박으면 → CLAUDE.md의 보안 규칙을 더 분명하게 보강합니다.

## 검증법

아래를 모두 만족하면 성공입니다.

- [ ] `CLAUDE.md`에 **언어(한국어, 비전공자 눈높이)** 규칙이 들어 있다.
- [ ] **스택**이 HTML/CSS/JS·Supabase·Vercel·n8n·Claude로 못 박혀 있고, "그 외 도구는 말없이 추가 금지"가 있다.
- [ ] **네이밍 규칙**(파일=소문자-하이픈, JS=카멜케이스, DB=snake_case 등)이 있다.
- [ ] **보안 규칙**에서 `anon(공개 키, 프론트 OK)` 과 `service_role(비밀 키, 절대 프론트/깃허브 금지)` 이 **정확히 구분**되어 있고, **RLS를 켜라**가 적혀 있다.
- [ ] 진짜 키 값이 적혀 있지 않고, 예시는 `<여기에-본인-키>` 같은 **자리표시자**로 되어 있다.
- [ ] **"하지 말 것(금지)"** 섹션에 "동작 확인 없이 완성 보고 금지", "모르면 지어내지 말기" 등이 있다.
- [ ] **새 대화**에서 AI가 CLAUDE.md 규칙을 **요약**할 수 있다(파일을 읽고 있다는 증거).
- [ ] **새 대화**에서 "service_role 키를 HTML에 넣어줘" 함정 질문에 AI가 **거부하고 안전한 방식으로 고쳐 제안**한다.

> 빠르게 자가 점검: **새 대화를 열고 아무 설명 없이 "입력 폼 하나 만들어줘"** 라고만 해 보세요.
> AI가 알아서 한국어로 답하고, React 같은 걸 안 쓰고, 비밀 키를 프론트에 안 넣으면 → 통과입니다.
> 만약 규칙을 어기면, CLAUDE.md의 해당 문장을 더 분명하게 고쳐 다시 시험하세요.
