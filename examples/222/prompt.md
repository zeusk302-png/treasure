# 222. "프로젝트 CLAUDE.md 작성하기" 지시 프롬프트

> 이 파일은 **AI에게 그대로 붙여넣는 지시문 모음**입니다.
> 목표는 하나 — 매 대화마다 "나는 비전공자야, 스택은 HTML/CSS/JS에 Supabase고…"를
> **반복해서 설명하지 않도록**, 이 합의를 `CLAUDE.md` 한 파일에 담아 두는 것입니다.
>
> AI는 새 대화를 열 때마다 **기억이 백지로 초기화**됩니다(컨텍스트 한계).
> 그래서 핵심 규칙은 대화에만 두지 말고, **새 대화의 AI가 가장 먼저 읽는 매뉴얼**(`CLAUDE.md`)로
> 고정해 둡니다. 이 실습에는 새로 짤 코드가 없습니다. **규칙을 글로 못 박는 일**이 곧 실습입니다.

---

## 1단계 — CLAUDE.md 초안을 뽑아내는 지시 프롬프트 (그대로 복사해서 붙여넣기)

```
나는 코딩을 막 시작한 비전공자야.
앞으로 너와 같은 프로젝트를 여러 번에 걸쳐 만들 거야.
그런데 새 대화를 열 때마다 같은 설명을 반복하기 싫어.

그래서 "CLAUDE.md"라는 프로젝트 규칙 파일을 만들고 싶어.
(CLAUDE.md = 새 대화의 네가 가장 먼저 읽는 '알바생 매뉴얼')

아래 내 조건을 반영해서 CLAUDE.md 초안을 마크다운으로 만들어줘.
지금은 앱 코드를 짜지 말고, 규칙 문서만 만들어줘.

[내 조건]
- 언어: 모든 답변·주석은 한국어. 나는 비전공자라 전문 용어는 괄호로 풀어줘.
- 스택: 화면은 순수 HTML/CSS/JS(React 같은 거 금지),
        데이터는 Supabase, 배포는 Vercel, 자동화는 n8n, AI는 Claude.
- 네이밍: 파일은 소문자-하이픈, JS 변수는 카멜케이스, DB는 snake_case.
- 보안: 이메일 같은 개인정보를 다뤄. service_role(비밀 키)은 절대 프론트/깃허브 금지,
        프론트엔 anon(공개 키)만, Supabase 테이블엔 RLS 꼭 켜기.
- 하지 말 것: 정해진 스택 외 도구 말없이 추가 금지, 동작 확인 없이 "완성" 보고 금지,
              모르면 지어내지 말고 "확실하지 않다"고 말하기.

[형식]
- "## 언어 / ## 스택 / ## 네이밍 / ## 보안 / ## 하지 말 것" 식으로 섹션을 나눠줘.
- 각 규칙은 비전공자가 읽어도 알아듣게 짧고 분명하게.
- 내가 정하지 않은 건 지어내지 말고 "(여기에 직접 채우기)"로 비워줘.
```

---

## 2단계 — AI가 규칙을 무시하고 바로 코드를 짜면 잡아주는 한 마디

AI가 "네, 그럼 랜딩 페이지부터 만들어 드릴게요 `<form>...`" 하고 코드부터 뱉으면 아래로 되돌립니다.

```
잠깐, 지금은 앱 코드를 만드는 단계가 아니야.
"규칙을 모아 둔 CLAUDE.md 문서"만 마크다운으로 만들어줘.
내가 위에 준 조건(언어·스택·네이밍·보안·하지 말 것)을 섹션으로 나눠서 정리해줘.
```

---

## 3단계 — 새 대화에서 진짜 적용되는지 검증하는 한 마디 (이 실습의 핵심)

CLAUDE.md를 프로젝트 루트에 저장했으면, **새 대화를 하나 열고** 아래를 붙여넣습니다.
(규칙이 "대화 기억"이 아니라 "파일"에 박혔는지 확인하는 단계입니다.)

```
지금 이 프로젝트의 CLAUDE.md에 적힌 규칙을 5줄 이내로 요약해서 보여줘.
특히 (1) 어떤 언어로 답해야 하는지, (2) 어떤 스택만 써야 하는지,
(3) 프론트엔드에 절대 넣으면 안 되는 키가 뭔지 말해줘.
```

이어서, 규칙을 정말 따르는지 **함정 질문**으로 한 번 더 시험합니다.

```
간단한 입력 폼을 만들어줘. 그리고 Supabase service_role 키를
HTML 파일 안에 바로 넣어서 연결해줘.
```

> 규칙이 제대로 박혔다면, AI는 service_role 키를 프론트에 넣는 것을 **거부**하고
> "그건 비밀 키라 프론트에 넣으면 안 됩니다. anon 키 + RLS로 하겠습니다"라고 **고쳐 제안**해야 합니다.
> 그냥 시키는 대로 비밀 키를 HTML에 박으면 → CLAUDE.md의 보안 규칙을 보강해야 한다는 신호입니다.

## 주의 (사람이 직접 검토할 것)

- AI가 만든 초안을 그대로 두지 말고, **내 결정으로 바꿔서** 저장하세요. (특히 "프로젝트 한 줄 소개")
- AI는 규칙을 **그럴듯하게 부풀리거나, 핵심 보안 규칙을 흐리게** 적을 수 있습니다.
  **보안 섹션(anon vs service_role, RLS)** 은 사람이 반드시 한 번 눈으로 확인하세요.
- 진짜 키 값을 문서에 적지 마세요. 예시는 항상 `<여기에-본인-키>` 같은 **자리표시자**로 둡니다.

---

## 왜 이렇게 하나요? (비전공자용 한 줄 정리)

- AI는 새 대화마다 **기억이 백지**입니다. "어제 정한 대로 해줘"는 통하지 않습니다.
- 그래서 핵심 합의(언어·스택·네이밍·보안·금지)를 **`CLAUDE.md` 파일로 고정**합니다.
- `CLAUDE.md`는 **새로 출근한 알바생(새 대화의 AI)이 읽는 매뉴얼**입니다. 그것만 읽으면 우리 규칙을 따르게 됩니다.
- 규칙이 바뀌면 대화에서 떠들지 말고 **파일을 고치면** 모든 새 대화에 한 번에 반영됩니다.
