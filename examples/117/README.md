# 실습 117 — 방명록 글 목록 select로 불러와 화면에 그리기

실습 116에서는 글을 **저장(insert)** 만 해 봤습니다.
그런데 저장만 하면 화면에는 아무것도 안 보이죠. 이번엔 그 반대 방향,
즉 **서버 표(guestbook)에 쌓인 글들을 불러와(select) 화면에 목록으로 그리기** 를 합니다.

이게 바로 거의 모든 웹앱의 기본 흐름인 **"서버 데이터를 받아 DOM에 뿌리기"** 입니다.
(게시판 글 목록, 댓글 목록, 상품 목록… 전부 이 패턴의 반복입니다.)

> 비유: 116이 창고 선반(guestbook 표) 위에 **종이 한 장(글 1건)을 올려놓기** 였다면,
> 117은 그 **선반에 쌓인 종이들을 한 장씩 꺼내 와 게시판에 붙이는** 연습입니다.

이 폴더에 있는 파일:

- `README.md` — 이 안내문
- `schema.sql` — `guestbook` 표 SQL (116과 **같은 표**. 이미 만들었으면 다시 실행 안 해도 됨)
- `index.html` — 글 목록이 표시될 화면 (`ul#list` + 새로고침 버튼)
- `script.js` — **핵심 코드.** `select()`로 글들을 받아 `forEach`로 `li`를 만들어 그립니다.

## 목표

- `supabase.from('guestbook').select('*')` 로 서버 표의 글들을 **여러 줄(배열)** 받아온다.
- 받아온 배열을 `forEach`로 한 줄씩 돌며 `document.createElement('li')`로 만들어 **화면 목록에 그린다.**
- `.order('created_at', { ascending: false })` 로 **최신 글이 맨 위에** 오도록 정렬한다.
- 다시 그리기 전에 `list.innerHTML = ""` 로 **목록을 비우는 이유**(중복 방지)를 이해한다.
- 글이 **0개일 때**(빈 배열)와 **에러일 때**를 구분해 사용자에게 다른 안내를 보여 준다.

## 따라하는 단계

1. **표를 준비한다.** 실습 116에서 `guestbook` 표를 이미 만들었다면 건너뛰세요.
   아직 없다면 Supabase 대시보드 → **SQL Editor → New query** 에 이 폴더의 `schema.sql`을
   통째로 붙여넣고 **[Run]** 을 누른다. (이 파일은 연습용 글 2개도 함께 넣어 줍니다.)
2. **읽을 글이 최소 1개 있어야 한다.** 목록에 보이는 게 없으면 화면도 비어 보입니다.
   116 폴더로 글을 몇 개 남겼거나, `schema.sql`의 연습용 `insert`를 실행했는지 확인하세요.
3. Supabase 대시보드 **Settings(톱니바퀴) → API** 에서 두 값을 복사한다.
   - **Project URL** : `https://xxxxxxxx.supabase.co` 형태의 주소 (비밀 아님)
   - **anon public** 키 (신형은 `sb_publishable_...` 로 시작) : 브라우저에 둬도 되는 **공개 출입증**
   - ⚠️ 같은 화면의 **`service_role` / `sb_secret_...` 키는 절대 쓰지 마세요.** 모든 보안을 무시하는 마스터 키입니다.
4. 이 폴더의 `script.js`를 열고, 맨 위 두 줄의 **자리표시자**를 내 값으로 바꾼다.
   ```js
   const SUPABASE_URL = "https://여기에-내-프로젝트-ID.supabase.co";   // ← 내 Project URL
   const SUPABASE_ANON_KEY = "sb_publishable_여기에-내-anon-공개키-붙여넣기"; // ← 내 anon public 키
   ```
5. `index.html`을 **브라우저로 연다.** (파일을 더블클릭)
   → 페이지가 열리자마자 자동으로 한 번 글을 불러와 **목록(li)** 으로 보여 줍니다.
6. **[새로고침(다시 불러오기)]** 버튼을 눌러 본다.
   116 폴더에서 새 글을 하나 더 남긴 뒤 이 버튼을 누르면, 그 글이 목록 **맨 위**에 나타납니다.
7. (이해 점검) `script.js`에서 `listEl.innerHTML = "";` 줄을 잠깐 지우고 새로고침을 여러 번 눌러 본다.
   → 글이 두 배, 세 배로 **중복되어 쌓이는** 걸 확인한 뒤, 다시 그 줄을 살려 두세요. (왜 비워야 하는지 체감용)

## 검증법

- 페이지를 열면 **글들이 li 카드 목록**으로 보이고, **최신 글이 맨 위**에 있는가?
- 각 줄에 **이름 · 작성 시각 · 메시지**가 제대로 표시되는가?
- 브라우저 **개발자 도구 → Console**(윈도우 `F12`, 맥 `Cmd + Option + I`)에
  `✅ 불러오기 성공! 서버가 돌려준 글 N개` 로그와 글 배열(`id`, `name`, `message`, `created_at`)이 찍혔는가?
- **[새로고침]** 을 눌러도 목록이 **중복으로 쌓이지 않는가?** (`innerHTML = ""` 가 잘 동작하는지)
- 글이 하나도 없을 때 빨간 에러가 아니라 **"아직 글이 없어요…" 파란 안내**가 뜨는가?
- **실패할 때 원인 찾기** (콘솔의 빨간 에러 메시지로 구분):
  - `relation "public.guestbook" does not exist` → 표가 없음. 1단계 `schema.sql`을 실행.
  - `Invalid API key` → anon 키를 잘못 붙여넣음. (혹시 service_role을 넣지 않았는지도 확인)
  - 주소 오류 / `Failed to fetch` → `SUPABASE_URL`의 철자나 `https://` 확인.
  - **에러는 없는데 목록만 계속 비어 있다?** → 표에 **RLS가 켜져 있는데 "읽기(select) 정책"이 없는** 경우가 가장 흔합니다.
    이때 `select`는 에러 대신 **빈 배열 `[]`** 을 돌려줘서 "글이 없는 것처럼" 보입니다.
    이 실습 단계처럼 RLS가 꺼져 있으면 정상적으로 다 보입니다. (보안을 켜는 법과 읽기 정책은 실습 119)
- **(안전 점검)** `script.js`에 넣은 키가 **`anon` / `sb_publishable_`** 로 시작하는가? `service_role` / `sb_secret_` 가 **아닌가?**
