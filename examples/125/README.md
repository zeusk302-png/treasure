# 실습 125 — 글이 많을 때 페이지네이션으로 10개씩 끊어 보기 (range + count)

실습 123에서 글들을 **최신순으로 정렬(.order)** 까지 했습니다.
그런데 글이 100개, 1000개가 되면 한 화면에 다 쏟아붓는 건 느리고 스크롤도 끝이 없죠.
그래서 게시판·댓글·검색 결과는 보통 **한 페이지에 10개씩** 보여 주고 **[이전] / [다음]** 으로 넘깁니다.

이번 실습의 핵심은 두 가지입니다.

```js
const { data, count, error } = await db
  .from("guestbook")
  .select("*", { count: "exact" })          // ① 전체가 총 몇 개인지(count)도 같이 받기
  .order("created_at", { ascending: false }) // ②  최신순으로 줄 세우고 (순서 고정용)
  .range(from, to);                          // ③  그 줄에서 '한 페이지 분량'만 잘라 오기 ← 핵심!
```

> 비유: 123이 "글들을 최신순으로 **한 줄로 세우기**"였다면,
> 125는 그 줄에서 "**1~10번째만 잘라서** 가져오기"입니다.
> 페이지를 넘긴다 = 자르는 **구간을 10칸씩 옮기는 것**일 뿐입니다.

이 폴더에 있는 파일:

- `README.md` — 이 안내문
- `schema.sql` — `guestbook` 표 SQL (116~124와 **같은 표**) + **페이지네이션 확인용 연습 글 25개**(3페이지 분량)
- `index.html` — 글 목록 + **[이전] / 현재페이지 / [다음]** 버튼이 있는 화면
- `script.js` — **핵심 코드.** `.range(from, to)` 와 `count` 로 페이지를 잘라 오고 버튼을 제어합니다.

## 목표

- `.range(from, to)` 로 표의 **일부 구간(10개)만** 잘라서 가져오는 법을 익힌다.
- `range`가 **0번부터 센다(0-based)** 는 함정을 이해한다. (1페이지 = `range(0, 9)`)
- `.select('*', { count: 'exact' })` 의 **count** 로 전체 개수를 알아내, **총 페이지 수**(`올림(전체 / 10)`)를 계산한다.
- **[이전] / [다음]** 버튼으로 `현재 페이지` 값을 바꾸면 자르는 구간이 옮겨지는 흐름을 체감한다.
- 페이지네이션에는 **`.order()` 가 짝꿍**이라는 점(순서가 고정돼야 1·2페이지가 안 겹친다)을 이해한다.

## 따라하는 단계

1. **표와 연습 글을 준비한다.** Supabase 대시보드 → **SQL Editor → New query** 에 이 폴더의
   `schema.sql`을 통째로 붙여넣고 **[Run]** 을 누른다.
   (116~124에서 `guestbook` 표를 이미 만들었어도 안전하게 다시 실행됩니다. 이 파일은 **연습용 글 25개**를 넣어 3페이지가 되게 해 줍니다.)
2. **글이 11개 이상 있어야 [다음] 버튼이 의미가 있다.** 글이 10개 이하면 한 페이지에 다 나와서 넘길 게 없습니다.
   1단계 연습 글을 넣었는지 확인하세요. (총 25개면 페이지는 1·2·3 세 장)
3. Supabase 대시보드 **Settings(톱니바퀴) → API** 에서 두 값을 복사한다.
   - **Project URL** : `https://xxxxxxxx.supabase.co` 형태의 주소 (비밀 아님)
   - **anon public** 키 (신형은 `sb_publishable_...` 로 시작) : 브라우저에 둬도 되는 **공개 출입증**
   - ⚠️ 같은 화면의 **`service_role` / `sb_secret_...` 키는 절대 쓰지 마세요.** 모든 보안을 무시하는 마스터 키입니다.
4. 이 폴더의 `script.js`를 열고, 맨 위 두 줄의 **자리표시자**를 내 값으로 바꾼다.
   ```js
   const SUPABASE_URL = "https://여기에-내-프로젝트-ID.supabase.co";   // ← 내 Project URL
   const SUPABASE_ANON_KEY = "sb_publishable_여기에-내-anon-공개키-붙여넣기"; // ← 내 anon public 키
   ```
5. `index.html`을 **브라우저로 연다.** (파일을 더블클릭)
   → 페이지가 열리면 **1페이지(최신 글 10개)** 가 보이고, 아래에 **`1 / 3`** 표시가 뜹니다.
6. **[다음 →]** 를 눌러 본다.
   → `range(10, 19)` 로 바뀌면서 **그다음 10개**가 나오고 표시가 **`2 / 3`** 으로 바뀝니다.
   - **첫 페이지**에서는 [← 이전]이, **마지막 페이지**에서는 [다음 →]이 **회색으로 잠겨** 눌리지 않습니다.
7. (이해 점검) `script.js`의 `PAGE_SIZE` 값을 `10` → `5`로 바꾸고 새로고침해 본다.
   → 한 페이지에 5개씩 보이고 총 페이지 수가 **5장**(25 ÷ 5)으로 늘어나면 성공입니다.
   `.range(from, to)`의 `from`·`to`가 페이지에 따라 어떻게 계산되는지 콘솔 로그로도 확인하세요.

## 🤖 바이브코딩 프롬프트

이 실습을 AI에게 시켜서 만들 때, 아래 프롬프트를 그대로 복사해 붙여넣으세요.
순서대로 1단계 → 2단계로 시키고, 막히면 세 번째 프롬프트로 진단을 요청하면 됩니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 초보 친화적인 웹 프론트엔드 강사야. 비전공자가 이해할 수 있게 만들어 줘.
  Supabase 자바스크립트 클라이언트(@supabase/supabase-js v2)를 CDN으로 불러오는
  순수 HTML+JS(빌드 도구 없이 브라우저에서 바로 열리는) 방명록 목록 화면을 만들어 줘.

  요구사항:
  - guestbook 테이블(컬럼: id, name, message, created_at)에서 글을 읽어와 목록으로 보여 줘.
  - created_at 기준 최신순(내림차순)으로 정렬해 줘.
  - 사용자 입력을 화면에 넣을 때는 innerHTML이 아니라 textContent를 써서 XSS를 막아 줘.
  - SUPABASE_URL, SUPABASE_ANON_KEY는 코드 맨 위에 자리표시자로 두고,
    anon(공개) 키와 service_role(비밀) 키의 차이를 주석으로 설명해 줘.
  - 파일은 index.html, script.js 두 개로 나눠 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  위 방명록에 '페이지네이션(10개씩 끊어 보기)' 기능을 추가해 줘.

  - .select('*', { count: 'exact' }) 로 잘라 온 글과 함께 전체 개수(count)도 받아 줘.
  - .range(from, to) 로 한 페이지 분량(PAGE_SIZE=10개)만 잘라서 가져와 줘.
    range는 0부터 세는(0-based) 점을 주석으로 꼭 짚어 줘. (1페이지 = range(0, 9))
  - count로 총 페이지 수 = 올림(전체개수 / PAGE_SIZE) 를 계산해 줘.
  - [← 이전] / "현재 / 전체" 표시 / [다음 →] 버튼을 만들고,
    첫 페이지에서는 [이전], 마지막 페이지에서는 [다음]을 disabled로 잠가 줘.
  - 페이지를 넘길 때마다 목록을 비우고(listEl.innerHTML = "") 다시 그려서
    글이 아래로 중복 누적되지 않게 해 줘.
  - PAGE_SIZE만 바꾸면 한 페이지 개수와 총 페이지 수가 같이 바뀌도록 해 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  방명록 페이지네이션이 동작하지 않아. 아래 정보를 보고 원인을 단계별로 짚어 줘.
  - 증상: (예) 글은 보이는데 항상 '1 / 1'만 나오고 [다음] 버튼이 회색으로 잠겨 있어.
  - 브라우저 콘솔(F12) 에러 메시지: (여기에 빨간 글씨 그대로 붙여넣기)
  - 관련 코드: (script.js의 select/order/range 부분과 updatePager 함수 붙여넣기)
  먼저 가장 가능성 높은 원인부터, 내가 직접 확인할 수 있는 점검 순서로 알려 줘.
  ```
> 프롬프트 팁: 끝에 **"코드만 주지 말고 왜 그렇게 했는지 주석으로 한 줄씩 설명해 줘"** 를 덧붙이면, 결과를 그대로 베끼지 않고 '왜 그런지'까지 배울 수 있어 학습에 훨씬 좋습니다.

## 검증법

- 페이지를 처음 열면 **최신 글 10개**가 보이고 아래에 **`1 / 3`** 이 표시되는가?
- **[다음 →]** 를 누르면 **다음 10개**로 바뀌고 표시가 `2 / 3` → `3 / 3` 으로 올라가는가?
- **마지막 페이지(3 / 3)** 에서 [다음 →] 버튼이 **회색으로 잠겨** 더 안 넘어가는가?
- **첫 페이지(1 / 3)** 에서 [← 이전] 버튼이 **잠겨** 있는가?
- 페이지를 여러 번 넘겨도 글이 **아래로 중복 누적되지 않는가?** (`listEl.innerHTML = ""` 동작 확인)
- 브라우저 **개발자 도구 → Console**(윈도우 `F12`, 맥 `Cmd + Option + I`)에
  `✅ 성공! 전체 N개 중 이 페이지 M개를 받았습니다. (총 K페이지)` 로그가 찍히고,
  `range(0, 9)` → `range(10, 19)` 처럼 **구간이 10칸씩 이동**하는 게 보이는가?
- `PAGE_SIZE`를 바꾸면 **총 페이지 수가 그에 맞게 다시 계산**되는가? (예: 5로 바꾸면 5페이지)
- **실패할 때 원인 찾기** (콘솔의 빨간 에러 메시지로 구분):
  - `relation "public.guestbook" does not exist` → 표가 없음. 1단계 `schema.sql`을 실행.
  - `Invalid API key` → anon 키를 잘못 붙여넣음. (혹시 service_role을 넣지 않았는지도 확인)
  - 주소 오류 / `Failed to fetch` → `SUPABASE_URL`의 철자나 `https://` 확인.
  - **count(전체 개수)가 `null`로 와서 페이지가 1장만 나온다?** → `.select('*', { count: 'exact' })` 처럼
    **두 번째 인자에 `{ count: 'exact' }`** 를 넣었는지 확인. 이게 없으면 전체 개수를 안 줘서 총 페이지를 못 셉니다.
  - **에러는 없는데 목록이 비어 있고 `0 / 1` 로 나온다?** → 표에 **RLS가 켜져 있는데 "읽기(select) 정책"이 없는** 경우입니다.
    받아 올 글 자체가 0개라 페이지가 1장으로 보입니다. (정책 거는 법은 실습 119)
- **(안전 점검)** `script.js`에 넣은 키가 **`anon` / `sb_publishable_`** 로 시작하는가? `service_role` / `sb_secret_` 가 **아닌가?**
