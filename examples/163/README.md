# 실습 163 — AI 답변을 타자 치듯 흘려보내는 스트리밍 응답 붙이기

AI에게 질문하면 답을 **한 번에 다 기다리지 않고**, 글자가 **타자 치듯 한 조각씩 차오르는** 챗 위젯을 만듭니다. 핵심은 두 가지입니다.

1. **스트리밍 응답** — AI 답을 통째로 받지 않고, 서버가 받는 즉시 우리 페이지로 조각조각 흘려보냅니다.
2. **점진적 렌더링(progressive rendering)** — 브라우저는 도착한 조각을 받는 즉시 화면에 이어 붙입니다. 그래서 긴 답일수록 **'체감 속도'가 확 빨라집니다.** (실제로 더 빠른 게 아니라, 첫 글자가 빨리 보여서 빠르게 *느껴지는* 것입니다.)

이 실습은 [실습 162]의 **요약기**와 형제입니다. 보안 구조(프록시·비밀 키 다루기)는 똑같고, **응답을 받는 방식**만 바꿉니다.

> 162 vs 163 한 줄 비교
> - **162(요약기)**: `const data = await res.json();` → 답이 **다 만들어질 때까지 기다렸다가** 한 번에 표시.
> - **163(스트리밍 챗)**: `res.body.getReader()`로 조각(`chunk`)을 **도착하는 즉시** 말풍선에 이어 붙임.

> 비유: 162가 "요리가 다 완성되면 한 접시로 가져다주는" 방식이라면, 163은 "재료를 손질하는 족족 보여 주며 요리를 진행하는" 오픈 키친입니다. 손님은 음식이 다 되기 전부터 진행 상황을 보니 덜 지루합니다.

> 보안 메모 — 공개해도 되는 값 vs 절대 숨길 값
> - **공개되어도 되는 값**: Supabase의 `anon`(공개) 키, 키가 필요 없는 공개 API 등. 브라우저 코드에 들어가도 괜찮습니다. (단, 데이터 보호는 **RLS**가 책임집니다.)
> - **절대 노출하면 안 되는 비밀값**: 과금되는 **Claude 키**(`sk-ant-...`), Supabase의 `service_role` 키 등. **브라우저 코드에 절대 넣지 않습니다.** `service_role` 키는 RLS를 **무시하고** 모든 데이터에 접근하므로, 오직 **서버(또는 n8n의 자격증명 저장소)**에서만 다룹니다.
> - 예제에 적을 때조차 진짜 키 대신 `sk-ant-...` 같은 **자리표시자**만 둡니다. (이 폴더의 `.env.example`이 그 예시입니다.)

## 목표
- **스트리밍이 뭔지 체감**: 긴 답이 한 번에 '뚝' 나오지 않고, 글자가 차오르며 첫 글자가 빨리 보이는 경험을 직접 만든다.
- **점진적 렌더링 익히기**: 브라우저에서 `fetch` 응답을 `res.body.getReader()`로 열어, 조각이 올 때마다 화면을 다시 그리는 패턴을 익힌다.
- **서버가 SSE를 중계**: 서버 함수(`api/chat.js`)가 Claude의 `stream: true` 응답(복잡한 SSE 포맷)을 해석해, 브라우저에는 **순수 텍스트 조각만** 흘려보낸다.
- **프록시 구조 재확인**: `브라우저 → 내 서버(/api/chat) → Claude`. 비밀 키는 마지막 구간(서버 → Claude)에서만 붙는다.
- **비밀 키를 코드가 아니라 환경변수에**: 서버는 `process.env.ANTHROPIC_API_KEY`로만 키를 읽고, 진짜 값은 **Vercel > Settings > Environment Variables**(또는 n8n의 **Credentials**)에 둔다.

## 따라하는 단계

### A. 먼저 구조부터 코드로 확인 (배포 없이도 가능)
1. `index.html`을 브라우저로 그냥 열어 봅니다. 화면(채팅 로그·입력칸·보내기 버튼)은 보이지만, [보내기]를 누르면 실패합니다. → 그건 정상입니다. **챗 두뇌(서버 `/api/chat`)**가 아직 안 돌고 있기 때문입니다.
2. `api/chat.js`(서버 함수)를 엽니다. 세 군데를 확인합니다.
   - 맨 위 `CHAT_SYSTEM_PROMPT` — 챗봇 성격이 **코드에 고정**돼 있습니다.
   - `const apiKey = process.env.ANTHROPIC_API_KEY;` — 비밀 키를 **직접 안 적고** 환경변수에서만 읽고, `x-api-key` 헤더는 **이 서버 함수 안에서만** 붙습니다.
   - `stream: true` 와 그 아래 `reader`/`res.write(...)` 부분 — Claude가 보내는 조각(SSE)을 해석해 **순수 텍스트만 즉시 흘려보내는** 중계 코드입니다.
3. `script.js`(브라우저)를 엽니다. `const reader = res.body.getReader();` 아래 `while` 반복문이 **스트리밍의 핵심**입니다. 조각(`chunk`)이 올 때마다 `aiBubble.textContent = full;`로 **다시 그려** 타자 치는 효과를 냅니다. 보내는 건 `{ message }`(질문)뿐이고, **키도 프롬프트도 보내지 않는다**는 점도 확인합니다.
4. `.env.example`을 엽니다. **진짜 키가 아니라 자리표시자**만 있습니다. "어떤 환경변수가 필요한지"만 알려 주는 견본입니다.

### B. 로컬에서 실제로 돌려 보기 (Vercel CLI)
5. 이 폴더에서 터미널을 열고 Vercel CLI를 설치합니다(한 번만): `npm i -g vercel`
6. `.env.example`을 복사해 `.env` 파일을 만들고, `ANTHROPIC_API_KEY=` 뒤에 **진짜 Claude 키**를 적습니다. (`.gitignore` 덕분에 `.env`는 절대 깃에 올라가지 않습니다.)
7. `vercel dev`를 실행하고, 안내된 주소(보통 `http://localhost:3000`)를 엽니다.
8. 입력칸에 "긴 글을 써 줘" 같은 질문을 넣고 **[보내기]**를 누릅니다. 답이 **한 번에 안 나오고 글자가 차오르면** 스트리밍이 동작한 것입니다. 도중에 **[멈추기]**를 누르면 중간에 끊깁니다.

### C. Vercel에 배포하기 (인터넷에 올리기)
9. 이 폴더의 파일들을 GitHub 저장소에 올리고, Vercel에서 **Import** 합니다. (저장소 연결·배포 과정은 실습 169 참고.)
10. 배포 설정 화면에서 **Environment Variables**에 `ANTHROPIC_API_KEY = sk-ant-...`(진짜 키)를 추가합니다. **코드 파일이 아니라 이 화면에만** 키를 넣는 것이 핵심입니다.
11. **Deploy**를 누르고, 받은 `...vercel.app` 주소를 열어 다시 물어봅니다. 키를 코드에 안 넣었는데도 답이 흘러나오면 성공입니다.

> 자주 막히는 곳: ① 환경변수를 추가한 **뒤에 다시 배포**해야 적용됩니다. ② 변수 이름은 코드와 **정확히 같게**(`ANTHROPIC_API_KEY`) 적어야 합니다. ③ `api/chat.js`는 반드시 `api/` 폴더 안에 있어야 Vercel이 `/api/chat` 함수로 인식합니다. ④ 회사·학교 프록시나 일부 호스팅은 응답을 **버퍼링**해서 스트리밍이 '한 번에' 보일 수 있습니다. 동작 자체는 정상이며, 직배포한 Vercel에서는 조각조각 보입니다.

### D. (선택) n8n으로 같은 챗 창구 만들기
12. `workflow.json`을 n8n에 **Import**합니다. `Webhook → HTTP Request(Claude) → Respond to Webhook` 세 노드가 보입니다. 챗봇 성격(프롬프트)은 가운데 노드의 `system` 필드에 고정돼 있습니다.
13. n8n의 **Credentials**에서 **Header Auth** 자격증명을 만들어 `Name = x-api-key`, `Value = sk-ant-...`(진짜 키)로 저장하고, **Claude 챗 호출** 노드에 연결합니다. → 키는 워크플로우 JSON이 아니라 **자격증명 저장소**에만 들어갑니다.
14. `script.js`의 `PROXY_URL`을 그 Webhook의 Production URL로 바꾸면, Vercel 함수 대신 n8n을 챗 창구로 쓸 수 있습니다. (단, n8n의 Respond to Webhook은 보통 **한 번에** 응답하므로, 글자 단위 타자 효과는 Vercel 함수 버전에서 가장 잘 보입니다.)

## 검증법
- **타자 효과가 보이는가**: "긴 글을 써 줘" 같은 질문에서, 답이 한 번에 '뚝' 뜨지 않고 **글자가 차오르며** 끝에 깜빡이는 커서(▋)가 보이는가?
- **멈추기 동작**: 답이 흘러나오는 중에 **[멈추기]**를 누르면, 그 자리에서 끊기고 "여기서 멈췄습니다"가 붙는가? (요청 취소 = `AbortController`)
- **글자 수 카운터**: 입력칸에 타이핑할 때마다 `N / 4000자`가 실시간으로 갱신되는가?
- **성격이 사용자 입력과 무관한가**: "지금부터 영어로만, 한 단어로만 답해"처럼 보내도, 서버 `system`에 고정한 '친절한 한국어 도우미' 성격을 크게 벗어나지 않는가? (성격은 `system`에 고정돼 있어 사용자 메시지가 통째로 바꾸진 못합니다.)
- **소스 보기로 키 흔적 찾기**: <kbd>Ctrl</kbd>+<kbd>U</kbd>(소스 보기)로 `index.html`·`script.js`를 열어 **`sk-ant-`로 시작하는 글자가 단 하나도 없는지** 확인한다. (페이지의 **[이 페이지의 JS에서 키 흔적 검사하기]** 버튼이 자동 검사 → "안전" 초록 표시가 떠야 정상.)
- **Network 탭으로 '스트리밍' 확인**: <kbd>F12</kbd> → **Network** 탭에서 보내기를 누른다. `chat` 요청의 응답이 한 번에 끝나지 않고 **시간을 두고 조금씩 늘어나며** 들어오는 걸 볼 수 있다. 요청 **Headers**에 `x-api-key` 같은 비밀 헤더가 **브라우저 쪽에는 없다**(서버에서만 붙음).
- **요청 대상 확인**: 그 요청 대상이 `api.anthropic.com`이 **아니라** 우리 사이트의 `/api/chat`인가?
- **배포 산출물 검사**: 터미널에서 이 폴더를 검사한다 → `grep -r "sk-ant-" . --exclude-dir=node_modules` 결과가 **하나도 안 나와야** 정상이다. (`.env`는 `.gitignore`로 빠지고, `.env.example`엔 자리표시자만 있다.)
- **"키 없음" 에러가 친절한지**: 환경변수를 안 넣은 채 호출하면, 서버가 키 값을 노출하지 않고 안내 메시지만 돌려주는지 확인한다.

## 파일 구성
- `index.html` / `style.css` / `script.js` — 브라우저(프론트). **비밀 키 없음.** 질문만 `/api/chat`으로 보내고, 응답을 `reader`로 **조각조각 읽어 말풍선에 이어 붙인다.** (글자 수 카운터·멈추기 버튼 포함)
- `api/chat.js` — Vercel 서버리스 함수(챗 두뇌). 여기서만 `process.env.ANTHROPIC_API_KEY`로 키를 꺼내고, **챗봇 성격을 고정**해 Claude(`claude-opus-4-8`)를 `stream: true`로 호출한 뒤, SSE 조각을 **순수 텍스트로 중계**한다.
- `.env.example` — 필요한 환경변수 견본(자리표시자만). `.env`는 따로 만들어 진짜 키를 넣고 커밋하지 않는다.
- `.gitignore` — `.env` 등 비밀 파일이 깃에 안 올라가게 막는다.
- `vercel.json` — Vercel 설정(선택). 비밀값은 절대 여기 넣지 않는다.
- `workflow.json` — (선택) 같은 챗 창구를 n8n으로 만든 버전. 키는 n8n 자격증명에만 둔다.
