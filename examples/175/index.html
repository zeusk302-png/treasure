Production과 Preview 환경변수 칸 나눠 설정하기

이 화면은 Vercel의 "환경변수(Environment Variables)" 설정 화면을 흉내 낸 연습판입니다. 같은 이름의 키(SUPABASE_URL, SUPABASE_ANON_KEY)라도 Production(실서비스)과 Preview(미리보기)에 서로 다른 값을 넣어 두면, 배포되는 환경에 따라 알맞은 값이 자동으로 쓰입니다. 아래에서 직접 입력해 보고, 환경을 바꿔 가며 "어떤 값이 적용되는지" 눈으로 확인하세요.

⚠️ 이 페이지는 연습용 화면이라 입력한 값이 이 브라우저 안에서만 보입니다(서버로 전송하지 않음). 그래도 습관을 들이기 위해 진짜 비밀값은 절대 넣지 마세요. 여기서 다루는 anon(공개) 키는 공개돼도 되는 출입증이고, service_role(비밀) 키는 마스터 키라서 브라우저 쪽에는 절대 넣지 않습니다.

1) 환경변수 등록 (Settings → Environment Variables)

변수 한 개당 줄 하나입니다. 같은 이름(Key)이라도 적용 범위(Environment)를 다르게 해서 두 줄로 등록하면, 실서비스와 미리보기가 각각 다른 값을 씁니다.

Key (변수 이름) Value (값) Environment (적용 범위)
SUPABASE_URL Production
SUPABASE_ANON_KEY Production
SUPABASE_URL Preview
SUPABASE_ANON_KEY Preview

💡 채울 값이 없으면 "예시 값 채우기" 버튼을 누르세요(자리표시자만 들어갑니다). 진짜 키는 Supabase 대시보드 → Project Settings → API 에서 가져옵니다.

2) 배포 환경을 골라 "적용되는 값" 확인

Vercel은 배포가 어떤 환경인지에 따라 위 표에서 알맞은 값을 골라 씁니다. 아래에서 환경을 바꿔 보세요. 같은 변수 이름인데 값이 바뀌는 게 핵심입니다.

3) 왜 환경을 나눌까? 그리고 무엇을 넣어야 안전할까?

구분Production (실서비스)Preview (미리보기)
언제 쓰이나 기본 브랜치(main) 배포 = 진짜 사용자용 다른 브랜치 / Pull Request 배포 = 테스트용
가리키는 Supabase 진짜 데이터가 있는 실서비스 프로젝트 연습 데이터가 있는 별도 프로젝트
실수로 데이터 지우면? 진짜 고객 데이터 손상 (위험) 연습 데이터라 안전

🔑 두 환경 모두 넣는 건 anon(공개) 키까지만입니다. service_role 비밀 키는 환경을 나누든 말든 브라우저로 내려보내는 변수에는 절대 넣지 않습니다. 공개해도 되는 anon 키가 안전한 이유는, Supabase에서 RLS(행 수준 보안)가 켜져 있어 그 출입증으로는 허용된 데이터만 만질 수 있기 때문입니다.
