# 102. 타이핑 멈춘 뒤 검색 실행하는 디바운스 적용하기

검색창에 글자를 칠 때마다 검색을 실행하면, 빠르게 입력할수록 검색이 수십 번씩 일어납니다. 검색 대상이 데이터베이스나 외부 API라면 그만큼 요청이 쏟아져 느려지고 비용도 듭니다. 이 실습에서는 "타이핑이 멈추고 0.3초가 지나면 그때 딱 한 번만 검색"하도록 만드는 **디바운스(debounce)** 기법을 배웁니다. 화면의 "키를 누른 횟수"와 "실제로 검색을 실행한 횟수"를 비교하면 최적화 효과가 눈으로 보입니다.

## 목표

- `setTimeout`으로 "잠시 뒤에 실행하기"를 예약하는 법을 익힙니다.
- `clearTimeout`으로 "예약을 취소하기"를 익혀, 키를 또 누르면 시계를 처음부터 다시 재게 만듭니다.
- 키 입력마다 매번 실행 vs 멈춘 뒤 한 번 실행의 차이를 카운터로 직접 비교합니다.
- 검색·필터처럼 "자주 일어나는 이벤트를 적당히 솎아내는" 실전 패턴의 기본기를 잡습니다.

## 따라하는 단계

1. `102` 폴더 안에 `index.html`, `style.css`, `script.js` 세 파일이 같은 위치에 있는지 확인합니다.
2. `index.html`을 더블클릭해 브라우저로 엽니다. 검색창, 그 아래 "키를 누른 횟수 / 실제로 검색을 실행한 횟수" 계기판, 맛집 8곳 목록이 보입니다.
3. 검색창에 `파스타`를 **빠르게** 칩니다(쉬지 말고 한 번에). 타이핑하는 동안 안내문이 "입력 중... 멈추면 0.3초 뒤 검색합니다"로 바뀌는지 봅니다.
4. 손을 멈추고 0.3초쯤 기다립니다. 그제서야 목록이 "파스타공방"만 남고, "검색 완료!"로 바뀌며 "실제로 검색을 실행한 횟수"가 1만 올라가는지 확인합니다.
5. "키를 누른 횟수"(예: 3)와 "실제로 검색을 실행한 횟수"(1만 증가)를 비교합니다. 키는 여러 번 눌렀어도 검색은 한 번만 일어난 것이 디바운스입니다.
6. 검색창을 모두 지우고 잠시 기다립니다. 목록 8곳이 다시 전부 나타나는지 확인합니다.
7. `script.js`를 열어 `clearTimeout(timerId)`와 `timerId = setTimeout(runSearch, 300)` 부분의 주석을 천천히 읽어 봅니다. 이 두 줄이 디바운스의 전부입니다.
8. (응용) `setTimeout(runSearch, 300)`의 `300`을 `1000`으로 바꿔 저장하고 새로고침해 봅니다. 이제 멈춘 뒤 1초가 지나야 검색되는지 확인합니다.

## 검증법

- 화면이 처음 뜨면 목록 8곳이 모두 보이고 개수가 "8곳"으로 표시된다. (시작 시 한 번 검색하므로 "실제로 검색을 실행한 횟수"는 1에서 시작한다.)
- `파스타`를 쉬지 않고 빠르게 치면, "키를 누른 횟수"는 3 늘지만 "실제로 검색을 실행한 횟수"는 0.3초 뒤에 단 1만 늘어난다.
- 타이핑하는 도중에는 안내문이 주황색 "입력 중..."이고, 멈추고 0.3초 뒤에 검은색 "검색 완료!"로 바뀐다.
- `파스타` 검색 결과: "파스타공방" 한 곳만 남고 개수가 "1곳"이 된다.
- 대문자/소문자 상관없이 `cafe`나 `CAFE`처럼 적어도 "향기카페"가 같은 결과로 나온다(코드에서 소문자로 맞춰주기 때문).
- `zzz`처럼 없는 글자를 치고 멈추면, 목록이 모두 사라지고 "검색 결과가 없습니다" 안내가 뜬다.
- 글자를 한 자 칠 때마다 검색 횟수가 같이 1씩 오르면 디바운스가 안 걸린 것이다(이 경우 `clearTimeout`/`setTimeout` 부분을 다시 확인한다).

## 더 알아두기

- 디바운스의 한 줄 요약: "이벤트가 들어와도 바로 실행하지 말고, 일정 시간 조용할 때까지 기다렸다가 마지막 한 번만 실행한다."
- `clearTimeout` 없이 `setTimeout`만 쓰면 예약이 쌓여서 결국 모두 실행됩니다. **이전 예약을 취소(clearTimeout)하는 것이 핵심**입니다.
- 비슷하지만 다른 친구로 "스로틀(throttle)"이 있습니다. 디바운스는 "멈출 때까지 기다렸다 한 번", 스로틀은 "일정 간격마다 한 번"입니다. 스크롤·창 크기 조절에는 스로틀이, 검색·자동완성에는 디바운스가 잘 맞습니다.
- 실전에서는 이 검색을 Supabase 같은 데이터베이스 조회로 바꿉니다. 키마다 요청하면 DB가 과부하되지만, 디바운스를 끼우면 사용자가 타이핑을 멈췄을 때만 요청이 나가 훨씬 효율적입니다. 기본 원리는 여기서 익힌 그대로입니다.
