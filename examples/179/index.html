깨진 배포 일부러 만들고 Instant Rollback으로 즉시 되돌리기

고장난 변경을 라이브(Production)에 올려 사이트가 깨졌을 때, 코드를 다시 고치지 않고 Vercel의 Instant Rollback(즉시 되돌리기)으로 직전의 멀쩡한 버전에 클릭 한 번으로 복구하는 흐름의 연습판입니다. 실제 Vercel 대시보드를 흉내 낸 것이라 설치 없이 더블클릭으로 동작합니다.

0) 지금 손님에게 보이는 화면 (Production 미리보기)

이 액자가 곧 실제 라이브 사이트라고 생각하세요. 아래 배포 목록에서 어떤 버전이 라이브냐에 따라 이 화면이 바뀝니다.

My Site

환영합니다 🎉

정상 작동 중인 멀쩡한 페이지입니다.

현재 라이브: v3 (정상) — 사이트가 정상입니다.

1) 일부러 깨진 변경을 라이브에 올리기

실전에서는 "별것 아니겠지" 하고 올린 변경이 사이트를 깨뜨립니다. 여기서는 그 상황을 일부러 만들어 봅니다. 아래 diff가 이번에 올릴 "고장난 변경"입니다. 

index.html (배포할 코드)
  <script>
-   document.getElementById("app").innerText = "환영합니다";
+   document.getElementByID("app").innerText = "환영합니다";  // 오타: ID 대문자
  </script>

getElementById를 getElementByID로 잘못 적었습니다(대소문자 오타). 문법 검사로는 안 걸리지만 브라우저에서 실행되는 순간 페이지가 멈춥니다.

누르면 새 배포 v4가 라이브가 됩니다(그리고 깨집니다).

2) Vercel 대시보드 — 배포 목록(Deployments)

Vercel은 배포할 때마다 이전 버전을 지우지 않고 그대로 보관합니다. 그래서 문제가 생기면 멀쩡했던 과거 버전을 그대로 다시 라이브로 "승격"시킬 수 있습니다 — 이것이 Instant Rollback입니다. 지금 라이브인 배포에는 Current 배지가 붙습니다.

# 배포/롤백할 때 Vercel에서 일어나는 일이 여기에 표시됩니다

3) 결과물 — 롤백으로 정상화된 사이트 + 복구 절차 메모

이번 실습의 결과물(Deliverable)

  • 정상화된 라이브: 손님 화면이 다시 멀쩡한 v3로 돌아옴 (위 0번 액자 확인)
  • 코드 수정 0줄: 오타를 직접 고치지 않고 과거 정상 배포로 되돌리기만 했습니다
  • 복구 절차 메모: 무슨 일이 있었고 어떻게 복구했는지 기록 → recovery-notes.md

핵심: 장애 한복판에서 당황하며 코드를 고치는 대신, 일단 직전 정상 버전으로 즉시 되돌려 사이트부터 살린 뒤, 여유 있게 진짜 원인(오타)을 고쳐 다시 배포하면 됩니다. "되돌리기는 항상 가능하다"는 안전망이 있어야 마음 편히 자주 배포할 수 있습니다.
