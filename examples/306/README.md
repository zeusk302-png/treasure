# 실습 306 — Redis로 조회수 카운터 만들기

블로그 글이나 상품 페이지에 흔히 붙는 **"조회수 1,234회"** 숫자를, 데이터베이스(DB)를 매번 두드리지 않고 **Redis(인메모리 저장소)** 위에서 빠르게 세는 방법을 만들어 봅니다. 핵심 명령어는 단 하나, **`INCR`**(증가). 방문할 때마다 메모리에 있는 숫자를 1씩 올리고, 그 값을 즉시 돌려줍니다. 이 실습으로 "왜 메모리 저장소가 디스크 DB보다 빠른지"를 손으로 만져 봅니다.

> 한 줄 그림: **사용자가 페이지 방문 → 서버 함수 호출 → Redis에 `INCR page:42:views` → 메모리에서 숫자 +1 → 새 조회수를 즉시 응답**

> 비유: DB에 쓰는 건 매번 **창고 깊숙이 들어가 장부에 손글씨로 한 줄 적고 나오는 일**입니다. 사람이 몰리면 창고 문 앞에 줄이 깁니다. Redis는 **계산대 옆에 둔 디지털 카운터기**예요. 손님이 지날 때마다 버튼을 톡 누르면 숫자가 바로 올라갑니다(메모리니까 즉시). 장부(DB)는 한가할 때 몰아서 한 번만 정리하면 됩니다.

> 보안 메모 — 공개해도 되는 값 vs 절대 숨겨야 하는 값
> - **공개되어도 되는 값**: 조회수 숫자 자체, 페이지 키 이름(`page:42:views`). 이건 누가 봐도 안전합니다.
> - **절대 노출하면 안 되는 비밀값**: **Redis 접속 주소·비밀번호(`REDIS_URL`)**. 이 값이 새면 누구나 내 카운터를 조작하거나 데이터를 지울 수 있습니다. 그래서 코드에 박지 않고 **환경변수(`.env`)**에만 두고, `.env`는 `.gitignore`로 깃에서 제외합니다.
> - 이 폴더의 코드 어디에도 진짜 주소는 없습니다. `.env.example`에는 **자리표시자**만 들어 있습니다.

## 목표
- **Redis의 `INCR`로 조회수를 1씩 올린다**: 한 번의 명령으로 "읽고 + 1 더하고 + 저장"이 한꺼번에 일어나는(원자적) 카운터를 만든다.
- **인메모리 저장소가 왜 빠른지 체감한다**: DB(디스크) 쓰기와 Redis(메모리) 쓰기의 속도 차이를 직접 비교해 본다.
- **서버 함수에서 외부 저장소에 안전하게 접속한다**: 접속 주소 같은 비밀값을 코드가 아니라 환경변수에 두는 습관을 만든다.
- **동시 접속에도 숫자가 안 깨지는 이유를 이해한다**: `INCR`가 "원자적(atomic)"이라 여러 사람이 동시에 방문해도 숫자가 빠지지 않는다는 걸 안다.

## 따라하는 단계

### A. 준비물 설치 (Node.js + Redis)
1. **Node.js**가 깔려 있어야 합니다. 터미널에서 `node -v`를 쳐서 버전이 나오면 OK입니다(없으면 nodejs.org에서 설치).
2. **Redis**를 준비합니다. 둘 중 편한 방법을 고르세요.
   - **(쉬움) 클라우드 무료 Redis**: [Upstash](https://upstash.com) 같은 서비스에서 무료 Redis를 하나 만들고, 접속 주소(`redis://...` 또는 `rediss://...`)를 복사합니다.
   - **(직접) Docker로 로컬 Redis**: Docker가 있다면 `docker run -p 6379:6379 redis`를 실행하면 내 컴퓨터에 Redis가 뜹니다. 이때 접속 주소는 `redis://localhost:6379` 입니다.

### B. 프로젝트 세팅
3. 이 폴더(`examples/306`)에서 터미널을 열고 의존성을 설치합니다.
   ```bash
   npm install
   ```
4. `.env.example`을 복사해 **`.env`** 파일을 만들고, A단계에서 받은 **진짜 Redis 주소**를 `REDIS_URL`에 붙여 넣습니다.
   ```bash
   cp .env.example .env
   ```
   - `.env`는 `.gitignore`에 걸려 있어 깃에 올라가지 않습니다(비밀값이라 그렇습니다).

### C. 실행하고 조회수 올려 보기
5. 서버를 켭니다.
   ```bash
   npm start
   ```
   `서버 실행: http://localhost:3000` 같은 안내가 뜨면 성공입니다.
6. 브라우저에서 **http://localhost:3000** 을 엽니다. "조회수: 1"이 보입니다. **새로고침(F5)**할 때마다 숫자가 1씩 오르면 카운터가 동작하는 것입니다.
7. 페이지를 바꿔 가며 세 보기: 주소창에 `http://localhost:3000/?page=hello`, `?page=world`처럼 다른 페이지 이름을 붙이면 **페이지마다 조회수가 따로** 쌓입니다(키가 `page:hello:views`로 분리되기 때문).

### D. "왜 빠른지" 직접 비교해 보기
8. 서버가 켜진 상태에서 **속도 비교** 엔드포인트를 열어 봅니다: **http://localhost:3000/benchmark**
   - 같은 작업(조회수 1,000번 올리기)을 **Redis(메모리)** 방식과 **파일(디스크) 흉내** 방식으로 각각 돌려 걸린 시간(ms)을 보여 줍니다.
   - 보통 Redis 쪽이 훨씬 빠릅니다. "메모리에서 처리하니 빠르다"를 숫자로 확인하는 단계입니다.

## 검증법
- **조회수가 오르는지 확인**: http://localhost:3000 을 열고 **새로고침(F5)**할 때마다 숫자가 1씩 오르면 `INCR`가 잘 동작하는 것이다.
- **페이지별로 따로 세는지 확인**: `?page=a`와 `?page=b`로 들어가면 두 숫자가 **독립적으로** 오른다(키가 분리되기 때문).
- **메모리에 실제로 들어갔는지 확인**: 로컬 Redis라면 `redis-cli`로 `GET page:home:views`를 쳐서 화면 숫자와 같은 값이 나오는지 본다.
- **속도 차이 확인**: http://localhost:3000/benchmark 에서 Redis(메모리)가 디스크 방식보다 **걸린 시간(ms)이 더 작은지** 본다. "메모리라서 빠르다"가 숫자로 보이면 성공이다.
- **비밀값이 코드에 안 보이는지 확인**: `server.js`와 깃에 올라갈 파일들을 열어 **진짜 Redis 주소(`redis://...`의 비밀번호 부분)가 한 글자도 없는지** 본다. 진짜 값은 `.env`(깃 제외)에만 있어야 한다.
  - 점검 명령: `grep -nE "redis://[^/]*:[^@]+@" server.js` → **아무것도 안 나와야** 정상이다(진짜 비밀번호가 코드에 없다는 뜻).

## 파일 구성
- `server.js` — express 서버. `GET /`에서 Redis `INCR`로 조회수를 올려 응답하고, `GET /benchmark`로 메모리 vs 디스크 속도를 비교한다. 비밀값은 `process.env.REDIS_URL`로만 읽는다.
- `package.json` — 의존성(express, redis, dotenv)과 `npm start` 스크립트.
- `.env.example` — 필요한 비밀값 견본(자리표시자만). 복사해 `.env`를 만들고 진짜 Redis 주소는 거기에만 넣는다.
- `.gitignore` — `.env`와 `node_modules`가 깃에 안 올라가게 막는다.
