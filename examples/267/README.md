# 267. n8n 크론으로 매일 아침 대시보드 요약을 메일로 받기

매일 아침 사이트 관리자 페이지에 들어가 "어제 가입 몇 명? 주문 몇 건? 매출 얼마?"를 손으로 확인하는 건 잊기 쉽고 귀찮습니다.

이 실습은 그 일을 기계에 넘깁니다. **매일 정해진 시간(아침 8시)** 에 n8n이 알아서 깨어나, Supabase에서 핵심 지표를 모아 계산하고, 보기 좋은 **요약 메일 한 통**을 보내 줍니다. 알람시계를 맞춰 두면 내가 깜빡해도 알아서 울리는 것과 같습니다.

> 결과물은 한 파일입니다. (아키타입 미니 결과물 — 한 단계로 도는 워크플로우 하나)
> - [`workflow.json`](workflow.json) — n8n에 Import 하면 바로 도는 완성본 (노드 6개)

이 실습은 `orders`(주문) 표와 `users`(가입자) 표가 이미 Supabase에 있다고 가정합니다. 표 이름이나 열 이름이 다르면 워크플로우의 URL만 내 것에 맞게 바꾸면 됩니다.

## 목표

- **크론(스케줄) 트리거**로 매일 아침 8시에 워크플로우가 스스로 깨어나게 한다. (시간 기반 자동화)
- Supabase에서 **오늘 주문**과 **오늘 가입자**를 읽어, **신규 가입 수·주문 수·매출 합계·처리 대기 주문 수**를 한 번에 집계한다.
- 집계 결과를 **카드형 요약 메일**로 만들어 내(또는 팀) 받은편지함으로 보낸다.
- 비밀 키(`service_role`)와 메일 비밀번호를 **워크플로우 JSON에 평문으로 쓰지 않고**, n8n의 환경변수·자격증명에만 두는 안전한 습관을 익힌다.

## 따라하는 단계

### A. n8n에 워크플로우 올리기

1. n8n에 로그인하고 우측 위 **"..." 메뉴 → Import from File** 로 이 폴더의 [`workflow.json`](workflow.json)을 불러온다. 화면에 **노드 6개**가 한 줄로 이어져 보이면 성공이다.
2. **요약 메일 발송 (SMTP)** 노드에서 **Credential(SMTP)** 칸에 내 메일 계정을 연결한다. JSON 속 `REPLACE_WITH_YOUR_SMTP_CREDENTIAL_ID` 는 자리표시자다. 실제 메일 비밀번호는 **n8n > Credentials** 에만 저장하고 JSON에는 절대 적지 않는다.
3. 같은 노드에서 `fromEmail`(`no-reply@your-domain.com`)을 내 발신 주소로, `toEmail`(`REPLACE_WITH_YOUR_REPORT_INBOX@example.com`)을 리포트를 받을 실제 주소로 바꾼다.

### B. 비밀 키를 환경변수로 넣기 (Supabase service_role)

4. Supabase 대시보드 → **Project Settings → API** 에서 **`service_role`** 키를 복사한다. (`anon`(공개) 키가 아니다! 둘을 헷갈리지 말 것 — 아래 표 참고)
5. n8n에서 환경변수 `SUPABASE_SERVICE_ROLE_KEY` 에 그 키를 넣는다. (n8n 클라우드: Variables / 셀프호스트: `.env` 파일) 워크플로우의 `{{ $env.SUPABASE_SERVICE_ROLE_KEY }}` 가 이 값을 자동으로 가져온다.
6. **"오늘 주문 조회"** 와 **"오늘 가입자 조회"** 두 노드의 URL에서 `YOUR_PROJECT_REF` 를 내 Supabase 프로젝트 주소로 바꾼다. (예: `https://abcdwxyz.supabase.co`)

### C. 내 데이터에 맞추기 (표·열 이름)

7. 내 표 이름이 `orders`/`users`가 아니라면, 두 조회 노드 URL의 `/rest/v1/orders`, `/rest/v1/users` 부분을 내 표 이름으로 바꾼다.
8. 매출 칸 이름이 `amount`가 아니거나 상태 칸이 `status`가 아니라면, **"지표 집계 (Code)"** 노드 안의 `amount`·`status` 글자를 내 열 이름으로 바꾼다. (코드에 한 줄씩 한국어 주석이 달려 있다.)

### D. 시간대 맞추기 (중요)

9. 워크플로우 우측 위 **Settings → Timezone** 이 `Asia/Seoul` 인지 확인한다. (이 JSON에는 이미 넣어 두었다.) 서버 기본값은 보통 UTC라서, 시간대를 안 맞추면 한국 아침 8시가 아니라 **새벽 5시**에 메일이 오는 사고가 난다.

### E. 켜기

10. 화면 우측 위 **"Test workflow"** 로 한 번 수동 실행해, 메일이 오는지 확인한다. (크론은 시간이 돼야 자동으로 도므로, 테스트는 이렇게 수동 실행으로 한다.)
11. 잘 되면 우측 위 토글을 **Active(켜짐)** 로 둔다. 이제 매일 아침 8시마다 요약 메일이 자동으로 나간다.

## 🤖 바이브코딩 프롬프트

이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. (n8n 화면에서 직접 노드를 잇기 전에, AI에게 워크플로우 JSON 초안을 받아 Import하면 훨씬 빠릅니다.)

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 n8n 자동화 전문가다. 비전공자도 Import만 하면 도는 n8n 워크플로우 JSON을 만들어 줘.
  목표: 매일 아침 8시(한국 시간, Asia/Seoul)에 자동으로 깨어나, Supabase에서 '오늘 주문'과 '오늘 가입자'를 읽어,
        신규 가입 수·주문 수·매출 합계·처리 대기 주문 수를 집계한 뒤, 요약 메일 한 통을 보낸다.
  노드 구성: ① Schedule(Cron) 트리거 → ② HTTP Request로 orders 조회 + ③ HTTP Request로 users 조회 →
            ④ Merge로 합치기 → ⑤ Code 노드로 지표 집계 → ⑥ Send Email(SMTP)로 발송.
  제약:
   - 시간대는 워크플로우 settings.timezone을 'Asia/Seoul'로 박아 둘 것. (안 그러면 새벽에 메일이 옴)
   - Supabase 비밀 키(service_role)는 JSON에 평문으로 절대 쓰지 말고 {{ $env.SUPABASE_SERVICE_ROLE_KEY }} 환경변수 참조로만 둘 것.
   - SMTP 비밀번호도 JSON에 쓰지 말고 credential ID 자리표시자(REPLACE_WITH_...)만 남길 것.
   - 프로젝트 주소·표 이름·메일 주소는 YOUR_PROJECT_REF 같은 자리표시자로 둘 것.
  산출물: n8n에 Import 가능한 완성 workflow.json 한 개. 각 노드의 notes에 '무엇을·왜' 한국어로 적어 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  위 워크플로우를 개선해 줘.
  1) 메일 본문을 신규 가입 / 오늘 주문 / 오늘 매출 / 처리 대기 주문 네 칸의 '카드형' HTML 표로 보기 좋게 만들어 줘. (모바일에서도 잘 보이게 인라인 style)
  2) 매출 숫자에 천 단위 콤마를 붙여 줘. (예: 1,250,000원)
  3) 오늘 데이터가 0건이어도 에러 없이 모두 0으로 표시되게 해 줘.
  4) 메일 제목에 오늘 날짜가 자동으로 들어가게 해 줘. (예: [일일 리포트] 2026-06-19 대시보드 요약)
  바꾼 부분은 왜 그렇게 했는지 한국어 주석/notes로 설명해 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  n8n에서 이 워크플로우를 Test workflow로 실행했더니 에러가 났어. 아래 에러 메시지를 붙여넣을게.
  (여기에 n8n 실행 화면의 빨간 에러 메시지 전체를 그대로 붙여넣기)
  비전공자가 이해하게 원인을 한 줄로 짚어 주고, 가장 흔한 원인 순서대로 점검 체크리스트를 만들어 줘.
  특히 다음을 확인해 줘: ① Supabase URL의 YOUR_PROJECT_REF를 실제 주소로 바꿨는지, ② service_role 키 환경변수가 비어 있지 않은지,
  ③ 표 이름(orders/users)과 열 이름(amount/status)이 내 DB와 같은지, ④ SMTP 자격증명을 노드에 연결했는지, ⑤ 시간대가 Asia/Seoul인지.
  ```
> 프롬프트 팁: 끝에 "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘"를 덧붙이면, 나중에 표·열 이름이나 시간을 내 손으로 고칠 때 어디를 건드려야 하는지 알 수 있어 학습에 좋습니다.

## 검증법

아래를 모두 만족하면 성공입니다.

- [ ] [`workflow.json`](workflow.json)을 Import 했을 때 노드가 **6개**이고 `Cron → (주문 조회 + 가입자 조회) → Merge → Code(집계) → 메일` 순서로 이어진다.
- [ ] **"Test workflow"** 로 수동 실행하면, 받은편지함에 **`[일일 리포트] (오늘 날짜) 대시보드 요약`** 제목의 메일이 도착한다.
- [ ] 메일 안에 **신규 가입 / 오늘 주문 / 오늘 매출 / 처리 대기 주문** 네 칸이 숫자로 채워져 보인다. (오늘 데이터가 없으면 모두 0으로 보이는 것이 정상)
- [ ] Supabase에 오늘 주문을 한 건 더 넣고 다시 실행하면, 메일의 **주문 수와 매출 숫자가 그만큼 늘어** 있다.
- [ ] 워크플로우 Settings의 **Timezone 이 `Asia/Seoul`** 로 되어 있다. (그래야 한국 아침 8시에 정확히 돈다)
- [ ] [`workflow.json`](workflow.json)을 메모장으로 열었을 때 **실제 `service_role` 키·메일 비밀번호가 평문으로 보이지 않는다.** 키는 `{{ $env.SUPABASE_SERVICE_ROLE_KEY }}`, 메일 비밀번호는 자격증명 ID 자리표시자(`REPLACE_WITH_...`)로만 존재한다.

> ### 보안 한눈에: anon vs service_role
>
> | 키 | 성격 | 어디에 두나 | 이 실습에서 쓰는 곳 |
> |---|---|---|---|
> | `anon` (공개 키) | 브라우저에 노출돼도 되는 **공개** 키. RLS 규칙 안에서만 동작. | 프런트엔드(브라우저) | (여기선 안 씀 — 사이트 화면에서 사용) |
> | `service_role` (비밀 키) | **RLS를 통째로 우회**하는 관리자 키. 노출되면 DB 전체가 위험. | **서버/n8n 환경변수에만** | 오늘 주문·가입자 조회 |
>
> 일일 요약은 *모든 사용자의* 주문·가입을 읽어 합산해야 하므로, RLS(행 수준 보안)를 우회하는 `service_role` 키가 n8n(서버 쪽)에 필요합니다.
> 하지만 이 키는 **브라우저에 절대 넣으면 안 됩니다.** 노출되면 누구나 DB 전체를 읽고 고칠 수 있기 때문입니다.
> 그래서 n8n 환경변수에만 두고, 워크플로우 JSON에는 `$env` 참조만 남깁니다. n8n은 브라우저가 아닌 서버에서 도는 도구라 이 키를 안전하게 쓸 수 있습니다.
