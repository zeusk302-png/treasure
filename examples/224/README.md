# 224. F12 콘솔 에러 전문을 그대로 붙여넣어 고치기

## 목표

브라우저 콘솔(F12)에 뜬 **빨간 에러 메시지를 요약하지 말고 "전문(원문)" 그대로** AI에게 붙여넣고,
**언제·어떻게 하면 똑같이 나는지(재현 절차)** 를 함께 주고,
**"고치기 전에 원인부터 설명해"** 라고 못 박아서 AI의 **추측 수정**을 막는 법을 익힙니다.

"여기 빨간 줄 떴어요, 고쳐주세요"라고만 하면 AI는 코드를 제대로 안 보고 "아마 이 부분일 거예요" 하며
엉뚱한 곳을 바꿉니다. 그러면 에러는 그대로인데 멀쩡하던 다른 부분까지 망가지기 쉽습니다.
**에러 원문 + 재현 절차 + "원인부터"** 라는 세 가지를 주면, AI가 추측 대신 **근거를 짚어** 고치게 됩니다.

이 폴더의 파일은 넷입니다.

- [`broken.html`](broken.html) — **일부러 고장 낸 코드.** 이름을 넣고 버튼을 누르면 콘솔에 빨간 `TypeError`가 납니다. (파일 맨 위 주석에 재현 절차가 적혀 있습니다)
- [`index.html`](index.html) — `broken.html`을 고친 **정상 작동 버전.** (무엇을 고쳤는지 주석으로 표시)
- [`prompt.md`](prompt.md) — 에러 전문 + 재현 절차를 통째로 붙여넣고 "원인부터 설명해"라고 시키는, 그대로 복사하는 지시 프롬프트
- `README.md` — 지금 읽는 이 안내문 (아래에 **원인 → 수정 해설**이 있습니다)

> 이 실습은 **새 앱을 짜는 게 아니라, 에러를 "읽고 옳게 질문하는" 연습**입니다.
> 그래서 결과물도 `에러 원문 → 원인 설명 → 고친 코드`라는 흐름 그대로입니다.

## 따라하는 단계

1. [`broken.html`](broken.html)을 브라우저로 엽니다. (파일을 더블클릭하면 됩니다)
2. **F12**를 눌러 개발자 도구를 열고 위쪽 탭에서 **Console(콘솔)** 을 켭니다.
3. 입력칸에 `철수`라고 적고 **인사하기** 버튼을 누릅니다. 화면엔 인사말이 안 뜨고, 콘솔에 **빨간 줄**이 하나 찍힙니다.
4. 그 **빨간 줄 전체**를 마우스로 드래그해 복사합니다. 보통 이렇게 생겼습니다.
   `Uncaught TypeError: Cannot set properties of null (setting 'textContent')` + 그 아래 `at greet ...` 스택까지 통째로.
   (줄 번호는 환경마다 다를 수 있으니 **메시지 전문**을 그대로 복사하세요.)
5. [`prompt.md`](prompt.md)의 **1단계 틀**을 복사해, `[콘솔 에러 전문]` 자리에 4번에서 복사한 원문을, `[관련 코드]` 자리에 `broken.html` 내용을 통째로 붙여넣습니다. **재현 절차(1·2·3·4)도 함께** 넣습니다.
6. 그 프롬프트를 실제 Claude(또는 쓰는 AI)에 붙여넣습니다. **"고치기 전에 원인부터 설명해"** 가 들어 있는지 꼭 확인합니다.
7. AI가 **원인을 먼저** 짚는지 봅니다. 올바른 답이라면: "`output`이 `null`이다 → `getElementById('greeting')`가 못 찾았다 → **HTML엔 `id`가 `result`뿐이라 `id`가 안 맞았다**" 순서로 거슬러 올라갑니다.
8. 만약 AI가 원인 설명 없이 바로 "이렇게 바꾸세요"만 주면, [`prompt.md`](prompt.md)의 **2단계 한 마디**("코드부터 바꾸지 마. 원인부터 설명해")로 다시 잡습니다.
9. AI가 제안한 수정안을 **사람이 직접 적용**해 봅니다. 핵심은 둘 중 하나로 **id를 일치**시키는 것입니다.
   - 자바스크립트의 `getElementById("greeting")`를 `getElementById("result")`로 바꾸거나, (이 폴더의 정답 방식)
   - 반대로 HTML의 `<p id="result">`를 `<p id="greeting">`로 바꾸기.
10. 고친 페이지를 새로고침하고 다시 버튼을 눌러, **인사말이 뜨고 콘솔에 빨간 에러가 사라졌는지** 확인합니다. 막히면 [`index.html`](index.html)과 비교해 보세요.

## 🤖 바이브코딩 프롬프트

이 실습(콘솔 에러 전문 붙여넣어 고치기)을 AI에게 시킬 때 **그대로 복사해 쓰는** 프롬프트입니다.
주의: 이 실습의 진짜 결과물은 "고친 코드"가 아니라 **"에러를 옳게 질문하는 습관"** 입니다.

- **1단계(뼈대 만들기)** — 일부러 고장 낸 연습용 페이지부터 만들기:
  ```text
  너는 비전공자에게 "콘솔 에러 읽는 법"을 가르치는 강사야.
  연습용으로, 일부러 한 군데만 고장 낸 HTML 한 파일(broken.html)을 만들어줘.
  - 동작: 입력칸에 이름을 적고 "인사하기" 버튼을 누르면 화면에 "OO님, 안녕하세요!"가 떠야 함
  - 버그: 자바스크립트가 getElementById로 찾는 id와, HTML 요소의 id가 서로 안 맞게 해서
    버튼을 누르면 콘솔에 "Cannot set properties of null" 류 TypeError가 나도록 해줘
  - 파일 맨 위 주석에 "이 파일이 무엇이고, 어떤 순서로 누르면 에러가 재현되는지" 절차를 적어줘
  - 외부 라이브러리 없이 순수 HTML/CSS/JS 한 파일로. 한국어 UI.
  왜 그렇게 했는지 주석으로 한 줄씩 설명해줘.
  ```
- **2단계(기능 추가/개선)** — 에러 원문 + 재현 절차로 "원인부터" 시키기:
  ```text
  방금 그 broken.html을 브라우저로 열고 아래 절차로 동작시켰더니 콘솔에 에러가 났어.
  고치기 전에 "원인부터" 설명해줘. 추측하지 말고, 어느 줄에서 왜 나는지 근거를 짚어줘.

  [재현 절차]
  1) broken.html을 브라우저로 연다
  2) F12 > Console(콘솔) 탭을 켠다
  3) 입력칸에 "철수"라고 적고 "인사하기" 버튼을 누른다
  4) 그러면 아래 빨간 에러가 콘솔에 뜬다

  [콘솔 에러 전문 — 한 글자도 빼지 않고 그대로]
  (여기에 F12 콘솔의 빨간 줄 전체 + 그 아래 at ... 스택까지 통째로 붙여넣기)

  [관련 코드 — 문제로 의심되는 파일 전체]
  (여기에 broken.html 내용을 통째로 붙여넣기)

  설명 순서: 1) 에러가 한국어로 무슨 뜻인지 2) 몇 번째 줄의 어떤 값이 null인지
  3) 그 값이 왜 null이 됐는지(근본 원인) 4) 그다음에야 한 군데만 최소로 고치는 수정안.
  ```
- **막혔을 때(디버깅)** — AI가 원인 없이 코드부터 들이밀 때 다시 잡기:
  ```text
  잠깐. 코드부터 바꾸지 마.
  먼저 "이 줄의 이 값이 null이다 → 왜 null인가(어떤 id/선택자가 안 맞는가)"를
  근거와 함께 설명해줘. 원인을 확정한 다음에야 수정안을 보여줘.
  그리고 멀쩡한 다른 부분은 절대 건드리지 말고, 딱 한 군데만 고쳐줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 **왜 그렇게 했는지 주석으로** 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다. 특히 디버깅에선 **"고치기 전에 원인부터"** 한 마디가 AI의 추측 수정을 막는 핵심 장치입니다.

## 검증법

아래를 모두 만족하면 성공입니다.

- [ ] `broken.html`에서 **빨간 콘솔 에러를 실제로 재현**했고, 그 **전문을 요약 없이 통째로** 복사했다.
- [ ] AI에게 줄 때 **재현 절차(언제 터지는지)** 를 함께 주었다.
- [ ] 프롬프트에 **"고치기 전에 원인부터 설명해"** 가 들어 있다(추측 수정 방지).
- [ ] AI가 **원인을 먼저** 설명했다: `output`이 `null` → `getElementById`가 못 찾음 → **id 불일치**라는 근본 원인까지 짚었다.
- [ ] 수정은 **id를 일치**시키는 한 군데 최소 변경이다. (멀쩡한 다른 부분은 안 건드렸다)
- [ ] 고친 뒤 새로고침하면 **인사말이 화면에 뜨고**, 콘솔에 **빨간 에러가 더 이상 안 뜬다.**
- [ ] (보안) 에러 로그에 비밀 값(키·토큰·비밀번호)이 섞였다면 **자리표시자로 가린 뒤** 붙여넣었다.

> 빠른 자가 점검: 고친 `index.html`을 열고 F12 콘솔을 켠 채 버튼을 눌러 보세요.
> **콘솔이 조용하고(빨간 줄 없음) 화면에 "철수님, 안녕하세요!"** 가 뜨면 통과입니다.

## 원인 → 수정 해설 (이 실습의 정답 풀이)

**증상:** 이름을 넣고 버튼을 눌러도 인사말이 안 뜨고, 콘솔에 빨간 줄이 뜸.

```
Uncaught TypeError: Cannot set properties of null (setting 'textContent')
    at greet (broken.html:48)
    at HTMLButtonElement.onclick (broken.html:30)
```

**이 메시지를 한국어로 풀면:**
- `TypeError` = "타입(종류)이 안 맞아서 못 한 작업"이라는 뜻의 에러입니다.
- `Cannot set properties of null (setting 'textContent')` = **`null`(아무것도 없음)** 에다 `textContent`를 넣으려 했다는 뜻입니다.
  즉, 어떤 변수가 **있어야 할 화면 요소 대신 `null`** 을 담고 있었습니다.
- `at greet ...` = 그 일이 `greet` 함수 안에서 일어났다는 위치 표시(스택)입니다.

**근본 원인:** `broken.html`에서
- 자바스크립트는 인사말을 넣을 자리를 `document.getElementById("greeting")` 로 찾습니다.
- 그런데 HTML에는 그 자리가 `<p id="result">` 로 적혀 있습니다. **id가 `greeting`이 아니라 `result`** 입니다.
- 찾는 id(`greeting`)가 화면에 없으니 `getElementById`는 **`null`** 을 돌려줍니다.
- 그 `null`에 `.textContent = ...` 를 하려는 순간 위 `TypeError`가 터집니다.

**수정:** **id를 서로 일치**시키면 됩니다. (이 폴더의 `index.html` 방식)

```js
// broken.html (틀림): HTML에 없는 id를 찾는다 → null
const output = document.getElementById("greeting");

// index.html (고침): HTML의 <p id="result">와 같은 id를 찾는다 → 요소를 제대로 가져옴
const output = document.getElementById("result");
```

**교훈:** `Cannot read/set properties of null` 류 에러는 거의 항상
**"찾으려던 요소를 못 찾았다(보통 id/선택자 오타나 불일치)"** 가 원인입니다.
콘솔이 가리키는 줄을 열고 → 그 줄의 변수가 `getElementById` 결과인지 보고 →
그 id가 **HTML에 진짜 있는지 Ctrl+F로** 찾아보면 대부분 잡힙니다.
