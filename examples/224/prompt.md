# 그대로 붙여넣는 지시 프롬프트 (224. 콘솔 에러 전문을 통째로 붙여넣어 고치기)

> 핵심 원칙: **에러 메시지를 요약하지 말고 "전문(원문)"을 통째로** 붙여넣고,
> **재현 절차**(어떻게 하면 똑같이 나는지)를 함께 줍니다.
> 그리고 **"고치기 전에 원인부터 설명해"** 라고 못 박아 AI의 추측 수정을 막습니다.
> (코드를 안 읽고 "아마 이거겠죠?" 하며 엉뚱한 곳을 바꾸는 걸 막는 장치입니다.)

---

## 1단계 — 에러 원문 + 재현 절차를 통째로 붙여넣기 (원인부터 설명 요청)

아래 틀을 복사해, 대괄호 `[ ]` 부분만 본인 것으로 채워 붙여넣으세요.

```
아래 코드를 브라우저로 열고 다음 절차로 동작시켰더니 콘솔에 에러가 났어.
고치기 전에 "원인부터" 설명해줘. 추측하지 말고, 어느 줄에서 왜 나는지 근거를 짚어줘.

[재현 절차]
1) index.html(또는 broken.html)을 브라우저로 연다
2) F12 > Console(콘솔) 탭을 켠다
3) 입력칸에 "철수"라고 적고 "인사하기" 버튼을 누른다
4) 그러면 아래 빨간 에러가 콘솔에 뜬다

[콘솔 에러 전문 — 한 글자도 빼지 않고 그대로]
Uncaught TypeError: Cannot set properties of null (setting 'textContent')
    at greet (broken.html:48)
    at HTMLButtonElement.onclick (broken.html:30)

[관련 코드 — 문제로 의심되는 파일 전체를 붙여넣기]
(여기에 broken.html 내용을 통째로 붙여넣기)

설명 순서는 이렇게 해줘:
1. 이 에러 메시지가 한국어로 무슨 뜻인지 (TypeError / null / textContent가 뭔지)
2. 정확히 몇 번째 줄에서, 어떤 값이 null이라서 터지는지
3. 그 값이 왜 null이 됐는지(근본 원인)
4. 그다음에야 수정안을 보여줘. (한 군데만 최소로 고치는 방향으로)
```

> 왜 "원인부터"인가: 이렇게 시키면 AI가 `output`이 `null`이라는 사실 →
> `getElementById("greeting")`가 못 찾았다는 사실 → **HTML엔 id가 "result"뿐이라 id가 안 맞았다**는
> 근본 원인까지 거슬러 올라갑니다. 원인을 못 짚으면 수정도 못 믿습니다.

## 2단계 — AI가 원인 설명 없이 바로 "이렇게 바꾸세요"만 줄 때 (다시 잡기)

```
잠깐. 코드부터 바꾸지 마.
먼저 "이 줄의 이 값이 null이다 → 왜 null인가"를 근거와 함께 설명해줘.
원인을 확정한 다음에 수정안을 보여줘.
```

## 3단계 — 같은 종류 에러를 다음에 스스로 읽는 법 (자가 점검 질문)

```
방금 그 TypeError를 일반화해서, 앞으로 "Cannot read/set properties of null" 류 에러를 만나면
사람이 직접 점검할 체크리스트 5줄로 만들어줘. (예: 콘솔이 가리키는 줄 열기, 그 줄의 변수가
getElementById 결과인지 보기, HTML에 그 id가 진짜 있는지 Ctrl+F로 찾기 등)
```

## 붙여넣을 때 지켜야 할 것 (중요)

- **에러는 "요약"하지 말고 원문 그대로.** "널 에러 났어요" 같은 말은 AI가 추측하게 만듭니다.
  `Uncaught TypeError: ...`로 시작하는 **빨간 줄 전체 + 그 아래 at ... 스택**까지 통째로 복사하세요.
- **재현 절차**(1·2·3·4)를 꼭 같이 줍니다. "언제" 터지는지가 원인 추적의 절반입니다.
- **비밀 값은 절대 붙여넣지 않습니다.** 만약 에러 로그에 Supabase `service_role` 키나 비밀번호,
  토큰 같은 게 섞여 있으면 그 부분은 `<여기에-비밀값-가림>` 같은 **자리표시자**로 바꾼 뒤 붙여넣으세요.
  (콘솔 로그를 그대로 복사하다 비밀 키가 새는 일이 실제로 자주 있습니다.)
