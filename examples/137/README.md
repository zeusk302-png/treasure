# 실습 137 — 로그인한 사람의 이메일·가입일 보여주는 '내 프로필' 카드

로그인 기능을 만들었다면, 그다음 궁금한 건 "그래서 **지금 로그인한 사람이 누구냐**"입니다. 이번 실습에서는 Supabase의 `getUser()`로 현재 사용자의 **이메일·가입 시각·user id**를 가져와 마이페이지(`mypage.html`)에 **프로필 카드**로 보여줍니다.

핵심은 단 한 줄, `await db.auth.getUser()` 입니다. 이 함수는 브라우저에 저장된 로그인 세션을 보고 "이 사람은 누구다"라는 정보를 돌려줍니다. 로그인 상태면 `data.user` 안에 정보가 들어 있고, 로그아웃 상태면 `data.user`가 `null`입니다. 우리는 그 값을 꺼내 화면에 예쁘게 그리기만 하면 됩니다.

이번 실습의 결과물은 **내 정보를 보여주는 `mypage.html` 카드**(스타일은 `style.css`, 로직은 `app.js`)입니다.

## 목표
- `await db.auth.getUser()` 한 줄로 **현재 로그인한 사용자 정보를 읽는다**는 걸 이해한다.
- 돌려받은 `user` 객체에서 `email`, `created_at`(가입 시각), `id`(user id) 같은 값을 **꺼내 쓰는 법**을 익힌다.
- `created_at` 같은 날짜 문자열을 `toLocaleString("ko-KR")`로 **사람이 읽기 좋게** 바꾸는 법을 배운다.
- 로그아웃 상태(`data.user`가 `null`)일 때 **카드를 비우고 안내를 보여주는** 분기 처리를 한다.

## 따라하는 단계
1. 앞 실습(131·132)에서 만든 **Supabase 프로젝트**와 **테스트 계정**을 그대로 사용한다. (계정이 없으면 Authentication → Users에서 "Auto Confirm User"를 켜고 하나 추가한다.)
2. 대시보드 → **Settings → API**에서 `Project URL`과 `anon`(publishable) 키를 복사한다.
3. `app.js` 위쪽의 `SUPABASE_URL`, `SUPABASE_ANON_KEY` 두 값을 내 값으로 바꾼다. (코드에 적힌 `https://여기에-...`, `sb_publishable_...`는 자리표시자다.)
4. `mypage.html`을 브라우저로 연다. 아직 로그아웃 상태라 카드 대신 **'🔒 로그인하면 내 프로필이…'** 안내와 데모 로그인 박스가 보인다.
5. 데모 로그인 박스에 테스트 계정으로 **로그인**한다 → 헤더에 이메일이 뜨고, **프로필 카드**에 이메일·가입일·마지막 로그인·user id가 채워진다.
6. 카드에 표시된 **가입일**이 내가 그 계정을 만든 날짜와 맞는지 확인한다.
7. (이해 점검) 개발자도구 → **Console**에서 `await db.auth.getUser()`를 직접 입력해, 우리가 꺼내 쓴 `email`·`created_at`·`id`가 실제 어디에 들어 있는지 눈으로 본다.

## 검증법
- 로그인하면 프로필 카드에 **내 이메일·가입일·user id가 모두** 표시되는가?
- 가입일이 `2026년 6월 17일 14:30` 처럼 **한국어 형식**으로 보기 좋게 나오는가? (날짜 변환이 잘 됐다는 증거)
- 개발자도구 → **Console**에서 `await db.auth.getUser()`를 실행하면, 화면에 표시된 값과 같은 `data.user.email` / `data.user.created_at` / `data.user.id`가 보이는가?
- **로그아웃 상태**(또는 새 시크릿 창)로 열면 카드가 비고 **'🔒 로그인하면…'** 안내가 뜨는가? (`data.user`가 `null`일 때의 처리)
- 로그인한 뒤 **새로고침(F5)** 해도 카드가 그대로 다시 채워지는가? (세션이 유지되므로 `getUser`가 같은 사람을 돌려준다)

## 핵심 한 줄
"지금 누가 로그인했지?"는 `getUser()` 한 줄이면 됩니다.
```js
const { data } = await db.auth.getUser();
if (data.user) {
  console.log(data.user.email);      // 이메일
  console.log(data.user.created_at); // 가입 시각 (ISO 문자열)
  console.log(data.user.id);         // 이 사람의 고유 번호(UUID)
} else {
  // data.user 가 null = 로그인 안 한 상태
}
```

## getUser() vs getSession() — 헷갈리기 쉬운 두 형제
- `getSession()`은 **브라우저에 저장된 세션 그대로**를 빠르게 돌려줍니다. (네트워크 요청 없음 → 빠르지만, 토큰이 진짜 유효한지까지는 확인 안 함)
- `getUser()`는 그 토큰을 **Supabase 서버에 한 번 물어봐서** "이거 진짜 유효한 사용자 맞아?"를 확인한 뒤 사용자 정보를 돌려줍니다. 그래서 **"누가 로그인했는지"를 신뢰성 있게 알고 싶을 때**는 `getUser()`가 더 안전합니다. 이번 프로필 표시처럼 사용자 정보를 화면에 보여줄 때 적합합니다.

## 보안 메모 — anon vs service_role, 그리고 '화면 표시 ≠ 권한'
- 여기 넣는 건 **anon(publishable) 키** 하나뿐입니다. anon 키는 "공개돼도 되는 **출입증**"이라 브라우저·GitHub에 있어도 괜찮습니다. (코드의 `sb_publishable_...`는 자리표시자이니 내 값으로 바꿔 쓰세요.)
- `service_role`(secret) 키는 모든 **RLS(행 수준 보안)를 통째로 우회**하는 마스터키라, 브라우저나 깃허브에 두면 절대 안 됩니다. 오직 서버(n8n·엣지 함수)에서 **환경변수**로만 사용하세요. (코드에 들어가는 비밀값은 언제나 자리표시자로 두고, 실제 값은 서버 환경변수로 주입합니다.)
- 중요: `getUser()`로 받은 **user id를 화면에 보여주는 것**과, 그 사람이 **DB의 어떤 데이터를 볼 수 있는지(권한)** 는 별개입니다. 진짜 권한은 DB의 **RLS 정책**이 `auth.uid()`(= 지금 로그인한 사람의 id)와 행의 주인을 비교해 결정합니다. 즉 프로필 카드에 id를 띄운다고 권한이 생기는 게 아니라, "이 사람이 자기 데이터만 읽도록" 막아주는 건 RLS입니다.
