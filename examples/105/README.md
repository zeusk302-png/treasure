# 검증 통과한 문의 폼을 Supabase에 저장하고 전송 후 피드백 띄우기

이름·이메일·문의 내용을 적고 **[문의 보내기]** 를 누르면, **검증을 통과한 값만** 인터넷 너머의 데이터베이스(Supabase)에 저장하는 진짜 문의 폼입니다.
저장하는 동안에는 버튼 안에서 **동그라미 스피너가 빙글빙글** 돌고, 끝나면 **초록색(성공) 또는 빨간색(실패) 메시지**가 뜹니다.

> 비유: 우체국 창구에 편지를 내는 것과 같습니다.
> 먼저 직원이 주소(이메일)와 내용이 제대로 적혔는지 확인하고(검증), 통과하면 편지를 접수합니다(저장).
> 접수하는 동안 "처리 중입니다" 표시가 뜨고(로딩), 끝나면 접수 번호가 적힌 영수증(성공 메시지)을 줍니다.

지금까지의 실습은 모두 **내 컴퓨터 안에서만** 동작했지만, 이번에는 처음으로 **인터넷 너머 서버에 데이터를 보내 저장**합니다.

## 목표

- 직접 만든 검증(이름·이메일 형식·10자 이상)을 통과한 값만 서버로 보내는 흐름을 익힌다.
- `supabase.createClient(...)`로 데이터베이스에 연결하고, `.from('contacts').insert([...])`로 한 줄을 저장하는 법을 배운다.
- `async`/`await`로 **"서버에 보내고 답이 올 때까지 기다린다"** 는 비동기 흐름을 이해한다.
- 저장하는 동안 **로딩 스피너**를 돌리고 버튼을 잠가 **중복 제출(연타)** 을 막는 법을 익힌다.
- `try / catch / finally`로 성공·실패·네트워크 오류를 각각 **다른 메시지**로 안내한다.
- 공개해도 되는 키(anon)와 절대 숨겨야 할 키(service_role)의 차이를 안다.

## 따라하는 단계

1. 이 폴더(`105`)의 `index.html`, `style.css`, `script.js` 세 파일을 같은 폴더에 둡니다. (이미 준비되어 있습니다.)
2. [Supabase](https://supabase.com)에 가입하고 새 프로젝트를 하나 만듭니다. 그리고 데이터를 담을 표(테이블) `contacts`를 만듭니다. 이 표에는 `name`, `email`, `message` 칸이 있어야 합니다. (칸 이름이 `script.js`와 똑같아야 저장됩니다.)
3. Supabase 대시보드에서 **Settings → API** 로 들어가 두 값을 복사합니다.
   - **Project URL**: 내 데이터베이스의 인터넷 주소 (비밀 아님)
   - **anon public key**: 손님 자격으로 들어가는 공개 출입증 (브라우저에 박아도 됨)
4. `script.js` 맨 위의 두 줄에서 `여기에-내...` 로 된 **자리표시자**를 방금 복사한 내 진짜 값으로 바꿉니다.
   - `SUPABASE_URL = "..."`
   - `SUPABASE_ANON_KEY = "..."`
5. `index.html`을 더블클릭해 브라우저로 엽니다. 흰 카드 안에 이름·이메일·문의 내용 입력칸이 보입니다.
6. **빈 칸인 채로 [문의 보내기]** 를 눌러 봅니다. 빨간 안내 문구가 뜨고, **서버로 보내지 않고 멈추는지** 확인합니다. (검증이 먼저 막아 주는 것입니다.)
7. 이름을 적고, 이메일은 `example@email.com`처럼, 문의 내용은 **10자 이상** 채운 뒤 [문의 보내기]를 누릅니다. 버튼에 스피너가 잠깐 돌고 **초록색 성공 메시지(접수 번호 포함)** 가 뜨면 성공입니다.
8. Supabase 대시보드의 **Table Editor → contacts** 표를 새로고침해, 방금 보낸 내용이 한 줄로 들어와 있는지 눈으로 확인합니다.
9. `script.js`를 열어 주석을 따라 읽으며 `validateForm`(검증) → `setLoading(true)`(로딩) → `await ...insert()`(저장) → 성공/실패 메시지 → `finally`에서 로딩 끄기로 이어지는 흐름을 따라갑니다.

## 🤖 바이브코딩 프롬프트

이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. 한 번에 다 시키지 말고 **단계로 쪼개서** 시키는 것이 핵심입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 프런트엔드 멘토야. 비전공자가 이해할 수 있게 만들어 줘.
  HTML/CSS/순수 자바스크립트(프레임워크 없이)로 '문의하기 폼'을 만들어 줘.
  - 입력칸: 이름(text), 이메일(email), 문의 내용(textarea), 그리고 [문의 보내기] 버튼
  - 디자인: 화면 가운데 흰 카드, 둥근 모서리, 은은한 그림자, 모바일에서도 안 깨지게
  - 아직 서버 저장은 하지 말고, 버튼을 누르면 콘솔에 입력값만 찍어 줘
  파일은 index.html / style.css / script.js 세 개로 나눠 주고,
  코드만 주지 말고 왜 그렇게 했는지 한 줄씩 한국어 주석으로 설명해 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  앞에서 만든 문의 폼에 아래 기능을 순서대로 더해 줘.
  1) 직접 검증: 이름 비어 있으면 안 됨, 이메일은 정규식으로 형식 검사,
     문의 내용은 10자 이상. 틀린 칸은 빨간 테두리 + 아래에 안내 문구.
     검증을 통과 못 하면 서버로 보내지 말고 멈춰.
  2) Supabase 저장: @supabase/supabase-js(CDN)로 createClient를 만들고,
     검증 통과한 값만 .from('contacts').insert([...])로 한 줄 저장.
     async/await와 try/catch/finally로 감싸 줘.
  3) 전송 피드백: 저장하는 동안 버튼을 잠그고 스피너를 돌리고(중복 제출 방지),
     끝나면 성공이면 초록, 실패면 빨강 결과 박스를 보여 줘. finally에서 로딩은 꼭 꺼.
  SUPABASE_URL과 anon 키는 코드에 자리표시자로 두고, 'anon 키는 공개돼도 되는 이유'를
  주석으로 적어 줘. 비전공자가 이해하게 각 단계를 한 줄씩 풀어서 주석으로 설명해 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  문의 폼에서 [문의 보내기]를 눌렀는데 저장이 안 돼.
  브라우저 콘솔(F12)에 이런 메시지가 떠: (여기에 빨간 에러 메시지를 그대로 붙여넣기)
  내 script.js와 contacts 표 구조도 같이 보여 줄게: (코드/표 칸 이름 붙여넣기)
  무엇이 문제인지 (1) URL/키 오타 (2) 표·칸 이름 불일치 (3) RLS 쓰기 권한 막힘
  중 어디에 해당하는지 하나씩 짚어 주고, 비전공자가 따라 할 수 있게 해결 순서를 알려 줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 **왜 그렇게 했는지 주석으로 설명해줘**", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 결과 코드가 그대로 학습 자료가 됩니다.

## 검증법

- **검증이 먼저 막는다**: 빈 칸이거나 이메일 형식이 틀리거나 문의가 10자 미만이면 빨간 메시지가 뜨고 서버로 가지 않는다.
- **로딩 표시**: 보내는 동안 버튼 글자가 "보내는 중…"으로 바뀌고 스피너가 돌며, 버튼이 잠겨 다시 눌리지 않는다.
- **성공**: 저장이 끝나면 **초록 박스**에 접수 번호가 뜨고, 입력칸이 비워진다. Supabase의 `contacts` 표에 새 줄이 실제로 추가된다.
- **자리표시자 안내**: `script.js`의 URL/키를 안 바꾸면, 서버에 보내기 전에 "아직 내 프로젝트 값이 입력되지 않았어요"라는 친절한 빨간 메시지가 먼저 뜬다.
- **실패 처리**: 인터넷을 끄거나 표 이름·칸 이름이 다르면 **빨간 박스**에 실패 메시지가 뜬다. 이때도 로딩은 반드시 꺼진다(`finally`).
- **콘솔 확인**: F12 → Console 탭에서 `⏳ 저장하는 중…` → `✅ 저장 성공!`(또는 `❌` 오류) 로그를 볼 수 있다. 빨간 오류가 있다면 표/칸 이름 또는 키 값을 다시 확인한다.

> 참고: 저장이 실패한다면 대부분 (1) `script.js`의 URL/키 오타, (2) `contacts` 표가 없거나 칸 이름이 다름, (3) 쓰기 권한(RLS 정책)이 막혀 있음 — 이 세 가지 중 하나입니다.
