# 실습 161 — 비밀 API 키를 프론트에 안 박고 서버로 숨기기 (프록시)

AI에게 질문을 보내면 답을 받아 주는 페이지를 만듭니다. 단, **비밀 키는 브라우저 코드에 한 글자도 두지 않습니다.** 브라우저는 Claude를 직접 부르는 대신, 우리가 만든 **서버 '중간 창구'**(Vercel 서버리스 함수 `/api/ask`, 또는 n8n 웹훅)에만 부탁하고, 진짜 키는 **서버 안에서만** 쓰입니다.

이 실습의 진짜 핵심은 한 가지 깨달음입니다.
> **브라우저 코드는 누구나 들여다볼 수 있다.** `F12`(개발자도구)나 '소스 보기'로 `index.html`·`script.js`를 그대로 읽을 수 있어서, 거기에 과금되는 AI 키를 박으면 **그 즉시 도둑맞아 요금 폭탄**이 납니다. 그래서 비밀 키는 코드가 아니라 **서버(또는 n8n)의 환경변수/자격증명**에만 두고, 브라우저는 키 없이 **우리 서버 창구**에만 부탁합니다.

> 비유: 비싼 금고 열쇠를 가게 **유리 진열장 안**(브라우저)에 걸어 두면 누구나 봅니다. 대신 **창구 직원**(서버)에게 "이거 좀 처리해 주세요"라고 부탁하면, 열쇠는 직원 **뒷주머니**(환경변수)에만 있고 손님은 결과만 받습니다. 프록시(proxy)가 바로 이 '대신 처리해 주는 창구'입니다.

> 보안 메모 — 공개해도 되는 값 vs 절대 숨겨야 하는 값
> - **공개되어도 되는 값**: Supabase의 `anon`(공개) 키, 키가 필요 없는 공개 API 등. 브라우저 코드에 들어가도 괜찮습니다. 단, 데이터 보호는 **RLS(행 수준 보안)**가 책임집니다. anon 키만 믿고 RLS를 끄면 누구나 데이터를 읽고 쓸 수 있어 위험합니다.
> - **절대 노출하면 안 되는 비밀값**: 과금되는 **AI(Claude) 키**, Supabase의 `service_role` 키 등. **브라우저 코드에 절대 넣지 않습니다.** `service_role` 키는 RLS를 **무시하고** 모든 데이터에 접근하므로, 오직 **서버(또는 n8n 같은 자동화 도구의 자격증명 저장소)**에서만 다룹니다.
> - 예제에 적을 때조차 진짜 키 대신 `sk-ant-...` 같은 **자리표시자**만 둡니다. (이 폴더의 `.env.example`이 그 예시입니다.)

## 목표
- **왜 위험한지 체감**한다: 브라우저 코드에 키를 박으면 `F12`로 그대로 보인다는 사실을, 직접 소스 보기/Network 탭으로 확인한다.
- **프록시(중간 창구) 구조를 이해**한다: `브라우저 → 내 서버(/api/ask) → Claude`. 비밀 키는 마지막 구간(서버 → Claude)에서만 붙는다.
- **키를 코드가 아니라 환경변수에 둔다**: 서버 함수는 `process.env.ANTHROPIC_API_KEY`로만 키를 읽고, 진짜 값은 **Vercel > Settings > Environment Variables**(또는 n8n의 **Credentials**)에 넣는다.
- **"키가 빌드 산출물에 안 보인다"를 검증**한다: 배포된 정적 파일과 네트워크 요청 어디에도 `sk-ant-` 가 없음을 확인한다.
- (선택) **같은 일을 n8n으로도** 할 수 있음을 안다: `workflow.json`은 Vercel 함수와 똑같은 창구를, n8n 웹훅 + HTTP 요청으로 구현한 버전이다.

## 따라하는 단계

### A. 먼저 구조부터 코드로 확인 (배포 없이도 가능)
1. 이 폴더의 `script.js`를 엽니다. 맨 위 주석의 **❌ 나쁜 예**(브라우저에 `sk-ant-` 키를 박는 코드)와 **✅ 올바른 예**(`PROXY_URL = "/api/ask"` 로만 부탁)를 비교해 봅니다.
2. `api/ask.js`(서버 함수)를 엽니다. 비밀 키를 **직접 적지 않고** `const apiKey = process.env.ANTHROPIC_API_KEY;` 로 읽는 부분, 그리고 `x-api-key` 헤더가 **이 서버 함수 안에서만** 붙는 부분을 확인합니다.
3. `.env.example`을 엽니다. 여기에는 **진짜 키가 아니라 자리표시자**만 있습니다. "어떤 환경변수가 필요한지"만 알려 주는 견본입니다.

### B. 로컬에서 실제로 돌려 보기 (Vercel CLI)
4. 이 폴더에서 터미널을 열고 Vercel CLI를 설치합니다(한 번만): `npm i -g vercel`
5. `.env.example`을 복사해 `.env` 파일을 만들고, `ANTHROPIC_API_KEY=` 뒤에 **진짜 Claude 키**를 적습니다. (`.gitignore` 덕분에 `.env`는 절대 깃에 올라가지 않습니다.)
6. `vercel dev` 를 실행합니다. 브라우저에서 안내된 주소(보통 `http://localhost:3000`)를 엽니다.
7. 입력칸에 질문을 두고 **[서버 창구에 부탁하기]**를 누릅니다. 잠시 뒤 AI 답이 뜨면, "브라우저 → 내 서버 → Claude" 경로가 동작한 것입니다.

### C. Vercel에 배포하기 (인터넷에 올리기)
8. 이 폴더의 파일들을 GitHub 저장소에 올리고, Vercel에서 **Import** 합니다. (저장소 연결·배포 과정은 실습 169 참고.)
9. 배포 설정 화면에서 **Environment Variables**에 `ANTHROPIC_API_KEY = sk-ant-...`(진짜 키)를 추가합니다. **코드 파일이 아니라 이 화면에만** 키를 넣는 것이 핵심입니다.
10. **Deploy**를 누르고, 받은 `...vercel.app` 주소를 열어 다시 질문해 봅니다. 키를 코드에 안 넣었는데도 정상 작동하면 성공입니다.

> 자주 막히는 곳: ① 환경변수를 추가한 **뒤에 다시 배포**해야 적용됩니다(변수만 추가하고 재배포 안 하면 "키 없음" 에러가 납니다). ② 변수 이름은 코드와 **정확히 같게**(`ANTHROPIC_API_KEY`) 적어야 합니다. ③ `api/ask.js`는 반드시 `api/` 폴더 안에 있어야 Vercel이 `/api/ask` 함수로 인식합니다.

### D. (선택) n8n으로 같은 창구 만들기
11. `workflow.json`을 n8n에 **Import**합니다. `Webhook → HTTP Request(Claude) → Respond to Webhook` 세 노드가 보입니다.
12. n8n의 **Credentials**에서 **Header Auth** 자격증명을 새로 만들어 `Name = x-api-key`, `Value = sk-ant-...`(진짜 키)로 저장하고, **Claude 호출** 노드에 연결합니다. → 키는 워크플로우 JSON이 아니라 **자격증명 저장소**에만 들어갑니다.
13. `script.js`의 `PROXY_URL`을 그 Webhook의 Production URL로 바꾸면, Vercel 함수 대신 n8n을 프록시로 쓸 수 있습니다.

## 검증법
- **소스 보기로 키 흔적 찾기**: 페이지에서 `Ctrl`+`U`(소스 보기)로 `index.html`을, `script.js`를 직접 열어 **`sk-ant-` 로 시작하는 글자가 단 하나도 없는지** 확인한다. (페이지의 **[이 페이지의 JS에서 키 흔적 검사하기]** 버튼이 이걸 자동으로 해 준다 → "안전" 초록 표시가 떠야 정상.)
- **Network 탭 확인**: `F12` → **Network** 탭을 열고 버튼을 누른다. `ask` 요청이 보이는데, 그 요청 **Headers**를 펼쳐도 `x-api-key` 같은 **비밀 헤더가 브라우저 쪽에는 없다**(그 헤더는 서버에서만 붙는다). 응답 본문에도 키가 없다.
- **요청 대상 확인**: 그 `ask` 요청의 대상이 `api.anthropic.com`이 **아니라** 우리 사이트의 `/api/ask` 인지 본다. (브라우저는 Claude를 직접 부르지 않는다.)
- **배포 산출물 검사**: 배포된 파일을 모두 뒤져도 키가 없어야 한다. 터미널에서 이 폴더를 검사해 본다:
  - `grep -r "sk-ant-" . --exclude-dir=node_modules` → **나오는 게 없어야** 정상이다. (`.env`는 `.gitignore`로 빠지고, `.env.example`엔 자리표시자만 있다.)
- **"키 없음" 에러가 친절한지**: 환경변수를 안 넣은 채 호출하면, 서버가 키 값을 노출하지 않고 "ANTHROPIC_API_KEY 환경변수가 없습니다 …" 안내만 돌려주는지 확인한다.
- **에러에도 키가 안 새는지**: 일부러 잘못된 키를 넣어 실패시켜 본다. 화면 에러 메시지에 **키 값 자체가 절대 찍히지 않아야** 한다.

## 파일 구성
- `index.html` / `style.css` / `script.js` — 브라우저(프론트). **비밀 키 없음.** `/api/ask` 창구에만 부탁한다.
- `api/ask.js` — Vercel 서버리스 함수(중간 창구). 여기서만 `process.env.ANTHROPIC_API_KEY`로 키를 꺼내 Claude(`claude-opus-4-8`)를 호출한다.
- `.env.example` — 필요한 환경변수 견본(자리표시자만). `.env`는 따로 만들어 진짜 키를 넣고 커밋하지 않는다.
- `.gitignore` — `.env` 등 비밀 파일이 깃에 안 올라가게 막는다.
- `vercel.json` — Vercel 설정(선택). 비밀값은 절대 여기 넣지 않는다.
- `workflow.json` — (선택) 같은 창구를 n8n으로 만든 버전. 키는 n8n 자격증명에만 둔다.
