# CLAUDE.md — 이 프로젝트의 "항상 켜져 있는 메모"

> 이 파일은 AI(Claude 등)가 **이 폴더에서 일을 시작할 때 자동으로 먼저 읽는 메모**입니다.
> 매번 채팅창에 "우리 스택은 ~야, 비밀 키는 절대 노출하지 마" 라고 반복하지 않도록,
> **한 번 적어 두면 계속 적용되는 규칙집**입니다. 짧고 분명하게 적는 것이 핵심입니다.
> (아래 값들은 예시이니, 내 프로젝트에 맞게 바꿔 쓰세요.)

---

## 1. 이 프로젝트가 무엇인가

- 한 줄 소개: 정적 웹(HTML/CSS/JS) + Supabase(데이터) + Vercel(배포)로 만드는 소규모 서비스.
- 나는 **디렉터**입니다. 코드를 손으로 다 짜기보다, AI에게 **무엇을·왜·어떤 기준으로** 만들지 지시하고, 결과를 **검증·승인**합니다.

## 2. 우리 기술 스택 (여기서 벗어나지 말 것)

- 프론트엔드: **순수 HTML / CSS / JavaScript** (별도 프레임워크 없음)
- 데이터베이스/인증: **Supabase**
- 배포: **Vercel** (main 브랜치에 push하면 자동 배포)
- 자동화: **n8n** (웹훅·스케줄 기반)
- AI: **Claude** (이 작업환경)

> 규칙: 위 스택으로 해결되는 일은 새 라이브러리를 끌어오지 말 것. 꼭 필요하면 **먼저 이유를 설명하고 나(디렉터)의 승인**을 받을 것.

## 3. 보안 규칙 (가장 중요 — 절대 어기지 말 것)

키는 **공개해도 되는 것**과 **절대 숨겨야 하는 것** 두 종류가 있습니다.

| 종류 | 예시 이름 | 어디에 두나 | 브라우저(공개 코드)에 노출 |
|---|---|---|---|
| 공개 키 (anon / publishable) | `SUPABASE_ANON_KEY` | 프론트엔드 코드에 있어도 됨 | 가능 (단, **RLS가 켜져 있어야** 안전) |
| 비밀 키 (service_role / secret) | `SUPABASE_SERVICE_ROLE_KEY` | **서버/환경변수에만** (n8n, Vercel 환경변수 등) | **절대 금지** |

- **anon 키**는 출입증과 같아서 공개돼도 됩니다. 단, 그 자체로는 아무거나 못 보게 **Supabase에서 RLS(행 수준 보안)를 반드시 켤 것.**
- **service_role 키**는 마스터 키입니다. RLS를 무시하고 모든 데이터를 읽고 지울 수 있으므로 **프론트엔드 코드·깃 저장소·채팅창에 절대 적지 말 것.**
- 이 저장소에 올라가는 어떤 예시 코드에도 **진짜 키를 적지 말 것.** 반드시 `REPLACE_WITH_...` / `YOUR_API_KEY` 같은 **자리표시자**로만 둘 것.
- `.env`, `*.local`, `*-secret.*` 파일은 **커밋 금지.** (`.gitignore`에 들어 있어야 함)
- 사용자 입력은 화면에 그대로 넣지 말 것(XSS). `textContent`로 넣거나 이스케이프할 것.

## 4. 작업 방식 (어떻게 일을 시킬지)

1. **기획 먼저.** 코드를 짜기 전에, "무엇을 / 성공 기준은 / 엣지 케이스는" 을 짧은 사양서로 먼저 정리한다. → `feature-spec` 스킬 사용.
2. **작게 만든다.** 한 번에 한 기능. 큰 변경은 단계로 쪼갠다.
3. **외부 동작 전 사람 승인.** 파일 삭제, DB 쓰기, PR 코멘트 달기, 배포 같은 **되돌리기 어려운 동작은 먼저 무엇을 할지 보여주고**, 내 "진행해" 한 마디를 받은 뒤 실행한다.
4. **검증 후 보고.** "완벽합니다" 금지. "예/아니오 + 근거(파일:줄)" 로 보고하고, 확실하지 않으면 "확실하지 않음"이라고 솔직히 말한다.

## 5. 코드 스타일

- 들여쓰기 2칸, 한글 주석 환영.
- 함수·변수 이름은 하는 일이 드러나게.
- 새 파일을 만들기 전에 비슷한 기존 파일이 있는지 먼저 확인하고 재사용한다.

## 6. 자주 쓰는 스킬·도구 (이 작업환경의 구성)

- `feature-spec` 스킬 → 기획(사양서 만들기). `.claude/skills/feature-spec.md`
- `security-review` 스킬 → 보안리뷰(배포 직전 점검). `.claude/skills/security-review.md`
- GitHub MCP → 내 PR을 AI가 직접 읽고 코드리뷰. 설정 예시: `.claude/mcp.example.json`
- Supabase MCP → 내 DB를 AI가 직접 조회(읽기 위주, 최소 권한). 설정 예시: `.claude/mcp.example.json`

> 기획 → 작업 → 보안리뷰 → 배포. 이 순서가 이 작업환경의 기본 흐름입니다.
