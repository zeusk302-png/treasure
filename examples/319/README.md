# 실습 319 — CSS 애니메이션으로 부드러운 등장 효과 만들기

페이지를 스크롤하다 보면 카드나 글이 **아래에서 슬며시 떠오르며 나타나는** 화면을 본 적이 있을 겁니다. 이번 실습에서는 그 "등장 애니메이션"을 직접 만듭니다. **CSS의 transition/animation**으로 움직임을 정의하고, **IntersectionObserver**(요소가 화면에 들어왔는지 감시하는 브라우저 기능)로 "화면에 보일 때만" 그 움직임을 켭니다. 마지막으로 **`prefers-reduced-motion`**(사용자가 운영체제에서 "움직임 줄이기"를 켠 경우)을 존중해, 멀미·어지럼증이 있는 사람에게는 과한 모션을 자동으로 꺼 주는 **배려**까지 넣습니다.

> 한 줄 그림: **사용자가 스크롤 → IntersectionObserver가 "이 카드가 화면에 들어왔다"를 감지 → 그 카드에 `is-visible` 클래스를 붙임 → CSS transition이 "투명+아래" 상태에서 "선명+제자리"로 부드럽게 이동 → 움직임 줄이기를 켠 사용자에겐 애니메이션 없이 즉시 표시**

> 비유: 등장 애니메이션은 무대의 **조명**입니다. 배우(카드)가 무대 가장자리(화면 아래)에서 대기하다가, **무대 중앙에 들어서는 순간**(화면에 보이는 순간) 조명이 부드럽게 켜집니다. IntersectionObserver는 "배우가 무대에 들어왔는지" 지켜보는 **무대 감독**이고요. 그런데 객석에 **밝은 빛에 약한 관객**이 있다면(움직임에 민감한 사용자), 감독은 조명 쇼를 생략하고 그냥 불을 켭니다. 그게 `prefers-reduced-motion` 배려입니다.

> 접근성 메모 — 왜 "움직임 줄이기"를 존중해야 하나
> - 화려한 등장·시차(parallax)·자동 회전 같은 모션은 **전정기관이 예민한 사람에게 멀미·어지럼증·두통**을 유발할 수 있습니다. 그래서 운영체제에는 "동작 줄이기" 설정이 있고, 브라우저는 그걸 `prefers-reduced-motion: reduce` 미디어쿼리로 알려 줍니다.
> - 이 실습의 CSS는 **기본은 애니메이션 ON**, 단 사용자가 줄이기를 켰으면 **즉시 보이게(애니메이션 OFF)** 바꿉니다. "예쁨"보다 "모두가 어지럽지 않게 보는 것"이 우선이기 때문입니다.

## 목표
- **CSS만으로 부드러운 움직임**을 정의한다: `opacity`와 `transform`을 `transition`으로 묶어, 등장 시 자연스럽게 떠오르게 한다.
- **"화면에 보일 때만" 애니메이션을 켠다**: `IntersectionObserver`로 요소가 뷰포트에 들어오는 순간을 감지해 클래스를 토글한다. (스크롤 이벤트를 직접 듣는 옛 방식보다 가볍고 정확하다.)
- **모션 접근성을 지킨다**: `prefers-reduced-motion: reduce`를 감지해, 움직임에 민감한 사용자에게는 애니메이션을 끄고 즉시 표시한다.
- **JS 없이도 깨지지 않게 한다**: 자바스크립트가 막혀도 내용은 보이도록(점진적 향상) 설계한다.

## 따라하는 단계

### A. 파일 열고 구조 보기
1. 이 폴더의 `index.html`을 브라우저로 엽니다(더블클릭이면 충분합니다 — 서버가 필요 없습니다).
2. 코드는 세 부분입니다: **HTML**(등장시킬 카드들), **`style.css`**(움직임을 정의), **`script.js`**(언제 켤지 결정). 각 파일 맨 위 요약 주석을 먼저 읽으세요.

### B. "처음엔 숨김, 보이면 등장" 원리 이해하기
3. `style.css`에서 `.reveal` 클래스는 **처음 상태**(투명 + 아래로 24px 내려가 있음)를, `.reveal.is-visible`은 **목표 상태**(선명 + 제자리)를 정의합니다.
4. 둘 사이를 잇는 `transition`이 그 변화를 **0.6초 동안 부드럽게** 보여 줍니다. 즉 "숨김 → 보임"으로 클래스가 바뀌는 순간 애니메이션이 일어납니다.

### C. IntersectionObserver로 "보이는 순간" 잡기
5. `script.js`는 `IntersectionObserver`를 만들어 모든 `.reveal` 요소를 감시합니다.
6. 요소가 화면에 들어오면(`entry.isIntersecting`) `is-visible` 클래스를 붙입니다. 한 번 나타난 뒤에는 `unobserve`로 감시를 끊어, 다시 스크롤해도 깜빡이지 않게 합니다.

### D. 동작 확인 + 접근성 테스트
7. 페이지를 천천히 아래로 스크롤하면 카드들이 **하나씩 떠오르며** 나타납니다.
8. "움직임 줄이기"를 켜고 새로고침해 보세요. 카드가 애니메이션 없이 **즉시** 보이면 접근성 배려가 작동하는 것입니다.
   - Windows: 설정 → 접근성 → 시각 효과 → **애니메이션 효과** 끄기
   - macOS: 시스템 설정 → 손쉬운 사용 → 디스플레이 → **동작 줄이기** 켜기

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  역할: 너는 비전공 학습자를 가르치는 프론트엔드 멘토야.
  목표: 외부 라이브러리 없이 순수 HTML/CSS/JS로 "스크롤 등장 애니메이션" 데모 페이지를 만들어 줘.
  요구사항:
  - index.html, style.css, script.js 세 파일로 분리.
  - 화면을 채울 만큼 길게(카드 6개 이상, 섹션 사이 여백 넉넉히) 만들어 스크롤이 생기게 해.
  - 각 카드에 .reveal 클래스를 주고, CSS에서 .reveal은 "opacity:0, transform: translateY(24px)"(숨김 상태),
    .reveal.is-visible는 "opacity:1, transform: none"(보임 상태)로 정의하고 transition으로 0.6초 부드럽게 이어 줘.
  - script.js는 IntersectionObserver로 .reveal 요소들을 감시하다가 화면에 들어오면 is-visible을 붙이고, 한 번 나타난 요소는 unobserve로 감시를 끊어 줘.
  제약:
  - 한국어 설명, 영어 식별자.
  - 모든 핵심 줄에 "무엇(기능)과 왜(이렇게 한 이유)"를 한국어 주석으로 달아 줘. 코드만 주지 말고 비전공자가 이해하게 한 줄씩 풀어서.
  - 자바스크립트가 꺼져도 내용이 보이도록 점진적 향상 방식으로 설계해 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  앞에서 만든 등장 애니메이션 데모를 다음처럼 개선해 줘:
  1) 모션 접근성: CSS에 @media (prefers-reduced-motion: reduce)를 추가해서, 사용자가 "움직임 줄이기"를 켜면
     transition/animation을 없애고 카드를 즉시 보이게 해 줘. 왜 이 배려가 필요한지 주석으로 설명도 붙여.
  2) 등장 방향 다양화: 일부 카드는 아래에서, 일부는 왼쪽/오른쪽에서 들어오게 .reveal-up / .reveal-left / .reveal-right 변형 클래스를 만들어 줘.
  3) 순차 등장(stagger): 같은 줄의 카드들이 약간의 시간차를 두고 나타나도록 transition-delay를 인라인 style이나 CSS 변수로 조절해 줘.
  4) IntersectionObserver의 threshold/rootMargin을 조절해 "카드가 15% 정도 보일 때" 발동하도록 하고, 그 숫자가 무슨 뜻인지 주석으로 적어 줘.
  여전히 한국어 주석 + 영어 식별자 규칙을 지켜 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  스크롤해도 카드가 나타나지 않아(또는 처음부터 다 보여). 아래 정보를 보고 원인을 단계별로 진단해 줘.
  - 증상: (예) 카드가 끝까지 투명한 상태로 안 나타남 / 새로고침하면 다 보임 / 콘솔에 빨간 에러가 있음
  - 콘솔 에러 메시지: (F12 → Console 탭의 내용을 그대로 붙여넣기)
  - 관련 코드: script.js의 IntersectionObserver 부분과 style.css의 .reveal / .is-visible 부분
  점검 순서로 알려 줘:
  1) is-visible 클래스가 실제로 붙는지 (F12 Elements에서 확인하는 법),
  2) CSS 선택자(.reveal.is-visible)가 정확한지,
  3) observer.observe(...)에 요소가 잘 전달됐는지,
  4) prefers-reduced-motion이 켜져 있어 애니메이션이 생략된 건 아닌지.
  각 단계에서 "이렇게 확인하고, 이러면 이게 원인"이라고 비전공자가 따라할 수 있게 풀어 줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법
- **등장 확인**: 페이지를 위에서 아래로 천천히 스크롤하면, 화면에 들어오는 카드가 **투명+아래에서 → 선명+제자리로** 부드럽게 나타나는지 본다. 처음부터 다 보이면 안 된다(아직 화면 밖인 카드는 숨어 있어야 한다).
- **한 번만 등장 확인**: 카드가 나타난 뒤 위로 다시 올렸다가 내려도 **깜빡이며 재생되지 않는지** 본다(`unobserve` 덕분).
- **접근성 확인(가장 중요)**: 운영체제에서 "움직임 줄이기"를 켜고 새로고침하면, 카드가 **애니메이션 없이 즉시** 보이는지 확인한다. 이게 `prefers-reduced-motion` 배려가 작동한다는 증거다.
- **JS 꺼짐 대비 확인**: 브라우저 개발자도구에서 자바스크립트를 끄고 새로고침해도 **내용 자체는 읽을 수 있는지** 본다. (애니메이션은 없어도 글은 보여야 한다 = 점진적 향상.)
- **성능 확인**: 스크롤이 **버벅이지 않는지** 본다. `opacity`와 `transform`만 애니메이션하므로(레이아웃을 다시 계산하지 않으므로) 부드러워야 한다.

## 파일 구성
- `index.html` — 등장시킬 카드들이 담긴 데모 페이지. CSS/JS 파일을 불러온다.
- `style.css` — 숨김 상태(`.reveal`)·보임 상태(`.is-visible`)와 `transition`, 그리고 `prefers-reduced-motion` 처리를 담은 스타일.
- `script.js` — `IntersectionObserver`로 화면에 들어온 요소에 `is-visible`을 붙이는 로직.

> 이 실습은 외부 서비스·비밀값을 쓰지 않습니다. 그래서 `.env.example`이나 API 키가 필요 없습니다. 파일을 브라우저로 바로 열면 동작합니다.
