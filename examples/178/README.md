# 내 도메인 사서 Vercel에 연결하고 HTTPS 자물쇠 확인하기

지금까지 만든 사이트는 `https://my-site.vercel.app` 처럼 **Vercel이 공짜로 준 긴 주소**로 떠 있었습니다. 이번 실습에서는 그 사이트에 **내이름.com 같은 내 도메인**을 얹어, 손님이 짧고 기억하기 쉬운 주소로 들어오게 만듭니다. 흐름은 네 단계입니다: **도메인 구매 → Vercel에 추가 → DNS 레코드 설정 → www/루트 통일(301) → (전파 기다린 뒤) HTTPS 자물쇠 확인**.

가장 중요한 마음가짐은 **"안 떠도 정상"** 입니다. 도메인은 샀다고 바로 연결되지 않습니다. DNS(주소록)가 전 세계에 퍼지는 데 시간이 걸리기 때문입니다. 그래서 설정 직후 한동안 "사이트를 찾을 수 없음" 또는 "Invalid Configuration"이 떠도 **고장이 아니라 정상**입니다. 보통 수 분~수 시간, 길면 하루(최대 48시간)까지 기다리면 자동으로 연결되고, Vercel이 **HTTPS 인증서를 공짜로 자동 발급**해 주소창에 **자물쇠(🔒)** 가 채워집니다.

이 폴더의 `index.html` 은 실제 등록업체/Vercel 화면을 흉내 낸 **연습판(시뮬레이터)** 입니다. 설치 없이 더블클릭으로 열려서, "도메인 사기 → Vercel 추가 → DNS 넣기 → 301 통일 → 전파 기다리기 → 자물쇠" 흐름을 손으로 한 번 따라가 볼 수 있습니다. 그다음 진짜 도메인 등록업체 + Vercel에서 똑같이 해 봅니다. (연습판은 진짜 도메인을 사지 않습니다.)

> 비전공자 눈높이 한 줄 요약: **도메인 = 가게 간판 주소**, **DNS = 전국 전화번호 안내소**, **Vercel = 손님을 맞는 가게**. 간판(내이름.com)을 새로 달면, 안내소(DNS)가 "그 간판으로 오면 이 가게로 보내라"고 전국에 퍼뜨리는 데 시간이 걸립니다. 다 퍼지면 문에 **자물쇠(HTTPS)** 가 자동으로 채워집니다.

## 목표

- `my-site.vercel.app` 같은 기본 주소 대신 **내 커스텀 도메인(내이름.com)** 으로 사이트가 열리게 한다.
- 등록업체 DNS 설정 화면에 **A 레코드(루트 `@`)** 와 **CNAME 레코드(`www`)** 를 넣어 도메인을 Vercel로 가리키게 한다.
- `내이름.com` 과 `www.내이름.com` 중 **하나를 대표로 정하고**, 다른 쪽은 **301(영구 이동)** 로 대표 주소에 자동으로 보내 **한 사이트 = 한 주소(SEO 정리)** 를 만든다.
- DNS는 **즉시 반영되지 않는다**는 점을 이해한다. 설정 직후 안 떠도 **정상**이고, 전파가 끝나면 **Vercel이 HTTPS 인증서를 자동 발급**해 주소창에 **자물쇠(🔒)** 가 생긴다는 흐름을 끝까지 따라간다.
- (보안 원칙) DNS 레코드(IP·CNAME 별칭)는 **공개돼도 안전한 정보**다. 반면 **API 키·토큰·비밀번호 같은 비밀값은 DNS나 코드에 절대 넣지 않는다.** 공개 가능한 값(Supabase `anon` 키·도메인)과 비밀값(`service_role` 키 등)을 구분하고, 비밀값은 코드 대신 **Vercel → Settings → Environment Variables** 에 **자리표시자**로 넣어 관리한다(예: `SUPABASE_SERVICE_ROLE_KEY = <여기에_실제_비밀키_절대_커밋_금지>`). `service_role` 키는 RLS(Row Level Security)를 무시하는 마스터 키라 노출되면 즉시 폐기·재발급해야 한다.

## 따라하는 단계

### A. 연습판으로 흐름 감 잡기 (이 폴더의 화면)

1. `examples/178/` 폴더의 `index.html` 을 브라우저로 엽니다. (더블클릭으로 열립니다.)
2. 맨 위 **"0) 지금 상태"** 보드를 봅니다. 왼쪽은 이미 살아 있는 `my-site.vercel.app`(자물쇠 있음), 오른쪽은 아직 연결 전인 목표 주소 `내이름.com`(자물쇠 🔓 열림)입니다.
3. **"1) 도메인 사기"** 에서 입력칸 값(`내이름.com`)을 확인하고 **이 도메인 구매하기** 를 누릅니다. → 다음 단계 버튼이 열립니다.
4. **"2) Vercel에 도메인 추가"** 버튼을 누릅니다. Vercel이 *"이 DNS 레코드를 넣으세요"* 라고 안내하는 상황을 흉내 냅니다.
5. **"3) DNS 레코드 넣기"** 의 표(A 레코드 `@`, CNAME `www`)를 읽고 **DNS 레코드 2줄 저장** 을 누릅니다. (값은 형식만 보여주는 예시입니다.)
6. **"4) www와 루트 통일(301)"** 에서 대표 주소를 고릅니다. 짧은 `내이름.com` 을 대표로 두는 것을 추천합니다. **301 통일 적용** 을 누릅니다.
7. **"5) 전파 기다리기"** 버튼을 누릅니다. 터미널에 *"지금 안 떠도 정상 → 기다림 → 전파 완료 → HTTPS 자물쇠 발급"* 이 차례로 흐르고, 목표 카드의 자물쇠가 🔓 → 🔒 로 바뀝니다.
8. 맨 아래 **"6) 결과물"** 칸에서 *내이름.com 연결 + 자물쇠 + 301 통일* 세 가지가 나타나는지 봅니다. **"처음부터 다시"** 로 순서를 한 번 더 익힙니다.

### B. 진짜 도메인 + Vercel에서 하기

> 전제: 앞 실습(169~170)대로 내 사이트가 이미 `프로젝트이름.vercel.app` 으로 배포돼 있어야 합니다.

9. **도메인을 삽니다.** 등록업체(예: Cloudflare Registrar, Namecheap, 가비아 등)에서 원하는 이름을 검색해 1년 등록합니다. (`.com` 기준 보통 연 1만~2만 원대)
10. **Vercel 대시보드 → 내 프로젝트 → Settings → Domains** 로 갑니다. 입력칸에 산 도메인(`내이름.com`)을 적고 **Add** 를 누릅니다.
11. Vercel이 **"이 레코드를 등록업체에 넣으세요"** 라며 값을 보여줍니다. 보통 두 종류입니다.
    ```text
    A      @     76.76.21.21            (루트 도메인 -> Vercel)
    CNAME  www   cname.vercel-dns.com   (www -> Vercel)
    ```
    > 화면에 보이는 **실제 값을 그대로** 쓰세요. 위 값은 형식 예시이며, 안내 IP/별칭은 바뀔 수 있습니다.
12. **등록업체의 DNS 설정 화면**으로 가서 위 두 줄을 똑같이 추가하고 저장합니다. (Cloudflare를 쓰면 같은 곳에서 한 번에 가능합니다.)
13. 다시 Vercel **Domains** 화면에서 **www와 루트 중 대표 주소**를 정합니다. 보통 `www.내이름.com` 옆 **"Redirect to 내이름.com"** (또는 그 반대)을 골라 **한쪽을 301로 통일**합니다. (선택: 이 폴더의 `vercel.json` 처럼 `redirects` 로 코드에 적어 둘 수도 있지만, 대시보드 설정이 더 간단합니다.)
14. **기다립니다.** Vercel Domains 화면의 도메인 상태가 처음엔 `Invalid Configuration`(빨강/주황)일 수 있습니다. **이건 고장이 아니라 전파 중**이라는 뜻입니다. 수 분~수 시간(길면 하루) 뒤 상태가 **Valid Configuration(초록)** 으로 바뀝니다.
15. 상태가 초록이 되면 **`https://내이름.com`** 을 새 탭에서 엽니다. 주소창 왼쪽에 **자물쇠(🔒)** 가 보이면, Vercel이 HTTPS 인증서를 자동 발급한 것입니다. (내가 인증서를 따로 살 필요 없음)
16. `www.내이름.com` 으로도 들어가 봅니다. **자동으로 대표 주소로 넘어가면** 301 통일이 잘 된 것입니다.

## 🤖 바이브코딩 프롬프트

이 실습(도메인 구매 → Vercel 추가 → DNS 설정 → 301 통일 → 전파/HTTPS 자물쇠)을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. 이 폴더의 연습판 시뮬레이터를 직접 만들어 보거나, 진짜 Vercel 연결을 도움받을 때 활용하세요.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text

  단일 HTML 파일 "커스텀 도메인 연결 연습판(시뮬레이터)"을 만들어 줘.
  목적: 진짜 도메인을 사지 않고도 "도메인 구매 → Vercel에 도메인 추가 →
  DNS 레코드(A @, CNAME www) 넣기 → www/루트 301 통일 → DNS 전파 기다리기 →
  HTTPS 자물쇠(🔒) 확인" 흐름을 손으로 따라가 보게 하는 것.

  제약:
  - 외부 라이브러리·빌드 도구 금지. 순수 HTML/CSS/JS만. 진짜 네트워크 호출 금지(전부 흉내).
  - 단계는 순서대로만 열리게(앞 단계를 끝내야 다음 버튼이 활성화).
  - "지금 상태" 보드: vercel.app 주소(이미 자물쇠 🔒)와 목표 도메인(아직 🔓)을 나란히 보여줘.
  - 화면 어디엔가 "DNS는 바로 반영 안 됨 → 설정 직후 안 떠도 정상" 안내문을 꼭 넣어줘.
  산출물: index.html / style.css / script.js 세 파일. 한국어 UI, 영어 식별자.
  코드만 주지 말고 왜 그렇게 했는지 한 줄씩 주석으로 설명해줘.
  ```

  ```text
  앞서 만든 연습판에 다음을 추가해 줘:
  1) "전파 기다리기" 버튼을 누르면 터미널 영역에
     "안 떠도 정상 → 확인 중 → 전파 완료 → HTTPS 인증서 자동 발급 → 자물쇠 🔒"가

  2) 마지막에 목표 카드의 자물쇠가 🔓 → 🔒 로 바뀌고 카드 테두리가 초록이 되게.

  API 키·service_role 같은 비밀값은 DNS·코드에 절대 넣지 말 것."
  바꾼 부분은 왜 그렇게 했는지 주석으로 설명해줘.
  ```

## 검증법

1. **연습판 검증**: 1~5단계를 순서대로 끝내면 목표 카드의 자물쇠가 🔓 → 🔒 로 바뀌고, 카드 테두리가 초록으로 변하며, 맨 아래 "결과물" 칸이 나타나면 성공입니다. (앞 단계를 안 끝내면 다음 버튼이 비활성인 점도 확인하세요.)
2. **결과물 — 자물쇠 걸린 라이브 사이트**: 진짜 `https://내이름.com` 을 열었을 때 ① **내 사이트 내용이 보이고** ② 주소창에 **자물쇠(🔒)** 가 있으면 커스텀 도메인 + HTTPS가 완성된 것입니다. 이게 이번 실습의 결과물(Deliverable)입니다.
3. **301 통일 확인**: `www.내이름.com` (또는 비대표 쪽)으로 들어갔을 때 주소창이 **대표 주소로 자동으로 바뀌면** 301이 작동하는 것입니다. (개발자도구 Network 탭에서 첫 요청의 상태 코드가 `301`로 찍히는 것으로도 확인됩니다.)
4. **HTTPS 인증서 확인**: 주소창의 자물쇠를 눌러 "연결이 안전함 / 인증서 유효"가 보이는지 봅니다. (Vercel이 발급·자동 갱신하므로 따로 관리할 게 없습니다.)
5. **"안 떠도 정상" 이해 점검**: 설정 직후 `Invalid Configuration` 이나 "사이트 못 찾음"이 떴다고 무언가를 되돌리거나 재설정하지 않았는지 떠올려 봅니다. **전파를 기다리면 저절로 연결된다**가 머릿속에 그려지면 이번 실습의 진짜 목표 달성입니다.
6. **흔한 실수 점검**:
   - **계속 Invalid 인데 한참 지남** → 등록업체에 넣은 **A/CNAME 값에 오타**가 없는지, 혹은 **옛날 레코드(다른 곳을 가리키던 A/CNAME)** 가 남아 충돌하는지 확인합니다. 옛 레코드는 지우세요.
   - **루트(`@`)에 CNAME을 넣어 막힘** → 많은 등록업체가 루트 도메인에는 CNAME을 허용하지 않습니다. 루트는 **A 레코드**, `www` 는 **CNAME** 으로 맞추세요. (Vercel 안내 그대로)
   - **자물쇠가 안 생김** → 보통 아직 인증서 발급 전입니다. 전파(Valid Configuration)가 끝나면 보통 몇 분 내 자동 발급됩니다. 그래도 안 되면 Vercel Domains에서 도메인을 **Refresh/재추가** 해 봅니다.
   - **둘 다 그냥 열려서 SEO 중복** → 13번의 **301 통일**을 안 한 경우입니다. 한쪽을 대표로 정해 Redirect를 켜세요.
7. **보안/노출 점검(필수)**: DNS 레코드(IP·CNAME 별칭)와 도메인 이름은 **공개돼도 안전**합니다. 하지만 **API 키·토큰·비밀번호 같은 비밀값은 DNS나 코드(이 `vercel.json` 포함)에 절대 넣지 않습니다.** Supabase를 붙였다면 **공개용 `anon` 키**는 프런트엔드에 둬도 되지만(반드시 **RLS** 켜기), **`service_role`(비밀) 키는 GitHub/코드에 올리면 안 되며** Vercel 환경변수에 자리표시자로만 둡니다. 노출되면 즉시 키를 폐기·재발급하세요.
