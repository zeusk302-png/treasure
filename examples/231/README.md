# 231. Supabase MCP 서버를 Claude에 연결해 내 DB 직접 조회시키기

## 목표

지금까지는 데이터를 보려면 **사람이** Supabase 대시보드에 로그인 → 테이블 클릭 →
SQL 에디터에 쿼리를 직접 쳐야 했습니다. 이번 실습은 그 다리를 AI에게 놓아 줍니다.

**MCP(Model Context Protocol)** 는 "AI에게 도구를 끼워 주는 표준 콘센트"입니다.
Supabase가 제공하는 MCP 서버를 Claude에 꽂으면, 앞으로는 **채팅창에 한국어로
"방명록 테이블 최근 5건 보여줘"라고 부탁만 해도 Claude가 직접 내 DB에 SQL을 날려
결과를 가져옵니다.** 사람은 SQL을 몰라도 되고, 대시보드를 열 필요도 없어집니다.

이 실습의 핵심은 두 가지입니다.

1. **연결 설정 파일(`.mcp.json`)** 을 정확한 위치에 두고, 토큰을 안전하게(자리표시자 →
   진짜 값) 채우는 것.
2. **처음엔 "읽기 전용(`--read-only`)" 으로만 연결**해서, AI가 실수로 데이터를 지우거나
   고치지 못하게 안전핀을 박는 것. (AI에게 쓰기 권한을 주는 건 훨씬 위험합니다)

> 한 가지 꼭 구분: 이번에 발급하는 **Supabase 개인 접근 토큰**은 내 계정 전체를 다룰 수
> 있는 **비밀값**입니다. 웹페이지에 박는 anon(공개) 키와는 완전히 다릅니다. 이 토큰은
> 절대 코드나 git에 노출되면 안 됩니다. (그래서 이 폴더의 파일들에도 진짜 값 대신
> `REPLACE_WITH_...` 자리표시자만 적혀 있습니다)

이 폴더의 파일과 구조는 이렇습니다.

- [`.mcp.json`](.mcp.json) — **이 실습의 핵심 결과물.** Claude(Claude Code)가 읽는 MCP 연결
  설정입니다. "supabase라는 이름의 도구를 npx로 실행하고, 내 토큰·프로젝트로 로그인하되
  읽기 전용으로 켜라"는 지시가 들어 있습니다.
- [`.env.example`](.env.example) — 비밀값(개인 접근 토큰)을 어디에 어떻게 넣는지 알려 주는
  본보기 파일. 복사해서 `.env` 로 바꿔 쓰고, `.env` 는 절대 커밋하지 않습니다.
- [`조회결과-예시.md`](조회결과-예시.md) — **AI가 DB를 직접 조회한 결과의 캡처 예시.**
  연결이 성공하면 채팅창에 이런 표가 떠야 한다는 정답지입니다.
- `README.md` — 지금 읽는 이 안내문

## 따라하는 단계

1. **준비물 확인.** 컴퓨터에 Node.js(npx 포함)가 깔려 있어야 합니다. 터미널에서
   `node -v` 가 버전을 보여 주면 OK. 그리고 이미 만들어 둔 Supabase 프로젝트(예: 방명록
   `guestbook` 테이블이 있는 것)가 있어야 합니다.
2. **프로젝트 식별자(Reference ID) 복사.** Supabase 대시보드 > 내 프로젝트 >
   Project Settings > General 에서 **Reference ID** 를 복사합니다. (이건 공개돼도
   위험하지 않은 값입니다)
3. **개인 접근 토큰 발급.** Supabase 대시보드 오른쪽 위 계정 아이콘 > Account >
   **Access Tokens** > "Generate new token" 으로 토큰을 만듭니다. **이 화면을 벗어나면
   다시 못 보니** 바로 복사해 둡니다. **이 토큰이 비밀값입니다.**
4. **설정 파일을 프로젝트 맨 위 폴더에 둡니다.** [`.mcp.json`](.mcp.json) 을 내 프로젝트의
   **루트 폴더**(README, index.html 등이 있는 가장 바깥 폴더)에 복사합니다. Claude Code는
   이 위치의 `.mcp.json` 을 자동으로 읽습니다.
5. **자리표시자를 진짜 값으로 바꿉니다.** `.mcp.json` 안에서
   - `REPLACE_WITH_YOUR_PROJECT_REF` → 2단계의 Reference ID
   - `REPLACE_WITH_YOUR_SUPABASE_ACCESS_TOKEN` → 3단계의 토큰
   으로 바꿉니다.
6. **비밀값이 git에 안 올라가게 막습니다.** `.gitignore` 에 `.env` 와, 토큰이 박힌
   `.mcp.json` 을 올릴 생각이라면 그 파일도 추가합니다. (안전하게 하려면 토큰은
   [`.env`](.env.example) 에만 두고 `.mcp.json` 에는 자리표시자만 남겨, 팀원은 각자
   자기 토큰을 `.env` 에 넣게 하는 방식이 좋습니다)
7. **Claude를 다시 시작합니다.** Claude Code를 껐다 켜면 `.mcp.json` 을 다시 읽습니다.
   `/mcp` 라고 입력하면 연결된 서버 목록이 보이는데, 거기에 **supabase** 가 떠 있어야
   합니다.
8. **AI에게 직접 부탁합니다.** 채팅창에 **"방명록 테이블 최근 5건 보여줘. 이름이랑
   메시지, 작성시간만"** 이라고 칩니다. Claude가 supabase MCP 도구를 쓰겠다고 **승인을
   물으면 "허용"** 을 누릅니다.
9. **결과를 캡처합니다.** Claude가 SQL을 스스로 만들어 실행하고 결과 표를 보여 주면,
   그 화면(내가 한 말 + Claude가 만든 쿼리 + 결과 표)을 캡처해 둡니다. 모습은
   [`조회결과-예시.md`](조회결과-예시.md) 와 같아야 합니다.

## 🤖 바이브코딩 프롬프트

이 실습(Supabase MCP 서버를 Claude에 연결해 DB를 직접 조회시키기)을 AI에게 시켜 만들 때
그대로 복사해 쓸 수 있는 프롬프트입니다. 이 실습은 "코드를 짜는" 일이 아니라 **설정 파일을
정확히 만들고 안전하게 연결하는** 일이라, 프롬프트도 그 방향에 맞춰져 있습니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 Claude Code MCP 설정을 도와주는 전문가야.
  나는 비전공자고, 이미 만들어 둔 Supabase 프로젝트(guestbook 테이블이 있음)를
  Claude에 "읽기 전용"으로 연결해서, 채팅으로 한국어 부탁만 해도 Claude가 내 DB를
  직접 조회하게 만들고 싶어.

  목표: 프로젝트 루트에 둘 .mcp.json 파일을 만들어 줘.
  제약:
   - @supabase/mcp-server-supabase 패키지를 npx로 실행할 것
   - 반드시 --read-only 플래그를 넣어서 AI가 데이터를 수정/삭제하지 못하게 할 것
   - 진짜 토큰/프로젝트ID는 코드에 박지 말고 REPLACE_WITH_... 자리표시자로 둘 것
  산출물: .mcp.json 전체 내용 + 각 줄이 무슨 뜻인지 한 줄 설명.
  그리고 이 토큰을 어디서 발급받고 .env로 어떻게 분리·보호하는지 단계로 알려 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  연결이 됐어. 이제 다음을 도와줘.
   1) 비밀값(개인 접근 토큰)이 실수로 git에 올라가지 않게 .gitignore를 어떻게 써야 해?
      .env와 토큰이 박힌 파일을 빠짐없이 막는 예시를 만들어 줘.
   2) "방명록 최근 5건만 이름·메시지·작성시간으로 보여줘" 같은 부탁을 했을 때
      Claude가 만들 SQL이 어떤 모습일지 미리 보여 줘.
   3) 읽기 전용이 잘 걸렸는지 확인할 수 있는, 일부러 "거부돼야 정상인" 부탁 예시를
      3개 알려 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  /mcp 를 쳤는데 supabase 서버가 안 보여(또는 connected가 아니라 failed로 떠).
  내 .mcp.json 내용은 이거야: (여기에 .mcp.json 붙여넣기 — 단, 진짜 토큰은 지우고)
  에러 메시지는 이거야: (터미널/Claude에 뜬 에러 붙여넣기)

  무엇이 원인일 수 있는지 가능성 높은 순서로 짚어 주고,
  한 번에 하나씩 확인할 수 있게 단계별 점검 절차로 알려 줘.
  (특히 파일 위치가 루트인지, 자리표시자가 안 바뀐 건 아닌지, Claude 재시작했는지)
  ```
> 프롬프트 팁: "코드만 주지 말고 **왜 그렇게 했는지 주석으로 설명해 줘**", "비전공자가
> 이해하게 한 줄씩 풀어 줘"를 덧붙이면, 설정 파일 한 줄 한 줄의 의미를 익히며 따라갈 수
> 있습니다.

## 검증법

아래를 모두 만족하면 성공입니다.

- [ ] `.mcp.json` 이 프로젝트 **루트 폴더**에 있고, `mcpServers` 안에 `supabase` 항목이
      있다.
- [ ] `.mcp.json` 안의 `REPLACE_WITH_...` 자리표시자가 **모두** 진짜 값으로 바뀌어 있다.
      (남아 있으면 연결이 안 됨)
- [ ] Claude에서 `/mcp` 를 쳤을 때 **supabase** 서버가 "connected" 상태로 보인다.
- [ ] "방명록 최근 5건 보여줘" 처럼 **SQL 없이 한국어로 부탁**했을 때, Claude가
      **스스로 SQL을 만들어** 실행하고 결과 표를 가져온다.
- [ ] 결과가 [`조회결과-예시.md`](조회결과-예시.md) 처럼 **내 DB의 실제 데이터**로 채워져
      나온다. (사람이 대시보드를 안 열고 AI가 직접 읽어 온 것)
- [ ] **읽기 전용이 지켜진다:** "방명록 다 지워줘" 같은 삭제·수정 요청은 `--read-only`
      때문에 **거부되거나 실행되지 않는다.**
- [ ] **비밀값이 새지 않는다:** 개인 접근 토큰이 git에 커밋되지 않았다(`git status` 로
      `.env`·토큰 박힌 파일이 추적 목록에 없음 확인). 이 폴더의 공유 파일에도 진짜 토큰이
      아닌 자리표시자만 적혀 있다.

> 빠른 자가 점검: `/mcp` 에 supabase가 떠 있고, **한국어 부탁 한마디로 내 테이블 데이터가
> 표로 돌아오면** 연결 성공입니다. 만약 "도구를 찾을 수 없다"거나 인증 오류가 나면 보통
> (1) `.mcp.json` 위치가 루트가 아니거나 (2) 토큰/Reference ID 자리표시자가 안 바뀌었거나
> (3) Claude를 재시작 안 한 경우입니다.
