# 실습 136 — 로그아웃 버튼 만들고 깔끔하게 빠져나가기

로그인이 있으면 로그아웃도 있어야겠죠. 이번 실습에서는 `signOut`으로 **세션(로그인 정보)을 지우고**, 화면에 남아 있던 **보호 데이터(비밀 메모)를 깨끗이 비운 뒤**, **로그인 페이지로 보내는** 세 단계를 한 번에 익힙니다.

핵심은 "로그아웃 = 세션만 지우면 끝"이 아니라는 점입니다. 세션만 지우고 화면을 그대로 두면, 방금까지 보던 개인 정보가 글자 그대로 화면에 남아 다음 사람이 볼 수 있습니다. 그래서 **세션 정리 + 화면 정리 + 이동**까지가 한 세트입니다.

이번 실습의 결과물은 **로그아웃 로직이 담긴 스크립트(`app.js`)** 와, 그것을 체험할 수 있는 보호 페이지(`index.html`)입니다.

## 목표
- `await db.auth.signOut()` 한 줄로 **브라우저에 저장된 로그인 세션을 지운다**는 걸 이해한다.
- 로그아웃할 때 **화면의 보호 데이터를 직접 비워야 한다**는 걸 체득한다. (세션만 지운다고 화면이 저절로 비워지지 않음)
- 로그아웃 뒤 `window.location.replace("login.html")`로 **로그인 페이지로 돌려보내는** 흐름을 익힌다. (`replace`를 쓰면 '뒤로 가기'로 보호 페이지에 못 돌아온다)
- `signOut`의 `scope`(`local` = 이 브라우저만 / `global` = 모든 기기) 차이를 안다.

## 따라하는 단계
1. 앞 실습(131·132)에서 만든 **Supabase 프로젝트**와 **테스트 계정**을 그대로 사용한다. (계정이 없으면 Authentication → Users에서 "Auto Confirm User"를 켜고 하나 추가한다.)
2. 대시보드 → **Settings → API**에서 `Project URL`과 `anon`(publishable) 키를 복사한다.
3. `app.js` 위쪽의 `SUPABASE_URL`, `SUPABASE_ANON_KEY` 두 값을 내 값으로 바꾼다.
4. `index.html`을 브라우저로 연다. 아직 로그아웃 상태라 비밀 메모 대신 **'🔒 로그인해야…'** 안내와 데모 로그인 박스가 보인다.
5. 데모 로그인 박스에 테스트 계정으로 **로그인**한다 → 헤더에 이메일과 로그아웃 버튼이 뜨고, **비밀 메모(보호 데이터)** 가 나타난다.
6. 본문의 빨간 **'로그아웃하고 나가기'** 버튼(또는 헤더의 작은 로그아웃 버튼)을 누른다.
7. 안내창이 뜬 뒤, **비밀 메모가 화면에서 사라지고** 다시 로그아웃 상태(데모 로그인 박스)로 돌아오는지 확인한다.
8. (실전 적용) 실제 서비스라면 `app.js`의 `// window.location.replace("login.html");` 주석을 풀고 내 로그인 페이지 경로로 바꾼다. 그러면 로그아웃 즉시 로그인 페이지로 이동한다.

## 검증법
- 로그아웃 버튼을 누르면 **비밀 메모가 화면에서 사라지는가?** (← 이번 실습의 핵심. 세션만 지우고 화면을 안 비우면 글자가 그대로 남는다.)
- 개발자도구 → **Console**에 로그아웃 시 `인증 상태 변화: SIGNED_OUT`이 찍히는가?
- 로그아웃한 뒤 **새로고침(F5)** 해도 로그아웃 상태가 유지되는가? (세션이 정말 지워졌다는 증거)
- (실전 경로를 켰다면) 로그아웃 후 **로그인 페이지로 이동**하고, 브라우저 '뒤로 가기'로 보호 페이지에 **되돌아가지지 않는가?** (`replace` 덕분)

## 핵심 한 줄
로그아웃은 "세션 지우기 → 화면 정리 → 이동" 세 단계가 한 세트입니다.
```js
async function logout() {
  await db.auth.signOut();              // (1) 세션 지우기
  secretBox.innerHTML = "";             // (2) 보호 데이터 화면에서 비우기
  window.location.replace("login.html"); // (3) 로그인 페이지로 이동
}
```
`signOut()`은 **이 브라우저에 저장된 세션을 지웁니다**(기본 `scope: "local"`). 모든 기기·탭에서 한꺼번에 로그아웃시키려면 `db.auth.signOut({ scope: "global" })`을 씁니다.

## 보안 메모 — anon vs service_role, 그리고 '화면 숨김 ≠ 보안'
- 여기 넣는 건 **anon(publishable) 키** 하나뿐입니다. anon 키는 "공개돼도 되는 **출입증**"이라 브라우저·GitHub에 있어도 괜찮습니다. (코드의 키 값 `sb_publishable_...`는 자리표시자이니 내 값으로 바꿔 쓰세요.)
- `service_role`(secret) 키는 모든 **RLS(행 수준 보안)를 통째로 우회**하는 마스터키라, 브라우저나 깃허브에 두면 안 됩니다. 오직 서버(n8n·엣지 함수)에서 환경변수로만 사용하세요.
- 중요: **화면에서 비밀 메모를 지우는 것은 '정리'이지 '보안'이 아닙니다.** 진짜 보안은, 로그아웃해 세션이 없어지면 **DB의 RLS 정책**(`auth.uid()` 기반)이 데이터 요청 자체를 거부하는 것입니다. 즉 로그아웃하면 `db.from('memos').select()`를 다시 호출해도 RLS가 막아 아무것도 돌려주지 않습니다. 화면 정리는 그 위에 더하는 '깔끔한 마무리'일 뿐입니다.
