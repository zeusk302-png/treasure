# 비동기 순서 꼬임 잡기 — 데이터보다 먼저 그려지는 빈 목록

"오늘의 할 일 목록"을 서버에서 받아 화면에 그리는 페이지인데, **목록이 늘 비어 보입니다.**
에러도 안 나고, 콘솔에는 빨간 글씨 하나 없는데 결과만 비어 있어서 더 헷갈리는 버그입니다.
원인은 단 하나, **데이터가 도착하기도 전에 화면을 먼저 그렸기 때문**입니다.
`fetch` 같은 비동기 작업의 "실행 순서"를 이해하고 `async/await`로 고치는 디버깅 실습입니다.

## 목표

- `fetch`(서버에서 데이터 받기)는 **"지금 당장"이 아니라 "나중에" 끝나는** 비동기 작업이라는 것을 이해한다.
- 비동기 결과를 `await` 없이 그냥 받으면, 변수 안에는 진짜 데이터가 아니라 **"약속(Promise)"**이라는 빈 상자가 들어온다는 것을 눈으로 확인한다.
- 그래서 그 변수에 `.length`(개수)를 물으면 `undefined`가 나오고, 반복문이 한 번도 안 돌아 **화면이 비어 보이는 흐름**을 추적할 수 있다.
- 해결책인 `async`/`await`로 "데이터가 도착할 때까지 기다린 뒤에 화면을 그리도록" 순서를 바로잡는다.

## 따라하는 단계

1. **고장 난 화면부터 본다.** `broken.html`을 더블클릭해 브라우저로 엽니다. "불러오는 중..."이 떴다가 곧 "할 일 0개를 불러왔습니다."로 바뀌고, **목록은 끝까지 비어 있습니다.**
2. **콘솔에서 순서를 확인한다.** 키보드 `F12`(또는 우클릭 → 검사) → **Console(콘솔)** 탭을 엽니다. 다음 세 줄이 보입니다. → **이 화면이 "before(고치기 전)" 캡처입니다.**
   - `1) todos 값: Promise { <pending> }` ← 배열이 아니라 **약속(Promise)**이 들어 있습니다.
   - `2) todos.length: undefined` ← 약속에는 개수가 없으니 `undefined`입니다.
   - `3) 화면 그리기 끝 (그런데 목록은 비어 있다)` ← 0.5초 뒤 데이터가 도착하기도 **전에** 이미 다 그려 버렸습니다.
3. **원인을 짚는다.** `broken.html`의 `<script>`를 코드 편집기로 봅니다. `const todos = fetchTodos();` 한 줄이 범인입니다. `fetchTodos()`는 결과(배열)가 아니라 **"곧 줄게"라는 약속(Promise)**을 즉시 돌려줍니다. 그 약속을 기다리지(`await`) 않고 바로 `todos.length`로 반복문을 돌렸으니, 반복은 0번 실행되고 목록은 빈 채로 끝납니다.
4. **고치는 방법을 적용한다.** 이 폴더의 `index.html` + `script.js`가 정답 버전입니다. 두 곳만 바뀌었습니다.
   - 함수 앞에 `async`를 붙입니다 → `async function loadTodos() { ... }`
   - 데이터를 받는 줄 앞에 `await`를 붙입니다 → `const todos = await fetchTodos();`
   - `await`는 "이 약속이 지켜질 때까지(=데이터가 도착할 때까지) 잠깐 기다린 다음 진짜 결과를 꺼내 줘"라는 뜻입니다.
5. **고친 화면을 확인한다.** `index.html`을 브라우저로 엽니다. 약 0.5초 뒤 할 일 3개가 나타나고 "할 일 3개를 불러왔습니다."로 바뀝니다. 콘솔에는 `받은 데이터: (3) ["우유 사기", ...]`처럼 **진짜 배열**이 찍힙니다. → **이 화면이 "after(고친 후)" 캡처입니다.**

## 무엇을 어떻게 고쳤나 (before → after)

| | 고치기 전 (`broken.html`) | 고친 후 (`index.html` + `script.js`) |
| --- | --- | --- |
| 함수 선언 | `function loadTodos()` | `async function loadTodos()` |
| 데이터 받기 | `const todos = fetchTodos();` | `const todos = await fetchTodos();` |
| `todos` 안의 값 | `Promise { <pending> }` (빈 약속) | `["우유 사기", "운동 30분", ...]` (진짜 배열) |
| `todos.length` | `undefined` → 반복 0회 | `3` → 목록 정상 출력 |
| 실행 순서 | 데이터 도착 **전에** 화면을 그림 | 데이터 도착 **후에** 화면을 그림 |
| 결과 | 항상 빈 목록 | 할 일 3개 정상 표시 |

핵심은 코드를 복잡하게 늘린 게 아니라, **"기다렸다가 그리도록" 순서만 바로잡은 것**입니다. 단어 두 개(`async`, `await`)가 전부입니다.

### 한 가지 더 알아두기

- 고친 버전에는 `try { ... } catch (error) { ... }`도 넣었습니다. 실제 `fetch`는 와이파이가 끊기는 등 **실패할 수도** 있어서, 그럴 때 화면이 멈추지 않고 "불러오기 실패" 안내를 띄우도록 대비한 것입니다.
- `await`는 반드시 `async`가 붙은 함수 안에서만 쓸 수 있습니다. `async` 없이 `await`만 쓰면 문법 에러가 납니다.

## 검증법

1. `index.html`을 브라우저로 열고 약 0.5초 기다립니다. **할 일 3개(우유 사기 / 운동 30분 / 이메일 답장하기)**가 목록에 나타나면 성공입니다.
2. 상단 안내문이 "불러오는 중..." → "**할 일 3개를 불러왔습니다.**"로 바뀌면 성공입니다.
3. `F12` → **Console** 탭에 빨간 에러가 없고, `받은 데이터: (3) [...]`처럼 **배열**이 찍히면 정상입니다.
4. 비교 학습: `broken.html`을 열면 목록이 비어 있고 콘솔에 `Promise { <pending> }`와 `todos.length: undefined`가 그대로 떠야 합니다. before/after 콘솔 화면을 각각 캡처하면 제출물 완성입니다.
