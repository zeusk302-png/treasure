# 실습 329 — 외부 날씨 API 연동 위젯 만들기

내 페이지에 **"오늘 날씨"를 보여주는 작은 위젯**을 붙입니다. 날씨 데이터는 내가 만드는 게 아니라 **외부 서비스(날씨 API)**에서 받아 옵니다. 이 실습의 진짜 목표는 날씨 그 자체가 아니라, **외부 API에서 데이터를 받아 화면에 그리는 한 사이클**(요청 → 로딩 표시 → 성공/실패 처리)을 손에 익히는 것입니다. 이 흐름은 앞으로 만들 거의 모든 앱(검색·지도·환율·번역·AI 답변)에 똑같이 반복됩니다.

> 한 줄 그림: **사용자가 도시 선택 → `fetch`로 날씨 API에 요청 → 기다리는 동안 스켈레톤(깜빡이는 회색 줄) → 응답 도착 → 온도·날씨 그리기 → 실패하면 빨간 에러 + "다시 시도" 버튼**

> 비유: 날씨 API는 **전화로 답을 주는 기상청 콜센터**입니다. 내 위젯은 그 번호로 전화를 거는 사람이고요. 전화를 걸면 (1) 신호 가는 동안 "통화 연결 중"을 보여주고(로딩), (2) 상담원이 답하면 받아 적고(성공), (3) 통화가 끊기면 "다시 걸기" 버튼을 줍니다(실패). 이 세 경우를 다 챙겨야 사용자가 "먹통이 됐나?" 하고 불안해하지 않습니다.

> 키 관련 메모 — 이번 실습은 **API 키가 필요 없는** 공개 API(Open-Meteo)를 씁니다.
> - 그래서 코드(프론트)에 박혀 새어 나갈 **비밀값 자체가 없습니다.** (`.env`가 필요 없어, 첫 연동 실습으로 가장 안전합니다.)
> - 만약 **키가 필요한 API**(예: OpenWeatherMap)였다면, 그 키는 `index.html`/`script.js`에 절대 두면 안 됩니다. `F12`로 누구나 보고 도용하기 때문입니다. 그땐 **서버(또는 n8n/서버리스 함수)를 한 번 거쳐** 호출하고, 키는 서버 환경변수에만 둡니다. (관련 원리는 아래 가이드 링크 참고.)

## 목표
- **외부 API를 호출**한다: `fetch`로 날씨 API에 요청을 보내고, 돌아온 JSON 응답을 화면에 그린다.
- **세 가지 상태를 모두 처리**한다: 로딩 중(스켈레톤) · 성공(온도·날씨) · 실패(에러 메시지 + 다시 시도). "성공만" 처리하는 흔한 실수를 피한다.
- **"키가 필요한 API인지" 판별**한다: 공개 API는 그냥 호출하고, 키가 필요한 API는 왜 프론트에 키를 두면 안 되는지 안다.
- **안전하게 화면에 그린다**: 받아온 값은 `textContent`로 넣어 XSS를 피한다(`innerHTML`로 값을 합치지 않는다).

## 따라하는 단계

1. 이 폴더의 `index.html`을 **더블클릭**해 브라우저로 엽니다. (서버·설치 없이 바로 열립니다.)
2. 페이지가 열리면 자동으로 **부산 날씨**가 한 번 조회됩니다. 도시 드롭다운을 바꾸거나 **조회** 버튼을 누르면 다시 불러옵니다.
3. **로딩을 직접 보기**: 인터넷이 빠르면 순식간이라 안 보일 수 있습니다. `F12` → **Network** 탭에서 속도를 **Slow 3G**로 바꾼 뒤 조회하면, **스켈레톤(깜빡이는 회색 줄)**이 또렷이 보입니다.
4. **실패를 직접 만들어 보기**: `F12` → **Network** 탭에서 **Offline**에 체크하고 조회를 누릅니다. **빨간 에러 + 다시 시도** 버튼이 나오는지 확인합니다. (다시 온라인으로 바꾸고 "다시 시도"를 누르면 정상 복구됩니다.)
5. **데이터의 출처 보기**: `F12` → **Network**에서 `forecast?...` 요청을 클릭하면, 서버가 보낸 **원본 JSON**을 볼 수 있습니다. 코드의 `WEATHER_CODE` 표가 그 숫자 코드를 한국어로 바꾸는 부분입니다.
6. **다른 API로 바꿔 보기(선택)**: `script.js`의 `url`만 다른 공개 API 주소로 바꾸고, `renderSuccess`에서 꺼내는 필드 이름을 그 응답에 맞추면, 같은 골격으로 환율·미세먼지 같은 다른 위젯도 만들 수 있습니다.

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 비전공 입문자를 돕는 프론트엔드 멘토야.
  설치·빌드 없이 더블클릭으로 열리는 "오늘 날씨 위젯" 한 페이지(index.html + script.js)를 만들어 줘.

  요구사항:
  - 날씨 데이터는 API 키가 필요 없는 공개 API인 Open-Meteo(api.open-meteo.com/v1/forecast)에서 fetch로 받아온다.
  - 도시 드롭다운(부산/서울/대구/제주/인천)을 두고, 각 도시의 위도·경도를 option 값으로 미리 넣는다.
  - 받아온 온도·현재 날씨(weather_code)·습도·바람을 카드 형태로 보여준다.
  - weather_code(숫자)는 한국어 설명+이모지로 바꿔서 표시한다.

  제약:
  - 모든 코드에 "무엇(기능) + 왜(이렇게 한 이유)" 한국어 주석을 달고, 파일 맨 위엔 이 파일이 무엇인지 요약 주석을 둬.
  - 변수·함수 이름은 영어로.
  - 사용자에게 보일 값은 innerHTML로 문자열을 합치지 말고 textContent로 넣어(XSS 방지). 이유도 주석으로 적어.
  산출물: index.html, script.js 두 파일 전체 코드.
  ```

- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 날씨 위젯에 "세 가지 상태"를 제대로 처리하는 코드를 추가해 줘.
  1) 로딩 중: 데이터를 기다리는 동안 깜빡이는 스켈레톤(회색 줄)을 보여주고, 조회 버튼은 잠가서 중복 호출을 막아줘.
  2) 성공: 정상적으로 날씨를 그린다.
  3) 실패: fetch가 실패하거나(res.ok가 false거나 네트워크 끊김) 응답 형식이 예상과 다르면,
     빨간 에러 메시지와 "다시 시도" 버튼을 보여줘. 다시 시도를 누르면 같은 조회를 한 번 더 한다.
  - try/catch/finally를 쓰고, finally에서 버튼 잠금을 항상 풀어줘.
  - fetch는 404·500에도 throw하지 않으니 res.ok를 직접 확인해야 한다는 점을 주석으로 설명해줘.
  - 왜 그렇게 했는지 비전공자가 이해하게 한 줄씩 주석으로 풀어줘.
  ```

- **막혔을 때(디버깅)** 프롬프트:
  ```text
  날씨 위젯이 동작을 안 해. 아래 정보를 보고 원인을 단계별로 진단하고, 고친 코드를 알려줘.
  - 증상: (예) 조회를 눌러도 계속 로딩만 돌고 결과가 안 나온다 / "TypeError: Cannot read properties of undefined" 가 콘솔에 뜬다.
  - 콘솔(F12 → Console) 에러 전체: (여기에 붙여넣기)
  - Network 탭에서 forecast 요청의 상태 코드(200/404/CORS 등)와 응답 JSON 일부: (여기에 붙여넣기)
  점검해 줄 것:
  1) url이 정확한지(위도·경도 자리, current 파라미터 철자).
  2) 응답 JSON에서 내가 꺼내는 필드 이름(json.current.temperature_2m 등)이 실제 응답과 일치하는지.
  3) await를 빠뜨렸거나 .json()을 안 했는지.
  원인 → 고친 코드 → 왜 그게 문제였는지 순서로, 비전공자가 이해하게 설명해줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법
- **성공 화면 확인**: 페이지를 열면(또는 조회를 누르면) 온도·날씨 설명·습도·바람이 **숫자로** 뜬다. 도시를 바꾸면 값이 바뀐다.
- **로딩 상태 확인**: `F12` → Network에서 속도를 **Slow 3G**로 낮추고 조회하면, 결과가 오기 전에 **스켈레톤(깜빡이는 회색 줄)**이 보인다.
- **실패 상태 확인**: `F12` → Network에서 **Offline** 체크 후 조회하면 **빨간 에러 + 다시 시도** 버튼이 뜬다. 온라인으로 되돌리고 "다시 시도"를 누르면 정상 복구된다.
- **중복 호출 방지 확인**: 조회를 누른 직후 버튼이 잠깐 **비활성(흐려짐)**되었다가, 끝나면 다시 눌러진다.
- **원본 데이터 대조**: Network에서 `forecast?...` 요청의 응답 JSON에 찍힌 온도와, 화면에 보이는 온도가 **일치**하는지 본다.
- **비밀값이 없는지 확인**: 이번 API는 키가 없어 코드에 비밀값이 있으면 안 된다. 폴더에서 아래를 실행하면 결과가 **비어 있어야** 정상이다.
  - `grep -nE "api[_-]?key|Bearer [A-Za-z0-9]{10}|sk-[A-Za-z0-9]{10}" index.html script.js`

## 파일 구성
- `index.html` — 날씨 위젯의 화면(구조)과 스타일. 도시 드롭다운·조회 버튼·결과 영역이 들어 있다.
- `script.js` — 동작 부분. 외부 API 호출(`fetch`)과 로딩/성공/실패 세 상태 처리가 모두 여기에 있다.
- (이번 실습은 **API 키가 필요 없어** `.env`/`.gitignore`가 필요 없습니다. 키가 필요한 API로 바꿀 땐 키를 서버 환경변수에 두고 `.env`는 `.gitignore`에 넣으세요.)
