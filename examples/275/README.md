# 실습 275 — AI 챗봇 SaaS 배포 · 도메인 연결 · 포트폴리오로 완성하기

> **아키타입 미니프로젝트 (난이도 5)** · 분류: 아키타입 미니프로젝트 · 개념: 통합 배포, 도메인, 포트폴리오화

이 실습은 챗봇 시리즈(271→272→273→274)의 **마지막 한 걸음**입니다.
앞에서 만든 챗봇(말풍선 UI · API 키 보호 · 대화 이력 · RAG)을 이제 **세상에 내보내고**, 산 도메인을 붙여 **"내 작품"으로 정리**합니다. 코드를 새로 많이 짜는 단계가 아니라, **배포 + 도메인 + 포트폴리오 카드**라는 한 개의 결과물을 완성하는 단계입니다.

이 폴더에 들어 있는 것:
- `index.html` — 바로 쓸 수 있는 **포트폴리오 프로젝트 설명 카드**(취업/외주용). 그대로 열어보고, 표시된 `YOUR_...` 자리만 내 정보로 바꾸면 됩니다.
- `vercel.json` — Vercel 배포 시 적용할 기본 보안 헤더 설정.
- `.env.example` — 배포할 때 어떤 값을 어디에 넣어야 하는지 알려주는 **견본**(가짜 값만 들어 있어 안전).

---

## 목표

- 깃허브에 올린 코드가 **GitHub → Vercel 자동배포**로 인터넷에 공개되는 과정을 직접 경험한다.
- 비밀 값(서비스 롤 키 · AI API 키)을 **코드에 박지 않고** Vercel 환경변수 화면에 넣는 올바른 방법을 익힌다.
- 무료로 받는 `xxx.vercel.app` 주소를 **내가 산 도메인 + HTTPS(자물쇠)**로 바꾼다.
- 완성한 프로젝트를 **한 장짜리 설명 카드**(`index.html`)로 정리해 이력서·포트폴리오에 붙일 **취업 자산**으로 만든다.

### 비유로 이해하기

지금까지는 **집을 다 지어 놓고(코드 완성)**, 마당(내 컴퓨터)에만 세워 둔 상태였습니다.
- **배포**는 그 집을 진짜 땅(인터넷)에 옮겨 세우는 일이고,
- **도메인 연결**은 "어디 시 어디 동 123번지" 같은 외우기 좋은 **주소 간판**을 다는 일이며,
- **포트폴리오 카드**는 그 집 앞에 세우는 **"이 집은 제가 이렇게 지었습니다" 안내판**입니다.

---

## 따라하는 단계

1. **이 폴더의 `index.html`을 더블클릭**해서 브라우저로 엽니다. 어떤 모양의 설명 카드인지 먼저 눈으로 봅니다.
2. `index.html`을 메모장/VS Code로 열어 **`YOUR_...` 표시를 모두 내 정보로** 바꿉니다.
   - `YOUR_NAME_HERE` → 내 이름, `YOUR_EMAIL@example.com` → 내 메일
   - `https://YOUR_DOMAIN_HERE.com` → (4번에서 정할) 진짜 도메인 주소
   - `YOUR_GITHUB_ID` → 내 깃허브 아이디
3. **코드를 깃허브에 올립니다.** 앞 실습에서 만든 챗봇 폴더를 GitHub 저장소(repository)로 올립니다(push). 이때 `.env`(진짜 비밀 값) 파일은 **절대 같이 올라가면 안 됩니다** — `.gitignore`에 `.env`가 들어 있는지 확인하세요. (가이드 04/03)
4. **Vercel에 깃허브 저장소를 연결**합니다. [vercel.com](https://vercel.com) 가입 → "New Project" → 내 저장소 선택 → Deploy. 잠시 뒤 `프로젝트이름.vercel.app` 주소가 만들어집니다. (가이드 05/01)
5. **비밀 값을 Vercel 환경변수에 입력**합니다. Vercel 프로젝트 → Settings → Environment Variables 에서 `.env.example`에 적힌 이름 그대로 넣습니다.
   - `SUPABASE_URL`, `SUPABASE_ANON_KEY` → **공개해도 되는 값** (프론트에서 사용)
   - `SUPABASE_SERVICE_ROLE_KEY`, `AI_API_KEY` → **절대 숨길 값**, **서버 함수에서만** 사용. 브라우저 코드에 넣지 않습니다. (가이드 04/01)
6. **커스텀 도메인을 연결**합니다. 도메인을 구매(예: 가비아·카페24·Cloudflare 등)한 뒤, Vercel 프로젝트 → Settings → Domains에서 도메인을 추가하고 안내대로 DNS 레코드를 등록합니다. 몇 분~몇 시간 뒤 연결되며 **HTTPS 자물쇠는 Vercel이 자동**으로 붙여 줍니다. (가이드 05/06)
7. 도메인이 붙으면 **`index.html`의 `YOUR_DOMAIN_HERE` 두 곳**(상단 메타태그·"라이브 데모 열기" 버튼)을 진짜 도메인으로 다시 한번 맞춰 줍니다.
8. AI에게 검토 요청해 마무리합니다.
   > "이 포트폴리오 설명 카드를 비전공자 신입 지원자의 이력서용으로 본다면, 더 보강하면 좋을 한 줄을 제안해줘."

## 🤖 바이브코딩 프롬프트

이 실습(배포 + 도메인 연결 + 포트폴리오 카드)을 AI에게 시켜 완성할 때 그대로 복사해 쓸 수 있는 프롬프트입니다. `< >` 안은 내 정보로 바꿔서 보내세요.

- **1단계(뼈대 만들기)** — 포트폴리오 설명 카드 만들기:
  ```text
  너는 비전공 신입 개발자의 포트폴리오를 돕는 프론트엔드 도우미야.
  내가 만든 "AI 챗봇 SaaS"를 한 장으로 소개하는 정적 포트폴리오 카드(index.html) 하나를 만들어줘.

  [담을 내용]
  - 상단 히어로: 프로젝트 이름 + 한 줄 소개 + "라이브 데모 열기" / "소스 코드(GitHub)" 버튼 2개
  - 핵심 기능 4가지 카드: 로그인/사용자 구분, API 키 보호(서버 중계), 대화 이력 저장, 문서 기반 답변(RAG)
  - 사용 기술 칩, "내가 직접 한 일", "배운 점" 목록
  - 푸터에 이름·이메일

  [제약]
  - HTML 파일 하나에 <style>까지 다 넣어 더블클릭만으로 열리게 해줘(외부 라이브러리·빌드 도구 없이).
  - 이름/도메인/깃허브 아이디처럼 나중에 바꿀 값은 YOUR_NAME_HERE 같은 자리표시자로 표시해줘.
  - 모바일에서도 안 깨지게 반응형으로.
  - 비전공자가 읽을 수 있게, 막힐 만한 부분에 "무엇을 왜 했는지" 한국어 주석을 달아줘.
  ```

- **2단계(기능 추가/개선)** — 배포 준비물 갖추기:
  ```text
  위 포트폴리오 프로젝트를 Vercel에 배포할 준비를 도와줘.

  1) vercel.json 을 만들어서 기본 보안 헤더(X-Content-Type-Options: nosniff,
     X-Frame-Options: SAMEORIGIN, Referrer-Policy)를 모든 경로에 적용해줘.
     각 헤더가 무엇을 막아주는지 설명도 같이 해줘.
  2) .env.example 견본을 만들어줘. SUPABASE_URL / SUPABASE_ANON_KEY 는
     "공개해도 되는 값", SUPABASE_SERVICE_ROLE_KEY / AI_API_KEY 는
     "절대 숨겨야 하는 값"으로 구분해서 주석으로 표시하고, 진짜 값은 넣지 말고
     가짜 자리표시자만 넣어줘. .gitignore 에 .env 가 들어가야 하는 이유도 알려줘.
  3) 검색·공유용 메타태그(title, description, og:title, og:url)를 index.html 에 넣어줘.
  코드만 주지 말고, 왜 그렇게 했는지 한 줄씩 풀어서 설명해줘.
  ```

- **막혔을 때(디버깅)** — 배포 후 문제 진단:
  ```text
  Vercel에 배포했는데 문제가 생겼어. 비전공자가 이해하게 단계별로 진단해줘.

  [증상] <예: 배포는 됐는데 챗봇이 답을 안 한다 / 콘솔에 401 에러가 뜬다 / http로만 열린다>
  [에러 메시지] <F12 콘솔이나 Vercel 빌드 로그에 뜬 빨간 글자를 그대로 붙여넣기>

  - 원인 후보를 가능성 높은 순서로 알려주고,
  - 각각 내가 직접 눌러서 확인할 수 있는 방법(어느 화면 → 무엇을 본다)을 알려줘.
  - 특히 service_role 키나 AI_API_KEY 가 브라우저로 새고 있지는 않은지 점검하는 법을 꼭 포함해줘.
  ```

> 프롬프트 팁: 어떤 단계든 끝에 "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 그냥 결과물을 받는 게 아니라 직접 판별할 수 있는 '디렉터'가 됩니다.

## 검증법

- **라이브 접속**: 브라우저 주소창에 내 도메인을 직접 쳐서 들어갔을 때 챗봇이 열리고, 질문을 보내면 답이 오는가?
- **HTTPS 확인**: 주소창에 **자물쇠 아이콘**이 보이고, 주소가 `https://` 로 시작하는가? (`http://` 면 아직 미완)
- **비밀 키 안 새는지 확인 (가장 중요)**: 배포된 사이트에서 `F12 → Network/소스`를 열어, **`service_role` 키나 `AI_API_KEY` 글자가 브라우저로 내려오지 않는지** 확인한다. 보이면 안 됩니다. (보이면 그 값은 즉시 폐기·재발급 → 가이드 04/05)
- **공개 키는 보여도 정상**: 반대로 `anon`(공개) 키가 브라우저에 보이는 것은 **정상**입니다. RLS가 막아 주기 때문입니다. (가이드 04/01, 04/02)
- **다른 기기 테스트**: 휴대폰(다른 와이파이/데이터)에서 같은 주소로 들어가도 똑같이 작동하는가? → "내 컴퓨터에서만 되는" 게 아니라 진짜 배포된 것.
- **포트폴리오 카드**: `index.html`에 `YOUR_` 로 시작하는 자리표시자가 **하나도 안 남아 있는가?** "라이브 데모 열기" 버튼이 진짜 사이트로 연결되는가?
