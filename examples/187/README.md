# 187 — 내 페이지 주소를 적은 sitemap.xml 만들기

검색엔진(구글·네이버 같은 곳)은 **"크롤러"** 라는 자동 로봇을 보내 내 사이트를 돌아다니며 페이지를 하나씩 찾아 읽습니다.
그런데 로봇이 링크를 따라가다 보면 **숨어 있는 페이지**(아무도 링크를 안 걸어 둔 페이지)는 영영 못 찾을 수도 있습니다.

`sitemap.xml`은 그 로봇에게 건네주는 **"우리 사이트 페이지 목록(지도)"** 입니다.
"우리 집에는 이런 방들이 있어요" 하고 **주소를 한 번에 모아서** 알려 주는 명단이라고 보면 됩니다.

이번 실습에서는 이 파일을 **직접 만들어** 사이트 루트(맨 앞 주소)에 올리고, 브라우저로 잘 열리는지 확인합니다.

- 카테고리: SEO·성능·접근성 (코드 I)
- 난이도: 2 / 5
- 개념: sitemap.xml, URL 목록
- 결과물: 사이트 루트에 배치된 **`sitemap.xml` 파일** (이 폴더의 `sitemap.xml`이 올릴 파일입니다)

> 이 폴더 안의 **`sitemap.xml`** 이 바로 올릴 파일입니다. 그대로 쓰지 말고, 안의 주소를 **내 사이트 주소로 바꿔서** 올리면 됩니다.

---

## 목표

`sitemap.xml`은 어렵게 생겼지만, 실제로 외울 건 **딱 두 가지**뿐입니다.

- **`<urlset>` … `</urlset>`** — 페이지 목록 전체를 감싸는 큰 바구니.
- **`<url>` … `</url>`** — 페이지 **한 개**를 담는 칸. 페이지가 4개면 이 묶음이 4개 있습니다.

그리고 `<url>` 한 칸 안에 들어가는 정보는 이렇습니다. 진짜 필수는 **`<loc>` 하나뿐**이고 나머지는 "있으면 참고용"입니다.

| 태그 | 뜻 | 필수? |
|---|---|---|
| `<loc>` | 페이지의 **전체 주소(URL)** | **필수** (이것만 있어도 됨) |
| `<lastmod>` | 마지막으로 **고친 날짜** (YYYY-MM-DD) | 선택 |
| `<changefreq>` | 얼마나 자주 바뀌나 (`daily`/`weekly`/`monthly` 등) | 선택 |
| `<priority>` | 사이트 안에서의 **중요도** (0.0 ~ 1.0, 홈이 보통 1.0) | 선택 |

> 비유: `sitemap.xml`은 가게 입구에 비치하는 **"우리 가게 안내 지도"** 입니다.
> 손님(검색 로봇)이 직접 발품 팔지 않아도, 이 지도만 보면 **"여기에 어떤 코너들이 있구나"** 하고 한눈에 알 수 있습니다.
> 그래서 새로 만든 페이지도 **더 빨리, 더 빠짐없이** 검색에 잡히게 됩니다.

지켜야 할 약속 두 가지만 기억하세요.

1. **파일 이름은 반드시 소문자 `sitemap.xml`** 입니다. (`Sitemap.xml`, `sitemap.html` 같은 건 인식 안 됨)
2. **`<loc>` 안의 주소는 `https://`까지 포함한 전체 주소**여야 합니다. (`/about`처럼 쓰면 안 되고 `https://내사이트.com/about`)

> 보안 메모: `sitemap.xml`은 **누구나 열어 볼 수 있는 공개 파일**입니다 (`내사이트.com/sitemap.xml`로 바로 보입니다).
> 그러니 **로그인해야만 보이는 관리자 페이지나 비밀 주소를 여기에 적지 마세요.** 적는 순간 "여기 이런 페이지가 있어요" 하고 광고하는 꼴이 됩니다.
> 비밀번호·API 키 같은 **비밀값은 절대 넣지 않습니다.** 진짜로 숨겨야 하는 페이지는 sitemap이 아니라 **로그인/권한(예: Supabase RLS)** 으로 막아야 합니다.

## 따라하는 단계

### 1단계 — 이 폴더의 sitemap.xml 열어 보기

1. 이 폴더(`examples/187/`)의 **`sitemap.xml`** 을 메모장이나 VS Code로 엽니다.
2. 맨 윗줄 `<?xml ... ?>`와 `<!-- ... -->`(설명 주석)는 그대로 두고, **`<url> … </url>` 묶음**이 4개 있는 것을 확인합니다. (홈/소개/블로그/문의)
3. `<url>` 한 묶음이 **페이지 한 개**라는 점만 눈으로 확인하면 됩니다.

### 2단계 — 내 사이트 주소로 바꾸기

1. 파일 안의 **`https://내사이트.com`** 을 전부 **내 실제 도메인**으로 바꿉니다. (예: `https://my-portfolio.vercel.app`)
   - VS Code라면 `Ctrl + H`(바꾸기)로 `내사이트.com`을 한 번에 내 주소로 치환하면 편합니다.
2. **`<loc>` 안의 뒷부분**(`/about`, `/blog` 등)을 내 페이지 주소에 맞게 고칩니다. 없는 페이지는 그 `<url> … </url>` 묶음을 **통째로 지웁니다.**
3. **페이지가 더 있으면** `<url> … </url>` 한 묶음을 복사해서 아래에 붙이고 주소만 바꿔 늘립니다.
4. `<lastmod>` 날짜는 그 페이지를 마지막으로 고친 날로 적으면 됩니다. (잘 모르겠으면 오늘 날짜를 적거나 그 줄을 지워도 동작합니다.)

> 헷갈리지 마세요: `<loc>`에는 반드시 **`https://`로 시작하는 전체 주소**를 적습니다. `/about`처럼 짧게 쓰면 검색엔진이 인식하지 못합니다.

### 3단계 — 사이트 "루트"에 올리기

`sitemap.xml`은 반드시 사이트 맨 앞 주소(루트)에 있어야 합니다. 즉 `내사이트.com/sitemap.xml`로 열려야 합니다. 쓰는 도구에 따라 위치만 다릅니다.

- **Vercel / 정적 사이트:** 프로젝트의 **`public/` 폴더**에 `sitemap.xml`을 넣고 평소처럼 배포(push)합니다. `public` 안에 둔 파일은 자동으로 루트(`/sitemap.xml`)로 올라갑니다.
- **GitHub Pages:** 저장소 **맨 위(루트)** 에 `sitemap.xml`을 올립니다. (`index.html`과 같은 위치)
- **직접 서버:** 웹 루트 폴더(보통 `index.html`이 있는 곳)에 그대로 둡니다.

### 4단계 — robots.txt에 위치 알려 주기(선택, 추천)

`robots.txt`(186번 실습 참고)가 있다면 마지막 줄에 아래 한 줄을 넣어 두면 검색엔진이 sitemap을 더 잘 찾습니다.

```
Sitemap: https://내사이트.com/sitemap.xml
```

### 5단계 — 구글에 제출하기(선택)

- **Google Search Console** → "Sitemaps" 메뉴에서 `sitemap.xml`을 입력해 제출하면, 구글이 내 페이지 목록을 더 빨리 받아 갑니다. (필수는 아니지만 새 사이트라면 추천합니다.)

## 🤖 바이브코딩 프롬프트

`sitemap.xml`은 직접 손으로 만들 수도 있지만, AI에게 시키면 내 페이지 목록에 맞게 한 번에 만들어 줍니다. 아래 프롬프트를 그대로 복사해 쓰세요. (`내사이트.com`과 페이지 목록은 내 것으로 바꿔서)

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 SEO를 잘 아는 웹 도우미야. 내 사이트의 sitemap.xml을 만들어 줘.
  - 내 도메인: https://my-portfolio.vercel.app  (← 내 실제 주소로 바꿀 것)
  - 페이지 목록: 홈(/), 소개(/about), 블로그(/blog), 문의(/contact)
  - 표준 형식: <?xml ...?> 선언 + <urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9"> 사용
  - 각 <url>에는 <loc>(전체 주소, https:// 포함)을 필수로, <lastmod>(오늘 날짜)·<changefreq>·<priority>를 함께 넣어 줘.
  제약: <loc>에는 절대 /about 같은 짧은 주소가 아니라 https://로 시작하는 전체 주소만 넣을 것.
  결과물: sitemap.xml 파일 내용 하나. 그리고 각 줄이 무슨 뜻인지 한국어 주석(<!-- -->)으로 설명해 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  좋아. 이제 페이지를 더 추가하고 우선순위를 다듬자.
  - 추가 페이지: /portfolio (작품 모음), /blog/first-post (블로그 글 1개)
  - 홈은 priority 1.0, 소개·블로그·포트폴리오는 0.8, 개별 글·문의는 0.5로 정리해 줘.
  - 관리자 페이지(/admin)나 로그인해야 보이는 비밀 페이지는 절대 넣지 마. (공개 파일이라 광고하는 꼴이 됨)
  - robots.txt에 넣을 'Sitemap:' 한 줄도 같이 알려 줘.
  바뀐 부분이 왜 그런지 비전공자가 이해하게 한 줄씩 풀어서 설명해 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  내 sitemap.xml을 브라우저(https://내사이트.com/sitemap.xml)로 열었더니 아래 에러가 떠.
  [여기에 화면에 뜬 에러 메시지나 빨간 글씨를 그대로 붙여넣기]
  무엇이 문제인지 단계별로 짚어 주고, 고친 전체 파일을 다시 줘.
  특히 다음을 점검해 줘: 여는 태그/닫는 태그(<url>·</url>) 개수가 맞는지,
  주소에 &·<·> 같은 특수문자가 그대로 들어갔는지, <loc>가 전부 https://로 시작하는지.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면, 결과물을 그냥 받기만 하는 게 아니라 옳은지 직접 판별하는 눈이 생깁니다.

## 검증법

아래가 모두 맞으면 성공입니다.

- **파일이 열린다:** 배포 후 주소창에 **`https://내사이트.com/sitemap.xml`** 을 직접 입력하면, 페이지 목록(XML 내용)이 그대로 보인다. (404가 뜨면 위치가 루트가 아니거나 파일 이름이 틀린 것.)
- **빨간 에러가 없다:** 브라우저로 열었을 때 "오류"나 빨간 글씨가 안 보이면 XML 형식이 깨지지 않은 것이다.
  - 흔한 깨짐 원인: 여는 태그(`<url>`)와 닫는 태그(`</url>`) 개수가 안 맞거나, `&` 같은 특수문자를 주소에 그대로 쓴 경우.
- **주소가 진짜 주소다:** 모든 `<loc>` 안에 `내사이트.com` 같은 **자리표시자가 남아 있지 않고**, 전부 `https://`로 시작하는 내 실제 주소로 바뀌어 있다.
- **클릭하면 열린다:** `<loc>`에 적은 주소를 브라우저에 직접 넣으면 그 페이지가 정상으로 열린다. (없는 페이지·오타 주소가 섞이면 안 됨.)
- **구글 도구로 점검(추천):** Google Search Console에 sitemap을 제출하면 "읽음 성공/오류" 상태와 발견한 URL 개수를 알려 준다.

> 흔한 실수
> - **자리표시자(`내사이트.com`)를 안 바꿈:** 가짜 주소가 올라가 검색엔진이 페이지를 못 찾습니다. 올리기 전 `Ctrl+F`로 `내사이트.com`이 하나도 안 남았는지 확인하세요.
> - **위치가 루트가 아님:** `/docs/sitemap.xml`처럼 하위 폴더에 두면 무시됩니다. Vercel은 `public/`에, GitHub Pages는 저장소 루트에 둡니다.
> - **`<loc>`에 짧은 주소(`/about`)를 적음:** 반드시 `https://`로 시작하는 전체 주소여야 합니다.
> - **태그 짝이 안 맞음:** `<url>`을 복사해 늘릴 때 `</url>`을 빠뜨리면 파일 전체가 깨집니다. 묶음 단위(`<url>`부터 `</url>`까지)로 복사하세요.
> - **비공개/관리자 주소를 적음:** 공개 파일이므로 비밀 페이지·관리자 페이지 주소는 넣지 않습니다.
