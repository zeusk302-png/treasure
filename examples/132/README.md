# 실습 132 — 이메일·비밀번호 로그인 폼 만들고 "로그인 성공" 띄우기

이메일과 비밀번호를 입력해 로그인하고, **성공하면 환영 메시지**, **실패하면 에러 메시지**를 화면에 보여줍니다. 서버 코드 없이 브라우저에서 Supabase 인증(`signInWithPassword`)을 직접 부르는, 인증의 가장 첫 흐름입니다.

## 목표
- "로그인 = 누구인지 확인(인증)"의 첫 흐름을 직접 만들어 본다.
- 성공/실패를 갈라 **사용자에게 알맞은 메시지**를 보여주는 패턴을 익힌다.
- 브라우저에 두는 건 **anon(공개돼도 되는 출입증)** 키뿐이고, `service_role`(절대 숨길 비밀) 키는 절대 두지 않는다는 원칙을 체득한다.

## 따라하는 단계
1. [supabase.com](https://supabase.com)에서 프로젝트를 만든다(부트캠프에서 한 것).
2. **Authentication → Users**에서 테스트 계정을 하나 추가한다. (이메일 + 비밀번호. "Auto Confirm User"를 켜면 메일 인증 없이 바로 로그인됩니다.)
3. **Settings → API**에서 `Project URL`과 `anon`(publishable) 키를 복사한다.
4. `login.html` 위쪽의 `SUPABASE_URL`, `SUPABASE_ANON_KEY` 두 값을 내 값으로 바꾼다.
5. `login.html`을 브라우저로 열고, 2번에서 만든 이메일·비밀번호로 로그인해 본다.
6. 일부러 **틀린 비밀번호**도 넣어 본다 → 빨간 에러 메시지가 뜬다.

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. 내 상황(이메일/비밀번호 로그인)에 맞게 살짝만 고쳐 쓰세요.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 프론트엔드 멘토야. 서버 없이 브라우저에서 바로 열리는 login.html 한 파일을 만들어줘.
  - 화면: 이메일 입력칸(type=email), 비밀번호 입력칸(type=password), "로그인" 버튼, 결과 메시지 영역
  - 동작: 버튼을 누르면 Supabase의 signInWithPassword로 이메일·비밀번호 로그인 시도
  - 결과: 성공하면 초록색 환영 메시지, 실패하면 빨간색 에러 메시지를 화면에 보여줘
  - 보안 제약: Supabase URL과 anon(publishable) 키만 코드에 두고, service_role 키는 절대 넣지 마. 그 이유를 주석으로 적어줘.
  - 산출물: 외부 빌드 도구 없이 그냥 더블클릭으로 열리는 HTML 한 파일. 초보가 읽을 수 있게 한국어 주석을 달아줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 login.html을 개선해줘.
  - 로그인 처리 중에는 버튼을 비활성화(disabled)해서 더블 클릭으로 두 번 요청 가는 걸 막아줘.
  - 결과 메시지를 화면에 넣을 때 innerHTML 말고 textContent를 써줘. 왜 그게 안전한지(XSS) 주석으로 설명해줘.
  - 성공하면 data.user.email을 이용해 "○○님, 로그인 성공!"처럼 사용자 이메일을 넣어 환영해줘.
  - 바뀐 부분마다 "무엇을 했고 왜 했는지" 한국어 주석을 달아줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  login.html로 로그인하면 아래 에러가 떠. 비전공자도 이해하게 원인 후보를 우선순위대로 알려주고, 각각 어떻게 확인·수정하는지 한 단계씩 설명해줘.
  [여기에 브라우저 콘솔(F12)의 에러 메시지를 그대로 붙여넣기]
  특히 SUPABASE_URL/anon 키 오타, 테스트 계정 미생성, 이메일 미인증(Auto Confirm 안 켬), CDN 로드 실패 가능성을 짚어줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 훨씬 좋습니다.

## 검증법
- 올바른 이메일·비밀번호 → 초록색 "○○님, 로그인 성공! 환영합니다" 메시지가 뜨는가?
- 틀린 비밀번호 → 빨간색 "로그인 실패: ..." 메시지가 뜨는가?
- 이메일 칸에 형식에 안 맞는 값(예: `abc`)을 넣으면, 제출 전에 브라우저가 먼저 막는가? (`type="email"` 덕분)

## 안전(보안) 짚고 가기
- 여기 넣는 건 **anon(publishable) 키** 하나뿐입니다. anon 키는 "공개돼도 되는 출입증"이라 브라우저·GitHub에 있어도 괜찮습니다.
- `service_role`(secret) 키는 **RLS를 통째로 우회**하는 마스터키라, 브라우저나 깃허브에 두면 안 됩니다. 두 키를 헷갈리는 게 가장 흔한 사고입니다.
- 중요한 점: **로그인(인증)이 됐다고 끝이 아닙니다.** "로그인한 사람이 자기 데이터만 만지게" 막는 건 별개의 문제(인가)이고, 그건 DB의 **RLS 정책**으로 강제해야 합니다.
