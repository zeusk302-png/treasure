# 216. 나쁜 프롬프트 vs 좋은 프롬프트 3개 짝지어 적어보기

## 목표

"다크모드 토글 만들어줘" 같은 막연한 부탁을 **맥락·목표·제약** 세 가지를 넣어 다시 써 봅니다.
같은 일을 시켜도 프롬프트를 어떻게 쓰느냐에 따라 AI(Claude 등)의 결과물이 얼마나 달라지는지를
"나쁜 → 좋은" 3쌍을 직접 적어 보며 눈으로 익히는 것이 목표입니다.

이 실습에는 코드가 필요 없습니다. **글쓰기 연습**이 곧 실습입니다.
결과물은 [`prompts.md`](prompts.md) 한 개입니다.

## 따라하는 단계

1. [`prompts.md`](prompts.md) 파일을 엽니다. 맨 위에 적힌 **프롬프트 3원칙**(맥락·목표·제약)을 먼저 소리 내어 읽습니다.
2. 1쌍의 **나쁜 프롬프트**("다크모드 토글 만들어줘")를 보고, 무엇이 빠졌는지 스스로 짚어 봅니다. (맥락? 목표? 제약?)
3. 바로 아래 **좋은 프롬프트**를 읽으며, `[맥락] / [목표] / [제약]` 세 칸이 각각 어떤 내용으로 채워졌는지 확인합니다.
4. 2쌍(문의 폼), 3쌍(느린 사이트)도 같은 방식으로 "빠진 것 → 채운 것"을 비교합니다.
5. 이제 직접 해봅니다. 내가 만들고 싶은 것 하나를 골라, **나쁜 버전 한 줄**과 **좋은 버전(맥락/목표/제약 3칸)**을 새로 한 쌍 더 적어 봅니다.
6. (선택) 좋은 프롬프트를 실제 Claude에게 붙여넣어 보고, 나쁜 프롬프트로 받은 답과 비교해 봅니다.

## 🤖 바이브코딩 프롬프트

이 실습 자체가 '프롬프트 잘 쓰기' 연습이라 조금 특별합니다. 아래는 **AI에게 이 실습을 도와달라고 시킬 때** 그대로 복사해 쓸 수 있는 프롬프트입니다. (AI에게 좋은 프롬프트를 짜 달라고 하는 것도 좋은 프롬프트가 필요합니다!)

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  [맥락] 나는 비전공 바이브코딩 부트캠프 수강생이고, '나쁜 프롬프트 vs 좋은 프롬프트'를
  비교하는 글쓰기 연습을 하는 중이야. 결과물은 prompts.md 마크다운 파일 하나야.

  [목표] 프롬프트 3원칙(맥락/목표/제약)을 맨 위에 설명으로 정리하고,
  '나쁜 프롬프트 → 좋은 프롬프트' 1쌍을 예시로 만들어줘.
  나쁜 쪽은 한 줄짜리 막연한 부탁, 좋은 쪽은 [맥락]/[목표]/[제약] 3칸을 채운 형태로.

  [제약]
  - 코드가 아니라 마크다운 글이야. 코드 블록은 프롬프트 예시를 담는 용도로만 써.
  - 주제는 '다크모드 토글 만들기' 하나로.
  - 나쁜 프롬프트 아래에 '무엇이 빠졌나'를 3원칙 용어로 짚어줘.
  - 한국어로, 비전공자가 읽어도 이해되게.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  [맥락] 방금 만든 '다크모드 토글' 1쌍에 이어서 prompts.md를 더 채우고 싶어.

  [목표] 같은 형식(나쁜 → 좋은, 좋은 쪽은 맥락/목표/제약 3칸)으로
  '문의 폼 만들기'와 '사이트가 느려요' 두 쌍을 더 추가해줘.
  마지막에는 보내기 전 스스로 점검하는 '맥락/목표/제약' 체크리스트도 붙여줘.

  [제약]
  - 기존 1쌍의 형식·말투를 그대로 유지해서 통일감 있게.
  - 보안 예시(문의 폼)에서는 공개 가능한 anon 키와 비밀인 service_role 키를
    구분해서 설명해줘. (anon=공개 가능, service_role=절대 프론트 금지)
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  내가 쓴 '좋은 프롬프트'를 아래에 붙여넣을게. 이게 정말 '좋은' 프롬프트인지 점검해줘.
  맥락/목표/제약 3가지 중 빠지거나 약한 부분이 있으면 그것만 콕 집어 알려주고,
  어떻게 보완하면 좋을지 한 줄짜리 예시 문장으로 제안해줘.
  (내 프롬프트: 여기에 붙여넣기)
  ```
> 프롬프트 팁: AI에게 시킬 때 "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 결과물이 학습 자료가 됩니다.

## 검증법

아래를 모두 만족하면 성공입니다.

- [ ] `prompts.md`에 "나쁜 → 좋은" 프롬프트가 **3쌍 이상** 들어 있다.
- [ ] 각 **좋은 프롬프트**에 **맥락·목표·제약 3가지가 모두** 명시되어 있다. (한 가지라도 빠지면 다시 채우기)
- [ ] 나쁜 프롬프트마다 "무엇이 빠졌는지"를 3원칙 용어로 설명할 수 있다.
- [ ] 직접 추가한 1쌍에서도 좋은 버전이 맥락·목표·제약을 갖췄다.

> 빠르게 자가 점검: 좋은 프롬프트를 읽고 **"이 글만 보고 다른 사람도 똑같은 결과물을 만들 수 있겠다"** 싶으면 통과입니다.
> 읽고도 "그래서 뭘 만들라는 거지?" 싶으면 목표나 제약이 부족한 것입니다.
