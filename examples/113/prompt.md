# 다음 단계 학습 프롬프트 템플릿 — "왜 서버 DB가 필요한가"

실습 113에서 localStorage의 한계를 직접 확인했다면, 이제 그 경험을 **Claude(또는 다른 AI)** 에게 설명받아
**1쪽짜리 메모**로 정리할 차례입니다. 아래 프롬프트를 복사해서 그대로 붙여 넣고, 답변을 받은 뒤
`README.md`의 "한계 비교 실험 메모"에 내 말로 다시 적어 보세요.

> 팁: AI에게는 "내가 무엇을 직접 해봤는지"를 먼저 알려 줄수록 답이 정확해집니다.

---

## 프롬프트 1 — 한계 정리 부탁하기 (복사해서 사용)

```text
나는 웹 개발을 막 배우는 비전공자야. 방금 실습에서 다음을 직접 해 봤어.

- "할 일" 메모를 만들어 브라우저의 localStorage에만 저장했다.
- 같은 PC에서 시크릿 창을 열었더니 할 일이 하나도 안 보였다.
- 다른 브라우저(엣지)로 같은 파일을 열어도 안 보였다.
- 휴대폰으로 봤을 때도 PC에서 적은 할 일이 안 보였다.

이 현상을 바탕으로, 아래를 비전공자 눈높이로 쉽게 설명해 줘.
1) 왜 다른 창/브라우저/기기에서는 안 보였는지 (localStorage가 어디에 저장되는지)
2) localStorage가 적합한 경우와 부적합한 경우를 표로 비교
3) "여러 사람·여러 기기가 같은 데이터를 공유하려면 무엇이 필요한가"에 대한 한 줄 결론
4) 그 다음 단계로 Supabase 같은 서버 데이터베이스를 쓰면 무엇이 달라지는지
전문 용어는 쓰되 괄호 안에 쉬운 풀이를 같이 적어 줘. 답변은 한국어로.
```

## 프롬프트 2 — 다음 실습 예고 받기 (선택)

```text
앞 답변 고마워. 나는 이 "할 일" 데이터를
모든 기기에서 똑같이 보고 싶어. 다음 실습(Supabase 테이블 만들기)으로 넘어가기 전에,
"localStorage → 서버 DB로 옮기면 코드의 어떤 부분이 바뀌는지"를
저장(추가)과 불러오기(조회) 두 가지만 예시로 짧게 비교해 줘.
실제 비밀 키나 URL은 넣지 말고, 들어갈 자리는 다음처럼 자리표시자로 남겨 줘.
- 프로젝트 URL: <YOUR_SUPABASE_URL>
- 공개(anon) 키: <YOUR_SUPABASE_ANON_KEY>
```

## 받은 답을 메모로 정리할 때 체크리스트

- [ ] "왜 안 보였나"를 **한 문장**으로 내 말로 적었다.
- [ ] localStorage가 **적합 / 부적합**한 경우를 각각 1개 이상 적었다.
- [ ] "여러 기기 공유 = 서버 DB 필요"라는 결론을 적었다.
- [ ] 다음에 배울 것(Supabase 테이블 만들기, 실습 114)을 한 줄로 적었다.

> 주의: 다음 실습에서 Supabase를 쓸 때, **공개(anon) 키**는 화면(프론트엔드)에 노출돼도 되는 키지만,
> **service_role(비밀) 키**는 절대 코드나 화면에 넣으면 안 됩니다. 비밀 키가 필요한 작업은
> 서버에서만 처리하고, 공개 데이터 접근은 **RLS(행 수준 보안)** 로 보호합니다.
> 자세한 구분은 보안 가이드에서 다룹니다. (실습 113 단계에서는 아직 키를 쓰지 않습니다.)
