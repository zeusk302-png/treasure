# 실습 310 — WebSocket으로 실시간 채팅 만들기

작은 채팅 서버를 직접 띄워, **창 두 개를 열어 한쪽에서 보낸 글이 새로고침 없이 다른 쪽에 즉시 뜨는** 미니 채팅을 만듭니다. 이걸 만들면서 "물어볼 때만 답하는 일반 HTTP 요청-응답"과 "전화선처럼 계속 열려 있어 서버가 먼저 말을 거는 실시간 연결(WebSocket)"의 차이를 몸으로 익히는 것이 목표입니다.

> 한 줄 그림: **브라우저 ↔(WebSocket 연결 계속 열림)↔ 서버. 한 명이 메시지 전송 → 서버가 "접속한 모두에게" 그대로 퍼뜨림(브로드캐스트) → 모두의 화면에 즉시 등장**

> 비유: 일반 HTTP는 **편지**입니다. 궁금하면 내가 편지를 보내야(요청해야) 답장이 옵니다. WebSocket은 **단톡방 전화**예요. 한 번 연결해 두면 끊지 않고, 누가 말하면 그 순간 방 안 모두가 듣습니다. 서버는 "누가 말하면 방 전체에 다시 들려주는 사회자" 역할을 합니다.

> 보안 메모 — 이 실습엔 비밀값이 없습니다(그래서 더 안전)
> - 이 채팅 서버는 API 키·토큰 같은 **비밀값을 쓰지 않습니다**. 그래서 `index.html`에 서버 주소를 둬도 안전합니다(주소는 비밀이 아닙니다).
> - 대신 **사용자 입력(닉네임·메시지) 출력은 항상 `textContent`로** 합니다. `innerHTML`로 넣으면 누군가 채팅에 `<script>`나 `<img onerror=...>`를 적었을 때 그게 **실행되는 XSS** 위험이 있어서, 글자 그대로만 보여 주는 `textContent`로 막습니다.
> - 나중에 이 서버에 인증 토큰 같은 비밀값을 더한다면, 반드시 `.env`(서버 전용)에만 두고 클라이언트 코드(`index.html`)와 깃에는 올리지 않습니다. 견본은 `.env.example`에 자리표시자만 둡니다.

## 목표
- **양방향 연결을 연다**: 브라우저와 서버 사이에 끊기지 않는 WebSocket 연결을 열어, 서버가 먼저 말을 걸 수 있는 구조를 만든다.
- **브로드캐스트를 이해한다**: 한 사람이 보낸 메시지를 서버가 "접속한 모두에게" 다시 퍼뜨리는 흐름을 직접 구현하고 확인한다.
- **HTTP와 실시간의 차이를 체감한다**: 새로고침 없이 메시지가 즉시 도착하는 걸 보며, 요청-응답 1회성과 상시 연결의 차이를 안다.
- **사용자 입력을 안전하게 출력한다**: 모든 채팅 내용을 `textContent`로 그려 XSS를 막는다.

## 따라하는 단계

### A. 준비물 확인
1. **Node.js**가 깔려 있어야 합니다. 터미널에서 `node -v`를 쳐서 `v18` 이상 숫자가 나오면 OK. (없으면 https://nodejs.org 에서 LTS 설치)

### B. 서버 켜기
2. 터미널을 열고 이 폴더(`examples/310`)로 이동합니다.
3. 라이브러리 설치: `npm install` — 이 명령이 `package.json`을 읽어 WebSocket 서버 라이브러리(`ws`)를 받습니다.
4. 서버 실행: `npm start` (또는 `node server.js`). 터미널에 `WebSocket 서버가 ws://localhost:3000 에서 대기 중`이 뜨면 성공입니다. **이 터미널 창은 켜 둔 채로** 둡니다(끄면 서버가 멈춥니다).

### C. 채팅 화면 열기
5. `index.html`을 브라우저로 엽니다. 가장 쉬운 방법은 파일을 더블클릭하는 것입니다. (그래도 잘 되지만, 더 깔끔하게 하려면 별도 터미널에서 `npx serve .` 같은 정적 서버로 열어도 됩니다.)
6. 화면 위쪽 상태줄이 **"연결됨 ✓"**로 바뀌면 서버와 잘 붙은 것입니다.

### D. 실시간 확인 (핵심!)
7. **같은 `index.html`을 창(또는 탭) 2개**로 엽니다. 각 창에 다른 닉네임을 적어 보세요.
8. 한쪽 창에서 메시지를 보내면, **새로고침을 누르지 않았는데도** 다른 창에 즉시 나타납니다. 이게 WebSocket(실시간)입니다.
9. 친구에게도 보여 주고 싶다면, 같은 와이파이에서 친구가 `http://내컴퓨터IP:파일주소`로 접속하게 하거나, 배포 단계(아래 E)를 진행합니다.

### E. (선택) 인터넷에 올려 함께 쓰기
10. WebSocket 서버는 "계속 켜져 있어야" 하므로, 정적 호스팅이 아니라 **서버를 상시 실행해 주는 곳**(예: Render, Railway, Fly.io)에 `server.js`를 올립니다.
11. 그런 플랫폼은 포트를 자기가 정해 주므로, 우리 코드가 `process.env.PORT`를 읽게 해 둔 덕분에 그대로 동작합니다(코드에 포트를 박지 않은 이유).
12. 배포 후에는 페이지가 `https`로 열리니, `index.html`의 연결 주소를 그 서버의 `wss://...` 주소로 바꿉니다. (`http`에선 `ws://`, `https`에선 `wss://`를 써야 브라우저가 차단하지 않습니다.)

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 비전공자에게 친절한 웹개발 튜터야. Node.js와 'ws' 라이브러리로 아주 작은 WebSocket 실시간 채팅 서버(server.js)를 만들어 줘.
  요구사항:
  - 포트는 process.env.PORT가 있으면 그걸, 없으면 3000을 쓸 것 (포트를 코드에 박지 말 것, 이유도 주석으로).
  - 새 클라이언트가 연결되면 본인에게 "입장" 안내를, 나머지에게는 "새 사용자 입장 + 현재 접속 인원"을 알릴 것.
  - 누가 메시지를 보내면 접속한 "모두에게" 그대로 퍼뜨리는 broadcast 함수를 만들 것(보낸 본인 포함).
  - 받은 데이터는 JSON으로 파싱하고, name/message는 공백 제거 + 길이 제한(name 20자, message 500자)으로 잘라 안전하게 처리할 것.
  - 형식이 깨진 입력이나 개별 연결 오류로 서버 전체가 죽지 않게 막을 것.
  제약: 코드만 주지 말고 "무엇을 하는지 + 왜 그렇게 했는지"를 한국어 주석으로 한 줄씩 풀어서 달아 줘. 변수·함수 이름은 영어로.
  ```

- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 WebSocket 채팅에 브라우저 화면(index.html)을 붙여 줘. 요구사항:
  - 닉네임 입력칸, 메시지 입력칸, 보내기 버튼, 메시지가 쌓이는 영역, 연결 상태 표시줄을 둘 것.
  - 서버가 보내 준 메시지를 받으면 화면에 즉시 그릴 것. 내가 보낸 메시지는 오른쪽 + 다른 색으로.
  - ★중요★ 사용자 입력(닉네임/메시지) 출력은 반드시 textContent로 할 것. innerHTML은 XSS 위험이라 쓰지 말 것(이유도 주석으로).
  - 연결이 끊기면 2초 뒤 자동 재연결, https 페이지면 ws:// 대신 wss://를 쓰도록 자동 전환할 것.
  - Enter 키로도 전송되게 할 것.
  한국어 주석으로 "왜 이렇게 했는지"까지 설명해 줘. 비전공자가 따라 읽을 수 있게.
  ```

- **막혔을 때(디버깅)** 프롬프트:
  ```text
  WebSocket 채팅이 동작하지 않아. 아래 증상과 콘솔 에러를 줄 테니, 가능한 원인을 "가장 흔한 것부터" 순서대로 점검 목록으로 알려 주고, 각 점검을 비전공자가 직접 확인하는 방법까지 한 단계씩 풀어 줘.

  [증상] (예: 화면 상태줄이 "연결됨"으로 안 바뀜 / 메시지를 보내도 상대 창에 안 뜸)
  [브라우저 콘솔 에러] (F12 → Console 탭 내용을 그대로 붙여넣기)
  [터미널 출력] (node server.js를 띄운 터미널 내용)

  특히 이런 것들을 확인해 줘: 서버가 켜져 있는지, 포트(3000)가 맞는지, http/https에 따라 ws/wss를 맞게 썼는지, JSON 형식이 맞는지.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 훨씬 좋습니다.

## 검증법
- **연결 확인**: `index.html`을 열었을 때 상단 상태줄이 **"연결됨 ✓"**로 바뀌는지 본다. (안 바뀌면 `node server.js`가 켜져 있는지 확인)
- **실시간 확인(핵심)**: 창을 2개 띄우고 한쪽에서 메시지를 보낼 때, **새로고침 없이** 다른 창에 즉시 뜨면 WebSocket이 제대로 동작하는 것이다.
- **브로드캐스트 확인**: 창을 3개 이상 띄워도, 한 명이 보낸 글이 **모든 창**에 동시에 뜨는지 본다.
- **입·퇴장 안내 확인**: 새 창을 열면 "새 사용자 입장 / 현재 접속 N명", 닫으면 "퇴장 / 현재 접속 N명"이 다른 창에 뜨는지 본다.
- **XSS 방어 확인**: 채팅에 `<b>굵게</b>`나 `<img src=x onerror=alert(1)>`를 그대로 쳐 본다. **글자 그대로** 보이고(굵어지거나 경고창이 뜨지 **않고**) 아무 일도 안 일어나면 `textContent` 방어가 잘 된 것이다.
- **자동 재연결 확인**: 서버 터미널을 잠깐 껐다(Ctrl+C) 다시 켜면(`npm start`), 페이지가 새로고침 없이 다시 "연결됨"으로 돌아오는지 본다.

## 파일 구성
- `server.js` — WebSocket 서버. 연결을 열고, 메시지를 받아 접속한 모두에게 퍼뜨린다(브로드캐스트).
- `index.html` — 채팅 화면(클라이언트). 서버와 연결하고, 받은 메시지를 `textContent`로 안전하게 그린다.
- `package.json` — 실행 설정. `npm install`이 `ws` 라이브러리를 받고, `npm start`로 서버를 켠다.
- `.env.example` — 환경변수 견본(자리표시자만). 복사해 `.env`를 만든다. 이 실습엔 비밀값이 없지만 설정을 코드 밖에 두는 습관을 보여 준다.
- `.gitignore` — `.env`와 `node_modules`가 깃에 올라가지 않게 막는다.
