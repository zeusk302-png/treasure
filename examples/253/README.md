# 실습 253 — 쇼핑몰 주문 시 n8n으로 사장님에게 슬랙·이메일 알림 보내기

손님이 내 쇼핑몰에서 주문하는 **그 순간**, n8n이 자동으로 깨어나 사장님(나)에게 **슬랙 메시지와 이메일을 동시에** 보내 주는 자동화를 만듭니다. 관리자 페이지를 하루 종일 새로고침하며 지켜보지 않아도, 주문이 들어오면 알림이 먼저 날아옵니다.

이 실습은 한 단계짜리 미니 결과물입니다. 결과물은 **n8n에 그대로 Import 하면 도는 완성형 워크플로우 한 개**([`workflow.json`](workflow.json))입니다.

> 비유: 가게 문에 **종(웹훅)** 을 달아 둔 셈입니다. 손님이 들어오면(주문하면) 종이 울리고, 그 소리를 들은 점원(n8n)이 사장님 휴대폰(슬랙)과 우편함(이메일)에 동시에 "손님 오셨어요!"를 전합니다.

> 보안 메모 — 공개해도 되는 값 vs 절대 숨길 값
> - **공개되어도 되는 값**: 웹훅 자체가 받는 주문 데이터(주문번호·상품명 등)나 화면에 쓰는 Supabase `anon`(공개) 키처럼, 노출돼도 괜찮은 값.
> - **절대 노출하면 안 되는 비밀값**: 슬랙 봇 토큰(`xoxb-...` 형태), 메일 계정 비밀번호(앱 비밀번호), Supabase `service_role` 키 등. 이런 값은 **워크플로우 JSON에 직접 적지 않고**, n8n의 **Credentials(자격증명 저장소)** 에만 저장합니다. (`service_role` 키는 RLS를 무시하고 모든 데이터에 접근하므로 절대 브라우저나 코드 파일에 두지 않습니다.)
> - 이 폴더의 `workflow.json`에는 진짜 값 대신 `REPLACE_WITH_YOUR_SLACK_CREDENTIAL_ID`, `YOUR_OWNER_EMAIL@example.com` 같은 **자리표시자**만 들어 있습니다. 그래서 그대로 인터넷에 올려도 새는 비밀이 없습니다.

## 목표
- **"무슨 일이 생긴 순간" 도는 자동화(웹훅 트리거)** 를 직접 만든다: 새 주문이라는 사건이 자동화를 깨우는 흐름을 체감한다.
- **하나의 사건 → 여러 알림(슬랙 + 이메일)** 으로 동시에 보내는 분기 구조를 익힌다.
- **외부 서비스(슬랙·메일)를 안전하게 연동**한다: 비밀 토큰·비밀번호는 코드가 아니라 n8n **Credentials**에만 둔다.
- 결과적으로 **운영 자동화**(사람이 화면을 안 봐도 알림이 오는 구조)의 기본 골격을 손에 익힌다.

## 따라하는 단계
1. n8n을 연다(클라우드 n8n 또는 직접 설치한 n8n). 왼쪽 위 메뉴에서 **Import from File**을 눌러 이 폴더의 [`workflow.json`](workflow.json)을 불러온다. → `Webhook → Set → (Slack + Email) → Respond` 다섯 노드가 보이면 정상이다.
2. **슬랙 자격증명 만들기**: n8n의 **Credentials → New → Slack** 으로 슬랙 봇 토큰을 저장한다. 그 다음 **사장님 슬랙 알림 (Slack)** 노드를 열어 방금 만든 자격증명을 연결하고, `channelId`를 알림을 받을 채널 ID(예: `#주문알림`)로 바꾼다. (토큰은 노드에 직접 적지 않는다 — 자격증명에만 저장한다.)
3. **메일 자격증명 만들기**: **Credentials → New → SMTP** 로 내 메일 계정(보내는 주소·앱 비밀번호)을 저장한다. **사장님 이메일 알림 (Send Email)** 노드를 열어 그 자격증명을 연결하고, `fromEmail`(보내는 내 주소)·`toEmail`(받는 사장님 주소)을 진짜 주소로 바꾼다.
4. 오른쪽 위 토글로 워크플로우를 **Active(켜기)** 상태로 만든다. 그러면 **새 주문 신호 받기 (Webhook)** 노드에 **Production URL**(예: `https://...n8n.../webhook/new-order`)이 생긴다. 이 주소가 "주문 종"의 위치다.
5. 그 **Production URL**을, 주문이 생길 때 호출하는 쪽에 알려 준다.
   - 쇼핑몰/주문 폼 코드라면: 주문 저장 직후 이 URL로 주문 내용을 `POST` 하게 한다.
   - Supabase를 쓴다면: **Database → Webhooks**에서 `orders` 테이블에 새 행이 **INSERT** 될 때 이 URL로 보내도록 설정한다.
6. 끝. 이제 새 주문이 들어올 때마다 사장님에게 슬랙과 이메일이 자동으로 날아간다.

> 자주 막히는 곳: ① 워크플로우를 **Active로 켜야** Production URL이 생기고 실제 주문도 받는다(테스트 URL은 한 번만 듣는다). ② 슬랙 봇을 알림 채널에 **초대(Invite)** 해 두지 않으면 메시지가 안 들어간다. ③ Gmail 등은 일반 비밀번호가 아니라 **앱 비밀번호**가 필요할 수 있다.

## 검증법
- **모의 주문 한 번 쏘기**: 터미널에서 Production URL로 가짜 주문을 보낸다. 슬랙과 이메일이 둘 다 오면 성공.
  ```bash
  curl -X POST "여기에_내_Production_URL_붙여넣기" \
    -H "Content-Type: application/json" \
    -d '{"order_id":"A-1024","customer":"홍길동","item":"수제 비누 3개","amount":18000}'
  ```
- **슬랙 도착 확인**: 지정한 채널에 "새 주문이 들어왔어요!"와 주문번호·고객·상품·금액이 보이는가?
- **이메일 도착 확인**: 받는 메일함에 제목 `[새 주문] A-1024 - 홍길동님` 메일이 왔는가?
- **n8n 실행 기록 확인**: n8n의 **Executions**에서 방금 실행이 초록색(성공)으로 남았는가? 각 노드를 눌러 값이 잘 흘렀는지 본다.
- **두 갈래로 갈라졌는지**: `Set` 노드 다음이 Slack과 Email **두 노드로 동시에** 연결돼, 한 번의 주문으로 알림이 둘 다 나가는지 확인한다.
- **비밀값 누출 검사**: 이 폴더에서 아래를 실행했을 때 결과가 **하나도 안 나와야** 정상이다(자격증명에만 비밀이 있고 파일엔 자리표시자만 있음).
  ```bash
  grep -rE "xoxb-|sk-ant-|service_role" . 
  ```

## 파일 구성
- [`workflow.json`](workflow.json) — n8n에 Import 하면 바로 도는 완성형 워크플로우. 슬랙 토큰·메일 비밀번호는 **자격증명 참조(자리표시자)** 로만 들어 있다.
