# 실습 149 — 랜덤 강아지/고양이 사진 API로 사진 갤러리 만들기

버튼을 누르면 인터넷의 공개 API(서버)에서 **동물 사진 한 장의 주소(URL)** 를 받아와,
그 주소를 `<img>` 태그의 `src`에 꽂아 화면에 사진을 띄우는 한 장짜리 페이지입니다.

> 비유: 택배 상자(JSON)를 열면 안에 "사진이 걸려 있는 인터넷 주소"라는 쪽지가 들어 있습니다.
> 그 주소를 액자(`img`)의 못(`src`)에 걸면 사진이 보입니다.
> 이번 실습의 한 줄 핵심은 **"JSON 안의 값을 화면 요소(img)에 연결한다"** 입니다.

## 목표
- API가 돌려준 **JSON 안에서 사진 주소만 꺼내** `img.src`에 연결하는 흐름을 익힌다.
- "받은 데이터를 화면 요소에 꽂는다"는 감각을 잡는다.
  - `fetch(주소)` = 서버에 사진 한 장을 주문하기
  - `data.message` / `data[0].url` = 응답 JSON에서 **사진 주소만 꺼내기**
  - `img.src = 주소` = 꺼낸 주소를 액자에 걸기(=사진이 뜨는 순간)
- 강아지와 고양이 API의 **JSON 모양이 서로 다르다**는 것을 직접 본다.
  - 강아지: `{ "message": "사진주소", "status": "success" }` → 주소는 `message` 안에
  - 고양이: `[ { "url": "사진주소" } ]` → 응답이 **배열**이라 `data[0].url`에서 꺼냄

## 따라하는 단계
1. 이 폴더의 `index.html`을 더블클릭 → 브라우저에서 열린다. (인터넷 연결 권장)
2. **"새 사진" 버튼**을 누른다 → 강아지 사진이 한 장 뜨고, 아래에 "지금까지 1장 받았어요."가 보인다.
3. 버튼을 **여러 번** 눌러 본다 → 누를 때마다 **다른 강아지 사진**으로 바뀐다. 횟수도 늘어난다.
4. 위쪽의 **🐱 고양이** 버튼을 누른다 → 고양이 사진으로 바뀐다. 이제 "새 사진"은 고양이를 받아온다.
5. `script.js`를 열어 `const imageUrl = getImageUrl(currentAnimal, data);` 줄을 찾는다 → **JSON에서 사진 주소만 꺼내는 부분**이다.
6. 바로 아래 `img.src = imageUrl;` 줄을 본다 → **이 한 줄이 "주소를 액자에 거는" 핵심**이다.
7. `getImageUrl` 함수 안을 본다 → 강아지는 `data.message`, 고양이는 `data[0].url`로 **꺼내는 위치가 다른 것**을 눈으로 확인한다.
8. AI에게 시켜 보기:
   > "이 `script.js`에 '여우' API(https://randomfox.ca/floof/ , 응답은 `{ "image": "주소" }`)를 추가하고, 🦊 여우 버튼도 만들어줘."

## 검증법
- "새 사진" 버튼을 누르면 안내 문구가 사라지고 **실제 동물 사진이 뜨는가?**
- 버튼을 다시 누를 때마다 **매번 다른 사진**으로 바뀌는가?
- 🐶 강아지 / 🐱 고양이 버튼을 누르면 **선택한 동물 사진**으로 바뀌는가? (선택한 버튼에 테두리가 생기는가?)
- 누를 때마다 하단의 **"지금까지 N장 받았어요."** 숫자가 1씩 늘어나는가?
- 받아오는 동안 사진이 잠깐 **흐려졌다가** 또렷해지고, 버튼이 잠깐 **비활성화**되는가?
- 브라우저에서 `F12`(개발자 도구) → **Network 탭**을 켜고 버튼을 누르면 `random`(강아지) 또는 `search`(고양이) 요청이 가는 게 보이는가?
- (실패 대비) 와이파이를 끄고 버튼을 눌러도 **"(오프라인) 예비 사진"** 이 뜨는가?

## 키(API Key)는 필요 없어요
이 실습이 쓰는 강아지(dog.ceo)와 고양이(thecatapi 기본 검색) API는 **누구나 열쇠 없이** 부를 수 있는 **공개 API**입니다.
그래서 코드에 비밀값(`YOUR_API_KEY` 같은 것)을 넣지 않습니다.

나중에 유료 API나 내 데이터를 다루는 API를 쓸 때는 키가 필요하고, 그 키는 화면 코드(브라우저에 그대로 노출됨)에 넣으면 안 됩니다.
공개되어도 되는 값(예: Supabase의 `anon` 키)과 절대 노출하면 안 되는 비밀값(예: Supabase의 `service_role` 키)은 성격이 완전히 다릅니다.
비밀 키는 서버 쪽에서만 다루고 RLS(행 수준 보안)로 보호하며, 이는 보안 권에서 따로 배웁니다.
만약 키가 있는 API를 쓴다면 코드에는 `YOUR_API_KEY` 같은 **자리표시자**만 두는 것이 원칙입니다.
