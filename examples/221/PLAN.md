> 이 파일이 이 실습의 **결과물(제출물)** 중 하나입니다.
> [`RISKS.md`](RISKS.md)에서 AI가 짚어준 위험 5개를, 여기 기획서에 **"막을 것 / 미룰 것"** 으로 옮겨 적습니다.
> 아래는 예시 답으로 채워져 있습니다. **여러분이 직접 정한 내용**으로 바꿔 주세요.

## 목표

- 이 사이트로 이루고 싶은 것 한 줄:
  > 출시 전 서비스에 관심 있는 사람의 **이메일을 받아 두어**, 나중에 안내 메일을 보낼 명단을 모은다.

## 대상 (누가 보는가)

- 주로 볼 사람:
  > 출시 소식을 기다리는 잠재 사용자 (휴대폰으로 열어볼 수도 있음)

## 페이지·섹션

- 형태: **한 장짜리(one-page) 랜딩**
  1. 상단: 서비스 한 줄 소개
  2. 가운데: 이메일 입력칸 + **동의 체크박스** + 받기 버튼
  3. 하단: "입력한 이메일은 ○○ 안내 목적에만 사용합니다" 안내 한 줄

## 꼭 들어갈 것

- [x] 이메일 입력 폼 (형식 검증 포함)
- [x] 개인정보 안내 문구 + 동의 체크박스
- [x] Supabase 테이블에 이메일 + 받은 시각 저장
- [x] 휴대폰에서도 안 깨지게(반응형)

## 알게 된 위험 (AI가 먼저 짚음)

> [`RISKS.md`](RISKS.md)에서 AI가 자발적으로 경고한 5개를 한 줄씩 옮긴 것입니다.

1. **DB가 공개 키로 누구나 열람·삭제 가능 (보안)** → RLS로 막기
2. **이메일은 개인정보 — 동의·고지 없이 수집 금지 (개인정보)** → 동의 체크 + 안내 문구
3. **비밀 키(service_role) 노출 시 데이터 유출·요금 폭탄 (보안·비용)** → 공개 키만 프론트에, 비밀값은 환경변수
4. **봇이 가짜 이메일 대량 입력 (스팸·비용)** → 형식 검증 + 중복 방지(우선), 캡차는 나중
5. **무료 한도·백업 미인지 (비용·운영)** → 한도 알림 + 수동 CSV 백업

## 첫 버전에 막을 것

> "안 하면 진짜로 새거나 털리는 것"을 우선합니다.

- [x] 위험 1 — 테이블 **RLS 켜고 INSERT만 허용, SELECT 금지**
- [x] 위험 2 — **동의 체크박스 + 안내 문구**, 받은 시각 함께 저장
- [x] 위험 3 — 프론트엔드에는 **공개 키(anon)만**, **service_role 등 비밀값은 절대 프론트/깃허브 금지** → `.env` / Vercel 환경변수에만
- [x] 위험 4(일부) — **이메일 형식 검증 + 중복 방지(unique)**
- [x] 위험 5(일부) — 모인 이메일 **수동 CSV 백업**

## 다음으로 미룰 것 (범위 밖, 이번엔 안 함)

> 욕심을 줄여야 작게라도 **안전하게 완성**할 수 있습니다.

- 봇 방지 캡차(사람 확인) — 가입이 늘면 추가
- 백업 자동화
- 마케팅 메일 자동발송 (동의받은 명단 대상으로 나중에)

## 더 확인할 것 (미정)

> AI가 지어내지 않고 솔직히 "아직 안 정함"으로 남긴 항목입니다.

- 동의 문구의 정확한 문장 (서비스 성격에 맞게)
- 무료 한도 수치(저장량·요청 수) — 가입 후 실제 Supabase/Vercel 화면에서 확인
