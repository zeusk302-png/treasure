# 실습 333 — 환경변수·시크릿 안전하게 관리하기

API 키, 데이터베이스 비밀번호, 결제 시크릿 같은 **절대 새면 안 되는 값**을 코드 파일에서 분리해 `.env`에 두고, `.gitignore`로 깃에 안 올라가게 막고, 배포 플랫폼(Vercel 등)의 **시크릿 저장소**에 진짜 값을 넣는 표준 절차를 직접 만들어 봅니다. 더불어 "혹시 내가 실수로 키를 깃에 올렸나?"를 자동으로 찾아 주는 **점검 스크립트**까지 갖춰, 사고를 미리 잡고 사고가 났을 때 키를 **교체(회전)**하는 흐름까지 익힙니다.

> 한 줄 그림: **진짜 비밀값은 `.env`(깃 제외)·배포 플랫폼 시크릿에만 → 코드는 `process.env.X`로 "참조"만 → 커밋 전에 점검 스크립트가 "어? 여기 키가 박혀 있는데요?"를 잡아 줌**

> 비유: 비밀값은 **집 현관 비밀번호**입니다. 비밀번호를 현관문에 포스트잇으로 붙여 두지(=코드에 박지) 않고, **내 머릿속·금고(.env·시크릿 저장소)**에만 둡니다. `.gitignore`는 "이 금고는 사진 찍어 SNS에 올리지 마"라는 규칙이고, 점검 스크립트는 "혹시 어디 비밀번호 적힌 포스트잇 안 붙어 있나" 집 안을 한 바퀴 도는 **점검 알바**입니다.

> 보안 메모 — 공개해도 되는 값 vs 절대 숨겨야 하는 값
> - **공개되어도 되는 값**: Supabase `anon`(=publishable) 키, 공개 사이트 주소, 분석 측정 스니펫. 이건 브라우저로 나가도 되는 값이라 프론트 코드/`NEXT_PUBLIC_*` 환경변수에 둬도 됩니다. 보호는 키 숨김이 아니라 **RLS(행 수준 보안)**로 합니다.
> - **절대 노출하면 안 되는 비밀값**: Supabase `service_role` 키, Stripe `sk_...` 시크릿, Claude API 키(`sk-ant-...`), DB 비밀번호, 이메일 발송 키. 이건 **서버에서만** 쓰고, 코드가 아니라 `.env`(깃 제외) 또는 **배포 플랫폼 시크릿 저장소**에만 둡니다.
> - 이 폴더의 `.env.example`에는 진짜 값이 아니라 **자리표시자**(`sk-ant-REPLACE_ME` 등)만 들어 있습니다. 진짜 값은 복사본 `.env`에만 적고, `.env`는 `.gitignore`로 깃에서 빠집니다.

## 목표
- **비밀값을 코드에서 분리한다**: 키를 `index.js` 같은 코드에 직접 적지 않고, `process.env.X`로 **참조만** 하게 만든다.
- **3중 안전장치를 건다**: ① `.env`(진짜 값) ② `.gitignore`(`.env`를 깃에서 제외) ③ `.env.example`(견본만 공유) — 이 셋의 역할을 구분한다.
- **배포 플랫폼 시크릿을 이해한다**: 로컬은 `.env`, 배포는 Vercel/Netlify의 **Environment Variables(시크릿 저장소)**에 같은 키를 넣어, 코드 수정 없이 환경만 바꿔 끼운다.
- **사고를 자동으로 잡는다**: 커밋 전에 점검 스크립트를 돌려, `.env`가 추적되고 있거나 코드에 진짜 키가 박혔는지 **자동으로 탐지**한다.
- **키가 샜을 때 대응 절차를 안다**: 유출된 키는 지우는 걸로 끝이 아니라 **반드시 발급사에서 폐기·재발급(회전)** 해야 한다는 걸 익힌다.

## 따라하는 단계

### A. 비밀값을 `.env`로 분리하기
1. 이 폴더의 파일들을 봅니다. `config.js`가 **모든 비밀값을 한 곳에서 `process.env`로 읽는** 설정 로더이고, `app.js`는 그 설정을 받아 쓰는 예제 앱입니다. 코드 어디에도 진짜 키가 없습니다.
2. `.env.example`을 복사해 `.env`를 만듭니다.
   - 맥/리눅스/Git Bash: `cp .env.example .env`
   - 윈도우 PowerShell: `Copy-Item .env.example .env`
3. 새로 만든 `.env`를 열어 자리표시자(`REPLACE_ME` 등)를 **진짜 값**으로 바꿉니다. (지금은 연습이니 아무 임의 문자열을 넣어도 됩니다. 진짜 키는 각 서비스 대시보드에서 발급합니다.)

### B. `.gitignore`로 깃에서 `.env` 빼기 (가장 중요)
4. 이 폴더의 `.gitignore`에 이미 `.env`가 들어 있습니다. 이게 있어야 `.env`가 **절대 깃에 올라가지 않습니다.**
5. 확인: `git status`를 쳤을 때 `.env`가 **목록에 안 보여야** 정상입니다. (보이면 `.gitignore`가 안 먹은 것 — D절 참고.)

### C. 앱 실행해서 "코드는 참조만 한다" 확인하기
6. Node.js가 깔려 있어야 합니다. 이 폴더에서 `node app.js`를 실행합니다.
7. `.env`의 값이 잘 읽히면 가려진 형태(`sk-a****ME`)로 출력됩니다. **진짜 값 전체는 화면에도 안 찍습니다**(로그 유출 방지). 필수 키가 비어 있으면 친절한 에러로 멈춥니다.

### D. 점검 스크립트로 "실수로 올린 키" 잡기
8. 커밋하기 전에 점검을 돌립니다.
   - Git Bash/맥/리눅스: `bash check-secrets.sh`
   - 어디서나(Node): `node scan-secrets.js`
9. 점검기는 두 가지를 봅니다: ① `.env`가 깃에 **추적되고 있는지** ② 코드 파일에 **진짜 키처럼 보이는 문자열**(`sk-ant-...`, `sk_live_...`, AWS 키 등)이 박혀 있는지. 문제가 있으면 **빨간 경고와 함께 종료 코드 1**로 끝나, CI에서도 빌드를 막을 수 있습니다.

### E. 배포 플랫폼에 같은 키 넣기 (로컬 ≠ 배포)
10. 배포할 땐 `.env` 파일을 올리는 게 아니라, **플랫폼의 시크릿 저장소**에 같은 이름의 키를 넣습니다.
    - Vercel: 프로젝트 **Settings → Environment Variables**에서 `CLAUDE_API_KEY` 등 이름·값을 추가하고 환경(Production/Preview/Development)을 고릅니다.
    - 브라우저로 나가야 하는 **공개값만** `NEXT_PUBLIC_` 접두사를 붙입니다. 비밀값엔 절대 붙이지 않습니다(붙이면 번들에 섞여 브라우저로 새어 나갑니다).
11. 같은 키 이름을 쓰므로 코드(`process.env.CLAUDE_API_KEY`)는 **한 글자도 안 바뀝니다**. 로컬은 `.env`, 배포는 플랫폼 시크릿이 그 자리에 값을 끼워 줍니다.

### F. 키가 샜다면 — 지우지 말고 "회전"하기
12. 만약 키가 깃 히스토리에 올라갔다면, 파일에서 지워도 **과거 커밋에는 그대로 남아 있어 이미 유출된 것**입니다.
13. 순서는 ① 발급사 대시보드에서 그 키를 **즉시 폐기(revoke)** → ② **새 키 재발급** → ③ `.env`·플랫폼 시크릿에 새 키 교체. 코드에서 지우는 건 그다음입니다.

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  역할: 너는 비전공자에게 보안을 가르치는 시니어 개발자야.
  목표: Node.js로 "환경변수·시크릿 안전 관리" 예제를 만들어줘.
  요구사항:
  1) config.js — 필요한 모든 비밀값(CLAUDE_API_KEY, STRIPE_SECRET_KEY,
     DATABASE_URL, SUPABASE_SERVICE_ROLE_KEY)을 process.env에서만 읽는 설정 로더.
     코드에 진짜 키를 절대 박지 말고, 필수 키가 없으면 친절한 에러로 멈추게 해줘.
  2) app.js — config.js를 import해서 쓰는 예제. 비밀값은 절대 통째로 출력하지 말고
     앞뒤 몇 글자만 남기고 마스킹(sk-a****ME)해서 보여줘.
  3) .env.example — 진짜 값 대신 REPLACE_ME 같은 자리표시자만.
  4) .gitignore — .env 와 .env.local 을 반드시 제외.
  제약: 비밀값을 코드/예제 출력 어디에도 평문으로 남기지 마. 각 줄에 "무엇을 왜
  이렇게 했는지" 한국어 주석을 달고, 영어 식별자는 그대로 둬.
  ```

- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  이제 "실수로 비밀값을 깃에 올렸는지" 잡는 점검 스크립트를 추가해줘.
  - scan-secrets.js (Node) 와 check-secrets.sh (bash) 두 버전.
  - 검사 1: `git ls-files`로 .env 류 파일이 깃에 추적되고 있으면 경고.
  - 검사 2: 코드 파일(.js/.ts/.json 등)을 훑어 진짜 키 패턴
    (sk-ant-..., sk_live_..., AKIA로 시작하는 AWS 키, 긴 base64 토큰)을 정규식으로 탐지.
  - .env.example 의 자리표시자(REPLACE_ME 등)는 오탐이니 제외해줘.
  - 문제가 있으면 빨간 경고를 찍고 종료 코드 1로 끝내서 CI에서 빌드를 막을 수 있게 해줘.
  왜 그렇게 했는지 주석으로 설명하고, 비전공자가 한 줄씩 이해하게 풀어줘.
  ```

- **막혔을 때(디버깅)** 프롬프트:
  ```text
  문제 상황: .gitignore에 .env를 넣었는데도 git status에 .env가 계속 떠.
  (또는: node app.js 했더니 "필수 환경변수 CLAUDE_API_KEY 가 없습니다" 에러가 나.)
  내 .gitignore 내용과 `git status`, `git ls-files | grep env` 결과를 붙여넣을게:
  <여기에 출력 붙여넣기>
  원인을 단계별로 진단해줘. 특히 "이미 한 번 추적된 파일은 .gitignore가 무시 못 한다"
  같은 함정과, `git rm --cached .env`로 추적만 푸는 방법, 그리고 만약 이미 커밋
  히스토리에 키가 올라갔다면 키 자체를 폐기·재발급(회전)해야 하는 이유를 설명해줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법
- **코드에 진짜 키가 없는지 확인**: `config.js`·`app.js`를 열어 키 자리에 `process.env.X`만 있고 실제 키 문자열이 **한 글자도 없는지** 본다.
- **`.env`가 깃에서 빠지는지 확인**: `git status`에 `.env`가 **안 보이고**, `git ls-files | grep -E "(^|/)\.env$"`가 **아무것도 출력하지 않으면** 정상이다. (`.env.example`만 추적되어야 한다.)
- **앱이 환경변수를 읽는지 확인**: `.env`를 채운 뒤 `node app.js`를 돌리면 값이 **마스킹된 형태**로 찍히고, `.env`에서 필수 키 한 줄을 지우면 **친절한 에러로 멈추는지** 본다.
- **점검 스크립트가 사고를 잡는지 확인**: 일부러 `app.js`에 `const k = "sk-ant-api03-AAAAAAAAAAAAAAAAAAAAAAAA"` 같은 가짜 키를 넣고 `node scan-secrets.js`를 돌리면 **빨간 경고 + 종료 코드 1**(`echo $?` 또는 PowerShell `$LASTEXITCODE`가 `1`)로 끝나야 한다. 지우면 다시 통과한다.
- **마스킹이 진짜인지 확인**: 앱 출력 어디에도 비밀값 **전체**가 평문으로 찍히지 않는지 본다. (가운데가 `****`로 가려져야 한다.)

## 파일 구성
- `config.js` — 모든 비밀값을 `process.env`에서만 읽는 설정 로더. 필수 키 누락 시 멈추고, 출력용 마스킹 함수를 제공한다.
- `app.js` — `config.js`를 받아 쓰는 예제 앱. 비밀값을 통째로 찍지 않고 마스킹해서 보여준다.
- `scan-secrets.js` — 어디서나 돌아가는(Node) 점검기. `.env` 추적 여부 + 코드에 박힌 진짜 키 패턴을 탐지하고, 문제 시 종료 코드 1.
- `check-secrets.sh` — 같은 점검을 하는 bash 버전(Git Bash/맥/리눅스, CI용).
- `.env.example` — 필요한 비밀값 견본(자리표시자만). 복사해 `.env`를 만들고 진짜 값은 거기에만 넣는다.
- `.gitignore` — `.env` 등 비밀 파일이 깃에 안 올라가게 막는다.
- `package.json` — `npm run scan` 한 줄로 점검을 돌릴 수 있게 한 스크립트 정의.
