# 210 · 여러 건을 반복 처리하기 (Loop / Split In Batches) (n8n)

API나 구글 시트에서 데이터를 받으면 보통 **여러 줄(여러 건)** 이 한꺼번에 들어옵니다. "이 목록을 한 줄씩 차례로 처리하고, 다 끝나면 몇 건 했는지 합산해서 보고"하는 것이 자동화의 가장 기본적인 패턴입니다. 이 실습에서는 가짜 주문 5건을 만들어서, **Loop Over Items**(예전 이름 Split In Batches) 노드로 한 건씩 반복 처리한 뒤, 마지막에 처리 건수와 합계를 정리해 봅니다. 외부 계정/키 없이 바로 돌려볼 수 있도록 만들었습니다.

## 목표

- n8n에서 "여러 건의 데이터 = 여러 개의 item"이라는 핵심 개념을 이해한다.
- **Loop Over Items(Split In Batches)** 노드로 목록을 한 건씩 돌리는 법을 익힌다.
- Loop 노드의 출력이 **두 갈래(done / loop)** 로 나뉜다는 것을 직접 본다.
- 반복이 끝난 뒤 **Aggregate 노드로 결과를 한 덩어리로 모아** 총 건수·합계를 계산해 보고한다.

## 따라하는 단계

1. **워크플로우 가져오기 (Import)**
   - n8n 화면 우측 상단 `...` 메뉴 → `Import from File`을 누릅니다.
   - 이 폴더의 `workflow.json`을 선택하면 노드 6개가 연결된 워크플로우가 나타납니다.
   - (별도 계정/API 키 설정이 필요 없습니다. 그대로 실행됩니다.)

2. **들어오는 데이터 살펴보기**
   - `처리할 목록 만들기 (5건)` 노드를 클릭한 뒤 `Execute step`(노드 위 실행 버튼)을 누릅니다.
   - 오른쪽 출력 패널에 **5건(item 5개)** 이 보입니다. 이게 "한꺼번에 들어온 목록"입니다.
   - 실제 업무에서는 이 자리에 HTTP Request(API 호출)나 구글 시트/Supabase 조회 노드가 들어가, 거기서 받은 여러 건이 그대로 다음으로 흘러갑니다.

3. **Loop 노드의 구조 이해하기**
   - `한 건씩 반복 (Loop Over Items)` 노드를 보면 출력 점이 **두 개**입니다.
     - 위쪽 `done`: 반복이 **모두 끝난 뒤** 한 번만 흐릅니다. → `처리 결과 모으기 (Aggregate)`로 연결되어 있습니다.
     - 아래쪽 `loop`: **한 건씩** 흐릅니다. → `한 건 처리하기 (Set)`로 연결되어 있습니다.
   - `Batch Size`(한 번에 몇 건씩)가 `1`로 되어 있어 "딱 한 건씩" 처리합니다.

4. **'한 건 처리' 부분 확인하기**
   - `한 건 처리하기 (Set)` 노드는 들어온 한 건에 대해 작업을 합니다.
   - 여기서는 금액이 20,000원 이상이면 `등급`을 `VIP`로, 아니면 `일반`으로 표시하고 처리 메시지를 만듭니다.
   - 처리가 끝나면 화살표가 다시 Loop 노드로 **되돌아갑니다.** 이렇게 5번을 돌면 목록이 끝납니다.

5. **합산 보고 부분 확인하기**
   - 반복이 끝나면 Loop의 `done` 출력이 `처리 결과 모으기 (Aggregate)`로 흐릅니다. 이 노드가 흩어져 있던 결과들을 **하나의 묶음(data 배열)** 으로 모아 줍니다.
   - `건수 합산해 보고하기 (Code)` 노드가 그 묶음을 받아 `총건수`, `VIP건수`, `총금액`, `요약문`을 계산합니다.

6. **전체 실행하기**
   - 캔버스 아무 곳도 선택하지 않은 상태에서 `Test workflow`(또는 좌측 하단 실행 버튼)를 누릅니다.
   - 노드들이 순서대로 초록색으로 켜지며 끝까지 실행됩니다.

## 🤖 바이브코딩 프롬프트

이 실습(여러 건을 한 건씩 반복 처리하고 마지막에 합산 보고)을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. n8n은 화면에서 노드를 직접 끌어다 놓는 도구라, AI에게는 "어떤 노드를 어떻게 연결할지" 또는 "노드 안에 들어갈 Code/식(expression)"을 시키는 식으로 활용합니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 n8n 자동화 전문가야. 비전공자도 따라할 수 있게 설명해줘.
  목표: 여러 건의 주문 데이터를 '한 건씩' 반복 처리한 뒤, 마지막에 총 건수와 합계를 보고하는 워크플로우의 뼈대를 만들고 싶어.
  제약:
  - 외부 API/계정 없이 바로 돌아가게, 가짜 주문 5건은 Code 노드에서 직접 만들어줘(주문번호/고객명/금액).
  - 반복은 'Loop Over Items'(예전 이름 Split In Batches) 노드를 batchSize=1 로 써줘.
  산출물:
  - 필요한 노드 목록(Manual Trigger → Code(목록) → Loop Over Items → ...)과 각 노드를 어떤 순서로 어디에 연결하는지 화살표로 그려줘.
  - 특히 Loop 노드 출력이 'done'(끝난 뒤 한 번)과 'loop'(한 건씩) 두 갈래라는 걸 어디에 각각 연결해야 하는지 콕 집어 알려줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  위 워크플로우에 '건별 처리'와 '합산 보고'를 추가하고 싶어.
  - 한 건 처리: Set 노드로 금액이 20000원 이상이면 '등급'을 VIP, 아니면 '일반'으로 정하고, "주문 ... 처리 완료" 같은 처리메시지도 만들어줘. (n8n 식 expression 문법으로 정확히 써줘)
  - 처리된 모든 건을 Aggregate 노드로 하나의 data 배열로 모은 뒤, Code 노드에서 총건수 / VIP건수 / 총금액 / 요약문을 계산해줘.
  각 Code 노드와 Set 식에는 '무엇을 하는지'와 '왜 그렇게 했는지'를 한국어 주석으로 한 줄씩 달아줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  n8n에서 이 워크플로우를 실행했는데 결과가 이상해. 아래 증상을 단계별로 진단해줘.
  증상: (예) 합산 보고가 5건이 아니라 1건만 나와 / 반복이 한 번만 돌고 끝나 / Aggregate에 data가 비어 있어.
  내가 의심하는 곳: Loop 노드의 done/loop 연결, batchSize 값, Set 노드 식.
  지금 노드 연결 상태와 에러 메시지(또는 출력 패널 내용)는 이래: <여기에 붙여넣기>
  원인 후보를 가능성 높은 순서로 알려주고, 각 후보를 어떻게 눈으로 확인하는지(어느 노드를 클릭해 무엇을 보는지)도 알려줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다. n8n은 노드 연결이 핵심이라 "글로 그린 화살표 그림도 같이 줘"라고 요청하면 따라하기 쉽습니다.

## 검증법

- **반복이 5번 돌았는지**: `한 건 처리하기 (Set)` 노드를 클릭하면, 실행 후 그 노드를 거쳐 간 건수가 5건인지 확인할 수 있습니다(한 건씩 5번 통과).
- **최종 보고 확인**: `건수 합산해 보고하기 (Code)` 노드의 출력을 보면 `요약문`이 아래처럼 나오면 성공입니다.
  ```
  총 5건을 처리했습니다. (VIP 2건 / 일반 3건, 합계 76,500원)
  ```
  (A-1003 30,000원, A-1005 21,000원 → VIP 2건. 나머지 3건은 일반. 합계 12000+8500+30000+5000+21000 = 76,500원)
- **두 갈래 흐름 확인**: 실행 후 캔버스에서 Loop 노드의 `loop` 화살표(→ Set)는 여러 번, `done` 화살표(→ Aggregate)는 마지막에 한 번만 흐른 것을 눈으로 확인할 수 있습니다.
- **직접 바꿔보기(심화)**: `처리할 목록 만들기 (5건)` 노드에서 주문을 더 추가하거나 금액을 바꿔 다시 실행하면, 보고 숫자가 그에 맞게 달라집니다.

## 실무로 확장하기 (참고)

- 여기서는 데이터를 직접 만들었지만, 실무에서는 `처리할 목록 만들기` 자리에 **HTTP Request(API)** 나 **Supabase/구글 시트 조회** 노드를 둡니다.
- `한 건 처리하기` 자리에는 메일 발송, Slack 알림, DB 업데이트 같은 "건별 작업"을 넣습니다(예: 앞 단계 [209](../209/)의 환영 메일 발송).
- 외부 API를 부를 때 한 번에 너무 많은 건이 몰리지 않도록 `Batch Size`를 키우거나, 노드 옵션에서 호출 간격을 두는 것이 안전합니다.
