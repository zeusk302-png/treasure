# 실습 027 — 박스에 여백(margin)과 안쪽 여백(padding) 주기

`div` 박스 하나에 `margin`과 `padding`을 다르게 줘 보면서, "바깥 여백"과 "안쪽 여백"이 화면에서 어떻게 다르게 보이는지 직접 확인합니다. 파일은 `index.html` 하나뿐이고, 서버도 데이터베이스도 필요 없습니다. 더블클릭만 하면 됩니다.

## 목표
- `margin`(바깥 여백)과 `padding`(안쪽 여백)의 **차이를 눈으로** 구분한다.
- `padding`을 주면 박스가 **통통하게(더 크게)** 변한다는 것을 체험한다.
- `margin`을 주면 박스 크기는 그대로지만 **주변에서 멀어진다**는 것을 체험한다.

빵에 비유하면 이렇습니다.

| 속성 | 어디의 여백? | 빵 비유 | 결과 |
|---|---|---|---|
| `padding` | 박스 **안쪽** (테두리 ↔ 글자 사이) | 빵 껍질과 속재료 사이의 공간 | 박스가 **커진다** |
| `margin` | 박스 **바깥쪽** (박스 ↔ 옆 것 사이) | 접시 위 빵과 빵 사이의 간격 | 박스가 **멀어진다** |

## 따라하는 단계
1. 이 폴더의 `index.html`을 **더블클릭**합니다. → 기본 브라우저에서 페이지가 열립니다.
2. 파란 박스 3개를 위에서 아래로 비교합니다.
   - **1번**: `margin` 0, `padding` 0 → 글자가 테두리에 딱 붙고, 회색 틀에도 딱 붙어 있습니다. (기준점)
   - **2번**: `padding: 30px` → 같은 글자인데 박스가 **통통해졌습니다.** 글자와 파란 테두리 사이가 벌어졌죠.
   - **3번**: `margin: 30px` → 박스 크기는 1번과 같지만, 회색 틀 안쪽으로 **쑥 들어가** 사방에 회색 틈이 생겼습니다.
3. `index.html`을 메모장(또는 VS Code)으로 열어 `.box-2`의 `padding: 30px;`을 `padding: 60px;`으로 바꿔 저장합니다.
4. 브라우저로 돌아와 **새로고침(F5)** → 2번 박스가 더 통통해졌는지 확인합니다.
5. 이번엔 `.box-3`의 `margin: 30px;`을 `margin: 60px;`으로 바꿔 저장 후 새로고침 → 박스가 회색 틀에서 더 멀어졌는지(박스 크기는 그대로인지) 확인합니다.
6. AI에게 시켜 보기:
   > "이 index.html에, `margin: 10px 40px;`처럼 위·아래와 좌·우 여백을 다르게 준 4번 박스를 추가해줘. 기존 박스는 그대로 두고 새 .box-4만 추가해줘."

## 검증법
- 2번 박스(`padding`)와 1번 박스를 비교해, **글자는 같은데 박스가 더 커 보이는가?** → padding이 박스를 키운다는 증거.
- 3번 박스(`margin`)는 1번과 **박스 크기가 같지만 회색 틈이 생겼는가?** → margin은 크기를 키우지 않고 위치만 민다는 증거.
- 브라우저에서 `F12 → Elements`로 파란 박스를 클릭하면, 오른쪽에 **상자 모델 그림**(가운데 content, 그 바깥 padding, 또 바깥 margin)이 나옵니다. `padding`과 `margin` 칸의 숫자가 코드와 같은지 확인합니다.
- (선택) 회색 점선 틀에서 회색이 보이는 곳은 모두 `margin`이 만든 빈 공간입니다. 어디에 회색이 보이는지 짚어 봅니다.
