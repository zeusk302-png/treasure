# 실습 115 — Supabase 클라이언트 연결하고 프로젝트 URL·anon key 안전하게 다루기

실습 114에서 **서버에 표(memos 테이블)** 를 만들었습니다.
하지만 그 표는 아직 Supabase 대시보드 안에만 있고, **내 웹페이지와는 연결되지 않은 상태**예요.
이번 실습은 그 둘을 잇는 **첫 전선(케이블)** 을 연결하는 단계입니다.

거창한 화면을 만들지 않습니다. 목표는 딱 하나,
**"내 웹페이지가 Supabase 서버에 인사를 건넬 수 있는가?"** 를 콘솔(개발자 도구)에서 두 눈으로 확인하는 것입니다.

> 비유: 114에서 창고(서버 DB)에 선반 하나(memos 표)를 짰습니다.
> 이번엔 창고로 가는 **출입증(anon key)** 을 들고 가서, 문지기에게 "들어가도 되나요?"라고 물어보고
> "네, 들어오세요"라는 대답을 듣는 연습입니다.

이 폴더에 있는 파일:

- `README.md` — 이 안내문 (연결 방법 + 키 안전하게 다루기)
- `index.html` — 연결 결과를 보여 주는 아주 단순한 화면 (라이브러리 불러오기 + script.js 연결)
- `script.js` — **핵심 코드.** `createClient`로 연결하고 콘솔에 성공/실패를 찍습니다.

## 목표

- CDN으로 `@supabase/supabase-js` 라이브러리를 불러와 `supabase.createClient(URL, anon키)` 로 연결을 만든다.
- **anon key(공개 키)** 가 무엇인지, **왜 브라우저에 박혀 공개돼도 안전한지**(전제: 서버에 RLS를 켜 둠)를 이해한다.
- 반대로 **service_role 키(비밀 키)** 는 왜 절대 브라우저·깃허브에 두면 안 되는지 구분한다.
- 연결이 성공하면 **개발자 도구 콘솔에 ✅ 확인 로그**가 찍히는 것을 직접 본다.

## 따라하는 단계

1. 먼저 **실습 114** 를 끝내 `memos` 테이블이 있어야 합니다. (없으면 [실습 114](../114/) 먼저 진행)
2. Supabase 대시보드에서 왼쪽 아래 **Settings(톱니바퀴) → API** 메뉴로 들어간다.
3. 거기서 두 값을 복사한다.
   - **Project URL** : `https://xxxxxxxx.supabase.co` 형태의 주소. (비밀 아님)
   - **anon public** 키 (신형은 `sb_publishable_...` 로 시작) : 브라우저에 둬도 되는 **공개 출입증**.
   - ⚠️ 같은 화면에 있는 **`service_role` / `sb_secret_...` 키는 절대 복사해서 쓰지 마세요.** 이건 모든 보안을 무시하는 마스터 키입니다.
4. 이 폴더의 `script.js`를 메모장이나 에디터로 열고, 맨 위 두 줄의 **자리표시자**를 내 값으로 바꾼다.
   ```js
   const SUPABASE_URL = "https://여기에-내-프로젝트-ID.supabase.co";   // ← 내 Project URL
   const SUPABASE_ANON_KEY = "sb_publishable_여기에-내-anon-공개키-붙여넣기"; // ← 내 anon public 키
   ```
5. `index.html`을 **브라우저로 연다.** (파일을 더블클릭하면 됩니다.)
6. 키보드로 **개발자 도구**를 연다. (윈도우: `F12`, 맥: `Cmd + Option + I`) → 위쪽 탭에서 **Console** 을 누른다.
7. 콘솔에 다음 같은 줄이 보이면 성공입니다.
   ```
   ✅ Supabase 연결 성공! memos 테이블이 응답했습니다.
      현재 memos 테이블의 행(줄) 개수: 1
   ```
   동시에 페이지 가운데 박스가 **초록색 "연결 성공"** 으로 바뀝니다.

이 실습(웹페이지 ↔ Supabase 첫 연결)을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 웹 프론트엔드 튜터야. 비전공자도 따라할 수 있게 만들어줘.
  목표: 내 웹페이지가 Supabase 서버에 '연결되는지'만 확인하는 가장 단순한 예제.
  요구사항:
  - index.html 하나, script.js 하나로 구성 (빌드 도구 없이 더블클릭으로 열림)
  - index.html에서 CDN으로 @supabase/supabase-js v2 를 불러오고, 그 아래에서 script.js 를 불러올 것
  - 화면에는 연결 상태를 보여주는 박스 하나만 둘 것 (처음 '확인 중' → 성공 시 초록 → 실패 시 빨강)
  - script.js 맨 위에 SUPABASE_URL, SUPABASE_ANON_KEY 두 개의 '자리표시자' 상수를 두고,
    실제 값은 내가 나중에 직접 붙여넣는다고 가정할 것
  제약:
  - anon(공개) 키만 쓰고, service_role(비밀) 키는 절대 코드에 넣지 말 것
  - 사용자 입력을 화면에 찍을 일은 없지만, 출력은 textContent 를 쓸 것
  코드만 주지 말고, 비전공자가 막힐 만한 줄에 '무엇을 하고 왜 그렇게 했는지' 한국어 주석을 달아줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  위 예제에 '진짜로 연결됐는지' 확인하는 단계를 추가해줘.
  - 실습 114에서 만든 memos 테이블에 가장 가벼운 요청을 보내서(select 에 count: 'exact', head: true 옵션) 응답이 오는지만 확인할 것
  - 성공하면 콘솔에 ✅ 성공 메시지와 memos 행 개수를 찍고, 화면 박스를 초록으로 바꿀 것
  - 실패하면 콘솔에 ❌ 와 error.message 를 찍고, 화면 박스를 빨강으로 바꿀 것
  - 자리표시자를 안 바꾼 채 열면, 서버에 요청하기 전에 미리 '값을 먼저 입력하라'고 안내할 것
  추가한 부분도 왜 그렇게 했는지 주석으로 설명해줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  Supabase 연결이 안 돼. 개발자 도구(F12) Console 탭에 이런 에러가 떠:
  (여기에 콘솔의 빨간 에러 메시지를 그대로 붙여넣기)

  내 상황:
  - script.js 의 SUPABASE_URL / SUPABASE_ANON_KEY 에 내가 복사한 값을 넣었어
  - 실습 114에서 memos 테이블은 만들었어
  이 에러가 무슨 뜻인지, 어디를(URL 오타인지, 키를 잘못 넣었는지, 테이블 이름인지, RLS 때문인지) 어떤 순서로 확인하면 되는지 단계별로 알려줘. 비전공자가 이해하게 한 줄씩 풀어서 설명해줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법

- 화면의 상태 박스가 **노랑(확인 중) → 초록(연결 성공)** 으로 바뀌었는가?
- 콘솔에 **`✅ Supabase 연결 성공!`** 로그와 **memos 행 개수**가 찍혔는가?
- (이해 확인) anon 키를 브라우저에 그대로 둬도 되는 이유를 한 문장으로 설명할 수 있는가?
  → "anon 키는 손님 자격 출입증일 뿐이고, 진짜 안전장치는 서버의 **RLS**다."
- **실패할 때 원인 찾기** (콘솔의 빨간 에러 메시지로 구분):
  - `Invalid API key` → anon 키를 잘못 붙여넣음. (혹시 service_role을 넣지 않았는지도 확인)
  - 주소 오류 / `Failed to fetch` → `SUPABASE_URL`의 철자나 `https://`를 확인.
  - `relation "public.memos" does not exist` → 114에서 `memos` 표를 안 만들었거나 이름이 다름.
  - `... permission denied` / RLS 관련 → 표에 RLS가 켜져 있는데 읽기 정책이 없는 경우. 이번 실습 단계에선 114처럼 RLS를 꺼 둔 상태면 정상 통과합니다. (보안을 켜는 법은 실습 119)
- (안전 점검) `script.js`에 넣은 키가 **`anon`/`sb_publishable_`** 로 시작하는가? `service_role`/`sb_secret_` 가 **아닌가?**
