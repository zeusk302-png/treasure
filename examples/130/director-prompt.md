# 리뷰용 디렉터 프롬프트 템플릿 (실습 130)

지금까지 만든 Supabase CRUD 앱(실습 116~129)을 **Claude에게 "디렉터" 관점으로** 점검받기 위한 복사용 프롬프트 모음입니다.

핵심은 "코드 다 짜 줘"가 아니라, **무엇을·왜 점검할지 사람이 정하고 → 어떻게는 AI에게 정확히 시키는 것**입니다.

> 비전공자를 위한 한 줄: 디렉터는 코드를 외우는 사람이 아니라, "이 기준으로 검사하고, 위험한 것부터 알려 줘"라고 정확히 시킬 줄 아는 사람입니다.

---

## ⚠️ 붙여넣기 전 안전 점검 (제일 중요)

AI에게 코드를 붙여넣기 전에 **비밀값을 자리표시자로 가린 뒤** 보내세요. (AI 대화창도 화면 공유·로그에 남을 수 있습니다.)

- `service_role` / `sb_secret_...` 키 → `REPLACE_WITH_SERVICE_ROLE_KEY` 로 치환
- 슬랙/디스코드 Webhook URL → `REPLACE_WITH_SLACK_WEBHOOK_URL` 로 치환
- 이메일 비밀번호·SMTP 비번 → `REPLACE_WITH_SMTP_PASSWORD` 로 치환
- 내 실제 이메일 주소 → `REPLACE_WITH_MY_EMAIL@example.com` 로 치환
- (anon/`sb_publishable_...` 키는 공개돼도 되지만, 습관적으로 가려서 보내면 더 안전합니다.)

---

## 프롬프트 1 — 역할과 점검 기준 정하기 (먼저 이걸 보냄)

```
당신은 비전공자가 만든 웹앱을 점검하는 시니어 코드 리뷰 디렉터입니다.
저는 HTML/CSS/JS + Supabase로 방명록/할 일 CRUD 앱을 만든 비전공 초보입니다.

다음 기준으로만 점검해 주세요. 추측으로 코드를 새로 짜지 말고,
제가 붙여넣는 코드에 실제로 있는 문제만 지적하세요. 모르면 "코드에 없어서 확인 불가"라고 답하세요.

[점검 기준]
1. 보안: service_role(비밀) 키가 브라우저 코드(script.js)에 들어가 있지 않은가?
   anon(공개) 키만 쓰고 있는가? RLS가 켜져 있다는 전제가 코드와 맞는가?
2. 보안: 사용자 입력을 innerHTML로 넣어 XSS 위험이 있는 곳은 없는가? (textContent 사용 여부)
3. 안정성: insert/select/update/delete 에 에러 처리(try/catch 또는 error 확인)가 있는가?
4. UX: 로딩/성공/실패 상태를 사용자에게 보여 주는가? 빈 목록일 때 안내가 있는가?
5. 자동화: 새 글 알림(n8n)에서 비밀값이 자리표시자로만 들어가 있는가?

지금은 점검 기준만 확인하고, "준비됐습니다. 코드를 붙여넣어 주세요"라고만 답하세요.
```

## 프롬프트 3 — 우선순위 정해 다시 시키기 (디렉팅의 핵심)


## 프롬프트 4 — AI 답변을 의심하고 검증하기 (믿되 검증)

```
방금 제안한 수정 중 하나라도, 실제로는 문제가 없는데 오해해서 지적한 게 있나요?
(예: anon 키는 원래 공개해도 되는데 비밀 키로 오해한 경우)
당신 답변에서 틀렸을 수 있는 부분을 스스로 1~2개 짚고, 제가 직접 어떻게 확인하면 되는지
(예: "브라우저 콘솔에서 ~를 확인", "Supabase 대시보드 Policies에서 ~확인") 알려 주세요.
```

## 디렉터 체크리스트 (사람이 최종 눈으로 확인)

AI 답변을 그대로 믿지 말고, 아래는 **내가 직접** 확인합니다.

- [ ] `script.js`의 키가 `sb_publishable_`(anon)로 시작한다. `sb_secret_`(service_role)가 **아니다**.
- [ ] service_role 키는 **n8n Credentials/환경변수에만** 있고, 브라우저 코드·깃허브엔 없다.
- [ ] 사용자 글을 화면에 그릴 때 `textContent`를 쓴다(innerHTML 아님 → XSS 방지).
- [ ] 모든 Supabase 호출에 `if (error) throw error` 또는 try/catch가 있다.
- [ ] `workflow.json`을 깃허브에 올려도 안에 진짜 비밀값이 없다(전부 `REPLACE_WITH_...`).
- [ ] AI가 "anon 키가 노출됐으니 위험"이라고 하면 → **틀린 지적**임을 안다(RLS가 켜져 있으면 anon은 공개 OK).

> 마지막 한 줄: AI는 "그럴듯하게" 틀릴 수 있습니다. 특히 anon vs service_role을 헷갈려
> "공개 키가 노출됐다"고 겁주는 경우가 흔합니다. 디렉터인 내가 기준을 알고 걸러야 합니다.
