# 296. 내 사이트 키 줍기 게임 — F12로 공개키/비밀키 찾아내기

배포된 척하는 연습용 사이트에서 개발자도구(F12)를 열어, 그 안에 숨어 있는 **두 종류의 키**를 직접 줍는 게임입니다.
화면에 보여도 괜찮은 값(**publishable / 공개 출입증**)과, 보이면 사고가 나는 값(**secret / 마스터키**)을
눈으로 구분하는 감을 잡는 게 목표예요. 코딩 지식 없이, 마우스 클릭만으로 할 수 있습니다.

> 안심하세요: 이 폴더의 키 값은 전부 **가짜 자리표시자**(`…여기에…`)라 실제로 새는 정보가 없습니다.
> "이렇게 생긴 게 비밀키구나"를 알아보는 연습용입니다.

## 목표
- 브라우저는 화면에 안 보여도 키를 **이미 다 받아서** 가지고 있다는 사실을 체감한다.
- `sb_publishable_`(=anon, 공개 출입증)는 보여도 **OK**, `sb_secret_`(=service_role, 마스터키)는 **절대 안 됨**을 구분한다.
- F12의 **Sources / Network / Console** 탭에서 노출된 문자열을 직접 찾아 분류한다.
- 결과를 `note.md`에 "보여도 OK / 절대 안 됨"으로 표시한 1장짜리 점검 메모로 남긴다.

## 따라하는 단계
1. 이 폴더의 `index.html`을 더블클릭해서 브라우저로 엽니다. (배포한 사이트를 본다고 상상하세요.)
2. 키보드 **F12**(또는 마우스 우클릭 → "검사")를 눌러 개발자도구를 엽니다.
3. **Sources(소스)** 탭을 누르고 왼쪽 목록에서 `index.html`을 클릭해 코드를 봅니다. 그 안의 `<script>`에서 키 두 개를 찾습니다.
   - 🟢 `sb_publishable_…` 로 시작하는 줄 → **보여도 OK**
   - 🔴 `sb_secret_…` 로 시작하는 줄 → **절대 안 됨 (찾았다! = 사고 지점)**
4. **Console(콘솔)** 탭으로 가면 같은 두 값이 로그로 찍혀 있습니다. 비밀키 옆에 ⚠️ 경고가 보이는지 확인합니다.
5. **Network(네트워크)** 탭을 켠 채 **F5**(새로고침)를 누릅니다. 요청 목록을 클릭하면, 화면에 안 보이던 값들도 통신에 실려 전송된다는 걸 확인합니다. → "브라우저는 키를 숨길 수 없다"는 핵심 체감.
6. 찾은 두 값을 `note.md`의 표에 옮겨 적고, 각각을 🟢/🔴로 분류합니다. (비밀키는 앞부분 `sb_secret_…`만 적기)
7. (선택) Sources와 Network 화면을 **스크린샷**으로 찍어 이 폴더(`296/`)에 넣고, 캡처 위에 🟢"보여도 OK"·🔴"절대 안 됨"을 표시합니다.

## 검증법
- [ ] F12 → **Sources** 탭에서 `sb_publishable_`(🟢)와 `sb_secret_`(🔴) **두 값을 모두** 찾았다.
- [ ] 두 값을 거꾸로가 아니라 **올바르게** 분류했다. (publishable=보여도 OK, secret=절대 안 됨)
- [ ] **Network** 탭에서 새로고침했을 때, 화면에 안 보이던 키가 통신에 실려 있다는 걸 직접 봤다.
- [ ] `note.md`에 "보여도 OK / 절대 안 됨"이 표시된 1장짜리 점검 메모를 완성했다.
- [ ] "왜 publishable은 보여도 안전한가?"에 **"RLS가 권한을 막아주니까"**라고 한 줄로 답할 수 있다.

> 빠른 자가 점검: 친구에게 이 사이트 주소를 줘도 되는 키와, 주면 큰일 나는 키를 손가락으로 짚을 수 있으면 통과입니다.
