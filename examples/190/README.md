# 190 — 이미지를 WebP로 줄이고 width·height·lazy 넣기

웹페이지가 느린 가장 흔한 이유는 코드가 아니라 **무거운 사진** 입니다. 휴대폰으로 찍은 사진 한 장이 5MB가 넘기도 하는데, 그런 사진 몇 장이면 페이지가 "왜 이렇게 안 떠?" 소리를 듣습니다.

이번 실습에서는 **사진을 가볍게 만드는 3종 세트**를 배웁니다.

1. **WebP(웹피)로 변환** — 같은 사진을 더 작은 용량으로 저장하는 최신 이미지 형식 (JPG보다 보통 25~35% 더 가벼움)
2. **`width`/`height` 넣기** — 사진이 차지할 자리를 미리 알려줘 화면이 출렁이지 않게 함
3. **`loading="lazy"` 넣기** — 화면 밖에 있는 사진은 스크롤해서 가까워질 때 불러오기

189번 실습에서 일부러 성능 점수를 깎았던 **"너무 큰 빵 사진 + 크기 속성 없음"** 문제를, 이번에 실제로 고친 결과물이 이 폴더입니다.

- 카테고리: SEO·성능·접근성 (코드 I)
- 난이도: 3 / 5
- 개념: 이미지 최적화, WebP, lazy loading
- 결과물: **WebP로 교체되고 크기 속성이 들어간 이미지 섹션** (`index.html` + `style.css`)

> 이 폴더의 이미지들은 **학습용 자리표시 이미지(placehold.co)** 주소를 씁니다. 별도 사진 파일을 받지 않아도 브라우저에서 바로 동작을 확인할 수 있어요. 실제 프로젝트에서는 아래 "단계"에 따라 내 사진을 WebP로 바꿔 같은 폴더에 넣고 `src`만 `hero.webp`처럼 고치면 됩니다.

## 목표

핵심 개념 세 가지를 비유로 먼저 잡고 갑니다.

| 기법 | 무슨 일을 하나 | 어떤 점수가 좋아지나 | 한 줄 비유 |
|---|---|---|---|
| **WebP 변환** | 같은 사진을 더 작은 파일로 저장 | LCP(가장 큰 게 뜨는 시간) ↓ | 짐을 진공 압축팩에 넣어 부피 줄이기 |
| **`width`/`height`** | 사진이 들어갈 자리를 미리 비워 둠 | CLS(화면 밀림) ↓ | 식당에서 "4인석" 예약 표시 붙여 두기 |
| **`loading="lazy"`** | 화면 밖 사진은 나중에 불러옴 | 처음 로딩 데이터량 ↓ | 손님이 와서 주문할 때 요리 시작하기 |

용어 한 줄 정리

- **LCP (Largest Contentful Paint)**: 화면에서 가장 큰 콘텐츠(보통 대표 사진)가 다 뜨는 데 걸리는 시간. 짧을수록 "빨리 떴다"고 느낌.
- **CLS (Cumulative Layout Shift)**: 페이지를 읽는 도중 사진·광고가 뒤늦게 끼어들며 글자가 위아래로 **튀는 정도**. 0에 가까울수록 좋음.

> 왜 `width`/`height`가 화면 밀림을 막나요?
> 브라우저는 사진 파일이 도착하기 전에는 그 사진이 얼마나 클지 모릅니다. 그래서 자리를 0으로 잡았다가, 사진이 도착하면 갑자기 그만큼 아래 내용을 **쿵 하고 밀어냅니다.** `width="800" height="500"`을 미리 적어 두면, 브라우저가 처음부터 그만큼 빈 자리를 잡아 두기 때문에 사진이 늦게 와도 글자가 안 튑니다.

> 주의 — 첫 화면 대표 이미지에는 `loading="lazy"`를 넣지 마세요!
> lazy는 "화면 밖 사진을 미루는" 기능입니다. 그런데 페이지를 열자마자 보이는 **대표(히어로) 이미지를 lazy로 미루면 오히려 늦게 떠서 LCP가 나빠집니다.** 그래서 이 폴더의 `index.html`에서도 맨 위 큰 사진(`hero-img`)에는 일부러 lazy를 안 넣고, 스크롤해야 보이는 갤러리 사진에만 넣었습니다.

## 따라하는 단계

### 1단계 — 완성본을 먼저 브라우저로 열어 보기

1. 이 폴더(`examples/190/`)의 **`index.html`** 을 크롬으로 엽니다. (파일을 크롬 창에 드래그)
2. 빵집 페이지가 뜹니다. 위쪽 대표 사진은 바로 뜨고, 아래 갤러리는 스크롤하면 한 장씩 나타납니다.

### 2단계 — lazy가 실제로 작동하는지 눈으로 확인하기

1. `F12`로 개발자도구를 열고 위쪽 탭에서 **`Network`**(네트워크)를 누릅니다.
2. **`Img`** 필터(이미지만 보기)를 누른 뒤, 페이지를 새로고침(`F5`)합니다.
3. 처음에는 **위쪽 사진 몇 개만** 목록에 뜹니다. **아래로 천천히 스크롤**하면, 가까워질 때마다 갤러리 사진이 **하나씩 새로 목록에 추가**됩니다.
   - 이게 바로 `loading="lazy"`가 "필요할 때 불러오는" 모습입니다.

### 3단계 — width/height가 화면 밀림을 막는 걸 체감하기

1. 개발자도구의 **`Network`** 탭에서 속도를 **`Slow 3G`**(아주 느린 인터넷)로 바꿔 봅니다.
2. 새로고침하면 사진이 천천히 도착하는데, 이때 사진 자리에 **회색 박스가 미리 잡혀 있어** 글자가 위아래로 튀지 않습니다.
   - 비교: HTML에서 어떤 `<img>`의 `width`/`height`를 지워 보고 다시 새로고침하면, 그 사진이 도착하는 순간 아래 글자가 **쿵 하고 밀리는 것**을 볼 수 있습니다. 확인했으면 다시 원래대로 되돌리세요.

### 4단계 — 내 진짜 사진을 WebP로 바꾸기 (실제 프로젝트용)

자리표시 이미지 대신 내 사진을 쓰려면, 사진을 WebP로 변환해야 합니다. 코딩 없이 가능합니다.

1. **온라인 변환기 사용 (가장 쉬움):** "squoosh" 같은 무료 사이트(squoosh.app)에 사진을 올립니다.
   - 오른쪽 형식에서 **`WebP`** 를 고릅니다.
   - 품질(Quality)을 **75~80** 정도로 내려도 눈에는 거의 차이가 없으면서 용량이 확 줄어듭니다.
   - 화면 폭보다 큰 사진이면 **크기(Resize)도 800px 정도로 줄입니다.** (웹에 8000px짜리 원본을 그대로 올릴 필요는 없습니다.)
   - 내려받은 파일 이름을 예: `hero.webp`, `bread.webp`로 정해 이 폴더에 넣습니다.
2. **명령어가 익숙하다면:** `cwebp -q 80 hero.jpg -o hero.webp` 한 줄로도 변환됩니다.
3. `index.html`에서 자리표시 주소를 내 파일 이름으로 바꿉니다.

   ```html
   <!-- 바꾸기 전 (학습용 자리표시) -->
   <img src="https://placehold.co/800x500/webp?text=Croissant" alt="..." width="800" height="500" />

   <!-- 바꾼 후 (내 WebP 파일) -->
   <img src="hero.webp" alt="버터 향이 가득한 갓 구운 크루아상" width="800" height="500" />
   ```

   - `width`/`height`에는 **변환한 실제 사진의 가로·세로 픽셀 수**를 적습니다. (예: 800×500으로 줄였으면 그대로 800, 500)

### 5단계 (한 단계 더) — `<picture>`로 안전망 만들기

아주 오래된 브라우저는 WebP를 못 읽을 수 있습니다. `index.html` 맨 아래 `<picture>` 예시처럼 하면 **WebP를 먼저 시도하고, 안 되면 JPG로 자동 대체(폴백)** 됩니다.

```html
<picture>
  <source srcset="hero.webp" type="image/webp" />
  <img src="hero.jpg" alt="..." width="800" height="500" loading="lazy" />
</picture>
```

- `width`/`height`/`loading`은 항상 안쪽 `<img>`에 답니다.
- 2026년 기준 대부분의 브라우저가 WebP를 지원하므로, 이 안전망은 "있으면 더 안심" 수준입니다.

## 🤖 바이브코딩 프롬프트

이번 실습(이미지 WebP 변환 + `width`/`height` + `loading="lazy"`)을 AI에게 시켜 만들 때, 아래 프롬프트를 그대로 복사해 쓰면 됩니다. 한 번에 다 시키지 말고 **뼈대 → 기능 추가 → (막히면) 디버깅** 순서로 나눠 시키는 것이 핵심입니다.

- **1단계(뼈대 만들기)** 프롬프트:

  ```text
  너는 웹 성능을 챙기는 프론트엔드 개발자야. 비전공자가 이해할 결과물이 필요해.
  "우리 동네 빵집" 소개 페이지의 index.html과 style.css를 만들어 줘.

  [구성]
  - 맨 위에 대표(히어로) 이미지 1장 + 제목
  - 아래에 메뉴 갤러리 6장 (figure + figcaption 카드 그리드)
  - 마지막에 <picture>로 'WebP 우선, 안 되면 JPG' 안전망 예시 1개

  [제약]
  - 실제 사진 파일 없이 바로 확인되도록 이미지 src는 placehold.co 자리표시 주소를 써 줘
    (예: https://placehold.co/800x500/webp?text=Croissant)
  - 모든 <img>에 alt(한국어 설명)와 width/height를 반드시 넣어 줘
  - 갤러리는 CSS grid의 auto-fit + minmax로 반응형으로
  - 코드만 주지 말고, 왜 그렇게 했는지 한국어 주석으로 한 줄씩 풀어서 설명해 줘
  ```

- **2단계(기능 추가/개선)** 프롬프트:

  ```text
  좋아. 이제 성능 최적화 3종 세트를 정확히 적용해 줘. 각각 '왜'를 주석으로 달아 줘.

  1) loading="lazy": 화면 밖 갤러리 이미지에만 넣어 줘.
     단, 첫 화면 대표(히어로) 이미지에는 절대 넣지 마. (lazy로 미루면 LCP가 나빠지니까)
  2) width/height: 모든 <img>에 실제 비율과 같은 가로·세로 숫자를 넣어 화면 밀림(CLS)을 막아 줘.
  3) CSS에서 img { max-width:100%; height:auto } 로 반응형 비율을 유지하고,
     사진 도착 전 자리를 회색 박스(background)로 보여 줘서 밀림이 없음을 눈으로 확인되게 해 줘.

  추가로, 내 진짜 사진을 WebP로 바꿔 쓰는 방법(squoosh 사용, 품질 75~80, 800px로 리사이즈)을
  README에 단계별로 정리해 줘.
  ```

- **막혔을 때(디버깅)** 프롬프트:

  ```text
  개발자도구 Network → Img 탭에서 확인했는데 기대대로 안 돼. 단계별로 원인을 진단해 줘.

  [증상] (해당하는 것을 붙여넣기)
  - 스크롤해도 갤러리 이미지가 처음부터 전부 한꺼번에 받아진다 (lazy가 안 먹는 듯)
  - Slow 3G로 새로고침하면 사진 도착 순간 글자가 위아래로 쿵 하고 튄다 (CLS 발생)
  - 사진이 가로세로 비율이 안 맞아 찌그러져 보인다

  내 index.html과 style.css 코드는 아래에 붙여넣을게. (코드 붙여넣기)
  무엇이 원인인지, 어느 줄을 어떻게 고쳐야 하는지, 왜 그렇게 고치는지 함께 설명해 줘.
  ```

> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면, 결과물이 그대로 학습 자료가 됩니다.

## 검증법

아래가 모두 되면 이번 실습은 성공입니다.

- **페이지가 뜬다:** `index.html`을 열면 빵집 페이지가 깨지지 않고 보인다.
- **lazy가 작동한다:** 개발자도구 `Network → Img`에서, 처음엔 위쪽 사진만 받고 **스크롤하면 갤러리 사진이 하나씩 추가로** 받아진다.
- **화면이 안 튄다:** `Slow 3G`로 새로고침해도 사진 자리(회색 박스)가 미리 잡혀 있어 글자가 위아래로 밀리지 않는다.
- **크기 속성이 다 있다:** 모든 `<img>`에 `width`와 `height`가 들어 있다. (대표 이미지 포함)
- **대표 이미지엔 lazy가 없다:** 첫 화면 큰 사진(`hero-img`)에는 `loading="lazy"`가 **없고**, 갤러리·하단 사진에만 있다.
- **(실제 프로젝트라면) 용량이 줄었다:** 원본 JPG와 변환한 WebP 파일 용량을 비교해 WebP가 더 작다. (`Network` 탭의 `Size` 열에서도 확인 가능)
- **(개념 확인)** "WebP는 용량(LCP), width/height는 화면 밀림(CLS), lazy는 처음 로딩량을 줄인다"를 각각 한 문장으로 설명할 수 있다.

> 흔한 실수
> - **대표 이미지에 lazy를 넣음:** 첫 화면 사진을 미뤄서 오히려 더 느려 보입니다. 히어로 이미지에는 lazy를 빼세요.
> - **width/height를 안 넣음:** WebP로 가볍게 만들어도, 자리 표시가 없으면 화면이 여전히 출렁입니다. 둘은 같이 가야 합니다.
> - **원본을 그대로 WebP로만 바꿈:** 8000px짜리 거대한 사진을 WebP로만 바꾸면 여전히 무겁습니다. **크기(픽셀)도 화면에 맞게 줄여야** 진짜 가벼워집니다.
> - **width/height에 실제 비율과 다른 숫자를 적음:** 사진이 찌그러져 보입니다. 변환한 사진의 실제 가로·세로를 적으세요.

> 보안 메모: 이 실습에는 **비밀값이 전혀 들어가지 않습니다.**
> 이미지 파일·HTML·CSS는 모두 누구나 볼 수 있는 **공개 정보**입니다(브라우저로 그대로 내려받아짐). 그래서 비밀번호, API 키, Supabase의 `service_role`(비밀) 키 같은 값은 이미지의 파일명이나 페이지 어디에도 넣지 않습니다.
> 페이지에 노출해도 되는 값은 Supabase의 `anon`(공개) 키처럼 애초에 "공개용"으로 설계된 값뿐이지만, 이번 실습에서는 그조차 사용하지 않습니다.
