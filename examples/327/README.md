# 실습 327 — 이메일 발송(Resend/SMTP) 연동하기

문의 폼이나 가입 폼을 만들면, 다음으로 거의 항상 필요한 게 **"제출하면 확인 메일이 자동으로 가는"** 기능입니다. 이번 실습에서는 작은 **문의 폼(index.html)** 과 **작은 서버(server.js)** 를 만들어, 폼이 제출되면 서버가 **Resend(이메일 API)** 를 호출해 **신청자에게 확인 메일을 자동 발송**하게 만듭니다. 이렇게 사람이 보내는 게 아니라 **시스템 동작에 맞춰 한 통씩 자동으로 나가는 메일**을 **트랜잭션 메일**이라고 부릅니다. 동시에 **API 키를 코드에 박지 않고 서버 환경변수에만 두는 법**, **발신 도메인을 인증해 스팸함을 피하는 기본**도 익힙니다.

> 한 줄 그림: **사용자가 폼 제출 → 브라우저가 내 서버(`/api/contact`)로 보냄 → 서버가 비밀 API 키로 Resend 호출 → Resend가 확인 메일 발송 → 사용자 받은편지함에 "신청 확인" 메일 도착**

> 비유: 이메일 API는 **우체국에 미리 계약해 둔 자동 발송 창구**입니다. 내가 봉투를 일일이 부치는 게 아니라, "이 주소로 이런 내용 보내 줘"라고 창구에 요청서(API 호출)만 넣으면 우체국이 알아서 부쳐 줍니다. 이때 **계약 번호(API 키)** 는 나만 알아야 하는 비밀이라, 손님(브라우저)에게 절대 보여 주지 않고 **사무실 금고(서버 환경변수)** 에만 둡니다.

> 보안 메모 — 공개해도 되는 값 vs 절대 숨겨야 하는 값
> - **공개되어도 되는 것**: 폼 화면(`index.html`)과 폼이 호출하는 **내 서버 주소**(`/api/contact`). 이건 누가 봐도 안전합니다.
> - **절대 노출하면 안 되는 비밀값**: **Resend API 키**(`re_...`). 이 키를 브라우저 코드(`index.html`/프런트 JS)에 박으면 `F12` 한 번에 그대로 새어, 남이 내 계정으로 메일을 마구 보낼 수 있습니다. 그래서 키는 **오직 서버(`server.js`)에서만, 그것도 환경변수(`process.env.RESEND_API_KEY`)로** 읽습니다.
> - 이 폴더의 `server.js`에는 진짜 키가 한 글자도 없습니다. 진짜 값은 `.env`(또는 배포 서비스의 환경변수)에만 적고, `.env`는 `.gitignore`로 깃에서 빠집니다. `.env.example`에는 **자리표시자**만 들어 있습니다.

## 목표
- **트랜잭션 메일이 무엇인지** 이해한다: 사람이 손으로 보내는 게 아니라, "폼 제출" 같은 **동작 한 건마다 자동으로 한 통씩** 나가는 메일.
- **이메일 API(Resend)를 서버에서 연동**한다: 폼 → 내 서버 → Resend → 확인 메일 도착까지 흐름을 직접 동작시켜 본다.
- **API 키를 코드가 아니라 서버 환경변수에 둔다**: 키를 브라우저에 절대 노출하지 않고, `server.js`에서 `process.env`로만 읽는다.
- **발신 신뢰(스팸 회피) 기본을 안다**: 발신 도메인을 인증(SPF·DKIM·DMARC)하면 왜 스팸함行을 피하는지, 인증 전엔 무엇이 한계인지 안다.
- **사용자 입력을 안전하게 다룬다**: 받은 이름·메시지를 메일 본문에 넣을 때 이스케이프하고, 화면 출력은 `textContent`로 한다(XSS 방지).

## 따라하는 단계

### A. Resend 계정과 API 키 준비
1. [resend.com](https://resend.com) 에 가입합니다(무료 등급으로 충분합니다).
2. 좌측 메뉴 **API Keys → Create API Key** 로 키를 하나 만듭니다. 키는 `re_` 로 시작합니다. **이 키는 생성 직후 한 번만 전부 보여 주므로 복사해 둡니다.**
3. 처음엔 발신 주소로 Resend가 주는 테스트 주소 `onboarding@resend.dev` 를 쓸 수 있습니다. **단, 테스트 주소는 보통 "내 계정에 등록한 메일"로만 보낼 수 있습니다.** 그래서 받는사람(`to`)에는 **가입할 때 쓴 내 이메일**을 넣어 먼저 테스트하세요.

### B. 프로젝트 셋업
4. 이 폴더(`examples/327/`)에서 터미널을 엽니다.
5. 의존성을 설치합니다.
   ```bash
   npm install express resend
   ```
6. `.env.example` 을 복사해 `.env` 를 만들고, 그 안에만 진짜 값을 적습니다. (`.env` 는 `.gitignore` 덕분에 깃에 안 올라갑니다.)
   ```bash
   cp .env.example .env
   ```
   `.env` 안:
   ```
   RESEND_API_KEY=re_여기에_진짜_키_붙여넣기
   MAIL_FROM=onboarding@resend.dev
   ```

### C. 서버 켜고 메일 보내 보기
7. 서버를 실행합니다.
   ```bash
   node server.js
   ```
   터미널에 `서버 실행 중: http://localhost:3000` 이 보이면 성공입니다.
8. 브라우저에서 `http://localhost:3000` 을 엽니다. 폼이 뜹니다.
9. 이름·이메일(가입 때 쓴 내 메일)·메시지를 넣고 **보내기**를 누릅니다.
10. 화면에 "확인 메일을 보냈습니다" 가 뜨고, **내 받은편지함(또는 스팸함)에 확인 메일이 도착**하면 연동 성공입니다.

### D. (선택) 내 도메인으로 발신해 스팸함 피하기
11. Resend 의 **Domains → Add Domain** 에서 내 도메인(예: `mycafe.com`)을 추가합니다.
12. Resend가 알려 주는 **DNS 레코드(SPF·DKIM·DMARC)** 를 내 도메인 DNS에 등록합니다. 인증이 끝나면 `MAIL_FROM` 을 `hello@mycafe.com` 같은 **내 도메인 주소**로 바꿀 수 있고, **아무에게나** 보내도 스팸함에 덜 빠집니다.
    - SPF: "이 서버는 우리 도메인 메일을 보낼 권한이 있다"는 허가증.
    - DKIM: 메일에 위조 못 할 도장(서명)을 찍는 것.
    - DMARC: 위 둘이 실패하면 어떻게 처리할지 정하는 정책.

> SMTP로 보내고 싶다면: Resend 외에 회사 메일 서버(SMTP)를 쓰는 경우, `resend` 대신 `nodemailer` 패키지를 쓰고 호스트·포트·계정을 환경변수로 둡니다. **API 키든 SMTP 비밀번호든, "비밀값은 코드 밖 환경변수에"라는 원칙은 똑같습니다.**

  ```text
  방금 만든 메일 발송 예제를 더 튼튼하게 개선해줘. 코드와 함께 "왜 필요한지"도 설명해줘.

  2) XSS/주입 방지: 사용자가 넣은 이름·메시지를 메일 HTML 본문에 넣을 때 <,>,& 등을 이스케이프해줘.
  3) 화면 출력: 폼 성공/실패 안내 메시지는 textContent로 넣어(innerHTML 금지) — 이유도 주석으로.
  4) 운영자 사본: 신청자에게 보내는 확인 메일 외에, 운영자(나)에게도 "새 문의 도착" 메일을 한 통 더 보내는 옵션을 추가해줘(받는 주소도 환경변수로).

  "가능성 높은 순"으로 정리하고, 각 후보를 확인하는 방법을 한 단계씩 알려줘.

  - 증상: (예: 화면엔 "보냈습니다"가 뜨는데 메일이 안 옴 / 401 에러 / "domain is not verified" 에러)
  - 내 상황: 발신주소(MAIL_FROM)는 ___, 받는주소(to)는 ___ 로 테스트 중.

  - RESEND_API_KEY 가 .env 에서 제대로 로드됐는지(서버 시작 로그로 확인하는 법, 단 키 값 자체는 출력하지 말 것)
  - 테스트 발신주소(onboarding@resend.dev)는 "내 계정 메일"로만 보내지는 제약 때문인지
  - 메일이 스팸함에 들어간 건 아닌지, 도메인 인증(SPF/DKIM)이 필요한 상황인지
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비밀값을 코드에 박지 말고 환경변수로 빼줘"를 항상 덧붙이세요.

## 검증법
- **메일 도착 확인**: 폼을 제출하면 받은편지함(또는 스팸함)에 확인 메일이 **실제로 도착**하는지 본다. 스팸함에만 온다면 도메인 인증(D단계)이 필요한 신호다.
- **키가 브라우저에 안 새는지 확인**: 페이지에서 `F12 → Sources`(또는 `Ctrl`+`U` 소스 보기)로 프런트 코드를 열어 `re_` 나 `RESEND_API_KEY` 같은 문자열이 **0건**인지 검색한다. (보이면 안 된다 — 키는 서버에만 있어야 한다.)
- **요청이 내 서버로 가는지 확인**: `F12 → Network` 에서 폼 제출 시 요청이 **외부 Resend 주소가 아니라 내 서버(`/api/contact`)** 로 가는지 본다. 브라우저가 Resend를 직접 부르면 키가 새는 위험 신호다.
- **코드에 비밀값이 없는지 확인**: 이 폴더에서 아래를 실행하면 **자리표시자만** 나와야 정상이다.
  - `grep -rnE "re_[A-Za-z0-9]{10,}" server.js index.html .env.example` → 진짜 키가 **안 나와야** 정상이다.
- **입력 검증 확인**: 이메일을 비우거나 `abc`(형식 오류)로 넣고 제출했을 때, 메일이 안 가고 **안내 메시지**가 뜨는지 본다.

## 파일 구성
- `index.html` — 문의 폼(이름·이메일·메시지). 제출 시 `fetch`로 내 서버 `/api/contact`를 호출한다. 안내 메시지는 `textContent`로 출력(XSS 방지).
- `server.js` — Express 서버. `POST /api/contact`에서 입력을 검증하고, Resend로 확인 메일을 발송한다. API 키는 `process.env`로만 읽는다.
- `package.json` — 의존성(`express`, `resend`)과 실행 스크립트.
- `.env.example` — 필요한 비밀값 견본(자리표시자만). 복사해 `.env`를 만들고 진짜 값은 거기에만 적는다.
- `.gitignore` — `.env`·`node_modules` 등이 깃에 안 올라가게 막는다.
