# 실습 150 — 오늘의 명언 + 작가 이름을 한 카드에 함께 묶기

공개 API에서 받은 **JSON 한 덩어리**에서 글귀(`content`)와 작가(`author`) **두 개의 값을 동시에 꺼내**,
한 카드 안의 서로 다른 자리에 나란히 채워 넣는 한 장짜리 페이지입니다.

직전 실습(148)이 "버튼을 누를 때마다 **다시** 받아오기"였다면,
이번 150은 **받은 한 덩어리 안에서 여러 칸(필드)을 꺼내 쓰는 법**에 집중합니다.

> 비유: 택배 상자(JSON 한 덩어리)를 하나 받았습니다.
> 상자를 열면 안에 물건이 여러 개 들어 있고, 각 물건에는 이름표(키, key)가 붙어 있습니다.
> `data.content`는 "글귀"라는 이름표가 붙은 물건을, `data.author`는 "작가"라는 이름표가 붙은 물건을 꺼내는 것입니다.

## 목표
- 서버 응답(JSON) 한 덩어리가 **값 하나가 아니라 여러 칸으로 이루어진 '객체'**임을 이해한다.
- 객체에서 점(`.`)을 써서 **여러 키를 동시에** 꺼내는 법을 익힌다.
  - `data.content` = "글귀" 칸의 값 꺼내기
  - `data.author` = "작가" 칸의 값 꺼내기
- 꺼낸 두 값을 화면(DOM)의 **서로 다른 자리**(글귀 자리 / 작가 자리)에 각각 채워 한 카드로 묶는다.

## 따라하는 단계
1. 이 폴더의 `index.html`을 더블클릭 → 브라우저에서 열린다. (인터넷 연결 권장)
2. **"명언 받기" 버튼**을 누른다 → 카드 안에 **글귀**와 그 아래 **작가 이름**이 함께 나타난다.
3. `script.js`를 열어 `const data = await res.json();` 줄을 찾는다 → 이 `data`가 **여러 칸이 든 한 덩어리(객체)**다.
4. 그 바로 아래 `render(data)`를 본다 → 받은 한 덩어리를 통째로 화면 그리는 함수에 넘긴다.
5. `render` 함수 안에서 **두 줄**을 나란히 본다. 이게 이번 실습의 핵심이다.
   - `quoteEl.textContent = quote.content;` → `content` 칸 값을 글귀 자리에
   - `authorEl.textContent = "— " + quote.author;` → `author` 칸 값을 작가 자리에
6. 브라우저에서 `F12`(개발자 도구) → **Console 탭**에서 직접 확인해 본다.
   - `fetch("https://api.quotable.io/random").then(r => r.json()).then(d => console.log(d))` 를 입력하고 Enter
   - 출력된 `{ content: "...", author: "...", ... }`에서 **여러 칸(키)이 한 덩어리**에 들어 있는 모습을 눈으로 본다.
7. AI에게 시켜 보기:
   > "이 `script.js`에서 명언의 글자 수(`length` 같은 길이 정보)도 카드 아래에 작게 함께 보여주도록, JSON에서 또 다른 값을 꺼내 화면에 추가해줘."

## 검증법
- "명언 받기" 버튼을 누르면 카드 안에 **글귀**가 나타나는가?
- 글귀 **바로 아래에 작가 이름**(`— 이름` 형태)이 **함께** 보이는가?
- 버튼을 다시 누르면 글귀와 작가가 **둘 다 한꺼번에** 새 값으로 바뀌는가?
- 작가 정보가 없는 명언이 와도 `— 작자 미상`으로 깨지지 않고 표시되는가?
- `F12` → **Network 탭**을 켜고 버튼을 누르면 `random` 요청이 실제로 한 번 가는가?
- (실패 대비) 와이파이를 끄고 버튼을 눌러도 **글귀와 작가가 짝으로** 든 예비 명언이 뜨는가?

## 키(API Key)는 필요 없어요
이 실습이 쓰는 명언 API는 **누구나 열쇠 없이** 부를 수 있는 **공개 API**입니다.
그래서 코드에 비밀값(`YOUR_API_KEY` 같은 것)을 넣지 않습니다.
나중에 유료 API나 내 데이터를 다루는 API를 쓸 때는 키가 필요하고,
그 키는 화면 코드(브라우저에 그대로 노출됨)에 넣으면 안 됩니다.
비밀 키는 서버 쪽(예: Supabase의 `service_role`)에서만 다루며, 이는 보안 권에서 따로 배웁니다.
