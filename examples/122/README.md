# 실습 122 — 할 일 삭제 `delete`로 서버에서 지우기 (CRUD 완성)

지금까지 만든 할 일 앱은 **추가(`insert`)·목록(`select`)·완료 토글(`update`)** 까지 됐습니다.
딱 하나가 빠졌죠. **"이 할 일 지워!"** 하는 기능입니다.

이번 122번에서는 각 할 일 오른쪽에 빨간 **[삭제]** 버튼을 달고, 누르면 그 줄만 골라
**`delete`(삭제)** 로 서버에서 영구히 지웁니다. 삭제는 되돌릴 수 없으니, 진짜 지우기 전에
**`confirm`(정말 삭제할까요?)** 으로 한 번 더 묻는 실수 방지 장치도 함께 답니다.
이걸로 **CRUD(Create·Read·Update·Delete = 만들고·읽고·고치고·지우기)** 가 완성됩니다.

> 비유: 서버의 `todos` 표를 '큰 출석부'라고 하면, `delete().eq("id", id)`는
> **"3번 학생 줄만 통째로 찢어서 버리는"** 일입니다.
> `eq("id", id)`(번호 콕 집기)가 없으면 **출석부 전체를 찢어 버립니다**(대형 사고!).
> 게다가 찢은 종이는 다시 못 붙이므로(되돌리기 불가), 찢기 전에 `confirm`으로 한 번 더 확인합니다.

**이번 실습의 한 줄 핵심:**

```js
db.from("todos").delete().eq("id", id)
//                 ┗ 무엇을 할지       ┗ 어느 줄을 지울지(이게 빠지면 전부 삭제됨)
```

| 하는 일 | 어떻게 | 언제 배웠나 |
| --- | --- | --- |
| 할 일 추가 (Create) | `db.from("todos").insert({ text })` | 116·120 |
| 목록 보기 (Read) | `db.from("todos").select("*")` | 117·120 |
| 완료 토글 (Update) | `db.from("todos").update({ done }).eq("id", id)` | 121 |
| **할 일 삭제 (Delete)** | **`db.from("todos").delete().eq("id", id)`** | **이번 122** |

이 폴더에 있는 파일:

- `README.md` — 이 안내문
- `schema.sql` — **먼저 실행.** `todos` 표·RLS·읽기/쓰기·수정 정책(120·121번 것) + **`delete` 정책(이번 추가분)**
- `index.html` — 각 할 일에 **체크박스 + 빨간 [삭제] 버튼**이 붙은 화면
- `script.js` — [삭제] 버튼을 누르면 `confirm` 후 `delete`로 서버 행을 지우는 `deleteTodo` 함수가 핵심

## 목표

- 삭제 버튼에 **`delete().eq("id", id)`** 를 연결해 **특정 행 한 건만** 서버에서 지우는 패턴을 익힌다.
- `delete`에도 **`eq`로 대상 한 건 콕 집기**가 짝꿍처럼 따라온다는 것(안 그러면 표가 전부 삭제됨)을 이해한다.
- 삭제처럼 **되돌릴 수 없는 동작 전에는 `confirm`으로 한 번 더 확인**하는 안전 습관을 익힌다.
- RLS에서 **동작별로 정책이 따로 필요**하다는 것을 다시 체감한다 — 121번까지는 `delete` 정책이 없어 삭제가 막혀 있고, 이번에 **`delete` 정책**을 추가해야 통과한다. 이로써 **CRUD 4개 동작이 모두 완성**된다.
- **anon(공개) 키만** 코드에 넣고, **service_role(비밀) 키는 절대 넣지 않는** 보안 원칙을 지킨다.

## 따라하는 단계

1. **`schema.sql`을 실행해 서버에 `delete` 정책을 추가한다.**
   Supabase 대시보드 → **SQL Editor → New query** 에 이 폴더의 `schema.sql` **전체**를 붙여넣고 **[Run]** 합니다.
   → 120·121번을 이미 했다면 1~4단계는 건너뛰고, **5단계 `delete` 정책**이 새로 추가됩니다. (여러 번 실행해도 안전합니다.)
2. `script.js`의 맨 위 두 줄 **자리표시자**를 내 **anon(공개) 키** 값으로 바꾼다.
   Supabase 대시보드 → **Settings(톱니바퀴) → API** 에서 복사합니다.
   ```js
   const SUPABASE_URL = "https://여기에-내-프로젝트-ID.supabase.co";        // ← Project URL
   const SUPABASE_ANON_KEY = "sb_publishable_여기에-내-anon-공개키-붙여넣기"; // ← anon public 키
   ```
   ⚠️ **`service_role` / `sb_secret_...` 키는 절대 넣지 마세요.** RLS를 통째로 무시하는 마스터 키라, 브라우저에 노출하면 누구나 데이터를 마음대로 지울 수 있게 됩니다.
3. `index.html`을 **브라우저로 열기** 전, 개발자 도구(`F12`) → **Console** 탭을 켜 둔다. (성공/실패 로그가 여기 찍힙니다.)
4. `index.html`을 **더블클릭해서 열고**, 할 일을 2~3개 추가한다. (없으면 입력칸에 적고 [추가])
5. 지우고 싶은 할 일 오른쪽의 빨간 **[삭제] 버튼을 클릭**한다.
   → `"○○ 할 일을 정말 삭제할까요?"` 확인창이 뜹니다. **[취소]를 누르면 아무 일도 일어나지 않습니다.**
6. 같은 버튼을 다시 누르고 이번엔 **[확인]** 을 누른다.
   → `삭제 중…` → `삭제했어요!` 가 뜨고, **그 줄이 목록에서 사라지면** 성공입니다.
   → Console에 `✅ 삭제 완료: {id: ..., text: "..."}` 로그가 찍힙니다.
7. **서버에서 진짜 지워졌는지 확인:** 페이지를 **새로고침(F5)** 한다.
   → 지운 할 일이 다시 나타나지 않으면, 화면뿐 아니라 **서버에서도 지워진 것**입니다.
8. Supabase 대시보드 → **Table Editor → todos** 표를 열어, 삭제한 줄이 **표에서 사라졌는지** 눈으로 확인한다.

## 🤖 바이브코딩 프롬프트

이 실습(할 일 앱에 `delete` 삭제 기능을 붙여 CRUD를 완성)을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. 한 번에 다 시키지 말고 **1단계 → 2단계** 순서로 시키고, 막히면 **디버깅 프롬프트**로 물어보세요.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 비전공자도 따라할 수 있게 설명해 주는 웹 개발 도우미야.
  Supabase(JS CDN @supabase/supabase-js@2)로 동작하는 "할 일(todo) 앱"의 뼈대를 만들어 줘.

  [상황] 이미 todos 표가 있고(컬럼: id, text, done, created_at) 추가(insert)·목록(select)은 동작해.
  이번엔 "삭제(delete)" 기능을 새로 붙이고 싶어. CRUD(만들고·읽고·고치고·지우기) 완성이 목표야.

  [요구사항]
  - 파일은 index.html / script.js / schema.sql 세 개로 나눠 줘.
  - script.js 맨 위에 SUPABASE_URL, SUPABASE_ANON_KEY 자리표시자를 두고,
    반드시 anon(공개, sb_publishable_...) 키만 쓰도록 안내 주석을 달아 줘.
    service_role(sb_secret_...) 키는 절대 브라우저에 넣지 말라고 경고 주석도 달아 줘.
  - 목록을 select로 불러와 화면(ul)에 그리고, 각 줄 오른쪽에 빨간 [삭제] 버튼을 넣어 줘.
  - schema.sql에는 todos 표 + RLS 켜기 + select/insert 정책을 'if not exists / drop if exists' 형태로
    여러 번 실행해도 안전하게 작성해 줘.

  [제약] 한국어 주석, 영어 변수/함수명. 비전공자가 막힐 만한 곳엔 '무엇을 하는지 + 왜 그렇게 했는지'를 주석으로 달아 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  좋아. 이제 [삭제] 버튼에 실제 삭제 동작을 연결해 줘.

  1) 삭제 버튼을 누르면 deleteTodo(id, text) 함수를 호출하게 해 줘.
  2) deleteTodo 안에서 먼저 confirm("'○○' 할 일을 정말 삭제할까요?")으로 한 번 더 확인하고,
     [취소]를 누르면 서버를 건드리지 말고 그냥 함수를 끝내(early return).
  3) [확인]일 때만 db.from("todos").delete().eq("id", id) 로 그 줄 한 건만 서버에서 지워 줘.
     → .eq("id", id)를 빼면 표 전체가 삭제될 수 있으니 그 위험을 주석으로 꼭 설명해 줘.
  4) 삭제 성공/실패 시 화면에 상태 메시지를 보여 주고, 성공하면 목록을 다시 그려 줘.
  5) schema.sql에 'delete 정책'(for delete, to anon/authenticated, using (true))을 추가해 줘 —
     이 정책이 없으면 RLS에 막혀 삭제가 안 된다는 점을 주석으로 알려 줘.

  삭제는 되돌릴 수 없는 동작이라는 점을 비전공자에게 한 줄로 설명하는 주석도 넣어 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  삭제 버튼을 눌렀는데 화면에선 사라졌다가 새로고침(F5)하면 다시 나타나.
  Console에 이런 에러가 떴어: (여기에 에러 메시지 그대로 붙여넣기)

  비전공자가 이해하게 한 줄씩 풀어서:
  1) 이 에러가 무슨 뜻인지,
  2) 가장 흔한 원인이 무엇인지(예: delete 정책 누락, .eq 누락, anon 키 오타),
  3) 어디를(schema.sql인지 script.js인지) 어떻게 고쳐야 하는지,
  4) 고친 뒤 제대로 됐는지 확인하는 방법
  순서대로 알려 줘. 코드를 고쳐 줄 땐 왜 그렇게 고쳤는지 주석으로 설명해 줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 훨씬 좋습니다.

## 검증법

- **확인창(실수 방지):** [삭제]를 누르면 `confirm`이 뜨는가? **[취소]를 누르면 아무 것도 안 지워지고** 목록 그대로인가?
- **삭제 동작:** [확인]을 누르면 그 줄만 사라지고 `✅ 삭제했어요!` 가 뜨는가? Console에 `✅ 삭제 완료: { id, text }` 로그가 찍히는가?
- **서버 반영(이번 실습의 핵심):** 삭제한 뒤 **새로고침(F5)** 해도 그 할 일이 다시 나타나지 않는가? (다시 나타나면 화면에서만 지워진 것 — RLS 정책 누락 가능성)
- **다른 기기 동기화:** 다른 브라우저·기기에서 열어도 삭제한 할 일이 똑같이 사라져 있는가?
- **서버 확인:** **Table Editor → todos** 에서 삭제한 줄이 표에서 사라졌는가?
- **`eq`의 중요성(딱 한 줄만 삭제):** 한 할 일만 지웠을 때 **다른 할 일은 그대로 남아** 있는가? (모두 함께 사라진다면 코드에서 `.eq("id", id)`가 빠진 것 — 대형 사고)
- **CRUD 완성:** 추가(C)·목록(R)·완료 토글(U)·삭제(D) **네 동작이 모두** 정상 동작하는가?
- **anon 키만 썼는지(중요):** `script.js`의 키가 **`sb_publishable_`(anon)** 로 시작하는가? **`sb_secret_`(service_role)** 가 **아닌가?**
- **자주 나는 에러 (Console에서 확인):**
  - `... violates row-level security` 또는 삭제를 눌렀는데 새로고침 시 **다시 나타남** → **`delete` 정책이 없음.** `schema.sql`의 **5단계**를 실행.
  - `relation "public.todos" does not exist` → 표가 없음. `schema.sql` **1단계**부터 실행.
  - `Invalid API key` → anon 키 오타. / `Failed to fetch` → `SUPABASE_URL` 철자·`https://` 확인.
  - `아직 내 프로젝트 값이 입력되지 않았어요` → **2단계**에서 자리표시자를 안 바꿈.
