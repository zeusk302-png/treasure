# 186 — robots.txt 손으로 만들어 올리기

검색엔진(구글·네이버 같은 곳)은 **"크롤러"** 라는 자동 로봇을 보내 내 사이트를 돌아다니며 페이지를 읽어 갑니다.
`robots.txt`는 그 로봇에게 거는 **안내문**입니다. "여기는 봐도 돼(Allow), 여기는 보지 마(Disallow)" 하고 알려 줍니다.

이번 실습에서는 이 파일을 **손으로 직접 만들어** 사이트 루트(맨 앞 주소)에 올려 봅니다.
그리고 가장 사고가 많은 실수 한 가지 — **운영 중인 사이트에 `Disallow: /`(전면 차단)가 남아 검색에서 통째로 사라지는 일** — 을 점검하는 법을 익힙니다.

- 카테고리: SEO·성능·접근성 (코드 I)
- 난이도: 2 / 5
- 개념: robots.txt, 크롤러 허용/차단
- 결과물: 사이트 루트에 배치된 **`robots.txt` 파일** (이 폴더의 `robots.txt`가 올릴 파일입니다)

> 이 폴더 안의 **`robots.txt`** 가 바로 올릴 파일입니다. 그대로 쓰거나, 내 사이트에 맞게 주소만 바꿔 올리면 됩니다.

---

## 목표

`robots.txt`의 핵심은 단어 두 개뿐입니다. 이것만 정확히 구분하면 됩니다.

- **Allow (허용)** — "이 경로는 검색 로봇이 **봐도 된다**."
- **Disallow (차단)** — "이 경로는 검색 로봇이 **보지 마라**."

그리고 누구에게 하는 말인지 정하는 한 줄이 더 있습니다.

- **User-agent: \*** — "별표(\*)는 **모든 크롤러**에게 하는 말"이라는 뜻입니다.

여기서 딱 한 가지 위험한 표현을 반드시 외워 둡니다.

| 적은 내용 | 뜻 | 결과 |
|---|---|---|
| `Disallow:` (뒤에 아무것도 없음) | "막을 게 없다" | 전체 **허용** (안전) |
| `Disallow: /admin/` | "/admin/ 폴더만 막아" | 그 폴더만 차단 (정상) |
| **`Disallow: /`** | **"슬래시 하나 = 사이트 전체를 막아"** | **사이트 전체가 검색에서 사라짐 (위험!)** |

> 비유: `robots.txt`는 가게 입구에 붙이는 **"여긴 들어오세요 / 여긴 직원 전용"** 안내판입니다.
> 그런데 실수로 **"전 구역 출입 금지"(`Disallow: /`)** 안내판을 붙여 두면, 손님(검색엔진)이 가게 전체에 못 들어와
> 검색 결과에 우리 사이트가 **하나도 안 뜨게** 됩니다.

이런 `Disallow: /`는 보통 **개발/준비 중일 때** 일부러 막아 두려고 적습니다.
문제는 **사이트를 진짜로 공개(운영)한 뒤에도 이 줄을 지우는 걸 깜빡**하는 것입니다.
그래서 이번 목표는 ① 올바른 `robots.txt`를 만들고 ② 운영 사이트에 전면 차단이 **남아 있지 않은지 점검**하는 것까지입니다.

> 보안 메모: `robots.txt`는 **누구나 열어 볼 수 있는 공개 파일**입니다 (`내사이트.com/robots.txt`로 바로 보입니다).
> 그러니 여기에 **비밀번호, API 키, 진짜 관리자 경로 같은 비밀값을 적지 마세요.**
> 또한 `Disallow`는 **"예의 바른 로봇에게 하는 부탁"** 일 뿐, 비밀번호처럼 강제로 막는 잠금장치가 **아닙니다.**
> "남에게 안 보이게 진짜로 숨기고 싶은 페이지"는 `robots.txt`가 아니라 **로그인/권한(예: Supabase RLS)** 으로 막아야 합니다.

## 따라하는 단계

### 1단계 — 이 폴더의 robots.txt 열어 보기

1. 이 폴더(`examples/186/`)의 **`robots.txt`** 를 메모장이나 VS Code로 엽니다.
2. 줄을 천천히 읽어 봅니다. `#`으로 시작하는 줄은 **설명(주석)** 이라 로봇은 무시합니다. 사람이 읽으라고 적어 둔 것입니다.
3. 실제로 동작하는 핵심 4줄은 이것뿐입니다.
   - `User-agent: *` → 모든 크롤러에게
   - `Allow: /` → 전체를 봐도 된다
   - `Disallow: /admin/` 등 → 단, 이 폴더들만 보지 마라
   - `Sitemap: ...` → 사이트 지도 위치 안내(있을 때만)

### 2단계 — 내 사이트에 맞게 고치기

1. **막고 싶은 폴더가 있나요?** 관리자 페이지(`/admin/`)나 임시 폴더(`/tmp/`)가 있으면 `Disallow:` 줄로 적고, 없으면 그 줄들을 지웁니다.
2. **사이트 전체를 검색에 노출하고 싶다면(대부분 이 경우)** `Allow: /` 만 두고 `Disallow:` 차단 줄을 모두 지우거나, 막을 폴더만 남깁니다.
3. **`Sitemap:` 줄의 주소를 내 사이트 주소로 바꿉니다.** 사이트 지도(`sitemap.xml`)가 아직 없다면 그 줄은 통째로 지워도 됩니다.
4. **절대 하지 말 것:** 공개할 사이트인데 `Disallow: /` 한 줄을 남겨 두는 것. (이것이 이번 실습의 핵심 함정입니다.)

> 파일 이름은 반드시 소문자 **`robots.txt`** 입니다. `Robots.txt`, `robot.txt`(s 빠짐)는 인식되지 않습니다.

### 3단계 — 사이트 "루트"에 올리기

`robots.txt`는 반드시 사이트 맨 앞 주소(루트)에 있어야 합니다. 즉 `내사이트.com/robots.txt`로 열려야 합니다. 쓰는 도구에 따라 위치만 다릅니다.

- **Vercel / 정적 사이트:** 프로젝트의 **`public/` 폴더**에 `robots.txt`를 넣고 평소처럼 배포(push)합니다. `public` 안에 둔 파일은 자동으로 루트(`/robots.txt`)로 올라갑니다.
- **GitHub Pages:** 저장소 **맨 위(루트)** 에 `robots.txt`를 올립니다. (`index.html`과 같은 위치)
- **직접 서버:** 웹 루트 폴더(보통 `index.html`이 있는 곳)에 그대로 둡니다.

> 하위 폴더(예: `/docs/robots.txt`)에 두면 검색엔진이 **읽지 않습니다.** 꼭 맨 앞 주소에서 열려야 합니다.

### 4단계 — 브라우저로 직접 확인하기

1. 배포가 끝나면 주소창에 **`https://내사이트.com/robots.txt`** 를 직접 입력해 엽니다.
2. 방금 적은 내용이 그대로 텍스트로 보이면 올라간 것입니다.

## 🤖 바이브코딩 프롬프트

이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. `내사이트.com`은 내 실제 주소로 바꿔서 넣으세요.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 SEO를 도와주는 웹 도우미야. 정적 사이트(Vercel 배포)에 올릴 robots.txt 파일을
  처음부터 만들어 줘.

  요구사항:
  - 모든 크롤러(User-agent: *)에게 사이트 전체(/)를 허용(Allow)할 것.
  - 관리자 폴더 /admin/ 과 임시 폴더 /tmp/ 만 Disallow로 막을 것.
  - 사이트맵 위치는 https://내사이트.com/sitemap.xml 로 적을 것.
  - 절대 단독 'Disallow: /' (사이트 전체 차단) 줄을 넣지 말 것 — 검색에서 통째로 사라지니까.
  - 파일 맨 위에 "이 파일이 무엇이고 어디(루트)에 둬야 하는지" 설명 주석을 달 것.

  코드만 주지 말고, 각 줄이 무슨 뜻이고 왜 그렇게 적었는지 비전공자가 이해하게 주석으로 풀어 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 robots.txt를 개선해 줘.
  - /private/ 폴더도 차단 목록에 추가해 줘.
  - "개발 중일 때는 전체를 막고(Disallow: /), 운영(공개) 때는 허용"으로 환경에 따라 다르게
    써야 하는 이유를 주석으로 설명해 줘. 단, 지금 파일에는 공개용(허용) 버전을 남겨 줘.
  - 이 파일을 Vercel 프로젝트에서 정확히 어느 폴더에 둬야 /robots.txt 주소로 열리는지도
    알려 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  내 사이트가 며칠 전부터 구글 검색 결과에 하나도 안 떠. robots.txt 문제인 것 같아.
  내 robots.txt 내용은 아래와 같아:

  (여기에 robots.txt 전체 내용을 붙여넣기)

  이 파일에서 사이트 전체가 검색에서 사라지게 만드는 위험한 줄이 있는지 한 줄씩 점검해 주고,
  있으면 무엇을 어떻게 고쳐야 하는지, 그리고 robots.txt 파일이 루트(/robots.txt)에 제대로
  올라갔는지 확인하는 방법까지 단계별로 알려 줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법

아래가 모두 맞으면 성공입니다.

- **파일이 열린다:** `내사이트.com/robots.txt` 주소에 들어가면 텍스트 내용이 그대로 보인다. (404 페이지가 뜨면 위치가 루트가 아니거나 파일 이름이 틀린 것.)
- **전면 차단이 없다(가장 중요):** 운영(공개) 사이트라면, 파일 안에 단독으로 **`Disallow: /`** 줄이 **없어야** 합니다.
  - 빠른 점검: 파일을 열어 `Disallow:` 뒤에 **슬래시 하나만** (`/`) 있는 줄이 있는지 눈으로 찾습니다. 있으면 즉시 지워야 합니다.
- **구글 도구로 점검(추천):** Google Search Console의 **robots.txt 테스터/리포트**나, "내 사이트 주소 + robots.txt 점검"으로 검사하면 "이 페이지를 막고 있는지/허용하는지"를 확인할 수 있습니다.
- **막아야 할 곳만 막혔다:** `/admin/`처럼 일부러 막은 경로만 차단되고, 일반 페이지(`/`, `/about` 등)는 허용으로 나온다.

> 흔한 실수
> - **개발 때 넣은 `Disallow: /`를 안 지움:** 사이트는 멀쩡한데 며칠 뒤 검색에서 통째로 사라집니다. 공개 전/직후 **반드시** 이 줄을 확인하세요. (이번 실습이 막으려는 바로 그 사고입니다.)
> - **위치가 루트가 아님:** `/folder/robots.txt`에 두면 무시됩니다. Vercel은 `public/`에, GitHub Pages는 저장소 루트에 둡니다.
> - **`robots.txt`로 비밀을 숨기려 함:** `Disallow`는 부탁일 뿐 잠금이 아닙니다. 게다가 막은 경로가 파일에 그대로 적혀 "여기 뭔가 있다"고 광고하는 꼴이 됩니다. 진짜 비밀은 **로그인/권한(RLS)** 으로 막으세요.
> - **이름 오타:** 반드시 소문자 `robots.txt`. 다른 이름은 인식되지 않습니다.
