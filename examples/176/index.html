브랜치 만들어 미리보기(Preview) 배포 URL 받기

라이브(Production)는 그대로 두고, 새 브랜치 전용 임시 주소(Preview URL)에서 먼저 확인하는 연습입니다. 실제 Git/Vercel 화면을 흉내 낸 연습판이라 설치 없이 더블클릭으로 동작합니다.

1) 지금 어떤 주소들이 살아 있나요?

같은 프로젝트라도 브랜치마다 주소가 따로 생깁니다. Production 주소는 항상 한 개로 고정, Preview 주소는 브랜치(또는 PR)마다 하나씩 생겼다 사라집니다.

Production

브랜치: main

https://my-site.vercel.app

진짜 손님이 보는 라이브 화면. 이번 실습에서 절대 안 건드립니다.

Preview

브랜치: feature/new-hero

https://my-site-git-feature-new-hero-myname.vercel.app

새 브랜치 전용 임시 주소. 여기서 마음껏 실험해도 라이브엔 영향이 없습니다.

Preview 없음

아직 새 브랜치를 push하지 않아 Preview 주소가 없습니다. 아래 단계를 진행해 보세요.

2) 따라하기 — 명령을 순서대로 실행해 보세요

아래 버튼은 실제 터미널/Git/Vercel에서 일어나는 일을 흉내 냅니다. 위에서부터 차례로 눌러 보세요.

  1. git checkout -b feature/new-hero

    main에서 갈라져 나온 새 작업 가지(브랜치)를 만들고 그쪽으로 이동합니다.

  2. git commit -am "히어로 문구 변경"

    바꾼 내용을 이 브랜치에 기록합니다. (main에는 아직 아무 영향 없음)

  3. git push -u origin feature/new-hero

    브랜치를 GitHub에 올립니다. → Vercel이 이 push를 감지해 Preview 배포를 자동으로 시작합니다.

  4. Vercel: Building & Deploying Preview…

    Vercel이 브랜치를 빌드해 이 브랜치 전용 Preview URL을 발급합니다.

$ # 위 단계를 순서대로 실행하면 여기에 로그가 나옵니다

3) 결과물 — main과 분리된 Preview URL

이번 실습의 결과물(Deliverable)

  • Production(main): https://my-site.vercel.app — 그대로, 변화 없음
  • Preview(브랜치): 위 임시 주소 — 새 변경이 여기에만 반영됨

두 주소를 각각 열어 보면 내용이 다르다는 것이 핵심입니다. 라이브를 건드리지 않고도 "바뀐 화면"을 임시 주소에서 먼저 확인할 수 있습니다.
