# 404 라우팅 고치기 — 새로고침하면 사라지는 페이지와 깨진 내부 링크

여러 페이지(홈·소개·문의)로 이루어진 작은 정적 사이트입니다. 그런데 **메뉴 링크를 누르면 "이 페이지를 찾을 수 없습니다(404)"** 가 뜨고, 게다가 **홈 화면은 스타일이 하나도 안 입혀진 민무늬 상태**로 보입니다.
원인은 코드의 로직이 아니라 **주소(URL)와 실제 파일 이름·위치가 서로 안 맞기 때문**입니다. 비전공자가 배포(Vercel 등) 직후 가장 많이 겪는 "내 컴퓨터에선 됐는데 올리니까 404" 문제의 축소판입니다.

- `broken.html` : 일부러 깨뜨린 홈 페이지 (3가지 경로 버그)
- `index.html` : 고친 홈 페이지 (정답)
- `about.html` / `contact.html` : 정상 동작하는 소개·문의 페이지
- `style.css` : 세 페이지가 공유하는 스타일

## 목표

- **URL(주소)은 결국 "파일을 찾아가는 길"** 이라는 것을 이해한다. 길(href)이 실제 파일 이름·위치와 한 글자라도 다르면 404가 난다.
- **상대경로 `style.css` 와 절대경로 `/style.css` 의 차이**를 안다. `/`로 시작하면 "사이트 맨 꼭대기(루트)부터"라는 뜻이라, 파일이 거기 없으면 깨진다.
- **배포 서버는 파일 이름의 대소문자를 구분한다**는 사실을 안다. (`About.html` ≠ `about.html`) 내 윈도우 컴퓨터에서는 우연히 열려도, 배포하면 404가 날 수 있다.
- 버그를 추측으로 고치지 않고, **F12 → Network 탭에서 "무슨 파일을 못 찾았는지" 빨간 줄로 직접 확인**한 뒤 그 이름에 맞춰 고치는 습관을 들인다.

## 따라하는 단계

1. **고장 난 화면부터 본다.** `broken.html`을 더블클릭해 브라우저로 엽니다.
   - 글자만 덩그러니 있고 색·여백이 하나도 없습니다. (스타일이 안 먹은 상태)
   - 위 메뉴의 "소개" / "문의"를 누르면 **404(페이지를 찾을 수 없음)** 가 뜹니다. → **이 화면이 "before(고치기 전)" 캡처입니다.**
2. **무엇을 못 찾았는지 눈으로 확인한다.** `F12`(또는 우클릭 → 검사) → **Network(네트워크)** 탭을 연 뒤 새로고침합니다.
   - `style.css` 가 빨간색(404 또는 못 찾음)으로 보입니다 → ❌문제1.
   - "소개" 링크를 눌러 보면 `About.html` 요청이 404로 찍힙니다 → ❌문제2.
   - "문의" 링크를 눌러 보면 `contect.html` 요청이 404로 찍힙니다 → ❌문제3.
3. **깨진 경로 3곳을 찾아낸다.** `broken.html`을 코드로 열어 보면 세 군데가 문제입니다. (아래 "깨졌던 경로 목록" 표 참고)
4. **주소를 실제 파일 이름·위치에 맞춘다.** 이 폴더의 `index.html`이 정답 버전입니다. 딱 세 가지만 바뀌었습니다.
   - `href="/style.css"` → `href="style.css"` ( 맨 앞 `/` 를 떼서 "같은 폴더의 파일"로 )
   - `href="About.html"` → `href="about.html"` ( 대문자 A → 소문자 a, 실제 파일명과 일치 )
   - `href="contect.html"` → `href="contact.html"` ( 오타 수정, 실제 파일명과 일치 )
   - 본문 안내 링크(`<ul>` 안)도 같은 이유로 똑같이 고칩니다.
5. **고친 화면을 확인한다.** `index.html`을 브라우저로 엽니다. 파란 포인트 색과 여백이 입혀진 화면이 나오고, "소개"·"문의"를 누르면 페이지가 정상으로 열리며, 각 페이지에서 "홈"을 누르면 다시 돌아옵니다. → **이 화면이 "after(고친 후)" 캡처입니다.**

## 깨졌던 경로 목록 (before → after)

| 위치 | 고치기 전 (`broken.html`) | 고친 후 (`index.html`) | 왜 404/깨짐이었나 |
| --- | --- | --- | --- |
| CSS 연결 | `href="/style.css"` | `href="style.css"` | 맨 앞 `/`는 "사이트 루트부터"라는 뜻. 파일은 같은 폴더에 있으므로 `/`를 떼야 찾는다 |
| 소개 링크 | `href="About.html"` | `href="about.html"` | 실제 파일은 소문자 `about.html`. 배포 서버는 대소문자를 구분해 `About.html`을 못 찾음 |
| 문의 링크 | `href="contect.html"` | `href="contact.html"` | `contect`는 오타. 그런 파일이 없어서 404 |

핵심은 코드를 새로 짠 게 아니라, **가리키는 주소(href)를 실제 파일의 진짜 이름·위치에 한 글자까지 똑같이 맞춘 것**뿐입니다.

### "새로고침하면 사라지는 페이지"는 왜 그럴까 (한 걸음 더)

- 이 실습처럼 **여러 개의 .html 파일**로 만든 사이트는, 각 주소가 곧 실제 파일이라 새로고침해도 그 파일을 다시 찾으면 됩니다. 즉, **파일과 주소만 맞으면 새로고침해도 멀쩡합니다.**
- 반면 React 같은 도구로 만든 **SPA(한 개의 index.html로 화면을 갈아끼우는 방식)** 사이트는, `/about` 같은 주소가 실제 파일이 아니라 자바스크립트가 그려 주는 "가짜 경로"입니다. 그래서 그 주소에서 **새로고침하면 서버가 `/about`이라는 파일을 진짜로 찾으려다 404**가 납니다.
- 이때는 "어떤 주소로 와도 일단 index.html을 돌려줘"라고 서버에 알려 줘야 합니다. Vercel에서는 프로젝트 루트에 `vercel.json`을 두고 아래처럼 적습니다. (비밀값이 아니므로 그대로 써도 됩니다.)

```json
{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}
```

- 정리: **다중 .html 사이트의 404 = 파일 이름/경로가 안 맞음** (이 실습에서 고친 것), **SPA의 새로고침 404 = 서버에 "전부 index.html로 보내" 설정이 빠짐** (위 `vercel.json`으로 해결).

## 🤖 바이브코딩 프롬프트

이 실습(여러 .html 페이지 + 공유 CSS, 그리고 일부러 깨뜨린 404 버그 잡기)을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 HTML/CSS를 가르치는 웹 강사야. 비전공자도 따라할 수 있게 만들어 줘.
  목표: "부산 산책 모임"이라는 작은 정적 사이트를 만든다. 페이지는 index.html(홈),
  about.html(소개), contact.html(문의) 세 개이고, 세 페이지가 style.css 하나를 공유한다.

  제약(중요):
  - CSS 연결과 페이지 사이 링크는 전부 "상대경로"로 쓴다. href="style.css", href="about.html"처럼
    맨 앞에 / 를 붙이지 않는다. (왜 / 를 떼는지 주석으로 설명해 줘)
  - 파일 이름은 전부 소문자로 통일한다(About.html 같은 대문자 금지). 배포 서버는 대소문자를 구분하니까.
  - 모든 페이지 상단에 홈/소개/문의 네비게이션을 똑같이 넣어, 어디서든 서로 오갈 수 있게 한다.

  산출물: index.html, about.html, contact.html, style.css 전체 코드.
  각 파일 맨 위에 "이 파일이 무엇이고 왜 있는지" 한국어 요약 주석을 달아 줘.
  ```

- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  좋아. 이제 학습용으로 "일부러 깨뜨린" 홈 페이지 broken.html 을 하나 더 만들어 줘.
  목적: 비전공자가 배포 직후 가장 많이 겪는 404 버그 3종을 직접 눈으로 보고 고치는 연습.

  broken.html 에는 아래 3가지 버그를 의도적으로 심고, 각 줄에 "왜 이게 404/깨짐인지"를
  한국어 주석(<!-- -->)으로 설명해 줘:
  1) CSS를 절대경로로 연결: href="/style.css" (맨 앞 / 때문에 파일을 못 찾아 민무늬가 됨)
  2) 소개 링크를 대문자로: href="About.html" (실제 파일은 about.html → 대소문자 불일치로 404)
  3) 문의 링크에 오타: href="contect.html" (그런 파일이 없어서 404)

  그리고 README에 "깨졌던 경로 목록(before → after)" 표와, F12 Network 탭에서
  빨간 줄(404)로 원인을 확인하는 검증 절차를 정리해 줘.
  ```

- **막혔을 때(디버깅)** 프롬프트:
  ```text
  내 사이트를 Vercel에 배포했더니 "내 컴퓨터에선 됐는데" 올리니까 페이지가 404가 나고
  스타일도 안 먹어. F12 → Network 탭을 새로고침하면 style.css 와 about 페이지가 빨간색(404)으로 떠.
  아래 내 코드를 보고, 어떤 href가 실제 파일 이름·위치와 안 맞는지 한 줄씩 짚어 줘.
  특히 (1) 맨 앞 / 로 시작하는 절대경로, (2) 대소문자 불일치, (3) 파일명 오타 세 가지를 우선 의심해 줘.
  고치는 이유도 같이 설명해 줘. (여기에 내 html 코드 붙여넣기)
  ```

> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 훨씬 좋습니다.

## 검증법

1. `index.html`을 브라우저로 열었을 때 파란색 포인트와 여백이 입혀진 화면이 나오면 ❌문제1 해결입니다. (민무늬가 아니어야 함)
2. 상단 메뉴 "소개" → "문의" → "홈" 순서로 눌러 봅니다. **세 페이지가 전부 404 없이 열리고**, 각 페이지에서 "홈"으로 다시 돌아올 수 있으면 ❌문제2·3 해결입니다.
3. `F12` → **Network** 탭에서 새로고침했을 때, 빨간색(404) 줄이 **하나도 없으면** 정상입니다. `style.css`가 200(정상)으로 찍혀야 합니다.
4. 비교 학습: `broken.html`은 민무늬로 뜨고, 링크를 누르면 404가 나야 합니다. 2단계의 **before(깨진) 화면**과, 고친 뒤 **after(정상 이동) 화면**을 각각 캡처하면 제출물(모든 페이지가 정상 열리는 사이트 + 깨졌던 경로 목록)이 완성됩니다.
