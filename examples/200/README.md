# 공개 API를 HTTP Request 노드로 호출해 결과 받기

앞 실습(199)에서 웹훅은 **외부가 나를 찾아오는** 방식이었습니다. 이번에는 반대로, **내가 외부로 요청을 보내는** 방식을 배웁니다. n8n의 **HTTP Request 노드**가 바로 "다른 인터넷 서비스에 전화를 걸어 정보를 받아오는" 도구입니다.

이 실습에서는 가입도, 비밀 키도 필요 없는 **공개 날씨 API**(Open-Meteo)에 전화를 걸어, 돌아온 응답(JSON) 더미에서 **오늘 부산의 기온 하나**만 깔끔하게 꺼내 봅니다.

> **API를 한마디로:** 다른 서비스가 "이 주소로 이렇게 물어보면, 이런 형식으로 답을 줄게" 라고 공개해 둔 **자판기**입니다. 정해진 버튼(주소+조건)을 누르면, 정해진 형식(JSON)으로 답이 툭 떨어집니다.
>
> **JSON을 한마디로:** `{ "이름": "값" }` 모양으로 정리된 **데이터 상자**입니다. 상자 안에 또 상자가 들어 있을 수 있어서, `상자.작은상자.값` 처럼 점(.)을 찍어 안쪽으로 들어가 원하는 값을 꺼냅니다.

## 목표

- **HTTP Request 노드**로 공개 API에 요청을 보내고, 응답이 JSON으로 돌아오는 것을 눈으로 확인한다.
- 돌아온 JSON 더미 속에서 **내가 원하는 값 하나(오늘 기온)** 가 어디에 들어 있는지 경로를 찾는다.
- **Set 노드**로 그 값만 꺼내 `현재기온`처럼 이름을 붙여 보기 좋게 정리한다.

> 이 워크플로우는 노드 3개입니다.
> `시작 (Manual Trigger)` → `날씨 API 호출 (HTTP Request)` → `필요한 값만 추리기 (Set)`
> 1번은 "지금 한 번 돌려라" 버튼, 2번이 외부 API에 전화를 걸어 답을 받고, 3번이 답 더미에서 핵심 값만 추려 냅니다.

## 따라하는 단계

1. **n8n에 로그인**합니다. (n8n Cloud 가입형 또는 직접 설치한 n8n 모두 가능)
2. 화면 오른쪽 위 **`...`(점 3개) → `Import from File`** 을 눌러 이 폴더의 **`workflow.json`** 파일을 불러옵니다. 노드 3개가 한 줄로 연결되어 나타납니다.
3. **`날씨 API 호출 (HTTP Request)` 노드를 더블클릭**해서 안을 살펴봅니다.
   - **`URL`**: `https://api.open-meteo.com/v1/forecast` — 날씨 자판기의 주소입니다.
   - **`Query Parameters`(질의 조건)**: 자판기에 누르는 버튼입니다. `latitude`(위도)와 `longitude`(경도)로 "부산 위치"를, `current=temperature_2m`로 "지금 기온을 달라"고 요청합니다.
   - 인증(Authentication)은 `None`입니다. 이 API는 누구나 무료로 호출할 수 있는 공개 API라 비밀 키가 필요 없습니다.
4. 노드 화면 안에서 **`Test step`(이 단계만 실행)** 버튼을 눌러 봅니다. 오른쪽 `OUTPUT` 패널에 날씨 API가 돌려준 **JSON 응답**이 통째로 나타납니다.
5. `OUTPUT` 패널에서 응답 구조를 살펴봅니다. `current`라는 상자 안에 `temperature_2m`(기온)이 들어 있습니다. 그래서 기온을 꺼내는 경로는 **`current.temperature_2m`** 입니다.
6. 캔버스로 돌아와 화면 위 가운데 **`Test workflow`(전체 실행)** 버튼을 눌러 처음부터 끝까지 한 번 돌립니다.
7. **`필요한 값만 추리기 (Set)` 노드를 클릭**합니다. `OUTPUT`에 `도시`, `현재기온`, `단위`, `측정시각` 네 항목만 깔끔하게 정리되어 있으면 성공입니다.

## 🤖 바이브코딩 프롬프트

이 실습을 AI(클로드 등)에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. n8n 워크플로우는 결국 JSON 파일이라, AI에게 "이런 워크플로우 JSON을 만들어 달라"고 시킬 수 있습니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  당신은 n8n 자동화 전문가입니다. n8n에 그대로 Import 할 수 있는 워크플로우 JSON을 만들어 주세요.
  목표: 공개 날씨 API(Open-Meteo)에 요청을 보내 부산의 현재 기온을 받아오기.
  구성: 노드 3개를 한 줄로 연결.
    1) Manual Trigger (수동 실행 버튼)
    2) HTTP Request 노드 — URL은 https://api.open-meteo.com/v1/forecast,
       Query Parameters로 latitude=35.18, longitude=129.08, current=temperature_2m,
       인증(Authentication)은 None (이 API는 비밀 키가 필요 없는 공개 API라서).
    3) Set 노드 — 일단은 비워 두기.
  제약: 비전공자가 읽을 수 있게 노드 이름은 한국어로 지어 주세요.
  산출물: workflow.json 전체 내용만 코드블록으로 주세요.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  위 워크플로우의 Set 노드를 채워 주세요.
  HTTP Request 응답 JSON은 current 상자 안에 temperature_2m(기온)과 time(측정시각)이 있고,
  current_units 상자 안에 temperature_2m(단위, 예: °C)이 들어 있습니다.
  Set 노드에서 아래 네 항목만 한국어 이름으로 깔끔하게 정리해 주세요.
    - 도시: "부산 (위도 35.18, 경도 129.08)" (고정 문자열)
    - 현재기온: 응답의 current.temperature_2m (숫자)
    - 단위: 응답의 current_units.temperature_2m (문자열)
    - 측정시각: 응답의 current.time (문자열)
  n8n 표현식 문법({{ $json.경로 }})을 사용하고, 각 값의 경로를 왜 그렇게 잡았는지도 알려 주세요.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  n8n에서 위 워크플로우를 실행했는데 Set 노드의 '현재기온'이 비어 있습니다(또는 오류가 납니다).
  HTTP Request 노드의 OUTPUT(JSON 응답)은 아래와 같습니다:
  (여기에 OUTPUT 패널의 JSON을 그대로 붙여넣기)
  무엇이 문제인지 단계별로 짚어 주세요.
  특히 제가 쓴 경로( {{ $json.current.temperature_2m }} )가 실제 응답 구조와 맞는지,
  Query Parameter(current=temperature_2m)를 빠뜨리거나 오타 내지 않았는지 확인해 주세요.
  ```
> 프롬프트 팁: "코드(JSON)만 주지 말고 각 노드를 왜 그렇게 설정했는지, 값의 경로를 왜 그렇게 잡았는지 주석처럼 한 줄씩 풀어서 설명해줘"를 덧붙이면, 단순히 복붙하는 데서 그치지 않고 'API 응답에서 값 꺼내는 원리'를 배울 수 있습니다.

## 검증법

1. 4단계에서 HTTP Request 노드의 `OUTPUT`에 JSON이 나타나고, 그 안에 `current` 상자와 `temperature_2m` 값이 보이면 호출 성공입니다. 대략 이런 모양입니다.
   ```json
   {
     "latitude": 35.18,
     "longitude": 129.08,
     "current_units": { "time": "iso8601", "temperature_2m": "°C" },
     "current": { "time": "2026-06-18T14:00", "temperature_2m": 24.3 }
   }
   ```
2. 마지막 Set 노드의 `OUTPUT`이 아래처럼 **딱 네 항목**으로 정리되어 있으면 추출 성공입니다. (기온 숫자와 시각은 실행 시점에 따라 달라집니다.)
   ```json
   {
     "도시": "부산 (위도 35.18, 경도 129.08)",
     "현재기온": 24.3,
     "단위": "°C",
     "측정시각": "2026-06-18T14:00"
   }
   ```
3. 세 노드 모두에 **초록색 체크 표시**가 떴는지 확인합니다.
4. **다른 도시로 바꿔 보기:** HTTP Request 노드에서 `latitude`를 `37.57`, `longitude`를 `126.98`로 바꾸면 **서울** 기온을 받아옵니다. 값이 바뀌면 "내가 보낸 조건에 따라 답이 달라진다"는 API의 핵심을 체감한 것입니다.
5. **실패 케이스 점검:** `current=temperature_2m`를 일부러 `current=없는항목`으로 바꿔 다시 실행해 봅니다. `current` 상자가 비어, Set 노드의 `현재기온`이 비거나 오류가 납니다. **요청 조건(질의)이 응답 내용을 결정한다**는 것을 확인할 수 있습니다. (확인 후 원래대로 되돌리세요.)

## 핵심만 짚기 (디렉터 관점)

- **웹훅 vs HTTP Request:** 웹훅은 "남이 나를 부르면" 깨어나는 **받는 쪽**, HTTP Request는 "내가 남을 부르는" **거는 쪽**입니다. 자동화는 이 둘을 엮어, "무슨 일이 생기면(웹훅) → 외부 정보를 가져와(HTTP) → 처리한다" 흐름을 만듭니다.
- **응답은 JSON이라는 '상자 안의 상자'로 옵니다.** 원하는 값을 꺼내려면 그 값이 들어 있는 경로를 점(.)으로 따라가야 합니다. 여기선 `current` 상자 안의 `temperature_2m`이라 `{{ $json.current.temperature_2m }}`로 꺼냈습니다.
- **Set 노드로 '핵심만 추리기'를 꼭 거치세요.** API 응답은 보통 안 쓰는 정보까지 잔뜩 딸려 옵니다. 다음 단계(메일 보내기, 시트에 적기 등)가 헷갈리지 않도록, 필요한 값에 한국어 이름을 붙여 미리 정리해 두는 습관이 중요합니다.

## 보안, 비밀값은 어떻게 다루나

- 이 실습의 Open-Meteo는 **인증이 없는 완전 공개 API**라 비밀 키가 없습니다. 그래서 `workflow.json`을 그대로 공유해도 안전합니다.
- 하지만 대부분의 실무 API(날씨 유료 플랜, 환율, 챗봇 등)는 **API 키**를 요구합니다. 이때 절대로 키를 URL이나 노드 값에 직접 적지 마세요.
  - 올바른 방법: n8n의 **`Credentials`(자격증명) 금고**에 키를 저장하고, HTTP Request 노드의 `Authentication`에서 그 자격증명을 골라 씁니다. 그러면 키는 금고에만 있고 `workflow.json`에는 남지 않습니다.
  - 파일에 예시로 적어야 할 때는 실제 값 대신 **자리표시자**(예: `YOUR_API_KEY`)만 둡니다 — 이 파일을 남에게 줘도 비밀이 새지 않습니다.
- 한 줄 원칙: **공개해도 되는 값(공개 주소, 위도/경도)은 노드에, 새면 안 되는 값(API 키, 토큰)은 자격증명 금고에.**
