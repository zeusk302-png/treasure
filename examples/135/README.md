# 실습 135 — 로그인 상태에 따라 헤더 바뀌게 하기 (실시간 감지)

`onAuthStateChange`로 로그인/로그아웃이 **일어나는 순간**을 감지해, 헤더의 메뉴를 자동으로 바꿉니다. 로그아웃 상태면 **'로그인' 버튼**, 로그인 상태면 **'내 계정 + 로그아웃'**이 보입니다. 새로고침이나 페이지 이동 없이, 상태가 바뀌는 즉시 메뉴가 따라 바뀌는 게 핵심입니다.

이번 실습의 결과물은 어느 페이지에든 붙일 수 있는 **공통 헤더 스크립트(`header.js`)** 입니다.

## 목표
- `db.auth.onAuthStateChange((event, session) => { ... })`가 **로그인/로그아웃 순간마다** 다시 호출된다는 걸 이해한다. (페이지가 처음 열릴 때도 한 번 호출됨)
- "세션이 있으면(=로그인) A 메뉴, 없으면(=로그아웃) B 메뉴"처럼 **상태에 따라 화면(UI)을 갈라 그리는** 패턴을 익힌다.
- 헤더 하나를 **공통 부품**으로 만들어 여러 페이지에서 재사용하는 감각을 잡는다.
- 브라우저에 두는 건 **anon(공개돼도 되는 출입증)** 키뿐이고, `service_role`(절대 숨길 비밀) 키는 두지 않는다는 원칙을 다시 체득한다.

## 따라하는 단계
1. 앞 실습(131·132)에서 만든 **Supabase 프로젝트**와 **테스트 계정**을 그대로 사용한다. (계정이 없으면 Authentication → Users에서 "Auto Confirm User"를 켜고 하나 추가한다.)
2. 대시보드 → **Settings → API**에서 `Project URL`과 `anon`(publishable) 키를 복사한다.
3. `header.js` 위쪽의 `SUPABASE_URL`, `SUPABASE_ANON_KEY` 두 값을 내 값으로 바꾼다.
4. `index.html`을 브라우저로 연다. 처음엔 로그아웃 상태라 헤더에 **'로그인' 버튼**만 보인다.
5. 본문 아래 미니 로그인 박스에 테스트 계정의 이메일·비밀번호를 넣고 **로그인**한다.
6. 새로고침하지 않았는데도 헤더가 **'이메일 + 내 계정 + 로그아웃'** 으로 즉시 바뀌는지 확인한다. (이게 이번 실습의 핵심!)
7. 헤더의 **로그아웃** 버튼을 누른다 → 헤더가 다시 **'로그인' 버튼** 버전으로 자동으로 돌아간다.
8. (선택) 다른 페이지를 만들 때도 `<header id="appHeader"></header>` 한 줄과 `header.js`만 넣으면, 같은 헤더가 그대로 동작한다.

## 검증법
- 로그인하는 순간, 새로고침 없이 헤더가 **'내 계정 + 로그아웃'** 으로 바뀌는가? (← 핵심)
- 로그아웃 버튼을 누르면 헤더가 다시 **'로그인' 버튼**으로 돌아가는가?
- 개발자도구 → **Console**에 로그인 시 `인증 상태 변화: SIGNED_IN`, 로그아웃 시 `SIGNED_OUT`이 찍히는가?
- 로그인한 상태에서 **새로고침(F5)** 해도 헤더가 '내 계정' 버전으로 유지되는가? (세션이 살아 있으므로 onAuthStateChange가 그 세션을 들고 다시 그려줌)

## 핵심 한 줄
로그인/로그아웃이 일어날 때마다 이 콜백이 다시 불려서, 헤더를 항상 최신 상태로 그립니다.
```js
db.auth.onAuthStateChange((event, session) => {
  // session 이 있으면 로그인 메뉴, null 이면 로그아웃 메뉴
  renderHeader(session);
});
```
`getSession`(실습 134)이 "지금 한 번 상태를 읽는" 것이라면, `onAuthStateChange`는 "상태가 바뀔 때마다 계속 알려주는" 구독입니다. 그래서 헤더처럼 **항상 최신이어야 하는 UI**에 잘 맞습니다.

## 보안 메모 — anon vs service_role
- 여기 넣는 건 **anon(publishable) 키** 하나뿐입니다. anon 키는 "공개돼도 되는 **출입증**"이라 브라우저·GitHub에 있어도 괜찮습니다. (코드의 키 값은 `sb_publishable_...` 자리표시자이니 내 값으로 바꿔 쓰세요.)
- `service_role`(secret) 키는 모든 **RLS(행 수준 보안)를 통째로 우회**하는 마스터키라, 브라우저나 깃허브에 두면 안 됩니다. 오직 서버(n8n·엣지 함수)에서 환경변수로만 사용하세요.
- 중요: **헤더가 '로그인' 버전으로 보인다고 보안이 되는 게 아닙니다.** 메뉴를 숨기는 건 그저 화면 꾸미기일 뿐, 누구나 개발자도구로 데이터를 직접 요청할 수 있습니다. "로그인한 사람이 자기 데이터만 만지게" 막는 진짜 보안은 DB의 **RLS 정책**(`auth.uid()` 기반)으로 강제해야 합니다.
