# 168 — GitHub Pages로 정적 사이트를 무료 주소에 띄우기

167번에서 GitHub 저장소에 올린 `index.html`을, 이번에는 **GitHub Pages** 기능을 켜서
`https://내아이디.github.io/저장소이름/` 같은 **진짜 인터넷 주소**로 세상에 공개합니다.
서버를 빌리거나 돈을 내지 않고, 저장소 설정에서 스위치 하나만 켜면 끝납니다.

- 카테고리: 배포·운영·도구 (코드 H)
- 난이도: 1 / 5
- 개념: GitHub Pages, 정적 호스팅
- 결과물: **접속 가능한 `github.io` 라이브 URL** (이 폴더의 `index.html`, `style.css`가 공개될 파일입니다)

> 이 폴더 안의 `index.html`과 `style.css`가 바로 **공개할 파일**입니다.
> 167번에서 이미 파일을 올렸다면 그 파일을 그대로 써도 되고, 이 폴더의 파일로 바꿔 올려도 됩니다.

---

## 목표

지금까지는 내가 만든 페이지를 **내 컴퓨터에서만** 볼 수 있었습니다.
(`index.html`을 더블클릭하면 주소창에 `file:///C:/...` 처럼 뜨는데, 이건 나만 볼 수 있는 주소입니다.)

이번 목표는 그 페이지를 **누구나 접속할 수 있는 공개 주소**로 바꾸는 것입니다.

핵심 단어 세 개만 기억하면 됩니다.

- **정적 사이트(static site)**: HTML/CSS/JS 파일만으로 된, 서버에서 계산할 게 없는 페이지.
  GitHub Pages는 이런 정적 사이트를 **공짜로** 인터넷에 올려 줍니다.
- **호스팅(hosting)**: 내 파일을 항상 켜져 있는 컴퓨터(서버)에 올려 두어, 내 컴퓨터가 꺼져 있어도 남들이 접속할 수 있게 하는 것.
- **배포(deploy)**: 코드를 실제 인터넷 주소로 "내보내서" 공개하는 일. 이번 실습이 바로 첫 배포입니다.

> 비유: 167번이 "내 물건을 GitHub 사물함(저장소)에 넣은 것"이라면,
> 168번은 "그 사물함을 **유리 진열장**으로 바꿔 지나가는 사람 누구나 안을 볼 수 있게" 하는 것입니다.

이 실습에서 다루는 파일은 두 개입니다. **반드시 두 개가 같은 저장소에 함께** 있어야 디자인까지 제대로 보입니다.

- `index.html` — 페이지의 내용(글·구조). **파일 이름은 꼭 `index.html`** 이어야 합니다. (GitHub Pages가 대문 페이지로 자동 인식하는 이름입니다.)
- `style.css` — 페이지의 디자인(색·여백·글꼴)

> 보안 메모: GitHub Pages로 올린 파일은 **소스 코드까지 누구나 볼 수 있게** 공개됩니다.
> 그래서 정적 사이트에는 **비밀번호, API 키, `service_role` 키 같은 비밀값을 절대 넣지 않습니다.**
> 비밀이 필요한 기능(예: Supabase)은 공개해도 되는 **anon(공개) 키**만 프런트엔드에 두고,
> 비밀 키(`service_role`)는 서버/환경변수에만 보관합니다. 이번 페이지에는 비밀값이 전혀 없으니 안심하고 공개해도 됩니다.

---

## 따라하는 단계

### 1단계 — 공개할 파일이 저장소에 있는지 확인하기

1. **https://github.com** 에 로그인하고, 167번에서 만든 저장소(예: `https://github.com/내아이디/my-first-website`)로 들어갑니다.
2. 저장소 첫 화면 파일 목록에 **`index.html`** 이 있는지 확인합니다.
   - 없다면 167번 방식(**Add file → Upload files** → 파일 끌어다 놓기 → **Commit changes**)으로 이 폴더의 `index.html`과 `style.css`를 먼저 올립니다.
   - 디자인까지 보이게 하려면 `style.css`도 **함께** 올려야 합니다.

> 주의: 파일 이름은 반드시 소문자 **`index.html`** 입니다. `Index.html`, `home.html`, `index.htm` 으로 두면 대문 페이지가 안 열립니다.

### 2단계 — 저장소 설정(Settings) 화면 열기

1. 저장소 위쪽 메뉴 줄에서 맨 오른쪽의 **⚙ Settings**(설정)를 누릅니다.
   - Settings가 안 보이면, 그 저장소의 **주인 계정으로 로그인**되어 있는지 확인하세요. (남의 저장소에는 Settings가 안 보입니다.)

### 3단계 — Pages 메뉴로 들어가기

1. 왼쪽 사이드바를 아래로 내려 **Pages**(페이지) 항목을 누릅니다.
   - (또는 주소창에 `https://github.com/내아이디/저장소이름/settings/pages` 를 직접 입력해도 같은 화면이 나옵니다.)

### 4단계 — 배포할 소스(브랜치) 고르기

1. **Build and deployment**(빌드 및 배포) 영역에서 **Source**(소스)를 **`Deploy from a branch`**(브랜치에서 배포)로 둡니다. (기본값입니다.)
2. 그 아래 **Branch**(브랜치) 드롭다운에서 **`main`** 을 선택합니다.
3. 그 옆 폴더 드롭다운은 **`/ (root)`**(루트) 그대로 둡니다.
   - 우리는 `index.html`을 저장소 맨 위(루트)에 올렸기 때문에 `/ (root)`가 맞습니다.
4. 초록색 **Save**(저장) 버튼을 누릅니다.

### 5단계 — 공개 주소(URL) 받고 접속해 보기

1. Save를 누르면 잠시 후 Pages 화면 위쪽에
   **"Your site is live at https://내아이디.github.io/저장소이름/"** 같은 문구와 함께 **공개 주소**가 나타납니다.
   - 처음 배포는 **1~3분 정도** 걸릴 수 있습니다. 안 보이면 페이지를 **새로고침(F5)** 하며 잠깐 기다립니다.
2. 그 주소 옆의 **Visit site**(사이트 방문) 버튼을 누르거나, 주소를 복사해 새 탭에 붙여 넣고 들어갑니다.
3. 내가 만든 카드 페이지("인터넷에 공개됐습니다!")가 디자인까지 입혀진 채로 뜨면 **배포 성공**입니다.

> 이 주소가 바로 이번 실습의 **결과물(라이브 URL)** 입니다. 메모해 두세요.

## 🤖 바이브코딩 프롬프트

이 실습(만든 페이지를 GitHub Pages로 무료 공개)을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 웹 입문자를 돕는 프런트엔드 멘토야.
  GitHub Pages로 공개할 아주 단순한 정적 사이트 한 페이지를 만들어 줘.
  - 파일은 index.html과 style.css 딱 두 개만, 같은 폴더 기준으로.
  - 파일 이름은 반드시 소문자 index.html (GitHub Pages 대문 페이지 규칙).
  - 내용: "인터넷에 공개됐습니다!" 라는 큰 제목 + 한 줄 소개 + 만든 사람/공개한 날 표시.
  - 자바스크립트나 서버 기능은 쓰지 마(정적 사이트라서). 비밀번호·API 키 같은 비밀값도 절대 넣지 마.
  - HTML lang은 "ko", UTF-8 meta, 모바일용 viewport meta를 넣어 줘.
  코드만 주지 말고, 초보가 막힐 만한 줄에 "무엇을 하는지 + 왜 그렇게 했는지"를 한국어 주석으로 달아 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 index.html과 style.css를 GitHub에 올려 Pages로 공개하려고 해.
  1) GitHub 웹사이트에서 새 저장소를 만들고 파일을 올리는 순서를 클릭 단위로 알려 줘(Public으로).
  2) Settings → Pages 에서 Deploy from a branch → main → / (root) 로 켜는 순서를 화면 문구 그대로 짚어 줘.
  3) 공개 주소(https://내아이디.github.io/저장소이름/)가 뜨면 잘 됐는지 확인하는 방법도 알려 줘.
  그리고 style.css에 모바일에서도 잘 보이게 하는 간단한 반응형(작은 화면에서 여백·글자 크기 조정)을 더해 줘.
  바꾼 부분은 왜 그렇게 했는지 주석으로 설명해 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  GitHub Pages로 배포했는데 문제가 생겼어. 아래 증상을 보고 원인 후보를 가능성 높은 순으로 정리하고,
  각각 어디를 어떻게 확인/수정하면 되는지 한 단계씩 알려 줘.
  [증상] 예: "주소로 들어가면 404 — There isn't a GitHub Pages site here. 가 떠"
         또는 "글자는 나오는데 색·여백 디자인이 하나도 안 보여"
  [내 상황] 파일 이름: ____ / 저장소 공개 여부: Public/Private / Pages 설정 브랜치·폴더: ____ / 배포 후 기다린 시간: ____분
  설명은 비전공자가 이해하게 한 줄씩 풀어서 해 줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 결과물을 그냥 받아 쓰는 게 아니라 직접 검증하는 '디렉터'가 될 수 있습니다.

## 검증법

아래가 모두 맞으면 성공입니다.

- **공개 주소 확인**: Settings → Pages 화면에 **"Your site is live at ..."** 와 함께 `내아이디.github.io` 주소가 보인다.
- **접속 확인**: 그 주소를 새 탭(또는 시크릿 창)에 붙여 넣어 들어가면, 카드 페이지가 **디자인까지** 보인다. (글자만 보이고 색·여백이 없다면 `style.css`가 같이 안 올라간 것.)
- **로그아웃해도 보임**: GitHub에서 로그아웃하거나 **휴대폰**으로 그 주소를 열어도 똑같이 보인다 → 나만이 아니라 **누구나** 접속 가능한 공개 주소라는 증거입니다.
- **친구에게 전송**: 주소를 친구에게 보내 "열린다"는 답을 받으면 확실합니다.

> 흔한 실수
> - **"404 — There isn't a GitHub Pages site here." 가 뜸**: 거의 다 파일 이름 문제입니다.
>   대문 파일이 소문자 **`index.html`** 인지, 저장소 **맨 위(루트)** 에 있는지 확인하세요. (`/docs` 안에 넣었다면 4단계 폴더를 `/docs`로 맞춰야 함.)
> - **너무 빨리 포기**: 첫 배포는 1~3분 걸립니다. Save 직후 404가 떠도 잠시 뒤 새로고침하면 떠 있는 경우가 많습니다.
> - **디자인이 빠진 채 글자만 나옴**: `style.css`가 같은 저장소에 함께 올라가 있는지, `index.html`의 `<link rel="stylesheet" href="style.css" />` 한 줄이 있는지 확인하세요.
> - **수정했는데 화면이 그대로**: 파일을 고쳐 다시 커밋하면 자동으로 재배포되지만, **브라우저 캐시** 때문에 옛 화면이 보일 수 있습니다. **강력 새로고침(Ctrl+Shift+R)** 또는 시크릿 창으로 확인하세요.
> - **저장소가 Private(비공개)인데 Pages가 안 됨**: 무료 계정은 보통 **Public(공개) 저장소**에서 Pages가 동작합니다. 저장소를 Public으로 두세요. (비밀값을 안 올렸으니 공개해도 안전합니다.)
