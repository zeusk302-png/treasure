# 실습 328 — 이미지 업로드를 Supabase Storage에 저장하기

사용자가 파일 선택 버튼으로 **이미지를 고르면**, 그 이미지를 내 서버가 아니라 **Supabase Storage(클라우드 보관함)** 에 올리고, 받아 온 **공개 URL**로 화면에 바로 보여 주는 한 페이지를 만듭니다. 동시에 "버킷을 공개로 둘까, 비공개로 둘까"라는 **스토리지 권한** 개념과, 파일 업로드의 기본 흐름을 손으로 익히는 것이 목표입니다.

> 한 줄 그림: **사용자가 사진 선택 → 브라우저가 Supabase Storage 버킷에 업로드 → Storage가 "이 사진의 주소(URL)" 돌려줌 → 그 주소를 `<img>`에 넣어 화면에 표시**

> 비유: Supabase Storage는 **무인 사진 보관함(코인 로커)** 입니다. 사진을 맡기면(`upload`) 보관함이 **라커 번호표(공개 URL)** 를 줍니다. 그 번호표만 있으면 누구든 사진을 꺼내 볼 수 있죠. "아무나 꺼내도 되는 공개 라커"로 둘지, "주인만 꺼낼 수 있는 비공개 라커"로 둘지는 우리가 정합니다 — 그게 바로 **버킷 권한**입니다.

> 보안 메모 — 공개해도 되는 값 vs 절대 숨겨야 하는 값
> - **공개되어도 되는 값**: Supabase 프로젝트의 **URL**과 **anon(공개) 키**. 이 두 값은 브라우저 코드에 그대로 나가도 됩니다. 설계상 "공개를 전제로 한" 키이고, 진짜 보호는 **RLS(행 수준 보안)와 Storage 정책**이 합니다. ("anon 키 = 비밀번호"는 틀린 설명입니다.)
> - **절대 노출하면 안 되는 비밀값**: **service_role 키**. 이 키는 RLS·정책을 전부 무시하는 마스터 키라서, 브라우저나 깃에 절대 두면 안 되고 **서버(또는 n8n/Edge Function)** 에서만 씁니다.
> - 이 폴더의 `.env.example`에는 진짜 값이 아니라 **자리표시자**만 있습니다. 진짜 값은 복사해 만든 `.env`(또는 배포 플랫폼 환경변수)에만 넣고, `.env`는 `.gitignore`로 깃에서 빠집니다.

## 목표
- **파일 업로드 흐름**을 이해한다: `파일 선택 → Storage에 업로드 → 공개 URL 받기 → 화면에 표시`라는 4단계를 직접 돌려 본다.
- **오브젝트 스토리지**의 역할을 안다: 이미지·동영상 같은 큰 파일은 데이터베이스(표)가 아니라 **Storage(파일 보관함)** 에 두고, DB에는 그 **주소(URL)만** 저장한다는 원칙을 익힌다.
- **버킷 권한(공개/비공개)** 을 구분한다: 누구나 URL로 볼 수 있는 **public 버킷**과, 정책으로 막아 둔 **private 버킷**의 차이와, 각각 언제 쓰는지를 안다.
- **비밀값을 코드 밖에 둔다**: Supabase URL·anon 키는 환경변수(또는 자리표시자)로 관리하고, service_role 키는 절대 브라우저에 넣지 않는다.

## 따라하는 단계

### A. Supabase 프로젝트와 버킷 만들기
1. [supabase.com](https://supabase.com)에 가입하고 **New project**로 프로젝트를 하나 만듭니다. (무료 플랜으로 충분합니다.)
2. 왼쪽 메뉴 **Storage** → **New bucket** → 이름을 `images`로 짓습니다.
3. 처음에는 학습을 위해 **Public bucket(공개 버킷)** 으로 체크해서 만듭니다. (공개 버킷이면 업로드한 파일의 URL을 누구나 바로 볼 수 있어, 화면에 띄우기 쉽습니다.)

### B. 내 프로젝트 키 가져오기 (공개해도 되는 값만)
4. 왼쪽 메뉴 **Project Settings** → **API**로 들어갑니다.
5. **Project URL**(예: `https://abcd1234.supabase.co`)과 **anon public** 키를 복사합니다. — 이 둘은 **브라우저에 나가도 되는 공개 값**입니다.
6. 같은 화면의 **service_role** 키는 **절대 복사해서 페이지에 넣지 마세요.** 이번 실습에서는 쓰지 않습니다.

### C. 코드에 내 값 연결하기
7. 이 폴더의 `.env.example`을 복사해 `.env`를 만들고, 위에서 복사한 값을 채웁니다. (`.env`는 `.gitignore`가 깃에서 막아 줍니다.)
8. `index.html`을 열어 맨 위 `<script>` 안의 **`SUPABASE_URL`** 과 **`SUPABASE_ANON_KEY`** 자리표시자를 내 값으로 바꿉니다. (이 두 값은 공개 값이라 프론트 코드에 둬도 됩니다.)

### D. 페이지 열어서 업로드 테스트
9. `index.html`을 더블클릭해 브라우저로 엽니다. (외부 라이브러리는 CDN으로 불러오므로 별도 설치가 없습니다.)
10. **이미지 선택** 버튼으로 사진을 하나 고르면, 업로드 진행 표시가 뜨고 → 잠시 뒤 아래에 **올라간 이미지가 미리보기**로 보이면 성공입니다.
11. Supabase 화면의 **Storage → images** 버킷으로 가 보면 방금 올린 파일이 실제로 들어가 있는 걸 확인할 수 있습니다.

### E. (선택) 비공개 버킷으로 바꿔 권한 체감하기
12. Storage에서 버킷을 **private(비공개)** 로 바꾸면, 공개 URL로는 더 이상 안 보입니다(403). 이때는 `getPublicUrl` 대신 **시간 제한이 있는 서명 URL(`createSignedUrl`)** 을 받아야 합니다 — `index.html` 하단 주석에 바꾸는 방법이 적혀 있습니다.
13. 업로드/조회를 진짜로 제어하려면 **Storage 정책(RLS)** 을 답니다. 예: "로그인한 사용자만 업로드 가능". 정책 SQL 예시는 이 폴더의 `storage-policies.sql`에 있습니다 — Supabase **SQL Editor**에 붙여넣어 적용합니다.

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 비전공 초보를 돕는 웹개발 멘토야. 순수 HTML 한 파일(index.html)로
  "이미지 업로드 → Supabase Storage 저장 → 미리보기" 데모를 만들어 줘.

  요구사항:
  - 외부 빌드 도구 없이 브라우저에서 더블클릭으로 열리게, supabase-js v2를
    CDN(<script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2">)으로 불러와.
  - <input type="file" accept="image/*"> 파일 선택 버튼, "업로드 중..." 상태 텍스트,
    결과 이미지를 보여줄 <img> 영역을 둬.
  - supabase.storage.from('images').upload(...)로 올리고,
    getPublicUrl로 공개 URL을 받아 <img>의 src에 넣어.
  - SUPABASE_URL, SUPABASE_ANON_KEY는 코드 맨 위 상수에 자리표시자로 두고,
    "이건 공개해도 되는 값이고 service_role 키는 절대 넣지 말 것"이라고 주석으로 설명해.

  제약: 한국어 주석으로 "무엇을 하는지"뿐 아니라 "왜 그렇게 했는지"까지 적어 줘.
  코드만 주지 말고 비전공자가 한 줄씩 이해하게 풀어서 설명도 같이 줘.
  ```

- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 업로드 데모를 개선해 줘.
  1) 같은 파일명이 덮어쓰이지 않게, 업로드 경로를 `${Date.now()}-${원본파일명}`처럼
     고유하게 만들어 줘. (왜 그렇게 했는지 주석으로)
  2) 5MB가 넘거나 이미지가 아닌 파일이면 업로드 전에 막고 안내 메시지를 띄워 줘.
  3) 업로드 실패(네트워크 오류, 권한 거부 403 등) 시 사용자에게 친절한 한국어
     에러 메시지를 보여 줘. 에러 메시지는 textContent로 출력해(innerHTML은 XSS 위험이니 금지).
  4) 버킷을 비공개(private)로 바꿨을 때를 대비해, getPublicUrl 대신
     createSignedUrl(유효시간 60초)을 쓰는 버전도 주석으로 같이 보여 줘.
  각 변경마다 "왜 필요한지" 한국어 주석을 달아 줘.
  ```

- **막혔을 때(디버깅)** 프롬프트:
  ```text
  이미지 업로드가 안 돼. 아래 정보를 보고 원인을 단계별로 짚어 줘.
  - 브라우저 콘솔(F12) 에러: <여기에 에러 메시지 그대로 붙여넣기>
  - 증상: <예: 업로드는 되는데 미리보기 이미지가 깨져 보임 / 403 Unauthorized / CORS 에러>
  - 버킷 설정: 이름 images, 공개 여부 <public 또는 private>
  체크해야 할 것을 순서대로 알려 줘:
  1) SUPABASE_URL / anon 키가 맞는지, service_role을 잘못 넣진 않았는지
  2) 버킷 이름 철자와 공개/비공개 설정이 코드와 일치하는지
  3) Storage 정책(RLS)이 업로드/조회를 막고 있진 않은지(정책 SQL 예시도 줘)
  4) public 버킷인데 미리보기가 깨지면 getPublicUrl 결과 URL을 어떻게 점검하는지
  비전공자도 따라할 수 있게 "어디를 눌러 무엇을 확인" 식으로 설명해 줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법
- **업로드 성공 확인**: 페이지에서 이미지를 고르면 "업로드 중..."이 떴다가, 잠시 뒤 아래에 **그 이미지가 미리보기로** 보인다.
- **Storage에 실제 저장 확인**: Supabase **Storage → images** 버킷에 방금 올린 파일이 **실제로 들어가 있는지** 본다. (파일명이 `시각-원본이름` 형태로 고유한지도 확인.)
- **공개 URL 동작 확인**: 미리보기 이미지를 우클릭 → "새 탭에서 이미지 열기"를 했을 때, `https://<프로젝트>.supabase.co/storage/v1/object/public/images/...` 주소로 이미지가 **단독으로도 열리는지** 본다.
- **비밀값이 코드에 안 보이는지 확인**: 브라우저에서 `Ctrl`+`U`(소스 보기)로 페이지를 열어 **service_role 키가 한 글자도 없는지** 확인한다. (anon 키와 URL은 보여도 정상, service_role은 절대 보이면 안 됨.)
- **권한 체감(선택)**: 버킷을 private로 바꾼 뒤 같은 공개 URL을 열면 **403(접근 거부)** 이 떠야 정상이다 — 비공개 버킷은 서명 URL이 있어야만 열린다.
- **잘못된 파일 차단 확인**: 5MB 초과 파일이나 이미지가 아닌 파일을 고르면 업로드 전에 **안내 메시지로 막히는지** 본다.

## 파일 구성
- `index.html` — 이미지 업로드 데모 페이지 한 장. supabase-js를 CDN으로 불러와 업로드·미리보기·검증·에러처리까지 한다. URL/anon 키는 자리표시자로 둔다.
- `storage-policies.sql` — 비공개 버킷에서 "로그인 사용자만 업로드/조회" 같은 권한을 거는 **Storage 정책(RLS) 예시**. Supabase SQL Editor에 붙여넣어 적용한다.
- `.env.example` — 필요한 키 견본(자리표시자만). 복사해 `.env`를 만들고 진짜 값은 거기/배포 플랫폼 환경변수에만 넣는다. service_role 키는 서버에서만 쓴다.
- `.gitignore` — `.env` 등 비밀 파일이 깃에 올라가지 않게 막는다.
