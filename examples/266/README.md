# 대시보드 데이터를 검색·정렬·페이지네이션하는 표로 만들기

주문 120건처럼 **큰 목록**을 다루는 대시보드 표를 만듭니다. 한 번에 다 불러오는 대신, **검색**으로 좁히고 · **정렬**로 줄 세우고 · **페이지네이션**으로 10개씩 나눠서 불러옵니다.

> 비유: 도서관에서 책 10만 권을 한 번에 책상에 쌓아 두면 못 찾습니다.
> 검색은 "제목에 '코딩' 들어간 책만요", 정렬은 "최신순으로 줄 세워 주세요", 페이지네이션은 "한 번에 10권씩만 보여 주세요" 라고 사서에게 부탁하는 것과 같습니다.
> 핵심은 **사서(서버/Supabase)가 추려서 10개만 건네주는 것** — 내 브라우저가 10만 권을 직접 다 받지 않습니다.

## 목표

- Supabase 쿼리에 **검색(`ilike`/`or`)·필터(`eq`)·정렬(`order`)·페이지 자르기(`range`)** 를 조립해 본다.
- "현재 화면 상태"(검색어·정렬 기준·페이지 번호)를 **쿼리 파라미터**처럼 변수에 모아 두고, 그 값이 바뀔 때마다 표를 다시 그리는 흐름을 익힌다.
- `select('*', { count: 'exact' })` 로 **전체 개수**를 받아 **총 페이지 수**를 계산하는 법을 익힌다.
- 이 표는 **읽기 전용**(공개 `anon` 키로 `select` 만 허용, RLS 로 잠금)이라 안전하다는 원칙을 확인한다.

## 따라하는 단계

1. [supabase.com](https://supabase.com)에서 프로젝트를 만듭니다. (앞 실습에서 만든 게 있으면 그대로 써도 됩니다.)
2. 왼쪽 메뉴 **SQL Editor**를 열고, 이 폴더의 `schema.sql` 전체를 붙여넣은 뒤 **[Run]** 합니다. → `orders` 테이블과 **가짜 주문 120개**가 생깁니다.
3. **Settings → API**에서 `Project URL`과 `anon`(공개) 키를 복사합니다.
4. `index.html` 위쪽의 `SUPABASE_URL`, `SUPABASE_ANON_KEY` 두 값을 내 값으로 바꿉니다. (`REPLACE_WITH_YOUR_ANON_PUBLIC_KEY` 자리를 내 anon 키로)
5. `index.html`을 브라우저로 엽니다. 첫 화면에 주문 10건이 **최신 주문일 순(▼)** 으로 보이고, 아래에 `120건 중 1 / 12 페이지` 라고 뜹니다.
6. 위쪽 검색칸에 상품 이름 일부(예: `텀블러`)를 쳐 봅니다. → 결과가 좁혀지고 페이지 수도 줄어듭니다.
7. **상태 전체** 드롭다운에서 `배송중` 을 골라 검색과 겹쳐 봅니다. (검색 + 필터 동시 적용)
8. 표 머리글 **금액**을 클릭하면 금액 오름차순(▲), 한 번 더 누르면 내림차순(▼)으로 바뀝니다. 다른 머리글도 눌러 봅니다.
9. 아래 **다음 ▶ / ◀ 이전** 버튼으로 페이지를 넘겨 봅니다.

## 검증법

- **검색이 서버에서 걸림**: `텀블러` 로 검색하면 표에 텀블러 주문만 남고, 안내문의 총 건수도 줄어든다. (검색 결과가 10개보다 많으면 페이지가 여러 장 생긴다.)
- **검색 + 필터 동시 적용**: 검색어를 둔 채 상태를 `취소`로 바꾸면 둘 다 만족하는 행만 보인다.
- **정렬 방향 토글**: **금액** 머리글을 한 번 누르면 가장 싼 주문이 위로(▲), 다시 누르면 가장 비싼 주문이 위로(▼) 온다. 화살표 표시도 같이 바뀐다.
- **페이지네이션 동작**: `다음 ▶` 을 누르면 다음 10건이 보이고 안내문이 `2 / 12 페이지` 로 바뀐다. 1페이지에서는 `◀ 이전` 이, 마지막 페이지에서는 `다음 ▶` 이 비활성화된다.
- **한 페이지만 받는지 확인(가장 중요)**: F12 → **Network** 탭을 열고 페이지를 넘겨 봅니다. 요청 응답이 **매번 10건만** 담겨 옵니다 → 120건을 다 받는 게 아니라 필요한 구간만 받는다는 증거입니다. (`Range` 헤더로 `0-9`, `10-19` … 가 보입니다.)
- **오류 없음**: 정상 흐름에서 F12 → Console 에 빨간 오류가 없어야 한다.

> 잘 안 되면 점검: ① `SUPABASE_URL`·`anon` 키를 바꿨는지 ② `schema.sql` 을 [Run] 해서 `orders` 에 120행이 있는지(Table Editor 에서 확인) ③ 정렬이 안 되면 머리글의 `data-col` 값이 실제 칼럼명(customer/product/amount/status/created_at)과 같은지.

!!! warning "키 주의"
    `index.html`에 넣는 건 **anon(공개) 키**여야 합니다. 이 대시보드는 RLS 로 **읽기(select)만** 열어 두었으니 공개 키를 브라우저에 둬도 표를 망가뜨릴 수 없습니다. 반대로 `service_role`(secret) 키는 **RLS 를 통째로 무시**하므로 브라우저·GitHub에 절대 두지 마세요. 비밀 키가 필요한 작업(대량 입력·관리자 삭제 등)은 반드시 **서버(또는 n8n)** 쪽에서만 처리합니다.
