# 실습 314 — Figma 디자인을 스크린샷→AI로 코드화하기

Figma 시안(또는 그냥 화면 캡처 한 장)을 AI에게 주고 **"이 디자인 그대로 HTML/CSS로 만들어"**라고 시킨 뒤, 받은 코드를 시안과 **나란히 비교·보정**하는 워크플로우를 익힙니다. 직접 픽셀을 재는 대신, **AI에게 그림을 명세서로 건네고 → 결과를 시안과 대조하며 어긋난 곳만 고치는** 디렉터식 작업 방식이 목표입니다. 이 폴더의 `index.html`은 "잘 보정된 결과물이 어떻게 생겨야 하는지" 보여주는 **비교 기준(완성 예시)**입니다.

> 한 줄 그림: **시안(그림) → AI에게 스크린샷 첨부 + "이대로 만들어" → AI가 HTML/CSS 생성 → 시안과 결과를 나란히 놓고 다른 곳만 콕 집어 보정 → 시안과 거의 똑같은 정적 페이지 완성**

> 비유: 시안은 **집 설계 도면**, AI는 그 도면을 보고 벽을 세우는 **목수**입니다. "예쁘게 지어줘"라고 말로만 하면 목수는 매번 다른 집을 짓지만, **도면(스크린샷)을 손에 쥐여주면** 치수·배치를 보고 거의 그대로 짓습니다. 마지막에 도면과 실제를 대보며 "여백 더, 색 살짝 진하게"만 손보는 게 디렉터의 일입니다.

## 목표
- **디자인→코드 워크플로우를 체득**한다: 스크린샷 첨부 → AI 생성 → 시안 대조 → 보정의 4단계 흐름을 직접 돌려 본다.
- **AI에게 명확히 디렉팅**한다: "색은 눈대중 말고 정확한 HEX", "여백은 8의 배수", "모바일에서 어떻게 쌓이는지도 설명"처럼 **구체 제약**을 주어 결과 편차를 줄인다.
- **시안과 코드를 비교·보정**한다: 색·여백·정렬·반응형이 시안과 어디서 어긋나는지 눈으로 찾아 **그 부분만** 고친다.
- **디자인 토큰을 이해**한다: 반복되는 색·간격을 CSS 변수로 모아 "값 하나만 바꿔 전체를 맞추는" 보정 방식을 익힌다.

## 따라하는 단계

### A. 비교 기준이 될 완성 예시 먼저 보기
1. 이 폴더의 `index.html`을 더블클릭해 브라우저로 엽니다. (서버·빌드 도구 필요 없음 — 그냥 열립니다.)
2. 히어로(큰 제목) → 가격 카드 3개 → 푸터로 이어지는 흔한 SaaS 랜딩 모습이 보일 겁니다. 이게 **"AI가 시안대로 잘 만들었을 때의 목표 상태"**입니다.
3. 브라우저 창을 좁게 줄여 보세요. 가격 카드가 3칸 → 2칸 → 1칸으로 **자동으로 접히는지**(반응형) 확인합니다.

### B. 내 시안(스크린샷) 준비하기
4. 따라할 디자인 한 장을 정합니다. 셋 중 하나면 됩니다.
   - Figma 시안이 있으면: 프레임을 클릭하고 우상단 **Export**로 PNG로 내보내거나, 그냥 **화면 캡처**(Windows `Win`+`Shift`+`S`)합니다.
   - Figma가 없으면: 마음에 드는 웹사이트 화면을 캡처하거나, 이 폴더의 `index.html`을 캡처해 "이걸 처음부터 다시 만들어 봐"라고 연습해도 됩니다.
5. 캡처는 **한 화면씩** 준비합니다. (한 장에 너무 많은 화면을 욱여넣으면 AI가 헷갈립니다.)

### C. AI에게 시켜서 코드 받기
6. AI 채팅(Claude 등)에 **스크린샷을 첨부**하고, 아래 **🤖 바이브코딩 프롬프트 → 1단계** 를 복사해 붙여 넣습니다. (스택은 "순수 HTML/CSS 한 파일"로 시켰습니다 — 비전공자가 더블클릭만으로 열 수 있어서입니다.)
7. AI가 준 코드를 새 파일(예: `my.html`)로 저장하고 브라우저로 엽니다.

### D. 시안과 나란히 놓고 보정하기 (이 실습의 핵심)
8. **시안 캡처와 내 결과 화면을 화면 절반씩 띄워** 나란히 봅니다. 체크리스트로 비교하세요.
   - 색이 같은가? (특히 버튼·강조색) — 다르면 AI에게 "버튼색을 정확히 `#4f46e5`로 바꿔줘".
   - 여백·간격이 비슷한가? — 들쭉날쭉하면 "여백을 8의 배수(8/16/24px)로 통일해줘".
   - 정렬이 맞는가? (가운데/왼쪽) / 글자 크기 위계가 맞는가?
   - 좁은 화면에서 안 깨지는가?
9. 어긋난 항목만 모아 **🤖 → 2단계** 프롬프트로 한 번에 보정 요청합니다. 한 번에 다 안 맞으면 2~3회 반복합니다. (AI 결과는 100% 똑같이는 안 나오므로 "거의 같게 + 마지막 손질"이 정상입니다.)
10. 더 정확히 맞추고 싶으면 Figma **Dev Mode**(개발자 모드)에서 색·여백 값을 복사해 "이 값 그대로 써줘"라고 주면 편차가 크게 줍니다.

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. **1단계는 디자인 스크린샷을 채팅에 첨부한 뒤** 보내세요.

- **1단계(뼈대 만들기)**:
  ```text
  역할: 너는 디자인 시안을 정적 웹페이지로 옮기는 프론트엔드 개발자야.
  첨부한 디자인 스크린샷대로 화면을 만들어줘.

  스택/제약:
  - 빌드 도구 없이 더블클릭으로 바로 열리게, 순수 HTML/CSS "한 파일"(index.html)로 만들어줘.
    CSS는 <style> 태그 안에 넣어줘. (비전공자가 바로 열 수 있어야 함)
  - 색은 눈대중 말고 가능한 한 정확한 HEX 값으로. 같은 색이 여러 번 나오면 CSS 변수(:root)로
    한 곳에 모아줘(디자인 토큰).
  - 여백·간격은 8의 배수(8/16/24px 등)로 통일해줘.
  - 모바일에서도 안 깨지게 반응형으로. 카드가 여러 개면 좁은 화면에서 자동으로 1~2칸으로
    접히게 해줘(grid auto-fit + minmax).
  - 사용자 입력을 화면에 표시하는 부분이 있다면 innerHTML 말고 textContent를 쓰고, 그 이유도
    주석으로 적어줘.

  출력 규칙:
  - 코드만 주지 말고, 비전공자가 이해하게 "무엇을 하는지 + 왜 그렇게 했는지"를 한 줄씩 한국어
    주석으로 풀어서 달아줘. 식별자(클래스/변수명)는 영어로.
  - 파일 맨 위에 이 파일이 무엇이고 왜 있는지 요약 주석 한 블록도 넣어줘.
  ```

- **2단계(기능 추가/개선 — 시안과 다른 곳 보정)**:
  ```text
  방금 만든 페이지를 시안과 비교했더니 아래가 달라. 이 부분만 고쳐줘(다른 멀쩡한 코드는 건드리지 말 것):
  1) 버튼/강조색이 시안과 달라 → 메인색을 정확히 #4f46e5, 호버색을 #4338ca 로 맞춰줘.
  2) 카드 사이 간격이 좁아 보여 → 카드 간격(gap)을 24px로, 카드 안쪽 여백을 28px로.
  3) 가운데 "추천" 카드만 테두리를 메인색으로 강조하고 살짝 위로 떠 보이게(그림자 + translateY).
  4) 좁은 화면에서 상단 메뉴 링크가 넘쳐 → 640px 이하에서는 가운데 메뉴 링크를 숨기고
     로고와 시작 버튼만 남겨줘.
  고친 이유도 각 줄에 한국어 주석으로 적어줘. 그리고 무엇을 바꿨는지 한국어로 요약해줘.
  ```

- **막혔을 때(디버깅)**:
  ```text
  카드가 모바일(좁은 화면)에서 한 줄로 안 접히고 옆으로 삐져나와서 가로 스크롤이 생겨.
  관련 HTML/CSS를 아래에 붙일게. 다음을 단계별로 진단해줘:
  1) 가로 스크롤이 생기는 원인 후보(고정 width, grid 칸 최소폭이 화면보다 큰지,
     box-sizing 누락, 큰 패딩 등)를 하나씩 짚어줘.
  2) 각 후보를 내가 어떻게 직접 확인하는지(F12 개발자도구에서 어디를 보는지)도 알려줘.
  3) 가장 가능성 높은 원인 1개를 고친 수정 코드를 주고, 왜 그게 원인이었는지 비전공자가
     이해하게 한국어로 설명해줘.

  [여기에 내 코드 붙여넣기]
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다. 보정은 한 번에 다 안 맞는 게 정상이니 **다른 점만 모아 2~3회 반복**하세요.

## 검증법
- **나란히 비교**: 시안 캡처와 내 결과 화면을 좌우로 띄워 색·여백·정렬·글자 크기 위계가 **거의 일치**하는지 본다. (픽셀 단위로 100% 같을 필요는 없다 — "한눈에 같아 보이면" 합격.)
- **반응형 확인**: 브라우저 창을 좁게 줄였을 때 가격 카드가 3 → 2 → 1칸으로 자연스럽게 접히고, **가로 스크롤이 생기지 않는지** 확인한다.
- **색이 토큰으로 모였는지 확인**: 코드에서 같은 메인색(`#4f46e5`)이 여기저기 직접 박혀 있지 않고 `:root`의 CSS 변수 한 곳에 정의돼 재사용되는지 본다. (보정이 쉬워진다.)
- **비밀값이 없는지 확인**: 이 실습은 정적 페이지라 API 키·토큰이 있으면 안 된다. 코드를 훑어 키처럼 보이는 긴 문자열이 없는지 본다. (폼이 실제로 데이터를 보낸다면 키는 서버에만 둔다.)
- **접근성 한 번 점검**: 키보드 `Tab` 키만으로 버튼·링크에 차례로 포커스가 가는지, 이미지가 있다면 의미 있는 `alt`가 있는지 확인한다.

## 파일 구성
- `index.html` — 시안을 잘 보정해 코드로 옮겼을 때의 **완성 예시(비교 기준)**. 히어로 + 반응형 가격 카드 3개 + 푸터. 디자인 토큰(CSS 변수)·반응형 그리드가 들어 있고, 초보가 막힐 지점마다 "무엇+왜" 주석이 달려 있다.
