# 실습 307 — Redis에 로그인 세션 저장하기

로그인한 사용자가 "누구인지"를 기억하는 **세션 정보**를, 서버 메모리 안이 아니라 **Redis라는 바깥 저장소**에 키-값으로 보관합니다. 만료 시간(TTL)을 걸어 일정 시간이 지나면 자동으로 로그아웃되게 하고, 무엇보다 **서버를 재시작하거나 서버를 여러 대로 늘려도 로그인이 그대로 유지**되는 구조를 만드는 것이 목표입니다.

> 한 줄 그림: **로그인 성공 → 무작위 세션 ID 발급 → Redis에 `session:<ID> = {유저정보}`를 TTL과 함께 저장 → 브라우저 쿠키엔 ID만 → 다음 요청마다 쿠키의 ID로 Redis를 조회해 "이 사람 누구"를 알아냄**

> 비유: 세션 ID는 **물품보관소(코인락커)의 번호표**입니다. 번호표(쿠키)에는 내 짐 내용이 적혀 있지 않고 **번호만** 있습니다. 진짜 짐(유저 정보)은 보관소(Redis)에 들어 있고, 직원은 번호표를 받으면 그 칸을 열어 줍니다. 보관소를 **건물 밖 공용 창고(Redis)**에 두면, 우리 가게(서버) 문을 닫았다 열어도·옆에 분점(서버 2대째)을 내도 같은 번호표로 같은 짐을 찾을 수 있습니다.

> 보안 메모 — 공개해도 되는 값 vs 절대 숨겨야 하는 값
> - **쿠키에 담기는 세션 ID**: 무작위로 만든 긴 문자열이라, 그 자체로는 유저 정보가 들어 있지 않습니다. 다만 이 ID를 훔치면 남의 세션을 그대로 쓸 수 있으므로 쿠키는 `httpOnly`(JS가 못 읽음) + `secure`(HTTPS에서만 전송)로 보호합니다.
> - **절대 노출하면 안 되는 비밀값**: `REDIS_URL`(아이디·비번이 들어간 Redis 접속 주소), `SESSION_SECRET`(쿠키 서명용 비밀키). 이건 **서버 전용**이라 브라우저로 절대 나가면 안 되고, `.env`에만 두고 `.gitignore`로 깃에서 뺍니다.
> - 이 폴더의 코드에는 진짜 값이 없습니다. `.env.example`에 **자리표시자**만 있고, 진짜 값은 복사해 만든 `.env`(깃 제외)에만 적습니다.

## 목표
- **세션을 외부에 저장하는 이유**를 이해한다: 로그인 상태를 서버의 변수(메모리)에 두면 서버를 끄는 순간 모두 로그아웃되고, 서버가 2대면 서로 모른다. Redis에 두면 이 문제가 사라진다(상태 외부화).
- **세션 스토어를 직접 만든다**: 로그인 시 무작위 세션 ID를 만들어 `session:<ID>` 키로 Redis에 저장하고, 쿠키에는 ID만 담는다.
- **TTL(만료)을 건다**: 세션 키에 만료 시간을 줘서, 일정 시간 활동이 없으면 Redis가 알아서 키를 지워 자동 로그아웃되게 한다.
- **서버 재시작에도 살아남는 걸 확인한다**: 로그인한 채 서버를 껐다 켜도 같은 쿠키로 로그인이 유지되는지 눈으로 본다.

## 따라하는 단계

### A. 준비물 설치
1. Node.js가 깔려 있어야 합니다(`node -v`로 확인). 이 폴더에서 터미널을 엽니다.
2. `npm install` 을 실행해 의존성(express, redis, cookie-parser)을 설치합니다.
3. **Redis를 띄웁니다.** 가장 쉬운 방법은 Docker입니다: `docker run -d --name redis-demo -p 6379:6379 redis:7`
   - Docker가 없으면 [Upstash](https://upstash.com) 같은 무료 클라우드 Redis를 만들어 접속 URL을 받아도 됩니다.

### B. 비밀값을 .env에 넣기 (코드에 박지 않기)
4. `.env.example`을 복사해 `.env` 파일을 만듭니다: `cp .env.example .env` (윈도우 PowerShell은 `Copy-Item .env.example .env`).
5. `.env`를 열어 두 값을 채웁니다.
   - `REDIS_URL` — 로컬 Docker면 `redis://localhost:6379`, 클라우드면 받은 주소(아이디·비번 포함).
   - `SESSION_SECRET` — 아무에게도 안 알려 줄 긴 무작위 문자열. 만들기: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
   - `.env`는 `.gitignore`에 들어 있어 깃에 올라가지 않습니다. 절대 직접 커밋하지 마세요.

### C. 서버 실행하고 로그인 흐름 보기
6. `npm start` 로 서버를 켭니다. 콘솔에 `http://localhost:3000` 이 뜹니다.
7. 브라우저로 그 주소를 열면 데모 페이지가 나옵니다. 아이디·비밀번호를 넣고 **로그인**을 누릅니다. (이 데모는 학습용이라 비밀번호 검증은 단순화되어 있습니다.)
8. 로그인되면 "환영합니다, OOO 님" 과 **남은 세션 시간(TTL)** 이 보입니다. 새로고침해도 로그인이 유지됩니다(쿠키의 세션 ID로 Redis를 다시 조회하기 때문).

### D. "외부 저장"의 진가 확인하기 (이 실습의 핵심)
9. **서버 재시작 테스트**: 터미널에서 서버를 `Ctrl+C`로 끄고 다시 `npm start` 합니다. 브라우저를 새로고침해도 **여전히 로그인 상태**입니다. → 세션이 서버 메모리가 아니라 Redis에 있기 때문입니다. (만약 메모리에 저장했다면 여기서 로그아웃됐을 것입니다.)
10. **만료(TTL) 테스트**: 데모 화면의 "남은 시간"이 0이 될 때까지 두거나, 데모를 짧은 TTL로 바꿔 두면, 만료 후 새로고침 시 자동으로 로그아웃됩니다. → Redis가 만료된 키를 스스로 지웠기 때문입니다.
11. **로그아웃 테스트**: **로그아웃** 버튼을 누르면 서버가 Redis에서 해당 `session:<ID>` 키를 지우고 쿠키도 비웁니다. 새로고침하면 로그인 화면으로 돌아갑니다.

> Redis에 실제로 들어간 걸 보고 싶다면(선택): `docker exec -it redis-demo redis-cli` 로 들어가 `KEYS session:*` 을 치면 저장된 세션 키들이 보이고, `TTL session:<ID>` 로 남은 만료 시간(초)을 볼 수 있습니다.

## 검증법
- **로그인 유지 확인**: 로그인 후 브라우저를 여러 번 새로고침해도 "환영합니다 …" 화면이 유지되는지 본다(쿠키의 세션 ID로 Redis를 다시 조회하기 때문).
- **서버 재시작에도 유지(핵심)**: 서버를 `Ctrl+C`로 껐다 `npm start`로 다시 켠 뒤 새로고침해도 **여전히 로그인 상태**면, 세션이 서버 메모리가 아니라 Redis에 외부화된 것이다.
- **만료(TTL) 동작 확인**: 화면의 "남은 시간"이 0이 된 뒤(또는 짧은 TTL로 설정 후) 새로고침하면 자동 로그아웃되는지 본다. `redis-cli`에서 `TTL session:<ID>`가 0/음수로 가며 키가 사라지는 걸 확인한다.
- **로그아웃이 서버에서 무효화되는지**: 로그아웃 후 `redis-cli`로 `KEYS session:*`를 보면 해당 키가 **사라져 있어야** 한다(쿠키만 지우는 게 아니라 Redis에서도 지워야 진짜 로그아웃).
- **비밀값이 코드/브라우저에 안 보이는지**: 배포·실행된 페이지에서 `Ctrl+U`(소스 보기)와 F12로 `REDIS_URL`·`SESSION_SECRET`이 **한 글자도 안 보이는지** 확인한다(서버 전용 값이므로 보이면 안 된다).
- **코드에 비밀값이 안 박혔는지**: 이 폴더에서 `grep -nE "redis://[^l].*:.*@|[0-9a-f]{32,}" server.js` 를 돌렸을 때 진짜 접속정보/시크릿이 안 나오고 `process.env.*` 참조만 있으면 정상이다.

## 파일 구성
- `server.js` — Express 서버. 로그인 시 세션 ID 발급 → Redis에 TTL과 함께 저장 → 쿠키엔 ID만 → 요청마다 Redis로 세션 조회. 모든 줄에 "무엇+왜" 주석.
- `package.json` — 의존성(express, redis, cookie-parser)과 `npm start` 스크립트.
- `.env.example` — 필요한 비밀값 견본(자리표시자만). 복사해 `.env`를 만들고 진짜 값은 거기에만 넣는다.
- `.gitignore` — `.env`, `node_modules` 등이 깃에 안 올라가게 막는다.
