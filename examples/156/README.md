# 실습 156 — 로딩 스피너와 '실패했어요' 에러 메시지 붙이기

버튼을 누르면 **무료 공개 날씨 API**에서 도시 날씨를 받아오는 작은 위젯입니다.
이번 실습의 진짜 주제는 날씨 그 자체가 아니라, 화면이 가질 수 있는 **세 가지 상태**를 모두 만드는 것입니다.

1. **① 받아오는 중(로딩)** — 빙글 도는 스피너 + "받아오는 중이에요…"
2. **② 성공** — 받아온 기온·날씨를 보여 줌
3. **③ 실패** — "날씨를 받아오지 못했어요" 같은 **사용자용 에러 문구** + [다시 시도] 버튼

> 비유: 음식을 주문하면 (1) "조리 중입니다" → (2) "나왔습니다" 또는 (3) "재료가 떨어졌어요, 다시 주문해 주세요" 중 하나가 됩니다.
> 화면도 똑같습니다. **데이터를 받아오는 일은 항상 이 세 갈래로 끝납니다.**

> 디렉터로서 꼭 알아야 할 핵심: AI에게 "날씨 받아와서 보여줘"라고 하면 대부분 **성공했을 때 화면만** 만들어 줍니다.
> 하지만 인터넷이 끊기거나, 주소가 틀렸거나, 서버가 점검 중이면 **실패**합니다. 이때 빈 화면·멈춘 화면이 나오면 사용자는 당황합니다.
> 그래서 **"실패하면 어떻게 보일지"를 직접 챙기는 것**이 이번 실습의 한 줄 목표입니다. 그 도구가 바로 `try`/`catch`입니다.

## 목표
- 한 화면이 가질 수 있는 **세 가지 상태(로딩/성공/실패)**를 구분하고, 한 번에 **하나만** 보이게 전환하는 법을 익힌다.
- `try` / `catch` / `finally`로 **실패 경로**를 직접 처리한다.
  - `try`: 받아오기를 시도하는 부분
  - `catch`: 실패했을 때 **에러 화면**을 띄우는 부분 (AI가 자주 빠뜨리는 곳)
  - `finally`: 성공이든 실패든 **항상** 버튼을 다시 풀어 주는 부분
- 응답이 정상(200대)이 아니면 `if (!res.ok) throw ...`로 **일부러 에러를 던져** catch로 보내는 패턴을 익힌다. (이게 없으면 '실패한 걸 성공한 척'하는 버그가 생긴다.)
- 사용자에게는 **친절한 한국어 한 줄**을 보여 주고, 자세한 원인은 `console.error`로 **개발자 콘솔에만** 남기는 분리 원칙을 익힌다.

## 따라하는 단계
1. 이 폴더의 `index.html`을 더블클릭 → 브라우저에서 열린다. (인터넷 연결 필요)
2. 도시를 **서울/부산/제주** 중에서 고르고 **[날씨 받기]** 버튼을 누른다.
3. 누르는 순간 **① 빙글 도는 스피너**가 잠깐 보였다가, **② 성공 화면**(이모지·도시·기온·날씨)으로 바뀐다.
4. 이번엔 드롭다운에서 **⚠️ (없는 도시) 실패 화면 보기**를 고르고 **[날씨 받기]**를 누른다 → **③ 빨간 실패 화면**과 안내 문구, **[다시 시도]** 버튼이 뜬다.
5. 실패 화면에서 **[다시 시도]**를 눌러 본다 → 다시 로딩 후 (없는 도시이므로) 또 실패 화면이 나온다. 정상 도시로 바꿔 누르면 성공으로 돌아온다.
6. **인터넷을 끄고**(또는 비행기 모드) 정상 도시로 **[날씨 받기]**를 눌러 본다 → 역시 ③ 실패 화면이 뜬다. (네트워크 끊김도 `catch`가 잡아 준다.)
7. `script.js`에서 `loadWeather()` 함수를 찾는다. `try` 안은 성공 흐름, `catch` 안이 **실패 화면을 띄우는 부분**, `finally`가 **버튼을 다시 푸는 부분**이다.
8. 같은 파일의 `showState("loading")` / `showState("result")` / `showState("error")`를 본다 → 한 번에 **하나의 상태만** 보이게 전환하는 핵심 도우미다.
9. `if (!res.ok) throw new Error(...)` 줄을 본다 → 서버가 에러를 줘도 그냥 통과하지 않도록 **일부러 에러를 던지는** 안전장치다.
10. AI에게 시켜 보기:
    > "이 `script.js`에 **'로딩이 5초 넘게 걸리면 자동으로 실패 처리'**하는 타임아웃을 추가해줘. 단, 기존의 로딩/성공/실패 **세 가지 상태 전환(`showState`)과 `try/catch/finally` 구조는 그대로 유지**하고, 사용자에게는 친절한 한국어 문구를, 자세한 원인은 `console.error`에만 남기게 해줘."

## 검증법
- 정상 도시로 누르면 **로딩 스피너 → 성공 화면(기온·날씨)** 순서로 바뀌는가? (세 박스 중 한 번에 하나만 보이는가)
- **⚠️ (없는 도시)**를 고르면 **빨간 실패 화면 + [다시 시도] 버튼**이 뜨는가?
- 실패 화면에서 사용자에게 보이는 문구가 **친절한 한국어 한 줄**인가? (영어 에러 코드나 `undefined`가 그대로 노출되지 않는가)
- `F12`(개발자 도구) → **Console 탭**을 열고 실패를 일으키면, 자세한 원인이 `날씨 받아오기 실패: ...`로 **콘솔에만** 찍히는가? (화면에는 안 보임)
- `F12` → **Network 탭**에서 새로 받아올 때 `forecast?latitude=...` 요청이 보이는가? 정상 도시는 `200`, 없는 도시는 `4xx/5xx`로 떠서 실패로 이어지는가?
- 인터넷을 끈 상태로 눌러도 **앱이 멈추지 않고** 실패 화면으로 넘어가는가? (다시 켜고 [다시 시도]를 누르면 복구되는가)

> 참고: 이 위젯은 **Open-Meteo**(`open-meteo.com`)라는 **무료 공개 날씨 API**를 씁니다. 회원가입과 API 키가 필요 없습니다.
> '없는 도시'는 일부러 위도/경도를 잘못 넣어(`lat: 999`) 실패를 흉내 내려는 학습용 항목입니다.

## 공개 API와 비밀값 — 보안 메모
이 실습이 쓰는 **Open-Meteo**는 **누구나 열쇠(API 키) 없이** 부를 수 있는 **공개 API**입니다.
그래서 이 코드에는 **넣을 비밀값이 아예 없습니다.** 브라우저 코드는 누구나 들여다볼 수 있으니, 비밀값이 없다는 점이 안전합니다.

나중에 **키가 필요한** 날씨/외부 API를 쓰게 되면, 값의 성격을 반드시 구분해야 합니다.

- **공개되어도 되는 값**(예: Supabase의 `anon`(공개) 키): 브라우저 코드에 들어가도 괜찮습니다. 단, 데이터 보호는 **RLS(행 수준 보안)** 가 책임집니다.
- **절대 노출하면 안 되는 비밀값**(예: Supabase의 `service_role` 키, 유료 날씨 API 키): **브라우저 코드에 절대 넣지 않습니다.** 비밀값은 서버(또는 n8n 같은 자동화 도구의 자격 증명 저장소)에서만 다룹니다.
- 키가 있는 API를 예제로 적을 때는, 코드에 진짜 키 대신 `YOUR_API_KEY` 같은 **자리표시자**만 두는 것이 원칙입니다.

```js
// 키가 필요한 날씨 API를 '브라우저에서 직접' 부르는 것은 키 노출 위험이 있습니다.
// 예시로 적을 때조차 진짜 키는 넣지 말고 자리표시자만 둡니다.
const WEATHER_API_KEY = "YOUR_API_KEY"; // ← 자리표시자. 실제 비밀키는 절대 코드에 넣지 않는다.
// 실제로는 이런 비밀키 호출은 서버(또는 n8n)에서 처리하고, 브라우저는 그 서버를 부릅니다.
```
