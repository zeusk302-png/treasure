# 매일 아침 오늘 날씨를 이메일로 받기

앞 실습(201)에서는 "매일 정해진 시각에 스스로 깨어나는" 알람(Schedule Trigger)을 배웠습니다. 그런데 깨어나기만 하고 시각만 메모지에 적었죠. 이번에는 그 알람이 깨어나면 **실제로 일을 시킵니다.** 인터넷에서 **오늘 날씨를 받아오고(API)**, 그 내용으로 **메일을 한 통 써서 나에게 보내는(Email)** 것입니다.

즉, 지금까지 따로따로 배운 세 가지 부품을 **하나의 흐름(파이프라인)** 으로 잇습니다.

> **이 워크플로우는 노드 4개입니다.**
> `매일 오전 7시 (Schedule Trigger)` → `오늘 날씨 가져오기 (HTTP Request)` → `메일 내용 만들기 (Set)` → `메일 보내기 (Send Email)`
>
> 비유하자면: ① 알람이 울린다 → ② 날씨 사이트에 전화해서 오늘 날씨를 묻는다 → ③ 들은 내용으로 편지를 쓴다 → ④ 그 편지를 우체통에 넣는다. 물이 위에서 아래로 흐르듯, 데이터가 왼쪽 노드에서 오른쪽 노드로 흘러갑니다.

> **API를 한마디로:** 다른 컴퓨터에게 "이 정보 좀 줘"라고 정해진 방식으로 요청하면 정해진 방식으로 답을 주는 **주문 창구**입니다. 여기서는 날씨 정보를 주는 무료 창구(Open-Meteo)에 "오늘 부산 날씨 줘"라고 요청합니다. 이 창구는 **API 키(비밀번호)가 필요 없어서** 별도 가입 없이 바로 씁니다.

## 목표

- **Schedule + HTTP Request + Email** 세 종류의 노드를 한 줄로 이어, 매일 아침 '오늘 날씨' 메일이 **자동으로** 오게 만든다.
- 인터넷에서 데이터를 받아오는 **API 호출(HTTP Request)** 이 무엇인지, 받아온 데이터를 어떻게 **다음 노드에서 꺼내 쓰는지**(`{{ $json... }}`)를 이해한다.
- 메일 계정 비밀번호 같은 **비밀값을 어디에 넣어야 안전한지**(노드가 아니라 `Credentials` 금고)를 정확히 익힌다.

## 따라하는 단계

1. **n8n에 로그인**합니다. (n8n Cloud 가입형 또는 직접 설치한 n8n 모두 가능)
2. 화면 오른쪽 위 **`...`(점 3개) → `Import from File`** 을 눌러 이 폴더의 **`workflow.json`** 을 불러옵니다. 노드 4개가 일렬로 연결되어 나타납니다.
3. **`오늘 날씨 가져오기 (HTTP Request)` 노드를 더블클릭**해서 안을 봅니다. 이미 이렇게 설정돼 있습니다. 별도 가입/키가 필요 없으니 그대로 두면 됩니다.
   - **`URL`**: `https://api.open-meteo.com/v1/forecast` — 무료 날씨 창구 주소입니다.
   - **`Query Parameters`(질문 항목)**: `latitude=35.18`, `longitude=129.08`(부산 좌표), `timezone=Asia/Seoul`, 그리고 "오늘 최고/최저 기온과 비 올 확률을 달라"는 항목이 적혀 있습니다.
   - **다른 도시로 바꾸려면** `latitude`/`longitude` 값만 그 도시 좌표로 바꾸면 됩니다. (예: 서울 `37.57` / `126.98`)
4. 이 노드 화면에서 **`Test step`(이 단계만 실행)** 을 눌러 봅니다. 오른쪽 `OUTPUT`에 `daily` 안에 `temperature_2m_max`, `temperature_2m_min`, `precipitation_probability_max` 같은 값이 들어오면 API 연결 성공입니다.
5. **`메일 내용 만들기 (Set)` 노드를 클릭**합니다. `제목`과 `본문`에 `{{ $json.daily.temperature_2m_max[0] }}` 같은 표현이 들어 있는데, 이건 **바로 앞 노드가 받아온 날씨 값을 끼워 넣어라**라는 뜻입니다. 즉 숫자가 자동으로 채워집니다.
6. 이제 메일 부분입니다. **`메일 보내기 (Send Email)` 노드를 더블클릭**합니다. 여기만 직접 설정이 필요합니다.
   - **`Credential`(자격증명)**: `Create New Credential` 또는 기존 SMTP 자격증명을 고릅니다. 여기에 **내 메일 계정 정보(SMTP 서버 주소, 아이디, 비밀번호/앱 비밀번호)** 를 넣습니다. **이 비밀값은 노드 화면이 아니라 자격증명 금고에 저장됩니다.** (Gmail이면 보안 때문에 일반 비밀번호 대신 '앱 비밀번호'를 발급받아 넣어야 합니다.)
   - **`From Email`(보내는 사람)**: 내 메일 주소로 바꿉니다. (파일에는 `YOUR_SENDER_EMAIL@example.com` 자리표시자가 들어 있습니다.)
   - **`To Email`(받는 사람)**: 날씨를 받을 내 메일 주소로 바꿉니다. (`YOUR_RECEIVER_EMAIL@example.com` 자리표시자를 교체)
   - `Subject`와 `Text`는 이미 `{{ $json.제목 }}` / `{{ $json.본문 }}` 로 연결돼 있으니 건드리지 않아도 됩니다.
7. 전체 흐름을 한 번 점검합니다. 캔버스의 **`Test workflow`(전체 실행)** 버튼을 누릅니다. 모든 노드에 초록 체크가 뜨고, **내 메일함에 날씨 메일이 한 통 도착**하면 성공입니다.
8. 마지막으로, 사람이 안 눌러도 매일 오게 만듭니다. 캔버스 오른쪽 위의 **`Active`(활성) 토글을 켭니다.** 이제 매일 오전 7시가 되면 n8n이 알아서 이 흐름을 돌려 메일을 보냅니다.

## 🤖 바이브코딩 프롬프트

이 자동화를 AI(예: n8n의 AI Assistant, 또는 ChatGPT/Claude에게 JSON 구조를 물어볼 때)에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. n8n 노드 이름이나 표현식(`{{ $json... }}`)을 헷갈릴 때 특히 유용합니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 n8n 자동화 워크플로우를 설계하는 전문가야. 비전공자도 따라할 수 있게 도와줘.
  목표: "매일 아침 7시에 오늘 부산 날씨를 받아 내 이메일로 보내는" n8n 워크플로우를 만들고 싶어.
  제약:
  - 노드는 4개로 구성: Schedule Trigger(매일 오전 7시) → HTTP Request → Set → Send Email.
  - 날씨는 가입/API 키가 필요 없는 무료 API인 Open-Meteo(api.open-meteo.com)를 써줘. 부산 좌표(위도 35.18, 경도 129.08), 시간대 Asia/Seoul로.
  - 받아올 값: 오늘 최고기온, 최저기온, 비 올 확률.
  산출물: 각 노드를 어떤 순서로 추가하고 무엇을 설정해야 하는지 단계별 설명. 노드 이름과 핵심 파라미터를 표로 정리해줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  앞에서 만든 날씨 메일 워크플로우를 이어서 개선하고 싶어.
  1) HTTP Request로 받아온 날씨 값을 메일 본문에 끼워 넣어야 해. n8n에서 앞 노드의 값을 다음 노드에서 꺼내 쓰는 표현식 문법({{ $json... }})을 예시와 함께 알려줘. 예: 최고기온은 $json.daily.temperature_2m_max[0] 처럼 배열의 첫 번째 값을 써야 한다는 점도 설명해줘.
  2) 메일 비밀번호 같은 비밀값을 어디에 저장해야 안전한지(노드 파라미터 vs Credentials 금고) 이유와 함께 알려줘. Gmail이면 '앱 비밀번호'가 왜 필요한지도.
  3) 비가 올 확률이 60% 이상일 때만 "우산 꼭 챙기세요!" 문구를 추가하려면 어떻게 해야 할지 방법을 제안해줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  n8n 날씨 메일 워크플로우에서 에러가 났어. 단계별로 원인을 진단해줘.
  - 증상: (예) "메일은 오는데 본문에 27도 대신 {{ $json.daily.temperature_2m_max[0] }} 글자가 그대로 찍혀 나온다" / "Send Email 노드에서 인증(authentication) 에러가 난다" / "HTTP Request에서 빈 응답이 온다"
  - 내가 한 설정: (여기에 노드 설정이나 에러 메시지 전문을 붙여넣기)
  무엇부터 확인해야 하는지 우선순위대로 체크리스트를 만들어주고, 각 항목이 왜 문제가 되는지 비전공자가 이해하게 한 줄씩 풀어서 설명해줘.
  ```
> 프롬프트 팁: "코드/설정만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 그냥 따라 치는 대신 원리를 익히게 되어 학습에 좋습니다.

## 검증법

1. **API 연결 확인:** `오늘 날씨 가져오기 (HTTP Request)` 노드에서 `Test step`을 눌렀을 때 `OUTPUT`에 `daily.temperature_2m_max` 같은 숫자가 들어오면 정상입니다. 빨간 에러가 나면 URL이나 Query Parameters에 오타가 있는지 봅니다.
2. **값 끼워넣기 확인:** `메일 내용 만들기 (Set)` 노드 `OUTPUT`의 `본문`에 `{{ ... }}` 가 그대로 남아 있지 않고 **실제 숫자(예: 27도)** 로 바뀌어 있으면, 앞 노드 값을 잘 받아온 것입니다.
3. **메일 도착 확인(가장 확실한 증거):** `Test workflow`를 누른 뒤 **받는 메일함**을 확인합니다. 아래 같은 메일이 오면 성공입니다. (숫자는 그날 실제 날씨에 따라 달라집니다.)
   ```
   제목: 오늘(2026-06-18) 부산 날씨 알림

   좋은 아침입니다!

   오늘(2026-06-18) 부산 날씨를 알려드립니다.

   - 최고기온: 27도
   - 최저기온: 21도
   - 비 올 확률: 40%

   비 올 확률이 높으면 우산을 챙기세요. 좋은 하루 되세요!
   ```
4. **Active 켜짐 확인:** 캔버스 오른쪽 위 `Active` 토글이 **켜진(색이 들어온)** 상태인지 봅니다. 꺼져 있으면 시각이 와도 메일이 안 옵니다 — 가장 흔한 실수입니다.
5. **7시까지 못 기다릴 때(빠른 확인법):** Schedule Trigger 노드에서 `Trigger Interval`을 잠깐 **`Minutes`** 로 바꾸고 `Minutes Between Triggers`를 `1`로 두면 1분마다 돌아 메일이 옵니다. **확인이 끝나면 반드시 다시 `Days` / 7시 / 0분으로 되돌리세요.** (안 그러면 1분마다 메일 폭탄이 옵니다.)

## 핵심만 짚기 (디렉터 관점)

- **자동화는 '부품 잇기'입니다.** 트리거(언제 시작?) + 데이터 가져오기(무엇을?) + 행동(무엇을 한다?)을 레고처럼 잇는 게 전부입니다. 이번 흐름은 그 가장 표준적인 3단 구조입니다.
- **노드 사이의 데이터는 `{{ $json... }}` 로 흐릅니다.** 앞 노드가 만든 값을 뒤 노드가 꺼내 쓰는 이 문법 하나만 익히면, 어떤 노드든 자유롭게 이어 붙일 수 있습니다.
- **시간대(Timezone)와 좌표 주의:** '오전 7시'는 n8n 시간대 설정 기준입니다. 한국 시각으로 받으려면 n8n 시간대가 `Asia/Seoul`이어야 합니다. 날씨가 엉뚱한 도시로 나오면 `latitude`/`longitude` 좌표를 확인하세요.

## 보안 — anon(공개) vs 비밀값, 어디에 넣나

자동화에서 가장 자주 사고가 나는 지점이 '비밀값을 잘못된 곳에 적는 것'입니다. 이 실습에는 두 종류의 값이 나옵니다.

- **공개해도 되는 값(노드에 그대로 둬도 됨):** 날씨 API 주소(`api.open-meteo.com`), 도시 좌표, 메일 제목/본문 문구. 이 Open-Meteo 창구는 **API 키 없이 누구나 부를 수 있는 공개 창구**라서 `workflow.json`에 그대로 적어도 안전합니다. (Supabase로 치면 브라우저에 노출돼도 되는 `anon`(공개) 키와 같은 성격입니다.)
- **새면 절대 안 되는 비밀값(반드시 금고에):** 메일 계정의 **SMTP 비밀번호(또는 앱 비밀번호)**. 이건 새어 나가면 내 메일 계정으로 남이 메일을 보낼 수 있는 위험한 값입니다. (Supabase로 치면 모든 권한을 가진 `service_role`(비밀) 키와 같은 급으로 다뤄야 합니다.) 그래서 이 값은 노드 화면이 아니라 n8n의 **`Credentials`(자격증명) 금고**에만 저장합니다. 금고에 넣어 두면 노드에서는 "내 메일 계정"이라는 이름표만 고를 뿐, 실제 비밀번호는 `workflow.json`에 절대 들어가지 않습니다.

> **그래서 이 파일의 비밀 자리에는 자리표시자만 들어 있습니다.** `workflow.json`의 `fromEmail`/`toEmail`은 `YOUR_..._EMAIL@example.com`, 자격증명 id는 `REPLACE_WITH_YOUR_SMTP_CREDENTIAL_ID`로 채워 두었습니다. 실제 값으로 바꿔 쓰되, **진짜 비밀번호를 노드 파라미터나 파일 본문에 적는 일은 절대 하지 마세요.**

> **한 줄 원칙:** 공개해도 되는 값(API 주소·좌표·문구)은 노드에, 새면 안 되는 값(메일 비밀번호·API 키·토큰)은 `Credentials` 금고에.
