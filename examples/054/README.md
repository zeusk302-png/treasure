# 히어로+내비+카드+푸터를 합친 랜딩페이지 한 장 조립

지금까지 따로따로 배운 조각들이 있습니다. **내비게이션 바**(033~035), **히어로 배너**(043), **카드 그리드**(041, 047), **푸터**. 이 예제는 그 조각들을 한 파일에 **위에서 아래로 차곡차곡 쌓아** 진짜 제품처럼 보이는 한 장짜리 랜딩페이지(소개 페이지)로 조립합니다.

핵심은 새 문법이 아니라 **순서와 흐름**입니다. 방문자가 페이지를 위에서 아래로 읽어 내려가는 자연스러운 동선(메뉴 → 첫인상 → 기능 소개 → 가격 → 연락처)을 섹션으로 나누어 만드는 감각을 익힙니다. 예제 주제는 "모두의 가계부"라는 가상의 앱입니다.

## 목표

- 페이지를 **내비바 → 히어로 → 카드 → 요금 → 푸터** 다섯 개의 의미 있는 섹션(`header` / `section` / `footer`)으로 나누어 쌓는 흐름을 이해한다.
- 각 섹션을 만들 때 어떤 레이아웃 도구를 쓰는지 구분한다: 내비바·푸터는 **flex**(가로 배치/양끝 정렬), 카드 묶음은 **grid**(자동 줄바꿈 격자).
- `auto-fit` + `minmax()`로 화면 너비에 따라 카드 열 수가 **자동으로** 늘고 주는 반응형 격자를 적용한다.
- `@media`(미디어쿼리)로 좁은 화면(휴대폰)에서는 메뉴를 숨기고 푸터 칼럼을 세로로 쌓아, 모바일에서도 깨지지 않게 만든다.
- `#id` 앵커 링크로 내비바·버튼을 누르면 해당 섹션으로 이동하게 연결한다.

## 따라하는 단계

1. `054` 폴더 안의 `index.html`을 마우스로 더블클릭해 브라우저(크롬 등)로 엽니다. 같은 폴더의 `style.css`가 자동으로 함께 불러와집니다. (두 파일은 반드시 같은 폴더에 있어야 합니다.)
2. 화면을 천천히 아래로 스크롤하며 **다섯 덩어리**를 눈으로 확인합니다: 맨 위 고정 메뉴 → 파란 히어로 → 카드 3개 → 요금 박스 → 어두운 푸터.
3. **섹션의 뼈대 보기**: `index.html`에서 주석 `① 내비게이션 바`, `② 히어로`, `③ 카드 그리드`, `④ 요금 안내`, `⑤ 푸터`를 찾습니다. 각 덩어리가 `<header>`, `<section>`, `<footer>` 태그로 깔끔히 나뉘어 있는 것을 봅니다. 랜딩페이지는 이렇게 "의미 있는 큰 상자"를 쌓는 일입니다.
4. **고정 메뉴 확인**: 페이지를 아래로 내려도 상단 메뉴가 따라옵니다. `style.css`의 `.nav` 규칙에서 `position: sticky;`와 `top: 0;`이 그 역할을 합니다.
5. **자동 줄바꿈 카드 체험**: 브라우저 창의 **가로 폭을 마우스로 천천히 줄였다 늘렸다** 해 봅니다. 카드가 3개 → 2개 → 1개로 자동으로 줄을 바꿉니다. `style.css`의 `.cards`에 있는 `grid-template-columns: repeat(auto-fit, minmax(260px, 1fr));`이 이 마법을 담당합니다. (`260px`를 `200px`로 바꿔 저장(Ctrl+S)·새로고침(F5)하면 더 잘게 들어갑니다.)
6. **모바일 모습 확인**: 창을 휴대폰처럼 아주 좁게 줄이면 가운데 메뉴가 사라지고 푸터가 세로로 쌓입니다. `style.css` 맨 아래 `@media (max-width: 640px)` 부분이 좁은 화면에서만 적용되는 규칙입니다.
7. **앵커 링크 확인**: 상단 메뉴의 "요금"이나 히어로의 "기능 둘러보기" 버튼을 누르면 해당 섹션으로 화면이 이동합니다. 버튼의 `href="#price"`와 섹션의 `id="price"`가 짝을 이루기 때문입니다.
8. **내 것으로 바꿔 보기**: `index.html`에서 앱 이름(모두의 가계부), 카드 3개의 제목·설명, 요금 숫자를 본인 아이디어로 고쳐 봅니다. `style.css`의 `:root` 안 `--brand: #4f7cff;` 색 코드를 바꾸면 페이지 전체 포인트 색이 한 번에 바뀝니다.

## 검증법

- 위에서 아래로 **내비바 → 히어로 → 카드 → 요금 → 푸터** 다섯 덩어리가 순서대로 보이면 조립 성공입니다.
- 창 폭을 줄였다 늘렸을 때 카드가 **숫자가 바뀌며 자동 줄바꿈**되면 `auto-fit` + `minmax`가 제대로 작동하는 것입니다.
- 휴대폰 너비로 줄였을 때 글자가 화면 밖으로 **넘치거나 가로 스크롤이 생기지 않으면** 반응형이 잘 된 것입니다.
- 스크롤을 내려도 상단 메뉴가 **계속 따라오면** sticky가 적용된 것입니다.
- 메뉴/버튼을 눌렀을 때 해당 섹션으로 **이동하면** 앵커 링크가 연결된 것입니다.
- F12(개발자 도구)의 **콘솔(Console)** 탭에 빨간 오류 메시지가 없으면 코드가 깨진 곳 없이 잘 작동하는 것입니다.
