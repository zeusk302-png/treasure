# 실습 114 — Supabase 프로젝트 만들고 첫 테이블(memos) 생성하기

지금까지는 데이터를 **localStorage**(내 브라우저 안 서랍)에만 저장했습니다.
이번 실습부터는 **진짜 서버 데이터베이스(DB)** 의 세계로 들어갑니다.
첫걸음은 거창한 코딩이 아니라, **Supabase에 가입해 프로젝트를 만들고, 마우스 클릭만으로 표(테이블) 하나를 만들어 보는 것**입니다.
"내 컴퓨터가 아니라 인터넷 어딘가(서버)에 표가 하나 생겼다"는 감각을 얻는 게 목표예요.

> 비유: 지금까지는 내 책상 서랍(localStorage)에 메모를 넣었어요.
> 이제는 누구나 같은 걸 볼 수 있는 **중앙 창고(서버 DB)** 에 선반 하나(memos 표)를 짜 넣는 겁니다.

이 폴더에 있는 파일:

- `README.md` — 이 안내문 (가입 → 프로젝트 → 표 만들기 전 과정)
- `column-plan.md` — 제출물인 **컬럼 설계 메모** (어떤 칸을 왜 만드는지 정리)
- `schema.sql` — 클릭(GUI) 대신 **SQL로 똑같은 표를 만드는 코드** (선택/검증용)

## 목표

- Supabase에 **가입**하고 **새 프로젝트**를 1개 만든다. (프로젝트 = 내 DB가 사는 집 한 채)
- **Table Editor(표 편집기)** 로 `memos` 테이블을 만들고, 컬럼 3개를 설계한다.
  - `id`(자동 번호), `content`(메모 글자), `created_at`(만든 시각)
- "데이터가 내 브라우저가 아니라 **서버에 저장된다**"는 것을 대시보드에서 눈으로 확인한다.
- 컬럼을 왜 그렇게 설계했는지 `column-plan.md`에 **내 말로** 정리한다.

## 따라하는 단계

1. 브라우저에서 **https://supabase.com** 에 접속하고 오른쪽 위 **[Start your project]** 를 누른다.
2. **GitHub 계정** 또는 이메일로 **가입/로그인** 한다. (무료 플랜으로 충분합니다.)
3. 대시보드에서 **[New project]** 를 누른다.
   - **Name(프로젝트 이름)**: `my-first-db` 처럼 알아보기 쉽게.
   - **Database Password(DB 비밀번호)**: 자동 생성 버튼을 쓰고, **메모장에 따로 안전하게 보관**한다. (화면이나 코드에 적어 두지 않기)
   - **Region(지역)**: `Northeast Asia (Seoul)` 처럼 한국과 가까운 곳을 고른다.
   - **[Create new project]** 클릭 → 1~2분 정도 "설정 중" 표시를 기다린다.
4. 본격적으로 표를 만들기 전에, 이 폴더의 `column-plan.md`를 먼저 열어 **어떤 컬럼을 만들지** 눈으로 익힌다.
5. 왼쪽 메뉴에서 **Table Editor**(표 모양 아이콘)를 누른 뒤 **[New table]** 또는 **[Create a new table]** 를 클릭한다.
6. 표 기본 정보를 입력한다.
   - **Name(표 이름)**: `memos`
   - **Description(설명, 선택)**: `한 줄 메모 저장용 첫 테이블`
   - **Enable Row Level Security (RLS)** 체크박스가 보이면, 이번 연습에서는 일단 **체크를 해제**한 채로 진행한다. (나중에 실습 119에서 켜는 법을 배웁니다.)
7. 컬럼을 설계한다. Supabase가 기본으로 `id`와 `created_at`을 미리 넣어 줍니다. 우리는 여기에 **메모 내용 칸 하나만 추가**하면 됩니다.
   - `id` : 기본 그대로 둔다. (타입 `int8`, **Primary key 체크**, 자동 증가 = "겹치지 않는 번호표")
   - `created_at` : 기본 그대로 둔다. (타입 `timestamptz`, 기본값 `now()` = "저장하는 순간 시각 자동 기록")
   - **[+ Add column]** 을 눌러 새 칸을 추가한다.
     - **Name**: `content`
     - **Type**: `text` (글자)
     - **Default value**: 비워 둔다.
     - **Allow Nullable(빈 값 허용)** 체크를 **해제** 한다. → 내용 없는 빈 메모를 막는다.
8. **[Save]** 를 눌러 표를 만든다. Table Editor에 빈 `memos` 표(칸 3개)가 나타나면 성공.
9. 시험 삼아 한 줄을 직접 넣어 본다. **[Insert] > [Insert row]** 를 누르고 `content`에 `나의 첫 번째 메모입니다!` 를 입력한 뒤 **[Save]**.
   - `id`와 `created_at`은 **건드리지 않아도** 자동으로 채워지는 것을 확인한다.
10. (선택, 코드로 만들고 싶다면) 7~9단계 대신 왼쪽 **SQL Editor** 에서 이 폴더의 `schema.sql` 내용을 붙여넣고 **[Run]** 해도 똑같은 표가 만들어진다.
11. 이 폴더의 `column-plan.md`의 빈칸/표를 **내 말로** 채워 제출물을 완성한다.

## 🤖 바이브코딩 프롬프트

이 실습은 '코딩'보다 **설계(어떤 칸을 왜 만들지)와 검증**이 핵심입니다.
표 자체는 Supabase 대시보드에서 클릭으로 만들지만, AI에게 **설계를 점검받고 SQL로 정확히 만들도록** 시키면 더 빠르고 안전합니다. 아래 프롬프트를 복사해 쓰세요.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 Supabase/PostgreSQL 초보를 돕는 멘토야. 나는 비전공자고, '한 줄 메모'를 서버 DB에 저장할 첫 테이블을 만들려고 해.
  - 표 이름: memos
  - 필요한 칸: 자동 증가하는 고유 번호(id), 메모 내용 글자(content, 빈 값 금지), 만들어진 시각(created_at, 자동 기록)
  요청: 위 조건에 맞는 CREATE TABLE SQL을 Supabase SQL Editor에 그대로 붙여넣을 수 있게 만들어 줘.
  제약: id는 자동 증가 + 기본키, content는 NOT NULL, created_at은 기본값 now()로. 각 줄이 무슨 역할인지 한국어 주석으로 한 줄씩 설명해 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 memos 표를 다듬고 싶어.
  1) 표와 각 컬럼에 한국어 설명(COMMENT)을 달아서 나중에 표만 봐도 무슨 칸인지 알게 해 줘.
  2) 표가 잘 만들어졌는지 확인용으로 시험 데이터 1줄을 넣고(content만 채우고 id/created_at은 자동) 전체를 조회하는 SQL도 같이 줘.
  3) 이 표를 나중에 웹에서 공개로 쓸 때 위험한 점(RLS 꺼짐)과, 지금 단계에서 뭘 주의해야 하는지 비전공자가 알아듣게 설명해 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  Supabase SQL Editor에서 표를 만들다가 에러가 났어. 내가 실행한 SQL과 에러 메시지를 그대로 붙일게.
  [여기에 내 SQL 전체]
  [여기에 빨간 에러 메시지 전체]
  부탁: (1) 이 에러가 무슨 뜻인지 비전공자 말로 풀어 주고, (2) 가장 흔한 원인 순서로 점검 목록을 주고, (3) 고친 SQL 전체를 다시 줘. 'relation already exists'처럼 표가 이미 있다는 에러면 안전하게 다시 만드는 방법도 알려 줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법

- Table Editor에 **`memos`** 표가 보이고, 컬럼이 **`id` / `content` / `created_at`** 세 개인가?
- `id`에 **열쇠(🔑) 아이콘**(Primary key)이 붙어 있는가? 행을 추가할 때 **자동으로 번호가 채워지는가?**
- `content`를 **비운 채로** 행을 저장하려 하면 **거부되는가?** (Not Null이 잘 걸렸다는 뜻)
- 행을 추가할 때 `created_at`을 직접 안 적어도 **현재 시각이 자동으로 들어가는가?**
- 9단계에서 넣은 메모가 표에 **한 줄로 보이는가?** (이게 "서버에 저장됐다"의 증거)
- (선택) **새로고침**하거나 **다른 브라우저/기기**로 같은 Supabase 대시보드에 로그인해도 그 메모가 **그대로 보이는가?**
  → localStorage와 달리 서버에 있으니 **어디서 봐도 똑같이 보이는** 게 핵심 차이입니다.
- `column-plan.md`의 컬럼 설계 표와 빈칸을 모두 채웠는가?
