# 188 — canonical 태그로 대표 주소 한 개 지정하기

내가 만든 페이지 **한 개**가, 실제로는 **여러 개의 주소(URL)** 로 열릴 수 있다는 사실을 알고 계셨나요?

- `https://내사이트.com/`
- `https://www.내사이트.com/` (앞에 `www`만 붙음)
- `https://내사이트.com/index.html` (`index.html`까지 붙음)
- `https://내사이트.com/?utm_source=kakao` (카톡 광고용 꼬리표가 붙음)

사람 눈에는 **다 똑같은 한 페이지**입니다. 하지만 검색엔진(구글·네이버) 로봇은 이걸 **서로 다른 페이지 4개**로 착각할 수 있습니다.
그러면 "검색 점수"가 4갈래로 **쪼개져서** 어느 주소도 상위에 못 올라가는 손해가 생깁니다.

`canonical`(캐노니컬, 대표 주소) 태그는 이 문제를 막아 줍니다.
`<head>` 안에 딱 한 줄을 넣어서 **"이 페이지의 진짜 대표 주소는 바로 이거예요"** 하고 한 개를 콕 집어 알려 주는 것입니다.

- 카테고리: SEO·성능·접근성 (코드 I)
- 난이도: 2 / 5
- 개념: canonical, 중복 URL 정리
- 결과물: **canonical 링크가 포함된 HTML `<head>`** (이 폴더의 `index.html` 안에 들어 있습니다)

> 이 폴더의 **`index.html`** 을 열어 `<head>` 안의 `<link rel="canonical" ...>` 한 줄을 확인하세요.
> 그대로 쓰지 말고, 주소를 **내 사이트 주소로 바꿔서** 쓰면 됩니다.

---

## 목표

외울 건 **딱 한 줄**입니다.

```html
<link rel="canonical" href="https://내사이트.com/" />
```

이 한 줄을 페이지의 `<head>` 안 (`<title>` 근처)에 넣으면 됩니다. 의미를 풀면 이렇습니다.

| 부분 | 뜻 |
|---|---|
| `<link>` | "이 페이지와 관련된 다른 정보를 연결한다"는 태그 |
| `rel="canonical"` | 연결의 종류가 **"대표 주소 지정"** 이라는 표시 |
| `href="https://내사이트.com/"` | **진짜 대표로 칠 전체 주소** (이게 핵심) |

> 비유: canonical은 한 사람이 여러 별명(`철수`, `철수야`, `김철수`)으로 불릴 때
> **"제 진짜 본명은 김철수예요"** 라고 한 번 정해 주는 것과 같습니다.
> 검색엔진은 별명들로 흩어진 점수를 **본명(대표 주소) 하나로 모아** 줍니다.

지켜야 할 약속 세 가지만 기억하세요.

1. **`href`에는 `https://`로 시작하는 전체 주소**를 적습니다. (`/about` 처럼 짧게 쓰면 무시됩니다.)
2. **한 페이지에는 canonical을 한 개만** 넣습니다. (두 개를 넣으면 검색엔진이 둘 다 무시할 수 있습니다.)
3. **대표 주소는 실제로 열리는 정상 주소**여야 합니다. (오타·없는 페이지를 적으면 역효과.)

> 보안 메모: canonical 태그는 **비밀과 전혀 상관없는 공개 정보**입니다.
> 여기에는 페이지 주소만 들어가며, 비밀번호·API 키·Supabase의 `service_role` 키 같은 **비밀값은 절대 넣지 않습니다.**
> (애초에 `<head>`는 누구나 "페이지 소스 보기"로 볼 수 있는 공개 영역이라, 어떤 비밀값도 넣으면 안 됩니다.)

## 따라하는 단계

### 1단계 — 이 폴더의 index.html 열어 보기

1. 이 폴더(`examples/188/`)의 **`index.html`** 을 메모장이나 VS Code로 엽니다.
2. 위쪽 `<head>` 안에서 아래 줄을 찾습니다.
   ```html
   <link rel="canonical" href="https://내사이트.com/" />
   ```
3. 이 한 줄이 바로 "대표 주소 지정"입니다. `<title>` 바로 아래에 있는 것을 눈으로 확인하세요.

### 2단계 — 내 사이트 주소로 바꾸기

1. `href` 안의 **`https://내사이트.com/`** 를 **내 실제 대표 주소**로 바꿉니다.
   - 예: `https://my-portfolio.vercel.app/`
   - 소개 페이지라면 `https://my-portfolio.vercel.app/about`
2. 대표 주소를 **하나로 통일**해서 정합니다. 아래 둘 중 하나로 **팀/나만의 규칙**을 정해 쭉 지키면 됩니다.
   - `www` 없이: `https://내사이트.com/`  ← (Vercel 기본은 보통 이 형태)
   - `www` 붙여서: `https://www.내사이트.com/`
3. 끝의 슬래시(`/`)와 `index.html` 여부도 **한 가지로만** 적습니다. (`https://내사이트.com/` 권장)

> 헷갈리지 마세요: canonical은 "내가 정한 **대표 주소 하나**"를 적는 곳입니다.
> www가 붙은 주소와 안 붙은 주소 둘 다 같은 내용이어도, canonical에는 **둘 중 하나만** 적습니다. 그래야 점수가 한 곳으로 모입니다.

### 3단계 — 페이지마다 자기 자신의 주소를 적기

canonical은 보통 **"그 페이지 자신의 대표 주소"** 를 적습니다. (이걸 "자기 참조 canonical"이라고 부릅니다.)

- 홈(`index.html`)의 head → `href="https://내사이트.com/"`
- 소개 페이지(`about.html`)의 head → `href="https://내사이트.com/about"`
- 블로그 글 페이지의 head → `href="https://내사이트.com/blog/첫-글"`

즉, **페이지를 새로 만들 때마다** 그 페이지 head에 자기 주소로 canonical을 한 줄씩 넣어 주면 됩니다.

### 4단계 — 배포하고 소스 보기로 확인

1. 평소처럼 배포(예: Vercel에 push)합니다.
2. 배포된 페이지를 브라우저로 연 뒤, **마우스 오른쪽 버튼 → "페이지 소스 보기"**(또는 `Ctrl + U`)를 누릅니다.
3. `<head>` 안에 canonical 줄이 **그대로** 들어 있는지, 주소가 **내 실제 주소로 바뀌어** 있는지 확인합니다.

## 검증법

아래가 모두 맞으면 성공입니다.

- **소스에 한 줄이 보인다:** "페이지 소스 보기"를 했을 때 `<head>` 안에
  `<link rel="canonical" href="https://...">` 가 **딱 한 개** 보인다.
- **자리표시자가 안 남았다:** `href` 안에 `내사이트.com` 같은 **가짜 주소가 남아 있지 않고**, 전부 `https://`로 시작하는 내 실제 주소다.
  (올리기 전 `Ctrl + F`로 `내사이트.com`이 하나도 안 남았는지 확인하세요.)
- **그 주소가 진짜 열린다:** canonical에 적은 주소를 브라우저 주소창에 직접 넣으면 그 페이지가 **정상으로 열린다.** (404·오타면 안 됨.)
- **개수가 한 개다:** 한 페이지에 canonical 줄이 **여러 개 있지 않다.**
- **(추천) 구글 도구로 점검:** Google Search Console에서 그 페이지의 "URL 검사"를 하면
  "Google이 선택한 표준(canonical) URL"이 **내가 지정한 주소와 같은지** 확인할 수 있다.

> 흔한 실수
> - **자리표시자(`내사이트.com`)를 안 바꿈:** 가짜 대표 주소가 올라가 효과가 사라집니다.
> - **짧은 주소(`/about`)를 적음:** 반드시 `https://`로 시작하는 **전체 주소**여야 합니다.
> - **canonical을 두 개 넣음:** 검색엔진이 둘 다 무시할 수 있습니다. 한 페이지에 **딱 한 개**.
> - **모든 페이지에 똑같이 홈 주소만 적음:** 소개·블로그 페이지인데 canonical을 전부 `https://내사이트.com/`(홈)으로 적으면, 검색엔진이 "이 페이지들은 사실 홈이구나"로 오해해 **개별 페이지가 검색에서 사라질 수 있습니다.** 페이지마다 **자기 주소**를 적으세요.
> - **`<head>` 밖(`<body>` 안)에 넣음:** canonical은 반드시 `<head>` 안에 있어야 합니다.
