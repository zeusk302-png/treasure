# 실습 159 — 도서 검색 결과에 '다음 페이지' 페이지네이션 붙이기

책 제목이나 작가를 검색하면 결과가 **한 쪽(페이지)에 10권씩** 나오고, 아래 **[← 이전]·[다음 →]** 버튼으로 쪽을 넘기는 페이지를 만듭니다.

이 실습의 진짜 핵심은 한 가지 깨달음입니다.
> **검색 결과가 수천 권이어도 한 번에 다 받지 않는다.** 서버에 `page`(몇 쪽)와 `limit`(한 쪽에 몇 개)만 바꿔 부탁해, **쪽 단위로 조금씩** 받아온다.

> 비유: 사전에서 단어를 찾을 때, 사전 전체를 한꺼번에 펼쳐 들지 않습니다. **펼친 '한 쪽'만** 보고, 필요하면 **다음 장을 넘깁니다**. 페이지네이션이 바로 이 '한 쪽씩 넘기기'입니다.

이 데모는 키가 필요 없는 무료 공개 API만 씁니다.
- **Open Library 검색 API**(`https://openlibrary.org/search.json`): 책을 검색하는 무료 공개 API. 키 없음, 회원가입 불필요.
- 요청에 `page`(쪽 번호)와 `limit`(한 쪽 크기)를 붙이면, 응답에 그 쪽의 책 목록(`docs`)과 **전체 결과 수(`numFound`)**가 함께 옵니다.

그래서 **인터넷 연결만 있으면** 그대로 동작합니다. (가입·키·결제 모두 불필요)

## 목표
- **페이지네이션의 두 글자 `page`·`limit`**를 이해한다.
  - `page` = 몇 번째 쪽을 줄지 (Open Library는 1쪽부터 셈)
  - `limit` = 한 쪽에 몇 개를 줄지 (이 실습은 `PER_PAGE = 10`)
- **전체 쪽 수 계산법**을 익힌다: `Math.ceil(전체개수 / 한쪽크기)`.
  - 예) 결과 23권, 한 쪽 10권 → 23 / 10 = 2.3 → **올림하면 3쪽**. (올림을 안 하면 자투리 3권이 들어갈 마지막 쪽이 사라진다)
- **'지금 몇 쪽을 보고 있는지' 상태(state)를 변수로 기억**하는 패턴을 익힌다(`currentQuery`, `currentPage`, `totalPages`). [이전]/[다음]은 결국 이 숫자를 ±1 해서 같은 함수(`loadPage`)를 다시 부른다.
- **버튼 잠그기**: 첫 쪽에서는 [이전]을, 마지막 쪽에서는 [다음]을 `disabled`로 잠가, 있지도 않은 0쪽·11쪽을 요청하지 않게 한다.
- **새 검색은 항상 1쪽부터** 시작한다(검색어가 바뀌면 보던 쪽 번호는 의미가 없으므로 초기화).
- 결과 없음 / 서버 오류 / 인터넷 끊김을 **각각 다른 친절한 안내**로 처리한다(157·158에서 배운 `try/catch/finally`를 그대로 응용).

## 따라하는 단계
1. 이 폴더의 `index.html`을 더블클릭 → 브라우저에서 열린다. (검색은 인터넷에서 불러오므로 **인터넷 연결이 필요**합니다.)
2. 예시 칩 중 **[해리포터]**를 눌러 본다 → 잠깐 "불러오는 중…"이 뜬 뒤, **책 10권**이 목록으로 나오고, 아래에 **[← 이전] 2 / N [다음 →]** 막대가 생긴다.
3. 맨 처음에는 **[← 이전]이 흐리게 잠겨** 있는지 확인한다 (지금이 1쪽이라 더 이전이 없으므로).
4. **[다음 →]**을 눌러 본다 → 다른 책 10권으로 바뀌고, 가운데 표시가 **2 / N**으로 올라가며, 이제 **[← 이전]이 눌리게** 풀린다.
5. **[← 이전]**을 눌러 1쪽으로 돌아가 본다 → 다시 1쪽이 보이고 [이전]이 잠긴다.
6. **[다음 →]**을 계속 눌러 **마지막 쪽**까지 가 본다 → 마지막 쪽에서는 **[다음 →]이 흐리게 잠기는지** 확인한다 (더 다음 쪽이 없으므로).
7. 상태 줄에 **"총 ○○○권 중 N쪽을 보고 있어요"**가 뜨는지 본다 → `numFound`(전체 개수)를 읽어 보여 준다는 증거다.
8. **아무 의미 없는 글자**(예: `asdfqwerzxcv`)를 넣고 검색해 본다 → "검색 결과가 없어요"라는 **빨간 안내**가 뜨고 페이지 막대가 사라진다. (결과 없음 처리 확인)
9. `script.js`를 열고 **페이지네이션의 핵심 세 곳**을 직접 찾아본다.
   - 요청에 쪽을 붙이는 곳: `params.set("page", page)` 와 `params.set("limit", PER_PAGE)`
   - 전체 쪽 수 계산: `totalPages = Math.ceil(total / PER_PAGE)`
   - 버튼 잠그기: `prevBtn.disabled = currentPage <= 1` / `nextBtn.disabled = currentPage >= totalPages`
10. AI에게 시켜 보기 (디렉터 연습):
    > "이 `script.js`에서, 가운데 페이지 표시를 **`2 / 17` 대신 `1`·`2`·`3` … 같은 숫자 버튼 몇 개**로 바꿔서 한 번에 원하는 쪽으로 점프할 수 있게 해 줘. 단, **기존의 `loadPage(page)` 흐름, `Math.ceil` 전체 쪽 수 계산, `try/catch/finally`, 요청 중 버튼 잠금 구조는 그대로 유지**해 줘."

## 검증법
- 검색하면 결과가 **딱 10권씩** 나오는가? (한 번에 수백 권이 쏟아지지 않는가)
- 처음(1쪽)에는 **[← 이전]이 잠겨** 있고, **[다음 →]**을 누르면 **2 / N**으로 바뀌며 새 10권이 보이는가?
- **마지막 쪽**까지 가면 **[다음 →]이 잠기는가?** (있지도 않은 다음 쪽을 요청하지 않는가)
- 상태 줄에 **"총 ○○○권 중 N쪽"**처럼 전체 개수와 현재 쪽이 함께 보이는가?
- **의미 없는 글자**로 검색하면 "검색 결과가 없어요" **빨간 안내**가 뜨고, 페이지 막대가 숨겨지는가? (성공일 땐 초록, 실패일 땐 빨강으로 색이 다른가)
- **빈 칸**으로 [검색]을 누르면 "먼저 검색어를 입력해 주세요"가 뜨고, 헛된 요청을 보내지 않는가?
- 새 단어로 다시 검색하면 **항상 1쪽부터** 다시 시작하는가? (이전 검색의 쪽 번호가 그대로 남아 있지 않은가)
- `F12`(개발자 도구) → **Console 탭**을 열고 일부러 인터넷을 끊은 뒤 검색하면, 자세한 원인이 `도서 검색 실패: ...`로 **콘솔에만** 찍히고 화면에는 친절한 한 줄만 나오는가?

## 흔한 함정 (페이지가 어긋날 때 여기부터)
- **전체 쪽 수에 올림을 안 씀**: `total / PER_PAGE`를 그냥 쓰면 23/10 = 2.3 → 정수 부분 2쪽만 인정돼 마지막 자투리가 사라집니다. 반드시 **`Math.ceil`(올림)**을 씁니다.
- **쪽 번호 시작값 혼동**: Open Library의 `page`는 **1쪽부터**입니다. 0쪽을 요청하면 엉뚱한 결과가 옵니다. (어떤 API는 `offset=0`처럼 0부터 세니, 새 API를 쓸 땐 문서에서 시작값을 꼭 확인합니다.)
- **버튼을 안 잠금**: 1쪽에서 [이전]을, 마지막 쪽에서 [다음]을 누를 수 있게 두면 있지도 않은 쪽을 요청해 빈 화면이 됩니다. `disabled`로 막습니다.
- **새 검색 때 쪽 초기화를 안 함**: 5쪽을 보다가 다른 단어로 검색했는데 5쪽부터 보여 주면 어색합니다. 새 검색은 `loadPage(1)`로 **1쪽부터** 시작합니다.

## 공개 API와 비밀값 — 보안 메모
이 실습은 **키가 필요 없는 공개 API**(Open Library)만 써서, 브라우저 코드에 그대로 둬도 안전합니다.
하지만 **키가 필요한 유료/사설 API**로 바꾸면 이야기가 달라지므로 원칙을 정리해 둡니다.

- **공개되어도 되는 값**(예: Supabase의 `anon`(공개) 키, 키 없는 Open Library): 브라우저 코드에 들어가도 괜찮습니다. 단, 데이터 보호는 **RLS(행 수준 보안)**가 책임집니다. anon 키만 믿고 RLS를 끄면 누구나 데이터를 읽고 쓸 수 있어 위험합니다.
- **절대 노출하면 안 되는 비밀값**(예: Supabase의 `service_role` 키, 과금되는 유료 API 키): **브라우저 코드에 절대 넣지 않습니다.** 브라우저 코드는 `F12`로 누구나 들여다볼 수 있어, 비밀키를 넣으면 그대로 도둑맞아 **요금 폭탄·데이터 유출**로 이어집니다. `service_role` 키는 RLS를 **무시하고** 모든 데이터에 접근하므로, 오직 서버(또는 n8n 같은 자동화 도구의 자격 증명 저장소)에서만 다룹니다.
- 키가 필요한 검색 API로 바꾼다면: 브라우저 → **내 서버(또는 n8n 워크플로)** → 유료 API 순으로 호출해, 키는 서버 쪽에만 둡니다.
- 예제에 적을 때조차 진짜 키 대신 `YOUR_API_KEY` 같은 **자리표시자**만 둡니다.

```js
// 키가 필요한 '유료' 검색 API로 바꾸는 경우 — 이렇게 하면 안 됩니다 (브라우저에 키 노출!)
// const url = "https://api.example.com/books?key=진짜키&page=" + page;  // ❌ 금지

// 올바른 방향: 키는 코드에 넣지 말고 내 서버/n8n을 거쳐 호출합니다.
const API_KEY = "YOUR_API_KEY"; // ← 자리표시자. 실제 비밀키는 절대 브라우저 코드에 넣지 않는다.
// (이 키는 브라우저가 아니라 서버 환경변수에만 존재해야 합니다.)
```

> 정리: **이 실습의 Open Library는 키가 없으니 브라우저에서 직접 불러도 안전**합니다. 하지만 **키가 붙는 순간, 그 호출은 서버(또는 n8n) 뒤로 숨겨야** 합니다. 페이지네이션 자체(`page`·`limit`)는 공개든 비밀이든 똑같이 동작합니다.
