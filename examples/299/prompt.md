# 키 사용처 점검을 AI에게 시키는 프롬프트

아래 프롬프트를 그대로 복사해 AI(Claude)에게 붙여 넣으세요.
핵심은 **"추측하지 말고, 실제 파일·줄을 근거로만 보고"** 시키는 것입니다.
이 보고를 받아서 `audit-table.md`의 표를 채우면 이번 실습의 결과물이 완성됩니다.

---

## 1) 키 사용처 전수 조사 프롬프트 (복사해서 사용)

```
너는 보안 점검자야. 이 프로젝트의 모든 코드 파일을 훑어서, Supabase 키가
"어디서, 어떤 종류로" 쓰이는지 파일명과 줄 번호 단위로 보고해줘.

규칙:
1. 추측하지 말고, 실제로 파일에서 발견한 줄만 인용해. 줄 번호를 붙여.
2. 각 사용처를 다음 중 하나로 분류해:
   - anon / publishable (VITE_ 접두가 붙은 공개 키)
   - service_role / secret (접두 없는 비밀 키, RLS 우회)
3. 각 파일이 "브라우저로 전달되는 코드"인지 "서버에서만 도는 코드"인지도 적어.
   - 일반적으로 src/ 안의 .js/.jsx/.ts/.tsx 는 브라우저로 번들됨 → 공개
   - api/ 나 server/ 안의 코드는 서버에서만 돎 → 비공개
4. 마지막에 "service_role(secret) 키가 브라우저로 가는 코드(src/ 등)에서
   import 되거나 등장하는 곳이 한 군데라도 있는가?"에 예/아니오로 답해.
   있으면 그 줄을 🔴로 강조해서 모두 나열해.

출력은 다음 컬럼의 마크다운 표로:
| 키 종류 | 발견 위치(파일:줄) | 실행 환경(브라우저/서버) | 판정 |
판정은 🟢(안전) 또는 🔴(위험)으로만 표기해.
```

## 2) 위험만 다시 확인하는 짧은 후속 프롬프트

```
방금 조사에서 service_role(secret) 키가 브라우저로 가는 파일(src/ 등)에
단 한 군데라도 등장하면, 그 파일명·줄·코드 한 줄을 그대로 보여줘.
하나도 없으면 "service_role 노출 0건"이라고만 답해.
```

---

### 왜 이렇게 시키나요?
- AI는 시키지 않으면 "괜찮아 보여요" 같은 **두루뭉술한 답**을 합니다. 그래서 **파일·줄 근거**를 강제합니다.
- 우리가 진짜 알고 싶은 건 단 하나입니다: **service_role 키가 브라우저로 새는 곳이 0건인가?**
- 표로 받으면 그대로 `audit-table.md`에 옮겨 결과물(점검 표)을 만들 수 있습니다.
