# 실습 316 — 다크모드 토글(시스템 설정 연동) 만들기

내 페이지에 **다크모드**를 붙입니다. 처음 방문하면 사용자의 **운영체제(시스템) 다크모드 설정**을 그대로 따르고, **토글 버튼**으로 손수 바꾼 선택은 `localStorage`에 기억해 **새로고침하거나 다시 와도 유지**되게 만드는 것이 목표입니다. 색은 일일이 바꾸지 않고 **CSS 변수(디자인 토큰) 한 묶음**만 갈아끼워 페이지 전체를 한 번에 전환합니다.

> 한 줄 그림: **처음 방문 → "시스템이 다크인가?"를 물어봐 자동 적용 → 사용자가 버튼 클릭 → 라이트/다크 뒤집고 그 선택을 localStorage에 저장 → 다음 방문엔 저장된 선택을 먼저 따름**

> 비유: 다크모드는 방의 **조명 스위치**입니다. 처음 들어온 손님에겐 "지금 바깥이 밤이니 일단 어둡게" 알아서 맞춰주고(시스템 설정), 손님이 스위치를 직접 누르면 그 취향을 **메모해 뒀다가** 다음에 또 오면 그대로 켜 줍니다(localStorage).

## 목표
- **시스템 설정 자동 연동**: `prefers-color-scheme`로 OS가 다크모드면 처음부터 어두운 화면으로 뜬다.
- **수동 토글**: 버튼 한 번으로 라이트↔다크를 즉시 전환한다.
- **선택 기억**: 손으로 고른 테마를 `localStorage`에 저장해 새로고침/재방문에도 유지한다.
- **디자인 토큰으로 전환**: 색을 직접 박지 않고 CSS 변수 세트만 바꿔 페이지 전체 색을 한 번에 전환한다.
- **번쩍임(FOUC) 방지**: 화면이 그려지기 전에 테마를 먼저 결정해 "밝게 떴다 어두워지는" 깜빡임을 없앤다.

## 따라하는 단계

1. 이 폴더의 `index.html`을 브라우저로 엽니다(파일을 더블클릭해도 됩니다). 별도 설치·서버가 필요 없는 순수 정적 페이지입니다.
2. **시스템 연동 확인**: 아직 토글을 한 번도 누르지 않은 상태에서, PC/폰의 **운영체제 테마**를 라이트↔다크로 바꿔 봅니다. 페이지 색도 따라 바뀌면 `prefers-color-scheme` 연동이 동작하는 것입니다.
3. **수동 토글 확인**: 오른쪽 위 버튼을 누릅니다. 라이트↔다크가 즉시 바뀌고, 버튼의 아이콘(🌙/☀️)과 글자도 함께 바뀝니다.
4. **기억 확인**: 다크로 바꾼 뒤 **새로고침(F5)** 합니다. 다크가 그대로 유지되면 `localStorage` 저장이 잘 된 것입니다.
5. (원하면) `index.html` 안 `:root`와 `[data-theme="dark"]`의 색 변수 값을 바꿔, 내 브랜드 색으로 라이트/다크 톤을 직접 디자인해 봅니다.
6. 완성되면 정적 호스팅(예: GitHub Pages, Vercel, Netlify)에 그대로 올려 배포합니다.

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 프론트엔드를 가르치는 멘토야. 순수 HTML/CSS/JS 한 파일(index.html)로 "다크모드 토글" 데모를 만들어줘.
  요구사항:
  - 색은 직접 쓰지 말고 :root에 CSS 변수(디자인 토큰: --bg, --card, --text, --muted, --line, --accent)로 정의하고,
    [data-theme="dark"]에서 같은 변수의 값만 어두운 톤으로 덮어쓰는 구조로 해줘.
  - <html>의 data-theme 속성으로 라이트/다크를 전환하게 해줘.
  - 오른쪽 위에 토글 버튼을 두고, 누르면 라이트↔다크가 바뀌게 해줘.
  - 헤더, 카드 몇 개, 링크가 있는 샘플 화면도 같이 넣어줘.
  제약:
  - 외부 라이브러리/프레임워크 없이 순수 코드로만.
  - 비전공자가 읽을 수 있게, 각 핵심 코드에 "무엇을 하는지 + 왜 그렇게 했는지"를 한국어 주석으로 달아줘.
  - 식별자(변수/함수명)는 영어로.
  ```

- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 다크모드에 아래 3가지를 추가해줘. 각 추가 부분마다 한국어 주석으로 이유까지 설명해줘.
  1) 처음 방문 시 사용자가 고른 적이 없으면 window.matchMedia('(prefers-color-scheme: dark)')로
     시스템 다크모드 설정을 자동으로 따르게 해줘. (우선순위: localStorage 저장값 > 시스템 설정)
  2) 사용자가 토글로 고른 테마를 localStorage('theme')에 저장해서, 새로고침/재방문해도 유지되게 해줘.
  3) 화면이 그려지기 전에 테마를 먼저 적용해 "밝게 떴다가 어두워지는 깜빡임(FOUC)"이 없게,
     테마 결정 스크립트를 <head> 맨 위에 동기적으로 넣어줘.
  추가로 버튼에 aria-pressed를 갱신하고, 시스템 테마가 도중에 바뀔 때
  (사용자가 직접 고른 적이 없을 때만) 따라가게 matchMedia change 이벤트도 붙여줘.
  ```

- **막혔을 때(디버깅)** 프롬프트:
  ```text
  다크모드가 이상해. 아래 증상을 비전공자도 알게 단계별로 원인을 진단하고, 고친 코드와 이유를 알려줘.
  [증상 붙여넣기 예]
  - 새로고침하면 잠깐 흰 화면이 번쩍였다가 다크로 바뀐다.
  - 토글은 되는데 새로고침하면 항상 라이트로 돌아간다.
  - 시스템을 다크로 바꿔도 페이지가 안 따라간다.
  점검해줄 것: <head>의 테마 적용 스크립트가 body보다 먼저 실행되는지,
  localStorage.getItem/setItem('theme') 키 이름이 일치하는지,
  matchMedia('(prefers-color-scheme: dark)')를 제대로 읽는지,
  CSS 변수가 [data-theme="dark"]에서 실제로 덮어써지는지.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법
- **시스템 자동 연동**: 토글을 한 번도 누르지 않은 새 상태에서 OS 테마를 다크로 바꾸면 페이지도 어두워진다. (이미 토글을 눌러 선택을 저장했다면, 그 선택이 우선이라 시스템 변경을 따르지 않는 게 정상이다.)
- **수동 토글**: 버튼을 누를 때마다 라이트↔다크가 즉시 바뀌고, 버튼 아이콘(🌙↔☀️)·글자(다크모드↔라이트모드)도 같이 바뀐다.
- **선택 기억**: 다크로 바꾼 뒤 새로고침해도 다크가 유지된다. 개발자도구(F12) → Application → Local Storage에 `theme: dark`가 저장돼 있는지 확인한다.
- **깜빡임 없음**: 다크 상태에서 새로고침할 때 흰 화면이 번쩍이지 않는다. (번쩍이면 테마 스크립트가 body보다 늦게 실행되는 것.)
- **대비 확인**: 다크모드에서도 글자가 배경에 묻히지 않고 또렷하게 읽힌다(글자색 `--text` vs 배경 `--bg` 대비 유지).

## 파일 구성
- `index.html` — 다크모드 토글 데모 한 파일(HTML+CSS+JS 포함). CSS 변수 토큰, `prefers-color-scheme` 자동 연동, `localStorage` 저장, FOUC 방지 스크립트가 모두 들어 있다. 비밀값이 전혀 없는 순수 프론트엔드라 `.env`/`.gitignore`가 필요 없다.
