Pull Request로 미리보기 검토 후 라이브에 합치기

새 브랜치를 라이브에 바로 합치지 않고, Pull Request(PR)를 열어 Preview URL로 먼저 검토한 뒤, 마음에 들 때만 Merge해서 Production(라이브)에 반영하는 AI 작업물 안전 검수 흐름의 연습판입니다. 실제 GitHub/Vercel 화면을 흉내 낸 것이라 설치 없이 더블클릭으로 동작합니다.

0) 지금 상태 — 브랜치는 만들었고, Preview까지 떠 있습니다

앞 실습(176)에서 새 브랜치를 push해 Preview URL이 이미 생긴 상태입니다. 이번 실습은 "그 Preview를 검토하고 → 라이브에 합치는" 마지막 한 걸음입니다.

Production (라이브)

브랜치: main

https://my-site.vercel.app

진짜 손님이 보는 화면. 아직 옛날 버튼 색(파랑) 그대로입니다.

Preview (PR 미리보기)

브랜치: feature/new-hero

https://my-site-git-feature-new-hero-myname.vercel.app

PR에 자동으로 붙는 임시 주소. 바뀔 화면(초록 버튼)을 여기서 미리 봅니다.

1) Pull Request 열기 — "이 변경을 main에 합쳐 주세요"

PR은 "내 브랜치의 변경을 main에 합쳐도 될까요?"라는 공식 요청서입니다. 합치기 전에 무엇이 어떻게 바뀌는지 모두가 함께 검토할 수 있습니다.

● Open #42

버튼 색을 파랑에서 초록으로 변경

feature/new-hero → main

신청 버튼이 눈에 잘 안 띈다는 피드백을 반영해 버튼 색을 초록으로 바꿨습니다.
Preview URL에서 확인 부탁드립니다.

▲ Vercel 이 PR의 미리보기가 준비됐어요: https://my-site-git-feature-new-hero-myname.vercel.app Ready

Files changed (이 PR이 바꾸는 코드)

초록은 새로 들어온 줄(+), 빨강은 지워지는 줄(-)입니다. 딱 한 줄만 바뀝니다.

style.css
  .signup-btn {
-   background: #2563eb; /* 파랑 */
+   background: #16a34a; /* 초록 */
    color: #fff;
  }

2) 검토(Review) → 모두 확인해야 Merge가 열립니다

Merge는 되돌리기 번거로우니, 합치기 전에 꼭 점검합니다. 아래 4가지를 모두 체크하면 Merge 버튼이 활성화됩니다.

위 4가지를 모두 체크하면 열립니다

# Merge하면 GitHub와 Vercel에서 일어나는 일이 여기에 표시됩니다

3) 결과물 — 병합된 PR 1건 + 갱신된 라이브

이번 실습의 결과물(Deliverable)

  • PR #42: 상태가 Merged 로 바뀜 (검토 후 병합 완료)
  • 라이브(Production): https://my-site.vercel.app 의 버튼이 이제 초록
  • Preview: 역할을 다했으니 정리되어도 됩니다 (브랜치 삭제 시 함께 사라짐)

핵심: 라이브를 직접 손대지 않았는데도 검토를 거쳐 안전하게 반영됐습니다. AI가 만든 코드도 이렇게 PR로 받아 Preview에서 확인하고 합치면, 사고를 크게 줄일 수 있습니다.
