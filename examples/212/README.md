# AI 노드로 들어온 문의를 자동 분류·요약하는 간단 봇

지금까지는 사람이 직접 문의를 읽고 "이건 환불 건이네", "이건 버그 신고네" 하고 분류했습니다. 이번에는 그 판단을 **AI(Claude)에게 맡깁니다.** 문의 문장을 AI 노드에 넣으면, AI가 **카테고리 한 단어 + 한 줄 요약**을 만들어 돌려주고, 그 결과를 **Slack에 보기 좋게 올려** 줍니다.

핵심은 **"AI에게 무엇을, 어떤 형식으로 답하라고 시키느냐"** 입니다. 이걸 정해 주는 글이 **프롬프트**입니다. AI를 잘 부리는 사람은 코드를 더 잘 짜는 사람이 아니라, **지시(프롬프트)를 또렷하게 쓰는 사람**입니다. 이 실습이 바로 그 연습입니다.

> **AI 노드를 한마디로:** "이 문장을 읽고 이렇게 답해 줘" 라고 부탁하면, AI가 글로 답해 주는 **똑똑한 조수 노드**입니다. 우리는 "분류해 줘 + 요약해 줘 + JSON 형식으로 줘"라고 부탁합니다.
>
> **이 워크플로우는 노드 6개입니다.**
> `문의 받기 (Webhook)` → `AI로 분류·요약 (LLM Chain)` → `필요한 값만 추리기 (Set)` → `Slack에 올리기`
> 그리고 AI 노드 아래에 **`Claude 모델`** 과 **`JSON으로 정돈`** 두 개가 보조로 붙어 "어떤 AI로, 어떤 형식으로 답할지"를 정해 줍니다.

## 목표

- **AI(Claude) 노드**에 문의 문장을 보내고, AI가 분석해 답을 돌려주는 흐름을 직접 만든다.
- AI에게 **"카테고리 한 단어 + 한 줄 요약을, 정해진 JSON 형식으로"** 답하라고 지시하는 **프롬프트 설계**를 익힌다.
- AI가 돌려준 답에서 필요한 값만 꺼내 **Slack에 자동으로 정리해 올린다.**

## 따라하는 단계

1. **n8n에 로그인**합니다. (n8n Cloud 가입형 또는 직접 설치한 n8n 모두 가능. AI 노드를 쓰려면 비교적 최신 버전이 좋습니다.)
2. 화면 오른쪽 위 **`...`(점 3개) → `Import from File`** 을 눌러 이 폴더의 **`workflow.json`** 을 불러옵니다. 노드 6개가 나타납니다.
3. **Anthropic(Claude) 자격증명을 연결**합니다. 이게 있어야 AI 노드가 동작합니다.
   - 먼저 Anthropic 콘솔(console.anthropic.com)에서 **API 키**를 발급받습니다.
   - n8n에서 **`Claude 모델 (Anthropic Chat Model)` 노드를 더블클릭** → `Credential` 칸에서 **`Create New Credential`** → 발급받은 키를 붙여넣고 저장합니다.
   - **중요:** API 키는 `workflow.json` 파일에 적지 않습니다. n8n의 **자격증명 금고**에만 저장됩니다. (그래서 이 파일에는 `REPLACE_WITH_YOUR_ANTHROPIC_CREDENTIAL_ID` 같은 자리표시자만 들어 있습니다.)
   - 모델은 **`claude-opus-4-8`** 로 두면 됩니다.
4. **`AI로 분류·요약 (LLM Chain)` 노드를 더블클릭**해서 **프롬프트(지시문)** 를 읽어 봅니다. 이 실습의 핵심입니다.
   - 위쪽 **시스템 메시지**: "너는 분류 담당자다. 카테고리는 이 5개 중 하나만 골라라. 요약은 한 문장으로 해라. **반드시 JSON 형식으로만** 답해라." — AI에게 **역할과 규칙과 출력 형식**을 정해 주는 부분입니다.
   - 아래쪽 **사용자 메시지**: `{{ $json.body.message }}` — Webhook으로 들어온 **실제 문의 문장**이 이 자리에 끼워집니다.
5. **`Slack에 올리기` 노드를 더블클릭**합니다.
   - `Slack account` 자격증명을 연결하고(3단계와 같은 방식), 알림을 보낼 **채널 ID**를 넣습니다. (`REPLACE_WITH_YOUR_SLACK_CHANNEL_ID` 자리)
   - 메시지 본문에 `{{ $json.카테고리 }}` 와 `{{ $json.요약 }}` 가 들어가는 것을 확인합니다. AI가 만든 값이 여기로 흘러갑니다.
6. **Webhook 주소 정하기:** `문의 받기 (Webhook)` 노드를 열어 `Path` 칸의 자리표시자를 원하는 단어(예: `inquiry`)로 바꿉니다. n8n이 만들어 주는 **Test URL**을 복사해 둡니다.
7. **한 번 테스트하기:** 캔버스 위 **`Test workflow`** 를 누르면 n8n이 "문의가 오기를" 기다립니다. 이 상태에서 아래 검증법 1번처럼 가짜 문의를 한 번 보내 봅니다.

## 검증법

1. **가짜 문의 보내 보기.** 터미널(또는 [reqbin.com](https://reqbin.com) 같은 도구)에서 6단계의 Test URL로 아래처럼 POST 요청을 보냅니다. `<여기에_Test_URL>` 자리에 복사해 둔 주소를 넣으세요.
   ```bash
   curl -X POST "<여기에_Test_URL>" \
     -H "Content-Type: application/json" \
     -d '{"message": "어제 결제했는데 두 번 빠져나갔어요. 환불해 주세요."}'
   ```
2. **AI 노드 결과 확인.** `AI로 분류·요약 (LLM Chain)` 노드의 `OUTPUT`에 아래와 비슷한 모양이 나오면 AI가 지시대로 답한 것입니다. (문장에 따라 값은 달라집니다.)
   ```json
   {
     "output": { "category": "환불요청", "summary": "이중 결제로 인한 환불 요청" }
   }
   ```
3. **Slack 확인.** 지정한 채널에 이런 메시지가 떴으면 성공입니다.
   ```
   📥 새 문의가 도착했습니다.
   *카테고리:* 환불요청
   *요약:* 이중 결제로 인한 환불 요청
   ```
4. **모든 노드에 초록색 체크 표시**가 떴는지 확인합니다.
5. **다른 문의로 바꿔 보기.** 1번의 `message`를 `"다크 모드 기능도 만들어 주세요!"` 로 바꿔 다시 보내면, 카테고리가 `기능제안`으로 바뀌어야 합니다. **같은 워크플로우가 문장에 따라 다르게 판단**하는 것이 AI 노드의 핵심입니다.
6. **프롬프트가 결과를 바꾼다.** 4단계 시스템 메시지에서 카테고리 5개 중 하나(예: `버그신고`)를 지운 뒤 버그 관련 문의를 보내면, AI가 `기타`로 분류하거나 망설입니다. **지시(프롬프트)를 어떻게 쓰느냐가 결과를 결정한다**는 것을 직접 확인할 수 있습니다. (확인 후 원래대로 되돌리세요.)

## 핵심만 짚기 (디렉터 관점)

- **AI 노드의 품질 = 프롬프트의 품질.** 같은 Claude라도 "알아서 정리해 줘"라고만 하면 제멋대로 답합니다. **역할 + 규칙 + 출력 형식(JSON)** 세 가지를 또렷이 정해 줘야 다음 노드(Slack)가 받아 쓸 수 있는 깔끔한 답이 나옵니다.
- **출력 형식을 고정하는 게 자동화의 열쇠입니다.** AI가 매번 다른 문장으로 답하면 기계가 값을 꺼낼 수 없습니다. "반드시 `{"category": ..., "summary": ...}` 형식으로"라고 못 박고, `JSON으로 정돈` 보조 노드로 형식을 강제하면 항상 같은 자리에서 값을 꺼낼 수 있습니다.
- **흐름은 늘 같습니다:** 무슨 일이 생기면(Webhook) → AI에게 판단을 맡기고(AI 노드) → 결과를 사람이 보는 곳에 알린다(Slack). 사이의 AI 노드만 바꾸면 분류·요약 외에 번역, 답변 초안 작성 등 무엇이든 할 수 있습니다.

## 보안, 비밀값은 어떻게 다루나

- **API 키(Anthropic), Slack 토큰**은 새면 안 되는 비밀값입니다. 절대 `workflow.json`이나 노드 값에 직접 적지 마세요.
  - 올바른 방법: n8n의 **`Credentials`(자격증명) 금고**에 저장하고, 노드에서는 그 자격증명을 **고르기만** 합니다. 그러면 키는 금고에만 있고 파일에는 남지 않습니다.
  - 그래서 이 파일에는 실제 값 대신 `REPLACE_WITH_YOUR_ANTHROPIC_CREDENTIAL_ID`, `REPLACE_WITH_YOUR_SLACK_CREDENTIAL_ID` 같은 **자리표시자**만 들어 있습니다. 이 파일을 남에게 줘도 비밀이 새지 않습니다.
- **Webhook 주소도 일종의 비밀입니다.** 주소를 아는 사람은 누구나 우리 봇을 깨울 수 있으니, 추측하기 어려운 Path를 쓰고 외부에 함부로 공개하지 않습니다. (이 파일엔 `REPLACE_WITH_YOUR_WEBHOOK_PATH` 자리표시자만 있습니다.)
- 한 줄 원칙: **공개해도 되는 값은 노드에, 새면 안 되는 값(API 키·토큰)은 자격증명 금고에.**
