# 192 — 색 대비 검사로 흐린 텍스트 합격선까지 고치기

"디자인은 예쁜데 글씨가 잘 안 보여요." 이 말의 정체는 대부분 **색 대비(명도대비) 부족** 입니다. 흰 배경에 연한 회색 글씨, 연한 하늘색 버튼에 흰 글씨처럼 두 색의 밝기 차이가 작으면, 시력이 좋은 사람도 눈이 피로하고 저시력·고령 사용자나 밝은 햇빛 아래에서는 아예 못 읽습니다.

이걸 "느낌"이 아니라 **숫자**로 판정하는 국제 기준이 **WCAG AA** 입니다. 두 색의 밝기 비율을 1:1 ~ 21:1 사이 숫자로 재서, 이 숫자가 기준선을 넘으면 합격입니다.

| 글자 종류 | WCAG AA 합격선 |
|---|---|
| 일반 본문 글자 | **4.5:1** 이상 |
| 큰 글자(약 24px 이상, 또는 굵은 18.66px 이상) | **3:1** 이상 |

이 폴더는 같은 동네빵집 페이지에서 **(1) 일부러 흐리게 만든 "고치기 전" 영역**과 **(2) 색만 진하게 바꿔 합격시킨 "고친 후" 영역**을 나란히 두고, 마지막에 **합격선을 넘긴 색상 팔레트**를 결과물로 정리했습니다.

- 카테고리: SEO·성능·접근성 (코드 I)
- 난이도: 3 / 5
- 개념: 색 대비, WCAG AA, 가독성
- 결과물: **대비 합격선을 넘긴 색상 팔레트와 수정된 CSS** (`index.html` + `style.css`)

> 핵심은 단 하나입니다. **글자 크기·구조는 그대로 두고 "색"만 바꿉니다.** 비교 영역 두 곳의 HTML은 글자까지 똑같고, 다른 것은 CSS의 색뿐입니다.

---

## 목표

대비 검사 도구로 흐린 글자색을 측정하고, WCAG AA(본문 4.5:1)를 통과하도록 색을 조정해 봅니다.

핵심 비유 한 줄: **대비 = 글자와 배경의 "밝기 차이". 차이가 클수록 또렷하게 읽힌다.**

- **고치기 전(불합격) 예시**
  - 본문: `#999` 회색 글자 / 흰 배경 → **2.85:1** (4.5:1 미달, 불합격)
  - 버튼: 흰 글자 / `#9ec5f7` 연한 파랑 → **1.78:1** (불합격)
- **고친 후(합격) 팔레트 — 이 폴더의 결과물**
  - 제목: `#1a1a1a` / 흰 배경 → **17.4:1** (합격)
  - 본문: `#595959` / 흰 배경 → **7.0:1** (본문 4.5:1 통과)
  - 버튼: 흰 글자 / `#1d4ed8` 진한 파랑 → **6.7:1** (합격)
  - 강조/링크: `#b91c1c` / 흰 배경 → **6.5:1** (합격)

> 왜 색만 바꾸면 되나요?
> 대비는 "글자 색"과 "바로 뒤 배경 색" 두 가지로만 결정됩니다. 글꼴이나 크기를 키워도 색이 흐리면 여전히 불합격일 수 있고, 반대로 **색만 진하게 바꿔도 즉시 합격**할 수 있습니다. 그래서 가장 적은 노력으로 가독성을 올리는 방법이 "색 조정"입니다.

> 주의 — "큰 글자 3:1"의 함정
> 제목처럼 큰 글자는 기준이 느슨한 3:1입니다. 하지만 **본문은 무조건 4.5:1** 이어야 합니다. 본문에 "이 정도면 보이겠지" 하고 회색을 쓰다 불합격하는 경우가 가장 흔합니다.

## 따라하는 단계

### 1단계 — 완성본을 브라우저로 열어 차이 보기

1. 이 폴더(`examples/192/`)의 **`index.html`** 을 크롬 창에 드래그해 엽니다.
2. 위쪽 빨간 배지 **"고치기 전 · 불합격"** 영역의 본문 글자가 **흐려서 잘 안 보이는지** 확인합니다.
3. 아래 초록 배지 **"고친 후 · 합격"** 영역은 같은 문장인데 **또렷하게 읽히는지** 비교합니다. 두 영역의 차이는 오직 색뿐입니다.

### 2단계 — 대비 검사 도구로 직접 숫자 재기 (코딩 없이)

다음 중 편한 것 하나로 측정합니다.

- **온라인 검사기(가장 쉬움):** "WebAIM Contrast Checker"(webaim.org/resources/contrastchecker/) 같은 사이트에 들어갑니다.
  - **Foreground(글자색)** 칸에 `#999999`, **Background(배경색)** 칸에 `#ffffff` 를 넣습니다.
  - 결과에 **2.85:1** 과 함께 본문(Normal Text)이 **Fail(불합격)** 로 표시되는지 봅니다.
  - 이번엔 글자색을 `#595959` 로 바꿔 넣습니다. **7.0:1**, **Pass(합격)** 로 바뀌는지 확인합니다.
- **크롬 개발자도구로 재기:** `index.html`에서 `F12` → 왼쪽 위 화살표 아이콘으로 흐린 본문 글자를 클릭 → 오른쪽 **Styles** 패널에서 색상 칸을 누르면 **Contrast ratio(대비비)** 와 합격 여부가 그 자리에서 표시됩니다.

### 3단계 — 불합격 색을 합격 색으로 고치기

`style.css` 맨 위 `:root`에 색을 **변수(CSS 변수)** 로 모아 두었습니다. 실제 사이트라면 흐린 값을 합격 값으로 바꾸기만 하면 됩니다.

```css
:root {
  --text-body: #595959; /* 흰 배경 대비 7.0:1 (합격) */
  --btn-bg:   #1d4ed8;   /* 흰 글자 대비 7.0:1 (합격) */
}
```

- 이 파일에서는 "고치기 전" 영역(`.before`)에만 일부러 흐린 값(`--bad-text`, `--bad-btn-bg`)을 적용해 두었습니다. 비교가 끝났다면, 실제 사이트에서는 흐린 변수를 아예 지우고 합격 변수만 쓰면 됩니다.

### 4단계 — 색만 바꾸기 어려울 때의 대안

목표 색을 도저히 못 바꾸는 상황(브랜드 색이 연할 때 등)이라면:

1. **글자색이 아니라 배경색을 진하게** 바꿔도 대비는 올라갑니다. (둘의 밝기 차이만 키우면 됩니다.)
2. 연한 색을 꼭 써야 하면 그 위 글자를 **큰 글자(3:1 기준)** 로 만들거나 굵게 합니다.
3. 그래도 안 되면 그 색은 **장식(테두리·아이콘)** 으로만 쓰고, 읽어야 하는 글자에는 합격 색을 씁니다.

## 🤖 바이브코딩 프롬프트

이 실습(색 대비를 WCAG AA 합격선까지 고치기)을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. 색상값(HEX)은 모두 공개 정보이므로 비밀값 걱정 없이 그대로 붙여 넣어도 됩니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 웹 접근성을 챙기는 프론트엔드 개발자야.
  "동네빵집" 한 페이지를 index.html + style.css 두 파일로 만들어 줘.
  목적: 색 대비(WCAG AA)를 눈과 숫자로 비교해 보는 학습용 예제.
  - 같은 문구(제목 h2 + 본문 p + '주문하기' 버튼)를 가진 비교 영역 2개를 위아래로 둬:
    (1) "고치기 전 · 불합격" 영역: 본문은 연한 회색(#999), 버튼은 연한 하늘색 배경에 흰 글자.
    (2) "고친 후 · 합격" 영역: 위와 글자/크기는 똑같고 "색만" 진하게(본문 #595959, 버튼 배경 #1d4ed8).
  - 두 영역의 차이가 오직 색뿐임을 강조하고, 각 영역에 빨강/초록 배지를 달아 줘.
  - 색은 style.css 맨 위 :root에 CSS 변수로 모아 두고, 각 변수 옆에 흰 배경 대비 비율을 주석으로 적어 줘.
  - 비전공자가 읽을 거라 코드마다 "무엇을 하는지 + 왜 그렇게 했는지" 한국어 주석을 달아 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  좋아. 이제 페이지 맨 아래에 "합격선을 넘긴 색상 팔레트" 영역을 추가해 줘.
  - 색칠된 작은 사각형(swatch) + 용도(제목/본문/버튼/강조) + HEX 코드 + "흰 배경 대비 N:1" 을 한 줄씩 목록으로 보여 줘.
  - 본문은 4.5:1 이상, 큰 글자/제목은 3:1 이상이라는 AA 합격선 기준도 표기해 줘.
  - 버튼에 :focus-visible 외곽선을 넣어 키보드 사용자도 잘 보이게 해 줘(대비와 짝꿍인 접근성).
  - 추가한 색이 실제로 AA를 통과하는지 검증하는 방법(WebAIM Contrast Checker, 크롬 F12 Contrast ratio)도 README에 정리해 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  Lighthouse 접근성 검사에서 "Background and foreground colors do not have a sufficient contrast ratio"
  경고가 떴어. 아래 내 style.css를 붙여넣을게.
  - 어떤 글자/배경 조합이 4.5:1(본문) 또는 3:1(큰 글자)에 미달인지 찾아 줘.
  - 각 불합격 색의 현재 대비 비율과, 합격선을 넘기는 가장 가까운 대체 HEX 색을 제안해 줘.
  - 글자색 대신 배경색을 바꾸는 대안도 있으면 같이 알려 줘.
  - 왜 그 색이 불합격이었는지 비전공자가 이해하게 한 줄씩 풀어서 설명해 줘.
  [여기에 style.css 내용 붙여넣기]
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면, 색을 왜 그 값으로 바꿨는지까지 배울 수 있어 학습에 좋습니다.

## 검증법

아래가 모두 되면 이번 실습은 성공입니다.

- **눈으로:** `index.html`에서 "고친 후" 영역의 본문과 버튼 글자가 또렷하게 읽힌다.
- **숫자로(본문):** 본문 글자색 `#595959` / 흰 배경 `#ffffff` 의 대비가 **4.5:1 이상**(=7.0:1)으로 측정되어 **Pass** 가 뜬다.
- **숫자로(버튼):** 버튼 흰 글자 / 배경 `#1d4ed8` 의 대비가 **4.5:1 이상**(=6.7:1)으로 **Pass** 가 뜬다.
- **불합격 재현 확인:** "고치기 전" 본문 `#999999` / 흰 배경은 **4.5:1 미만**(=2.85:1)으로 **Fail** 이 뜬다. (왜 고쳐야 했는지 숫자로 설명 가능)
- **(선택) Lighthouse:** 크롬 개발자도구 → **Lighthouse** → **Accessibility(접근성)** 만 켜고 검사했을 때, "contrast(대비)" 관련 경고가 합격 색에서는 뜨지 않는다.
- **(개념 확인)** "본문 합격선은 4.5:1, 큰 글자는 3:1"과 "대비는 글자색과 배경색의 밝기 차이로 결정된다"를 한 문장으로 설명할 수 있다.

> 흔한 실수
> - **본문에 연한 회색을 씀:** 가장 흔한 불합격 원인입니다. 본문은 `#595959` 정도까지는 진하게 가야 안전합니다.
> - **'큰 글자 3:1'을 본문에 적용:** 본문은 작아서 무조건 4.5:1입니다. 3:1은 제목 같은 큰 글자 전용입니다.
> - **회색 위 회색, 색 위 색:** 흰 배경만 생각하다 실제로는 연한 회색 박스 위에 글자를 얹어 또 흐려지는 경우가 많습니다. 대비는 항상 **'바로 뒤 배경'** 기준으로 다시 재세요.
> - **placeholder(입력칸 흐린 안내문)를 본문 취급:** placeholder는 진짜 글자가 아니라 안내이지만, 너무 흐리면 안 보입니다. 입력값 색은 반드시 합격 색으로 두세요.

> 보안 메모: 이 실습에는 **비밀값이 전혀 들어가지 않습니다.**
> 색상값(HEX 코드)·HTML·CSS는 모두 브라우저로 그대로 내려받히는 **공개 정보** 입니다. 그래서 비밀번호, API 키, Supabase의 `service_role`(비밀) 키 같은 값은 색 팔레트나 페이지 어디에도 넣지 않습니다.
> 페이지에 노출해도 되는 값은 Supabase의 `anon`(공개) 키처럼 애초에 "공개용"으로 설계된 값뿐이지만, 이번 실습에서는 그조차 사용하지 않습니다.
