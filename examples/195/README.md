# 195. AI를 'SEO·접근성 감사관'으로 세우고, n8n으로 정기점검 자동화하기

검색 노출(SEO)과 모두가 쓸 수 있게 만드는 접근성(Accessibility)은 "느낌"이 아니라
**체크리스트로 채점**해야 빠뜨리지 않습니다. 이 실습은 두 가지를 합칩니다.

1. AI(Claude 등)에게 **고정된 채점 기준(seo-check)** 을 심어 **상시 감사관**으로 세우기 → [`prompt.md`](prompt.md)
2. 그 점검을 사람이 매번 시키지 않도록, n8n으로 **매주 자동으로 사이트를 열어보고** 문제가 있으면 메일로 알리기 → [`workflow.json`](workflow.json)

> 결과물은 두 파일입니다.
> - [`prompt.md`](prompt.md) — AI 감사관에게 그대로 붙여넣는 점검 프롬프트 템플릿
> - [`workflow.json`](workflow.json) — n8n에 Import 하면 바로 도는 정기점검 워크플로우(완성본)

## 목표

- AI에게 **12개 항목 체크리스트**를 먼저 심어, 매번 같은 잣대로 SEO·접근성을 채점하게 만든다.
- AI가 "채점표 → 고칠 곳 → 수정안" 순서로 보고하게 하고, **내가 승인한 항목만** 고치게 한다(선보고 후실행).
- n8n으로 **매주 월요일 9시**에 배포된 사이트를 자동으로 열어 `<title>`·`<meta description>`·`<html lang>`·`alt 없는 이미지`·응답 상태를 점검한다.
- 모두 통과하면 "통과 메일", 한 가지라도 빠지면 "경고 메일"이 오게 해 **디렉터의 상시 감사 체계**를 세운다.

## 따라하는 단계

### A. AI 감사관 세우기 (prompt.md)

1. [`prompt.md`](prompt.md)의 **1단계** 블록을 통째로 복사한다. 이게 감사관의 "채점 기준표"다.
2. 맨 아래 `(여기에 코드를 붙여넣기)` 자리에 내 `index.html` 전체를 붙여넣고 Claude에 보낸다.
3. AI가 **표로 12개 항목을 통과/경고/실패로 채점**하고, 고칠 곳을 우선순위로 정리해 주는지 확인한다. (이때 코드는 아직 고치지 않아야 정상)
4. 고치고 싶은 항목이 정해지면 **2단계** 승인 문장("좋아, 수정 진행해. 단 높음 항목만…")으로 하나씩 맡긴다.
5. 페이지가 여러 개면 **3단계**처럼 파일들을 한 번에 넣어 "페이지별 점수 요약표"부터 받는다.

### B. n8n 정기점검 자동화 (workflow.json)

6. n8n 클라우드에 로그인한다. 우측 위 **"..." 메뉴 → Import from File** 로 이 폴더의 [`workflow.json`](workflow.json)을 불러온다.
7. **"사이트 열어보기 (HTTP Request)"** 노드를 더블클릭해, `url` 의 `https://YOUR-SITE.vercel.app` 를 **내가 배포한 실제 주소**로 바꾼다.
8. **메일 보내기** 노드(통과/경고 2개)의 `YOUR_SENDER_EMAIL` / `YOUR_RECEIVER_EMAIL` 을 내 주소로 바꾼다.
9. 같은 메일 노드의 **Credential(SMTP)** 칸에서 내 메일 계정을 연결한다. (워크플로우의 `REPLACE_WITH_YOUR_SMTP_CREDENTIAL_ID` 는 자리표시자이므로, 실제 비밀번호는 n8n Credentials에만 저장하고 JSON에는 절대 적지 않는다.)
10. **"Test workflow"** 버튼을 눌러 한 번 수동 실행해 본다. 통과면 통과 메일, 문제가 있으면 경고 메일이 오는지 확인한다.
11. 잘 되면 화면 우측 위 토글을 **Active(켜짐)** 로 두어, 매주 월요일 9시에 자동으로 돌게 한다.
12. (확장) 더 깊은 성능 점수가 필요하면 [Core Web Vitals·Lighthouse](../../docs/05-deploy-ops-seo/05.md) 문서를 참고해, HTTP Request 단계 대신 Lighthouse/PageSpeed API 호출로 바꿔 점수까지 메일로 받는다.

## 🤖 바이브코딩 프롬프트

이 실습(AI 감사관 프롬프트 + n8n 정기점검 워크플로우)을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** — AI 감사관용 체크리스트 프롬프트부터 만들기:
  ```text
  너는 웹 SEO·접근성 교육 도우미야. 비전공자인 내가 내 사이트(index.html)를 매번 같은 잣대로 점검할 수 있도록,
  "SEO·접근성 감사관 프롬프트 템플릿"을 markdown 파일(prompt.md) 한 개로 만들어줘.

  [요구사항]
  - 감사 기준은 12개 항목 체크리스트로 고정한다. SEO 기본(title 길이, meta description, h1 1개, html lang, viewport, canonical)과
    접근성(img alt, input의 label, 링크 텍스트 명확성, 제목 위계 h1→h2→h3, 진짜 button/a 사용, 색 대비)을 모두 포함해.
  - 출력 형식을 강제해: ① 12개 항목을 "통과/경고/실패" 표로 채점 → ② 고칠 곳을 우선순위(높음/중간/낮음)로 정리 →
    ③ 내가 "수정 진행해"라고 말하기 전에는 코드를 절대 고치지 말 것(선보고 후실행).
  - 맨 아래에 "여기에 점검할 페이지 코드를 붙여넣기" 자리표시자를 둬.
  왜 그렇게 했는지(특히 출력 형식을 강제하는 이유)를 주석/설명으로 한 줄씩 풀어서 알려줘.
  ```
- **2단계(기능 추가/개선)** — 그 점검을 n8n으로 매주 자동화하기:
  ```text
  방금 만든 점검을 사람이 매번 시키지 않게, n8n 워크플로우(workflow.json)로 자동화해줘.

  [요구사항]
  - 노드 구성: 매주 월요일 9시 Schedule Trigger → HTTP Request로 내 사이트 HTML 받아오기(neverError로 죽지 않게) →
    Set 노드에서 정규식으로 title/meta description/html lang 존재 여부와 'alt 없는 img 개수', 응답 상태코드를 계산 →
    IF 노드로 "모두 통과인가" 판정 → 통과면 통과 메일, 하나라도 빠지면 경고 메일.
  - 메일 비밀번호·API 키는 JSON에 평문으로 절대 넣지 말고, n8n Credentials ID 자리표시자(REPLACE_WITH_...)로만 남겨.
  - 사이트 주소·보내는/받는 메일 주소는 YOUR_... 자리표시자로 둬서 사용자가 바꾸게 해.
  각 노드를 왜 그 순서로 뒀는지, neverError를 왜 켰는지 한 줄씩 설명해줘.
  ```
- **막혔을 때(디버깅)** — 워크플로우가 의도대로 안 돌 때:
  ```text
  n8n에서 위 워크플로우를 Test workflow로 실행했더니 이런 결과가 나왔어: (에러 메시지나 이상 동작을 그대로 붙여넣기)
  내 상황: 사이트는 브라우저에서 잘 열리는데 (예: 경고 메일이 안 온다 / IF가 항상 통과로만 간다 / Set 값이 전부 false 다).
  원인을 한 번에 고치지 말고, 가능성 높은 순서로 1)→2)→3) 단계별로 어디를 확인해야 하는지 알려줘.
  특히 HTTP Request의 fullResponse 옵션, Set 노드 정규식, IF 노드 combinator(and) 중 무엇이 문제인지 진단 절차를 줘.
  ```
> 프롬프트 팁: 위 프롬프트 끝에 "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면, 결과물을 그대로 베끼지 않고 '왜 이렇게 되는지'까지 배울 수 있습니다.

## 검증법

아래를 모두 만족하면 성공입니다.

- [ ] AI가 첫 답변에서 **12개 항목을 표로 채점**하고, 코드를 곧바로 고치지 않고 **수정 계획만** 보고했다.
- [ ] 내가 **"수정 진행해"라고 승인한 항목만** 바뀌고, 다른 태그·구조는 그대로다.
- [ ] [`workflow.json`](workflow.json)을 n8n에 Import 했을 때 **노드 6개**(Schedule → HTTP → Set → IF → 통과메일 / 경고메일)가 선으로 이어져 보인다.
- [ ] 수동 실행 시 모든 노드에 **초록 체크**가 뜬다. IF 노드는 통과/경고 중 **한쪽 가지로만** 흐른다.
- [ ] 일부러 사이트에서 `<meta name="description">` 를 지우고 다시 배포한 뒤 실행하면 **경고 메일**이 오고, 다시 넣으면 **통과 메일**로 바뀐다. (점검이 실제로 작동한다는 증거)
- [ ] JSON 어디에도 **실제 비밀번호·API 키가 평문으로 적혀 있지 않다.** 비밀값은 n8n Credentials 또는 자리표시자(`REPLACE_WITH_...`)로만 존재한다.

> 빠른 자가 점검: 워크플로우 JSON을 메모장으로 열었을 때, 메일 비밀번호가 보이면 위험합니다.
> n8n에서 비밀값은 노드가 아니라 **Credentials**(암호화 저장소)에 들어가야 합니다. 공유용 JSON에는 ID 자리표시자만 남깁니다.
