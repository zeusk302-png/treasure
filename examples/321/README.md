# 실습 321 — 스켈레톤 로딩 UI 만들기

데이터를 불러오는 동안 **빈 화면(흰 화면)** 대신, 콘텐츠가 들어올 자리에 **회색 뼈대(스켈레톤)**를 먼저 깔아 줍니다. 같은 시간을 기다려도 "뭔가 진행 중이다 / 곧 카드가 뜨겠구나"가 보이면 사람은 **더 빠르다고 느낍니다(체감 속도)**. 이 실습에서는 카드 목록을 불러오는 화면을 만들어, `로딩 중 → 스켈레톤` / `완료 → 진짜 콘텐츠` / `실패 → 다시 시도`까지 **로딩 상태 3종을 직접 설계**해 봅니다.

> 한 줄 그림: **버튼 클릭 → 로딩 시작(스켈레톤 뼈대 + 반짝임 표시) → 잠시 후 데이터 도착 → 스켈레톤을 진짜 카드로 교체 → (실패하면) 에러 + 다시 시도 버튼**

> 비유: 스켈레톤은 식당에서 주문하면 먼저 깔아 주는 **수저·물·앞접시 세팅**과 같습니다. 음식(진짜 데이터)은 아직 안 나왔지만, 자리가 차려지는 걸 보면 "준비되고 있구나" 싶어 덜 지루하죠. 흰 화면은 텅 빈 테이블에 아무도 안 오는 것과 같아 같은 시간도 더 길게 느껴집니다.

## 목표
- **스켈레톤 UI가 무엇인지** 이해한다: 콘텐츠가 들어올 자리의 모양(제목 줄, 본문 줄, 썸네일)을 회색 박스로 미리 그려 두는 기법.
- **로딩 상태 3종을 설계**한다: `loading`(스켈레톤) · `success`(진짜 데이터) · `error`(에러 + 재시도). 화면은 항상 이 셋 중 하나만 보인다.
- **체감 속도(perceived performance)**를 직접 느낀다: 똑같은 대기 시간이라도 빈 화면보다 스켈레톤이 더 빠르게 느껴지는 것을 비교한다.
- **레이아웃 흔들림(layout shift)을 막는다**: 스켈레톤을 진짜 콘텐츠와 같은 크기로 만들어, 데이터가 들어와도 화면이 덜컥 움직이지 않게 한다.
- **접근성 기본**을 챙긴다: 로딩 영역에 `aria-busy`를 주어, 화면을 못 보는 사람에게도 "지금 로딩 중"을 알린다.

## 따라하는 단계

### A. 파일 열고 그대로 실행해 보기
1. 이 폴더의 `index.html`을 브라우저로 그냥 엽니다(더블클릭). 서버 없이 동작합니다.
2. 화면의 **「불러오기」** 버튼을 누릅니다. 약 1.5초 동안 **회색 뼈대 카드들이 은은하게 반짝이다가**, 진짜 카드 6개로 바뀝니다.
3. **「실패 모드로 불러오기」** 버튼을 누르면, 일부러 실패시켜 **에러 메시지 + 다시 시도** 버튼이 뜨는 걸 봅니다.

### B. 코드가 어떻게 나뉘는지 보기
4. `index.html` — 화면 뼈대(헤더, 버튼, 카드가 들어갈 빈 영역 `#list`).
5. `style.css` — 스켈레톤의 핵심인 **회색 박스 + 반짝임(shimmer) 애니메이션**, 그리고 진짜 카드 디자인이 들어 있습니다.
6. `script.js` — 버튼을 누르면 `render('loading')`으로 스켈레톤을 깔고, (가짜) 데이터를 받아오면 `render('success')`로 진짜 카드로 교체하는 **상태 전환 로직**이 들어 있습니다.

### C. 직접 바꿔 보며 익히기
7. **개수 바꾸기**: `script.js`의 `SKELETON_COUNT`(스켈레톤 몇 개를 깔지)와 진짜 데이터 개수를 같게 맞추면, 교체될 때 화면이 안 흔들립니다. 일부러 다르게 해 보고 흔들림을 관찰해 보세요.
8. **대기 시간 바꾸기**: `FAKE_DELAY_MS`를 `300` → `3000`으로 바꿔, 느린 네트워크에서 스켈레톤이 얼마나 도움이 되는지 체감합니다.
9. **빈 화면과 비교하기**: 스켈레톤을 끄고 그냥 "로딩 중..." 글자만 보이게 한 버전과 번갈아 보면, 체감 차이가 분명해집니다.

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 프론트엔드 멘토야. 비전공자가 이해할 수 있게, 외부 라이브러리 없이
  순수 HTML/CSS/JavaScript로 "스켈레톤 로딩 UI" 예제를 만들어 줘.

  요구사항:
  - index.html / style.css / script.js 세 파일로 나눠 줘(서버 없이 더블클릭으로 동작).
  - 화면 구성: 상단에 "불러오기" 버튼, 그 아래 카드들이 들어갈 빈 영역 하나.
  - "불러오기"를 누르면 먼저 회색 스켈레톤 카드 6개를 깔고, 약 1.5초 뒤
    (setTimeout으로 가짜 데이터) 진짜 카드 6개로 교체해 줘.
  - 카드 한 장은 [썸네일 자리(직사각형)] + [제목 한 줄] + [본문 두 줄] 구조.
  - 스켈레톤 박스는 회색 + 좌우로 흐르는 shimmer(반짝임) 애니메이션을 CSS로.
  - 중요: 스켈레톤 카드와 진짜 카드의 크기를 똑같이 맞춰서, 교체될 때
    화면이 덜컥 움직이는 layout shift가 없게 해 줘.

  코드만 주지 말고, 초보가 막힐 만한 줄에는 "이게 무슨 기능이고 왜 넣었는지"를
  한국어 주석으로 한 줄씩 풀어서 달아 줘.
  ```

- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  위 스켈레톤 예제에 로딩 상태를 제대로 설계해서 추가해 줘.

  - 상태를 'loading' / 'success' / 'error' 세 가지로 명확히 나누고,
    render(state) 함수 하나가 상태에 따라 화면을 그리게 리팩터링해 줘.
  - "실패 모드로 불러오기" 버튼을 추가해서, 일부러 실패시키면 에러 메시지와
    "다시 시도" 버튼이 뜨게 해 줘. 다시 시도를 누르면 정상 불러오기를 재시도.
  - 접근성: 카드 목록 영역에 로딩 중이면 aria-busy="true"를 주고, 끝나면 false로.
  - 데이터를 화면에 넣을 때는 innerHTML 대신 textContent를 써서, 데이터에
    섞인 <script> 같은 게 실행되지 않게(XSS 방지) 해 줘. 그 이유도 주석으로.
  - prefers-reduced-motion(움직임 줄이기 설정)을 켠 사용자에게는 shimmer
    애니메이션을 끄도록 CSS에 미디어쿼리를 추가해 줘.
  ```

- **막혔을 때(디버깅)** 프롬프트:
  ```text
  스켈레톤이 진짜 카드로 바뀔 때 화면이 위아래로 덜컥 움직여(layout shift).
  아래 내 코드를 보고, 원인을 초보가 이해하게 한국어로 설명한 뒤,
  스켈레톤과 진짜 카드의 크기를 똑같이 맞추는 방향으로 고쳐 줘.
  콘솔에 에러가 있으면 그 줄도 짚어 줘.

  [여기에 style.css의 카드/스켈레톤 부분과 script.js를 붙여넣기]
  ```

> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법
- **상태 전환 확인**: 「불러오기」를 누르면 (1) 회색 스켈레톤이 먼저 뜨고 → (2) 잠시 후 진짜 카드로 바뀌는 **두 단계**가 눈에 보이는가? 느리게 보고 싶으면 `FAKE_DELAY_MS`를 `3000`으로 올린다.
- **에러 경로 확인**: 「실패 모드로 불러오기」를 누르면 스켈레톤 → **에러 메시지 + 다시 시도** 순서로 바뀌고, 다시 시도를 누르면 정상으로 복구되는가?
- **레이아웃 흔들림 확인**: 스켈레톤이 진짜 카드로 바뀌는 순간, 화면(특히 버튼 위치)이 **위아래로 덜컥 움직이지 않는지** 본다. 움직이면 스켈레톤과 카드의 높이가 다른 것이다.
- **반짝임(shimmer) 확인**: 스켈레톤 박스 위로 밝은 띠가 **좌→우로 흐르는** 애니메이션이 보이는가? (체감 속도를 올려 주는 핵심 디테일)
- **접근성 확인**: 브라우저 개발자도구(F12)로 `#list` 요소를 보면, 로딩 중에는 `aria-busy="true"`, 끝나면 `"false"`로 바뀌는지 확인한다.
- **XSS 안전 확인**: `script.js`에서 카드 텍스트를 넣는 부분이 `innerHTML`이 아니라 `textContent`인지 본다. (데이터에 `<script>`가 섞여도 실행되면 안 된다.)

## 파일 구성
- `index.html` — 화면 뼈대. 버튼들과 카드가 들어갈 빈 영역(`#list`)만 두고, 실제 내용은 JS가 그린다.
- `style.css` — 스켈레톤 박스 + shimmer(반짝임) 애니메이션, 진짜 카드 디자인, 에러 박스 스타일. 레이아웃 흔들림을 막는 크기 통일이 핵심이다.
- `script.js` — `render('loading'|'success'|'error')` 한 함수로 화면을 그리는 **상태 전환 로직**. 데이터는 가짜(setTimeout)로 흉내 낸다.
