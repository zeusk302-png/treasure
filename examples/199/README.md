# Webhook URL로 외부 요청 받아보기

n8n에 **Webhook 노드**를 두면, n8n이 나만의 **고유한 주소(URL)** 를 하나 발급해 줍니다. 그 주소를 브라우저나 다른 프로그램이 호출(=노크)하면, n8n이 잠에서 깨어나 **들어온 데이터를 받아** 화면에 보여 줍니다. 이 실습으로 "웹훅이 도대체 뭔지"를 몸으로 이해합니다.

> **웹훅(Webhook)을 한마디로:** "누가 이 주소로 노크하면, 그때 자동으로 일을 시작해" 라고 약속해 둔 **전용 초인종**입니다. 평소엔 가만히 있다가, 외부에서 그 주소를 부르는 순간 워크플로우가 깨어납니다.

## 목표

- Webhook 노드를 추가해 n8n이 발급해 주는 **나만의 고유 URL**을 받아 본다.
- 그 URL을 **브라우저 주소창으로 직접 호출**해서, 외부 요청이 n8n까지 도착하는 것을 확인한다.
- 호출할 때 같이 보낸 값(예: 이름)을 n8n이 **받아서 화면과 응답에 보여 주는** 것을 눈으로 확인한다.

> 이 워크플로우는 노드 3개입니다.
> `Webhook (요청 받기)` → `받은 값 정리하기 (Set)` → `응답 돌려주기 (Respond to Webhook)`
> 1번이 외부 요청을 받고, 2번이 받은 값을 보기 좋게 정리하고, 3번이 그 결과를 호출한 쪽에 되돌려 줍니다.

## 따라하는 단계

1. **n8n에 로그인**합니다. (n8n Cloud 가입형 또는 직접 설치한 n8n 모두 가능)
2. 화면 오른쪽 위 **`...`(점 3개) → `Import from File`** 을 눌러 이 폴더의 **`workflow.json`** 파일을 불러옵니다. 노드 3개가 한 줄로 연결되어 나타납니다.
3. **`Webhook (요청 받기)` 노드를 더블클릭**합니다. 노드 안에 두 종류의 주소가 보입니다.
   - **`Test URL`(테스트용)**: 캔버스에서 직접 실행해 볼 때 쓰는 주소.
   - **`Production URL`(실제용)**: 워크플로우를 켜 둔(Active) 상태에서 늘 받는 주소.
   - 지금은 **`Test URL` 옆의 복사 버튼**을 눌러 주소를 복사해 둡니다.
4. 노드 화면에서 **`Listen for test event`(테스트 이벤트 기다리기)** 버튼을 누릅니다. n8n이 "지금부터 노크를 기다릴게" 상태로 들어가, 주소를 호출해 주길 기다립니다.
5. **새 브라우저 탭**을 열고, 복사한 Test URL 끝에 `?name=홍길동` 을 붙여 주소창에 입력하고 엔터를 칩니다.
   - 예: `https://여러분의n8n주소/webhook-test/my-first-webhook?name=홍길동`
   - `?name=홍길동` 은 "이 요청과 함께 `name`이라는 값으로 `홍길동`을 같이 보낼게" 라는 뜻입니다.
6. n8n 화면으로 돌아오면, 방금 노크가 들어와 **워크플로우가 자동으로 한 번 실행**된 것이 보입니다.
7. **`받은 값 정리하기 (Set)` 노드를 클릭**해, 들어온 이름과 받은 시각이 정리되어 있는지 확인합니다.
8. (실제 운영처럼 써 보기) 캔버스 우측 상단 **`Active` 스위치를 켜면**, 이제 `Test URL`이 아닌 **`Production URL`** 이 항상 살아 있어, 언제 호출해도 받습니다.

## 검증법

1. 5단계에서 URL을 호출한 직후, **브라우저 탭에 JSON 응답**이 나타나면 성공입니다. 아래처럼 보입니다.
   ```json
   {
     "받은이름": "홍길동",
     "받은시각": "2026-06-18 14:30:00",
     "안내": "Webhook이 외부 요청을 정상적으로 받았습니다."
   }
   ```
2. n8n 캔버스에서 세 노드 모두에 **초록색 체크 표시**가 떴는지 확인합니다.
3. **`Webhook (요청 받기)` 노드 → `OUTPUT`** 패널을 엽니다. `query` 안에 `name: "홍길동"` 이 들어와 있는지 확인합니다. (외부에서 보낸 값이 여기로 들어옵니다.)
4. **이름을 바꿔서 다시 호출**해 봅니다. `?name=김철수` 로 주소를 바꿔 호출하면, 응답의 `받은이름`도 `김철수`로 바뀝니다. 호출할 때마다 다른 값이 들어오는 것을 확인하세요.
5. (실패 케이스 점검) `?name=홍길동` 부분을 빼고 그냥 기본 URL만 호출해 봅니다. 그래도 워크플로우는 정상 실행되며, `받은이름`이 **`이름 없음`** 으로 채워집니다. (값이 안 와도 멈추지 않도록 `|| '이름 없음'` 으로 대비해 둔 것입니다.)

## 핵심만 짚기 (디렉터 관점)

- **웹훅 = 받는 쪽이 먼저 주소를 열어 두는 방식**입니다. 내가 외부에 요청을 보내는 게 아니라, 외부가 내 주소로 찾아오면 그때 깨어납니다. 그래서 "어떤 일이 생긴 순간"에 반응하는 자동화의 출발점이 됩니다.
- **들어온 값은 `$json` 안에 담깁니다.** 주소 끝에 `?name=...` 으로 보낸 값은 `$json.query.name` 에 들어옵니다. (보내는 방식에 따라 `query`, `body`, `headers` 등 자리가 달라집니다.)
- **`Test URL` vs `Production URL`**: 테스트 URL은 `Listen for test event`를 누른 직후 한 번만 받는 연습용, 프로덕션 URL은 `Active`를 켜 두면 항상 받는 실제용입니다. 헷갈리면 호출이 안 들어온 것처럼 보일 수 있으니 둘을 구분하세요.

## 보안, 비밀값은 어떻게 다루나

- 이 실습의 URL에는 비밀 키가 없습니다. 하지만 실제 서비스에서는 **URL 자체가 일종의 열쇠**라서, 아무에게나 공개하지 않습니다. (주소를 아는 사람은 누구나 호출할 수 있기 때문)
- 한 단계 더 안전하게 하려면, Webhook 노드의 **`Authentication`(인증)** 을 `Header Auth` 등으로 켜고, 정해진 비밀 토큰을 보낸 요청만 받도록 합니다. 이때 비밀 토큰은 **n8n 자격증명(Credential) 금고**에 보관하고, `workflow.json`에는 실제 값 대신 자리표시자(`YOUR_WEBHOOK_SECRET`)만 둡니다 — 이 파일을 공유해도 비밀은 새어 나가지 않습니다.
