# 238 — 포트폴리오를 GitHub에 올리고 Vercel로 첫 배포해 내 URL 갖기

내가 만든 정적 사이트(`index.html` + `style.css`)를 **GitHub 저장소**에 올리고,
그 저장소를 **Vercel**에 연결해 `https://내프로젝트.vercel.app` 같은
**누구나 접속 가능한 진짜 주소**로 공개합니다.

서버를 빌리거나 돈을 내지 않아도 됩니다. GitHub와 Vercel 모두 **무료**로 시작할 수 있고,
한 번 연결해 두면 앞으로 코드를 고쳐 올릴 때마다 **자동으로 다시 배포**됩니다.

- 카테고리: 아키타입 미니프로젝트 (코드 L)
- 난이도: 1 / 5
- 개념: Git 커밋·푸시, Vercel 배포
- 결과물: **Vercel에 배포된 라이브 포트폴리오 URL** (이 폴더의 `index.html`, `style.css`가 공개될 파일입니다)

> 이 폴더 안의 `index.html`과 `style.css`가 바로 **공개할 포트폴리오 파일**입니다.
> 두 파일은 **반드시 같은 저장소에 함께** 올라가야 디자인까지 제대로 보입니다.
> `index.html` 안의 `[내 이름]`, `내아이디`, `내이메일@example.com` 같은 자리표시자는 본인 정보로 바꾸세요.

---

## 목표

지금까지는 내가 만든 페이지를 **내 컴퓨터에서만** 볼 수 있었습니다.
(`index.html`을 더블클릭하면 주소창에 `file:///C:/...` 처럼 뜨는데, 이건 나만 볼 수 있는 주소입니다.)

이번 목표는 그 페이지를 **누구나 접속할 수 있는 공개 주소**(`내프로젝트.vercel.app`)로 바꾸는 것입니다.

핵심 단어 네 개만 기억하면 됩니다.

- **저장소(repository)**: 내 코드 파일들을 GitHub에 보관하는 "온라인 폴더".
- **커밋(commit)·푸시(push)**: 바뀐 코드를 저장소에 "기록하고(커밋) 올리는(푸시)" 동작. (이 실습은 웹 화면으로 올리므로 명령어는 몰라도 됩니다.)
- **배포(deploy)**: 코드를 실제 인터넷 주소로 "내보내서" 공개하는 일. 이번 실습이 바로 그것입니다.
- **자동배포**: 저장소에 새 코드를 올리면 Vercel이 알아서 새 버전을 띄워 주는 것. 한 번 연결하면 끝입니다.

> 비유: GitHub는 내 물건을 넣어 두는 **창고(저장소)**, Vercel은 그 창고를 들여다보며
> 손님에게 보여 줄 **진열장(웹사이트)**을 자동으로 차려 주는 직원입니다.
> 창고에 새 물건을 넣으면(푸시) 진열장도 알아서 바뀝니다(자동배포).

> 보안 메모(중요): Vercel로 올린 정적 사이트는 **소스 코드까지 누구나 볼 수 있게** 공개됩니다.
> 그래서 이런 프런트엔드 파일에는 **비밀번호, API 키, Supabase의 `service_role` 키 같은 비밀값을 절대 넣지 않습니다.**
> - **anon 키(공개 키)**: 프런트엔드에 넣어도 되는 "공개용" 열쇠. 권한이 제한돼 있고 **RLS(행 수준 보안)**로 보호됩니다.
> - **`service_role` 키(비밀 키)**: 모든 권한을 가진 "마스터 열쇠". **절대 프런트엔드/공개 저장소에 올리지 않고**, Vercel의 **환경변수(Environment Variables)** 같은 비밀 보관소에만 둡니다.
> 이번 포트폴리오 페이지에는 비밀값이 **전혀 없으니** 안심하고 공개해도 됩니다.

---

## 따라하는 단계

### 1단계 — GitHub와 Vercel 계정 준비하기

1. **https://github.com** 에서 무료 계정을 만들어 로그인합니다. (이미 있으면 그대로 사용)
2. **https://vercel.com** 으로 가서 **Sign Up → "Continue with GitHub"** 를 눌러 **GitHub 계정으로 로그인**합니다.
   - GitHub로 가입해 두면 다음 단계에서 저장소를 바로 연결할 수 있어 가장 쉽습니다.
   - Vercel이 "GitHub 권한을 허용하겠냐"고 물으면 **Authorize(허용)** 를 누릅니다.

### 2단계 — 포트폴리오 파일을 GitHub 저장소에 올리기

1. GitHub 오른쪽 위 **➕ → New repository**(새 저장소)를 누릅니다.
2. **Repository name** 에 `my-portfolio` 처럼 영문 이름을 적고, **Public**(공개)으로 둡니다.
   - (비밀값이 없으니 공개해도 안전합니다. 무료 배포는 보통 Public에서 가장 매끄럽습니다.)
3. **Create repository**(저장소 만들기)를 누릅니다.
4. 빈 저장소 화면에서 **Add file → Upload files**(파일 업로드)를 누릅니다.
5. 이 폴더의 **`index.html`** 과 **`style.css`** **두 개를 함께** 끌어다 놓습니다.
   - `index.html` 안의 `[내 이름]`, `내아이디`, 이메일 등 자리표시자는 미리 본인 정보로 바꿔 두면 좋습니다.
6. 아래 **Commit changes**(변경 사항 커밋) 초록 버튼을 누릅니다. → 이게 바로 **커밋·푸시**입니다.

> 파일 이름은 반드시 소문자 **`index.html`** 입니다. (`Index.html`, `home.html`은 대문 페이지로 인식되지 않습니다.)

### 3단계 — Vercel에서 저장소 가져오기(Import)

1. **https://vercel.com/new** 로 갑니다. (또는 Vercel 대시보드의 **Add New… → Project**)
2. **Import Git Repository** 목록에서 방금 만든 **`my-portfolio`** 저장소 옆 **Import**(가져오기)를 누릅니다.
   - 목록에 안 보이면 **Adjust GitHub App Permissions / Configure**를 눌러 해당 저장소에 접근 권한을 줍니다.

### 4단계 — 설정 확인하고 배포(Deploy) 누르기

1. 설정 화면이 나오면 **거의 손댈 게 없습니다.** 우리 사이트는 순수 HTML/CSS라서
   - **Framework Preset**(프레임워크)은 **Other**(또는 자동 감지된 그대로) 둡니다.
   - **Build/Output 설정**은 비워 둔 기본값 그대로 둡니다. (정적 사이트는 빌드가 필요 없습니다.)
2. (비밀값이 있는 프로젝트라면 여기서 **Environment Variables**에 `service_role` 키 같은 비밀을 넣지만, **이번 포트폴리오에는 넣을 비밀값이 없습니다.**)
3. 파란 **Deploy**(배포) 버튼을 누릅니다.
4. 잠시(보통 10~30초) 기다리면 🎉 축하 화면과 함께 **미리보기 화면**이 뜹니다.

### 5단계 — 공개 주소(URL) 받고 접속해 보기

1. 배포가 끝나면 **`https://my-portfolio-xxxx.vercel.app`** 같은 **공개 주소**가 나타납니다.
   - **Continue to Dashboard → Visit**(사이트 방문) 버튼으로 바로 열어 볼 수 있습니다.
2. 주소를 복사해 **새 탭(또는 시크릿 창)**, 그리고 **휴대폰**으로도 열어 봅니다.
3. 내 포트폴리오 카드가 **디자인까지 입혀진 채로** 뜨면 **배포 성공**입니다.

> 이 `*.vercel.app` 주소가 바로 이번 실습의 **결과물(라이브 URL)** 입니다. 메모해 두세요.

### 6단계 (보너스) — 자동배포 확인하기

1. GitHub 저장소로 돌아가 `index.html`의 `[내 이름]`을 본인 이름으로 고쳐 **Commit changes**를 누릅니다.
2. Vercel 대시보드의 **Deployments** 탭을 보면, 방금 커밋으로 **새 배포가 자동으로 시작**됩니다.
3. 잠시 후 같은 주소를 **강력 새로고침(Ctrl+Shift+R)** 하면 바뀐 내용이 반영돼 있습니다.
   → "코드를 올리면 알아서 배포된다"는 자동배포를 직접 확인한 것입니다.

## 검증법

아래가 모두 맞으면 성공입니다.

- **공개 주소 확인**: Vercel 대시보드 프로젝트 화면에 **`*.vercel.app`** 주소가 보이고 **Ready**(준비됨) 상태다.
- **접속 확인**: 그 주소를 새 탭에 붙여 넣어 들어가면 포트폴리오 페이지가 **디자인까지** 보인다.
  (글자만 보이고 색·여백이 없다면 `style.css`가 같이 안 올라간 것입니다.)
- **로그아웃해도 보임**: GitHub/Vercel에서 로그아웃하거나 **휴대폰**으로 열어도 똑같이 보인다 → **누구나** 접속 가능한 공개 주소라는 증거입니다.
- **자동배포 확인(보너스)**: GitHub에서 파일을 고쳐 커밋하면, Vercel에 **새 배포가 자동으로 생기고** 잠시 뒤 바뀐 내용이 사이트에 반영된다.

> 흔한 실수
> - **디자인이 빠진 채 글자만 나옴**: `style.css`가 같은 저장소에 **함께** 올라갔는지, `index.html`에 `<link rel="stylesheet" href="style.css" />` 한 줄이 있는지 확인하세요.
> - **404 / 빈 화면**: 대문 파일이 소문자 **`index.html`** 인지, 저장소 **맨 위(루트)** 에 있는지 확인합니다. 하위 폴더에 넣었다면 Vercel의 **Root Directory** 설정을 그 폴더로 맞춰야 합니다.
> - **저장소가 Vercel 목록에 안 보임**: Import 화면의 **Adjust GitHub App Permissions / Configure**에서 해당 저장소에 접근 권한을 추가하세요.
> - **수정했는데 화면이 그대로**: 자동 재배포는 됐지만 **브라우저 캐시** 때문일 수 있습니다. **Ctrl+Shift+R**(강력 새로고침)이나 시크릿 창으로 확인하세요.
> - **비밀값을 올릴 뻔함**: API 키·비밀번호·`service_role` 키는 **절대** 저장소/프런트엔드에 넣지 않습니다. 필요하면 Vercel **Environment Variables**에만 두세요. (이번 페이지는 비밀값이 없습니다.)
