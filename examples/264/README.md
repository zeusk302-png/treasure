# 실습 264 — 대시보드에 KPI 카드와 합계·평균 통계 표시하기

Supabase에 쌓인 **주문 데이터**를 **집계(합치기·세기·평균내기)**해서,
대시보드 맨 위에 핵심 지표(**KPI**) 카드 4개로 보여 주는 미니 대시보드를 만듭니다.
"표에 흩어진 낱개 데이터를 **한 줄 요약 숫자**로 바꾸는" **집계 쿼리**를 한 번에 체험하는 것이 목표입니다.

> 비유: 가게 사장님이 하루 끝에 **영수증 더미(주문 표)**를 펼칩니다.
> 한 장 한 장 읽는 대신 **"오늘 몇 건? 매출은 다 더해 얼마? 한 건당 평균은? 손님은 몇 명?"**
> 네 가지만 적어 벽에 붙입니다. 그 '벽에 붙인 요약 숫자'가 바로 KPI 카드입니다.

이 폴더에 있는 파일:

- `README.md` — 이 안내문
- `index.html` — KPI 카드 4개의 뼈대 (처음엔 `—`, JS가 진짜 숫자로 채움)
- `style.css` — 카드 격자 디자인 (화면 폭에 맞춰 칸 수 자동 조절)
- `script.js` — **핵심.** 주문을 읽어 `COUNT/SUM/AVG/DISTINCT`로 집계해 카드에 그림
- `schema.sql` — 표 만들기 + RLS(읽기 전용) 정책 + DB 집계 함수 `order_stats()` + 샘플 주문 6건

## 목표

- 표에 쌓인 주문을 **집계**하는 네 가지 기본기를 익힌다 — **건수(COUNT)**, **합계(SUM)**, **평균(AVG)**, **서로 다른 값 개수(DISTINCT COUNT)**.
- 같은 집계를 **두 가지 방법**으로 할 수 있음을 이해한다 — (A) 브라우저에서 직접 더하기(쉬움), (B) DB 함수 `order_stats()`가 요약 한 줄만 돌려주기(빠름·권장).
- 집계 결과를 보기 좋은 **KPI 카드 UI**(라벨 + 큰 숫자 + 설명)로 그리는 법을 익힌다.
- 이 대시보드가 **읽기 전용**인 이유를 안다 — **anon(공개) 키** + RLS에서 **SELECT만 허용**했기 때문에, 통계는 볼 수 있어도 데이터를 넣거나 고치거나 지울 수는 없다.

## 따라하는 단계

1. **Supabase 표·보안·집계 함수·샘플을 만든다.**
   Supabase 대시보드 → **SQL Editor → New query** 에 이 폴더의 `schema.sql` **전체**를 붙여넣고 **[Run]** 한다.
   (표 `orders` 생성 + RLS 켜기 + **읽기(SELECT) 정책** + 집계 함수 `order_stats()` + 샘플 주문 6건이 한 번에 만들어집니다.)
2. **내 프로젝트 값을 코드에 넣는다.**
   Supabase 대시보드 → **Settings(톱니바퀴) → API** 에서 값을 복사해 `script.js` 맨 위 두 줄의 **자리표시자**를 바꾼다.
   ```js
   const SUPABASE_URL = "https://여기에-내-프로젝트-ID.supabase.co";        // ← Project URL
   const SUPABASE_ANON_KEY = "sb_publishable_여기에-내-anon-공개키-붙여넣기"; // ← anon public 키
   ```
   ⚠️ **`service_role` / `sb_secret_...` 키는 절대 넣지 마세요.** 그 키는 RLS를 통째로 무시하는 마스터 키라, 브라우저에 두면 누구나 모든 주문을 마음대로 보고·고치고·지울 수 있게 됩니다.
3. **`index.html`을 브라우저로 연다.** (그냥 더블클릭해도 됩니다.)
4. **카드 숫자를 확인한다.** 페이지가 열리면 JS가 자동으로 통계를 계산해 카드를 채웁니다.
   `schema.sql`의 샘플 6건을 그대로 두었다면 **주문 건수 6건 / 매출 합계 112,000원 / 평균 주문액 18,667원 / 고객 수 4명**이 보입니다.
5. **`↻ 새로고침` 버튼을 눌러 본다.** 통계를 다시 계산해 카드를 갱신합니다.
   (Supabase **Table editor → orders** 에서 주문을 한 줄 더 넣고 새로고침하면 숫자가 바뀌는 걸 확인할 수 있습니다.)

## 🤖 바이브코딩 프롬프트

이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. 한 단계씩 시키면 결과를 눈으로 확인하며 진행할 수 있습니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 프론트엔드 튜터야. 비전공자가 따라 할 수 있게 만들어 줘.
  Supabase에 쌓인 '주문(orders)' 데이터를 집계해서 보여 주는 'KPI 카드 대시보드'를 만들고 싶어.
  - 순수 HTML/CSS/JS만 사용 (프레임워크·빌드 도구 없이 index.html을 더블클릭하면 열리게)
  - Supabase는 CDN(@supabase/supabase-js@2)으로 불러오기
  - 화면 맨 위에 KPI 카드 4개: ① 주문 건수(COUNT) ② 매출 합계(SUM) ③ 평균 주문액(AVG) ④ 고객 수(서로 다른 customer = DISTINCT COUNT)
  - 카드는 처음엔 '—' 로 두고, JS가 통계를 계산해 진짜 숫자로 채우기
  - 카드 격자는 화면 폭에 맞춰 칸 수가 자동 조절되게 (CSS grid의 auto-fit + minmax)
  - 상단에 안내/에러 메시지 자리(status)와 '↻ 새로고침' 버튼 넣기
  - SUPABASE_URL / SUPABASE_ANON_KEY 는 자리표시자로 두고, 어디서 복사하는지 주석으로 적어 줘
  결과는 index.html, style.css, script.js 세 파일로 나눠 주고,
  각 줄이 무슨 일을 하는지, 그리고 왜 그렇게 했는지 한국어 주석으로 설명해 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 KPI 대시보드에 집계 로직을 추가해 줘.
  - [방법 A] 브라우저에서 직접 집계: orders를 select로 다 받아 와 JS로 count / sum / avg 계산,
    고객 수는 new Set(...).size 로 중복 없이 세기
  - [방법 B] DB가 대신 집계: schema.sql에 order_stats() 함수를 만들고(COUNT/SUM/AVG/DISTINCT를 한 줄로 반환),
    JS에서는 supabase.rpc("order_stats") 로 호출
  - 실행 순서: 먼저 빠른 [방법 B]를 시도하고, 함수가 없으면 자동으로 [방법 A]로 대체(fallback)
  - 숫자는 천 단위 콤마(toLocaleString)로 보기 좋게, 각 카드에 단위(건/원/명) 붙이기
  - orders 표는 RLS를 켜고 'SELECT(읽기)만' 허용하는 정책을 달아 줘. INSERT/UPDATE/DELETE 정책은 일부러 만들지 말고,
    왜 읽기 전용이 안전한지 주석으로 설명해 줘. (anon 공개 키 + RLS 조합)
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  KPI 대시보드가 동작을 안 해. 아래 정보를 보고 원인을 단계별로 짚어 줘.
  - 화면 status 메시지: (여기에 빨간 메시지 붙여넣기)
  - 브라우저 콘솔(F12) 에러: (여기에 에러 전문 붙여넣기)
  - 증상: 카드가 전부 '—' 그대로다 / 전부 0 이다 / 특정 카드만 이상하다 (해당하는 것)
  먼저 가장 흔한 원인부터 확인해 줘:
  (1) schema.sql을 SQL Editor에서 실제로 Run 했는지(orders 표가 있는지),
  (2) script.js의 SUPABASE_URL/ANON_KEY가 자리표시자 그대로는 아닌지,
  (3) 키가 anon(sb_publishable_)인지 service_role(sb_secret_) 실수는 아닌지,
  (4) RLS의 SELECT 정책이 실행됐는지.
  고친 부분은 무엇을 왜 바꿨는지 한 줄씩 설명해 줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법

- **카드가 채워지는가:** 페이지를 열면 네 카드가 `—`에서 진짜 숫자로 바뀌고, 상단에 초록색 "통계를 불러왔습니다." 메시지가 뜨는가?
- **샘플 숫자가 맞는가(핵심):** 샘플 6건 기준으로 아래가 그대로 나오는가?
  - 주문 건수: **6 건** (줄 수 = COUNT)
  - 매출 합계: **112,000 원** (15000+8000+23000+42000+5000+19000 = SUM)
  - 평균 주문액: **18,667 원** (112000 ÷ 6 반올림 = AVG)
  - 고객 수: **4 명** (홍길동·김영희·이철수·박지민 — 홍길동/김영희가 2번씩 주문해도 1명으로 셈 = DISTINCT)
- **새로고침 동작:** Table editor에서 주문을 1건 추가하고 `↻ 새로고침`을 누르면 건수·합계가 늘어나는가?
- **브라우저 개발자 도구 → Console**(윈도우 `F12`):
  - 성공: `✅ KPI 통계: {orderCount: 6, totalAmount: 112000, avgAmount: 18667, customerCount: 4}`
  - 함수가 없으면: `order_stats() 함수를 못 찾아 브라우저 집계로 대체합니다…` → 그래도 같은 숫자가 카드에 나오면 정상 (방법 B → A 자동 대체)
- **anon 키만 썼는지(중요):** `script.js`의 키가 **`sb_publishable_`(anon)** 로 시작하는가? **`sb_secret_`(service_role)** 가 **아닌가?**
- **읽기 전용 확인(보안):** 콘솔에서
  `await supabase.createClient(SUPABASE_URL, SUPABASE_ANON_KEY).from("orders").insert({customer:"테스트", amount:1000})`
  를 해보면 저장이 막힌다(INSERT 정책이 없어 거절). 즉 anon 키로는 **통계 읽기만 되고 데이터 추가·수정·삭제는 막힙니다.**
- **자주 나는 에러:**
  - `relation "public.orders" does not exist` → 1단계 `schema.sql`을 안 돌림. SQL Editor에서 실행하세요.
  - 카드가 전부 `0` → `orders` 표가 비어 있음. `schema.sql` 5단계 샘플을 실행하거나 Table editor에서 주문을 넣으세요.
  - `Invalid API key` → anon 키 오타. / `Failed to fetch` → `SUPABASE_URL` 철자·`https://` 확인.
