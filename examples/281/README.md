# 실습 281 — 모바일에서 가로 스크롤 생기는 페이지 고치기

> **디버깅 챌린지 (난이도 2)** · 분류: 디버깅 챌린지 · 개념: viewport 메타, 반응형, overflow

이 폴더에는 **일부러 고장 낸 파일**(`broken.html`)과 **고친 정답 파일**(`index.html` + `style.css`)이 들어 있습니다.
먼저 `broken.html`을 휴대폰(또는 개발자도구의 모바일 모드)으로 열어 **왜 좌우로 밀리는 가로 스크롤이 생기는지** 직접 찾아본 뒤, 정답과 비교하세요.

> **한 줄 원인 설명(제출물):** `<head>`에 **viewport 메타 태그가 없어서** 휴대폰이 페이지를 '데스크톱 너비'로 그리고, 거기에 더해 박스에 **고정 `width: 1200px`**, 이미지에 **고정 `width: 1000px`**가 박혀 있어서, 좁은 화면을 뚫고 나가 **가로 스크롤**이 생깁니다.

## 목표
- **viewport 메타 태그**가 무엇이고, 이게 없으면 휴대폰이 왜 페이지를 축소해서 작게 보여주는지 이해한다.
- **`width: 1200px`(고정)** 와 **`max-width: 1200px`(최대값)** 의 차이를 안다. → 고정 너비는 좁은 화면을 뚫고 나가지만, `max-width`는 "넓을 땐 최대 1200px, 좁을 땐 화면에 맞춤"이 된다.
- 이미지에 **`max-width: 100%`** 를 주면 그림이 부모 영역을 넘지 않아 화면 밖으로 삐져나가지 않는다는 것을 안다.
- "휴대폰에서 좌우로 화면이 밀린다(가로 스크롤)"는 증상을 만나면, **무엇이 화면 폭을 넘기고 있는지(overflow)** 부터 의심하는 습관을 들인다.

### 비유로 이해하기
휴대폰 화면을 **폭이 좁은 책상 서랍**이라고 생각해 보세요.
`width: 1200px`로 만든 박스는 **무조건 폭 1200짜리 큰 쟁반**입니다. 좁은 서랍에 큰 쟁반을 억지로 넣으면 한쪽이 **밖으로 삐져나오죠.** 그게 바로 가로 스크롤입니다.
반면 `max-width: 1200px`는 **"서랍이 넓으면 최대 1200까지, 좁으면 서랍 크기에 맞게 줄어드는 접이식 쟁반"** 입니다. 그래서 어떤 화면에서도 삐져나오지 않습니다.
그리고 viewport 메타 태그는 휴대폰에게 **"이 페이지는 네 화면 크기에 맞게 봐"** 라고 알려주는 쪽지예요. 이 쪽지가 없으면 휴대폰은 "데스크톱용인가 보다" 하고 페이지를 멀리서 축소해 보여줘서, 글씨가 깨알같이 작아집니다.

### 고친 오류 목록 (틀린 코드 → 정답)
| 위치 | 틀린 코드 | 올바른 코드 | 증상 |
| --- | --- | --- | --- |
| `<head>` 메타 | (viewport 메타 없음) | `<meta name="viewport" content="width=device-width, initial-scale=1.0" />` | 휴대폰이 페이지를 데스크톱 너비로 그려 통째로 축소 + 가로 스크롤 |
| `.page` 너비 | `width: 1200px;` | `width: 100%; max-width: 1200px;` (+ `box-sizing: border-box;`) | 고정 1200px 박스가 좁은 화면을 뚫고 나가 가로 스크롤 발생 |
| `.photo` 너비 | `width: 1000px;` | `width: 100%; max-width: 1000px;` | 이미지가 화면 폭(1000px)을 넘어 화면 밖으로 삐져나감 |

> 핵심은 **어떤 요소도 화면 폭을 넘지 않게** 만드는 것입니다. 고정 `width`(픽셀)를 `max-width`로 바꾸고, 이미지에 `max-width: 100%`를 주고, 무엇보다 **viewport 메타 태그**를 넣어 휴대폰이 페이지를 제 폭에 맞춰 그리게 했습니다. 정답에서는 메뉴 카드에 `flex-wrap: wrap`을 더해 좁은 화면에서 카드가 세로로 자연스럽게 쌓이게도 했습니다.

## 따라하는 단계
1. `broken.html`을 **더블클릭**해서 브라우저로 엽니다. (PC에서는 멀쩡해 보일 수 있습니다 — 문제는 좁은 화면에서 드러납니다.)
2. `F12`(또는 마우스 오른쪽 → 검사)로 개발자도구를 연 뒤, **모바일 모드 아이콘**(휴대폰/태블릿 모양, 보통 `Ctrl+Shift+M`)을 켭니다. 기기를 `iPhone` 같은 좁은 폭으로 고릅니다.
3. → 화면 **아래쪽에 가로 스크롤바**가 생기고, 손가락(또는 마우스)으로 **좌우로 밀 수 있는 것**을 확인합니다. 글씨도 작게 축소돼 보입니다. (= 버그 증상)
4. `broken.html`을 메모장이나 VS Code로 엽니다. 아래 세 곳을 고칩니다.
   - `<head>` 안, `<meta charset ...>` 바로 아래에 **`<meta name="viewport" content="width=device-width, initial-scale=1.0" />`** 한 줄을 추가합니다.
   - `.page` 규칙의 **`width: 1200px;`** 를 **`width: 100%; max-width: 1200px;`** 로 바꾸고, `box-sizing: border-box;` 도 한 줄 더해 줍니다.
   - `.photo` 규칙의 **`width: 1000px;`** 를 **`width: 100%; max-width: 1000px;`** 로 바꿉니다.
5. 저장하고 브라우저에서 **새로고침(F5)** → 모바일 모드에서 **가로 스크롤바가 사라지고**, 내용이 화면 폭에 딱 맞게 들어오면 성공입니다.
6. **폰 화면 캡처(제출물):** 고치기 전(가로 스크롤이 있는 화면)과 고친 후(스크롤 없이 화면에 꽉 찬 화면)를 각각 캡처해 비교 이미지로 남깁니다. (개발자도구 모바일 모드 또는 실제 휴대폰에서 캡처)
7. **원인 메모(제출물):** "viewport 메타 태그가 없어 휴대폰이 페이지를 데스크톱 너비로 그렸고, 고정 `width:1200px`/`width:1000px`가 화면 폭을 넘겨 가로 스크롤이 생겼다. 메타 태그를 넣고 고정 너비를 `max-width`로 바꿔 해결했다"는 **한 줄**을 적어 두세요.
8. 정답이 궁금하면 같은 폴더의 `index.html`과 `style.css`를 열어 내 수정과 비교합니다. (정답은 CSS를 `style.css` 파일로 분리해 두었습니다.)
9. AI에게 검토 시켜 보기:
   > "이 HTML/CSS가 휴대폰에서 가로 스크롤이 생기는 이유를 찾아줘. viewport 메타 태그가 빠졌는지, 고정 width(px)가 화면 폭을 넘기는지 확인하고 반응형으로 고쳐줘."

## 🤖 바이브코딩 프롬프트
이 실습(휴대폰에서 가로 스크롤이 생기는 페이지를 반응형으로 고치기)을 AI에게 시킬 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 HTML/CSS 초보를 돕는 웹 강사야.
  '우리 동네 빵집' 한 장짜리 소개 페이지를 만들어줘.
  구성: 상단 히어로(가게 이름 + 한 줄 소개), 메뉴 카드 3개(소금빵/크루아상/단팥빵), 빵집 사진 한 장, 하단 저작권 푸터.
  제약:
  - <head>에 charset과 viewport 메타 태그를 꼭 넣어줘.
  - 페이지를 감싸는 박스는 width 대신 max-width를 쓰고 가운데 정렬해줘.
  - 이미지는 max-width: 100%; height: auto; 로 화면을 넘지 않게 해줘.
  산출물: index.html과 style.css 두 파일로 분리해서 주고,
  비전공자가 이해하도록 각 줄에 '무엇을/왜' 한국어 주석을 달아줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 페이지를 휴대폰에서도 깨지지 않게 반응형으로 개선해줘.
  - 메뉴 카드들이 좁은 화면에서는 자동으로 세로로 쌓이도록 flex-wrap: wrap 과 flex: 1 1 200px 을 적용해줘.
  - .page 에 box-sizing: border-box 를 넣어 padding 때문에 너비가 넘치는 일을 막아줘.
  - 360px(아이폰SE) 폭에서 가로 스크롤이 절대 안 생기는지 점검해줘.
  바꾼 부분마다 '왜 이렇게 바꿨는지' 주석으로 설명해줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  내 페이지가 휴대폰(또는 개발자도구 모바일 모드)에서 좌우로 밀리는 가로 스크롤이 생겨.
  아래 HTML/CSS를 붙여넣을 테니 원인을 단계별로 진단해줘:
  1) <head>에 viewport 메타 태그가 있는지,
  2) 화면 폭을 넘기는 고정 width(px)를 쓴 요소가 있는지(특히 박스·이미지),
  3) padding/margin 때문에 너비가 넘치는지(box-sizing 확인).
  각 원인이 가로 스크롤과 어떻게 연결되는지 설명하고, 최소 수정안을 제시해줘.

  (여기에 내 코드 붙여넣기)
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 훨씬 좋습니다.

## 검증법
- 개발자도구 **모바일 모드**(또는 실제 휴대폰)에서 페이지를 열었을 때 **화면 아래 가로 스크롤바가 없는가?** 좌우로 밀어도 더 이상 밀리지 않는가?
- 글씨가 깨알처럼 축소돼 보이지 않고, **읽기 좋은 크기**로 화면 폭에 맞게 들어오는가? (= viewport 메타가 적용된 증거)
- 빵집 사진(`.photo`)이 **화면 폭을 넘지 않고** 안쪽에 온전히 들어오는가?
- (개념 확인) **가로 스크롤이 왜 생겼는지** 설명할 수 있는가? → viewport 메타가 없어 휴대폰이 페이지를 데스크톱 너비로 그렸고, 고정 픽셀 너비(1200px·1000px)가 좁은 화면을 뚫고 나갔기 때문입니다.

## 관련 가이드
- 화면 너비에 따라 메뉴를 세로로 쌓는 반응형 분기 → 실습 046 "미디어쿼리로 모바일에서 메뉴 세로로 쌓기"
- 모바일을 먼저 두고 화면을 넓혀가는 설계 감각 → 실습 047 "모바일 우선으로 1열→2열→3열 반응형 카드 만들기"
- 공간이 부족하면 자동 줄바꿈되는 flex-wrap/gap → 실습 036 "flex-wrap으로 줄바꿈되는 태그 목록 만들기"
- max-width 없이 화면에 꽉 차는 반응형 한 장 페이지 → 실습 054 "히어로+내비+카드+푸터를 합친 랜딩페이지 한 장 조립"
- 같은 디버깅 시리즈로 이어집니다 → 실습 280 "z-index·position 꼬임 풀기", 실습 282 "이미지·링크 깨진 경로 고치기"
