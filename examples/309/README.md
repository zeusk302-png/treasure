# 실습 309 — Redis 캐시로 느린 API 응답 캐싱하기

느린 외부 API(또는 무거운 DB 쿼리) 결과를 **Redis에 잠깐 저장(cache-aside)**해 두고, 같은 요청이 또 오면 **계산을 다시 하지 않고 즉시 돌려주는** 작은 서버를 만듭니다. 첫 요청은 1.5초, 두 번째부터는 거의 0초로 떨어지는 걸 직접 보면서 **캐시 적중(HIT)·만료(TTL)·무효화(invalidate)**가 무엇인지 몸으로 익히는 것이 목표입니다.

> 한 줄 그림: **요청 도착 → "Redis에 저장된 답 있나?" 확인 → 있으면(HIT) 즉시 응답 / 없으면(MISS) 느리게 계산하고 그 답을 Redis에 30초간 저장 → 다음 요청은 빨라짐**

> 비유: 캐시는 **자주 꺼내 쓰는 물건을 서랍 깊은 곳이 아니라 책상 위에 올려 두는 것**입니다. 처음 한 번은 창고(느린 원본)까지 다녀오지만, 그다음부터는 책상 위(Redis)에서 바로 집습니다. 단, 책상 위 물건은 너무 오래 두면 상하니(데이터가 낡으니) **유통기한(TTL)**을 붙여 두고, 내용이 바뀌면 **즉시 치웁니다(무효화)**.

> 보안 메모 — 공개해도 되는 값 vs 숨겨야 하는 값
> - **공개되어도 되는 값**: 포트 번호, 비밀번호 없는 로컬 Redis 주소(`redis://127.0.0.1:6379`)는 "어디에 붙을지"일 뿐이라 노출돼도 위험이 없습니다.
> - **숨겨야 하는 값**: 클라우드 Redis(예: Upstash)처럼 **비밀번호가 포함된 접속 주소**는 그 주소 한 줄이 곧 열쇠입니다. 코드(`server.js`)나 깃에 박지 말고 **`.env`(또는 배포 플랫폼 시크릿)**에만 넣습니다. 이 폴더의 `.env.example`에는 **자리표시자만** 있고, 진짜 값이 들어가는 `.env`는 `.gitignore`로 깃에서 빠집니다.

## 목표
- **cache-aside 패턴**을 직접 구현한다: `캐시 확인 → 없으면 원본 계산 → 결과를 TTL과 함께 캐시에 저장`이라는 네 줄 흐름을 이해한다.
- **캐시 적중률을 체감한다**: 같은 도시를 두 번 조회해 MISS(주황, 느림) → HIT(초록, 즉시)로 바뀌는 걸 시간(ms)으로 확인한다.
- **만료(TTL)**를 이해한다: 저장 후 30초가 지나면 캐시가 사라지고 다시 MISS가 나는 걸 본다.
- **무효화(invalidate)**를 이해한다: "원본이 바뀌면 캐시를 버린다"를 버튼으로 직접 눌러, 다음 조회가 다시 MISS가 되는 걸 확인한다.
- **비밀값을 코드 밖에 둔다**: Redis 접속 정보를 환경변수로 받아, 코드가 아니라 `.env`에 두는 습관을 들인다.

## 따라하는 단계

### A. Redis 띄우기 (둘 중 하나)
1. **Docker가 있으면** 터미널에서 한 줄로 띄웁니다(가장 쉬움):
   ```bash
   docker run --name redis-demo -p 6379:6379 -d redis
   ```
   - `-p 6379:6379` 는 "내 컴퓨터의 6379 포트를 컨테이너의 Redis에 연결"한다는 뜻입니다.
2. **Docker가 없으면** 무료 클라우드 Redis(예: Upstash)에서 데이터베이스를 하나 만들고, 제공되는 **접속 URL**(비밀번호 포함)을 복사해 둡니다. 이 값은 비밀이므로 다음 단계에서 `.env`에만 넣습니다.

### B. 환경 준비
3. 이 폴더에서 의존성을 설치합니다:
   ```bash
   npm install
   ```
4. `.env.example`을 복사해 `.env`를 만듭니다:
   ```bash
   cp .env.example .env
   ```
   - 로컬 Docker Redis를 쓰면 `.env`는 그대로 둬도 됩니다(`redis://127.0.0.1:6379`).
   - 클라우드 Redis를 쓰면 `REDIS_URL`을 **A-2에서 복사한 진짜 주소**로 바꿉니다. (이 값은 `.env`에만 — 코드/깃에 넣지 않습니다.)

### C. 서버 실행하고 캐시 체감하기
5. 서버를 켭니다:
   ```bash
   npm start
   ```
   - 콘솔에 `[redis] 연결됨` 과 `http://localhost:3000` 이 보이면 정상입니다. (`연결 오류`가 뜨면 Redis가 안 떠 있는 것 — A단계를 확인하세요.)
6. 브라우저에서 `http://localhost:3000` 을 엽니다.
7. **첫 조회(MISS)**: 도시(예: `Busan`) 그대로 두고 **"날씨 가져오기"**를 누릅니다. **주황색 MISS** 배지와 함께 **약 1500ms**가 걸립니다(원본을 느리게 계산했기 때문).
8. **두 번째 조회(HIT)**: 바로 다시 누릅니다. 이번엔 **초록색 HIT** 배지와 함께 **몇 ms**로 끝납니다. `계산 시각(computedAt)`이 **안 바뀌는 것**이 같은 캐시를 보고 있다는 증거입니다.

### D. 만료와 무효화 확인하기
9. **만료(TTL)**: HIT 상태에서 `남은 TTL`이 줄어드는 걸 보세요. 30초가 지난 뒤 다시 누르면 캐시가 사라져 **다시 MISS**가 나고 `계산 시각`이 새로 바뀝니다.
10. **무효화(invalidate)**: HIT 상태에서 **"캐시 비우기"**를 누른 뒤 다시 조회하면, TTL이 남아 있어도 **즉시 MISS**가 납니다. "원본이 바뀌어서 캐시를 버렸다"를 흉내 낸 것입니다.

## 검증법
- **첫 요청 vs 두 번째 요청 시간 비교**: 같은 도시를 두 번 조회했을 때 `걸린 시간`이 **약 1500ms → 몇 ms**로 확 줄면 캐시가 동작하는 것이다.
- **HIT/MISS 배지 확인**: 두 번째 조회에서 **초록 HIT**가 뜨고, `계산 시각(computedAt)`이 **첫 조회와 동일**하면 같은 캐시를 보고 있다는 증거다.
- **만료 확인**: HIT 후 30초를 기다렸다 다시 조회하면 **다시 MISS**가 나고 `계산 시각`이 **새로 바뀐다**.
- **무효화 확인**: "캐시 비우기"를 누른 직후 조회하면 TTL이 남아 있었더라도 **반드시 MISS**가 난다.
- **Redis에 정말 들어갔는지 직접 보기**(선택): Redis CLI에서 확인한다.
  - `docker exec -it redis-demo redis-cli` 로 접속한 뒤 `KEYS weather:*` → `weather:busan` 같은 키가 보이고, `TTL weather:busan` → 남은 초가 나오면 정상이다.
- **비밀값이 코드/깃에 없는지 확인**: `server.js`에 진짜 Redis 비밀번호가 한 글자도 없고(환경변수로만 읽음), `.env`가 `.gitignore`에 들어 있어 깃 추적에서 빠지는지 본다.

## 파일 구성
- `server.js` — Express + Redis 서버. cache-aside 조회 라우트와 무효화 라우트, 느린 원본 흉내 함수가 들어 있다.
- `index.html` — 버튼으로 조회/무효화하고 HIT·MISS·시간·TTL을 보여주는 데모 화면. 값은 `textContent`로만 출력(XSS 방지).
- `package.json` — 의존성(`express`, `ioredis`)과 `npm start` 실행 스크립트.
- `.env.example` — 필요한 환경변수 견본(자리표시자만). 복사해 `.env`를 만들고 진짜 값은 거기에만 넣는다.
- `.gitignore` — `.env`와 `node_modules`가 깃에 올라가지 않게 막는다.
