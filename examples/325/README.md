# 실습 325 — Stripe 테스트 결제(Checkout) 붙이기

내 사이트에 **"구매하기" 버튼**을 붙이고, 누르면 Stripe가 만든 **안전한 결제창**으로 넘어가 **테스트 카드로 결제**되게 만듭니다. 진짜 돈은 한 푼도 빠지지 않는 **테스트 모드**에서, "결제는 어떻게 흐르는가" 그리고 "**테스트키와 라이브키는 무엇이 다른가**"를 안전하게 몸으로 익히는 것이 목표입니다.

> 한 줄 그림: **손님이 "구매하기" 클릭 → 우리 서버가 Stripe에 "결제 세션 만들어 줘" 요청 → Stripe가 준 결제창 주소로 손님 이동 → 손님이 테스트 카드로 결제 → 우리 사이트의 "성공" 페이지로 복귀 → 서버가 "진짜 결제됐는지" 다시 확인**

> 비유: Stripe는 가게 입구에 세워 둔 **공인 카드 단말기 회사**입니다. 우리는 카드번호를 직접 만지지 않고(만지면 보안 책임이 커집니다), "이 손님한테 3,000원 받아 줘"라고 단말기 회사에 맡깁니다. 손님은 단말기 회사의 안전한 화면에서 결제하고, 끝나면 우리 가게로 돌아옵니다.

> 보안 메모 — 공개해도 되는 값 vs 절대 숨겨야 하는 값
> - **절대 숨겨야 하는 값**: **시크릿 키**(`sk_test_...` / `sk_live_...`). 이 키는 "결제를 일으킬 수 있는 진짜 열쇠"라, 브라우저(프론트)에 두면 `F12`로 보여 남이 내 계정으로 결제를 만들 수 있습니다. 그래서 **오직 서버(`server.js`)와 `.env`에만** 둡니다.
> - **공개되어도 되는 값**: **공개키**(`pk_test_...`)는 노출돼도 안전합니다(이번 실습은 서버가 결제창 URL을 직접 만들어 주므로 공개키를 따로 쓰지 않습니다).
> - **테스트키 vs 라이브키**: `sk_test_`/`pk_test_`는 **가짜 돈**으로 도는 연습용, `sk_live_`/`pk_live_`는 **진짜 돈**이 빠지는 실전용입니다. 실습 내내 **반드시 `_test_` 키만** 씁니다.
> - 이 폴더의 `.env.example`에는 **자리표시자만** 들어 있습니다. 진짜 키는 복사해 만든 `.env`에만 적고, `.env`는 `.gitignore`로 깃에서 빠집니다.

## 목표
- **결제 흐름을 한 바퀴 직접 돌려 본다**: 버튼 → 서버 → Stripe 결제창 → 성공/취소 페이지 복귀까지를 손으로 경험한다.
- **시크릿 키를 서버에만 둔다**: 결제를 만드는 시크릿 키는 브라우저에 절대 내려보내지 않고, 서버 코드와 `.env`에만 두는 안전한 구조를 익힌다.
- **테스트키와 라이브키를 구분한다**: `sk_test_`(가짜 돈)와 `sk_live_`(진짜 돈)의 차이를 이해하고, 실습은 테스트키로만 한다.
- **"도착 ≠ 결제 완료"를 안다**: 성공 페이지에 도착했다고 결제가 끝난 게 아니라, **서버가 Stripe에 다시 확인**해야 신뢰할 수 있음을 이해한다(진짜 신뢰는 다음 실습 326의 웹훅).
- **금액은 서버가 정한다**: 가격을 브라우저가 보내게 하면 조작될 수 있으니, 금액은 항상 서버가 결정하는 규칙을 익힌다.

## 따라하는 단계

### A. Stripe 테스트 키 받기
1. [stripe.com](https://stripe.com)에 가입/로그인합니다. (사업자 등록 없이도 **테스트 모드**는 바로 쓸 수 있습니다.)
2. 대시보드 우상단의 **Test mode(테스트 모드)** 토글이 **켜져 있는지** 확인합니다. (이게 켜져 있어야 `_test_` 키가 보입니다.)
3. 왼쪽 메뉴 **Developers → API keys**로 갑니다. **Secret key**(`sk_test_...`)를 복사합니다. (Reveal/표시 버튼을 눌러야 보입니다.)

### B. 프로젝트 준비
4. 터미널에서 이 폴더(`examples/325`)로 이동한 뒤 의존성을 설치합니다.
   ```bash
   npm install
   ```
5. `.env.example`을 복사해 `.env`를 만들고, 방금 복사한 시크릿 키를 넣습니다.
   ```bash
   cp .env.example .env
   ```
   `.env`를 열어 `STRIPE_SECRET_KEY=sk_test_...` 부분에 **내 테스트 시크릿 키**를 붙여 넣습니다. (`sk_test_`로 시작하는지 꼭 확인!)

### C. 서버 켜고 결제해 보기
6. 서버를 실행합니다.
   ```bash
   npm start
   ```
   터미널에 `서버 실행 중 → http://localhost:3000`이 보이면 성공입니다.
7. 브라우저에서 **http://localhost:3000** 을 엽니다. "부산코딩스쿨 굿즈 스티커팩 3,000원" 화면이 보입니다.
8. **구매하기 (테스트)** 버튼을 누르면 Stripe 결제창으로 넘어갑니다. 아래 **테스트 카드**로 결제합니다.
   - 카드번호: `4242 4242 4242 4242`
   - 만료일: **미래의 아무 날짜**(예: 12/34)
   - CVC: 아무 숫자 3자리 · 우편번호: 아무 값
9. 결제를 마치면 **성공 페이지(`success.html`)**로 돌아오고, "결제 확인 완료 · 금액 3,000KRW"가 뜨면 한 바퀴 성공입니다. (중간에 뒤로 가기를 누르면 **취소 페이지(`cancel.html`)**로 옵니다.)

### D. "진짜 됐는지"는 Stripe에서도 확인
10. Stripe 대시보드 **Payments(결제 내역)**에 방금 결제가 **Succeeded(성공)**로 떴는지 봅니다. 화면의 성공 페이지와 대시보드가 일치해야 진짜입니다.

> 다음 단계 예고: 지금은 성공 페이지에서 서버가 한 번 "확인"만 합니다. 하지만 손님이 결제 직후 창을 닫아 버리면 우리 서버는 모를 수 있습니다. 그래서 실전에서는 **Stripe가 서버로 직접 통보하는 '웹훅'**으로 결제 완료를 처리합니다 → **실습 326**.

## 검증법
- **결제 한 바퀴 확인**: `4242 4242 4242 4242` 테스트 카드로 결제하면 성공 페이지에 "결제 확인 완료 · 금액 3,000KRW"가 뜬다.
- **Stripe 대시보드 대조**: Stripe **Payments**에 방금 결제가 **Succeeded**로 떠 있고, 금액(₩3,000)이 화면과 일치한다.
- **취소 흐름 확인**: 결제창에서 뒤로 가기를 누르면 취소 페이지가 뜨고, 대시보드엔 결제가 기록되지 않는다.
- **시크릿 키가 프론트에 없는지 확인 (가장 중요)**: 브라우저에서 `Ctrl`+`U`(소스 보기)로 `index.html`/`script.js`를 열어 **`sk_test_`/`sk_live_`가 한 글자도 없는지** 본다. (보이면 안 된다 — 시크릿 키는 서버에만 있어야 한다.)
- **코드에 비밀값이 안 박혔는지 점검**: 이 폴더에서 아래를 실행하면 **결과가 없어야** 정상이다(자리표시자 제외).
  - `grep -rnE "sk_(test|live)_[A-Za-z0-9]{6,}" server.js public/` → **아무 것도 안 나와야** 정상이다. (`.env`에만 있어야 한다.)
- **테스트키만 썼는지 확인**: `.env`의 키가 `sk_test_`로 시작하는지 본다. `sk_live_`였다면 진짜 돈이 빠질 수 있으니 즉시 테스트키로 바꾼다.
- **금액 조작 방어 확인**: 브라우저 개발자도구에서 요청을 가로채 금액을 바꿔 보내도, 서버가 정한 3,000원으로만 결제되는지 본다(금액은 서버가 결정한다).

## 파일 구성
- `server.js` — 결제 세션을 만들고(`/create-checkout-session`) 결제 여부를 재확인하는(`/check-session`) 작은 서버. **시크릿 키를 다루는 유일한 곳**이다.
- `public/index.html` — "구매하기" 버튼이 있는 가게 화면. 시크릿 키가 없고, 서버에 요청만 한다.
- `public/script.js` — 버튼 클릭 시 서버에 세션 생성을 요청하고 결제 URL로 이동시키는 동작.
- `public/success.html` — 결제 후 돌아오는 성공 페이지. 서버에 "진짜 결제됐는지" 다시 묻는다.
- `public/cancel.html` — 결제를 취소했을 때 돌아오는 페이지.
- `package.json` — 필요한 라이브러리(express, stripe, dotenv)와 실행 명령(`npm start`).
- `.env.example` — 필요한 비밀값 견본(자리표시자만). 복사해 `.env`를 만들고 진짜 키는 거기에만 넣는다.
- `.gitignore` — `.env`와 `node_modules`가 깃에 올라가지 않게 막는다.
