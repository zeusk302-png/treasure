# 실습 279 — 오타 클래스명 매칭하기 (가운데 정렬이 안 되는 박스)

> **디버깅 챌린지 (난이도 1)** · 분류: 디버깅 챌린지 · 개념: CSS 선택자 매칭, 클래스명

이 폴더에는 **일부러 고장 낸 파일**(`broken.html`)과 **고친 정답 파일**(`index.html`)이 들어 있습니다.
먼저 `broken.html`을 열어 박스가 왜 가운데로 모이지 않고 흰 카드 모양도 안 나오는지 직접 찾아보고, 그다음 `index.html`과 비교하세요.

> **한 줄 메모(무엇이 잘못됐나):** HTML의 `<div class="continer">` 가 **오타**입니다. CSS에는 `.container` 규칙만 있는데 HTML에는 철자가 다른 `continer` 가 적혀 있어서, 둘이 **이름이 안 맞아 스타일이 통째로 빠집니다.** CSS 선택자는 **철자가 글자 하나까지 정확히 같아야** 적용됩니다. (`continer` ≠ `container`)

## 목표
- CSS 선택자(예: `.container`)와 HTML의 `class` 값은 **철자가 정확히 일치해야만** 스타일이 붙는다는 것을 체감한다.
- 글자 하나(`a` 빠짐)만 달라도 브라우저는 **"그런 클래스는 없다"** 며 조용히 무시한다는 것을 이해한다. (에러도 안 뜹니다 — 그래서 더 헷갈립니다.)
- 스타일이 "전부 안 먹을 때" 가장 먼저 **클래스 이름 짝이 맞는지** 확인하는 습관을 들인다.

### 비유로 이해하기
CSS 클래스 이름은 **택배 받는 사람 이름표**와 같습니다.
CSS는 "`container` 라는 이름표가 붙은 박스에게 흰 배경과 가운데 정렬을 배달해줘"라고 시켜 둔 상태입니다.
그런데 정작 박스에 붙은 이름표는 `continer`(철자 틀림)라서, 배달부(브라우저)는 **"이 이름을 가진 박스는 없네"** 하고 그냥 지나갑니다. 박스는 아무 스타일도 못 받고, 화면 왼쪽 위에 맨몸으로 남게 됩니다. **에러는 안 나지만 디자인만 통째로 사라지는** 것이 클래스명 오타의 특징입니다.

### 고친 오류 목록 (틀린 코드 → 정답)
| 위치 | 틀린 코드 | 올바른 코드 | 증상 |
| --- | --- | --- | --- |
| HTML `<div>`의 class | `<div class="continer">` | `<div class="container">` | `.container` CSS가 하나도 안 붙어, 흰 카드·그림자·가운데 정렬이 전부 사라짐 |

> 참고: 거꾸로 **CSS 쪽 선택자를 `.continer` 로 바꿔서** HTML의 오타에 맞춰도 화면은 똑같이 정상으로 보입니다. 하지만 `container`(컨테이너)가 **올바른 영어 철자**이고 의미도 맞으므로, 이 실습에서는 **HTML의 오타를 고치는 쪽**이 정석입니다. 둘 중 어느 쪽을 고치든 **이름표 양쪽 철자를 똑같이 맞춘다**는 원리는 같습니다.

## 따라하는 단계
1. `broken.html`을 **더블클릭**해서 브라우저로 엽니다. → 흰 카드도 없고, 박스가 가운데로 안 모인 채 글자만 화면 왼쪽 위에 보입니다.
2. `F12`(또는 마우스 오른쪽 → 검사)를 눌러 개발자도구를 엽니다.
3. **Elements(요소)** 탭에서 `<div class="continer">` 줄을 클릭합니다. 오른쪽 **Styles(스타일)** 패널에 `.container` 규칙이 **적용되지 않고 회색으로 떠 있거나 아예 안 보이는** 것을 확인합니다. (선택자가 박스와 안 맞는다는 신호입니다.)
4. `broken.html`을 메모장이나 VS Code로 엽니다.
5. `<body>` 안의 `<div class="continer">` 에서 클래스 이름을 `continer` → **`container`** 로 고칩니다. (빠진 `a` 한 글자를 넣어 줍니다: con**ta**iner.)
6. 저장하고 브라우저에서 **새로고침(F5)** → 흰색 둥근 카드가 생기고, 그림자가 붙고, 박스가 **화면 정중앙**으로 모이면 성공입니다.
7. **메모(제출물):** "HTML의 `class="continer"` 가 CSS의 `.container` 와 철자가 안 맞아 스타일이 빠졌고, `container` 로 고쳐서 맞췄다"는 한 줄을 적어 두세요. 어디가 왜 안 맞았는지 설명할 수 있어야 합니다.
8. 정답이 궁금하면 같은 폴더의 `index.html`을 열어 내 수정과 비교합니다.
9. AI에게 검토 시켜 보기:
   > "이 HTML/CSS에서 클래스 이름이 서로 안 맞는 곳이 있는지 찾아줘. CSS 선택자와 HTML의 class 값 철자를 비교해서 틀린 곳을 알려주고 고쳐줘."

## 🤖 바이브코딩 프롬프트
이 실습(클래스명 오타로 스타일이 통째로 빠지는 버그 찾기·고치기)을 AI에게 시킬 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 HTML/CSS 입문 강사야. 학습용 예제 페이지를 하나 만들어줘.

  - 카드 안에는 보라색 제목 <h1> "환영합니다"와 회색 문단 <p> 한 줄을 넣고, 글자는 가운데 정렬.
  - 카드는 둥근 모서리(border-radius)와 부드러운 그림자(box-shadow)를 가진 카드 모양으로.
  - 화면 중앙 정렬은 body에 flex(justify-content/align-items: center)로 해줘.
  - 박스 <div>에는 class="container" 를 주고, CSS에서도 .container 선택자로 스타일을 붙여줘.
  - 한 파일(index.html) 안에 <style>로 CSS를 같이 넣어줘.
  중요: 코드만 주지 말고, 각 부분이 무슨 일을 하고 왜 그렇게 했는지 한국어 주석으로 한 줄씩 설명해줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 페이지로 '디버깅 연습 문제'를 만들어줘.
  - index.html을 복사해 broken.html을 만들고, 거기서 <div>의 class 값만 일부러 오타("continer", a 한 글자 빠짐)로 바꿔줘. CSS의 .container 규칙은 그대로 둬.
  - 그 결과 흰 카드·그림자·가운데 정렬이 전부 사라지는 이유를, broken.html 안에 한국어 주석(BUG: ...)으로 적어줘.

  - CSS 선택자와 HTML class 값은 철자가 한 글자까지 정확히 같아야 적용된다는 핵심 원리를 주석에 꼭 넣어줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text

  ```

## 검증법
- 고친 뒤 박스가 **화면의 가로·세로 정중앙**에 떠 있는가?
- 박스에 **흰 배경, 둥근 모서리, 그림자**가 생겼는가? (= `.container` 스타일이 적용됐다는 증거)
- 박스 안의 제목/문단 글자가 **가운데 정렬**되어 있는가?
- (개념 확인) 고치기 전에는 **에러 메시지도 안 떴는데** 왜 디자인만 사라졌는지 설명할 수 있는가? → CSS 선택자(`.container`)와 class 값(`continer`)의 철자가 달라 둘이 매칭되지 않았고, 브라우저는 안 맞는 선택자를 에러 없이 그냥 무시하기 때문입니다.
