# 실습 308 — Redis로 API 레이트리밋(1분 N회) 걸기

내 API에 **"한 사람(IP)이 1분에 N번까지만 호출 가능"**이라는 규칙을 붙여, 봇이 도배하거나 누군가 새로고침을 미친 듯이 눌러도 서버가 버티게 만듭니다. 핵심 도구는 **Redis**라는 아주 빠른 인메모리 저장소입니다. Redis에 "이 IP가 이번 1분 동안 몇 번 왔는지"를 세는 카운터를 두고, 그 카운터에 **만료 시간(TTL)**을 걸어 1분이 지나면 저절로 0으로 리셋되게 합니다.

> 한 줄 그림: **요청이 들어옴 → 미들웨어가 Redis에서 `rl:<IP>` 카운터를 1 올림(INCR) → 처음이면 60초 만료를 걺(EXPIRE) → 카운트가 N 이하면 통과, N을 넘으면 즉시 `429 Too Many Requests`로 거절**

> 비유: 인기 맛집 입구의 **번호표 기계**입니다. 손님(요청)이 오면 번호표를 한 장 뽑고(카운터 +1), 가게는 "1분에 손님 10팀까지만"이라는 규칙으로 11번째부터는 "잠시 후 다시 와 주세요"(429)라고 돌려보냅니다. 그리고 번호표 통은 1분마다 비워집니다(TTL 만료).

> 보안 메모 — 공개해도 되는 값 vs 절대 숨겨야 하는 값
> - **공개되어도 되는 것**: 프론트(`public/index.html`)에서 내 서버의 `/api/hello`를 `fetch`로 부르는 코드. 이건 그냥 "내 서버에 요청 보낸다"는 평범한 호출이라 누가 봐도 안전합니다.
> - **절대 노출하면 안 되는 비밀값**: **Redis 접속 주소(`REDIS_URL`)** — 비밀번호가 들어 있으면 이걸 아는 사람은 내 캐시를 마음대로 읽고 지울 수 있습니다. 그래서 코드에 박지 않고 **`.env`(환경변수)**에만 두고, `.env`는 `.gitignore`로 깃에서 제외합니다. 이 폴더의 `.env.example`에는 **자리표시자만** 들어 있습니다.
> - 레이트리밋 자체가 **남용 방어(보안)** 장치라는 점도 기억하세요. 로그인·문의·결제 같은 민감한 엔드포인트일수록 더 빡빡하게 거는 게 좋습니다.

## 목표
- **레이트리밋이 무엇인지** 체감한다: "1분에 N회"를 넘는 요청을 `429`로 막아, 도배·무차별 대입(brute force)·비용 폭탄을 방어한다.
- **Redis의 INCR + EXPIRE 조합**을 익힌다: 카운터를 원자적으로 1 올리고, 첫 요청 때만 만료를 걸어 창(window)이 1분 뒤 자동으로 리셋되게 한다.
- **미들웨어로 분리**한다: 레이트리밋을 한 함수(미들웨어)로 만들어 여러 라우트에 재사용하고, 막혔을 때 표준 헤더(`Retry-After`, `X-RateLimit-*`)로 클라이언트에게 알려 준다.
- **비밀값을 코드 밖에 둔다**: Redis 접속 정보는 `.env`/환경변수에만 두고, 코드에는 `process.env.REDIS_URL` 참조만 남긴다.

## 따라하는 단계

### A. Redis 준비하기 (셋 중 하나)
1. **가장 쉬움 — 무료 클라우드 Redis**: [Upstash](https://upstash.com) 에 가입 → "Create Database" → 만들어진 DB의 **"Redis URL"**(예: `rediss://default:비밀번호@호스트:포트`)을 복사합니다. (Redis 클라우드, Render 등 다른 곳도 됩니다.)
2. **로컬에서 Docker로**: 도커가 있으면 터미널에서 `docker run -d -p 6379:6379 redis:7` 한 줄이면 끝. 이 경우 접속 주소는 `redis://localhost:6379` 입니다.
3. **로컬 설치**: Mac은 `brew install redis && brew services start redis`, 윈도우는 WSL이나 Docker 방식을 권장합니다.

### B. 프로젝트 셋업
4. 터미널에서 이 폴더(`examples/308`)로 이동한 뒤 의존성을 설치합니다.
   ```bash
   npm install
   ```
5. **환경변수 파일 만들기**: `.env.example`을 복사해 `.env`를 만들고, 위에서 받은 Redis 주소를 넣습니다.
   ```bash
   cp .env.example .env
   ```
   그리고 `.env` 안의 `REDIS_URL=` 뒤에 진짜 주소를 붙여넣습니다. (이 파일은 `.gitignore` 덕분에 깃에 안 올라갑니다.)
6. 원한다면 `.env`에서 한도도 바꿀 수 있습니다: `RATE_LIMIT_MAX`(1분당 허용 횟수, 기본 10), `RATE_LIMIT_WINDOW_SEC`(창 길이 초, 기본 60).

### C. 서버 켜고 직접 막혀 보기
7. 서버를 실행합니다.
   ```bash
   npm start
   ```
   콘솔에 `http://localhost:3000 에서 실행 중` 이 뜨면 성공입니다.
8. 브라우저에서 `http://localhost:3000` 을 엽니다. 데모 페이지에 **"요청 보내기" 버튼**과 **"빠르게 15번 연타" 버튼**이 있습니다.
9. **연타 버튼**을 누르면, 처음 N번(기본 10번)은 초록색 `200 OK`로 통과하고, 그 이후부터는 빨간색 `429 Too Many Requests`로 막히는 걸 눈으로 봅니다. 응답에 `남은 횟수`와 `몇 초 뒤에 풀리는지(Retry-After)`도 표시됩니다.
10. **1분(또는 설정한 창)을 기다린 뒤** 다시 누르면, 카운터가 리셋되어 또 통과합니다. 이게 "창이 만료되며 리셋"되는 모습입니다.

### D. (선택) 명령줄에서 빠르게 검증
11. 서버가 켜진 상태에서 다른 터미널에 아래를 붙여 넣어, 12번 연속 호출 중 11번째부터 막히는지 확인합니다.
    ```bash
    for i in $(seq 1 12); do curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/api/hello; done
    ```
    `200`이 10개, 그다음 `429`가 나오면 성공입니다.

## 검증법
- **눈으로 막히는지 확인**: 데모 페이지의 "15번 연타" 버튼을 누르면 앞쪽은 `200`(초록), 한도를 넘긴 뒤부터는 `429`(빨강)로 바뀌어야 한다.
- **명령줄로 확인**: D-11의 `for` 루프를 돌리면 `200`이 한도(기본 10)만큼 나온 뒤 `429`가 이어져야 한다.
- **리셋 확인**: 막힌 상태에서 창 길이(기본 60초)를 기다린 뒤 다시 호출하면 또 `200`이 나와야 한다. (카운터가 TTL 만료로 사라졌기 때문.)
- **Redis 안을 직접 보기**: `redis-cli`로 접속해 `KEYS rl:*` 를 치면 IP별 카운터 키가 보이고, `TTL rl:<IP>` 로 남은 만료 초를 볼 수 있다. (키가 0초 후 사라지는 게 정상.)
- **헤더 확인**: 브라우저 개발자도구(F12) → Network 탭에서 응답 헤더에 `X-RateLimit-Remaining`이 1씩 줄고, 막힌 응답엔 `Retry-After`가 있는지 본다.
- **비밀값이 코드에 없는지 확인**: 이 폴더에서 아래를 실행했을 때 진짜 Redis 비밀번호/호스트가 **안 나와야** 정상이다(자리표시자나 `process.env`만 나와야 함).
  - `grep -rnE "rediss?://[^ ]*:[^@]*@" server.js rateLimiter.js` → 진짜 접속 문자열이 나오면 안 된다.

## 파일 구성
- `server.js` — Express 서버. Redis에 연결하고 `/api/hello`에 레이트리밋 미들웨어를 붙인다. (파일 맨 위에 요약 주석 있음)
- `rateLimiter.js` — 레이트리밋 미들웨어(INCR + EXPIRE/TTL, 429 응답, 표준 헤더). 여러 라우트에 재사용 가능.
- `public/index.html` — 직접 눌러 막혀 보는 데모 페이지(한 번/연타 버튼, 결과 색 표시). 사용자에게 보이는 텍스트는 `textContent`로 출력.
- `package.json` — 의존성(express, redis)과 `npm start` 스크립트.
- `.env.example` — 필요한 환경변수 견본(자리표시자만). 복사해 `.env`를 만들고 진짜 `REDIS_URL`은 거기에만 넣는다.
- `.gitignore` — `.env`와 `node_modules`가 깃에 안 올라가게 막는다.
