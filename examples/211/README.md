# 211 · 주간 신규 문의 요약 리포트 자동 메일 발송 (n8n)

"매주 월요일 아침, 누가 시키지 않아도 지난 주에 들어온 문의를 모아서 '몇 건이 왔고, 어떤 내용이었는지'를 표로 정리한 메일이 자동으로 날아온다." 이게 이번 실습의 목표입니다. 사람이 매주 직접 시트를 열어 세어 보고 메일 쓰는 일을 n8n이 대신하게 만드는, 가장 실무적인 **정기 리포트 자동화**입니다.

흐름은 간단합니다: **(1) 매주 정해진 시간에 시작 → (2) 지난 주에 들어온 문의를 Supabase에서 가져오기 → (3) 건수와 목록을 HTML 표로 정리 → (4) 메일로 발송.** 앞 단계 [210](../210/)에서 배운 "여러 건 다루기"와 [209](../209/)에서 배운 "메일 발송"을 합쳐, 이번에는 **정기 집계 + 리포트**로 확장합니다.

## 목표

- **Schedule Trigger**로 "매주 월요일 오전 9시"처럼 정기적으로 자동 실행되는 워크플로우를 만든다.
- 날짜 조건(지난 주 시작~끝)을 계산해, Supabase에서 **그 기간의 데이터만** 골라 오는 법을 익힌다.
- 여러 건을 **Aggregate로 한 덩어리로 모은 뒤**, 코드로 건수를 세고 **HTML 표 리포트**로 가공한다.
- 완성된 리포트를 **메일로 자동 발송**해 "사람 손이 닿지 않는 주간 보고" 한 사이클을 끝까지 완성한다.

## 준비물 (한 번만 설정)

이 워크플로우는 진짜 메일을 보내고 진짜 DB를 읽기 때문에, 가져오기 후 **세 가지 자리표시자**를 본인 값으로 바꿔야 실제로 동작합니다. (값을 안 바꿔도 가져오기/구조 확인은 가능합니다.)

- **Supabase 프로젝트 주소**: `지난 주 문의 조회` 노드 URL의 `YOUR_PROJECT_REF`를 본인 프로젝트 ref로 교체.
- **서비스 키(비밀)**: n8n 환경변수 `SUPABASE_SERVICE_ROLE_KEY`에 Supabase의 **service_role 키**를 넣습니다. 이 키는 **절대 공개(브라우저)에 노출하면 안 되는 비밀 키**라 서버인 n8n에서만 씁니다. (홈페이지에 쓰는 anon 키와 다릅니다 — 자세한 차이는 보안 실습 가이드를 참고.)
- **메일 계정(SMTP)**: `리포트 메일 발송` 노드의 자격증명 `REPLACE_WITH_YOUR_SMTP_CREDENTIAL_ID` 자리에 본인 SMTP 계정을 연결하고, `fromEmail`/`toEmail`을 실제 보낼/받을 주소로 바꿉니다.

> 실습용 테이블 가정: Supabase에 `inquiries` 테이블이 있고 `id, name, email, message, created_at` 컬럼이 있다고 가정합니다. 테이블/컬럼 이름이 다르면 조회 노드 URL의 이름만 맞춰 바꾸세요.

## 따라하는 단계

1. **워크플로우 가져오기 (Import)**
   - n8n 우측 상단 `...` 메뉴 → `Import from File` → 이 폴더의 `workflow.json` 선택.
   - 노드 6개가 한 줄로 연결된 워크플로우가 나타납니다.

2. **언제 돌릴지 정하기 (Schedule)**
   - `매주 월요일 9시 (Schedule)` 노드를 엽니다. 주 1회, 월요일(day=1), 9시 0분에 실행되도록 설정돼 있습니다.
   - 연습 중에는 이 노드 대신 **`Test workflow` 버튼**으로 직접 실행할 수 있으니, 시간이 될 때까지 기다릴 필요는 없습니다.

3. **'지난 주' 기간 계산 이해하기**
   - `지난 주 기간 계산 (Code)` 노드를 클릭하고 `Execute step`을 누릅니다.
   - 출력에 `기간시작`, `기간끝`, `기간라벨`(예: `2026-06-08 ~ 2026-06-15`)이 나옵니다. 이게 "지난 주 한 주"입니다.

4. **그 기간 문의만 가져오기 (Supabase)**
   - `지난 주 문의 조회 (Supabase REST)` 노드의 URL을 보면 `created_at=gte.기간시작&created_at=lt.기간끝` 조건이 들어 있습니다. "이 기간에 만들어진 문의만 주세요"라는 뜻입니다.
   - 준비물(주소·service_role 키)을 채웠다면 이 노드를 실행해 실제 문의 목록이 오는지 확인합니다.

5. **모아서 표로 만들기**
   - `문의 전부 모으기 (Aggregate)`가 여러 건을 `data`라는 배열 하나로 묶습니다.
   - `HTML 리포트 만들기 (Code)`가 그 배열을 받아 **총 건수**를 세고, 각 문의를 표의 한 줄(`<tr>`)로 바꿔 제목과 HTML 본문을 완성합니다. (문의 내용의 `<`, `>`, `&`는 메일에서 깨지지 않게 안전하게 변환합니다.)

6. **메일로 보내기**
   - `리포트 메일 발송 (SMTP)` 노드가 앞에서 만든 `제목`과 `html`을 그대로 메일로 보냅니다.
   - 캔버스 빈 곳을 클릭해 아무 노드도 선택되지 않은 상태에서 `Test workflow`를 눌러 처음부터 끝까지 실행합니다.

7. **켜 두기 (Activate)**
   - 모든 게 잘 되면 우측 상단 **Active 토글을 켭니다.** 이제 사람이 손대지 않아도 매주 월요일 9시에 리포트가 자동 발송됩니다.

## 🤖 바이브코딩 프롬프트

이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. n8n 워크플로우는 코드가 아니라 **노드 흐름**이라, "어떤 노드를 어떤 순서로 연결할지"를 말로 또렷하게 시키는 게 핵심입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 n8n 자동화 전문가야. 비전공자가 이해할 수 있게 도와줘.
  목표: "매주 월요일 오전 9시에 자동 실행되어, 지난 한 주(지난 주 월요일~이번 주 월요일)에
  Supabase 'inquiries' 테이블에 들어온 문의를 모아 HTML 표 리포트로 만들어 메일로 보내는"
  n8n 워크플로우 JSON을 만들어줘.

  노드 구성(이 순서로 연결):
  1) Schedule Trigger — 매주 월요일(day=1) 9시 0분
  2) Code 노드 — '지난 주 월요일 0시 ~ 이번 주 월요일 0시' 기간을 ISO 형식으로 계산
  3) HTTP Request(Supabase REST GET) — created_at 이 그 기간 안인 행만 조회
  4) Aggregate 노드 — 여러 건을 data 배열 하나로 모으기
  5) Code 노드 — 건수 세고 HTML 표 만들기
  6) Send Email(SMTP) — 제목/본문 그대로 발송

  제약:
  - Supabase service_role 키는 코드에 박지 말고 n8n 환경변수($env.SUPABASE_SERVICE_ROLE_KEY)로 읽을 것
  - 프로젝트 주소·SMTP 자격증명은 자리표시자(YOUR_PROJECT_REF 등)로 둘 것
  산출물: n8n에서 Import 가능한 workflow.json 전체. 각 노드가 무엇을 왜 하는지 한국어 주석/설명을 곁들여줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 211 워크플로우를 이어서 개선해줘.
  1) 리포트 메일 본문에 "이름/날짜" 외에 '문의 내용 요약(앞 60자)' 칼럼을 추가하고,
     문의 내용에 들어있는 <, >, & 같은 글자가 메일에서 깨지거나 위험하지 않게 안전하게 변환(escape)해줘.
  2) 지난 주 문의가 0건일 때도 에러 없이 "지난 주에는 신규 문의가 없었습니다." 가 표시되고
     제목은 "신규 문의 0건" 으로 나가게 해줘.
  3) 표에 총 건수와 대상 기간 라벨(예: 2026-06-08 ~ 2026-06-15)을 눈에 띄게 보여줘.
  바꾼 부분이 왜 필요한지 한 줄씩 설명도 같이 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  211 워크플로우를 실행했는데 아래 단계에서 막혔어. 원인을 단계별로 짚어줘.
  - 증상: (예: Supabase 조회 노드에서 401/empty가 떠 / 메일은 가는데 표가 비어 있어 / 날짜 기간이 안 맞아)
  - 그 노드의 출력/에러 메시지: (여기에 붙여넣기)
  점검해줄 것: ① service_role 키 환경변수가 제대로 들어갔는지 ② URL의 created_at gte/lt 조건 형식이
  ISO(2026-06-08T00:00:00.000Z)인지 ③ Aggregate 출력의 data 배열을 다음 Code가 제대로 받는지
  ④ 시간대(UTC vs Asia/Seoul) 때문에 주 경계가 어긋난 건 아닌지.
  비전공자가 따라할 수 있게 고치는 방법을 순서대로 알려줘.
  ```
> 프롬프트 팁: 마지막에 "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면, 결과를 그대로 쓰지 않고 '옳은지 판별하는 디렉터'로 배울 수 있습니다.

## 검증법

- **기간이 맞는지**: `지난 주 기간 계산 (Code)` 출력의 `기간라벨`이 "지난 주 월요일 ~ 이번 주 월요일"로 7일 간격인지 확인합니다.
- **건수가 맞는지**: `HTML 리포트 만들기 (Code)` 출력의 `총건수`가, `지난 주 문의 조회` 노드가 가져온 행(item) 수와 같으면 정상입니다.
- **메일이 도착하는지**: `toEmail`로 지정한 주소의 받은 편지함에 `[주간 리포트] 신규 문의 N건 (기간)` 제목의 메일이 오고, 본문에 날짜·이름·문의 요약 표가 보이면 성공입니다.
- **문의가 0건일 때**: 지난 주 문의가 없으면 표 자리에 "지난 주에는 신규 문의가 없었습니다."가 표시되고, 제목은 `신규 문의 0건`으로 나옵니다(에러 없이 정상 발송).
- **데이터 없이 구조만 확인**: 준비물을 아직 안 채웠다면 Supabase 조회 노드에서 멈출 수 있습니다. 이때는 그 노드의 출력에 **연습용 데이터를 Pin**(고정)해 두면, 그 뒤(Aggregate→리포트)까지 흐름과 메일 본문 모양을 확인할 수 있습니다.

## 흔한 실수 (참고)

- **anon 키와 service_role 키를 헷갈림**: 이 자동화는 서버(n8n)에서만 도니 비밀 키인 **service_role**을 환경변수로 씁니다. service_role 키를 프런트엔드 코드나 공개 저장소에 절대 넣지 마세요.
- **날짜 비교가 안 됨**: Supabase 필터는 ISO 형식(`2026-06-08T00:00:00.000Z`)을 씁니다. 코드가 이미 이 형식으로 만들어 주므로 그대로 두면 됩니다.
- **시간대(Timezone)**: 이 예제는 UTC 기준으로 계산합니다. 한국 시간 기준 정확한 주 경계가 필요하면 n8n 설정의 Timezone을 `Asia/Seoul`로 바꾸고 계산 코드를 그에 맞춰 조정하세요.
