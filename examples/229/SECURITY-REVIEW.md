# 229. 보안 리뷰 리포트 (예시 결과물)

> 이것은 [`prompt.md`](prompt.md)의 1~3단계로 AI를 "보안 심사관"으로 세워
> [`vulnerable-code.html`](vulnerable-code.html) 와 [`vulnerable-policy.sql`](vulnerable-policy.sql)을
> 검사시킨 **예시 결과물**입니다. 여러분이 본인 코드로 돌리면 항목 판정은 달라질 수 있습니다.
> "내 결정" 칸은 **사람(디렉터)이 직접** 채웁니다.

## 1) 7개 항목 판정표

| # | 항목 | 판정 | 근거 (검사한 코드의 위치) | 한 줄 개선안 |
|---|------|:---:|------|------|
| 1 | 비밀키가 프론트에 박혀 있나 | ❌ | `vulnerable-code.html` 의 `SUPABASE_KEY = "sb_secret_..."` — 비밀키를 브라우저 코드에 둠 | 공개키(`sb_publishable_`)로 교체하고 비밀키는 서버 전용으로 |
| 2 | 프론트에 공개키만 쓰나 | ❌ | 위와 동일. 공개키가 아니라 비밀키가 들어가 있음 | anon/publishable 키로 교체 |
| 3 | RLS가 켜져 있나 | ❌ | `vulnerable-policy.sql` 에 `enable row level security` 줄이 아예 없음 | `alter table members enable row level security;` 추가 |
| 4 | 전체 읽기 정책에 개인정보가 노출되나 | ❌ | `for select using (true)` + 테이블에 `phone`, `email` 컬럼 존재 | 읽기를 `auth.uid() = user_id` (본인 행)로 좁힘 |
| 5 | 쓰기/수정/삭제가 본인·관리자만인가 | ⚠️ | `아무나 쓰기/수정/삭제` 정책이 모두 `(true)` | insert/update/delete 모두 `auth.uid() = user_id`로 제한 |
| 6 | 비밀값이 진짜 값으로 박혀 있나 | ⚠️ | 재료 파일은 자리표시자이나, 패턴상 진짜 `sb_secret_` 값이 들어갈 자리 | 키는 환경변수/서버로, 코드엔 자리표시자만 |
| 7 | 에러/디버그가 데이터를 그대로 뱉나 | ⚠️ | `console.log("전체 회원 데이터:", data)` 와 `console.error(error)` | 사용자용 메시지만 노출, 원문 로그 제거 |

> 총평(맨 마지막 한 줄): **지금 이대로 배포하면 회원 명단 전체가 털린다. ❌ 3건은 배포 전 필수 수정.**

## 2) 가장 위험한 것부터: 왜 ❌인가 (비전공자용 풀이)

- **❌ 비밀키를 프론트에 둠(1·2번):** `service_role`(=`sb_secret_`) 키는 RLS를 통째로 우회하는 **마스터키**입니다.
  브라우저로 내려가는 순간 F12 → Sources 에서 누구나 복사해, 자기 노트북에서 그 키로 접속하면
  모든 테이블을 다 읽고 지울 수 있습니다. **공개키(anon)는 화면에 보여도 안전하지만, 비밀키는 절대 아닙니다.**
- **❌ RLS 미설정(3번):** RLS가 꺼져 있으면 **공개키만으로도** 테이블 전체가 읽힙니다.
  "키만 숨기면 된다"가 틀린 이유가 이것입니다. **공개 키가 안전한 진짜 이유는 RLS** 입니다.
- **❌ 전체 읽기 + 개인정보(4번):** `using (true)`는 "아무나 전부 읽기"입니다.
  이름·전화·이메일이 든 명단을 통째로 가져갈 수 있어, RLS를 켜더라도 정책 자체가 열려 있으면 똑같이 뚫립니다.

## 3) 고친 정책 / 고친 코드 (❌·⚠️ 반영)

- 고친 SQL 정책 → [`fixed-policy.sql`](fixed-policy.sql)
  - `alter table members enable row level security;` (RLS 켬)
  - 읽기/쓰기/수정/삭제 모두 `auth.uid() = user_id` (본인 행만)
  - 기존 `using (true)` 정책은 `drop policy`로 제거 (정책은 OR라 하나만 열려도 뚫림)
- 고친 프론트 코드 → [`fixed-code.html`](fixed-code.html)
  - 비밀키 → 공개키(`sb_publishable_`)로 교체
  - `select("*")` 전체 → 본인 행만, 보여줄 컬럼만
  - 콘솔에 데이터/에러 원문 뱉던 부분 제거, 사용자용 메시지만

## 4) 내 결정 (← 사람이 직접 채우는 칸)

| 항목 | AI 개선안 | 내 결정 (지금 고친다 / 다음에 / 동의 안 함) |
|---|---|---|
| 1·2 비밀키 분리 | 공개키로 교체, 비밀키는 서버 | 지금 고친다 (배포 차단 사유) |
| 3 RLS 켜기 | enable + 본인 정책 | 지금 고친다 (배포 차단 사유) |
| 4 전체읽기 → 본인 | `auth.uid()=user_id` | 지금 고친다 |
| 5 쓰기/수정/삭제 제한 | 본인만 | 지금 고친다 |
| 6 비밀값 자리표시자 | 환경변수로 | 지금 고친다 |
| 7 디버그 로그 | 사용자 메시지만 | 다음에 (배포 차단 아님, 그러나 곧) |

> **마무리 점검(3단계 자진 보고):** 고친 정책이 (가) RLS enable 했고 (나) 읽기를 본인 행으로 좁혔고
> (다) 비밀키가 프론트에서 완전히 빠졌는가? → 세 가지 모두 **통과**. (미통과면 그 자리에서 다시 고칠 것)
