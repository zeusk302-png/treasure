# 230. 배포 자동화 스킬 /deploy 만들기 (비밀키 점검 단계 포함)

## 목표

매번 손으로 "상태 보고 → 빌드 확인 → 키 새는 거 없나 보고 → 커밋하고 → 푸시하고 → 주소 알려줘"라고
시키던 **배포 과정을, 스킬(SKILL.md) 한 장으로 자동화**해서 **"배포해줘" 한마디**면
AI가 늘 똑같은 **6단계 순서**로 안전하게 내보내게 만드는 연습입니다.

배포는 단계가 많고, 그래서 비전공자가 가장 자주 사고를 내는 지점입니다 —
특히 **비밀키(service_role)를 코드째 깃에 올려 버리는 사고**가 흔합니다. 한 번 올라가면 지워도 기록에 남습니다.
그래서 이번 스킬의 핵심은 **순서 중간에 "비밀키 점검"이라는 안전핀을 박아 두고, 거기서 ❌가 나면
커밋·푸시로 넘어가지 못하게 막는 것**입니다. 사람이 매번 기억하지 않아도, 스킬이 늘 같은 자리에서 멈춰 줍니다.

> 이전 실습(228)이 "배포 *전* 점검"을 스킬로 만들었다면, 이번 230은 **점검을 품은 채 실제 배포까지 가는
> 다단계 파이프라인**입니다. 여러 일을 정해진 순서로, 중간에 조건부로 멈추게 엮는 게 핵심입니다.

이 폴더의 파일과 구조는 이렇습니다.

- [`.claude/skills/deploy/SKILL.md`](.claude/skills/deploy/SKILL.md) — **이 실습의 핵심 결과물.** `/deploy` 스킬 본체. 맨 위 `---` 사이에 `name`/`description`(frontmatter), 아래 본문에 6단계 순서·중단 규칙·커밋 형식·보고 표가 들어 있습니다.
- [`sample/index.html`](sample/index.html) — 스킬을 **시험 삼아 돌려볼 배포 대상.** 일부러 service_role(비밀) 키를 박아 두어, 3단계에서 ❌로 멈춰야 합니다.
- [`sample-fixed/index.html`](sample-fixed/index.html) — 위 파일을 비밀키 없이 고친 버전. anon(공개) 키만 두어, 끝까지 배포가 진행됩니다.
- [`deploy-결과예시.md`](deploy-결과예시.md) — **실행 결과 보고의 예시.** 두 파일에 각각 돌렸을 때 나와야 하는 `✅/⚠️/❌/⏸️` 표입니다.
- `README.md` — 지금 읽는 이 안내문

## 따라하는 단계

1. 폴더 구조를 만듭니다. 프로젝트 안에 정확히 이 경로로 둡니다: `.claude/skills/deploy/SKILL.md`. (폴더 이름 `deploy`가 곧 스킬 이름 `/deploy`가 됩니다)
2. [`SKILL.md`](.claude/skills/deploy/SKILL.md)를 엽니다. 맨 위 `---`와 `---` 사이가 **frontmatter**입니다. 두 가지를 적습니다.
   - `name: deploy` — 스킬 이름(폴더명과 같게)
   - `description:` — **AI가 "지금 이 스킬을 써야 하나?"를 판단하는 한 줄.** "배포해줘 / 올려줘 / 푸시하고 배포" 같은 **호출 신호**와 "상태→빌드→비밀키→커밋→푸시→URL"이라는 **하는 일**을 함께 적습니다.
3. `---` 아래 본문에 **6단계 순서**와 **각 단계의 판정 기준**, **중단 규칙**, **커밋 메시지 형식**, **보고 표**를 적습니다. (이 폴더의 SKILL.md를 그대로 쓰거나 내 프로젝트에 맞게 고칩니다)
4. 가장 중요한 **3단계(비밀키)**를 정확히 적습니다. **anon(공개) 키·프로젝트 URL은 코드에 있어도 ✅**, **service_role(비밀) 키·`sk_live_`·비밀번호·토큰이 보이면 ❌ → 즉시 중단(커밋·푸시 금지)**. 그리고 **보고서에 비밀값을 그대로 옮기지 말고 자리표시자(`YOUR_SERVICE_ROLE_KEY`)로 가린다**는 규칙을 박아 둡니다.
5. **커밋 형식**을 Conventional Commits(`type: 요약`, 예 `feat: 방명록 폼 추가`)로 고정하고, **푸시는 사람 승인 후에만** 한다는 규칙을 본문에 넣습니다.
6. 시험해 봅니다(중단되는 경우). AI에게 **"/deploy 로 `sample/index.html` 배포해줘"** 라고 합니다. 비밀키가 있으므로 **3단계에서 ❌로 멈추고** 커밋·푸시를 하지 않아야 정답입니다([`deploy-결과예시.md`](deploy-결과예시.md) 예시 1 참고).
7. 시험해 봅니다(끝까지 가는 경우). 이번엔 **"/deploy 로 `sample-fixed/index.html` 배포해줘"** 라고 합니다. 비밀키가 없으므로 3단계가 ✅로 통과하고, 커밋 메시지를 제안한 뒤 **푸시 전에 한 번 확인**하고, 마지막에 배포 URL을 보고해야 합니다(예시 2 참고).
8. 마지막으로 **내 진짜 프로젝트**(GitHub에 연결되고 Vercel 자동배포가 붙은 폴더)에 같은 스킬을 돌립니다. 3단계를 모두 통과하면 사람이 푸시를 승인하고, **나온 배포 URL을 브라우저로 열어 1분간 직접 확인**합니다. (무엇을 커밋하고 언제 올릴지는 사람이 결정)

## 검증법

아래를 모두 만족하면 성공입니다.

- [ ] 경로가 정확히 `.claude/skills/deploy/SKILL.md` 다. (폴더 이름이 스킬 이름)
- [ ] SKILL.md 맨 위에 `---`로 감싼 **frontmatter**가 있고, 그 안에 `name`과 `description`이 있다.
- [ ] `description`에 **호출 신호("배포해줘" 등)** 와 **하는 일(6단계)** 이 함께 적혀 있다.
- [ ] "배포해줘" 같은 한마디로 스킬이 불려 나오고, **git 상태 → 빌드 확인 → 비밀키 점검 → 커밋 → 푸시 → 배포 URL** 6가지를 **이 순서로** 진행한다.
- [ ] **3단계(비밀키)에서 ❌가 나면 4단계 이후(커밋·푸시)로 넘어가지 않고 멈춘다.** ([`sample/index.html`](sample/index.html)에서 이 동작이 확인돼야 함)
- [ ] 비밀키 항목에서 **anon(공개) vs service_role(비밀)** 을 정확히 구분한다. (공개키·URL은 ✅, 비밀키 노출은 ❌)
- [ ] 커밋 메시지가 **Conventional Commits 형식(`type: 요약`)** 으로 나온다.
- [ ] **푸시 전에 사람에게 한 번 확인**하고, 승인 전 단계는 표에 `⏸️`로 표시한다.
- [ ] 결과가 **`✅/⚠️/❌/⏸️` 표**로 나오고, 마지막에 **배포 URL** 또는 **중단 사유**가 한 줄 결론으로 붙는다.
- [ ] 보고서·예시에 **비밀값을 그대로 적지 않고** 자리표시자로 가렸다.

> 빠른 자가 점검: [`sample/index.html`](sample/index.html)에 스킬을 돌려 **3단계에서 멈추면(커밋·푸시 안 함)** 안전핀이 작동하는 것이고, [`sample-fixed/index.html`](sample-fixed/index.html)에 돌려 **끝까지 가서 URL이 나오면** 파이프라인이 완성된 것입니다. 두 동작이 [`deploy-결과예시.md`](deploy-결과예시.md)와 같으면 통과입니다.
> 만약 비밀키가 있는데도 그냥 커밋·푸시까지 가 버리면, 아직 SKILL.md의 "중단 규칙"이 덜 단호한 것입니다.
