# /deploy 실행 결과 예시

`/deploy` 스킬을 두 파일에 각각 돌렸을 때 **나와야 하는** 보고서입니다.
이렇게 나오면 스킬이 제대로 작동하는 것입니다.

---

## 예시 1) `sample/index.html` 에 돌렸을 때 → 비밀키로 중단

`sample/index.html` 에는 service_role(비밀) 키가 박혀 있으므로, **3단계에서 멈추고 커밋·푸시로 넘어가지 않아야** 합니다.

```
# /deploy 결과 — sample (방명록)

| 단계 | 상태 | 내용 / 근거 |
|---|---|---|
| 1. git 상태 | ✅ | index.html 1개 변경. .env 등 위험 파일은 추적되지 않음 |
| 2. 빌드 확인 | ✅ | 정적 사이트. <script src> 경로 이상 없음 |
| 3. 비밀키 점검 | ❌ | index.html 안에 service_role(비밀) 키 사용. 변수명 SUPABASE_SERVICE_ROLE = "YOUR_SERVICE_ROLE_KEY" — 프론트에 두면 안 됨. 환경변수로 옮기고 키를 회전(재발급)할 것 |
| 4. 커밋 | ⏸️ | 비밀키 노출로 진행 안 함 |
| 5. 푸시 | ⏸️ | 비밀키 노출로 진행 안 함 |
| 6. 배포 URL | ⏸️ | 비밀키 노출로 진행 안 함 |

## 한 줄 결론
비밀키 노출로 중단 — service_role 키를 코드에서 빼고(anon 공개키로 교체) 다시 /deploy 하세요.
```

> 비밀값은 보고서에 진짜 값으로 적지 않고 `YOUR_SERVICE_ROLE_KEY` 같은 자리표시자로 가립니다.

---

## 예시 2) `sample-fixed/index.html` 에 돌렸을 때 → 끝까지 배포

비밀키를 빼고 anon(공개) 키만 둔 버전이라, **3단계가 ✅로 통과**하고 끝까지 진행됩니다.
(아래 커밋 메시지·URL은 예시값입니다. 실제로는 사람 승인 후 push되고, Vercel이 준 진짜 URL이 들어갑니다.)

```
# /deploy 결과 — sample-fixed (방명록)

| 단계 | 상태 | 내용 / 근거 |
|---|---|---|
| 1. git 상태 | ✅ | index.html 1개 변경. 위험 파일 없음 |
| 2. 빌드 확인 | ✅ | 정적 사이트. 경로 이상 없음 |
| 3. 비밀키 점검 | ✅ | anon(공개) 키 + 프로젝트 URL만 있음(노출돼도 안전). RLS가 켜져 있는지 한 번 확인 권장 |
| 4. 커밋 | ✅ | feat: 방명록 글쓰기 폼 추가 |
| 5. 푸시 | ✅ | origin main 으로 푸시(사람 승인 후) |
| 6. 배포 URL | ✅ | https://내사이트.vercel.app (production) |

## 한 줄 결론
배포 완료 — https://내사이트.vercel.app 를 브라우저로 열어 1분만 직접 확인하세요.
```
