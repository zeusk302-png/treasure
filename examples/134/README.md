# 실습 134 — 새로고침해도 로그인 유지되게 하기 (세션 읽기)

페이지가 열리는 순간 `getSession`으로 **지금 로그인돼 있는지**를 읽어, 새로고침하거나 다시 들어와도 로그인이 풀리지 않게 만듭니다. 서버 코드 없이 브라우저에서 Supabase 인증을 직접 부릅니다.

## 목표
- 로그인하면 Supabase가 토큰을 브라우저에 저장하고(`persistSession`), 다음에 들어올 때 `getSession`으로 그걸 읽어 **로그인이 유지**된다는 흐름을 이해한다.
- "로그인 상태(세션이 있음) / 로그아웃 상태(세션이 없음)"에 따라 화면을 갈라 보여주는 패턴을 익힌다.
- 브라우저에 두는 건 **anon(공개돼도 되는 출입증)** 키뿐이고, `service_role`(절대 숨길 비밀) 키는 절대 두지 않는다는 원칙을 다시 한번 체득한다.

## 따라하는 단계
1. 앞 실습(131·132)에서 만든 **Supabase 프로젝트**와 **테스트 계정**을 그대로 사용한다. (없으면 Authentication → Users에서 "Auto Confirm User"를 켜고 하나 추가한다.)
2. 대시보드 → **Settings → API**에서 `Project URL`과 `anon`(publishable) 키를 복사한다.
3. `index.html` 위쪽의 `SUPABASE_URL`, `SUPABASE_ANON_KEY` 두 값을 내 값으로 바꾼다.
4. `index.html`을 브라우저로 열면, 처음엔 로그인돼 있지 않으므로 **로그인 폼**이 보인다.
5. 테스트 계정의 이메일·비밀번호로 **로그인**하면, 폼이 사라지고 **환영 카드**가 뜬다.
6. 이 상태에서 **새로고침(F5)** 한다 → 로그인이 풀리지 않고 **환영 카드가 그대로** 나오는지 확인한다. (이게 이번 실습의 핵심!)
7. **로그아웃** 버튼을 누르면 세션이 지워지고 다시 로그인 폼으로 돌아간다. 이때 새로고침하면 여전히 로그아웃 상태다.

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 Supabase 인증을 가르치는 웹 강사야. 비전공자가 읽을 단일 index.html 파일 하나를 만들어줘.
  요구사항:
  - 외부 라이브러리는 CDN(@supabase/supabase-js@2) 한 줄만 쓰고, 빌드 도구 없이 브라우저에서 바로 열 수 있을 것.
  - SUPABASE_URL, SUPABASE_ANON_KEY 를 파일 위쪽 상수로 두고, 값은 'sb_publishable_...' 같은 자리표시자로.
  - 화면은 두 영역: (1) 로그인 폼(이메일·비밀번호) (2) 로그인 후 환영 카드 + 로그아웃 버튼.
  - 두 영역은 처음엔 모두 숨기고, JS가 세션을 읽은 뒤 맞는 쪽만 보이게 해줘.
  제약: anon 키만 브라우저에 두고 service_role 키는 절대 넣지 마. 코드만 주지 말고 왜 그렇게 했는지 한국어 주석으로 한 줄씩 설명해줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 로그인 페이지에 '새로고침해도 로그인 유지' 기능을 추가해줘.
  - 페이지가 열리는 순간 db.auth.getSession() 으로 지금 로그인돼 있는지 읽고, 세션이 있으면 환영 카드를, 없으면 로그인 폼을 보여줘.
  - createClient 옵션에 persistSession: true, autoRefreshToken: true 를 명시적으로 적고, 각 옵션이 무엇이고 왜 켜는지 주석으로 설명해줘.
  - 로그아웃 버튼은 db.auth.signOut() 으로 세션을 지우고 다시 로그인 폼으로 돌아가게 해줘.
  - 사용자 이메일을 화면에 찍을 때는 innerHTML 말고 textContent 를 써줘(이유도 주석으로).
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  새로고침하면 로그인이 풀려서 자꾸 로그인 폼으로 돌아가. 아래 상황과 콘솔 에러를 줄게. 한 단계씩 원인을 좁혀서 진단해줘.
  - 증상: (예) 로그인은 되는데 F5 누르면 다시 폼이 보임 / 개발자도구 Application → Local Storage에 sb-...-auth-token 이 없음
  - 콘솔 에러: (여기에 빨간 에러 메시지 붙여넣기)
  먼저 의심되는 원인 후보를 순서대로 나열하고, 각 후보를 내가 직접 확인할 방법(어디를 눌러 무엇을 보는지)을 알려줘. 그다음 고친 코드와 왜 고쳤는지 주석을 줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법
- 로그인 후 새로고침했을 때, 다시 로그인하지 않아도 **환영 카드가 유지**되는가? (← 핵심)
- 브라우저 개발자도구 → **Application → Local Storage**에 `sb-...-auth-token` 같은 항목이 생겼는가? (Supabase가 세션을 여기에 저장합니다.)
- 로그아웃 후 새로고침하면 **로그인 폼**이 나오는가? (Local Storage의 토큰 항목도 사라졌는지 확인)
- 탭을 닫았다가 같은 주소로 다시 열어도 로그인이 유지되는가?

## 핵심 한 줄
페이지가 열릴 때 이 한 줄로 "지금 로그인돼 있는지"를 읽습니다.
```js
const { data } = await db.auth.getSession();
// data.session 이 있으면 로그인 상태, null 이면 로그아웃 상태
```
그리고 `createClient`의 `persistSession: true`(기본값)가 로그인 토큰을 브라우저에 저장해두기 때문에, 새로고침해도 `getSession`이 그 세션을 다시 읽어옵니다.

## 보안 메모 — anon vs service_role
- 여기 넣는 건 **anon(publishable) 키** 하나뿐입니다. anon 키는 "공개돼도 되는 **출입증**"이라 브라우저·GitHub에 있어도 괜찮습니다. (코드의 키 값은 `sb_publishable_...` 자리표시자이니, 내 값으로 바꿔 쓰세요.)
- `service_role`(secret) 키는 모든 **RLS(행 수준 보안)를 통째로 우회**하는 마스터키라, 브라우저나 깃허브에 두면 안 됩니다. 오직 서버(n8n·엣지 함수)에서 환경변수로만 사용하세요. 두 키를 헷갈리는 게 가장 흔한 사고입니다.
- 주의: 브라우저 Local Storage에 저장되는 **세션 토큰**은 그 사용자 본인의 출입증입니다. 공용 PC에서는 꼭 **로그아웃**으로 지우세요.
- 그리고 **로그인이 유지된다고 안전한 게 아닙니다.** "로그인한 사람이 자기 데이터만 만지게" 막는 건 별개의 문제(인가)이고, 그건 DB의 **RLS 정책**(`auth.uid()` 기반)으로 강제해야 합니다.
