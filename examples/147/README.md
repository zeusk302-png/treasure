# 실습 147 — 개발자 도구 Network 탭으로 내 API 요청 엿보기

명언을 받아오는 그 순간, 브라우저 **F12 → Network 탭**을 열어 두면
화면 뒤에서 실제로 오간 **요청 URL · 상태코드(200) · 응답 JSON**을 직접 볼 수 있습니다.
"AI가 그럴 거라고 말한 것" 대신 **눈앞의 1차 증거**를 보는 습관을 들이는 실습입니다.

## 목표
- API 호출이 일어나면 Network 탭에 **요청 한 줄이 찍힌다**는 걸 눈으로 확인한다.
- 그 요청의 **상태코드 200**(정상 제공)과 **응답 JSON**을 직접 펼쳐 본다.
- 본 값을 페이지의 입력칸에 그대로 옮겨 적어, "추측이 아니라 관찰"을 기록한다.

## 따라하는 단계
1. 이 폴더의 `index.html`을 브라우저로 연다(더블클릭).
2. **F12**(또는 마우스 우클릭 → 검사)를 눌러 개발자 도구를 열고, 위쪽 탭에서 **Network**를 고른다.
3. Network 탭이 열린 상태에서 페이지의 **"명언 받아오기"** 버튼을 누른다. (목록이 비어 보이면 새로고침 후 다시 누른다.)
4. 목록에 새로 생긴 요청(`random` 같은 줄)을 **클릭**한다.
5. 오른쪽 패널에서 세 가지를 찾는다:
   - **Headers** 탭의 `Request URL` → 이게 요청 URL이다.
   - 같은 화면의 `Status Code` → **200**이면 정상이다.
   - **Response**(또는 Preview) 탭 → 받아온 **JSON** 안의 글귀 한 줄을 본다.
6. 페이지 아래 **"내가 관찰한 것 적기"** 칸에 위 세 값(요청 URL·상태코드·응답 일부)을 그대로 입력하고 **"관찰 결과 기록하기"** 버튼을 누른다.
7. (선택) Console 탭을 열면 코드가 찍어 둔 `상태코드(status):`와 `응답 JSON:` 로그가 보인다. Network 탭에서 본 값과 같은지 비교해 본다.

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 웹 초보를 가르치는 프론트엔드 멘토야.
  키 없이 누구나 호출 가능한 공개 명언 API(https://api.quotable.io/random)를 쓰는
  아주 단순한 한 페이지짜리 실습을 만들어줘.
  요구사항:
  - 파일은 index.html 과 script.js 두 개만. 외부 라이브러리·빌드 도구 없이 브라우저로 더블클릭하면 바로 동작.
  - "명언 받아오기" 버튼을 누르면 fetch로 위 API를 호출해 받아온 글귀와 저자를 화면에 표시.
  - 받아온 응답의 상태코드(response.status)와 응답 JSON 전체를 console.log 로도 찍어줘
    (목적: F12 → Network 탭에서 본 값과 Console 값을 비교해보게 하려는 것).
  - 사용자에게 보이는 글은 innerHTML 말고 textContent 로 넣어줘(이유도 주석으로).
  비전공자가 읽을 거라 코드 each 줄에 "무엇을 + 왜" 한국어 주석을 달아줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 페이지에 "내가 관찰한 것 적기" 패널을 추가해줘.
  - 입력칸 3개: 요청 URL / 상태코드(Status) / 응답 JSON 일부.
  - "관찰 결과 기록하기" 버튼을 누르면 세 값을 보기 좋게 정리해 화면 아래 박스에 표시.
  - 세 칸 중 하나라도 비어 있으면 기록하지 말고 "세 칸을 모두 채워 주세요" 안내만 띄워줘.
  - 입력값은 앞뒤 공백을 제거(trim)해서 다루고, 출력은 textContent 로 안전하게.
  이 패널의 목적은 "AI가 그럴 거다"가 아니라 Network 탭에서 직접 본 1차 증거를
  손으로 적어보게 하는 거야. 그 의도가 드러나게 placeholder 문구와 주석을 써줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  버튼을 눌렀는데 명언이 안 뜨고 "받아오는 중..."에서 멈춰. 아래 상황을 단계별로 진단해줘.
  - F12 → Console 탭에 빨간 에러가 있으면 그 의미를 한 줄씩 풀어줘.
  - F12 → Network 탭에서 그 요청의 상태코드가 몇 번인지(200/403/404/0/CORS 등)에 따라
    원인이 어떻게 갈리는지 표로 정리해줘.
  - 요청이 빨간 줄(실패)로 뜨는 경우와 200인데 화면만 안 바뀌는 경우를 구분해서
    각각 확인할 코드 위치를 알려줘.
  (여기에 콘솔/네트워크 에러 메시지 그대로 붙여넣기)
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 훨씬 좋습니다.

## 검증법
- 버튼을 누른 직후 Network 탭에 **요청 한 줄**이 새로 나타났는가?
- 그 요청의 상태코드가 **200**인가? (다른 숫자면 무슨 뜻인지 아래 표 참고)
- Response에서 본 글귀가 **화면에 뜬 명언과 같은가?** → 화면 글자가 곧 응답 JSON에서 나온 것임을 확인.
- 입력칸에 적은 세 값이 "관찰 결과" 박스에 정리되어 나타나는가?

!!! tip "상태코드는 디렉터의 진단 단어장"
    "안 돼요" 대신 **"401이 떠요" / "404가 떠요"** 라고 말하는 순간 문제의 성격이 정해집니다.
    `200` 정상 · `404` 주소(메뉴) 없음 · `401` 로그인 필요 · `403` 권한 없음 · `500` 서버가 터짐.

## 참고
- 이 실습은 외부 키가 필요 없는 **공개 API**(`https://api.quotable.io/random`)를 씁니다. 숨길 비밀값이 없으므로 자리표시자도 없습니다. (Supabase처럼 키가 필요한 경우엔 **anon = 공개돼도 되는 출입증**만 브라우저에 두고, **service_role = 절대 숨길 비밀**은 절대 넣지 않습니다.)
- 인터넷이 없으면 요청이 실패하며 Network 탭에 **빨간 줄**로 표시됩니다 — 그 자체가 "요청은 갔지만 응답을 못 받았다"는 증거입니다.
