# 044. 스크롤해도 위에 붙어 있는 스티키 내비바

거의 모든 웹사이트에는 페이지를 아무리 내려도 화면 맨 위에 **계속 보이는 메뉴 막대**가 있습니다. 이것을 **스티키(sticky, 끈끈하게 달라붙는) 내비바**라고 부릅니다. 이번 실습에서는 평소엔 평범하게 있다가 스크롤이 화면 꼭대기에 닿는 순간 **딱 붙어 따라오는** 내비게이션 바를 만듭니다. 핵심 도구는 딱 세 줄입니다. `position: sticky`(스크롤하다 닿으면 붙어라), `top: 0`(화면 맨 위에 붙어라), 그리고 `z-index`(본문보다 위 층에 둬라).

## 목표

- `position: sticky`가 **평소엔 자기 자리에 있다가 스크롤이 정해진 위치에 닿으면 붙는다**는 동작을 이해한다.
- `sticky`는 반드시 `top: 0` 같은 **위치 값과 짝으로** 써야 작동한다는 것을 익힌다.
- `z-index`로 "어느 층이 위에 올지" 정해 **내비바가 본문 위를 덮으며** 항상 보이게 하는 법을 익힌다.
- `position: sticky`와 `position: fixed`(처음부터 둥둥 떠 있음)의 차이를 구분한다.

## 따라하는 단계

1. `index.html`과 `style.css`가 **같은 폴더(044)** 안에 있는지 확인합니다. HTML 위쪽의 `<link rel="stylesheet" href="style.css" />` 한 줄이 두 파일을 연결해 줍니다.
2. `index.html`을 더블클릭해 브라우저(크롬 등)로 엽니다. 맨 위에 어두운 남색 메뉴 막대(내비바)가 보이면 시작 준비 완료입니다.
3. 마우스 휠이나 스크롤바로 **페이지를 천천히 아래로 내려 봅니다.** 본문은 위로 흘러 올라가지만, 위쪽 내비바는 화면 꼭대기에 **딱 붙은 채 그대로** 따라오는 것을 확인합니다. 이것이 스티키 효과입니다.
4. `style.css`의 `.navbar`에 있는 핵심 세 줄을 직접 바꿔보며 원리를 확인합니다. (확인 후 꼭 원래대로 되돌리세요.)
   - `position: sticky;`를 잠깐 `static`으로 바꾸면 → 내비바가 더 이상 붙지 않고, 스크롤하면 본문과 함께 위로 사라집니다. → `sticky`가 "붙이는 스위치"임을 알 수 있습니다.
   - `top: 0;`을 `top: 20px;`로 바꾸면 → 내비바가 화면 맨 위가 아니라 **위에서 20px 떨어진 자리**에 붙습니다. → `top`이 "어디에 붙을지"를 정하는 값임을 알 수 있습니다. (값을 아예 지우면 sticky가 작동하지 않습니다.)
   - `z-index: 10;`을 잠깐 지우거나 `-1`로 바꾸면 → 스크롤할 때 본문 글자가 내비바를 **뚫고 위로 비쳐 보입니다.** → `z-index`가 "층 순서"를 정해 내비바를 본문 위에 올리는 역할임을 알 수 있습니다.
5. (이해 포인트) `sticky`와 `fixed`의 차이를 떠올려 봅니다. `fixed`는 처음부터 화면에 둥둥 떠 있어 본문 맨 위 공간을 가립니다. 반면 `sticky`는 **평소엔 평범하게 자기 자리에 있다가** 스크롤이 닿는 순간에만 붙으므로, 페이지 맨 위에서는 본문을 가리지 않습니다.

> 참고: 스티키 효과는 '스크롤할 거리'가 있어야 눈에 보입니다. 그래서 예제 본문은 일부러 화면보다 길게(각 섹션 높이 `90vh`) 만들었습니다. 별도 이미지나 인터넷 연결 없이 `index.html`만 열어도 바로 동작합니다.

## 🤖 바이브코딩 프롬프트

이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. 한 번에 다 시키지 말고 **뼈대 → 기능 → 디버깅** 순서로 끊어서 시키면, AI가 만든 결과를 단계마다 눈으로 확인할 수 있어 실수를 잡기 쉽습니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 HTML/CSS를 가르치는 강사야. 인터넷 연결이나 외부 이미지 없이
  index.html 파일 하나만 더블클릭하면 바로 열리는 정적 웹페이지를 만들어줘.
  - 맨 위에 내비게이션 바(navbar)를 둬: 왼쪽에 로고 글자 1개, 오른쪽에 메뉴 링크 4개(홈/소개/강의/문의).
  - 내비바 아래에 본문 섹션을 4개 넣되, 각 섹션 높이를 화면보다 길게(min-height: 90vh) 만들어
    스크롤이 충분히 생기게 해줘.
  - CSS는 같은 폴더의 style.css 파일로 분리하고 <link>로 연결해줘.
  - 색은 어두운 남색 내비바 + 밝은 본문으로.
  - 비전공자가 읽을 거니까, 각 코드 줄이 '무엇을 하고 왜 넣었는지' 한국어 주석으로 설명해줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 내비바를 '스티키(sticky)'로 바꿔줘.
  스크롤을 내려도 내비바가 화면 맨 위에 딱 붙어서 계속 따라오게 하고 싶어.
  - .navbar 에 position: sticky; 와 top: 0; 을 짝으로 넣어줘.
  - 스크롤할 때 본문 글자가 내비바를 뚫고 비치지 않도록 z-index 로 내비바를 본문 위 층에 올려줘.
  - 떠 있는 느낌이 나게 내비바 아래에 옅은 그림자(box-shadow)도 넣어줘.
  - 그리고 sticky 와 fixed 가 어떻게 다른지, 왜 여기서는 fixed 가 아니라 sticky 를 쓰는지
    주석으로 짧게 설명해줘.
  - 화면이 좁은 모바일(600px 이하)에서는 글자와 간격이 작아지도록 미디어 쿼리도 추가해줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  내비바에 position: sticky; 를 줬는데도 스크롤하면 그냥 같이 위로 사라져버려.
  무엇이 문제인지 단계별로 짚어줘.
  - top 값이 빠지지 않았는지, 부모 요소에 overflow: hidden 같은 게 있어서 sticky 가
    안 먹는 건 아닌지 확인하는 방법을 알려줘.
  - 스크롤할 때 본문 글자가 내비바를 뚫고 비친다면 어디를 고쳐야 하는지도 알려줘.
  - 고친 뒤에는 무엇을 왜 바꿨는지 주석으로 설명해줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 **왜 그렇게 했는지 주석으로 설명해줘**", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면, AI가 만든 코드를 그대로 베끼는 게 아니라 직접 검증하는 '디렉터'가 될 수 있습니다.

## 검증법

- 브라우저로 `index.html`을 열면 맨 위에 **어두운 남색 내비바(로고 + 메뉴 4개)** 가 보인다.
- 페이지를 아래로 스크롤하면 본문은 올라가지만 **내비바는 화면 맨 위에 그대로 붙어 따라온다.**
- 스크롤 중에도 본문 글자가 내비바를 뚫고 비치지 않고, **내비바가 본문을 깔끔하게 덮으며 항상 또렷하게 보인다** (`z-index`가 적용된 상태).
- 다시 맨 위로 스크롤해 올라가면 내비바가 **원래 자리(맨 위)** 로 자연스럽게 돌아온다.
- 개발자도구(F12) > Elements에서 `.navbar`를 선택하면 `position: sticky`, `top: 0`, `z-index: 10`이 적용된 것을 확인할 수 있다.
- 브라우저 창 너비를 모바일 크기(600px 이하)로 줄이면 로고·메뉴 글자와 간격이 작아진다.
