# 수집 항목 사유표 (이번 실습의 결과물)

폼과 테이블에 있던 모든 항목을 한 줄씩 놓고, **"이게 없으면 서비스가 동작 안 하나?"** 라는 질문을 통과하는지 점검한 표입니다.
판정은 **🟢 유지(꼭 필요) / 🔴 삭제(안 씀·과수집)** 두 가지로만 매깁니다.

## 1) 항목별 점검 표

| 항목 | 이게 없으면 서비스가 안 되나? | 어디에 쓰나(쓴다면) | 민감도 | 판정 |
|---|---|---|---|---|
| 이름 | 예 — 사용자를 부르고 식별 | 화면 인사·식별 | 낮음 | 🟢 유지 |
| 이메일 | 예 — 로그인 ID이자 유일한 연락 수단 | 로그인·비번 재설정·공지 | 중간 | 🟢 유지 |
| 비밀번호 | 예 — 본인 인증의 핵심 | 로그인 (해시로만 저장) | 높음 | 🟢 유지 |
| 주민등록번호 | 아니오 — 쓰는 기능이 전혀 없음 | (사용처 없음) | 매우 높음 | 🔴 삭제 |
| 생년월일 | 아니오 — 연령 제한·개인화 미구현 | (사용처 없음) | 중간 | 🔴 삭제 |
| 집 주소 | 아니오 — 배송이 없는 서비스 | (사용처 없음) | 높음 | 🔴 삭제 |
| 휴대폰 번호 | 아니오 — 이메일 연락으로 충분 | (사용처 없음) | 중간 | 🔴 삭제 |
| 성별 | 아니오 — 개인화·통계에 안 씀 | (사용처 없음) | 중간 | 🔴 삭제 |

## 2) 삭제 항목의 "삭제 이유" 한 줄 정리

| 삭제 항목 | 삭제 이유 |
|---|---|
| 주민등록번호 | 법령상 근거 없는 주민번호 수집은 원칙적으로 금지. 식별에 이메일이면 충분 — **유출 시 가장 위험한 항목이라 애초에 받지 않는다.** |
| 생년월일 | 연령 제한·생일 쿠폰 같은 기능이 없어 "언젠가 쓸지도"의 추측 수집. 필요해지면 그때 받는다. |
| 집 주소 | 배송·방문이 없는 온라인 서비스라 수집 근거가 없음. |
| 휴대폰 번호 | 공지·인증 모두 이메일로 처리하므로 중복 연락처. |
| 성별 | 개인화/통계에 사용하지 않음. "혹시 몰라서" 받는 대표적 과수집 항목. |

## 3) 다이어트 결과 요약

| 구분 | 고치기 전(Before) | 고친 뒤(After) |
|---|---|---|
| 폼 입력란 수 | 8개 | 3개 |
| 테이블 칼럼 수(개인정보) | 7개 | 2개 (이름·이메일) |
| 민감정보(주민번호 등) | 4종 수집 | **0종** |

> 최종 결론: **안 쓰는 항목 5개를 폼·테이블에서 통째로 제거. 민감정보 수집 = 0건.**
> 핵심 원칙 — "모은 만큼 책임이 커진다. 그러니 처음부터 덜 모은다(데이터 최소 수집)."

## 4) 판정 기준 (왜 🟢/🔴인가)

- **🟢 유지**: "이 항목이 없으면 서비스의 핵심 기능이 동작하지 않는다"를 통과한 항목. 수집할 명확한 목적과 사용처가 있다.
- **🔴 삭제**: 현재 어떤 기능에서도 쓰지 않는데 "일단 받아두자 / 혹시 몰라서"로 모으던 항목. **과수집**이며, 받는 순간 보관·파기·유출 대응 책임만 늘어난다.
- 판단이 애매하면 기본값은 **🔴 삭제**. 정말 필요해지는 시점에 "왜 받는지(목적)"를 분명히 하고 그때 다시 추가하는 것이 안전하다.
