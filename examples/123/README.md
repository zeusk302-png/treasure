# 실습 123 — 방명록을 최신순으로 정렬해서 보여주기

실습 117에서 방명록 글들을 **불러오기(select)** 까지 했습니다.
그런데 글이 데이터베이스에 들어온 순서대로(혹은 뒤죽박죽으로) 보이면 읽기 불편하죠.
보통 게시판·댓글은 **최신 글이 맨 위**에 오는 게 자연스럽습니다.

이번 실습의 핵심은 `select` 뒤에 딱 한 줄, **`.order()`** 를 붙이는 것입니다.

```js
const { data, error } = await db
  .from("guestbook")
  .select("*")
  .order("created_at", { ascending: false }); // ← 이 한 줄이 전부!
```

> 비유: 117이 "선반 위 글들을 그냥 한 움큼 꺼내 오기"였다면,
> 123은 꺼내 오기 **전에** 서버에게 "**최신순으로 줄 세워서** 줘"라고 부탁하는 것입니다.
> 줄을 세우는 일(정렬)은 우리(브라우저)가 아니라 **서버(DB)** 가 대신 해 줍니다.

이 폴더에 있는 파일:

- `README.md` — 이 안내문
- `schema.sql` — `guestbook` 표 SQL (116~117과 **같은 표**. 이미 만들었으면 다시 실행 안 해도 됨 + 정렬 확인용 글 3개 포함)
- `index.html` — 글 목록이 표시될 화면 (`ul#list` + **정렬 기준 드롭다운** + 새로고침 버튼)
- `script.js` — **핵심 코드.** `.order(컬럼, { ascending })` 로 서버에 정렬을 부탁합니다.

## 목표

- `.order("created_at", { ascending: false })` 로 **최신 글이 맨 위에** 오게 정렬한다.
- `ascending` 옵션의 뜻을 이해한다: `false` = **내림차순(최신→옛날)**, `true` = **오름차순(옛날→최신)**.
- 정렬 **기준 컬럼**을 `created_at`(시간) ↔ `name`(이름)으로 바꿔 보며, **무엇을 기준으로 줄 세우는지**가 곧 정렬 컬럼임을 익힌다.
- 정렬은 **서버(DB)가 해서 보내 준다**는 점을 이해한다. (우리는 "기준"만 알려 주고, 받은 순서 그대로 그린다.)

## 따라하는 단계

1. **표를 준비한다.** 실습 116~117에서 `guestbook` 표를 이미 만들었다면 건너뛰세요.
   아직 없다면 Supabase 대시보드 → **SQL Editor → New query** 에 이 폴더의 `schema.sql`을
   통째로 붙여넣고 **[Run]** 을 누른다. (이 파일은 시각이 서로 다른 연습용 글 3개도 함께 넣어 줍니다 — 정렬 차이를 눈으로 보기 위함.)
2. **글이 2개 이상 있어야 정렬 차이가 보인다.** 글이 1개뿐이면 어떤 기준으로 정렬해도 똑같아 보입니다.
   1단계의 연습용 글을 넣었거나, 116 폴더로 글을 여러 개 남겼는지 확인하세요.
3. Supabase 대시보드 **Settings(톱니바퀴) → API** 에서 두 값을 복사한다.
   - **Project URL** : `https://xxxxxxxx.supabase.co` 형태의 주소 (비밀 아님)
   - **anon public** 키 (신형은 `sb_publishable_...` 로 시작) : 브라우저에 둬도 되는 **공개 출입증**
   - ⚠️ 같은 화면의 **`service_role` / `sb_secret_...` 키는 절대 쓰지 마세요.** 모든 보안을 무시하는 마스터 키입니다.
4. 이 폴더의 `script.js`를 열고, 맨 위 두 줄의 **자리표시자**를 내 값으로 바꾼다.
   ```js
   const SUPABASE_URL = "https://여기에-내-프로젝트-ID.supabase.co";   // ← 내 Project URL
   const SUPABASE_ANON_KEY = "sb_publishable_여기에-내-anon-공개키-붙여넣기"; // ← 내 anon public 키
   ```
5. `index.html`을 **브라우저로 연다.** (파일을 더블클릭)
   → 페이지가 열리면 기본값인 **최신순(created_at ↓)** 으로 한 번 불러와 목록을 보여 줍니다.
6. 화면 위쪽 **[정렬 기준]** 드롭다운을 바꿔 본다.
   - **최신순 (created_at ↓)** → 방금 쓴 글이 맨 위
   - **오래된순 (created_at ↑)** → 가장 먼저 쓴 글이 맨 위 (`ascending: true`)
   - **이름 가나다순 (name ↑)** → 글쓴이 이름 ㄱ→ㅎ 순
   - **이름 역순 (name ↓)** → 글쓴이 이름 ㅎ→ㄱ 순
   기준을 바꿀 때마다 **같은 글들이 순서만 바뀌어** 다시 그려지는 걸 확인하세요.
7. (이해 점검) `script.js`의 핵심 줄에서 `ascending` 값을 직접 `false` ↔ `true`로,
   컬럼을 `"created_at"` ↔ `"name"`으로 바꿔 보고 새로고침해 본다.
   → 코드 한 글자 차이로 목록 순서가 통째로 바뀌는 걸 체감하면 성공입니다.

## 검증법

- 페이지를 처음 열면 **최신 글이 맨 위**에 오는가? (기본 = `created_at` 내림차순)
- 드롭다운을 **오래된순**으로 바꾸면 **가장 먼저 쓴 글이 맨 위**로 올라오는가? (순서가 위아래로 뒤집힘)
- 드롭다운을 **이름 가나다순**으로 바꾸면 글쓴이 이름이 **ㄱ→ㅎ** 순서로 정렬되는가?
- 브라우저 **개발자 도구 → Console**(윈도우 `F12`, 맥 `Cmd + Option + I`)에
  `✅ 성공! 서버가 정렬해서 돌려준 글 N개` 로그가 찍히고, 그 배열의 순서가 화면 순서와 같은가?
  (= 정렬은 화면이 아니라 **서버가 해서 보낸** 것임을 확인)
- 정렬 기준을 여러 번 바꿔도 목록이 **중복으로 쌓이지 않는가?** (`listEl.innerHTML = ""` 동작 확인)
- **실패할 때 원인 찾기** (콘솔의 빨간 에러 메시지로 구분):
  - `relation "public.guestbook" does not exist` → 표가 없음. 1단계 `schema.sql`을 실행.
  - `column guestbook.xxx does not exist` → `.order()`에 **없는 컬럼 이름**을 넣음. 컬럼은 `id`·`name`·`message`·`created_at` 뿐.
  - `Invalid API key` → anon 키를 잘못 붙여넣음. (혹시 service_role을 넣지 않았는지도 확인)
  - 주소 오류 / `Failed to fetch` → `SUPABASE_URL`의 철자나 `https://` 확인.
  - **에러는 없는데 목록만 계속 비어 있다?** → 표에 **RLS가 켜져 있는데 "읽기(select) 정책"이 없는** 경우입니다.
    정렬을 어떻게 바꿔도 받아 올 글 자체가 0개라 비어 보입니다. (정책 거는 법은 실습 119)
- **(안전 점검)** `script.js`에 넣은 키가 **`anon` / `sb_publishable_`** 로 시작하는가? `service_role` / `sb_secret_` 가 **아닌가?**
