# 노드 실패 시 자동으로 실패 알림 받기 (Error Workflow)

자동화는 사람이 안 볼 때(새벽, 주말, 자는 동안)에도 돕니다. 그래서 가장 위험한 건 "**조용히 실패하고 아무도 모르는**" 상황입니다. 결제 정산이 새벽에 멈췄는데 다음 날 아침까지 아무도 모른다면, 그게 진짜 사고입니다.

이번 실습에서는 **"어떤 워크플로우든, 어떤 노드든 실패하면 나에게 즉시 알림이 오게"** 만듭니다. 비결은 알림을 보내는 **별도의 작은 워크플로우(Error Workflow)** 하나를 만들어 두고, 다른 워크플로우들이 실패할 때 그 알림 워크플로우를 호출하도록 **연결**해 두는 것입니다. 한 번 만들어 두면 여러 워크플로우가 같은 알림을 함께 쓸 수 있습니다.

> **한마디로:** "내 자동화가 넘어지면, 119에 자동으로 전화가 가게 해 두기"입니다. 119 역할을 하는 게 **Error Workflow**, 전화를 거는 신호가 **Error Trigger**입니다.
>
> **이 실습은 워크플로우가 2개입니다.**
> - **`error-workflow.json`** — 알림 담당. `에러 감지(Error Trigger)` → `에러 내용 정리(Set)` → `Slack으로 알림`. 노드 3개.
> - **`main-workflow.json`** — 평소에 일하는 워크플로우. 여기서는 **일부러 실패하는 노드**를 넣어 알림이 진짜 오는지 시험합니다. 노드 3개.

## 목표

- **Error Trigger**로 시작하는 **별도의 알림 워크플로우**를 만든다.
- 메인 워크플로우의 **설정(Error Workflow)** 에 그 알림 워크플로우를 **연결**해, 어떤 노드가 실패하든 자동으로 알림이 가게 한다.
- 실패한 **워크플로우 이름·노드 이름·에러 메시지·발생 시각**을 Slack 메시지에 담아, 무엇이 왜 멈췄는지 한눈에 알 수 있게 한다.

## 따라하는 단계

1. **n8n에 로그인**합니다. (n8n Cloud 또는 직접 설치한 n8n 모두 가능합니다.)
2. **먼저 알림 워크플로우부터 만듭니다.** 오른쪽 위 **`...`(점 3개) → `Import from File`** 로 이 폴더의 **`error-workflow.json`** 을 불러옵니다. 노드 3개(`에러 감지` → `에러 내용 정리` → `Slack으로 알림`)가 나타납니다.
3. **`Slack으로 알림 보내기` 노드를 더블클릭**합니다.
   - `Slack account` 자격증명을 연결합니다. (`Create New Credential`을 눌러 Slack 토큰을 넣고 저장 — 토큰은 **자격증명 금고에만** 저장되고 파일에는 남지 않습니다.)
   - 알림을 받을 **채널 ID**를 넣습니다. (지금은 `REPLACE_WITH_YOUR_SLACK_CHANNEL_ID` 자리표시자가 들어 있습니다.)
   - 메일로 받고 싶다면 Slack 노드 대신 `Send Email`(SMTP/Gmail) 노드로 바꿔도 됩니다. 들어오는 값(`{{ $json.에러_메시지 }}` 등)은 그대로 쓰면 됩니다.
4. **이 알림 워크플로우를 저장**합니다. 저장하면 브라우저 주소창에 이 워크플로우의 **ID**가 보입니다. 예: `.../workflow/abc123def456` 에서 `abc123def456` 부분이 ID입니다. **이 ID를 복사해 둡니다.** (5단계에서 씁니다.)
   - 참고: Error Trigger는 "다른 워크플로우가 실패했을 때 호출되는" 트리거라, 일반 트리거처럼 켜 둘 필요가 없습니다.
5. **이제 메인 워크플로우를 불러옵니다.** 같은 방식으로 **`main-workflow.json`** 을 Import 합니다. 노드 3개가 나타납니다. 가운데 `일부러 실패하는 노드`는 존재하지 않는 주소를 부르도록 만들어져 있어 **항상 실패**합니다. (알림 테스트용입니다.)
6. **메인 워크플로우에 알림 워크플로우를 연결합니다.** 이게 이 실습의 핵심입니다.
   - 캔버스 오른쪽 위 **`...`(점 3개) → `Settings`** 를 엽니다.
   - **`Error Workflow`** 항목에서, 방금 만든 **`214 - 실패 알림 (Error Workflow)`** 을 목록에서 고릅니다.
   - (JSON 파일에는 `errorWorkflow: "REPLACE_WITH_YOUR_ERROR_WORKFLOW_ID"` 자리표시자가 들어 있는데, Settings에서 목록으로 고르면 n8n이 4단계의 실제 ID로 자동으로 채워 줍니다.)
   - 저장합니다.
7. **메인 워크플로우를 한 번 실행해 봅니다.** 캔버스 위 **`Test workflow`** 를 누릅니다. 가운데 노드에서 빨간 에러가 나며 멈출 것입니다 — **일부러 그렇게 만든 것이니 정상입니다.**

## 🤖 바이브코딩 프롬프트

이 실습을 AI(n8n AI 어시스턴트나 ChatGPT 등)에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. n8n은 화면에서 노드를 끌어다 붙이는 도구라, AI에게는 "이런 워크플로우 JSON을 만들어 줘" 또는 "이 노드를 어떻게 설정하는지 단계별로 알려 줘" 식으로 시키는 게 좋습니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 n8n 자동화 전문가야. 비전공자가 이해할 수 있게 도와줘.
  목표: "어떤 워크플로우든 실패하면 Slack으로 즉시 알림이 오게" 하는 알림 전용 워크플로우(Error Workflow)를 만들고 싶어.
  제약:
  - 노드 3개로: (1) Error Trigger로 시작 → (2) Set 노드로 에러 정보(실패한 워크플로우 이름, 실패한 노드, 에러 메시지, 발생 시각, 실행 링크)를 정리 → (3) Slack 노드로 메시지 전송.
  - 발생 시각은 한국 시간(Asia/Seoul)으로 보여줘.
  - 비밀값(Slack 토큰)은 노드에 직접 적지 말고 n8n 자격증명(Credentials)을 쓰는 방식으로 안내해줘.
  산출물:
  - n8n에 Import할 수 있는 워크플로우 JSON
  - 각 노드를 왜 그렇게 설정했는지 비전공자용 설명
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  좋아. 이제 이걸 실제로 시험할 "메인 워크플로우"도 만들어줘.
  - Schedule Trigger(예: 1시간마다)로 시작.
  - 가운데에 "일부러 실패하는 노드"를 넣어줘. 존재하지 않는 주소를 호출하는 HTTP Request로 항상 실패하게.
  - 마지막에 Set 노드(성공 시 처리)를 둬.
  그리고 메인 워크플로우의 Settings에서 위 알림 워크플로우(Error Workflow)를 연결하는 방법을 화면 클릭 순서대로 알려줘.
  추가로, 알림 Slack 메시지에 이모지(🚨)와 굵은 글씨로 항목을 보기 좋게 정리해줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  메인 워크플로우를 일부러 실패시켰는데 Slack 알림이 안 와. 단계별로 원인을 찾아줘.
  - 내가 한 것: error-workflow.json과 main-workflow.json을 Import했고, Slack 자격증명도 연결했어.
  - 확인하고 싶은 것: (1) 메인의 Settings → Error Workflow가 제대로 연결됐는지 어떻게 확인해? (2) 알림 워크플로우의 Executions에 실행 기록이 남았는지 어디서 봐? (3) 채널 ID가 맞는지, Slack 앱이 그 채널에 초대돼 있어야 하는지?
  하나씩 체크리스트로 짚어주고, 각 단계에서 무엇이 정상이고 무엇이 문제 신호인지 알려줘.
  ```
> 프롬프트 팁: "코드(JSON)만 주지 말고 각 노드를 왜 그렇게 설정했는지 한 줄씩 풀어서 설명해줘"를 덧붙이면, 화면에서 직접 손볼 때 어디를 만져야 하는지 이해하기 좋습니다.

## 검증법

1. **Slack에 알림이 왔는지 확인합니다.** 7단계로 메인이 실패한 직후, 지정한 채널에 이런 메시지가 떴으면 연결 성공입니다.
   ```
   🚨 자동화가 실패했어요!
   워크플로우: 214 - 메인 워크플로우 (실패 테스트용)
   멈춘 노드: 일부러 실패하는 노드 (HTTP Request)
   에러 내용: (네트워크/주소 관련 에러 메시지)
   발생 시각: 2026-06-18 03:21:00
   자세히 보기: https://.../execution/...
   ```
2. **알림 워크플로우의 실행 기록을 확인합니다.** 알림 워크플로우 화면에서 `Executions` 탭을 열면, 메인이 실패한 시각에 알림 워크플로우가 **자동으로 한 번 실행된 기록**이 보여야 합니다. (Error Trigger가 메인의 실패를 받아 깨어난 것입니다.)
3. **노드 색으로 흐름 확인.** 알림 워크플로우의 그 실행 기록을 열면 노드 3개에 모두 **초록색 체크**가 떠 있어야 합니다.
4. **연결을 일부러 끊어 비교해 봅니다.** 메인의 `Settings → Error Workflow`를 **`None`** 으로 바꾼 뒤 다시 실패시키면, 똑같이 메인은 실패하지만 **Slack 알림은 오지 않습니다.** "연결을 해 둬야만 알림이 온다"는 점을 눈으로 확인할 수 있습니다. (확인 후 다시 원래 알림 워크플로우로 연결해 두세요.)
5. **실전 점검:** 진짜로 쓰는 워크플로우가 여러 개라면, 각 워크플로우의 `Settings → Error Workflow`에 이 알림 워크플로우 하나만 똑같이 연결하면 됩니다. **알림 담당은 한 명, 그를 부르는 워크플로우는 여럿** 구조가 됩니다.

## 핵심만 짚기 (디렉터 관점)

- **침묵은 정상이 아니라 실패 신호입니다.** 자동화가 멈췄는데 아무 일도 안 일어나는 게 가장 위험합니다. "실패하면 즉시 나에게 온다"는 알림 한 줄이, 자동화를 안심하고 맡길 수 있게 만듭니다.
- **알림은 따로 빼서 한 번만 만듭니다.** 워크플로우마다 알림 노드를 일일이 붙이지 않습니다. Error Workflow 하나를 만들어 두고 여러 워크플로우가 `Settings`에서 그것을 가리키게 하면, 알림 문구를 고칠 때 한 곳만 고치면 됩니다.
- **실패할 것을 전제로 설계합니다.** "잘 되면 어떡하지"가 아니라 "안 되면 내가 어떻게 알지"를 먼저 정하는 게 디렉터의 일입니다. 이 실습의 `일부러 실패하는 노드`처럼, **일부러 실패시켜 알림이 진짜 오는지 미리 시험**해 두면 진짜 사고 때 당황하지 않습니다.

## 보안, 비밀값은 어떻게 다루나

- **Slack 토큰(또는 메일 비밀번호)** 은 새면 안 되는 비밀값입니다. 절대 `error-workflow.json`이나 노드 값에 직접 적지 마세요.
  - 올바른 방법: n8n의 **`Credentials`(자격증명) 금고**에 저장하고, 노드에서는 그 자격증명을 **고르기만** 합니다. 그러면 비밀값은 금고에만 남고 파일에는 남지 않습니다.
  - 그래서 이 파일에는 실제 값 대신 `REPLACE_WITH_YOUR_SLACK_CREDENTIAL_ID`, `REPLACE_WITH_YOUR_SLACK_CHANNEL_ID` 같은 **자리표시자**만 들어 있습니다. 이 파일을 남에게 줘도 비밀이 새지 않습니다.
- **에러 메시지에 비밀이 섞일 수 있습니다.** 실패한 노드의 에러 메시지에 가끔 URL 일부나 키 조각이 들어갈 수 있습니다. 알림 채널은 **아무나 못 보는 비공개 채널**로 두는 게 안전합니다.
- 한 줄 원칙: **공개해도 되는 값은 노드에, 새면 안 되는 값(토큰·비밀번호)은 자격증명 금고에.**
