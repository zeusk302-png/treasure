# 이미지·링크 깨진 경로 고치기 — 안 뜨는 사진과 404 링크

## 목표
사진(`<img>`)이 안 뜨고 메뉴 링크(`<a>`)가 "페이지를 찾을 수 없음(404)"으로 깨지는 작은 가게 소개 사이트를 직접 고칩니다. 핵심은 **파일 경로가 "어디"를 기준으로 하는지**를 이해하는 것입니다.

경로에는 크게 세 종류가 있습니다. 비유로 정리하면 이렇습니다.

- **상대경로** (`images/food.svg`, `about.html`): "지금 이 파일이 있는 폴더"를 기준으로 길을 찾습니다. 같은 동네에서 "우리 집 옆 슈퍼"라고 말하는 것과 같아요. 정적 사이트에서는 보통 이게 정답입니다.
- **절대경로(웹 기준)** (`/images/food.svg`): 맨 앞 슬래시 `/` 는 "사이트의 최상위(루트) 폴더"를 뜻합니다. 진짜 웹 서버에 올렸을 때만 의미가 있고, 파일을 그냥 더블클릭해서 열면 `/` 가 내 컴퓨터의 `C:\` 같은 엉뚱한 곳을 가리켜 사진이 깨집니다.
- **내 컴퓨터 전체경로** (`C:\Users\me\Desktop\food.svg`): 오직 내 컴퓨터에서만 통하는 길입니다. 다른 사람이 받거나 인터넷에 올리면 100% 깨집니다. 절대 쓰면 안 됩니다.

추가로 두 가지 흔한 함정도 같이 고칩니다.

- **대소문자/철자**: 실제 폴더는 `images`인데 코드에 `Images`라고 쓰면, 웹 서버는 대소문자를 구분하기 때문에 사진을 못 찾습니다.
- **외부 링크의 `https://` 빠짐**: `www.naver.com` 처럼 쓰면 "현재 폴더 안의 www.naver.com 이라는 파일"을 찾으러 가서 깨집니다. 외부 사이트는 꼭 `https://`로 시작해야 합니다.

## 따라하는 단계
1. `C:\Users\김세영\Desktop\부산코딩스쿨_강의자료\treasure\examples\282\` 폴더를 엽니다. 안에는 `broken.html`(고장난 파일), `about.html`, `images\`(logo.svg, food.svg) 폴더가 있습니다.
2. 먼저 `broken.html`을 더블클릭해 브라우저로 엽니다. 로고와 메뉴 사진이 안 뜨고(깨진 그림 아이콘), 메뉴 링크를 눌러도 404가 나는 "고장난 상태"를 눈으로 확인합니다.
3. `broken.html`을 VS Code나 메모장으로 엽니다. 주석으로 `❌ 버그 1~5`가 표시되어 있습니다. 한 줄씩 찾아봅니다.
4. **버그 1·2 (절대경로 `/`)**: `src="/images/logo.svg"` 와 `href="/about.html"` 에서 맨 앞 슬래시 `/` 를 지웁니다. → `src="images/logo.svg"`, `href="about.html"`.
5. **버그 3 (대소문자)**: `href="Images/food.svg"` 의 `Images`를 실제 폴더명과 똑같은 소문자 `images`로 고칩니다.
6. **버그 4 (https 빠짐)**: `href="www.naver.com"` 을 `href="https://www.naver.com"` 으로 고칩니다. (`target="_blank" rel="noopener"`를 붙이면 새 탭에서 열려 더 좋습니다.)
7. **버그 5 (내 컴퓨터 전체경로)**: `src="C:\Users\me\Desktop\food.svg"` 를 프로젝트 안의 상대경로 `src="images/food.svg"` 로 바꿉니다.
8. 저장한 뒤 브라우저에서 새로고침해 사진과 링크가 살아났는지 확인합니다. 완성본은 옆에 있는 `index.html`과 같아집니다 — 막히면 비교해 보세요.

## 🤖 바이브코딩 프롬프트
이 실습(이미지·링크 깨진 경로 고치기)을 AI에게 시켜 만들거나 고칠 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 HTML 입문 강사야. 비전공자가 "경로(path)"를 배우는 실습용으로,
  작은 동네 가게 소개 웹페이지 하나(index.html)를 만들어줘.
  요구사항:
  - 상단 header에 로고 이미지 1개(images/logo.svg), 가게 이름 h1
  - nav에 링크 3개: 같은 폴더의 about.html로 가는 내부 링크, 하위 폴더의
    이미지(images/food.svg)로 가는 링크, 외부 사이트(네이버)로 가는 링크
  - card 박스 안에 대표 메뉴 이미지(images/food.svg)와 설명 문단
  - CSS는 <style> 안에 간단히, 외부 라이브러리 없이 순수 HTML/CSS만
  제약:
  - 모든 경로는 "상대경로"로 작성하고, 왜 절대경로(/)나 C:\ 전체경로를
    쓰면 안 되는지 한 줄씩 한국어 주석으로 설명해줘
  - 식별자(class 이름 등)는 영어로, 주석은 한국어로
  ```

- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 index.html을 학습용 "고장난 버전(broken.html)"으로도 만들어줘.
  - 일부러 경로 버그 5개를 심어줘: (1) img src에 맨 앞 슬래시(/) 붙이기,
    (2) 내부 링크 href에 맨 앞 슬래시(/) 붙이기, (3) 폴더 이름 대소문자 틀리기
    (images를 Images로), (4) 외부 링크에서 https:// 빼기,
    (5) 이미지 src를 C:\... 같은 내 컴퓨터 전체경로로 바꾸기
  - 각 버그 바로 위에 "❌ 버그 N: (무엇이 틀렸는지) — (왜 깨지는지)"
    형식의 한국어 주석을 달아줘. 고친 정답(index.html)과 1:1로 비교되게 해줘.
  ```

- **막혔을 때(디버깅)** 프롬프트:
  ```text
  내 HTML에서 이미지가 안 뜨고(깨진 그림 아이콘) 메뉴 링크가 404가 나.
  아래 코드를 붙여넣을게. 브라우저 F12 Console/Network 탭에 어떤 빨간 오류가
  뜨는지도 알려줄게.
  - 경로(path) 관점에서 한 줄씩 점검해줘: 상대경로/절대경로(/)/전체경로(C:\) 중
    무엇인지, 실제 폴더 구조(images 폴더에 logo.svg, food.svg)와 맞는지,
    대소문자가 정확한지, 외부 링크에 https://가 있는지
  - 무엇을 어떻게 고쳐야 하는지 "고치기 전 → 고친 후"로 보여주고,
    왜 그렇게 고치는지 비전공자가 이해하게 한 줄씩 풀어서 설명해줘
  [여기에 broken.html 코드와 콘솔 오류 메시지를 붙여넣기]
  ```

> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 단순히 고치는 데서 끝나지 않고 "경로가 어디를 기준으로 하는지"를 스스로 판별하는 눈이 생깁니다.

## 검증법
- `index.html`(또는 직접 고친 `broken.html`)을 브라우저로 열었을 때, 상단에 파란 **로고 사진**과 카드 안에 노란 **메뉴 사진**이 깨짐 아이콘 없이 또렷하게 보이면 이미지 경로가 맞은 것입니다.
- "가게 소개" 링크를 누르면 `about.html` 페이지로 이동하고, 그 페이지의 "← 첫 화면으로 돌아가기"로 다시 돌아오면 내부 링크가 정상입니다.
- "대표 메뉴 보기" 링크를 누르면 메뉴 사진(`images/food.svg`)이 단독으로 열리면 성공입니다.
- "네이버 바로가기"를 누르면 실제 naver.com이 열리면(404 페이지가 아니라) 외부 링크가 맞은 것입니다.
- (확인 팁) 브라우저에서 `F12` → `Console`/`Network` 탭을 열어 새로고침했을 때 빨간 404 오류가 더 이상 없으면 모든 경로가 해결된 것입니다.

## 경로 규칙 메모 (한 장 요약)
- 같은 폴더의 파일 → `파일이름` (예: `about.html`)
- 하위 폴더의 파일 → `폴더/파일이름` (예: `images/food.svg`)
- 상위 폴더로 한 칸 올라가기 → `../파일이름`
- 맨 앞 `/` 는 "사이트 루트". 로컬 더블클릭 환경에서는 보통 깨짐 → 정적 사이트에선 상대경로 사용
- 외부 사이트는 반드시 `https://`로 시작
- 폴더·파일 이름은 **대소문자까지 정확히** 일치 (`images` ≠ `Images`)
