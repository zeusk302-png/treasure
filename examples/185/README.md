# 185 — h1~h3 제목 위계로 문서 뼈대 바로잡기

페이지에 **`<h1>`은 단 하나만** 두고, 그 아래를 **`<h2>` → `<h3>`** 순서로 차근차근 내려가
검색엔진과 스크린리더가 이해하는 **올바른 '목차 구조'** 를 만드는 실습입니다.

- 카테고리: SEO·성능·접근성 (코드 I)
- 난이도: 2 / 5
- 개념: 제목 위계, 시맨틱 구조
- 결과물: 제목 위계가 정리된 HTML 본문 (`index.html`의 `<main>` 부분)

## 목표

제목 태그(`h1`~`h6`)는 **글자를 크게 만드는 도구가 아니라**, 문서의 **목차 단계**를 알려 주는 표지판입니다.
사람 눈에는 그냥 큰 글씨로 보이지만, 검색엔진(구글)과 시각장애인용 스크린리더는
이 태그만 따라 "이 글은 무엇에 대한 글이고, 어떤 단원으로 나뉘는지"를 파악합니다.

지켜야 할 규칙은 단 세 가지입니다.

1. **`<h1>`은 페이지에 하나만** — 이 페이지의 대제목(주제)입니다.
2. **단계를 건너뛰지 않기** — `h1` 다음은 `h2`, `h2` 다음은 `h3`. `h1`에서 바로 `h3`으로 점프하면 목차에 구멍이 생깁니다.
3. **크기가 아니라 '의미'로 고르기** — 더 작게/크게 보이고 싶은 것뿐이라면 태그를 바꾸지 말고 CSS로 크기를 조절합니다.

이 규칙을 지킨 본문이 `index.html`의 `<main>` 안에 들어 있습니다.
이 본문의 제목만 뽑으면 아래와 같은 깔끔한 목차 트리가 됩니다.

```
h1  햇살카페 안내
├─ h2  메뉴
│   ├─ h3  커피
│   └─ h3  디저트
├─ h2  오시는 길
│   └─ h3  주차 안내
└─ h2  영업시간
```

## 따라하는 단계

1. 이 폴더의 `index.html`을 브라우저로 엽니다 (파일을 더블클릭하면 됩니다).
2. 화면 위쪽 본문에서 **대제목(가장 큼) → 단원 제목(중간) → 세부 제목(작음)** 으로
   글자 크기가 단계별로 줄어드는 것을 눈으로 확인합니다. 이 단계가 곧 제목 위계입니다.
3. `index.html`을 메모장이나 에디터로 열어, `<main>` 안의 제목 태그들을 살펴봅니다.
   `<h1>`은 맨 위에 **한 번만** 나오고, 그 아래는 `<h2>`와 `<h3>`만 쓰이고 있습니다.
4. **직접 내 페이지로 바꿔 봅니다.** `<h1>` 안의 "햇살카페 안내"를 내 사이트 대제목으로 고치고,
   `<h2>`(메뉴·오시는 길·영업시간)는 내 페이지의 큰 단원 제목으로, `<h3>`은 그 안의 세부 항목으로 바꿉니다.
5. 규칙을 어기지 않았는지 확인합니다. **`<h1>`이 두 개가 되지 않았는지**,
   **`<h2>`를 건너뛰고 `<h3>`을 쓰지 않았는지** 점검합니다.
6. 저장한 뒤 브라우저에서 새로고침(F5)하여 목차 단계가 그대로 유지되는지 봅니다.
7. (선택) 페이지 아래쪽 회색 "학습 설명" 영역에서 목차 트리 그림과
   "흔히 하는 실수" 표를 다시 읽으며 규칙을 머리에 새깁니다.

## 🤖 바이브코딩 프롬프트

이 실습(제목 위계 h1~h3로 문서 뼈대 잡기)을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 시맨틱 HTML과 접근성에 밝은 프런트엔드 도우미야.
  '햇살카페'라는 동네 카페 소개 페이지의 본문(<main>)을 HTML로 만들어 줘.
  꼭 지킬 규칙:
  - <h1>은 페이지에 딱 하나(=대제목 "햇살카페 안내")만 쓴다.
  - 그 아래 큰 단원은 <h2>(예: 메뉴, 오시는 길, 영업시간), 그 안의 세부 항목은 <h3>로 쓴다.
  - 단계를 건너뛰지 않는다(h1 다음 바로 h3 금지). 한 칸씩만 내려간다.
  - 글자 크기 때문이 아니라 '의미(목차 단계)' 때문에 태그를 고른다.
  각 단원에는 짧은 설명 <p>도 한 줄씩 넣어 줘.
  비전공자도 이해하게, 왜 이 태그를 골랐는지 한국어 주석으로 한 줄씩 달아 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 본문은 그대로 두고, 디자인은 CSS(style.css)로만 단계를 표현해 줘.
  - h1은 가장 크게(+아래 굵은 밑줄), h2는 그다음 크기(+왼쪽 색 막대), h3은 한 단계 작게.
  - HTML의 제목 태그는 절대 크기 맞추려고 바꾸지 말 것(의미는 HTML, 크기는 CSS 담당).
  추가로, 페이지 맨 아래에 '학습용 설명 영역'을 회색 박스로 따로 만들어
  이 본문의 제목만 뽑은 '목차 트리(h1 > h2 > h3 들여쓰기)'를 <pre>로 보여 줘.
  각 CSS 규칙에도 '무엇을, 왜' 한국어 주석을 달아 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  내 HTML을 Lighthouse 접근성 검사에 돌렸더니
  "Heading elements are not in a sequentially-descending order"(제목 순서 오류) 경고가 떴어.
  아래 내 <main> 코드를 붙여넣을게. (여기에 코드 붙여넣기)
  1) 어느 부분에서 단계를 건너뛰었는지(예: h1 다음 h3, 또는 h1이 두 개) 짚어 주고,
  2) 왜 그게 문제인지 비전공자가 이해하게 설명하고,
  3) 의미를 해치지 않는 선에서 어떻게 고치면 되는지 수정안을 보여 줘.
  ```

> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 훨씬 좋습니다.

## 검증법

- **눈으로 단계 확인**: 본문에서 제목들이 대제목 → 단원 → 세부 순으로 또렷하게 나뉘면 성공입니다.
- **개발자도구로 목차 보기**: 브라우저에서 F12를 눌러 개발자도구를 열고, `<main>` 안의 태그를 살펴
  `<h1>`이 **하나뿐**이고 `h1 → h2 → h3` 순서가 지켜졌는지 확인합니다.
- **'문서 윤곽(outline)' 확장도구**: 크롬 웹스토어의 "HeadingsMap" 같은 무료 확장도구를 설치하면
  페이지의 제목 트리를 자동으로 그려 줍니다. 위 목차 트리와 같은 모양이 나오면 위계가 올바른 것입니다.
- **건너뛰기 금지 확인**: `h1` 바로 다음에 `h3`이 오거나, `h2` 없이 `h3`이 먼저 나오는 부분이
  하나도 없는지 확인합니다. 한 칸씩만 내려가야 합니다.
- **Lighthouse 접근성 점검**: 개발자도구 → Lighthouse 탭에서 Accessibility 검사를 돌리면
  "Heading elements are not in a sequentially-descending order"(제목 순서 오류) 경고가
  뜨지 않아야 합니다.
