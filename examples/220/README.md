# 220. 내 첫 기획서 PLAN.md 만들기 (AI가 나에게 질문하게)

## 목표

포트폴리오 사이트를 **만들기 전에**, AI가 나에게 하나씩 질문하게 만들어
**무엇을·누구를·어디까지** 정리한 기획서 **`PLAN.md`** 한 장을 완성하는 연습입니다.

비전공자가 가장 많이 하는 실수는 **"포트폴리오 사이트 만들어줘"** 한마디만 던지는 것입니다.
그러면 AI는 내 사정을 모른 채 **혼자 상상해서** 엉뚱한 사이트를 만들어 버립니다.
"무엇을·왜"는 **사람이** 정하고, "어떻게(코드)"는 AI가 만드는 것이 순서입니다.
그래서 **코드를 짜기 전에** AI를 **인터뷰어**로 부려서,
머릿속에만 있던 계획을 글 한 장(`PLAN.md`)으로 꺼내 놓습니다.

이 실습에는 새로 짤 코드가 없습니다. **AI에게 잘 질문시켜 기획서를 뽑아내는 글쓰기**가 곧 실습입니다.
특히 **"범위 밖(이번엔 안 함)"** 을 적어 욕심을 줄이는 것이 핵심입니다.

이 폴더의 파일은 넷입니다.

- [`prompt.md`](prompt.md) — AI를 "기획 인터뷰어"로 만드는, 그대로 붙여넣는 지시 프롬프트
- [`conversation.md`](conversation.md) — AI가 나에게 질문하며 PLAN.md를 끌어낸 대화 캡처(예시)
- [`PLAN.md`](PLAN.md) — **이 실습의 결과물.** 목표·대상·페이지·꼭 들어갈 것·범위 밖이 담긴 기획서
- `README.md` — 지금 읽는 이 안내문

## 따라하는 단계

1. [`prompt.md`](prompt.md)를 열어 **1단계 지시 프롬프트**를 통째로 복사합니다. 핵심 제약은 "지금은 코드 짜지 말고, 네가 나에게 한 번에 한두 개씩 질문해서 계획을 끌어내라"입니다.
2. 복사한 프롬프트를 실제 Claude(또는 쓰는 AI)에 붙여넣습니다.
3. AI가 **코드를 만들지 않고 나에게 질문**하는지 봅니다. 질문이 오면 솔직하게 내 상황을 답합니다. (목표·대상·페이지·꼭 넣을 것·뺄 것)
4. 만약 AI가 질문을 건너뛰고 **바로 사이트 코드를 만들어 버리면**, [`prompt.md`](prompt.md)의 **2단계 한 마디**("아직 코드 짜지 마, 질문부터")로 다시 잡아 줍니다.
5. 모바일에서 보기·연락 방식처럼 **내가 놓친 것**을 AI가 먼저 짚어주면, 함께 "이번에 할지 / 다음으로 미룰지" 정합니다. (대화 예시는 [`conversation.md`](conversation.md))
6. 충분히 답했으면 [`prompt.md`](prompt.md)의 **3단계 한 마디**로 `PLAN.md` 초안을 요청합니다. 구조는 `## 목표 / ## 대상 / ## 페이지·섹션 / ## 꼭 들어갈 것 / ## 범위 밖 / ## 다음에 정할 것` 입니다.
7. AI가 만든 초안을 같은 폴더의 [`PLAN.md`](PLAN.md)처럼 **내 답으로 바꿔** 저장합니다.
8. **가장 중요한 마무리:** 완성된 `PLAN.md`를 한 줄씩 읽으며 **"이거 내가 진짜 정한 거 맞나?"** 를 사람이 직접 확인합니다. AI가 상상으로 채운 부분이 있으면 지우고, 안 정한 건 **"다음에 정할 것"** 으로 남깁니다.

## 🤖 바이브코딩 프롬프트

이 실습은 **코드를 만드는 게 아니라 기획서(`PLAN.md`)를 뽑아내는** 연습이라, 아래 프롬프트도
"AI를 인터뷰어로 부려서 내 계획을 글로 끌어내는" 데 초점이 맞춰져 있습니다. 그대로 복사해 쓰세요.

- **1단계(뼈대 만들기 — AI를 인터뷰어로 세우기)** 프롬프트:
  ```text
  나는 코딩을 막 시작한 비전공자야. "포트폴리오 사이트"를 만들고 싶은데,
  지금은 머릿속에만 어렴풋이 있고 정리가 안 돼 있어.

  [가장 중요한 규칙] 지금은 코드를 한 줄도 짜지 마. HTML/CSS도 쓰지 마.
  대신 네가 나에게 "기획 인터뷰어"가 되어서, 질문을 던져 내 계획을 끌어내 줘.

  한 번에 한두 개씩만, 짧게 묶어서 차근차근 물어봐.
  - 목표(이 사이트로 무엇을 이루고 싶은가)
  - 대상(누가 보는가)
  - 페이지·섹션(어떤 화면이 필요한가)
  - 꼭 들어갈 것 / 제외할 것(범위 밖)
  그럼 첫 질문부터 시작해줘.
  ```

- **2단계(기능 추가/개선 — 빠진 결정거리까지 끌어내 PLAN.md로 정리)** 프롬프트:
  ```text
  좋아, 계속 인터뷰해줘. 내가 빠뜨리기 쉬운 것(연락 수단, 모바일에서 보기,
  사진 준비 같은 것)도 네가 먼저 "이건 어떻게 할까요?"라고 짚어줘.
  내 답이 두루뭉술하면 단정하지 말고 다시 되물어서 구체화해줘.

  충분히 물어봤다고 판단되면, 지금까지 내가 답한 내용만 가지고
  PLAN.md 초안을 만들어줘. 아래 구조를 지켜줘.
  ## 목표 / ## 대상 / ## 페이지·섹션 / ## 꼭 들어갈 것 /
  ## 범위 밖(이번엔 안 함) / ## 다음에 정할 것(미정)
  내가 분명히 말 안 한 건 지어내지 말고 "다음에 정할 것"에 넣어줘.
  ```

- **막혔을 때(디버깅 — AI가 규칙을 어기거나 상상으로 채울 때)** 프롬프트:
  ```text
  잠깐, 아직 코드 짜지 말랬어. 지금은 기획 단계야.
  (또는) 방금 PLAN.md에 내가 말한 적 없는 내용이 섞인 것 같아.
  네가 채워 넣은 항목을 하나씩 짚어서, "이건 사용자가 직접 말한 것"인지
  "네가 추정해서 넣은 것"인지 표시해줘. 추정한 건 "다음에 정할 것"으로 옮겨줘.
  그리고 다시 한 번에 한두 개씩만 질문하는 방식으로 돌아가자.
  ```

> 프롬프트 팁: 정리가 끝난 뒤 "왜 이 항목을 범위 밖으로 빼는 게 좋은지 한 줄씩 이유를 달아줘",
> "비전공자가 이해하게 풀어서 설명해줘"를 덧붙이면, 단순한 결과물이 아니라 **이유까지 남는** 기획서가 됩니다.

## 검증법

아래를 모두 만족하면 성공입니다.

- [ ] AI가 **코드를 바로 만들지 않고**, 먼저 나에게 **질문을 던졌다.**
- [ ] 질문이 **한 번에 한두 개씩** 나뉘어, 비전공자가 답하기 편했다.
- [ ] 완성된 [`PLAN.md`](PLAN.md)에 **`## 목표` `## 대상` `## 페이지·섹션` `## 꼭 들어갈 것` `## 범위 밖`** 이 모두 있다.
- [ ] **`## 범위 밖 (이번엔 안 함)`** 항목이 비어 있지 않다. (안 할 것을 정해 욕심을 줄였다)
- [ ] 내가 분명히 말하지 않은 것은 AI가 지어내지 않고 **"다음에 정할 것"** 으로 남겼다.
- [ ] `PLAN.md`를 한 줄씩 읽었을 때, 전부 **"내가 진짜 정한 내용"** 이다. (AI 상상이 섞이지 않았다)

> 빠르게 자가 점검: 이 `PLAN.md`만 보고 **"다음에 어떤 화면을 만들면 되는지 한눈에 보이면"** 통과입니다.
> 읽어도 "그래서 뭘 만들지?"가 안 잡히면, AI에게 더 질문시켜 구체화하세요.
