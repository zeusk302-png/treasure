# 실습 335 — 헬스체크 엔드포인트 + 업타임 모니터 만들기

내 서버에 "나 지금 살아있어요"를 알려 주는 작은 주소(`/health`)를 하나 달고, **무료 업타임 모니터**가 그 주소를 1~5분마다 두드려 보게 합니다. 서버가 응답을 안 하거나 "고장(503)"을 돌려주면 모니터가 **이메일/슬랙으로 먼저 알려 줍니다.** 손님이 "사이트 안 돼요"라고 전화하기 전에, 내가 먼저 아는 운영 습관을 만드는 것이 목표입니다.

> 한 줄 그림: **서버가 `/health`로 "정상(200)" 또는 "고장(503)"을 알림 → 업타임 모니터가 매분 그 주소를 두드림 → 응답이 끊기거나 503이면 → "사이트 다운!" 메일/슬랙이 나에게 먼저 도착**

> 비유: `/health`는 병원 침대 옆의 **맥박 측정기**입니다. 환자(서버)가 스스로 "맥박 정상"을 1초마다 보냅니다. 업타임 모니터는 그 모니터를 지켜보는 **간호사 스테이션**이고요. 맥박이 끊기는 순간 알람이 울려서, 의사(나)가 달려올 수 있게 해 줍니다.

> 보안 메모 — 공개해도 되는 값 vs 절대 숨겨야 하는 값
> - **공개되어도 무해한 것**: `/health` 주소 자체와, 거기서 돌려주는 `status: ok / uptime` 같은 요약. 모니터가 봐야 하니 공개 주소여도 됩니다. (단, DB 비밀번호·에러 스택 같은 **내부 정보는 본문에 절대 담지 마세요.**)
> - **절대 노출하면 안 되는 비밀값**: `DATABASE_URL`(DB 접속 문자열), `HEALTH_SECRET` 같은 토큰. 이건 `server.js`(코드)에 박지 말고 **`.env` 또는 배포 플랫폼의 Environment Variables 화면**에만 넣습니다.
> - 이 폴더의 `.env.example`에는 **자리표시자만** 들어 있습니다. 복사해 `.env`를 만들고 진짜 값은 거기에만 적으며, `.env`는 `.gitignore`로 깃에서 빠집니다.

## 목표
- **헬스체크 엔드포인트를 만든다**: 서버가 정상이면 `200`, 의존성(DB 등)이 죽었으면 `503`을 돌려주는 `/health`를 직접 띄워 본다.
- **얕은 점검과 깊은 점검을 구분한다**: `/healthz`(프로세스가 떠 있나만 빠르게)와 `/health`(DB까지 멀쩡한가)의 차이를 이해한다.
- **무료 업타임 모니터를 건다**: UptimeRobot 같은 무료 도구로 `/health`를 주기 점검하고, 다운되면 알림이 오게 설정한다.
- **일부러 고장 내서 알림을 받아 본다**: `FORCE_DB_DOWN`으로 서버를 "고장난 척" 시켜, 진짜로 다운 알림이 도착하는지 확인한다.
- **비밀값을 코드 밖에 둔다**: DB 접속 문자열·토큰을 `server.js`가 아니라 `.env`/환경변수에만 둔다.

## 따라하는 단계

### A. 서버를 내 컴퓨터에서 띄우기
1. 이 폴더에서 라이브러리를 받습니다: `npm install`
2. 서버를 켭니다: `npm start` → 콘솔에 `서버 시작: http://localhost:3000` 이 뜨면 성공입니다.
3. 브라우저로 점검 주소를 열어 봅니다.
   - `http://localhost:3000/healthz` → `{"status":"ok"}` (얕은 점검: 프로세스 생존만)
   - `http://localhost:3000/health` → `status: ok`, `uptimeSeconds`, `checks.database` 가 보입니다 (깊은 점검).

### B. "고장난 척" 시켜서 503 확인하기
4. 서버를 잠깐 끄고(`Ctrl`+`C`), 고장 스위치를 켠 채 다시 띄웁니다.
   - macOS/Linux: `FORCE_DB_DOWN=1 npm start`
   - Windows PowerShell: `$env:FORCE_DB_DOWN="1"; npm start`
5. 다시 `http://localhost:3000/health` 를 열면 이번엔 **HTTP 503**과 `status: error`, `checks.database.ok: false` 가 옵니다. (브라우저 개발자도구 Network 탭이나 `curl -i` 로 상태코드를 보세요.) 이게 모니터가 "다운"으로 인식할 신호입니다.
6. 확인이 끝나면 스위치를 끄고(`FORCE_DB_DOWN`을 비움) 다시 정상 기동합니다.

### C. 인터넷에 배포해 공개 주소 만들기
7. 모니터가 두드리려면 `localhost`가 아니라 **공개 주소**가 필요합니다. Render·Railway·Fly 같은 무료/저가 호스팅에 이 폴더를 올립니다.
   - 빌드/실행 명령: 설치 `npm install`, 시작 `npm start` (이미 `package.json`에 `start`가 있습니다).
   - 플랫폼이 주는 `PORT`를 코드가 자동으로 읽으니 포트는 따로 안 건드려도 됩니다.
   - DB를 실제로 점검하도록 확장했다면 `DATABASE_URL`을 **플랫폼의 Environment Variables**에 넣습니다(코드에 박지 않기).
8. 배포된 주소 `https://내앱.onrender.com/health` 가 브라우저에서 정상으로 열리는지 확인합니다.

### D. 무료 업타임 모니터 걸기 (가장 중요)
9. 무료 업타임 모니터(예: UptimeRobot)에 가입하고 **New Monitor**를 만듭니다.
   - Monitor Type: **HTTP(s)**
   - URL: 위에서 배포한 **`https://내앱.onrender.com/health`**
   - Monitoring Interval: 5분(무료 기본) — 더 촘촘히 보고 싶으면 유료에서 1분.
   - (있으면) **Keyword 모니터**로 본문에 `"status":"ok"` 가 들어 있는지까지 보게 하면, 200을 주면서 속으로 망가진 경우도 잡습니다.
10. **알림 받을 곳(Alert Contacts)**을 등록합니다: 이메일이 기본, 슬랙/디스코드 웹훅도 됩니다.
11. **알림이 진짜 오는지 시험**: 배포 환경변수에 `FORCE_DB_DOWN=1`을 넣고 재배포하면 `/health`가 503을 줍니다. 몇 분 뒤 모니터가 **"Down" 알림**을 보내면 성공입니다. 확인 후 `FORCE_DB_DOWN`을 지우고 재배포하면 곧 **"Up(복구)" 알림**이 옵니다.

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 Node.js 백엔드 멘토야. 비전공자가 따라 할 수 있는 아주 작은 Express 서버를 만들어 줘.
  요구사항:
  - GET /healthz : 프로세스 생존만 확인하는 '얕은' 헬스체크. 항상 HTTP 200, 본문 {"status":"ok"}.
  - GET /health  : 의존성(DB 등)까지 보는 '깊은' 헬스체크. 정상이면 200, 의존성이 죽었으면 503을 돌려줘.
    본문에 status, uptimeSeconds, timestamp(UTC), checks.database 를 담아 줘.
  - 포트는 process.env.PORT 를 먼저 쓰고 없으면 3000.
  - DB가 아직 없으니, 환경변수 FORCE_DB_DOWN=1 이면 의존성이 죽은 척(503)하게 만들어 줘(고장 알림 테스트용).
  제약:
  - 코드만 주지 말고, 각 줄에 '무엇을 하는지 + 왜 그렇게 했는지'를 한국어 주석으로 달아 줘(특히 200 vs 503 차이, PORT를 환경변수로 두는 이유).
  - 비밀값(DB 접속 문자열 등)은 코드에 절대 박지 말고 .env 로 빼는 구조로 해 줘.
  산출물: server.js, package.json, .env.example, .gitignore. 실행은 npm install && npm start 로 되게.
  ```

- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 헬스체크 서버를 실제 서비스에 가깝게 개선해 줘.
  1) checkDatabase() 안에 진짜 점검을 넣는 예시를 주석으로 보여 줘:
     - PostgreSQL이면 "SELECT 1", Supabase면 가벼운 select().limit(1).
     - 무거운 쿼리를 쓰면 안 되는 이유(모니터가 매분 부르니 DB 부하)도 주석으로 설명해 줘.
  2) checks 에 'memory'(여유 메모리), 'diskOrExternalApi' 같은 점검을 1개 더 추가해 줘.
  3) 각 점검에 200~300ms 타임아웃을 걸어, 의존성이 느리면 무한정 매달리지 않고 503으로 빨리 끊게 해 줘(이유도 주석으로).
  4) DATABASE_URL 같은 비밀값은 반드시 process.env 로 읽고, .env.example 에는 자리표시자만 두는 걸 다시 확인해 줘.
  바뀐 부분마다 '왜 이렇게 바꿨는지' 한국어 주석으로 설명해 줘.
  ```

- **막혔을 때(디버깅)** 프롬프트:
  ```text
  헬스체크 서버가 이상해. 아래 정보를 보고 원인 후보를 가능성 높은 순서로 정리하고, 한 번에 하나씩 확인할 단계를 알려 줘.
  - 증상: (예) 배포는 됐는데 https://내앱.onrender.com/health 가 502/타임아웃이 떠. 로컬에서는 잘 돼.
  - 실행 로그(그대로 붙임):
    (여기에 배포 플랫폼 로그를 붙여넣기)
  - 확인해 줬으면 하는 것:
    1) PORT를 환경변수로 제대로 읽고 있는지(플랫폼이 준 포트로 listen 하는지),
    2) 0.0.0.0 으로 바인딩해야 하는 건 아닌지,
    3) 헬스체크 경로 철자(/health vs /healthz)와 모니터에 등록한 URL이 일치하는지,
    4) FORCE_DB_DOWN 같은 환경변수가 실수로 켜져서 일부러 503을 주는 건 아닌지.
  비전공자도 이해하게 한 줄씩 풀어서 설명해 줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법
- **정상 응답 확인**: 로컬에서 `http://localhost:3000/health` 가 **HTTP 200**과 `status: ok`, 늘어나는 `uptimeSeconds`를 보여 주는지 확인한다.
- **얕은/깊은 차이 확인**: `/healthz`는 항상 가볍게 200, `/health`는 의존성까지 본 결과를 돌려준다 — 둘의 응답이 다른지 본다.
- **고장 신호 확인**: `FORCE_DB_DOWN=1`로 띄우면 `/health`가 **503**과 `status: error`, `checks.database.ok: false` 를 주는지 `curl -i http://localhost:3000/health` 로 상태코드까지 확인한다.
- **모니터 등록 확인**: 업타임 모니터 대시보드에서 내 `/health` 모니터가 **녹색(Up)** 으로 보이는지 본다.
- **다운 알림 도착 확인**: 배포 환경에서 `FORCE_DB_DOWN=1`로 고장 낸 뒤, 몇 분 안에 **"Down" 메일/슬랙**이 실제로 오는지 본다. (안 오면 알림 연락처가 안 붙은 것.)
- **복구 알림 확인**: 다시 정상으로 돌리면 **"Up(복구)" 알림**이 오는지 본다.
- **비밀값이 코드/깃에 없는지 확인**: 아래를 실행해 진짜 비밀값이 안 나와야 정상이다.
  - `grep -nE "postgres://[^U]|hooks.slack.com/services/[A-Z0-9]" server.js` → **아무것도 안 나와야** 정상(자리표시자/주석 예시만 허용).
  - `git status` 에 `.env` 가 안 보이는지(= `.gitignore`가 잘 막는지) 확인한다.

## 파일 구성
- `server.js` — `/health`(깊은 점검)·`/healthz`(얕은 점검) 엔드포인트가 든 Express 서버. 정상 200 / 고장 503을 돌려주고, `FORCE_DB_DOWN`으로 고장을 흉내 낼 수 있다.
- `package.json` — `npm install` / `npm start` 로 실행하기 위한 설명서(의존성·시작 스크립트).
- `.env.example` — 필요한 값 견본(자리표시자만). 복사해 `.env`를 만들고 진짜 값은 거기/플랫폼 환경변수에만 넣는다.
- `.gitignore` — `.env`·`node_modules` 가 깃에 안 올라가게 막는다.
