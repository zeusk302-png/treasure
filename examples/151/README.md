# 실습 151 — 공개 도서 검색 API로 책 제목·표지 목록 뽑기

검색어를 넣고 검색하면, 공개 도서 API(Open Library)가 보내준 **책 여러 권(배열)** 을
하나씩 펼쳐서 **제목·저자·표지 썸네일 목록**으로 화면에 그리는 한 장짜리 페이지입니다.

> 비유: 택배 상자(JSON)를 열었더니 책 한 권이 아니라 **책 묶음**이 들어 있습니다.
> 묶음을 풀어 책을 **한 권씩 꺼내(반복)** 책장(목록)에 **한 칸씩** 꽂습니다.
> 이번 실습의 한 줄 핵심은 **"배열 응답을 반복으로 펼쳐 여러 개의 화면 요소로 만든다"** 입니다.

## 목표
- API 응답 안에 든 **책 배열(`data.docs`)** 을 꺼내는 법을 익힌다.
- 그 배열을 **`map`(또는 `forEach`)으로 반복**해, 책 한 권마다 카드 하나씩을 만드는 흐름을 잡는다.
  - `fetch(주소)` = 서버에 "이 검색어로 책 찾아줘" 주문하기
  - `data.docs` = 응답 JSON에서 **책 여러 권이 든 배열** 꺼내기
  - `books.map(book => 카드HTML)` = 책 배열을 **카드 조각 배열**로 한 칸씩 바꾸기
  - `listEl.innerHTML = 조각들.join("")` = 조각들을 합쳐 목록에 한 번에 그리기
- 책마다 값이 **있을 수도, 없을 수도** 있음을 다루는 법을 본다 (저자·표지·출판연도가 비어 있을 때 기본값 처리).

## 따라하는 단계
1. 이 폴더의 `index.html`을 더블클릭 → 브라우저에서 열린다. (인터넷 연결 필요)
2. 검색창에 미리 `해리포터`가 들어 있다. 그대로 **검색 버튼**(또는 Enter)을 누른다.
3. 잠시 후 책 카드들이 **격자 모양으로 여러 개** 펼쳐진다. 각 카드에 **표지·제목·저자·출판연도**가 보인다.
4. 검색창을 지우고 `어린왕자`, `javascript` 등 다른 말로 바꿔 검색해 본다 → 그때마다 **다른 목록**으로 바뀐다.
5. `script.js`에서 `const books = data.docs;` 줄을 찾는다 → **응답에서 '책 배열'을 꺼내는 부분**이다.
6. 바로 아래 `renderBooks(books)`로 들어가, `books.map((book) => { ... })`를 본다 → **책 배열을 한 권씩 펼쳐 카드를 만드는 핵심**이다.
7. 카드 만드는 부분에서 `book.title`, `book.author_name`, `book.cover_i`를 어떻게 꺼내 쓰는지 확인한다. 값이 없을 때 `"저자 미상"`처럼 **기본값을 주는 까닭**도 본다.
8. AI에게 시켜 보기:
   > "이 `script.js`에서 책 카드에 **출판사(`book.publisher`)** 도 함께 보여줘. `publisher`도 배열로 올 수 있으니, 없으면 표시하지 않게 처리해줘."

## 검증법
- 검색 버튼(또는 Enter)을 누르면 안내 문구가 바뀌고, **책 카드가 여러 개** 뜨는가?
- 각 카드에 **표지 그림·제목·저자·연도**가 함께 보이는가?
- 검색어를 바꿔 다시 검색하면 **이전 목록이 사라지고 새 목록**으로 바뀌는가?
- 결과가 없을 검색어(예: `asdfqwerzxcv`)를 넣으면 **"검색 결과가 없어요"** 안내가 뜨는가?
- 표지가 없는 책은 **"표지 없음" 대체 그림**(📕)이 보이는가?
- 브라우저에서 `F12`(개발자 도구) → **Network 탭**을 켜고 검색하면 `search.json` 요청이 가고, **응답 JSON 안에 `docs` 배열**이 보이는가? (배열 안에 책 객체가 여러 개 들어 있는 것을 눈으로 확인)

## 키(API Key)는 필요 없어요
이 실습이 쓰는 **Open Library 검색 API**(`openlibrary.org/search.json`)와 표지 이미지 서버(`covers.openlibrary.org`)는
**누구나 열쇠 없이** 부를 수 있는 **공개 API**입니다. 그래서 코드에 비밀값을 넣지 않습니다.

나중에 키가 필요한 API를 쓰게 되면, **공개되어도 되는 값**과 **절대 노출하면 안 되는 비밀값**은 성격이 완전히 다릅니다.

- 공개되어도 되는 값(예: Supabase의 `anon` 키)은 브라우저 코드에 들어가도 괜찮습니다. 단, 데이터 보호는 **RLS(행 수준 보안)** 가 책임집니다.
- 비밀값(예: Supabase의 `service_role` 키, 유료 API 키)은 **브라우저 코드에 절대 넣지 않습니다.** 브라우저 코드는 누구나 들여다볼 수 있기 때문입니다. 비밀값은 서버(또는 n8n 같은 자동화 도구의 자격 증명 저장소)에서만 다룹니다.
- 만약 키가 있는 API를 쓴다면 예제 코드에는 `YOUR_API_KEY` 같은 **자리표시자**만 두는 것이 원칙입니다.
