# 실습 155 — 환율 API로 원↔달러 실시간 환전 계산기 만들기

페이지를 열면 **무료 공개 환율 API**에서 **오늘의 환율**(1달러가 몇 원인지)을 받아옵니다.
그 환율 숫자로 **원(KRW) ↔ 달러(USD)** 환전을 **즉시** 계산해 주는 한 화면짜리 계산기입니다.
**원 칸**에 금액을 적으면 **달러 칸**이 자동으로 채워지고, **달러 칸**에 적으면 **원 칸**이 채워집니다(양방향).
**API 키(열쇠) 없이** 누구나 쓸 수 있는 공개 환율 API(Frankfurter)를 사용합니다.

> 비유: 환율 안내소(환율 API)는 **"오늘은 1달러가 1,389원이에요"** 라는 **숫자 하나**만 알려줍니다.
> 그 숫자만 받아오면, **얼마짜리 물건이든** 우리가 직접 **곱하기·나누기**로 환산할 수 있습니다.
> 그래서 이번 실습의 한 줄 핵심은 **"받아온 숫자(환율)로 계산 로직을 직접 만들고, 한쪽을 입력하면 반대쪽이 자동으로 바뀌게 연결하기"** 입니다.

> 실습 153·154(날씨 API)와의 차이: 날씨는 받아온 데이터를 **그대로 보여주면 끝**이었습니다.
> 환율은 받아온 **숫자를 가지고 직접 계산**해야 합니다. (원 ÷ 환율 = 달러, 달러 × 환율 = 원)
> 그래서 이번에 새로 배우는 핵심은 **"API가 준 숫자로 나만의 계산을 만드는 법"** 입니다.

## 목표
- **환율 API**에서 필요한 **숫자 하나(1 USD = ? KRW)**만 골라 뽑아내는 법을 익힌다.
  - 응답 예시: `{ "base":"USD", "date":"2026-06-18", "rates": { "KRW": 1389.42 } }` → 우리가 쓸 값은 `rates.KRW` 하나뿐이다.
- 받아온 숫자로 **양방향 계산 로직**을 직접 만든다.
  - 원 → 달러: `달러 = 원 ÷ 환율`
  - 달러 → 원: `원 = 달러 × 환율`
- `input` 이벤트로 **타이핑하는 즉시** 반대쪽 칸이 갱신되는 **실시간 연결**을 익힌다.
- 받아온 환율을 변수(`usdToKrw`)에 **상태값으로 저장**해 두고, 어느 칸을 입력하든 그 값으로 계산하는 패턴을 익힌다.
- 받아오는 중 / 실패 상황을 **친절한 한국어 안내**로 처리하는 법을 익힌다. (입력 칸·버튼 잠금 → 받아온 뒤 해제)

## 따라하는 단계
1. 이 폴더의 `index.html`을 더블클릭 → 브라우저에서 열린다. (인터넷 연결 필요)
2. 페이지가 열리면 자동으로 환율을 받아온다. **검은 칸 ①**에 요청 주소가, **검은 칸 ②**에 `1 USD = 1,389.42 KRW (기준일 ...)` 같은 오늘 환율이 채워진다.
3. **🇰🇷 원(KRW) 칸**에 `13000`을 입력해 본다 → **🇺🇸 달러 칸**이 자동으로 약 `9.36`처럼 채워진다.
4. 반대로 **🇺🇸 달러 칸**에 `10`을 입력해 본다 → **🇰🇷 원 칸**이 자동으로 약 `13894.2`처럼 채워진다. (양방향 확인)
5. 한 칸을 **지우면** 반대쪽 칸도 비워진다. (빈 칸 처리 확인)
6. **[🔄 오늘 환율 다시 받기]** 버튼을 눌러 환율을 새로 받아온다. (환율은 시시각각 바뀌므로)
7. `script.js`에서 `loadRate()`(① 환율 받아오기)와 `convertFromKrw()` / `convertFromUsd()`(② 양방향 계산)를 찾는다 → **'받아온 숫자 → 계산'을 연결**하는 핵심이다.
8. 같은 파일의 `let usdToKrw = null;`을 본다 → 받아온 환율을 **상태값**으로 저장해 두는 곳이다. 두 계산 함수 모두 이 값을 사용한다.
9. `krwInput.addEventListener("input", convertFromKrw)` 두 줄을 본다 → **타이핑할 때마다** 반대쪽 칸을 즉시 다시 계산하는 '실시간 연결' 부분이다.
10. AI에게 시켜 보기:
    > "이 `script.js`에서, 통화를 **달러(USD) 말고도 엔(JPY)·유로(EUR)** 중에서 고를 수 있게 `<select>` 드롭다운을 추가해줘. 선택한 통화에 맞춰 `to=` 값을 바꿔 환율을 다시 받아오고, 라벨도 그 통화로 바뀌게 해줘. 그리고 받아온 환율은 기존처럼 `usdToKrw` 같은 상태값에 저장해서 양방향 계산이 그대로 동작하게 해줘."

    fetch로 호출해서 '오늘의 환율(1 USD = ? KRW)' 숫자 하나만 뽑아와줘. (API 키는 필요 없음)

## 검증법
- 페이지를 열면 **검은 칸 ②**에 `1 USD = ... KRW (기준일 ...)` 형태로 오늘 환율이 채워지는가?
- **원 칸**에 숫자를 입력하면 **달러 칸**이, **달러 칸**에 입력하면 **원 칸**이 **즉시(타이핑하는 동안)** 바뀌는가?
- 계산이 맞는가? 직접 검산: 원 `13000` ÷ 환율(예 `1389.42`) ≈ 달러 `9.36`. 화면 값과 일치하는지 확인한다.
- 한 칸을 **지우면** 반대쪽 칸도 같이 비워지는가? 음수나 글자를 넣으면 반대쪽이 계산되지 않는가?
- **[🔄 오늘 환율 다시 받기]**를 누르면 다시 받아오는가? (받아오는 동안 입력 칸·버튼이 잠시 흐려져 잠긴다)
- `F12`(개발자 도구) → **Network 탭**을 켜고 새로고침하면, `latest?from=USD&to=KRW` 요청이 보이는가? 그 응답의 `rates.KRW` 숫자가 화면 ②번에 표시된 값과 같은가?

> 참고: Frankfurter(`frankfurter.app`)는 **유럽중앙은행(ECB) 공시 환율** 기반이라, 은행 창구의 실거래 환율(우대율·수수료 포함)과는 조금 다를 수 있습니다. 이번 실습은 **'API가 준 숫자로 계산을 만드는' 학습**이 목적입니다.
> 또한 환율은 평일에 갱신되므로, 주말에는 직전 영업일 환율(`date` 값)이 그대로 나올 수 있습니다.

## 공개 API와 비밀값 — 보안 메모
이 실습이 쓰는 **Frankfurter**는 **누구나 열쇠(API 키) 없이** 부를 수 있는 **공개 API**입니다.
그래서 이 코드에는 **넣을 비밀값이 아예 없습니다.** 브라우저 코드는 누구나 들여다볼 수 있으니, 비밀값이 없다는 점이 안전합니다.

나중에 **키가 필요한** 환율/금융 API(예: 일부 상용 환율 서비스)를 쓰게 되면, 값의 성격을 반드시 구분해야 합니다.

- **공개되어도 되는 값**(예: Supabase의 `anon`(공개) 키): 브라우저 코드에 들어가도 괜찮습니다. 단, 데이터 보호는 **RLS(행 수준 보안)** 가 책임집니다.
- **절대 노출하면 안 되는 비밀값**(예: Supabase의 `service_role` 키, 유료 환율 API 키): **브라우저 코드에 절대 넣지 않습니다.** 비밀값은 서버(또는 n8n 같은 자동화 도구의 자격 증명 저장소)에서만 다룹니다.
- 키가 있는 API를 예제로 적을 때는, 코드에 진짜 키 대신 `YOUR_API_KEY` 같은 **자리표시자**만 두는 것이 원칙입니다.

```js
// 키가 필요한 환율 API를 '브라우저에서 직접' 부르는 것은 키 노출 위험이 있습니다.
// 예시로 적을 때조차 진짜 키는 넣지 말고 자리표시자만 둡니다.
const EXCHANGE_API_KEY = "YOUR_API_KEY"; // ← 자리표시자. 실제 비밀키는 절대 코드에 넣지 않는다.
// 실제로는 이런 비밀키 호출은 서버(또는 n8n)에서 처리하고, 브라우저는 그 서버를 부릅니다.
```
