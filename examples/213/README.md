# 키워드에 답하는 Slack 슬래시 명령 챗봇 만들기

앞 실습(212번)에서는 문의가 **들어오면** 봇이 알아서 Slack **채널에 글을 올려** 줬습니다. 이번에는 한 걸음 더 나아가, 사람이 Slack에서 **직접 봇에게 말을 거는** 챗봇을 만듭니다.

Slack 입력창에 `/ask 연차는 며칠인가요?` 처럼 치면, 그 질문이 우리 n8n 워크플로우로 날아오고, **AI(Claude)가 답을 만들어 곧바로 Slack에 되돌려** 줍니다. 즉 **요청(질문) → 처리(AI) → 응답(답변)** 이 한 바퀴 도는, 진짜 "대화하는 봇"의 기본 구조를 직접 만들어 보는 것입니다.

> **슬래시 명령(Slash Command)이란?** Slack에서 `/`로 시작하는 명령어입니다. (`/giphy`, `/remind` 같은 것을 본 적 있을 거예요.) 우리가 `/ask`라는 명령을 새로 만들고, 누가 그 명령을 쓰면 Slack이 **우리 n8n 주소(Webhook)로 질문을 보내** 줍니다. 우리 워크플로우가 답을 돌려주면 Slack이 그 답을 채팅창에 보여 줍니다.
>
> **앞 실습과 가장 큰 차이:** 212번은 답을 "채널에 글로 올리는" 방식이었습니다. 슬래시 명령은 **Slack이 답을 기다리고 있다가** 받은 답을 바로 보여 주는 방식이라, 마지막 노드가 `Slack 노드`가 아니라 **`Respond to Webhook`(답 돌려주기)** 노드입니다.
>
> **이 워크플로우는 노드 5개입니다.**
> `슬래시 명령 받기 (Webhook)` → `AI에게 답 만들기 (LLM Chain)` → `Slack 답장 모양 만들기 (Set)` → `Slack에 답 돌려주기 (Respond to Webhook)`
> 그리고 AI 노드 아래에 **`Claude 모델`** 이 보조로 붙어 "어떤 AI로 답할지"를 정해 줍니다.

## 목표

- Slack **슬래시 명령(`/ask`)** 을 만들고, 그 명령이 우리 n8n **Webhook**으로 질문을 보내도록 연결한다.
- 들어온 질문을 **AI(Claude) 노드**에 넘겨 답을 만들고, 그 답을 **다시 Slack 채팅창에 돌려주는** 한 바퀴(요청→처리→응답)를 완성한다.
- 답을 **Slack이 알아듣는 형식(`response_type` + `text`)** 으로 맞춰 내보내는 법을 익힌다.

## 따라하는 단계

1. **n8n에 로그인**합니다. (n8n Cloud 또는 직접 설치한 n8n 모두 가능. AI 노드를 쓰려면 비교적 최신 버전이 좋습니다.)
2. 화면 오른쪽 위 **`...`(점 3개) → `Import from File`** 을 눌러 이 폴더의 **`workflow.json`** 을 불러옵니다. 노드 5개가 나타납니다.
3. **Anthropic(Claude) 자격증명을 연결**합니다. 이게 있어야 AI 노드가 동작합니다.
   - 먼저 Anthropic 콘솔(console.anthropic.com)에서 **API 키**를 발급받습니다.
   - n8n에서 **`Claude 모델 (Anthropic Chat Model)` 노드를 더블클릭** → `Credential` 칸에서 **`Create New Credential`** → 발급받은 키를 붙여넣고 저장합니다.
   - **중요:** API 키는 `workflow.json` 파일에 적지 않습니다. n8n의 **자격증명 금고**에만 저장됩니다. (그래서 이 파일에는 `REPLACE_WITH_YOUR_ANTHROPIC_CREDENTIAL_ID` 같은 자리표시자만 들어 있습니다.)
   - 모델은 **`claude-opus-4-8`** 로 두면 됩니다.
4. **Webhook 주소(Path) 정하기:** `슬래시 명령 받기 (Webhook)` 노드를 열어 `Path` 칸의 자리표시자(`REPLACE_WITH_YOUR_WEBHOOK_PATH`)를 추측하기 어려운 단어(예: `ask-bot-a93f`)로 바꿉니다. 그러면 n8n이 **Test URL**과 **Production URL** 두 개를 보여 줍니다. 둘 다 메모해 둡니다.
5. **`AI에게 답 만들기 (LLM Chain)` 노드를 더블클릭**해서 **프롬프트(지시문)** 를 읽어 봅니다. 이 실습의 핵심입니다.
   - 위쪽 **시스템 메시지**: "너는 사내 안내 챗봇이다. 한국어로 친절하고 짧게(600자 이내) 답해라. 모르면 지어내지 말고 담당자 확인을 안내해라." — AI에게 **역할과 규칙**을 정해 주는 부분입니다.
   - 아래쪽 **사용자 메시지**: `{{ $json.body.text }}` — 슬래시 명령으로 들어온 **실제 질문 문장**이 이 자리에 끼워집니다. (Slack은 `/ask` 뒤에 쓴 글을 `text`라는 칸에 담아 보냅니다.)
6. **`Slack 답장 모양 만들기 (Set)` 노드를 더블클릭**합니다. Slack 슬래시 명령은 답을 **정해진 형식**으로 받아야 합니다. 이 노드가 그 형식을 만듭니다.
   - `response_type` = `in_channel` : 답을 **채널 모두에게** 보입니다. (혼자만 보려면 `ephemeral`로 바꾸세요.)
   - `text` = AI가 만든 답(`{{ $json.text }}`).
7. **Slack에서 슬래시 명령 만들기.** Slack API 사이트(api.slack.com/apps)에서 앱을 하나 만든 뒤 **`Slash Commands` → `Create New Command`** 로 들어갑니다.
   - **Command:** `/ask`
   - **Request URL:** 4단계에서 메모한 **n8n Production URL**을 붙여넣습니다.
   - 저장하고, 그 앱을 자신의 워크스페이스에 설치(Install)합니다.
8. **켜기.** n8n 화면 오른쪽 위 토글을 **`Active`(활성)** 로 바꿉니다. 이제 Slack에서 `/ask` 명령이 실제로 우리 워크플로우를 깨웁니다. (테스트만 할 때는 캔버스의 `Test workflow` 버튼과 Test URL을 쓰면 됩니다.)

## 🤖 바이브코딩 프롬프트

이 실습(슬래시 명령 → AI → 응답 한 바퀴)을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. n8n 노드를 손으로 일일이 만들기 전에, 먼저 AI에게 흐름과 설정을 설계하게 시키고 그 결과를 점검하는 '디렉터' 방식으로 써 보세요.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 n8n 자동화 워크플로우 설계를 도와주는 도우미야.
  목표: Slack 슬래시 명령 `/ask <질문>`을 받아 AI가 답하고, 그 답을 다시 Slack 채팅창에 돌려주는 챗봇을 만들고 싶어.
  제약:
  - 노드 흐름은 [Webhook(POST) → LLM Chain → Set → Respond to Webhook] 순서로 해줘.
  - LLM Chain의 모델은 Anthropic Claude(claude-opus-4-8)를 보조 노드로 붙여줘.
  - API 키 같은 비밀값은 절대 파일에 직접 적지 말고, n8n 자격증명(Credentials)으로 고르게 설명해줘.
  산출물: 각 노드를 무슨 목적으로 두는지, 어떤 값을 어디에 넣어야 하는지 단계별로 알려줘.
  나는 비전공자이니 전문 용어는 한 줄씩 풀어서 설명해줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  앞에서 만든 슬래시 명령 챗봇을 개선하고 싶어.
  1) Slack이 알아듣는 응답 형식 {"response_type": ..., "text": ...}을 Set 노드에서 어떻게 만드는지 정확히 알려줘.
  2) 답이 모두에게 보이는 in_channel과 나만 보이는 ephemeral의 차이를 설명하고, 바꾸는 방법을 알려줘.
  3) AI가 사내 챗봇답게 답하도록 시스템 메시지(역할·규칙)를 어떻게 쓰면 좋을지 예시를 만들어줘.
     - 한국어로, 600자 이내로, 모르면 지어내지 말고 담당자 확인을 안내하도록.
  4) 질문이 비어 있을 때 봇이 안내 문구를 내도록 프롬프트에 예외 규칙을 넣어줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  n8n 워크플로우에서 에러가 났어. 아래 정보를 보고 원인을 단계별로 짚어줘.
  - 무엇을 했는지: (예: Test URL로 curl 요청을 보냈다)
  - 기대한 결과: Slack 형식 JSON이 돌아오는 것
  - 실제 결과 / 빨간 X가 뜬 노드: (여기에 붙여넣기)
  - 에러 메시지 전문: (여기에 붙여넣기)
  특히 다음을 점검해줘: Webhook의 Path가 자리표시자 그대로인지, Anthropic 자격증명이 연결됐는지,
  사용자 질문이 {{ $json.body.text }}로 제대로 들어오는지, 마지막 노드가 Respond to Webhook인지.
  가능성 높은 원인부터 순서대로, 각각 어떻게 확인하고 고치는지 알려줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 훨씬 좋습니다.

## 검증법

1. **n8n 안에서 먼저 테스트(Slack 없이).** 캔버스의 **`Test workflow`** 를 누른 뒤, 터미널(또는 [reqbin.com](https://reqbin.com) 같은 도구)에서 4단계의 **Test URL**로 슬래시 명령을 흉내 낸 요청을 보냅니다. Slack은 폼(form) 형식으로 보내므로 아래처럼 보냅니다. `<여기에_Test_URL>` 자리에 메모해 둔 주소를 넣으세요.
   ```bash
   curl -X POST "<여기에_Test_URL>" \
     -H "Content-Type: application/x-www-form-urlencoded" \
     --data-urlencode "text=연차는 며칠인가요?"
   ```
2. **돌아온 답 확인.** 위 요청에 대한 응답으로 아래와 비슷한 JSON이 화면에 찍히면 한 바퀴가 정상으로 돈 것입니다. (질문에 따라 답 문장은 달라집니다.)
   ```json
   { "response_type": "in_channel", "text": "안녕하세요! 연차 관련 안내를 드릴게요. ..." }
   ```
3. **모든 노드에 초록색 체크 표시**가 떴는지 확인합니다. 빨간 X가 있으면 그 노드를 눌러 오류 메시지를 읽어 봅니다.
4. **진짜 Slack에서 확인(8단계까지 마쳤다면).** Slack 채팅창에 `/ask 회의실 예약은 어디서 하나요?` 라고 쳐 봅니다. 잠시 뒤 봇이 답을 채팅창에 띄우면 성공입니다.
5. **질문을 바꿔 보기.** 1번의 `text`를 `"점심 추천해 줘"` 로 바꿔 다시 보내면 **답 내용도 질문에 맞게 달라집니다.** 같은 워크플로우가 질문에 따라 다르게 답하는 것이 챗봇의 핵심입니다.
6. **빈 질문 처리 확인.** `--data-urlencode "text="` 처럼 질문을 비워 보내면, 5단계 프롬프트의 규칙대로 봇이 "무엇이 궁금하신가요?"라고 안내해야 합니다. **예외 상황까지 프롬프트로 미리 정해 두는 것**이 좋은 봇입니다.

## 핵심만 짚기 (디렉터 관점)

- **챗봇 = 한 바퀴 돌리기.** 자동화의 기본 흐름은 늘 같습니다. 무슨 일이 생기면(슬래시 명령) → 판단·생성을 맡기고(AI) → 결과를 사람에게 돌려준다(응답). 봇이 "대화한다"고 느껴지는 이유는 **이 한 바퀴가 빠르게 돌기** 때문입니다.
- **마지막 노드가 다른 이유.** 212번은 채널에 글을 "올리는" 봇이라 마지막이 `Slack 노드`였습니다. 슬래시 명령은 Slack이 **답을 기다리고 있다가** 받은 걸 보여 주는 방식이라, 마지막이 **`Respond to Webhook`(답 돌려주기)** 입니다. "누가 기다리고 있느냐"에 따라 마지막 노드가 달라집니다.
- **형식이 곧 약속이다.** Slack은 아무 글이나 받지 않고 `{"response_type": ..., "text": ...}` 형식만 알아듣습니다. 그래서 AI 답을 그대로 던지지 않고 `Set` 노드로 **Slack이 약속한 모양**으로 한 번 감싸 줍니다. 외부 서비스와 연동할 때는 항상 "상대가 어떤 형식을 원하는가"를 먼저 확인하세요.
- **AI의 품질 = 프롬프트의 품질.** "짧게, 한국어로, 모르면 지어내지 말 것" 같은 규칙을 또렷이 정해 줘야 사내 챗봇으로 쓸 만한 답이 나옵니다. 규칙을 바꾸면 봇의 성격이 통째로 바뀝니다.

## 보안, 비밀값은 어떻게 다루나

- **API 키(Anthropic)** 는 새면 안 되는 비밀값입니다. 절대 `workflow.json`이나 노드 값에 직접 적지 마세요.
  - 올바른 방법: n8n의 **`Credentials`(자격증명) 금고**에 저장하고, 노드에서는 그 자격증명을 **고르기만** 합니다. 그러면 키는 금고에만 있고 파일에는 남지 않습니다.
  - 그래서 이 파일에는 실제 값 대신 `REPLACE_WITH_YOUR_ANTHROPIC_CREDENTIAL_ID` 같은 **자리표시자**만 들어 있습니다. 이 파일을 남에게 줘도 비밀이 새지 않습니다.
- **Webhook 주소도 일종의 비밀입니다.** 주소를 아는 사람은 누구나 우리 봇을 깨워 AI 비용을 쓰게 만들 수 있으니, 추측하기 어려운 Path를 쓰고 외부에 함부로 공개하지 않습니다. (이 파일엔 `REPLACE_WITH_YOUR_WEBHOOK_PATH` 자리표시자만 있습니다.)
- **한 단계 더(실전 팁):** Slack은 요청을 보낼 때 **서명(Signing Secret)** 을 함께 붙여 "정말 Slack이 보낸 게 맞는지" 확인할 수 있게 해 줍니다. 실제 서비스에서는 이 서명을 검사해 가짜 요청을 막습니다. 이 서명 검증용 비밀값 역시 n8n 자격증명/환경변수에만 두고, 코드에는 `REPLACE_WITH_YOUR_SLACK_SIGNING_SECRET` 같은 자리표시자만 둡니다. (이번 실습에서는 흐름 이해가 목적이라 검증 노드는 넣지 않았습니다.)
- 한 줄 원칙: **공개해도 되는 값은 노드에, 새면 안 되는 값(API 키·토큰·서명 비밀)은 자격증명 금고에.**
