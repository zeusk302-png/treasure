# 실습 318 — 재사용 컴포넌트(버튼·카드) 만들기

버튼·카드처럼 **여기저기 똑같이 나오는 UI 조각**을 매번 복사-붙여넣기(복붙) 하는 대신, **한 번만 정의해 두고 이름으로 불러 쓰는** 방법을 익힙니다. 두 가지 길을 다 만들어 봅니다 — (1) **웹 컴포넌트**(브라우저 표준 `customElements`로 `<ui-button>`·`<ui-card>` 같은 나만의 태그를 만드는 방식)와 (2) **작은 템플릿 함수**(자바스크립트 함수가 HTML 문자열을 찍어 주는 더 쉬운 방식). 같은 결과를 두 방식으로 만들어 보며 "복붙 대신 컴포넌트로 묶으면 무엇이 좋은지"를 몸으로 느끼는 것이 목표입니다.

> 한 줄 그림: **버튼 모양을 한 곳에 정의 → `<ui-button>저장</ui-button>` 처럼 부르기만 하면 어디서든 같은 버튼이 나옴 → 색·테두리를 바꾸고 싶으면 정의 한 곳만 고치면 전부 같이 바뀜**

> 비유: 컴포넌트는 **쿠키 틀(모양 틀)** 입니다. 쿠키를 하나하나 손으로 빚으면(복붙) 모양이 제각각이고, 모양을 바꾸려면 전부 다시 빚어야 합니다. 틀을 한 번 만들어 두면(컴포넌트) 반죽만 눌러 찍으면 똑같은 쿠키가 끝없이 나오고, 모양을 바꾸려면 **틀 하나만** 고치면 됩니다.

## 목표
- **복붙의 문제**를 체감한다: 같은 버튼을 5곳에 복붙해 두면, 색 하나 바꿀 때 5곳을 다 고쳐야 한다는 걸 직접 본다.
- **웹 컴포넌트**로 `<ui-button>`·`<ui-card>` 라는 나만의 태그를 만들어, HTML에서 그냥 태그처럼 갖다 쓴다.
- **속성(attribute)으로 내용을 바꾸는** 법을 익힌다(예: `variant="primary"`, `title="..."` 처럼 같은 틀에 다른 값 넣기).
- **템플릿 함수** 방식도 만들어, 웹 컴포넌트가 어렵게 느껴질 때 쓸 수 있는 더 쉬운 대안을 안다.
- **사용자 입력은 `textContent`로 안전하게** 넣어, 남이 넣은 글자가 코드로 실행되는 사고(XSS)를 막는다.

## 따라하는 단계

1. 이 폴더의 `index.html`, `script.js`를 같은 폴더에 둡니다. (별도 서버 없이 동작합니다.)
2. `index.html`을 더블클릭해 브라우저로 엽니다. 화면에 **같은 버튼 3개**와 **같은 모양 카드 3장**이 보입니다 — 그런데 HTML 소스에는 버튼/카드 마크업이 **한 벌씩만** 적혀 있습니다. 이게 컴포넌트의 힘입니다.
3. `script.js`를 열어 **위쪽 "방법 1: 웹 컴포넌트"** 부분을 봅니다. `customElements.define('ui-button', ...)` 로 `<ui-button>` 이라는 새 태그를 등록하는 부분이 핵심입니다.
4. `index.html`에서 `<ui-button variant="primary">저장</ui-button>` 처럼 **그냥 태그로** 버튼을 쓴 곳을 찾습니다. 글자(`저장`)와 색(`variant`)만 바꿔서 새 버튼을 한 줄 더 추가해 보세요. 새로고침하면 바로 나옵니다.
5. **버튼 색을 바꿔 봅니다**: `script.js`의 버튼 정의 안 `--ui-primary` 색 값 **한 줄만** 고치고 새로고침하세요. 화면의 **모든 primary 버튼이 한꺼번에** 바뀝니다 — 복붙이었다면 전부 일일이 고쳐야 했을 일입니다.
6. `script.js` **아래쪽 "방법 2: 템플릿 함수"** 부분을 봅니다. `cardHtml(...)` 함수가 카드 HTML을 문자열로 만들어 주는 방식입니다. 데이터 배열을 돌며 카드를 찍어내는 부분(`renderCards`)도 같이 보세요.
7. (응용) `index.html` 위쪽 `cardData` 배열에 카드 데이터를 한 개 더 추가하고 새로고침하면, 카드가 한 장 더 자동으로 그려집니다.

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 프론트엔드 교사야. 비전공 초보가 "재사용 컴포넌트"를 처음 이해하도록,
  외부 라이브러리(React 등) 없이 순수 HTML/CSS/JS만으로 데모 페이지를 만들어 줘.

  요구사항:
  - 브라우저 표준 웹 컴포넌트(customElements.define)로 <ui-button>과 <ui-card> 두 개를 정의.
  - <ui-button>은 variant 속성("primary" | "secondary" | "danger")으로 색이 달라지게.
    버튼 글자는 태그 사이 내용(<ui-button>저장</ui-button>)으로 넣게.
  - <ui-card>는 title, body 속성으로 제목/본문을 받아 카드 모양으로 표시.
  - index.html에는 같은 버튼/카드를 여러 번 "태그로만" 갖다 써서, 정의는 한 벌인데
    화면엔 여러 개 나오는 걸 보여 줘.
  - 파일은 index.html, script.js로 나누고, 별도 서버 없이 더블클릭만으로 열려야 해.

  중요: 코드만 주지 말고, 비전공자가 한 줄씩 이해하도록 "이게 뭐고(기능) 왜 이렇게
  했는지(이유)"를 한국어 주석으로 충분히 달아 줘. 변수·함수 이름은 영어로.
  ```

- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  좋아. 이제 같은 결과를 만드는 "두 번째 방법"을 추가해서 비교하게 해 줘.

  - 방법 2로, 웹 컴포넌트 대신 "템플릿 함수"를 추가해 줘:
    cardHtml({title, body}) 처럼 HTML 문자열을 돌려주는 함수와,
    카드 데이터 배열을 돌며 한꺼번에 그려 주는 renderCards() 함수.
  - 두 방법을 화면에서 좌우(또는 위아래)로 나란히 보여 주고, 각 방법의 장단점을
    주석으로 짧게 설명해 줘(웹 컴포넌트=캡슐화 강함/표준, 템플릿 함수=쉽고 빠름).
  - 버튼 색·카드 테두리 같은 공통 값은 CSS 변수(디자인 토큰)로 한 곳에 모아,
    "한 줄만 바꾸면 전부 바뀐다"를 실제로 확인할 수 있게 해 줘.

  보안: 사용자나 데이터에서 온 글자를 화면에 넣을 땐 innerHTML 말고 textContent를
  써서 XSS를 막아 줘. 왜 그렇게 하는지도 주석으로 적어 줘.
  ```

- **막혔을 때(디버깅)** 프롬프트:
  ```text
  웹 컴포넌트가 화면에 안 나오거나 빈 칸으로만 보여. 아래 정보로 단계별로 진단해 줘.

  - 증상: (예) <ui-button>이 그냥 글자 "저장"만 나오고 버튼 모양이 안 됨 /
    또는 콘솔에 "Illegal constructor" 같은 에러가 뜸.
  - 콘솔 에러 전문: <여기에 붙여넣기>
  - 관련 코드: <customElements.define(...)와 해당 태그 사용 부분 붙여넣기>

  점검해 줘:
  1) <script>가 페이지 맨 아래(또는 defer)에 있어서 태그보다 먼저 정의됐는지
  2) 태그 이름에 하이픈(-)이 들어갔는지 (웹 컴포넌트는 ui-button처럼 - 필수)
  3) class가 HTMLElement를 상속하고 connectedCallback에서 그렸는지
  원인을 1~2개로 좁혀 주고, 비전공자가 따라 할 수 있게 고친 코드와 이유를 알려 줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법
- **태그로 쓰이는지 확인**: `index.html` 소스를 보면 버튼/카드가 `<ui-button>`·`<ui-card>` 또는 함수 호출 한 벌로만 적혀 있는데, 화면엔 여러 개가 뜬다 — 컴포넌트가 동작한다는 증거다.
- **"한 곳 고치면 전부 바뀜" 확인**: `script.js`의 `--ui-primary` 색 값 한 줄을 바꾸고 새로고침했을 때, 화면의 **모든 primary 버튼**이 같이 바뀌면 성공이다.
- **속성이 먹는지 확인**: `variant`를 `primary`→`danger`로 바꾸면 버튼 색이 빨강 계열로 바뀌고, 카드의 `title`을 바꾸면 제목이 따라 바뀐다.
- **두 방식 결과가 같은지 확인**: 웹 컴포넌트로 만든 카드와 템플릿 함수로 만든 카드가 **눈으로 봤을 때 같은 모양**이면, 같은 일을 두 방법으로 한 것이다.
- **XSS 안전 확인**: 카드 데이터의 `title`에 `<img src=x onerror=alert(1)>` 같은 문자열을 넣어도 **그 글자가 그대로 화면에 보일 뿐 경고창이 안 뜨면** `textContent`가 제대로 막은 것이다. (경고창이 뜨면 어딘가 `innerHTML`을 쓴 것이니 점검한다.)
- **콘솔 에러 없음**: `F12` → Console 탭에 빨간 에러가 없어야 한다.

## 파일 구성
- `index.html` — 데모 페이지. 컴포넌트를 **태그/함수 호출로만** 갖다 쓰는 모습을 보여 준다.
- `script.js` — 컴포넌트 정의 두 가지(방법 1: 웹 컴포넌트 `<ui-button>`·`<ui-card>`, 방법 2: 템플릿 함수). 모든 줄에 기능+이유 주석이 달려 있다.
