# 217. AI에게 "실행 전에 무엇을 할지 3줄로 먼저 보고해" 시키기

## 목표

히어로 섹션(첫 화면)의 **한 줄 소개 문구**를 바꾸는 작업을 시키되,
AI(Claude 등)가 **멋대로 곧바로 코드를 고치지 않고** "무엇을 / 왜 / 어떻게"를
**먼저 3줄로 보고**하게 만드는 지시법을 연습합니다.

이것을 **"선(先)보고 후(後)실행"** 이라고 부릅니다.
방향(무엇을·왜)은 사람이 정하고, 구현(어떻게)은 AI가 맡되,
**승인 전에는 코드를 건드리지 못하게** 하는 디렉터의 기본기입니다.
이 실습에는 새로 짤 코드가 거의 없습니다. **잘 지시하는 글쓰기**가 곧 실습입니다.

결과물은 세 파일입니다.

- [`prompt.md`](prompt.md) — AI에게 그대로 붙여넣는 지시 프롬프트
- [`conversation.md`](conversation.md) — AI가 "먼저 3줄 계획"을 출력한 대화 캡처(예시)
- [`index.html`](index.html) — 승인 후 문구 한 줄만 바뀐 결과물 (변경 전 문구는 주석으로 남겨 둠)

## 따라하는 단계

1. [`index.html`](index.html)을 더블클릭해 브라우저로 엽니다. 첫 화면 문구가 "오늘 아침 만든 집밥 반찬, 그대로 식탁까지"인 것을 확인합니다. (이게 *바꾼 뒤* 모습입니다.)
2. [`prompt.md`](prompt.md)의 **1단계 지시 프롬프트**를 통째로 복사합니다. 핵심은 제약 1번 — "지금 바로 코드를 고치지 마, 먼저 3줄로 계획만 보고해"입니다.
3. 복사한 프롬프트를 실제 Claude(또는 쓰는 AI)에 붙여넣습니다.
4. AI가 코드부터 뱉으면, [`prompt.md`](prompt.md)의 **2단계 한 마디**("아직 진행해라고 안 했어…")로 다시 계획만 받게 잡아줍니다.
5. AI가 "무엇을 / 왜 / 어떻게"를 **3줄로 보고**하면, 방향이 맞는지 읽고 판단합니다. (예시는 [`conversation.md`](conversation.md))
6. 마음에 들면 **3단계 승인 한 마디**("좋아, 진행해…")를 보냅니다. 그제서야 AI가 바뀐 한 줄만 보여줍니다.
7. AI가 준 문구로 [`index.html`](index.html)의 `<p class="hero-tagline">…</p>` **텍스트 한 줄만** 바꿔 저장하고, 브라우저를 새로고침해 확인합니다.
8. (제출용) 5단계의 "3줄 계획 보고" 화면을 캡처해 두면, 이 실습의 핵심 증거가 됩니다.

## 🤖 바이브코딩 프롬프트

이 실습의 주제는 **"선보고 후실행"** — AI가 멋대로 코드부터 고치지 못하게 막고, "무엇을/왜/어떻게"를 먼저 3줄로 보고하게 한 뒤 승인하는 통제법입니다. 그래서 이 실습은 *짤 코드*가 아니라 *시키는 글*이 핵심입니다. 아래 프롬프트를 그대로 복사해 AI에게 쓰세요. (위 [`prompt.md`](prompt.md)의 실전 버전을 학습용으로 정리한 것입니다.)

- **1단계(뼈대 만들기)** — "먼저 보고" 제약을 건 첫 지시:
  ```text
  너는 내 웹사이트 작업을 돕는 개발 파트너야.
  순수 HTML/CSS/JS로 만든 1페이지 소개 사이트(index.html 하나)가 있어.
  히어로 섹션(첫 화면)의 한 줄 소개 문구(hero-tagline 텍스트)를
  더 따뜻하고 신뢰감 있는 한 문장으로 바꾸고 싶어.

  [제약 — 가장 중요]
  1. 지금 바로 코드를 고치지 마. 먼저 "무엇을 / 왜 / 어떻게" 순서로 딱 3줄로 계획만 보고해.
  2. 바꾸는 범위는 hero-tagline 텍스트 한 줄로만 한정해. 다른 태그·클래스·구조는 절대 건드리지 마.
  3. 내가 "진행해"라고 답해야만 그때 바뀐 부분만 보여줘.
  4. 새 문구는 과장 광고(최고/1등/100%) 없이 20자 안팎으로 1개만 제안해.
  ```

- **2단계(기능 추가/개선)** — 계획이 맞으면 승인하고, 변경 흔적까지 남기게:
  ```text
  좋아, 그 방향으로 진행해. hero-tagline 텍스트 한 줄만 바꿔서 그 부분만 보여줘.
  그리고 나중에 비교할 수 있게, 바꾼 줄 바로 위에 "변경 전(before)" 문구를
  HTML 주석(<!-- -->)으로 함께 남겨줘. 다른 코드는 그대로 둬.
  ```

- **막혔을 때(디버깅)** — AI가 제약을 무시하고 코드부터 쏟아낼 때:
  ```text
  잠깐, 아직 "진행해"라고 안 했어. 코드 말고 "무엇을 / 왜 / 어떻게" 3줄 계획부터 다시 보여줘.
  방금 네가 시키지 않은 부분(태그·클래스·다른 문구)까지 손댔는지도 한 줄로 점검해서 알려줘.
  ```

> 프롬프트 팁: 어떤 단계든 끝에 **"코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘"** 를 붙이면, AI의 판단 근거가 드러나 방향이 틀렸을 때 더 빨리 잡아낼 수 있습니다.

## 검증법

아래를 모두 만족하면 성공입니다.

- [ ] AI가 **첫 답변에서 코드를 주지 않고** "무엇을 / 왜 / 어떻게" **3줄 계획**만 보고했다.
- [ ] 사람이 **"진행해"라고 승인한 뒤에야** 실제 코드 수정이 나왔다.
- [ ] 실제로 바뀐 것은 **`hero-tagline` 텍스트 한 줄뿐**이고, 다른 태그·클래스·구조는 그대로다.
- [ ] [`index.html`](index.html)을 브라우저로 열면 새 문구가 보이고, 주석에 **변경 전 문구**가 함께 남아 있어 before/after가 비교된다.
- [ ] 새 문구에 과장 광고(최고/1등/100%)가 없고 20자 안팎이다.

> 빠르게 자가 점검: AI가 코드를 주기 **전에** 내가 "방향이 틀렸으니 멈춰"라고 끼어들 틈이 있었다면 통과입니다.
> 끼어들 틈도 없이 코드부터 쏟아졌다면, "먼저 보고" 제약을 더 강하게(맨 위·굵게) 다시 거세요.
