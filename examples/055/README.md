# 055 - AI에게 디자인 시스템 지시해 일관된 컴포넌트 세트 만들기

지금까지는 버튼 하나, 카드 하나를 그때그때 색과 여백을 정해 가며 꾸몄습니다.
그러다 보면 어떤 버튼은 파랑, 어떤 버튼은 살짝 다른 파랑, 여백도 제각각이 되어
화면이 **"통일감 없이 어수선"** 해집니다.

진짜 서비스는 색·간격·폰트 규칙을 **먼저 한 곳에 정해 두고**(이걸 "디자인 토큰"이라고 합니다),
모든 버튼·카드·폼이 그 규칙만 가져다 씁니다. 그러면 규칙 한 줄만 바꿔도 전체가 통일된 채로 바뀝니다.

이 실습에서는 코드를 처음부터 손으로 짜는 대신, **AI(Claude)에게 "이 규칙대로 만들어 줘"라고 지시하는 디렉터**가 되어 봅니다.
이 폴더의 `prompt.md`가 그 지시문이고, `style.css` / `index.html`은 그 지시로 받을 수 있는 **정답 예시 결과물**입니다.

> 비전공자를 위한 한 줄 요약: 코드를 외워서 짜는 게 아니라, "무엇을 일관되게 만들지" 규칙을 정해 AI에게 정확히 시키는 능력이 핵심입니다.

## 목표

- 색·간격·폰트 규칙을 **디자인 토큰**(CSS 변수, `--color-primary` 같은 것)으로 한 곳에 정의한다.
- AI에게 "토큰을 먼저 정의하고, 모든 컴포넌트는 그 토큰만 써라"라고 지시하는 **디렉팅 프롬프트**를 쓴다.
- 그 규칙으로 버튼·카드·폼이 서로 어울리는(통일된) 컴포넌트 세트를 만든다.
- AI가 규칙을 안 지켰을 때(색을 직접 박아 넣었을 때) 그걸 알아보고 **다시 고치게 시키는** 디렉터의 눈을 기른다.

## 따라하는 단계

1. **결과물 먼저 본다.** 이 폴더의 `index.html`을 브라우저로 엽니다(더블클릭 또는 VS Code의 Live Server). 색이 통일된 버튼 3개, 카드 2개, 폼 1개가 보입니다.

2. **"한 줄로 전체 바꾸기"를 체험한다.** `style.css` 맨 위 `:root` 안에서 다음 한 줄을 찾아 색을 바꿔 보세요.

   ```css
   --color-primary: #2563eb;   /* 예: #16a34a (초록) 로 바꿔 보기 */
   ```

   저장하고 브라우저를 새로고침하면, 메인 버튼·폼 입력칸 강조색이 **한꺼번에** 바뀝니다. 이것이 디자인 토큰의 힘입니다.

3. **AI 디렉터가 되어 본다.** `prompt.md`를 엽니다. "프롬프트 1"(토큰 정의)을 복사해 Claude에 붙여 넣고, 이어서 "프롬프트 2"(컴포넌트 생성)를 보냅니다. AI가 직접 토큰과 컴포넌트 CSS를 만들어 줍니다.

4. **AI 결과를 검사한다.** 받은 코드에서, 버튼·카드·폼 안에 `#2563eb` 같은 색 코드나 `16px` 같은 숫자가 **직접** 박혀 있는지 살펴봅니다. 박혀 있으면 규칙 위반입니다.

5. **규칙을 안 지켰으면 다시 시킨다.** `prompt.md`의 "프롬프트 3"을 보내 직접 박은 값을 `var(--토큰)`으로 바꾸게 합니다. 이렇게 **"다시 고쳐"라고 지시하는 것**이 디렉팅의 핵심입니다.

6. **내 결과와 정답 예시를 비교한다.** AI가 만든 CSS를 이 폴더의 `style.css`와 나란히 놓고, 토큰을 잘 분리했는지·클래스 이름 규칙이 일관됐는지 비교합니다.

## 무엇이 "일관된 디자인 시스템"인가 (해설)

- **디자인 토큰 = 규칙을 적어 둔 한 곳.** `style.css` 맨 위 `:root`에 색·간격·폰트가 변수로 모여 있습니다. 컴포넌트들은 이 변수만 가져다 씁니다.

  ```css
  :root {
    --color-primary: #2563eb;   /* 메인 색 */
    --space-3: 16px;            /* 기본 간격 */
    --radius-sm: 6px;          /* 둥글기 */
  }
  .btn--primary { background-color: var(--color-primary); }  /* 색을 직접 안 쓰고 토큰 사용 */
  .card        { padding: var(--space-3); }                  /* 여백도 토큰 사용 */
  ```

- **같은 의미는 같은 토큰을 쓴다.** 버튼의 메인 색과 폼 입력칸을 클릭했을 때의 강조색이 **둘 다 `--color-primary` 계열**입니다. 그래서 서로 어울려 보입니다. 이게 "통일감"의 정체입니다.

- **클래스 이름도 규칙(BEM)으로 통일.** `블록__요소--변형` 형태입니다. 예: `.btn`(블록) / `.btn--primary`(변형) / `.card__title`(요소). 이름만 봐도 무엇인지 알 수 있고 충돌이 줄어듭니다.

- **AI가 자주 하는 실수.** 토큰을 정의하라고 해도, 막상 컴포넌트에서는 `background-color: #2563eb;`처럼 색을 **직접 박아 넣는** 경우가 많습니다. 이러면 나중에 메인 색을 바꿀 때 일일이 다 찾아 고쳐야 해서 디자인 시스템의 장점이 사라집니다. 디렉터가 이를 잡아내 다시 시켜야 합니다.

## 🤖 바이브코딩 프롬프트

이 실습(디자인 토큰으로 일관된 컴포넌트 세트 만들기)을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.
(같은 폴더 `prompt.md`에 더 자세한 버전이 있습니다. 아래는 README용 요약 3종입니다.)

- **1단계(뼈대 만들기)** — 디자인 토큰부터 정의시키기:

  ```text
  당신은 비전공 입문자를 돕는 프론트엔드 디자인 시스템 전문가입니다.
  순수 HTML/CSS만 쓰고(프레임워크·외부 라이브러리 금지), 한국어 주석을 답니다.

  먼저 style.css 맨 위 :root 에 "디자인 토큰"을 CSS 변수로 정의해 주세요.
  - 색: 메인 색(+hover 진한 색, +옅은 배경색), 본문/보조 글자색, 테두리색, 페이지·카드 배경색, 에러색, 성공색
  - 간격: 4px 배수 5단계(--space-1 ~ --space-5)
  - 폰트: 글꼴 패밀리, 크기 3단계(sm/base/lg), 굵기 2단계, 줄간격
  - 모서리 둥글기 2단계, 그림자 2단계
  제약: 앞으로 만들 모든 컴포넌트는 색 코드(#...)나 여백 숫자(16px)를 직접 쓰지 말고,
  반드시 위에서 정의한 var(--토큰) 만 쓸 것. 설명은 짧게, 코드 위주로.
  ```

- **2단계(기능 추가/개선)** — 그 토큰으로 컴포넌트 3종 + 데모 페이지 만들기:

  ```text
  좋아요. 방금 정의한 디자인 토큰만 사용해서 아래 3가지 컴포넌트를 만들어 주세요.
  색·여백·폰트·둥글기·그림자는 전부 var(--토큰) 으로만 지정하세요.
  1) 버튼(.btn): 공통 모양 1개 + 색만 다른 변형 3개(.btn--primary/.btn--secondary/.btn--danger),
     hover와 클릭(active) 상태 포함.
  2) 카드(.card): 제목(.card__title) + 본문(.card__body) + 안에 버튼을 넣을 수 있게.
  3) 폼(.form): 라벨(.form__label) + 입력칸(.form__input) + 도움말(.form__help),
     입력칸 focus 시 메인 색으로 강조하되 그 색은 버튼과 같은 토큰을 쓸 것.
  마지막으로 이 컴포넌트를 한 번에 보여 주는 index.html 데모 페이지도 만들어 주세요.
  클래스 이름은 BEM 스타일(블록__요소--변형)로 통일하세요.
  ```

- **막혔을 때(디버깅)** — 토큰을 안 지킨 곳(직접 박은 값) 찾아 고치기:

  ```text
  방금 만든 CSS에서 디자인 토큰(var(--...))을 쓰지 않고
  색 코드(#으로 시작)나 px 숫자를 직접 적은 곳이 있는지 전부 찾아 주세요.
  그리고 해당 줄을 알맞은 토큰으로 바꾼 수정본을 보여 주세요.
  (마땅한 토큰이 없으면 :root 에 새 토큰을 추가하는 방식으로 고쳐 주세요.)
  왜 그 줄이 문제였는지도 한 줄씩 설명해 주세요.
  ```

> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법

- `index.html`을 브라우저로 열어 버튼·카드·폼의 색·여백·둥글기가 서로 통일돼 보이는지 확인합니다.
- **핵심 검증:** `style.css`의 `--color-primary` 한 줄만 바꾸고 새로고침했을 때, 버튼과 폼 강조색이 **동시에** 바뀌면 토큰이 제대로 연결된 것입니다. 한 곳만 바뀌고 다른 곳은 안 바뀌면, 그 안 바뀐 곳이 색을 직접 박아 넣은 곳입니다.
- 폼 입력칸을 클릭(focus)했을 때 테두리·바깥 강조색이 메인 버튼과 같은 색 계열이면 일관성 통과입니다.
- `style.css`에서 `.btn`·`.card`·`.form` 코드 영역에 `#`으로 시작하는 색 코드나 `px` 숫자가 직접 박혀 있지 않고 전부 `var(--...)`인지 눈으로 확인합니다. (정답 예시는 데모 보조 스타일을 빼면 토큰만 씁니다.)
