# 실습 258 — 커뮤니티 게시판: 글 작성·목록 표시(CRUD의 C·R) 만들기

누구나 **글을 쓰면 Supabase에 저장**되고, 저장된 글이 **아래 목록에 바로 나타나는** 가장 단순한 커뮤니티 게시판을 만듭니다. 데이터로 할 수 있는 4가지 동작 CRUD(Create 만들기 · Read 읽기 · Update 수정 · Delete 삭제) 중에서, 이번에는 앞쪽 절반인 **생성(Create)**과 **조회(Read)**만 구현합니다. 수정·삭제를 일부러 빼는 이유는, 공개 키로는 남의 글을 함부로 고치거나 지울 수 없게 하기 위해서입니다.

> 한 줄 그림: **글쓰기 폼 입력 → script.js가 `posts` 표에 INSERT(저장) → 같은 표를 SELECT(조회)로 다시 읽어 → 화면 목록에 최신 글부터 그려 넣기**

> 비유: `posts` 표는 동네 게시판의 **코르크 보드**입니다. INSERT는 새 쪽지를 **압정으로 붙이는** 일, SELECT는 보드에 붙은 쪽지를 **쭉 읽어 내려가는** 일이에요. RLS(행 수준 보안)는 보드 옆에 선 **관리인**이라서, "쪽지 붙이기와 읽기는 누구나 OK, 하지만 남의 쪽지를 떼거나 고치는 건 금지"라는 규칙을 대신 지켜 줍니다.

> 보안 메모 — 공개해도 되는 값 vs 절대 숨겨야 하는 값
> - **공개되어도 되는 값**: `SUPABASE_URL`(내 DB의 인터넷 주소)과 **anon 키**(`sb_publishable_...`). 이 둘은 브라우저·`script.js`·깃허브에 그대로 올라가도 안전합니다. 안전한 이유는 표에 **RLS를 켜고** "읽기(SELECT)와 쓰기(INSERT)만 허용" 정책을 달아, 이 출입증으로 할 수 있는 일을 미리 제한해 두었기 때문입니다.
> - **절대 노출하면 안 되는 비밀값**: **service_role 키**(`sb_secret_...`). 이건 RLS 자체를 **통째로 우회하는 마스터 키**라, 정책이 무엇이든 무시하고 다 됩니다. 그래서 브라우저·코드·깃허브에 올리면 절대 안 되고, 오직 서버(예: n8n, 백엔드)에서만 비밀로 보관해 씁니다.
> - 이번 실습 화면(`index.html`/`script.js`)에는 **anon 키만** 들어갑니다. "anon=비밀키"는 흔한 오해인데, 정확히는 **anon=공개 가능, 보호는 RLS가 담당**입니다.

## 목표
- **CRUD의 절반(C·R)을 직접 만든다**: 글 저장은 `INSERT`(Create), 목록 표시는 `SELECT`(Read)로 이루어진다는 흐름을 코드로 체감한다.
- **RLS로 '공개 키로도 안전한' 게시판을 만든다**: `posts` 표에 RLS를 켜고 SELECT·INSERT 정책만 허용해, anon 키로는 읽기/쓰기는 되고 수정·삭제는 막히는 구조를 이해한다.
- **공개 가능한 값과 비밀값을 구분한다**: URL·anon 키는 화면에 두어도 되고, service_role 키는 절대 코드에 두지 않는다는 원칙을 손에 익힌다.
- **사용자 입력을 안전하게 출력한다**: 남이 쓴 글을 화면에 그릴 때 `innerHTML`이 아니라 `textContent`를 써서 XSS(악성 스크립트 실행)를 막는다.

## 따라하는 단계

### A. Supabase 프로젝트 만들고 표·보안 세팅하기
1. [Supabase](https://supabase.com)에 가입해 새 프로젝트를 하나 만듭니다. (DB 비밀번호는 잘 보관하세요.)
2. 왼쪽 메뉴에서 **SQL Editor → New query**를 열고, 이 폴더의 `schema.sql` 내용을 **통째로 붙여넣은 뒤 오른쪽 위 [Run]**을 누릅니다.
   - 이 한 번의 실행으로 (1) `posts` 표 생성, (2) RLS 켜기, (3) "누구나 읽기(SELECT)" 정책, (4) "누구나 쓰기(INSERT)" 정책, (5) 확인용 샘플 글 2개 넣기까지 끝납니다.
   - **UPDATE·DELETE 정책은 일부러 만들지 않습니다.** 정책이 없는 동작은 자동으로 막히므로, 공개 키로는 글을 고치거나 지울 수 없게 됩니다.

### B. 내 anon(공개) 키 연결하기
3. Supabase 대시보드의 **Settings → API**에서 **Project URL**과 **anon 키**(`sb_publishable_...`로 시작하는 공개 키)를 복사합니다. service_role 키는 절대 복사하지 않습니다.
4. `script.js` 위쪽의 두 자리표시자를 내 값으로 바꿉니다.
   - `SUPABASE_URL` ← 복사한 Project URL
   - `SUPABASE_ANON_KEY` ← 복사한 **anon(공개) 키** (`sb_secret_...`가 아닌지 한 번 더 확인)
   - 값을 안 바꾸면 `isPlaceholder()` 검사가 작동해 "아직 내 프로젝트 값이 입력되지 않았어요"라는 안내가 뜨고 글쓰기 버튼이 비활성화됩니다.

### C. 페이지 열어 글 써 보기
5. `index.html`을 브라우저로 엽니다. (HTML이 CDN으로 `@supabase/supabase-js`를 불러오므로 인터넷 연결이 필요합니다.)
6. 페이지가 열리면 `script.js`가 자동으로 `loadPosts()`를 실행해, `schema.sql`로 넣어 둔 샘플 글이 **최신순으로** 목록에 보입니다. 제목 옆 개수 `(2)`도 함께 채워집니다.
7. **이름**과 **내용**을 적고 **글 올리기**를 누릅니다. "글을 저장하는 중…" → "글이 등록되었어요!" 안내가 차례로 뜨고, 방금 쓴 글이 목록 맨 위에 나타나면 성공입니다. (내용칸만 비워지고 이름은 다음 글을 위해 남습니다.)

> 한 단계 더: 운영자(나)는 글을 어떻게 지우나요? — Supabase 대시보드의 **Table editor**에서 직접 지우거나 고치면 됩니다. 대시보드는 service_role 권한으로 동작해 RLS와 무관하게 다 되기 때문입니다. 코드로 수정·삭제 기능을 붙이려면 로그인(인증)과 "본인 글만 손댈 수 있는" 정책이 필요한데, 그건 다음 실습들에서 다룹니다.

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. 한 단계씩 시키고, 결과가 옳은지(특히 비밀값이 코드 밖에 있는지, 사용자 입력을 textContent로 출력하는지) 직접 확인하세요.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 비전공자를 돕는 웹/DB 멘토야. Supabase로 동작하는 '간단 커뮤니티 게시판'을 만들어 줘.
  기능은 딱 두 가지: (1) 글 작성(INSERT/Create), (2) 글 목록 조회(SELECT/Read).
  수정·삭제는 일부러 넣지 마.
  산출물 3개를 만들어 줘.
  (1) schema.sql:
      - posts 표(id, author 글쓴이, content 내용, created_at 작성시각 자동).
      - 그 표에 RLS(행 수준 보안)를 켜고, 'SELECT는 누구나 허용', 'INSERT는 누구나 허용' 정책만 만들어 줘.
      - UPDATE/DELETE 정책은 만들지 말고, 왜 안 만드는지(정책 없으면 기본 거절이라 공개 키로는 못 고침)
        주석으로 설명해 줘.
  (2) index.html:
      - 이름 입력칸, 내용 textarea, '글 올리기' 버튼, 글 목록 영역, 상태 메시지 자리.
      - Supabase JS 라이브러리를 CDN으로 불러오고, 그 아래에 script.js를 연결해 줘.
  (3) script.js:
      - SUPABASE_URL과 anon(공개) 키 자리표시자(placeholder)를 두고, 거기에 내 값을 넣게 안내 주석을 달아 줘.
      - 폼 제출 시 insert, 페이지 로드 시 select로 최신순 목록을 그려 줘.
  제약: anon 키만 화면에 두고 service_role 키는 절대 코드에 넣지 마.
        그 이유(anon=공개 가능, 보호는 RLS 담당 / service_role=RLS 우회 마스터 키라 서버 전용)를 주석으로 설명해 줘.
  코드만 주지 말고 왜 그렇게 했는지 비전공자가 이해하게 한 줄씩 풀어서 주석으로 적어 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  위 게시판을 이렇게 개선해 줘.
  - 목록을 그릴 때 글쓴이 이름과 내용을 innerHTML이 아니라 반드시 textContent로 넣어 줘.
    (남이 쓴 <script> 같은 코드가 내 화면에서 실행되는 XSS를 막기 위해서야. 왜 그런지 주석으로 설명해 줘.)
  - 작성 시각을 '방금 전 / N분 전 / N시간 전 / N일 전'으로 보여 주는 timeAgo 함수를 추가해 줘.
  - 저장 중에는 버튼을 잠깐 비활성화해서 연타로 같은 글이 두 번 올라가는 걸 막아 줘.
  - 글 개수를 제목 옆에 '(3)'처럼 표시하고, 글이 0개면 '아직 글이 없어요' 안내를 보여 줘.
  - 에러 메시지를 비전공자가 알아듣게 바꿔 주는 도우미를 만들어 줘(예: 'posts 표가 없어요. schema.sql을 먼저 실행하세요.').
  anon 키만 화면에 두고 비밀 키는 코드 밖에 두는 원칙은 계속 지켜 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  Supabase 게시판이 동작하지 않아. 단계별로 원인을 찾아 줘.
  - 증상: (예 - 글을 올려도 목록에 안 나타남 / 콘솔에 빨간 에러)
  - 브라우저 콘솔(F12)에 찍힌 에러 메시지 전문: (여기에 붙여넣기)
  먼저 가장 흔한 원인부터 순서대로 점검해 줘:
  (1) script.js의 SUPABASE_URL / SUPABASE_ANON_KEY가 자리표시자 그대로 아닌지(내 anon 값으로 바꿨는지),
  (2) schema.sql을 SQL Editor에서 실제로 Run 했는지(posts 표가 진짜 있는지),
  (3) RLS는 켰는데 SELECT/INSERT 정책을 안 만들어서 'row-level security' 위반으로 막힌 건 아닌지,
  (4) 혹시 service_role 키를 화면에 넣은 건 아닌지(그러면 즉시 anon 키로 교체).
  고친 부분은 왜 그게 원인이었는지 한 줄씩 풀어서 설명해 줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법
- **목록 자동 표시 확인**: 페이지를 열자마자 `schema.sql`로 넣어 둔 샘플 글 2개가 **최신순**으로 보이고, 제목 옆 개수가 `(2)`로 맞는지 본다.
- **글 작성 확인**: 이름·내용을 채워 올리면 "글이 등록되었어요!"가 뜨고, 방금 쓴 글이 **목록 맨 위**에 즉시 나타나는지 본다.
- **DB에 진짜 저장됐는지 확인**: Supabase 대시보드의 **Table editor → posts**를 열어, 내가 쓴 글이 실제 행(row)으로 들어가 있는지 본다.
- **공개 키로 수정·삭제가 막히는지 확인**: 브라우저 콘솔에서 `db.from("posts").delete().eq("id", 1)`을 실행해 보면, 삭제되지 않는다(정책이 없어 기본 거절). 이것이 RLS가 일하고 있다는 증거다.
- **XSS 방어 확인**: 내용칸에 `<script>alert('x')</script>`나 `<b>굵게</b>`를 넣어 올려 본다. 코드가 실행되거나 굵게 처리되지 않고 **글자 그대로** 보여야 정상이다(textContent로 출력하기 때문).
- **비밀값이 안 들어갔는지 확인**: `script.js`의 `SUPABASE_ANON_KEY`가 `sb_publishable_...`(공개 키)인지, 실수로 `sb_secret_...`(service_role)을 넣지 않았는지 다시 본다.

## 파일 구성
- `schema.sql` — `posts` 표 생성 + RLS 켜기 + SELECT/INSERT 정책 + 확인용 샘플 글. **Supabase SQL Editor에서 가장 먼저 한 번 실행**한다. (UPDATE·DELETE 정책은 일부러 없음.)
- `index.html` — 게시판 화면(뼈대). 글쓰기 폼과 목록 자리만 그리고, 실제 동작은 `script.js`에 맡긴다. Supabase JS 라이브러리를 CDN으로 불러온다.
- `script.js` — 핵심 동작. `SUPABASE_URL`·`SUPABASE_ANON_KEY`(공개 anon 키)를 내 값으로 바꿔 쓴다. `loadPosts()`(SELECT)·`renderPosts()`(textContent로 안전 출력)·폼 `submit`(INSERT)이 들어 있다.
- (참고) `index.html`은 `style.css`를 연결해 두었으니, 스타일을 입히고 싶으면 같은 폴더에 `style.css`를 만들어 꾸미면 된다. 없어도 게시판 동작 자체에는 지장이 없다.
