# 제출 막고 직접 검사 후 에러 모아 보여주기 (preventDefault)

회원가입 폼에서 "가입하기"를 눌렀을 때, 비어 있는 칸이나 형식이 틀린 칸이 있으면 화면 위쪽에 잘못된 항목이 한꺼번에 빨간 박스로 뜨는 것을 본 적이 있을 겁니다. 이 실습에서는 폼의 **제출(submit)을 자바스크립트로 가로채서(preventDefault)** 페이지가 새로고침되지 않게 막고, 모든 칸을 직접 검사한 다음 통과하지 못한 항목을 **에러 배열에 모아 한 번에** 보여주는 패턴을 만들어 봅니다. (실제 가입은 일어나지 않는 화면 연습용 예제입니다.)

## 목표

- `submit` 이벤트를 `addEventListener`로 잡고, `event.preventDefault()`로 **페이지 새로고침을 막는다**.
- 칸마다 `return`으로 멈추지 않고 끝까지 검사해서, 잘못된 항목을 **에러 배열에 모두 모은다(일괄 검증)**.
- 모은 에러를 `createElement`/`appendChild`로 목록(`<li>`)을 만들어 **에러 박스에 한 번에** 보여준다.
- 잘못된 칸에는 빨간 테두리(동적 클래스 `invalid`)를 붙이고, 모든 칸이 통과하면 **성공 메시지**를 보여준다.

## 따라하는 단계

1. `100` 폴더 안의 `index.html` 파일을 마우스로 더블클릭해 브라우저(크롬 등)로 엽니다. 이름·이메일·비밀번호·비밀번호 확인 입력칸과 약관 동의 체크박스, "가입하기" 버튼이 보입니다.
2. 아무것도 입력하지 않은 채 바로 "가입하기"를 눌러 봅니다. 화면이 **새로고침되지 않고**, 위쪽에 빨간 박스가 뜨며 "이름을 입력해 주세요", "이메일을 입력해 주세요" 등 잘못된 항목이 **한꺼번에** 나오면 1차 성공입니다. (잘못된 칸은 빨간 테두리로도 표시됩니다.)
3. 이메일 칸에 `abc`처럼 `@`가 없는 글자를 넣고 다시 제출합니다. "이메일 형식이 올바르지 않습니다" 메시지가 뜨는지 봅니다.
4. 비밀번호에 `1234`(8자 미만)를 넣고, 비밀번호 확인에는 다른 값을 넣어 제출합니다. "비밀번호는 8자 이상", "비밀번호 확인이 일치하지 않습니다"가 동시에 뜨는지 확인합니다. 여러 문제가 **동시에 모여서** 나오는 것이 이 실습의 핵심입니다.
5. 이제 올바르게 채웁니다: 이름 `홍길동`, 이메일 `you@example.com`, 비밀번호 `abcd1234`, 비밀번호 확인도 똑같이 `abcd1234`, 약관 동의 체크. 제출하면 빨간 박스가 사라지고 초록색 "가입 정보가 모두 올바릅니다" 메시지가 뜨면 성공입니다.
6. (코드 읽기) `script.js`의 `handleSubmit` 함수를 천천히 읽어 보세요. (1) `preventDefault()` → (2) 이전 에러 지우기 → (3) 칸마다 검사해서 `errors` 배열에 `push` → (4) 에러가 있으면 목록으로 만들어 보여주고, 없으면 성공 처리. 이렇게 단계가 나뉘어 있는 것이 핵심입니다.
7. (응용) 비밀번호 조건을 "숫자를 반드시 포함"으로 더 엄격하게 바꾸거나, 새 입력칸(예: 전화번호)을 추가하고 그에 맞는 검사 한 줄을 `handleSubmit` 안에 더해 보세요.

## 검증법

- **새로고침이 안 됨**: 잘못된 상태로 제출했을 때 주소창이 깜빡이며 페이지가 다시 로드되지 않아야 합니다. (그러면 `preventDefault()`가 잘 걸린 것입니다.) 만약 화면이 새로고침된다면 `event.preventDefault()`가 빠졌거나 함수가 연결 안 된 것입니다.
- **에러가 모여서 나옴**: 빈 폼을 제출했을 때 에러가 하나씩이 아니라 잘못된 항목 **여러 개가 한 번에** 목록으로 떠야 합니다. (칸마다 `return`으로 멈추지 않고 끝까지 검사했다는 증거입니다.)
- **빨간 테두리 일치**: 에러 메시지에 나온 칸만 정확히 빨간 테두리로 바뀌어야 합니다. 고친 뒤 다시 제출하면 그 칸의 빨간 테두리가 사라져야 합니다.
- **성공 전환**: 모든 칸을 올바르게 채워 제출하면 빨간 박스가 사라지고 초록 성공 메시지로 바뀌어야 합니다.
- 브라우저 개발자 도구(F12)의 콘솔에 빨간 오류 메시지가 없으면 코드가 깨진 곳 없이 잘 작동하는 것입니다.

> 참고: 이 검증은 사용자에게 친절하게 안내하는 **화면 쪽(클라이언트) 검사**일 뿐입니다. 화면 쪽 검사는 마음만 먹으면 우회할 수 있으므로, 진짜 서비스에서는 입력값을 서버(예: Supabase)로 보내 **서버에서 한 번 더** 검사해야 합니다. 또한 비밀번호 같은 비밀값은 화면 코드(JS)에 절대 적어 두지 않습니다. (공개되는 anon 키와 비밀인 service_role 키를 구분하는 것과 같은 원리입니다.)
