# 실습 153 — 공개 날씨 API로 도시 이름 넣어 오늘 날씨 표시하기

도시 이름을 입력하면, 그 도시의 **오늘 현재 날씨**(기온·날씨 상태·아이콘)를
한 장짜리 위젯으로 보여 주는 페이지입니다. **API 키(열쇠) 없이** 누구나 쓸 수 있는
공개 날씨 API(Open-Meteo)를 사용합니다.

> 비유: 날씨 API는 **도시 이름이 아니라 '좌표(위도·경도)'로만 날씨를 알려주는 안내소**입니다.
> 그래서 먼저 "부산은 지도에서 어디?"를 물어 **좌표**를 받고(=1단계),
> 그 좌표로 다시 "거기 지금 날씨 알려줘"를 요청합니다(=2단계).
> 그리고 안내소는 날씨 상태를 **숫자 코드**(예: `0`=맑음, `61`=비)로 주기 때문에,
> 우리가 그 숫자를 **한국어 + 이모지**로 바꿔서 보여줘야 합니다.
> 이번 실습의 한 줄 핵심은 **"공개 엔드포인트를 두 번 연결해서 부르고, 응답 속 숫자 코드를 사람이 읽을 날씨로 매핑하기"** 입니다.

## 목표
- **API 키 없이 쓰는 공개 엔드포인트**가 무엇인지 체감한다. (코드에 비밀값이 전혀 없다)
- 두 단계로 이어지는 **호출 연쇄**를 익힌다: ① 도시 이름 → 좌표(지오코딩) → ② 좌표 → 날씨.
- 한글·공백이 들어간 도시 이름을 **URL에 안전하게 끼워 넣는** 법을 익힌다.
  - `new URLSearchParams()` + `params.set("name", 도시이름)` = 키·값을 넣으면 **인코딩(안전 변환)을 자동**으로 해 준다. (한글 `부산` → `%EB%B6%80%EC%82%B0`)
- **응답 필드 매핑**을 익힌다: API가 준 JSON의 어느 칸(`temperature_2m`, `weather_code` 등)을 화면 어느 자리에 연결할지 짝지어 본다.
- API가 준 **숫자 코드(WMO 코드)**를 미리 만든 표(`WEATHER_CODE`)로 **한국어 설명 + 이모지**로 바꾸는 패턴을 익힌다.

> 실습 152와의 차이: 152는 "**사용자 입력을 한 번의 검색 요청에 안전하게 합치기**"가 핵심이었고,
> 153은 거기에 더해 "**요청을 두 번 연결(좌표→날씨)하고, 응답 속 숫자 코드를 한국어 날씨로 매핑하기**"가 핵심입니다.

## 따라하는 단계
1. 이 폴더의 `index.html`을 더블클릭 → 브라우저에서 열린다. (인터넷 연결 필요)
2. 검색창에 미리 `부산`이 들어 있고, 페이지가 열리자마자 한 번 검색되어 **오늘 부산 날씨 카드**가 보인다.
3. 검색창에 `서울`을 넣고 `날씨 보기` 버튼(또는 Enter)을 누른다 → 기온·날씨 상태·아이콘이 바뀐다.
4. 검색창 아래의 **검은 주소 칸 두 개**를 본다 → ①번에는 "도시→좌표 찾기" 주소가, ②번에는 "좌표→날씨 받기" 주소가 보인다. **요청이 두 번** 일어났다는 뜻이다.
5. 한글 도시(`부산`)를 넣으면 ①번 주소에서 한글이 `%EB%B6%80...` 같은 **안전 코드로 바뀐 모습**을 확인한다 → 이것이 `URLSearchParams`가 자동으로 해 준 인코딩이다.
6. `script.js`에서 `findCity(cityName)`(1단계)와 `getWeather(lat, lon)`(2단계) 두 함수를 찾는다 → **두 번의 요청을 연결하는** 핵심이다.
7. 같은 파일 위쪽 `WEATHER_CODE` 표를 본다 → API가 주는 **숫자 코드를 한국어+이모지로 바꾸는 매핑표**다. `describeWeather(code)`가 이 표를 사용한다.
8. `showWeather()` 함수 안에서 `document.getElementById("temp").textContent = ...` 부분을 본다 → **응답 필드를 화면 자리에 연결(매핑)** 하는 부분이다.
9. AI에게 시켜 보기:
   > "이 `script.js`에서 오늘 날씨뿐 아니라 **앞으로 3일 예보**도 같이 보여주게 바꿔줘. Open-Meteo `forecast`의 `daily=weather_code,temperature_2m_max,temperature_2m_min`을 추가로 요청하고, 카드 아래에 날짜별 최고/최저 기온과 아이콘을 한 줄씩 표시해줘."

## 검증법
- 페이지를 열면 **자동으로 부산 날씨**가 뜨는가? (기온·날씨 글자·이모지가 모두 채워졌는가)
- `서울`, `Tokyo`, `Paris` 등 다른 도시를 넣으면 결과가 바뀌는가?
- 검은 주소 칸 **두 개**가 모두 채워지는가? (요청이 ① 좌표 찾기 → ② 날씨 받기 순서로 두 번 일어남)
- 한글 도시명을 넣었을 때 ①번 주소에서 한글이 `%`로 시작하는 **안전 코드**로 바뀌어 보이는가?
- 없는 도시명(예: `asdfqwer`)을 넣으면 **"도시를 찾지 못했어요"** 안내가 뜨고, ②번 요청은 일어나지 않는가? (②번 주소 칸에 "좌표를 못 찾아 요청 안 함"이 보임)
- `F12`(개발자 도구) → **Network 탭**을 켜고 검색하면, `search`(지오코딩)와 `forecast`(날씨) **두 요청**이 차례로 보이는가?
- Network 탭에서 `forecast` 응답을 열어 `current.weather_code` 숫자를 확인하고, 화면의 **한국어 날씨 설명**과 표(`WEATHER_CODE`)대로 일치하는지 확인한다.

## 공개 API와 비밀값 — 보안 메모
이 실습이 쓰는 **Open-Meteo**(`open-meteo.com`)는 **누구나 열쇠(API 키) 없이** 부를 수 있는 **공개 API**입니다.
그래서 이 코드에는 **넣을 비밀값이 아예 없습니다.** 브라우저 코드는 누구나 들여다볼 수 있으니, 비밀값이 없다는 점이 안전합니다.

나중에 **키가 필요한** 날씨 API(예: OpenWeatherMap)를 쓰게 되면, 값의 성격을 반드시 구분해야 합니다.

- **공개되어도 되는 값**(예: Supabase의 `anon`(공개) 키): 브라우저 코드에 들어가도 괜찮습니다. 단, 데이터 보호는 **RLS(행 수준 보안)** 가 책임집니다.
- **절대 노출하면 안 되는 비밀값**(예: Supabase의 `service_role` 키, 유료 날씨 API 키): **브라우저 코드에 절대 넣지 않습니다.** 비밀값은 서버(또는 n8n 같은 자동화 도구의 자격 증명 저장소)에서만 다룹니다.
- 키가 있는 API를 예제로 적을 때는, 코드에 진짜 키 대신 `YOUR_API_KEY` 같은 **자리표시자**만 두는 것이 원칙입니다.

```js
// 키가 필요한 API를 '브라우저에서 직접' 부르는 것은 키 노출 위험이 있습니다.
// 예시로 적을 때조차 진짜 키는 넣지 말고 자리표시자만 둡니다.
const WEATHER_API_KEY = "YOUR_API_KEY"; // ← 자리표시자. 실제 비밀키는 절대 코드에 넣지 않는다.
// 실제로는 이런 비밀키 호출은 서버(또는 n8n)에서 처리하고, 브라우저는 그 서버를 부릅니다.
```
