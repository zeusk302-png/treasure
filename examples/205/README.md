# 내 정적 사이트 문의 폼 제출 → 슬랙/메일 알림 받기

앞 실습들에서는 n8n 안에서 버튼을 눌러(또는 정해진 시간에) 자동화를 실행했습니다. 이번에는 한 단계 더 나아가, **내가 만든 진짜 웹사이트(문의 폼)** 가 자동화를 깨우게 만듭니다.

흐름은 이렇습니다. 방문자가 사이트의 문의 폼에 이름·이메일·내용을 적고 `보내기`를 누르면 → 브라우저의 JavaScript(`fetch`)가 그 내용을 n8n의 **Webhook 주소**로 보냅니다 → n8n이 받아서 보기 좋게 정리한 뒤 **슬랙(또는 메일)으로 알림**을 띄웁니다. "내 사이트에 누가 연락하면, 내가 바로 알림을 받는다"는, 실무에서 가장 많이 쓰는 자동화 패턴입니다.

> **이 폴더에는 두 덩어리가 들어 있습니다.**
> - **사이트:** `index.html` + `style.css` + `script.js` — Vercel에 올릴 문의 폼 페이지
> - **워크플로우:** `workflow.json` — n8n에 불러올 자동화 (노드 4개)
>
> 워크플로우 흐름: `문의 받기 (Webhook)` → `문의 내용 정리하기 (Set)` → ┃ `슬랙으로 알림 보내기 (Slack)` ┃ + ┃ `폼에 응답 돌려주기 (Respond to Webhook)` ┃
>
> 비유하자면: ① 우체통이 편지를 받고(Webhook) → ② 내용을 깔끔히 옮겨 적은 뒤(Set) → ③ 한 장은 단체방에 붙이고(Slack), 한 장은 "잘 받았어요" 영수증으로 보낸 사람에게 돌려줍니다(Respond).

## 목표

- 정적 사이트(HTML/JS)에서 `fetch`로 외부 자동화(n8n Webhook)에 데이터를 **보내는(POST)** 법을 익힌다.
- n8n Webhook이 받은 폼 데이터를 정리해 **슬랙(또는 메일)으로 알림을 보내는** '폼 제출 → 알림' 자동화를 완성한다.
- 어떤 값이 **공개돼도 되는 값(Webhook 주소)** 이고 어떤 값이 **절대 새면 안 되는 비밀값(슬랙 토큰)** 인지 구분하는 보안 감각을 기른다.

## 따라하는 단계

1. **n8n에 워크플로우 먼저 올리기.** n8n에 로그인한 뒤, 오른쪽 위 `...`(점 3개) → **`Import from File`** 로 이 폴더의 **`workflow.json`** 을 불러옵니다. 노드 4개가 나타납니다.
2. **슬랙 봇과 자격증명 연결하기.** `슬랙으로 알림 보내기 (Slack)` 노드를 더블클릭합니다.
   - 슬랙 앱 관리 페이지(`api.slack.com/apps`)에서 `Create New App → From scratch` 로 봇을 만들고, `OAuth & Permissions`에서 **`chat:write`** 권한을 추가한 뒤 `Install to Workspace` 로 설치하면 **`Bot User OAuth Token`(`xoxb-`로 시작)** 이 발급됩니다. 이게 비밀값입니다.
   - 노드의 **`Credential to connect with`** 에서 `Create New Credential` 을 눌러 이 `xoxb-` 토큰을 붙여 넣고 저장합니다. **토큰은 이 자격증명 금고에만 저장되고 `workflow.json`에는 들어가지 않습니다.**
   - **`Channel`** 에서 알림을 받을 채널(예: `#문의알림`)을 고릅니다. (파일에는 가짜 ID `C0000000000` 자리표시자가 들어 있으니 반드시 내 채널로 다시 고릅니다.) 그 채널에 봇을 `/invite @봇이름` 으로 초대하는 것도 잊지 마세요.
   - (메일로 받고 싶다면 이 Slack 노드를 지우고 `Send Email`(SMTP) 노드를 같은 자리에 끼워, 받는 주소를 적고 본문을 `{{ $json.슬랙알림문구 }}` 로 연결하면 됩니다. 통로만 바꾸는 것입니다.)
3. **Webhook 주소 복사하기.** `문의 받기 (Webhook)` 노드를 클릭하면 두 가지 주소가 보입니다. `Test URL`(테스트용)과 `Production URL`(실제 운영용)입니다. 일단 테스트를 위해 캔버스 아래 **`Listen for test event`** 버튼을 누르고, 보이는 **Test URL을 복사**해 둡니다.
4. **사이트에 Webhook 주소 붙여넣기.** `script.js` 파일을 열어 맨 위의
   ```js
   const WEBHOOK_URL = "REPLACE_WITH_YOUR_N8N_WEBHOOK_URL";
   ```
   부분에서 따옴표 안을 방금 복사한 주소로 바꿉니다.
5. **로컬에서 먼저 테스트.** 이 폴더에서 `index.html` 을 브라우저로 열어(또는 VS Code의 Live Server로 띄워) 폼을 채우고 `보내기`를 누릅니다. 폼 아래에 "정상적으로 접수되었습니다" 가 뜨고, **슬랙 채널에 알림이 올라오면 성공**입니다.
6. **운영용으로 전환.** 잘 되면 n8n 워크플로우 오른쪽 위 **`Active`(활성) 토글을 켭니다.** 그러면 `Test URL` 대신 항상 살아 있는 `Production URL`(`/webhook/contact-form`)이 동작합니다. `script.js`의 `WEBHOOK_URL` 을 이 **Production URL** 로 바꿔 줍니다.
7. **Vercel에 배포.** 이 폴더(또는 사이트 파일들)를 GitHub에 올리고 Vercel로 배포하면, 인터넷 어디서든 접속 가능한 진짜 문의 폼이 완성됩니다.

## 🤖 바이브코딩 프롬프트

이 실습(문의 폼 → fetch → n8n Webhook → 슬랙 알림)을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. n8n 워크플로우는 화면에서 노드를 끼워야 하므로, AI에게는 주로 **사이트(폼) 쪽 코드**와 **흐름 설계 점검**을 시키면 좋습니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 프런트엔드 멘토야. 정적 사이트용 '문의 폼' 한 페이지를 만들어 줘.
  - 파일은 index.html, style.css, script.js 세 개로 분리.
  - 입력칸: 이름(필수, 2자 이상), 이메일(type=email, 필수), 문의 내용(필수, 5자 이상), 보내기 버튼.
  - 제출하면 페이지 새로고침 없이 JavaScript fetch로 POST 요청을 보내고,
    응답 결과(성공/실패)를 폼 아래에 색깔 있는 상태 메시지로 보여 줘.
  - 보내는 주소는 const WEBHOOK_URL 변수로 파일 맨 위에 두고,
    지금은 "REPLACE_WITH_YOUR_N8N_WEBHOOK_URL" 자리표시자로 둬(실제 비밀 아님).
  - 비전공자도 읽도록 한국어 주석을 달고, 왜 그렇게 했는지(예: 새로고침을 막는 이유)도 주석으로 설명해 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 문의 폼을 다음처럼 다듬어 줘.
  - 보내는 동안 버튼을 잠그고(disabled) "보내는 중..." 표시, 끝나면 다시 풀기.
  - 성공하면 폼을 비우고(form.reset) 초록색 성공 메시지, 실패하면 빨간색 메시지.
  - 보안: 상태 메시지는 innerHTML 말고 textContent로 출력해(사용자 입력에 섞인 <script> 실행 방지, XSS 예방).
  - 그리고 이 흐름을 n8n으로 받을 때 노드 구성을 글로 설계해 줘:
    Webhook(받기) → Set(이름·이메일·내용·시각 정리) → Slack(알림) + Respond to Webhook(영수증).
    어떤 값이 공개해도 되는 값이고(웹훅 주소) 어떤 값이 비밀인지(슬랙 토큰)도 알려 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  문의 폼을 제출했는데 동작이 이상해. 비전공자도 알게 원인을 단계별로 짚어 줘.
  - 증상: (예) 폼에 빨간 "전송에 실패했습니다"가 뜬다 / 폼은 성공인데 슬랙이 안 온다 / 콘솔에 CORS 에러.
  - 브라우저 콘솔 에러: <여기에 붙여넣기>
  - script.js의 WEBHOOK_URL: <현재 값 붙여넣기>
  점검 순서: ① 주소가 자리표시자 그대로인지 ② n8n이 테스트 모드면 Listen for test event를 눌렀는지/운영이면 Active를 켰는지
  ③ 슬랙 봇을 채널에 초대했는지(not_in_channel)·chat:write 권한이 있는지(missing_scope) ④ Webhook의 Allowed Origins가 * 인지.
  한 번에 하나씩, 무엇을 확인하고 어떻게 고치는지 알려 줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다.

## 검증법

1. **로컬 폼 제출 → 알림 도착(가장 확실한 증거):** `index.html`에서 폼을 제출한 직후 **슬랙 채널**을 봅니다. 아래 같은 알림이 봇 이름으로 올라오면 끝까지 성공입니다.
   ```
   📧 새 문의가 도착했습니다

   이름: 홍길동
   이메일: hong@example.com
   내용: 강의 일정이 궁금합니다.

   받은 시각: 2026-06-18 14:30
   ```
2. **n8n 실행 기록 확인:** n8n의 `Executions`(실행) 탭에 방금 제출이 초록색으로 기록되고, 4개 노드(Webhook → Set → Slack / Respond)에 모두 체크가 떠 있는지 봅니다.
3. **폼 화면 응답 확인:** 폼 아래 상태 메시지가 초록색 "정상적으로 접수되었습니다" 로 바뀌고 입력칸이 비워지면, `Respond to Webhook`이 영수증을 잘 돌려준 것입니다.
4. **흔한 실패 세 가지:**
   - 폼에 빨간 "전송에 실패했습니다" → `script.js`의 `WEBHOOK_URL`이 자리표시자 그대로이거나, n8n에서 **`Listen for test event`** 를 안 눌렀거나(테스트 모드), `Active`를 안 켰을(운영 모드) 때입니다.
   - 폼은 성공인데 슬랙이 안 옴 → 봇을 채널에 `/invite` 하지 않았거나(`not_in_channel`), `chat:write` 권한이 없을(`missing_scope`) 때입니다.
   - 브라우저 콘솔에 `CORS` 에러 → Webhook 노드의 `Options`에서 `Allowed Origins`가 `*`(또는 내 사이트 주소)로 돼 있는지 확인하세요. 이 파일에는 `*`로 넣어 두었습니다.

## 보안 — 어떤 값이 공개고, 어떤 값이 비밀인가

이 실습에는 성격이 완전히 다른 두 값이 나옵니다. 이 구분이 이번 실습의 핵심입니다.

- **공개돼도 되는 값 — Webhook 주소(`script.js`에 그대로 적음):** Webhook URL은 누구나 볼 수 있는 '받는 창구'입니다. 브라우저에 들어가는 코드라서 어차피 숨길 수도 없습니다. 주소를 안다고 해서 남이 내 슬랙에 직접 글을 쓸 수는 없으므로(슬랙 토큰은 n8n 안에만 있으니까) 사이트 코드에 그대로 적습니다. 성격상 Supabase의 **`anon`(공개) 키**와 같습니다 — 브라우저에 노출돼도 되는 값.
- **절대 새면 안 되는 비밀값 — 슬랙 봇 토큰(`xoxb-...`, n8n 금고에만):** 이 토큰을 가진 사람은 누구든 내 워크스페이스에 봇 이름으로 글을 쓸 수 있습니다. 그래서 사이트 코드나 `workflow.json`에 **절대** 적지 않고, n8n의 **`Credentials`(자격증명) 금고**에만 저장합니다. 성격상 Supabase의 **`service_role`(비밀) 키**와 같은 급으로 다뤄야 합니다 — 서버(여기선 n8n) 안에만 두는 값.

> **그래서 이 파일들의 비밀 자리에는 자리표시자만 들어 있습니다.** `script.js`의 주소는 `REPLACE_WITH_YOUR_N8N_WEBHOOK_URL`, `workflow.json`의 자격증명 id는 `REPLACE_WITH_YOUR_SLACK_CREDENTIAL_ID`, 채널은 가짜 ID `C0000000000`입니다. 진짜 `xoxb-` 토큰을 사이트 코드나 파일 본문에 직접 적는 일은 **절대 하지 마세요.**

> **한 줄 원칙:** 받는 창구 주소(Webhook URL)는 브라우저 코드에 공개해도 되지만, 슬랙 토큰 같은 진짜 비밀은 n8n 금고(서버) 안에만 둔다.

## 핵심만 짚기 (디렉터 관점)

- **'무엇이 깨우는가'와 '무엇을 하는가'는 분리된 부품입니다.** 이번엔 사이트 폼(Webhook)이 깨우고, 알림(Slack)이 일을 합니다. 통로를 메일로 바꾸거나, 다음 실습(206)처럼 구글 시트 저장을 한 갈래 더 붙여도 구조는 그대로입니다.
- **응답(Respond)을 돌려주는 습관.** 폼은 "보냈는데 됐나?"를 알아야 하므로, `Respond to Webhook`으로 "잘 받았다"는 영수증을 돌려줍니다. 그래야 사용자에게 성공/실패를 보여 줄 수 있습니다.
