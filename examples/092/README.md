# 이메일 형식·글자 수 제한 검증 (type·minlength·maxlength)

입력값의 "형식"과 "글자 수"를 JavaScript 없이 HTML 속성만으로 검사하는 실습입니다. `type="email"`로 이메일 형식을, `minlength`/`maxlength`로 최소·최대 글자 수를 브라우저가 알아서 검사하고 안내 풍선을 띄워줍니다.

## 목표

- `type="email"`을 쓰면 `@`가 없거나 형식이 어색한 값을 브라우저가 막아준다는 것을 직접 확인한다.
- `minlength`(최소 글자 수)와 `maxlength`(최대 글자 수)의 차이를 눈으로 비교한다. (특히 `maxlength`는 제출을 막는 게 아니라 입력 자체를 막는다는 점)
- "코드로 검사하기 전에 브라우저가 먼저 막아주는" HTML 기본 검증(HTML5 validation)을 한 단계 더 깊이 익힌다.

## 따라하는 단계

1. `index.html` 파일을 더블클릭해서 웹 브라우저로 엽니다. (별도 설치나 서버가 필요 없습니다.)
2. 이메일 칸에 `abc`처럼 `@`가 없는 값을 넣고 파란색 **가입하기** 버튼을 눌러봅니다. "이메일 주소에 '@'를 포함해 주세요" 같은 안내가 뜨고 제출이 막힙니다. 이것이 `type="email"`의 효과입니다.
3. 이메일을 `me@test.com`처럼 올바르게 고치면 칸 테두리가 초록색으로 바뀝니다.
4. 아이디 칸에 `ab`(2글자)만 넣고 눌러봅니다. "최소 4자 이상 입력하세요" 류의 안내가 뜹니다. 이것이 `minlength="4"`입니다.
5. 아이디 칸에 글자를 계속 쳐서 13글자째를 입력해봅니다. **더 이상 타이핑되지 않습니다.** 이것이 `maxlength="12"`입니다. (`minlength`는 "제출할 때" 검사하지만, `maxlength`는 "치는 순간" 막습니다.)
6. 비밀번호 칸에 7글자만 넣고 눌러봅니다. `minlength="8"`이라 막힙니다. 8글자 이상으로 채웁니다.
7. 이메일(올바른 형식) + 아이디(4~12자) + 비밀번호(8자 이상) 세 칸을 모두 올바르게 채우고 버튼을 누르면 "가입 완료!" 초록 메시지가 나타납니다.
8. `index.html`을 열어 이메일 input의 `type="email"`을 `type="text"`로 바꾼 뒤 저장하고 새로고침해, `@` 없는 값도 통과되는 것을 확인해봅니다. (확인 후 다시 `type="email"`로 되돌려 두세요.)

## 검증법

- 이메일 칸에 `@`가 없는 값을 넣으면 제출이 막히고 형식 안내 풍선이 뜬다 → `type="email"`이 작동하는 것입니다.
- 아이디를 3글자 이하로 넣고 제출하면 "최소 글자 수" 안내가 뜬다 → `minlength`가 작동하는 것입니다.
- 아이디 칸에 13글자째가 입력되지 않는다 → `maxlength`가 입력을 막는 것입니다.
- 세 칸(이메일 형식 OK / 아이디 4~12자 / 비밀번호 8자 이상)을 모두 만족하면 초록색 "가입 완료!" 메시지가 보인다.

## 핵심 정리

- `type="email"`은 `<input>`의 종류를 이메일로 지정해, 브라우저가 `@`를 포함한 형식인지 자동으로 검사하게 합니다. (모바일에서는 `@` 키가 있는 키패드가 뜨는 보너스도 있습니다.)
- `minlength`와 `maxlength`는 값(숫자)을 적는 속성입니다: `minlength="4" maxlength="12"`처럼 씁니다.
  - `minlength`: 제출(submit) 시점에 "너무 짧다"고 막습니다.
  - `maxlength`: 타이핑하는 순간 그 길이를 넘지 못하게 입력 자체를 막습니다.
- 이 검사는 **사용자 편의를 위한 1차 방어선**일 뿐입니다. 사용자가 개발자 도구로 속성을 지우거나 직접 데이터를 보내면 우회할 수 있습니다. 실제 서비스에서는 데이터를 받는 서버(예: Supabase) 쪽에서도 반드시 다시 검사해야 합니다. 브라우저 검증만으로 보안이 끝나지 않는다는 점을 기억하세요.
