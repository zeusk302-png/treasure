# 글자 한 줄 고치고 git push로 자동 재배포 확인하기

지난 실습(`examples/169`)에서 GitHub 저장소를 Vercel에 한 번 연결해 `https://프로젝트이름.vercel.app` 주소를 받았습니다. 이번에는 그 효과를 직접 체험합니다. **코드에서 글자 한 줄(`v1` → `v2`)만 고치고 GitHub에 올리면**, 내가 Vercel 대시보드를 건드리지 않아도 **Vercel이 알아서 다시 빌드하고 배포**합니다. 이 "고치기 → 올리기 → 자동 배포"가 이어지는 컨베이어 벨트를 **파이프라인(pipeline)** 이라고 부르는데, 이번 실습의 목표는 그 벨트가 도는 모습을 처음부터 끝까지 눈으로 따라가 보는 것입니다.

> 비전공자 눈높이 한 줄 요약: **GitHub = 코드 창고**, **Vercel = 창고를 지켜보다가 새 물건이 들어오면 자동으로 진열하는 직원**. `git push`는 "창고에 새 버전을 넣었어요"라고 알리는 행동이고, 그 순간 직원(Vercel)이 알아서 사이트를 새로 깔아 줍니다.

## 목표

- `index.html`의 **배포 버전 글자 한 줄**(`v1` → `v2`)을 고친다.
- 그 변경을 **GitHub에 올린다**(`git push`, 또는 GitHub 웹에서 *Commit changes*).
- Vercel **Deployments** 탭에 **새 배포 줄이 자동으로 생기는 것**을 확인한다.
- 같은 `.vercel.app` 주소를 새로고침해서 **바뀐 글자가 반영된 것**을 두 눈으로 본다.
- "내가 배포 버튼을 누른 적이 없는데도 사이트가 바뀐다"는 자동배포 파이프라인을 체감한다.

## 준비물 (이번 실습 전에 끝나 있어야 함)

1. `examples/169`을 끝내서, 내 GitHub 저장소가 **Vercel에 연결(Connected)** 되어 있고 `프로젝트이름.vercel.app` 주소가 살아 있어야 합니다.
2. 이 폴더(`examples/170/`)의 `index.html`, `style.css`(선택적으로 `vercel.json`)가 그 **GitHub 저장소에 올라가 있어야** 합니다. 아직이라면 먼저 세 파일을 저장소 루트에 올리고 한 번 배포해 둡니다.

> 보안 메모: 이 실습 파일에는 **비밀값(비밀번호·API 키·토큰)이 하나도 없습니다.** 정적 페이지라 누구에게 공개돼도 안전하므로 `git push`로 GitHub에 그대로 올려도 됩니다. 나중에 Supabase 같은 걸 붙이게 되면, **공개해도 되는 `anon`(공개) 키**는 프런트엔드 코드에 둬도 되지만(단, 반드시 **RLS = Row Level Security**를 켜서 테이블 접근을 제한해야 합니다), **`service_role`(비밀) 키는 절대 코드/GitHub에 올리면 안 됩니다.** `service_role`은 RLS를 무시하고 모든 데이터를 다룰 수 있는 마스터 키라서, 노출되면 데이터 전체가 위험해집니다. 그런 **비밀값은 코드 파일이 아니라 Vercel 대시보드 → Settings → Environment Variables**에 `자리표시자`처럼 넣어 관리합니다. (예: `SUPABASE_SERVICE_ROLE_KEY = <여기에_실제_비밀키_절대_커밋_금지>`)

## 따라하는 단계

아래는 두 가지 방법입니다. **A) GitHub 웹사이트에서 마우스로** 고치는 쉬운 방법과, **B) 내 컴퓨터에서 git 명령으로** 올리는 방법입니다. 둘 중 편한 쪽을 고르세요. (결과는 똑같이 자동 재배포됩니다.)

### 방법 A — GitHub 웹에서 고치기 (명령어 없이, 가장 쉬움)

1. GitHub에서 내 저장소를 열고 `index.html` 파일을 클릭합니다.
2. 파일 오른쪽 위 **연필(✏️ Edit this file)** 아이콘을 누릅니다.
3. 본문에서 다음 줄을 찾습니다.
   - 찾을 글자: `<p class="version">배포 버전: v1 (아직 수정 전)</p>`
   - 이렇게 바꿉니다: `<p class="version">배포 버전: v2 (git push 자동배포 성공)</p>`
   - 핵심은 **`v1` → `v2`** 한 군데입니다. (괄호 안 문구는 자유롭게 바꿔도 됩니다.)
4. 페이지 위쪽 초록색 **Commit changes...** 버튼을 누릅니다.
5. 커밋 메시지(예: `버전 글자 v1→v2 수정`)를 적고 **Commit changes**를 한 번 더 눌러 확정합니다. → 이 순간이 "창고에 새 버전을 넣은" 시점입니다.

### 방법 B — 내 컴퓨터에서 git push로 올리기

1. 저장소를 받아 둔 폴더에서 `index.html`을 편집기로 엽니다.
2. `배포 버전: v1 (아직 수정 전)` 부분에서 **`v1`을 `v2`로** 바꾸고 저장합니다.
3. 터미널에서 아래 명령을 순서대로 실행합니다. (한 줄씩 입력)
   ```bash
   git add index.html
   git commit -m "버전 글자 v1→v2 수정"
   git push
   ```
   - `git add`: 바뀐 파일을 "올릴 목록"에 담기
   - `git commit`: 변경 내용을 한 묶음으로 기록하기 (메시지는 나중에 알아보기 쉽게)
   - `git push`: GitHub 창고로 실제로 올려 보내기 → **이 순간 Vercel이 변경을 감지합니다.**

### 공통 — 자동 재배포 지켜보기 (방법 A/B 끝난 뒤)

6. Vercel 대시보드에서 내 프로젝트를 클릭하고 **Deployments** 탭으로 갑니다.
7. **맨 위에 방금 만든 커밋 메시지(예: "버전 글자 v1→v2 수정")가 적힌 새 배포 줄이 자동으로 생깁니다.** 상태가 잠깐 **Building**(빌드 중)이었다가 **Ready**(초록)로 바뀝니다. — 내가 Deploy 버튼을 누르지 않았는데도 시작된다는 점이 핵심입니다.
8. 상태가 **Ready**가 되면, 같은 `https://프로젝트이름.vercel.app` 주소를 **새 탭에서 새로고침**합니다.
9. 화면의 "배포 버전" 글자가 **v2**로 바뀌어 있으면 자동배포 파이프라인이 정상 작동한 것입니다. 🎉

> 자주 막히는 곳: ① 새로고침해도 글자가 그대로면 **브라우저 캐시** 때문일 수 있습니다 → `Ctrl/Cmd + Shift + R`로 강력 새로고침 하거나, Deployments에서 상태가 **Ready**인지 먼저 확인하세요. ② 배포 줄이 안 생기면 보통 **다른 브랜치에 push**했거나(보통 `main`/`master`가 배포 대상), 저장소가 Vercel과 **연결이 끊긴** 경우입니다 → Settings → Git에서 **Connected**인지 확인하세요. ③ 상태가 빨간 **Error**면 그 줄을 눌러 **빌드 로그**에서 원인을 봅니다(정적 HTML이라 보통은 에러가 거의 없습니다).

## 🤖 바이브코딩 프롬프트

이 실습(글자 한 줄 고치고 `git push`로 자동 재배포 확인하기)을 AI에게 시켜 만들거나, 막혔을 때 진단을 부탁할 때 그대로 복사해 쓸 수 있는 프롬프트입니다. AI에게 시킬 때는 **내 상황(정적 HTML, Vercel에 GitHub 연결됨)**을 함께 알려줘야 정확한 답이 나옵니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 웹 입문자를 돕는 멘토야. 비전공자가 "git push 자동 재배포"를 눈으로 확인할 수 있는
  아주 단순한 정적 페이지 한 장(index.html + style.css)을 만들어줘.
  요구사항:
  - 화면 가운데 카드 안에 "배포 버전: v1 (아직 수정 전)" 이라는 문구를 눈에 잘 띄게 보여줄 것
  - 이 문구의 'v1'을 'v2'로 바꿔서 push 하면 자동 재배포된 걸 확인하는 게 목적임을 안내 문구로 넣을 것
  - 비밀값(API 키/토큰/비밀번호)은 절대 코드에 넣지 말 것(정적 페이지라 필요 없음)
  - HTML/CSS만 사용, 외부 라이브러리 없이
  결과 코드와 함께, 비전공자가 어디를 고쳐야 하는지(어느 줄의 v1) 한 줄로 짚어줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 페이지에 이어서 개선해줘.
  - 현재 배포 버전 글자를 더 눈에 띄게(배지 모양 pill 스타일로) 바꿔줘
  - "이렇게 따라하세요" 순서를 1~5번 목록으로 화면에도 보여줘
    (v1을 v2로 고치기 → git push → Vercel Deployments에 새 줄 생김 → Ready 되면 새로고침 → v2 확인)
  - .html 주소가 깔끔하게 보이도록 Vercel 설정 파일(vercel.json)에 cleanUrls 옵션도 추가해줘.
    단, 이 파일은 선택사항이고 비밀값은 넣지 말라는 점을 주석으로 적어줘.
  바꾼 부분은 왜 그렇게 했는지 주석으로 설명해줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  나는 정적 HTML 페이지를 Vercel(GitHub 연결됨)에 올려 쓰고 있어. 비전공자야.
  글자를 v1에서 v2로 고치고 git push 했는데 사이트에 반영이 안 돼.
  아래 상황을 단계별로 점검하는 체크리스트를 만들어줘:
  - Vercel Deployments 탭에 새 배포 줄이 생겼는지 / 상태가 Building·Ready·Error 중 무엇인지
  - 어느 브랜치(main/master)로 push 했는지, 저장소가 Vercel과 Connected인지
  - 브라우저 캐시 때문일 가능성(강력 새로고침 방법)
  각 점검 항목마다 "왜 이걸 확인하는지" 이유도 한 줄씩 붙여서, 초보가 이해하게 설명해줘.
  ```
> 프롬프트 팁: 프롬프트 끝에 **"코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘"**, **"비전공자가 이해하게 한 줄씩 풀어줘"**를 덧붙이면, 결과 코드가 학습에 훨씬 도움이 됩니다.

## 검증법

1. **Deployments 기록 확인**: Vercel → 프로젝트 → Deployments 탭 맨 위에, 내가 적은 커밋 메시지가 붙은 **새 배포 줄**이 있고 상태가 **Ready**인지 본다. (이게 "결과물: Deployments 기록"입니다.)
2. **라이브 사이트 확인**: `프로젝트이름.vercel.app` 주소를 새로고침했을 때 글자가 **v2**로 바뀌어 보이는지 본다. (이게 "결과물: 수정 내용이 반영된 라이브 사이트"입니다.)
3. **휴대폰 확인(선택)**: 와이파이를 끄고 LTE/5G로 휴대폰 브라우저에서 같은 주소를 열어 v2가 보이면, 내 PC와 무관하게 인터넷에 새 버전이 떠 있다는 뜻입니다.
4. **파이프라인 이해 확인**: 내가 누른 것은 `Commit`/`git push` 뿐이고 **Deploy 버튼은 누른 적이 없다**는 사실을 떠올려 봅니다. "push만 하면 자동 배포된다"가 머릿속에 그려지면 이번 실습의 진짜 목표 달성입니다.
5. **(보너스) 한 번 더 돌려보기**: `v2`를 `v3`로 바꿔 다시 push 하면, Deployments에 줄이 **또 하나** 쌓입니다. 여러 줄이 쌓이는 모습 = 배포 이력(history)이라는 것도 함께 확인하세요.
