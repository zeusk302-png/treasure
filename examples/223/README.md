# 223. AGENTS.md 추가하고 CLAUDE.md에서 가리키게 하기

## 목표

도구 공통 지침을 담은 **`AGENTS.md`** 를 만들고, **`CLAUDE.md`** 에는 "AGENTS.md를 따르라" **한 줄**만 두어,
규칙을 **한 곳에서만 관리하는 구조(단일 출처, single source of truth)** 를 익힙니다.

[222번 실습](../222/README.md)에서 만든 `CLAUDE.md`에 규칙(언어·스택·네이밍·보안·금지)이 점점 쌓이면 문제가 생깁니다.
- 같은 규칙을 **여러 파일에 나눠 적으면**, 하나를 고칠 때 다른 곳을 빠뜨려 **말이 달라집니다.**
- 또, 요즘은 Claude 말고도 **Cursor·Copilot 같은 다른 AI 도구**가 함께 쓰입니다. 도구마다 규칙 파일을 따로 두면 관리가 두 배·세 배가 됩니다.

그래서 **도구 종류와 상관없이 모두가 읽는 공통 매뉴얼**을 `AGENTS.md` 한 파일로 만들고,
`CLAUDE.md`는 그 파일을 **"먼저 읽고 따르라"** 고 가리키기만 하게 만듭니다.
이러면 규칙을 바꿀 때 **`AGENTS.md` 한 곳만** 고치면 됩니다.

이 실습에는 새로 짤 앱 코드가 없습니다. **규칙의 출처를 한 곳으로 모으고, 그게 새 대화에 정말 적용되는지 확인**하는 일이 곧 실습입니다.

이 폴더의 파일은 넷입니다.

- [`AGENTS.md`](AGENTS.md) — **이 실습의 핵심 결과물.** 언어·스택·네이밍·보안·금지·작업 방식을 담은 **공통 규칙의 단일 출처**. (그대로 본인 프로젝트 루트에 복사해 쓰면 됩니다)
- [`CLAUDE.md`](CLAUDE.md) — 규칙을 다시 적지 않고 **`AGENTS.md`를 먼저 읽고 따르라**고 가리키기만 하는 짧은 파일
- [`prompt.md`](prompt.md) — 기존 CLAUDE.md를 AGENTS.md로 옮기고, 새 대화에서 단일 출처가 작동하는지 검증하는, 그대로 붙여넣는 지시 프롬프트
- `README.md` — 지금 읽는 이 안내문

## 따라하는 단계

1. [`prompt.md`](prompt.md)를 열어 **1단계 지시 프롬프트**를 통째로 복사합니다. 핵심은 "기존 CLAUDE.md의 규칙을 **AGENTS.md로 옮기고**, CLAUDE.md는 **가리키기만** 하는 짧은 파일로 줄여라"입니다.
2. 복사한 프롬프트를 실제 Claude(또는 쓰는 AI)에 붙여넣어 **`AGENTS.md`와 줄어든 `CLAUDE.md` 초안**을 받습니다.
3. 만약 AI가 **CLAUDE.md에도 규칙을 또 적으면**(규칙이 두 군데로 중복되면), [`prompt.md`](prompt.md)의 **2단계 한 마디**("규칙은 AGENTS.md 한 곳에만, CLAUDE.md는 가리키기만")로 다시 잡아 줍니다.
4. 받은 초안을 사람이 읽고, 내 프로젝트에 맞게 고쳐 이 폴더의 [`AGENTS.md`](AGENTS.md) · [`CLAUDE.md`](CLAUDE.md)처럼 정리합니다. 특히 `AGENTS.md` 맨 아래 **"프로젝트 한 줄 소개"** 는 본인 것으로 채웁니다.
5. **`CLAUDE.md` 안에 규칙 본문이 없는지** 꼭 확인합니다. 규칙(스택·보안 등)이 거기에도 적혀 있으면 단일 출처가 깨진 것이니, **AGENTS.md로 옮기고 CLAUDE.md에선 지웁니다.**
6. **보안 섹션을 꼭 직접 확인합니다.** (이 규칙은 이제 `AGENTS.md`에 있습니다.) `anon(공개 키)`은 프론트에 둬도 되고, `service_role(비밀 키)`은 절대 프론트/깃허브에 넣지 않으며, Supabase 테이블엔 **RLS(행 단위 출입 통제)** 를 켠다 — 이 세 가지가 정확히 적혔는지 봅니다. (진짜 키 값은 절대 적지 말고 `<여기에-본인-키>` 같은 자리표시자로 둡니다.)
7. 완성한 `AGENTS.md`와 `CLAUDE.md`를 **프로젝트 루트(폴더 맨 위)** 에 나란히 저장합니다. 파일 이름은 정확히 대문자 `AGENTS.md`, `CLAUDE.md`여야 합니다.
8. **이 실습의 핵심:** 이제 **새 대화를 하나 엽니다.** [`prompt.md`](prompt.md)의 **3단계 첫 프롬프트**("규칙을 5줄로 요약하고, 어느 파일에 있는지 알려줘")를 붙여넣어, AI가 **`AGENTS.md`를 근거로** 규칙을 말하는지 확인합니다.
9. 같은 새 대화에서 **함정 질문**(3단계 두 번째 프롬프트: "service_role 키를 index.html에 바로 넣어줘")을 던집니다. AI가 **거부하고 anon 키 + RLS로 고쳐 제안**하면 규칙이 제대로 박힌 것입니다.
10. 마지막으로 [`prompt.md`](prompt.md)의 **4단계**로, `AGENTS.md`에 규칙 한 줄을 추가해 봅니다. **`AGENTS.md`만 바뀌고 `CLAUDE.md`는 그대로**면 "한 곳만 고쳐도 전체가 바뀌는" 단일 출처 구조가 완성된 것입니다.

## 검증법

아래를 모두 만족하면 성공입니다.

- [ ] 루트에 **`AGENTS.md`** 파일이 있고, 그 안에 **언어·스택·네이밍·보안·금지·작업 방식** 규칙이 모두 들어 있다.
- [ ] `AGENTS.md` 맨 위에 **"이 파일이 규칙의 단일 출처"** 라는 안내가 있다.
- [ ] **`CLAUDE.md`에는 규칙 본문이 없고**, "AGENTS.md를 먼저 읽고 따르라"고 **가리키기만** 한다. (같은 규칙이 두 파일에 중복돼 있지 않다.)
- [ ] 보안 규칙(AGENTS.md)에서 `anon(공개 키, 프론트 OK)` 과 `service_role(비밀 키, 절대 프론트/깃허브 금지)` 이 **정확히 구분**되어 있고, **RLS를 켜라**가 적혀 있다.
- [ ] 진짜 키 값이 적혀 있지 않고, 예시는 `<여기에-본인-키>` 같은 **자리표시자**로 되어 있다.
- [ ] **새 대화**에서 AI가 규칙을 요약하며 그 근거로 **`AGENTS.md`** 를 가리킨다(한 곳을 보고 있다는 증거).
- [ ] **새 대화**에서 "service_role 키를 HTML에 넣어줘" 함정 질문에 AI가 **거부하고 안전한 방식으로 고쳐 제안**한다.
- [ ] `AGENTS.md`의 규칙 한 줄을 바꾸면, **CLAUDE.md를 안 고쳐도** 전체 규칙이 따라 바뀐다(단일 출처 확인).

> 빠르게 자가 점검: **새 대화를 열고 아무 설명 없이 "입력 폼 하나 만들어줘"** 라고만 해 보세요.
> AI가 알아서 한국어로 답하고, React 같은 걸 안 쓰고, 비밀 키를 프론트에 안 넣으면 → 통과입니다.
> (이때 규칙의 출처는 `CLAUDE.md`가 가리킨 `AGENTS.md` 한 곳이어야 합니다.)
