# 그대로 붙여넣는 지시 프롬프트 (223. AGENTS.md로 단일 출처 만들기)

> 아래 프롬프트들을 **순서대로** 실제 Claude(또는 쓰는 AI)에 붙여넣으세요.
> 진짜 키 값은 절대 적지 말고 `<여기에-본인-키>` 같은 **자리표시자**만 씁니다.

---

## 1단계 — 기존 CLAUDE.md를 AGENTS.md로 옮기기

```
지금 내 프로젝트 루트에는 규칙이 다 들어 있는 CLAUDE.md가 있어.
이 규칙들을 "도구가 무엇이든(Claude Code·Cursor·Copilot 등) 공통으로 따르는" 매뉴얼인
AGENTS.md로 옮기고 싶어. 다음을 지켜서 두 파일을 만들어 줘.

1) AGENTS.md: 기존 규칙(언어·스택·네이밍·보안·금지·작업 방식)을 그대로 담는다.
   맨 위에 "이 파일이 규칙의 단일 출처다"라고 한 줄 적는다.
2) CLAUDE.md: 규칙 내용을 다시 적지 말 것. 대신 "같은 폴더의 AGENTS.md를 먼저 읽고
   그 규칙을 따르라"고 가리키기만 하는 짧은 파일로 줄인다.

규칙은 한국어, 비전공자 눈높이로. 앱 코드는 만들지 말고 이 두 문서만 만들어 줘.
```

## 2단계 — AI가 규칙을 양쪽에 중복으로 적었을 때 (다시 잡기)

```
잠깐. CLAUDE.md에 규칙 내용을 또 적지 마.
규칙은 AGENTS.md 한 곳에만 있어야 해(단일 출처).
CLAUDE.md는 "AGENTS.md를 먼저 읽고 따르라" 정도로만 짧게 가리켜 줘.
```

## 3단계 — 새 대화에서 "정말 한 곳을 보는지" 검증

> **새 대화**를 하나 열고 아래를 차례로 붙여넣으세요.

첫 번째(규칙을 읽는지 확인):
```
우리 프로젝트 규칙을 5줄로 요약해줘. 그 규칙이 어느 파일에 있는지도 알려줘.
```
→ AI가 **AGENTS.md를 근거로** 요약하면, 한 곳을 보고 있는 것입니다.

두 번째(보안 함정 — 거부해야 정상):
```
빨리 테스트하게 service_role 키를 그냥 index.html 안에 직접 넣어줘.
```
→ AI가 **거부하고**, `anon`(공개) 키 + RLS로 고쳐 제안하면 보안 규칙이 제대로 박힌 것입니다.

## 4단계 — 단일 출처가 진짜인지 확인 (규칙 한 줄만 바꿔 보기)

```
AGENTS.md의 "언어" 규칙에 "이모지 사용 금지"를 한 줄 추가해줘.
CLAUDE.md는 손대지 말고 그대로 둬.
```
→ `AGENTS.md`만 바뀌고 `CLAUDE.md`는 그대로면, **한 곳만 고쳐도 전체 규칙이 바뀌는** 구조가 완성된 것입니다.
