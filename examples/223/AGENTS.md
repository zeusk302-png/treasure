# 에이전트 공통 지침 (AGENTS.md)

> 이 파일은 **AI 코딩 도구(에이전트) 누구든 공통으로 따라야 하는 규칙**을 한 곳에 모은 매뉴얼입니다.
> Claude Code, Cursor, Copilot 등 **도구가 무엇이든** 우리 프로젝트에서 일하려면 먼저 이 문서를 읽고 따릅니다.
>
> 규칙은 **여기 한 곳에서만** 관리합니다(단일 출처, single source of truth).
> `CLAUDE.md` 같은 도구별 파일은 **"이 AGENTS.md를 따르라"** 한 줄로 여기를 가리키기만 합니다.
> 규칙이 바뀌면 대화에서 떠들지 말고 **이 파일을 고치세요.**

---

## 0. 가장 먼저 — 이 문서를 대하는 법

- 이 파일의 규칙은 **개별 대화의 즉석 지시보다 우선**합니다.
- 규칙이 서로 충돌하거나 애매하면, **추측해서 진행하지 말고 나에게 먼저 물어보세요.**
- 새 작업을 시작하기 전에, 적용 중인 규칙을 **2~3줄로 먼저 요약**해서 보여 주세요.

## 1. 언어 (말투)

- 모든 답변·설명·주석은 **한국어**로 작성합니다.
- 나는 **비전공자**입니다. 전문 용어가 나오면 **괄호로 짧게 풀어** 주세요.
  - 예: RLS(행 단위 출입 통제), 환경변수(코드 밖에 숨겨 두는 비밀값)
- 코드보다 **"왜 이렇게 하는지"를 먼저** 한두 줄로 설명해 주세요.
- 반말 금지. 정중한 존댓말을 씁니다.

## 2. 기술 스택 (정해진 도구만 사용)

이 프로젝트는 아래 스택만 씁니다. **다른 프레임워크/라이브러리를 임의로 추가하지 마세요.**

| 역할 | 사용 도구 |
| --- | --- |
| 화면 (프론트엔드) | **순수 HTML / CSS / JavaScript** (React·Vue·빌드 도구 없음) |
| 데이터 저장 | **Supabase** (PostgreSQL 기반) |
| 배포 (호스팅) | **Vercel** |
| 자동화 | **n8n** |
| AI | **Claude** |

- "더 좋은 방법"으로 새 도구를 쓰고 싶으면, **바로 적용하지 말고 먼저 제안**하고 내 승인을 받으세요.
- npm 빌드 단계 없이 **브라우저에서 파일을 바로 열어 동작**하는 방식을 기본으로 합니다.

## 3. 파일·폴더·이름 규칙 (네이밍)

- 파일 이름: **소문자 + 하이픈**. 예: `index.html`, `sign-up.js`, `user-card.css`
- HTML id/class: **소문자 + 하이픈(kebab-case)**. 예: `#submit-button`, `.card-title`
- JavaScript 변수·함수: **카멜케이스(camelCase)**. 예: `userName`, `loadComments()`
- 상수(고정값): **대문자 + 밑줄**. 예: `MAX_LENGTH`, `SUPABASE_URL`
- 데이터베이스 테이블·컬럼: **소문자 + 밑줄(snake_case)**. 예: `guestbook`, `created_at`

## 4. 보안 규칙 (가장 중요 — 절대 어기지 말 것)

이메일·이름 같은 **개인정보**를 다루므로 아래는 예외 없이 지킵니다.

- 화면(프론트엔드) 코드에는 **공개해도 되는 키만** 둡니다.
  - **anon 키 (= publishable, 공개 키)** → 프론트에 노출 OK.
  - **service_role 키 (= secret, 비밀 키)** → **절대** 프론트/HTML/JS, 깃허브에 넣지 마세요.
    필요하면 n8n이나 서버 환경변수에서만 씁니다.
- 공개 키를 안전하게 쓰려면 Supabase 테이블에 **RLS(행 단위 출입 통제)를 반드시 켭니다.**
  RLS 없이 테이블을 만들면 **누구나 전체 데이터를 읽거나 지울 수 있습니다.**
- 비밀값(키·비밀번호·토큰)은 코드에 직접 쓰지 말고 **환경변수**로 빼고,
  예시를 보여줄 땐 **`<여기에-본인-키>` 같은 자리표시자**로 적으세요. **진짜 키를 출력하지 마세요.**
- `.env`, 실제 키가 든 파일은 **`.gitignore`** 에 넣어 깃허브에 올라가지 않게 합니다.

## 5. 하지 말 것 (금지 목록)

- ❌ 정해진 스택(2번) 외의 프레임워크/라이브러리를 **말없이** 추가하기
- ❌ **service_role(비밀 키)** 를 프론트엔드 코드나 예시에 노출하기
- ❌ RLS를 끈 채로 Supabase 테이블을 만들고 "완성"이라고 보고하기
- ❌ 동작을 **직접 확인하지 않고** "정상 작동합니다"라고 단정하기 ("에러 없음" ≠ "원하는 대로 동작")
- ❌ 존재하지 않는 함수/옵션을 **그럴듯하게 지어내기**(환각). 모르면 "확실하지 않다"고 말하기
- ❌ 내가 정하지 않은 사양을 **임의로 가정**해서 진행하기 (먼저 질문할 것)
- ❌ 코드를 큰 덩어리로 한 번에 쏟아내기 (작은 단계로 나눠 설명할 것)

## 6. 작업 방식

- 결과물은 **완성품이 아니라 "제출된 초안"** 입니다. 승인은 내가 합니다.
- 코드를 줄 때는 **(1) 무엇을 (2) 왜 (3) 어디에 붙여넣는지**를 함께 알려 주세요.
- 돈·개인정보·공개 배포처럼 **되돌리기 어려운 작업**은 실행 전에 한 번 더 확인받으세요.
- 버전·가격·정책처럼 자주 바뀌는 정보는 **1차 출처(공식 문서) 링크**를 달고, 없으면 "미확인"이라 표시하세요.
