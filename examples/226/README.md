# 226. 깨진 화면 스크린샷 붙여넣어 레이아웃 깨짐 고치기

## 목표

화면이 깨졌을 때 **말로 설명하는 대신, 깨진 화면을 캡처(스크린샷)해서 이미지로 AI에게 붙여넣고**,
**"고치기 전에 원인 후보 3개부터"** 라고 못 박아 AI의 추측 수정을 막는, **시각 증거 기반 디버깅**을 익힙니다.

"모바일에서 메뉴가 좀 이상해요"라고 글로만 말하면, 사람마다 떠올리는 그림이 달라서 AI도 엉뚱한 곳을 고칩니다.
하지만 **깨진 화면 캡처 한 장 + 언제(어떤 화면 폭에서) 깨지는지 + 관련 코드** 를 함께 주면,
AI는 그 이미지를 근거 삼아 "이 줄의 이 속성 때문에 겹친다"라고 **원인을 짚어** 고칩니다.
이것이 글이 아닌 그림으로 지시하는 **멀티모달(이미지) 디버깅**입니다.

이 폴더의 파일은 넷입니다.

- [`broken.html`](broken.html) — **일부러 레이아웃을 깨뜨린 코드.** 모바일 폭으로 줄이면 상단 메뉴가 로고/제목과 겹칩니다. (파일 맨 위 주석에 재현 절차가 있습니다 — 이게 "스크린샷으로 찍을 깨진 화면"입니다)
- [`index.html`](index.html) — `broken.html`을 고친 **정상 작동 버전.** (무엇을 고쳤는지 주석으로 표시)
- [`prompt.md`](prompt.md) — 깨진 스크린샷을 첨부하고 "원인 후보 3개부터"라고 시키는, 그대로 복사하는 지시 프롬프트
- `README.md` — 지금 읽는 이 안내문 (아래에 **원인 → 수정 해설**이 있습니다)

> 이 실습은 **새 디자인을 짜는 게 아니라, 깨진 화면을 "이미지로 보여 주며 옳게 질문하는" 연습**입니다.
> 그래서 결과물도 `깨짐 스크린샷 → 원인 후보 → 수정 후 정상 캡처`라는 흐름 그대로입니다.

## 따라하는 단계

1. [`broken.html`](broken.html)을 브라우저로 엽니다. (파일을 더블클릭하면 됩니다) 넓은 화면에서는 로고 왼쪽, 메뉴 오른쪽으로 멀쩡해 보입니다.
2. **F12**를 눌러 개발자 도구를 열고, 왼쪽 위 **기기 툴바(휴대폰 모양 아이콘)** 를 켭니다. (단축키: Windows `Ctrl+Shift+M`, Mac `Cmd+Shift+M`)
3. 화면 폭을 **375px**(아이폰 정도)로 줄입니다. 그러면 상단 파란 바 안에서 메뉴 글자들이 로고/제목과 **겹쳐서** 뭉개집니다.
4. 이 **겹친 화면을 스크린샷**합니다. (Windows `Win+Shift+S` → 영역 드래그) 이 한 장이 이번 실습의 "시각 증거"입니다.
5. [`prompt.md`](prompt.md)의 **1단계 틀**을 복사해, AI 대화창에 **4번 스크린샷을 첨부**하고 함께 붙여넣습니다. `[관련 코드]` 자리엔 `broken.html` 내용을 통째로, `[재현 환경]`(폭 375px)도 함께 넣습니다.
6. 그 프롬프트를 실제 Claude(또는 쓰는 AI)에 넣습니다. **"고치기 전에 원인 후보 3개부터"** 가 들어 있는지 꼭 확인합니다.
7. AI가 **원인 후보를 먼저** 늘어놓는지 봅니다. 올바른 답이라면 후보에 이런 것들이 들어갑니다: ① `.navbar`의 **고정 height(56px)**, ② 메뉴의 **`position: absolute`(절대 위치 띄우기)**, ③ 메뉴가 **줄바꿈되지 않음(`inline-block`)**, ④ **모바일용 미디어쿼리가 없음**.
8. 만약 AI가 원인 설명 없이 바로 "이렇게 바꾸세요"만 주면, [`prompt.md`](prompt.md)의 **2단계 한 마디**("코드부터 바꾸지 마. 원인 후보 3개부터")로 다시 잡습니다.
9. AI가 제안한 수정안을 **사람이 직접 적용**해 봅니다. 핵심 방향은: 고정 height를 없애고 → 메뉴를 absolute 대신 **flexbox 흐름**에 두고 → 모바일에서 **세로로 쌓기(미디어쿼리)** 입니다.
10. 고친 페이지를 모바일 폭에서 다시 보고, 메뉴가 더 이상 겹치지 않는지 확인한 뒤 **정상 화면도 다시 캡처**해 [`prompt.md`](prompt.md) **3단계**로 AI에게 "증상이 사라졌는지" 검증을 시킵니다. 막히면 [`index.html`](index.html)과 비교해 보세요.

## 🤖 바이브코딩 프롬프트

이 실습을 AI에게 시켜 진행할 때 그대로 복사해 쓰는 프롬프트입니다. 이번 주제는 "새 화면을 짜기"가 아니라 **깨진 화면을 이미지로 보여 주며 옳게 질문하기**라서, 1단계도 "깨진 코드 만들기 + 깨진 화면 캡처"부터 시작합니다.

- **1단계(뼈대 만들기)** 프롬프트 — 실습용으로 "일부러 깨진" 페이지를 받기:
  ```text
  너는 프런트엔드 디버깅 실습을 도와주는 도우미야.
  비전공자가 "레이아웃 깨짐을 스크린샷으로 보여 주며 고치는" 연습을 할 수 있게,
  일부러 깨뜨린 HTML+CSS 한 파일(broken.html)을 만들어줘.

  요구사항:
  - 가게 홈페이지 상단에 파란 내비게이션 바: 왼쪽 로고 1개 + 오른쪽 메뉴 4개
  - 데스크톱(넓은 폭)에서는 멀쩡해 보일 것
  - 단, 모바일 폭(375px)으로 줄이면 메뉴 글자가 로고와 "겹쳐서" 깨질 것
  - 깨지는 원인은 일부러 여러 개를 겹쳐 넣어줘:
    고정 height + position: absolute(메뉴 띄우기) + 줄바꿈 안 됨(inline-block) + 모바일 미디어쿼리 없음
  - 파일 맨 위 주석에 "어떻게 열어서 어떤 폭으로 줄이면 깨지는지" 재현 절차를 적어줘
  - 코드만 주지 말고, 어느 줄이 왜 깨짐을 만드는지 한국어 주석으로 한 줄씩 설명해줘
  ```

- **2단계(기능 추가/개선)** 프롬프트 — 깨진 화면을 이미지로 보여 주며 고치기:
  ```text
  (여기에 모바일 폭 375px에서 메뉴가 로고와 겹친 "깨진 화면" 스크린샷을 첨부)

  첨부 이미지처럼 모바일 폭에서 상단 메뉴 글자가 로고/제목과 겹쳐 보여.
  고치기 전에 "원인 후보를 3개" 가능성 높은 순서로, 각각 코드의 어느 줄 때문인지 근거와 함께 짚어줘.
  코드는 아직 바꾸지 마.

  [언제 깨지나 / 재현 환경]
  broken.html을 브라우저로 열고 → F12 → 기기 툴바(휴대폰 아이콘) → 화면 폭을 375px로 줄이면 겹침.
  (데스크톱 넓은 폭에서는 멀쩡함)

  [관련 코드]
  (여기에 broken.html 내용을 통째로 붙여넣기)

  원인 후보를 확정한 다음에야 수정안을 보여줘.
  고정 height를 없애고 → 메뉴를 absolute 대신 flex 흐름에 두고 → 모바일에서 세로로 쌓는 방향으로,
  데스크톱 화면은 새로 안 깨지게 최소 변경으로 고쳐줘.
  ```

- **막혔을 때(디버깅)** 프롬프트 — AI가 원인 설명 없이 바로 코드부터 바꿀 때:
  ```text
  잠깐, 코드부터 바꾸지 마.
  첨부한 깨진 화면(스크린샷)의 겹침이 "코드의 어느 줄" 때문인지 후보 3개를 근거와 함께 먼저 보여줘.
  그중 가장 유력한 1개를 고른 이유까지 말한 다음에 수정안을 줘.
  그리고 수정 후 모바일 폭에서 정말 겹침이 사라지는지, 데스크톱에서 새로 깨진 곳은 없는지 확인 포인트도 알려줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 **왜 그렇게 했는지 한국어 주석으로 한 줄씩** 설명해줘"를 덧붙이면, 고친 CSS가 왜 겹침을 없애는지(고정 height 제거·flex 흐름·미디어쿼리)까지 같이 배우게 됩니다. 그리고 말 대신 **깨진 화면 캡처 한 장**을 첨부하는 것이 이 실습의 핵심입니다.

## 검증법

아래를 모두 만족하면 성공입니다.

- [ ] `broken.html`에서 **모바일 폭(375px)으로 줄여 메뉴 겹침을 실제로 재현**했고, 그 **깨진 화면을 스크린샷**으로 찍었다.
- [ ] AI에게 줄 때 **말 대신 이미지(스크린샷)** 를 첨부했고, **언제 깨지는지(화면 폭/환경)** 를 함께 주었다.
- [ ] 프롬프트에 **"고치기 전에 원인 후보 3개부터"** 가 들어 있다(추측 수정 방지).
- [ ] AI가 **원인 후보를 가능성 높은 순으로** 짚었고, 각각 코드의 어느 줄 때문인지 근거를 댔다. (고정 height / position: absolute / 줄바꿈 안 됨 / 미디어쿼리 없음)
- [ ] 수정 후 **모바일 폭에서 메뉴가 로고/제목과 겹치지 않는다.** (정상 화면을 다시 캡처해 비교했다)
- [ ] 데스크톱 넓은 폭에서도 **새로 깨진 곳이 없다.** (로고 왼쪽, 메뉴 오른쪽 한 줄 유지)
- [ ] (보안) 스크린샷에 **비밀 값(키·토큰·비밀번호·환경변수 파일)** 이 같이 찍히지 않았다. 찍혔다면 가린 뒤 붙여넣었다.

> 빠른 자가 점검: 고친 [`index.html`](index.html)을 열고 F12 기기 툴바로 폭을 375px → 768px → 1200px로 바꿔 보세요.
> **어느 폭에서도 메뉴 글자가 다른 글자와 겹치지 않으면** 통과입니다.

## 원인 → 수정 해설 (이 실습의 정답 풀이)

**증상:** 데스크톱(넓은 폭)에서는 멀쩡한데, 모바일(좁은 폭, 375px)로 줄이면 상단 메뉴 글자들이 로고/제목 위로 삐져나와 **겹쳐서** 읽을 수 없다.

**스크린샷에서 무엇이 보이나:** 파란 상단 바 안에 "맛있는 분식집"(로고)과 "메뉴/오시는 길/리뷰/예약하기"(메뉴 4개)가 좁은 공간에서 서로 포개져 글자가 뭉개진 모습.

**근본 원인은 세 가지가 겹쳐서 생깁니다.**

1. **고정 height (`height: 56px`)** — `.navbar`의 높이를 56px로 못 박아 두면, 화면이 좁아져 내용이 늘어나도 바가 같이 커지지 못합니다. 들어갈 공간이 없는데 높이는 고정이라 내용이 밖으로/위로 넘칩니다.
2. **`position: absolute` (절대 위치 띄우기)** — 메뉴(`.menu`)를 `position: absolute; right: 20px;`로 **흐름에서 떼어 내 떠 있게** 했습니다. 떠 있는 요소는 로고가 차지한 자리를 모릅니다. 그래서 좁아지면 로고 위로 그대로 겹칩니다.
3. **줄바꿈 안 됨 (`display: inline-block`)** — 메뉴 항목들이 항상 가로 한 줄로만 배치되어, 폭이 좁아도 아래로 접히지 못하고 옆으로 비집고 나옵니다.

여기에 **모바일용 미디어쿼리(`@media`)가 아예 없다**는 것이 더해져, 좁은 화면을 위한 다른 배치 규칙이 하나도 적용되지 않습니다.

**수정:** 떠 있는 절대 위치를 버리고 **흐름 안에서 flex로 배치**한 뒤, **좁아지면 세로로 쌓이게** 만듭니다. (이 폴더 `index.html` 방식)

```css
/* broken.html (틀림): 높이 고정 + 절대 위치 + 줄바꿈 안 됨 → 겹침 */
.navbar { height: 56px; position: relative; }
.menu   { position: absolute; top: 0; right: 20px; }
.menu li { display: inline-block; }

/* index.html (고침): 높이 고정 제거 + flex 흐름 + 줄바꿈 허용 + 모바일 미디어쿼리 */
.navbar {
  padding: 10px 20px;                 /* height 고정 대신 여백으로 → 내용만큼 늘어남 */
  display: flex; align-items: center;
  justify-content: space-between;     /* 로고 왼쪽, 메뉴 오른쪽 */
  flex-wrap: wrap; gap: 8px;          /* 좁으면 자연스럽게 줄바꿈 */
}
.menu { display: flex; flex-wrap: wrap; gap: 4px 14px; }
@media (max-width: 480px) {
  .navbar { flex-direction: column; align-items: flex-start; }  /* 로고 아래로 메뉴를 세로로 */
}
```

**교훈:** 레이아웃 깨짐은 원인이 **한 가지가 아닐 때가 많습니다.** "고정 크기 + 절대 위치 + 줄바꿈 안 됨"이 합쳐져 생기는 게 대표적입니다.
그래서 "원인 하나"로 단정하지 말고 **후보를 늘어놓고 근거로 좁히는** 것이 핵심입니다.
또한 같은 코드라도 **데스크톱은 멀쩡하고 모바일만 깨지는** 경우가 흔하므로, "언제(어떤 화면 폭에서) 깨지는가"를 AI에게 반드시 함께 알려 줘야 합니다. 그리고 글보다 정확한 증거는 **깨진 화면 캡처 한 장**입니다.
