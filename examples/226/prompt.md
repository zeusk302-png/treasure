# 그대로 붙여넣는 지시 프롬프트 (226. 깨진 화면 스크린샷 붙여넣어 레이아웃 깨짐 고치기)

> 핵심 원칙: 말로 "메뉴가 이상해요"라고 설명하는 대신, **깨진 화면을 캡처(스크린샷)해서 이미지로 붙여넣습니다.**
> 그리고 **"고치기 전에 원인 후보 3개부터"** 라고 못 박아 AI가 코드를 안 보고 추측으로 손대는 것을 막습니다.
> 이미지(시각 증거) + 재현 환경(어떤 화면 폭에서) + 관련 코드 = AI가 추측 없이 근거로 고치게 하는 3종 세트입니다.

---

## 1단계 — 깨진 스크린샷 + 환경 + 코드를 함께 붙여넣기 (원인 후보부터 요청)

먼저 깨진 화면을 캡처하세요.
- `broken.html`을 브라우저로 열고 → F12 → 기기 툴바(휴대폰 아이콘, Ctrl+Shift+M) → 폭을 375px로 줄입니다.
- 메뉴 글자가 로고/제목과 겹친 화면이 보이면 그 화면을 **스크린샷**합니다. (Windows: Win+Shift+S)

그다음 아래 틀을 복사해, AI 대화창에 **스크린샷 이미지를 첨부**하고 함께 붙여넣으세요. 대괄호 `[ ]`만 본인 것으로 채웁니다.

```
(여기에 깨진 화면 스크린샷 이미지 첨부)

첨부한 이미지처럼 화면이 깨졌어. 모바일 폭에서 상단 메뉴 글자가 로고/제목 위로 겹쳐 보여.
고치기 전에 "원인 후보를 3개"부터 가능성 높은 순서로 짚어줘. 코드는 아직 바꾸지 마.

[언제 깨지나 / 재현 환경]
1) broken.html을 브라우저로 연다
2) F12 > 기기 툴바(휴대폰 아이콘)를 켠다
3) 화면 폭을 375px로 줄인다
4) 그러면 첨부 이미지처럼 메뉴가 로고/제목과 겹친다 (데스크톱 넓은 폭에서는 멀쩡함)

[관련 코드 — 의심되는 파일 전체를 붙여넣기]
(여기에 broken.html 내용을 통째로 붙여넣기)

답변은 이 순서로 해줘:
1. 이미지에서 무엇이 어떻게 깨져 보이는지(증상)를 먼저 글로 짚어줘
2. 원인 후보 3개를 "가능성 높은 순"으로, 각각 코드의 어느 줄 때문인지 근거와 함께
3. 그중 가장 유력한 1개를 고른 이유
4. 그다음에야 수정안을 보여줘. 멀쩡한 데스크톱 화면은 안 깨지게, 최소 변경으로.
```

> 왜 "원인 후보 3개부터"인가: 레이아웃 깨짐은 원인이 한 가지가 아닐 때가 많습니다
> (고정 height, position: absolute, 줄바꿈 안 됨, 미디어쿼리 없음 등). AI가 한 가지만 단정하면
> 엉뚱한 곳을 고치기 쉽습니다. **후보를 늘어놓고 → 근거로 좁히는** 순서가 추측 수정을 막습니다.

## 2단계 — AI가 원인 설명 없이 바로 "이렇게 바꾸세요"만 줄 때 (다시 잡기)

```
잠깐. 코드부터 바꾸지 마.
첨부 이미지의 깨진 부분이 "코드의 어느 줄" 때문인지, 후보 3개를 근거와 함께 먼저 보여줘.
유력한 원인을 확정한 다음에 수정안을 보여줘.
```

## 3단계 — 고친 뒤 "정상 화면"도 이미지로 확인 요청 (검증 마무리)

```
방금 수정안을 적용했어. (여기에 모바일 폭에서 다시 캡처한 "정상 화면" 스크린샷 첨부)
이 화면이면 원래 증상(메뉴 겹침)이 사라진 게 맞아? 데스크톱 넓은 폭에서 새로 깨진 데는 없는지도 봐줘.
```

---

## 붙여넣을 때 지켜야 할 것 (중요)

- **말로 설명하지 말고 이미지로 보여 주세요.** "메뉴가 이상해요"는 사람마다 떠올리는 게 다릅니다.
  깨진 화면 캡처 한 장이 글 열 줄보다 정확합니다. (이것이 멀티모달=이미지 지시의 힘입니다)
- **언제 깨지는지(화면 폭/기기)를 꼭 함께** 주세요. 같은 코드라도 데스크톱은 멀쩡하고 모바일만 깨지는 일이 흔합니다.
- **고친 뒤 "정상 화면"도 다시 캡처**해서, 증상이 진짜 사라졌는지 눈으로 확인하고 끝맺습니다. (3단계)
- **스크린샷에 비밀 값이 찍히지 않게** 합니다. 화면 한쪽에 열려 있던 환경변수 파일, Supabase `service_role` 키,
  비밀번호, 토큰 등이 캡처에 같이 들어가면 그대로 새 나갑니다. 캡처 전에 그런 창은 닫거나,
  찍힌 부분은 `<여기에-비밀값-가림>` 처럼 까맣게 가린 뒤 붙여넣으세요.
