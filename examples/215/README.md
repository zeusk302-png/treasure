# 재시도·에러 처리·로그 저장까지 갖춘 안정 자동화 파이프라인

자동화를 "만드는 것"과 "맡길 수 있게 만드는 것"은 다릅니다. 데모는 한 번 잘 돌면 끝이지만, **실제로 운영하는 자동화**는 한밤중에도, 외부 서버가 잠깐 느려져도, 인터넷이 깜빡여도 알아서 버텨야 합니다. 그리고 무슨 일이 있었는지 **나중에 확인할 수 있어야** 합니다.

이번 실습에서는 평범한 "API 호출 → 처리" 흐름을 **운영 가능한 파이프라인**으로 끌어올립니다. 핵심 장치는 세 가지입니다.

> - **재시도(Retry On Fail) + 타임아웃** — 외부 API가 잠깐 흔들려도 곧장 포기하지 않고 몇 번 다시 시도하고, 너무 오래 기다리면 끊습니다. (한 번의 깜빡임으로 자동화 전체가 멈추지 않게)
> - **실패 시 자동 알림(Error Workflow)** — 그래도 끝내 실패하면, 별도의 작은 워크플로우가 깨어나 **나에게 즉시 알림**을 보냅니다. (조용한 실패 방지)
> - **모든 실행 결과를 구글 시트에 로그로 저장** — 성공도 실패도 한 줄씩 시트에 쌓입니다. (나중에 "언제 왜 멈췄는지" 추적 가능)
>
> **이 실습은 워크플로우가 2개입니다.**
> - **`main-workflow.json`** — 평소에 일하는 메인 파이프라인. `정해진 시간마다 시작(Schedule)` → `API 호출(재시도+타임아웃)` → `성공 로그 만들기(Set)` → `구글 시트에 기록`. 노드 4개.
> - **`error-workflow.json`** — 실패 담당. `에러 감지(Error Trigger)` → `실패 내용 정리(Set)` → `구글 시트에 실패 기록` → `Slack 알림`. 노드 4개.

## 목표

- API 호출 노드에 **재시도 횟수·재시도 간격·타임아웃**을 걸어, 일시적인 외부 장애를 스스로 버티게 만든다.
- 메인 워크플로우의 **설정(Error Workflow)** 에 실패 처리용 워크플로우를 연결해, 끝내 실패하면 자동으로 **시트 기록 + Slack 알림**이 가게 한다.
- **성공/실패를 가리지 않고** 모든 실행 결과를 같은 구글 시트에 한 줄씩 남겨, 나중에 운영 상태를 추적할 수 있게 한다.

## 따라하는 단계

1. **구글 시트를 하나 준비합니다.** 새 스프레드시트를 만들고 첫 행(머리글)에 왼쪽부터 **`워크플로우` · `상태` · `메모` · `시각`** 4칸을 적어 둡니다. 시트 탭 이름은 `실행로그`로 바꿔 두면 헷갈리지 않습니다.
2. **n8n에 로그인**합니다. (n8n Cloud 또는 직접 설치한 n8n 모두 가능합니다.)
3. **먼저 실패 처리 워크플로우부터 만듭니다.** 오른쪽 위 **`...`(점 3개) → `Import from File`** 로 이 폴더의 **`error-workflow.json`** 을 불러옵니다. 노드 4개가 나타납니다.
4. **자격증명을 연결합니다.** (비밀값은 절대 파일에 적지 않습니다. 아래 "보안" 항목 참고)
   - `구글 시트에 실패 기록` 노드를 더블클릭해 **Google Sheets 계정**을 연결하고, `documentId`에 1단계에서 만든 시트를 고릅니다. (지금은 `REPLACE_WITH_YOUR_SHEET_DOCUMENT_ID` 자리표시자가 들어 있습니다.)
   - `Slack으로 알림 보내기` 노드를 더블클릭해 **Slack 계정**을 연결하고, 알림 받을 **채널 ID**를 넣습니다. (지금은 `REPLACE_WITH_YOUR_SLACK_CHANNEL_ID` 자리표시자입니다.)
5. **이 실패 처리 워크플로우를 저장**합니다. 저장하면 주소창에 이 워크플로우의 **ID**가 보입니다. 예: `.../workflow/abc123def456` 에서 `abc123def456` 부분이 ID입니다. **복사해 둡니다.** (7단계에서 씁니다.)
6. **이제 메인 워크플로우를 불러옵니다.** 같은 방식으로 **`main-workflow.json`** 을 Import 합니다. 노드 4개가 나타납니다. 여기서도 `구글 시트에 기록` 노드에 4단계와 **같은 시트·같은 구글 계정**을 연결합니다.
7. **메인에 실패 처리 워크플로우를 연결합니다 (이 실습의 핵심).**
   - 캔버스 오른쪽 위 **`...`(점 3개) → `Settings`** 를 엽니다.
   - **`Error Workflow`** 항목에서 방금 만든 **`215 - 실패 처리 (로그+알림)`** 을 목록에서 고릅니다. (JSON에는 `errorWorkflow: "REPLACE_WITH_YOUR_ERROR_WORKFLOW_ID"` 자리표시자가 있는데, 목록에서 고르면 n8n이 실제 ID로 자동으로 채워 줍니다.)
   - 저장합니다.
8. **재시도·타임아웃 설정을 눈으로 확인합니다.** `API 호출 (재시도+타임아웃)` 노드를 열면 이미 이렇게 설정돼 있습니다.
   - `Settings` 탭 → **`Retry On Fail` 켜짐**, `Max Tries` = **3**, `Wait Between Tries` = **5000ms**. (실패하면 5초 간격으로 최대 3번 시도)
   - `Options` → **`Timeout` = 8000ms**. (응답이 8초 넘게 안 오면 끊고 실패 처리)
9. **메인을 한 번 실행해 정상 동작을 봅니다.** 캔버스 위 **`Test workflow`** 를 누릅니다. 기본 주소(`https://httpbin.org/delay/1`)는 1초 뒤 정상 응답하므로, 노드가 모두 초록불이 되고 시트에 **성공** 한 줄이 쌓입니다.
10. **이번엔 일부러 실패시켜 봅니다.** `API 호출` 노드의 `url`을 잠깐 `https://존재하지-않는-주소.example/실패`로 바꾸고 다시 실행합니다. 재시도 3번이 모두 실패한 뒤 메인이 멈추고, **실패 처리 워크플로우가 자동으로 깨어나** 시트에 **실패** 한 줄을 남기고 Slack 알림을 보냅니다. (확인 후 url을 원래대로 되돌려 두세요.)

## 🤖 바이브코딩 프롬프트

이 실습(재시도+타임아웃+에러 워크플로우+로그를 갖춘 n8n 자동화)을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. n8n은 화면에서 노드를 직접 끌어다 놓는 도구지만, "어떤 노드를 어떤 설정으로 어떻게 연결할지"를 AI에게 설계받아 그대로 따라 하면 훨씬 빠릅니다. (JSON을 만들어 달라고 한 뒤 `Import from File`로 붙여 넣을 수도 있습니다.)

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 n8n 자동화 설계를 도와주는 전문가야. 나는 코드를 잘 모르는 비전공자야.
  "운영 가능한 자동화 파이프라인"의 메인 워크플로우 뼈대를 설계해 줘.
  - 노드 흐름: 정해진 시간마다 시작(Schedule Trigger, 1시간 간격) → 외부 API 호출(HTTP Request, GET, https://httpbin.org/delay/1) → 성공 로그 만들기(Set 노드, 칸: 워크플로우/상태/메모/시각) → 구글 시트에 한 줄 추가(Google Sheets append).
  - 시각은 한국시간(Asia/Seoul) 'yyyy-MM-dd HH:mm:ss' 형식으로 넣어 줘.
  - 비밀값(구글 계정 권한)은 절대 노드 값에 직접 쓰지 말고, n8n 자격증명(Credentials)을 고르는 방식으로 설명해 줘.
  각 노드를 왜 그 자리에 두는지, 어떤 설정을 어디서 켜는지 한 단계씩 풀어서 알려 줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  좋아, 이제 이 자동화를 "한밤중에도 알아서 버티게" 강화하고 싶어.
  1) API 호출 노드에 재시도와 타임아웃을 걸어 줘: Retry On Fail 켜기, Max Tries 3, Wait Between Tries 5000ms, Options의 Timeout 8000ms. 각 숫자를 왜 그렇게 잡는지(재시도=버티는 힘, 타임아웃=포기할 줄 아는 힘)도 설명해 줘.
  2) 실패를 담당하는 별도의 작은 워크플로우를 따로 만들어 줘: Error Trigger → 실패 내용 정리(Set: 멈춘 노드 이름과 에러 메시지를 메모에 담기) → 같은 구글 시트에 실패 한 줄 기록 → Slack으로 알림.
  3) 메인 워크플로우의 Settings → Error Workflow에 이 실패 워크플로우를 연결하는 방법을 알려 줘.
  성공도 실패도 같은 시트에 쌓이게 하는 이유까지 설명해 줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  n8n 워크플로우가 내 생각대로 안 돼. 아래 상황을 보고 원인을 단계별로 같이 찾아 줘.
  - 증상: (예: 메인은 실패하는데 Slack 알림이 안 온다 / 구글 시트에 줄이 안 쌓인다 / 재시도가 도는 것 같지 않다)
  - 내가 한 설정: (Error Workflow 연결 여부, 자격증명 연결 여부, 노드 에러 메시지 그대로 붙여넣기)
  가능성이 높은 원인부터 차례로 말해 주고, 각 원인을 어디서 어떻게 눈으로 확인하는지(Executions 탭, 노드 설정 위치)도 알려 줘. 비밀값은 가리고 보여 줄게.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면, 결과를 그대로 따라 하지 않고 '왜 그런지'를 배우게 되어 나중에 직접 고칠 수 있습니다.

## 검증법

1. **성공 로그 확인 (9단계 후).** 구글 시트에 `상태`가 **성공**인 줄이 한 개 추가됐는지 봅니다. `시각` 칸에 한국시간(KST) 실행 시각이 찍혀 있어야 합니다.
2. **재시도가 진짜 도는지 확인 (10단계 중).** 메인의 `Executions` 탭에서 실패한 실행을 열어 보면 `API 호출` 노드가 **여러 번 시도한 흔적**(재시도 로그)이 남아 있습니다. 한 번 만에 포기하지 않았다는 증거입니다.
3. **실패 로그 확인 (10단계 후).** 같은 시트에 이번엔 `상태`가 **실패**인 줄이 추가됐는지 봅니다. `메모` 칸에 멈춘 노드 이름과 에러 메시지가 들어 있어야 합니다.
4. **Slack 알림 확인.** 지정한 채널에 아래 같은 메시지가 떴으면 연결 성공입니다.
   ```
   🚨 자동화가 실패했어요!
   워크플로우: 215 - 메인 파이프라인 (재시도+타임아웃+로그)
   상태: 실패
   내용: 멈춘 노드: API 호출 (재시도+타임아웃) / (네트워크/주소 관련 에러 메시지)
   발생 시각: 2026-06-18 03:21:00
   자세히 보기: https://.../execution/...
   ```
5. **실패 처리 워크플로우의 자동 실행 확인.** `215 - 실패 처리 (로그+알림)`의 `Executions` 탭을 열면, 메인이 실패한 시각에 **자동으로 한 번 실행된 기록**이 보여야 합니다. (Error Trigger가 메인의 실패를 받아 깨어난 것)
6. **연결을 끊어 비교 (선택).** 메인의 `Settings → Error Workflow`를 **`None`** 으로 바꾼 뒤 다시 실패시키면, 메인은 똑같이 실패하지만 **시트의 실패 로그도, Slack 알림도 오지 않습니다.** "연결을 해 둬야만 실패가 기록·통보된다"는 점을 눈으로 확인할 수 있습니다. (확인 후 다시 연결해 두세요.)

## 핵심만 짚기 (디렉터 관점)

- **재시도는 '버티는 힘', 타임아웃은 '포기할 줄 아는 힘'.** 둘은 짝입니다. 재시도만 있고 타임아웃이 없으면, 응답 없는 서버를 무한정 붙잡고 자동화 전체가 멈춥니다. "몇 번까지 다시 해보고, 한 번에 몇 초까지만 기다린다"를 숫자로 정해 두는 게 운영 설계입니다.
- **로그는 성공도 남깁니다.** 실패만 기록하면 "원래 안 돌던 건지, 돌다가 멈춘 건지" 구분이 안 됩니다. 성공 줄이 규칙적으로 쌓이다가 끊긴 지점이 보여야 진짜 추적이 됩니다.
- **실패 처리는 따로 빼서 한 번만 만듭니다.** 워크플로우가 여러 개여도 각자의 `Settings → Error Workflow`에 이 실패 처리 워크플로우 하나만 똑같이 가리키면 됩니다. **실패 담당은 한 명, 그를 부르는 워크플로우는 여럿** 구조입니다.

## 보안, 비밀값은 어떻게 다루나

- 자동화에서 새면 안 되는 비밀값은 **Slack 토큰**과 **구글 계정 권한(OAuth)** 입니다. 절대 JSON 파일이나 노드 값에 직접 적지 마세요.
  - 올바른 방법: n8n의 **`Credentials`(자격증명) 금고**에 저장하고, 노드에서는 그 자격증명을 **고르기만** 합니다. 비밀값은 금고에만 남고 파일에는 남지 않습니다.
  - 그래서 이 파일들에는 실제 값 대신 `REPLACE_WITH_YOUR_SLACK_CREDENTIAL_ID`, `REPLACE_WITH_YOUR_SLACK_CHANNEL_ID`, `REPLACE_WITH_YOUR_GOOGLE_SHEETS_CREDENTIAL_ID`, `REPLACE_WITH_YOUR_SHEET_DOCUMENT_ID`, `REPLACE_WITH_YOUR_ERROR_WORKFLOW_ID` 같은 **자리표시자**만 들어 있습니다. 이 폴더를 통째로 남에게 줘도 비밀이 새지 않습니다.
- **에러 메시지·로그에 비밀이 섞일 수 있습니다.** 실패한 노드의 에러 메시지에 URL 일부나 키 조각이 들어갈 수 있습니다. 알림 채널과 로그 시트는 **아무나 못 보는 비공개**로 두세요.
- 한 줄 원칙: **공개해도 되는 값(시트 머리글, 메시지 문구)은 노드에, 새면 안 되는 값(토큰·계정 권한)은 자격증명 금고에.**
