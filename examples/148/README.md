# 실습 148 — '새 명언' 버튼으로 누를 때마다 다른 글귀 받기

버튼을 누를 때마다 인터넷의 공개 API(서버)에서 **새 명언을 다시 받아와** 화면을 갈아끼우는 한 장짜리 페이지입니다.
실습 146이 "한 번 받고 끝"이었다면, 이번에는 **누른 만큼 계속 다시 호출**하는 흐름을 익힙니다.

> 비유: 자판기 버튼은 한 번 누르면 음료 한 캔이 나옵니다. 또 누르면 또 한 캔.
> `fetch`도 똑같이, 버튼을 누를 때마다 서버에 **새 주문서**를 보냅니다.

## 목표
- 버튼 **클릭 이벤트가 일어날 때마다** `fetch`가 **다시** 실행되는 흐름을 몸으로 안다.
- 매번 받은 새 데이터로 화면(DOM)의 글귀와 이름을 **갈아끼우는** 법을 익힌다.
- "한 번 받고 끝"이 아니라 **반복 호출**이라는 감을 잡는다.
  - `addEventListener("click", ...)` = 자판기 버튼 연결(한 번만 연결해도 누를 때마다 작동)
  - `fetch(주소)` = 누를 때마다 서버에 새 주문서 보내기
  - 호출 횟수 표시 = "지금 몇 번째 다시 부르고 있나"를 눈으로 확인

## 따라하는 단계
1. 이 폴더의 `index.html`을 더블클릭 → 브라우저에서 열린다. (인터넷 연결 권장)
2. **"새 명언" 버튼**을 누른다 → 첫 명언과 말한 사람이 뜨고, 아래에 "지금까지 1번 받았어요."가 보인다.
3. 버튼을 **여러 번** 눌러 본다 → 누를 때마다 글귀가 살짝 흐려졌다가 **다른 명언**으로 바뀐다. 횟수도 2, 3, 4… 늘어난다.
4. `script.js`를 열어 `btn.addEventListener("click", getNewQuote)` 줄을 찾는다 → "버튼을 누르면 이 함수를 실행"이라는 연결이다.
5. `getNewQuote` 함수 안의 `await fetch("https://api.quotable.io/random")` 줄을 본다 → **이 줄이 클릭마다 다시 실행**되는 것이 핵심이다.
6. `render(...)` 함수가 받은 새 값으로 화면의 `quote`와 `author`를 갈아끼우는 부분을 눈으로 따라가 본다.
7. AI에게 시켜 보기:
   > "이 `script.js`에서 방금 받은 명언이 직전 명언과 똑같으면, 한 번 더 자동으로 다시 받아오게 고쳐줘."

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 프런트엔드 튜터야. 비전공자가 이해할 한 장짜리 웹페이지를 만들어줘.
  목표: '새 명언' 버튼을 누르면 공개 명언 API(https://api.quotable.io/random)에서
  명언 하나를 받아와 화면에 보여주는 페이지.
  제약:
  - 파일은 index.html, style.css, script.js 세 개로 분리해줘.
  - API 키가 필요 없는 '공개 API'만 써. 비밀값은 코드에 절대 넣지 마.
  - 사용자에게 보일 글자는 한국어로.
  산출물: 명언 글귀가 들어갈 자리, 말한 사람 이름 자리, '새 명언' 버튼이 있는
  가운데 정렬된 카드 형태. 각 줄이 '무엇을 왜 하는지' 한국어 주석으로 설명해줘.
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 페이지에 아래 기능을 더해줘. 기존 동작은 그대로 두고 추가만 해줘.
  1) 버튼을 누를 때마다 '다시' fetch해서 매번 새 명언으로 갈아끼우기(반복 호출).
  2) 지금까지 몇 번 받았는지 "지금까지 N번 받았어요."로 화면에 표시.
  3) 받아오는 동안에는 버튼을 잠깐 비활성화해서 중복 클릭 막기.
  4) 글귀가 바뀔 때 잠깐 흐려졌다가 또렷해지는 페이드 연출 추가.
  5) 인터넷이 끊겼을 때를 대비해 예비 명언 몇 개를 랜덤으로 보여주는 폴백 처리.
  각 기능을 왜 그렇게 구현했는지 한 줄씩 주석으로 설명해줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  버튼을 눌러도 명언이 안 바뀌어. 아래 정보를 보고 원인을 단계별로 짚어줘.
  - 내 script.js 전체 코드: (여기에 붙여넣기)
  - 브라우저 F12 → Console 탭의 빨간 에러 메시지: (여기에 붙여넣기)
  - F12 → Network 탭에서 버튼을 누를 때 random 요청이 가는지 여부: (가는지/안 가는지)
  먼저 "가장 의심되는 원인 1순위"를 말하고, 내가 직접 확인할 방법을 알려줘.
  그다음 고친 코드를 주되, 바뀐 부분만 한국어 주석으로 표시해줘.
  ```
> 프롬프트 팁: 끝에 "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 훨씬 좋습니다.

## 검증법
- "새 명언" 버튼을 누르면 안내 문구가 **실제 명언으로 바뀌는가?**
- 버튼을 다시 누를 때마다 **매번 다른 명언**으로 갈아끼워지는가?
- 누를 때마다 하단의 **"지금까지 N번 받았어요."** 숫자가 1씩 늘어나는가?
- 받아오는 동안 버튼이 잠깐 **비활성화(흐리게)** 되었다가 다시 눌리는가?
- 글귀가 바뀔 때 잠깐 **흐려졌다가 또렷해지는** 페이드 연출이 보이는가?
- 브라우저에서 `F12`(개발자 도구) → **Network 탭**을 켜고 버튼을 **세 번** 누르면 `random` 요청이 **세 번** 가는 게 보이는가?
- (실패 대비) 와이파이를 끄고 버튼을 눌러도 **"(오프라인) …"** 예비 명언이 매번 다르게 뜨는가?

## 키(API Key)는 필요 없어요
이 실습이 쓰는 명언 API는 **누구나 열쇠 없이** 부를 수 있는 **공개 API**입니다.
그래서 코드에 비밀값(`YOUR_API_KEY` 같은 것)을 넣지 않습니다.
나중에 유료 API나 내 데이터를 다루는 API를 쓸 때는 키가 필요하고,
그 키는 화면 코드(브라우저에 그대로 노출됨)에 넣으면 안 됩니다.
비밀 키는 서버 쪽(예: Supabase의 `service_role`)에서만 다루며, 이는 보안 권에서 따로 배웁니다.
