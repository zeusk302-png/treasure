# 025 - AI 디렉팅으로 '맛집 소개' 페이지 만들고 깨진 태그 고치기

AI(Claude)에게 "맛집 소개 페이지를 만들어 줘"라고 시켜서 코드를 받았다고 상상해 보세요.
AI가 만든 코드는 대부분 잘 작동하지만, 가끔 **태그를 안 닫거나 순서를 헷갈려서** 화면이 깨질 때가 있습니다.
이 실습에서는 일부러 5개의 버그를 심어 둔 `broken.html`을 직접 고쳐 보면서,
HTML의 **닫는 태그**와 **중첩(태그 안에 태그 넣기) 순서**를 눈으로 익힙니다.

> 비전공자를 위한 한 줄 요약: AI는 코드를 빠르게 만들어 주지만, "어디가 틀렸는지 알아보고 고치는 눈"은 사람이 가져야 합니다. 그 눈을 키우는 연습입니다.

## 목표

- AI에게 시맨틱 구조(header/main/footer)·표·이미지·링크를 갖춘 맛집 페이지를 요청하는 "디렉팅 프롬프트"를 써 본다.
- AI가 준 코드에 흔히 생기는 두 가지 실수를 직접 찾아낸다.
  - **닫히지 않은 태그** (예: `</td>`, `</li>`를 빠뜨림)
  - **잘못된 중첩** (예: `<a>...</p></a>`처럼 여는 순서와 닫는 순서가 어긋남)
- 고친 결과(`index.html`)가 브라우저에서 깔끔하게 보이는지 검증한다.

## 따라하는 단계

1. **AI에게 페이지를 주문한다.** Claude에게 아래 프롬프트를 그대로 보내 보세요. (이미 받은 결과가 `broken.html`이라고 생각하면 됩니다.)

   ```
   당신은 HTML 강사입니다. 비전공 초보자가 읽을 수 있도록
   "부산 돼지국밥 맛집 소개" 한 페이지를 순수 HTML로 만들어 주세요.
   조건:
   - <header>(가게 이름) / <main>(본문) / <footer>(저작권) 시맨틱 구조
   - <main> 안에 4개의 <section>: 가게 소개(이미지 포함), 메뉴 가격표(table),
     추천 이유(ul 목록), 찾아오는 길(외부 링크 a 태그)
   - 외부 라이브러리 없이 한 파일로
   설명 없이 코드만 주세요.
   ```

2. **`broken.html`을 브라우저로 연다.** 파일을 더블클릭하거나 VS Code의 Live Server로 엽니다. 표가 밀려 보이거나 링크가 이상하게 잡히는 등 **화면이 어딘가 어그러져** 있을 겁니다.

3. **버그를 직접 찾는다.** 아래 "직접 찾아볼 포인트"만 보고, 정답 해설은 잠시 가린 채 5곳을 찾아 표시해 보세요.
   - 여는 태그(`<td>`)가 있으면 짝이 되는 닫는 태그(`</td>`)가 반드시 있어야 합니다.
   - `<a><p>...</a></p>`처럼 **나중에 연 태그를 먼저 닫는 것**은 잘못된 중첩입니다. 항상 "마지막에 연 것을 먼저 닫기" 순서입니다.

4. **한 곳씩 고친다.** 한 번에 다 고치지 말고, 하나 고칠 때마다 브라우저를 새로고침해서 화면이 어떻게 바뀌는지 관찰하세요. 그래야 어떤 버그가 어떤 증상을 일으키는지 몸으로 익힙니다.

5. **완성본과 비교한다.** 5곳을 다 고쳤다면, 같은 폴더의 `index.html`(정답 완성본)과 비교해 빠뜨린 곳이 없는지 확인합니다.

## 해설: 숨겨 둔 5개의 버그

`broken.html`에 일부러 심은 버그와 고친 방법입니다.

1. **`<title>`은 있지만 `<meta name="viewport">`가 없음 (선택 개선)**
   - 모바일에서 글자가 작게 보입니다. 완성본은 `<head>`에 `<meta name="viewport" content="width=device-width, initial-scale=1.0">`를 추가했습니다.

2. **메뉴 표의 `<td>`가 닫히지 않음 (닫는 태그 누락)**
   - `broken.html`: `<td>수육백반` 뒤에 `</td>`가 없습니다.
   - 증상: "수육백반"과 "12,000원"이 한 칸으로 합쳐지거나 표가 밀립니다.
   - 수정: `<td>수육백반</td>` 로 닫아 줍니다.

3. **추천 목록의 `<li>`가 닫히지 않음 (닫는 태그 누락)**
   - `broken.html`: `<li>주문 즉시 삶아내는 부드러운 수육` 뒤에 `</li>`가 없습니다.
   - 증상: 그 줄과 다음 줄이 한 항목처럼 붙어 버립니다.
   - 수정: `<li>...수육</li>` 로 닫아 줍니다.

4. **링크의 `<a>`와 `<p>` 중첩 순서가 뒤바뀜 (잘못된 중첩)**
   - `broken.html`:
     ```html
     <p>
       <a href="https://map.kakao.com">카카오맵에서 길찾기</p>
     </a>
     ```
     `<p>`를 먼저 열었는데 `<a>`보다 `</p>`를 먼저 닫고, `</a>`가 그 뒤에 나옵니다. 순서가 꼬였습니다.
   - 증상: 링크 영역이 이상하게 잡히거나, 브라우저가 임의로 구조를 고쳐 의도와 다르게 렌더링됩니다.
   - 수정: "마지막에 연 것을 먼저 닫는다" 규칙대로 `<a>...</a>`를 먼저 닫고 그다음 `</p>`:
     ```html
     <p>
       <a href="https://map.kakao.com" target="_blank">카카오맵에서 길찾기</a>
     </p>
     ```

5. **외부 링크에 `target="_blank"`가 없음 (사용성 개선)**
   - 맛집 길찾기 같은 외부 사이트 링크는 새 탭에서 열리는 게 자연스럽습니다. 완성본은 `target="_blank"`를 추가했습니다.

> 핵심 규칙 두 가지만 기억하세요.
> (1) 여는 태그가 있으면 닫는 태그도 반드시 있다.
> (2) 태그는 "나중에 연 것을 먼저 닫는다" — 양말 신고 신발 신었으면, 벗을 땐 신발부터 벗는다.

## 검증법

- `index.html`을 브라우저로 열어 메뉴 표가 2열로 가지런하고, 추천 목록이 3줄로 또렷이 나뉘고, "카카오맵에서 길찾기" 링크가 정상 작동하는지 확인합니다.
- 무료 온라인 검사기 [W3C Markup Validation Service](https://validator.w3.org/#validate_by_input)에 `index.html` 내용을 붙여넣어 오류 0개가 나오는지 확인합니다. (`broken.html`을 같은 곳에 넣으면 위 버그들이 오류로 잡히는 것도 비교해 보세요.)
- VS Code에서 파일을 열면 닫히지 않은 태그에 노란 물결 밑줄이 표시됩니다. 완성본에는 밑줄이 없어야 합니다.
