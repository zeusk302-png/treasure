# 실습 124 — 방명록 키워드 검색창 만들기 (ilike 부분 일치)

실습 123에서 방명록 글을 **정렬(order)** 해서 보여줬습니다.
글이 점점 쌓이면 이번엔 **원하는 단어가 들어간 글만** 찾고 싶어집니다.
게시판·댓글의 **검색창**이 바로 이 기능이죠.

이 실습의 핵심은 `select` 뒤에 딱 한 줄, **`.ilike()`** 를 붙이는 것입니다.

```js
const { data, error } = await db
  .from("guestbook")
  .select("*")
  .ilike("message", `%${word}%`)            // ← 이 한 줄이 검색의 전부!
  .order("created_at", { ascending: false }); // (123에서 배운 정렬도 함께)
```

`.ilike("message", "%안녕%")` 를 한 글자씩 풀면:

- **`message`** : 어느 컬럼에서 찾을지 (메시지 내용 칸에서 찾음)
- **`%안녕%`** : 찾을 패턴. **`%`** 는 "아무 글자나 와도 됨" 이라는 와일드카드라서,
  **앞뒤에 무엇이 오든 '안녕' 이 포함**되기만 하면 일치합니다. → "안녕하세요", "반갑고 안녕" 모두 걸림.
- **`i`** like 의 **i** = **대소문자 무시**. `hello` 로 검색해도 글 속의 `Hello` / `HELLO` 를 찾아 줍니다.

> 비유: 123이 "받아오기 **전에** 줄 세워서 줘"였다면,
> 124는 받아오기 **전에** "이 단어가 든 글만 골라서 줘"라고 서버에 부탁하는 것입니다.
> 거르는 일(검색)을 **우리(브라우저)가 다 받아서 하는 게 아니라 서버(DB)가 대신** 해 줍니다.
> 이걸 **서버 측 필터링**이라고 부릅니다. (필요한 글만 오니 빠르고 가볍습니다.)

이 폴더에 있는 파일:

- `README.md` — 이 안내문
- `schema.sql` — `guestbook` 표 SQL (116~117과 **같은 표**. 이미 만들었으면 다시 실행 안 해도 됨 + 검색 연습용 글 4개 포함)
- `index.html` — **검색창(입력칸 + [검색]/[전체 보기] 버튼)** 과 결과 목록(`ul#list`)이 있는 화면
- `script.js` — **핵심 코드.** `.ilike("message", "%검색어%")` 로 서버에 검색을 부탁합니다.

## 목표

- `.ilike("message", "%검색어%")` 로 **메시지에 검색어가 포함된 글만** 골라 받아온다.
- **`%`(와일드카드)** 의 뜻을 이해한다: `%단어%` = "앞뒤가 무엇이든 단어가 **포함**되면 일치"(부분 검색).
- **`ilike` 의 `i`** = **대소문자 무시**임을 이해한다. (대소문자를 구분하는 `like` 와의 차이)
- 검색어가 **비어 있으면 `.ilike` 를 붙이지 않고 전체**를 보여 주는, 조건부로 쿼리를 조립하는 패턴을 익힌다.
- 검색(거르기)은 **서버(DB)가 해서 보내 준다**(서버 측 필터링)는 점을 이해한다.

## 따라하는 단계

1. **표를 준비한다.** 실습 116~117에서 `guestbook` 표를 이미 만들었다면 건너뛰세요.
   아직 없다면 Supabase 대시보드 → **SQL Editor → New query** 에 이 폴더의 `schema.sql`을
   통째로 붙여넣고 **[Run]** 을 누른다. (이 파일은 서로 다른 단어가 든 검색 연습용 글 4개도 함께 넣어 줍니다.)
2. **검색해 볼 글이 여러 개 있어야 한다.** 글이 1개뿐이면 검색의 '걸러지는' 느낌이 안 납니다.
   1단계의 연습용 글을 넣었거나, 116 폴더로 글을 여러 개 남겼는지 확인하세요.
3. Supabase 대시보드 **Settings(톱니바퀴) → API** 에서 두 값을 복사한다.
   - **Project URL** : `https://xxxxxxxx.supabase.co` 형태의 주소 (비밀 아님)
   - **anon public** 키 (신형은 `sb_publishable_...` 로 시작) : 브라우저에 둬도 되는 **공개 출입증**
   - ⚠️ 같은 화면의 **`service_role` / `sb_secret_...` 키는 절대 쓰지 마세요.** 모든 보안을 무시하는 마스터 키입니다.
4. 이 폴더의 `script.js`를 열고, 맨 위 두 줄의 **자리표시자**를 내 값으로 바꾼다.
   ```js
   const SUPABASE_URL = "https://여기에-내-프로젝트-ID.supabase.co";   // ← 내 Project URL
   const SUPABASE_ANON_KEY = "sb_publishable_여기에-내-anon-공개키-붙여넣기"; // ← 내 anon public 키
   ```
5. `index.html`을 **브라우저로 연다.** (파일을 더블클릭)
   → 페이지가 열리면 먼저 **전체 목록**을 한 번 불러와 보여 줍니다.
6. 검색창에 **`안녕`** 을 입력하고 **[검색]** 버튼(또는 Enter 키)을 누른다.
   → '안녕' 이 **포함된 글만** 남는 걸 확인하세요. (연습용 글 기준: '가나다', '아자차' 의 글)
7. 이번엔 **`hello`** 를 (소문자로) 입력하고 검색한다.
   → 글 속에 대문자로 적힌 **`Hello`** 가 걸리는 걸 확인하세요. (= 대소문자 무시 `i` 의 효과)
8. **[전체 보기]** 버튼을 누른다. → 입력칸이 비워지고 다시 **모든 글**이 보입니다.
9. (이해 점검) `script.js`의 핵심 줄에서 패턴을 바꿔 본다.
   - `` `%${word}%` `` → `` `${word}%` `` 로 바꾸면 → **단어로 시작**하는 글만 걸립니다.
   - `.ilike` 를 `.like` 로 바꾸면 → **대소문자를 구분**하게 되어 `hello` 로는 `Hello` 가 안 걸립니다.
   → 한 글자 차이로 검색 결과가 달라지는 걸 체감하면 성공입니다.

## 검증법

- 검색창에 **`안녕`** 을 넣고 검색하면, 메시지에 '안녕' 이 **들어간 글만** 남는가? ('날씨' 글 등은 사라짐)
- **`hello`** 를 소문자로 검색해도, 글 속 대문자 **`Hello`** 가 결과에 나오는가? (= `ilike` 대소문자 무시 확인)
- **[전체 보기]** 를 누르면 입력칸이 비워지고 **모든 글**이 다시 보이는가?
- 검색 결과가 하나도 없는 단어(예: `존재하지않는단어123`)를 넣으면
  **에러가 아니라** `'...' 가 들어간 글이 없어요` 안내가 뜨는가? (빈 결과 ≠ 에러)
- 여러 번 연달아 검색해도 목록이 **중복으로 쌓이지 않는가?** (`listEl.innerHTML = ""` 동작 확인)
- 브라우저 **개발자 도구 → Console**(윈도우 `F12`, 맥 `Cmd + Option + I`)에
  `🔎 서버에 부탁: ... 가 포함된 글만 보내 줘` 와 `✅ 성공! 서버가 골라서 돌려준 글 N개` 로그가 찍히는가?
  (= 거르는 일을 **서버가 했다**는 증거. 우리가 받은 배열은 이미 걸러진 상태)
- **실패할 때 원인 찾기** (콘솔의 빨간 에러 메시지로 구분):
  - `relation "public.guestbook" does not exist` → 표가 없음. 1단계 `schema.sql`을 실행.
  - `column guestbook.xxx does not exist` → `.ilike()` 의 **컬럼 이름**을 잘못 적음. 검색 대상 컬럼은 `message`.
  - `Invalid API key` → anon 키를 잘못 붙여넣음. (혹시 service_role을 넣지 않았는지도 확인)
  - 주소 오류 / `Failed to fetch` → `SUPABASE_URL`의 철자나 `https://` 확인.
  - **에러는 없는데 검색 결과가 늘 비어 있다?** → 표에 **RLS가 켜져 있는데 "읽기(select) 정책"이 없는** 경우입니다.
    검색어를 무엇으로 바꿔도 받아 올 글 자체가 0개라 늘 비어 보입니다. (정책 거는 법은 실습 119)
- **(안전 점검)** `script.js`에 넣은 키가 **`anon` / `sb_publishable_`** 로 시작하는가? `service_role` / `sb_secret_` 가 **아닌가?**
