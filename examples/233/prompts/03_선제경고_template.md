# 템플릿 3 — 선제 경고 (내가 묻기 전에 위험을 먼저 말해)

> **언제 쓰나요?**
> 새로운 걸 만들기 **시작하기 전에**, 또는 어떤 결정을 내리기 직전에.
> AI는 내가 **묻지 않은 것은 잘 안 알려줍니다.** 그래서 "모르는 걸 모르는"(내가 위험이 있는지조차 모르는) 함정에 빠집니다.
> 이 템플릿은 AI가 **함정·비용·되돌리기 어려운 결정**을 먼저 꺼내 놓게 만듭니다.

---

## 빈칸 채우는 법

- `[[하려는 일]]` — 지금 시작하려는 작업 (예: 방명록에 사진 업로드 기능 추가 / Supabase로 회원 로그인 붙이기 / n8n으로 문의 자동 알림)
- `[[내 수준/제약]]` — 솔직한 내 상태 (예: 비전공자, 무료 요금제만 쓰고 싶음, 혼자 운영)
- `[[가장 두려운 것]]` — 절대 피하고 싶은 사고 (예: 비밀 키 유출 / 남이 내 데이터 삭제 / 갑자기 요금 폭탄)

---

## 복붙용 프롬프트

```
나는 지금 [[하려는 일]] 을 시작하려고 해.
바로 코드부터 주지 말고, 먼저 "내가 묻지 않았지만 알아야 할 것"을 경고해줘.

[내 상황]
- 수준/제약: [[내 수준/제약]]
- 가장 피하고 싶은 사고: [[가장 두려운 것]]

[먼저 말해줄 것 — 코드보다 이게 먼저야]
1. 이 작업에서 "되돌리기 어려운 결정"이 뭐야? (한 번 정하면 바꾸기 힘든 것)
2. 비전공자가 여기서 가장 자주 저지르는 실수 3가지와, 각각의 결과.
3. 보안에서 반드시 지켜야 할 것:
   - 어떤 값이 "비밀(절대 공개 금지)"이고 어떤 값이 "공개해도 되는" 값인지 구분해줘.
     (예: Supabase의 anon 키 vs service_role 키)
   - 그 비밀값이 새어 나가면 무슨 일이 일어나?
4. 돈/요금 관점: 무료 범위를 넘기면 비용이 튀는 지점이 있어?
5. 위 [[가장 두려운 것]] 을 막기 위해 시작 전에 꼭 해둬야 할 한 가지.

[규칙]
- 모르면 "확실하지 않음"이라고 말하고 추측으로 안심시키지 마.
- 위 5가지를 다 말한 다음에야, "그럼 이제 어떻게 시작할까"를 물어봐.
```

---

## 왜 이렇게 시키나요? (비전공자용)

- AI에게 그냥 "만들어줘"라고 하면 **곧장 코드**부터 줍니다. 그런데 진짜 위험(비밀 키 노출, 요금 폭탄, 못 되돌리는 설정)은 그 코드를 **돌리기 전에** 알아야 합니다.
- **"묻지 않았지만 알아야 할 것"** 이라는 한 줄이 핵심입니다. 이게 "모르는 걸 모르는" 함정을 깨는 열쇠입니다.
- **비밀값 vs 공개값 구분**을 매번 물어 버릇하면, 어디에 진짜 키를 적으면 안 되는지가 몸에 뱁니다.
  - 안전 수칙: 어떤 템플릿에도 **진짜 키·토큰·웹훅 주소를 적지 마세요.** 항상 `REPLACE_WITH_...`, `YOUR_API_KEY` 같은 자리표시자로 둡니다.
