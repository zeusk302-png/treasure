# 실습 233 — 재사용 프롬프트 템플릿 라이브러리(3종) 정리하기

자주 쓰는 AI 지시를 매번 새로 짜지 말고, **빈칸만 채워 복붙하는 템플릿**으로 만들어 두는 실습입니다. 코드는 없고, `prompts/` 폴더 안에 세 가지 상황별 템플릿(마크다운 글)이 들어 있습니다. AI에게 더 정확하고 안전하게 일을 시키는 "말 거는 법"을 손에 익히는 게 목적입니다.

이 폴더에 담긴 3종 템플릿은 다음과 같습니다.

| 파일 | 이름 | 언제 쓰나 |
|---|---|---|
| `prompts/01_검증요구_template.md` | 검증 요구 | AI가 "완벽합니다 / 잘 됩니다"라고 단정할 때, 증거를 가져오게 되받아칠 때 |
| `prompts/02_비판리뷰_template.md` | 비판 리뷰 | 내(또는 AI) 코드·글을 칭찬 빼고 깐깐하게 두들겨 보고 싶을 때 |
| `prompts/03_선제경고_template.md` | 선제 경고 | 뭔가 만들기 **시작하기 전에**, 함정·비용·되돌리기 어려운 결정을 먼저 듣고 싶을 때 |

## 목표
- 자주 쓰는 AI 지시를 **빈칸형 템플릿**으로 만들어, 상황이 올 때마다 복붙해 재사용하는 습관을 들인다.
- 세 가지 상황(검증 요구 / 비판 리뷰 / 선제 경고)에서 각각 어떤 식으로 AI에게 지시하면 더 정확하고 안전한 답이 나오는지 체감한다.
- 템플릿의 `[[...]]` 빈칸을 내 상황에 맞게 바꿔 끼우는 연습을 한다.

## 따라하는 단계
1. `prompts/` 폴더를 열어 세 개의 `.md` 파일을 메모장(또는 VS Code)으로 하나씩 읽어 봅니다. 각 파일 맨 위의 "언제 쓰나요?" 설명부터 봅니다.
2. 파일 안의 **"빈칸 채우는 법"** 항목을 보고, `[[무엇]]`, `[[성공의 기준]]` 같은 `[[...]]` 칸에 무엇을 넣어야 하는지 확인합니다.
3. **"복붙용 프롬프트"** 안의 텍스트를 통째로 복사한 뒤, `[[...]]` 칸만 내 실제 상황에 맞게 바꿔 채웁니다. (예: `[[무엇]]` → "방금 받은 회원가입 폼 코드")
4. 채운 프롬프트를 AI(Claude 등)에 붙여넣고, 답이 평소보다 더 구체적이고 깐깐하게 나오는지 비교해 봅니다.
5. 세 템플릿을 모두 한 번씩 직접 써 보고, 내가 자주 쓰는 다른 상황이 있다면 같은 형식(언제 쓰나 → 빈칸 → 복붙용 프롬프트)으로 4번째 템플릿을 추가로 만들어 봅니다.
6. 안전 수칙: 어떤 템플릿에도 **진짜 키·토큰·웹훅 주소를 적지 마세요.** 항상 `YOUR_API_KEY` 같은 자리표시자로 둡니다.

## 🤖 바이브코딩 프롬프트
이 실습(상황별 재사용 프롬프트 템플릿 라이브러리)을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. `[[...]]` 칸만 내 상황으로 바꿔 끼우세요.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 비전공자에게 "AI에게 일 시키는 법"을 가르치는 강사야.
  내가 자주 쓰는 AI 지시를 매번 새로 짜지 않게, 빈칸만 채워 복붙하는
  "재사용 프롬프트 템플릿" 3종을 마크다운(.md) 파일로 만들어줘.

  [만들 3종]
  1) 검증 요구 — AI가 "완벽합니다/잘 됩니다"라고 단정할 때 증거를 가져오게 되받아치는 템플릿
  2) 비판 리뷰 — 칭찬 빼고 코드·글을 깐깐하게 두들겨 보게 하는 템플릿
  3) 선제 경고 — 만들기 시작하기 전에 함정·비용·되돌리기 어려운 결정을 먼저 듣는 템플릿

  [각 .md 파일의 공통 구조 — 이 순서를 꼭 지켜]
  - 맨 위: "언제 쓰나요?" (이 템플릿을 쓰는 상황 2~3줄)
  - "빈칸 채우는 법": [[무엇]], [[성공의 기준]] 같은 [[...]] 칸이 뭘 뜻하는지 설명
  - "복붙용 프롬프트": ```로 감싼, 통째로 복사할 수 있는 본문 (안에 [[...]] 빈칸 포함)
  - "왜 이렇게 시키나요? (비전공자용)": 이 템플릿이 왜 효과 있는지 풀어 설명

  [제약]
  - 독자는 비전공자야. 어려운 용어는 풀어서, 비유를 곁들여 써줘.
  - 어떤 템플릿에도 진짜 키·토큰·웹훅 주소를 넣지 말고 YOUR_API_KEY 같은 자리표시자만 써.

  [산출물]
  - prompts/01_검증요구_template.md
  - prompts/02_비판리뷰_template.md
  - prompts/03_선제경고_template.md
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 3종 템플릿을 더 단단하게 다듬어줘.

  1) 각 "복붙용 프롬프트" 안에, AI가 추측으로 안심시키지 못하게
     "확실하지 않으면 '확실하지 않음'이라고 솔직히 말해" 규칙을 한 줄씩 넣어줘.
  2) 비판 리뷰 템플릿에는 비전공자가 가장 자주 놓치는 보안 점검 항목을 추가해줘:
     - 비밀 키(service_role 등)가 프론트엔드 코드에 노출됐는지
       (프론트엔드엔 공개용 anon 키만, DB 테이블엔 RLS가 켜져 있어야 함)
     - 사용자 입력을 그대로 innerHTML에 넣어 XSS 위험이 있는지
  3) 내가 자주 쓰는 4번째 상황(예: "이 글을 초등학생도 알게 쉽게 풀어줘")도
     같은 구조(언제 쓰나 → 빈칸 → 복붙용 프롬프트 → 왜)로 하나 더 만들어줘.
  4) 각 템플릿 맨 아래에 연결 가이드 링크 줄을 달아, 왜 이 템플릿이 필요한지
     본문 페이지로 이어지게 해줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  내가 만든 프롬프트 템플릿을 실제 AI에 넣었는데 기대와 다르게 동작해.
  아래 [상황]을 보고 무엇이 문제인지 단계별로 진단해줘.

  [상황]
  - 내가 쓴 프롬프트: (여기에 [[...]] 채운 실제 프롬프트를 붙여넣기)
  - 기대한 답: (예: 증거·체크리스트가 나오길 바람)
  - 실제로 나온 답: (예: 또 "완벽합니다"만 함 / 빈칸 [[...]]을 그대로 따라 출력함)

  [진단 순서]
  1) 내 프롬프트에서 AI가 빠져나갈 "구멍"(애매한 지시, 안 박힌 성공 기준)을 짚어줘.
  2) 그 구멍을 메우려면 어느 문장을 어떻게 고쳐야 하는지 "전 → 후"로 보여줘.
  3) 고친 프롬프트 전체를 다시 한 번 통째로 줘. (바로 복붙하게)
  4) 확실하지 않은 부분은 "확실하지 않음"이라고 표시해.
  ```
> 프롬프트 팁: 위 어느 프롬프트든 끝에 **"코드(또는 템플릿)만 주지 말고, 왜 그렇게 했는지 한 줄씩 주석/설명으로 풀어줘"**를 덧붙이면, 결과를 그냥 받기만 하지 않고 *왜 그런지*까지 배우게 되어 학습에 좋습니다.

## 검증법
- `prompts/` 폴더 안에 템플릿 파일이 **3개** 들어 있는가? (검증 요구 / 비판 리뷰 / 선제 경고)
- 각 템플릿에 **"언제 쓰나요?" → "빈칸 채우는 법" → "복붙용 프롬프트"** 세 부분이 모두 들어 있는가?
- 복붙용 프롬프트에 `[[...]]` 형태의 **빈칸**이 남아 있어, 내 상황만 바꿔 끼우면 바로 쓸 수 있는가?
- 실제로 한 템플릿을 골라 빈칸을 채워 AI에 넣었을 때, 칭찬·단정 대신 **증거·지적·경고** 같은 더 단단한 답이 돌아오는가?
