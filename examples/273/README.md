# 챗봇 대화 기록을 Supabase에 저장하고 다시 불러오기

대부분의 챗봇 데모는 새로고침하면 대화가 **싹 사라집니다.** 이번 실습에서는 대화 한 줄 한 줄을 **데이터베이스(Supabase)** 에 저장해서, 새로고침하거나 내일 다시 와도 **이전 대화가 그대로 보이게** 만듭니다.

그리고 한 걸음 더 나아가, AI에게 답을 받을 때 **방금 질문 하나만** 보내는 게 아니라 **최근 대화 맥락(history)을 함께** 보냅니다. 그래야 "아까 그거 다시 설명해줘" 같은 말을 AI가 알아듣습니다. 이걸 **컨텍스트(맥락) 유지**라고 부릅니다.

> 비유: 메모 없이 대화하면 상대는 1분 전에 한 말도 잊습니다. 대화를 적어 두고(저장) 매번 같이 보여 주면(맥락 전달), 비로소 "이어지는 대화"가 됩니다. AI도 똑같습니다.

## 목표

- 대화 한 줄(사람/AI 메시지)을 **Supabase 테이블에 저장**하고, 페이지를 열 때 **시간순으로 다시 불러와 복원**한다.
- 로그인 없이도 **사용자별로 대화를 구분**하는 방법(`user_key`)을 이해한다.
- AI에게 **최근 맥락(messages 배열)을 함께 전달**해 대화가 이어지게(컨텍스트 유지) 만든다.
- AI API 키 같은 **비밀값은 브라우저에 두지 않고**, n8n 웹훅이 대신 호출하게 한다는 원칙을 익힌다.

## 따라하는 단계

1. [supabase.com](https://supabase.com)에서 프로젝트를 만든다. (부트캠프에서 한 것과 동일)
2. 왼쪽 메뉴 **SQL Editor**를 열고, 이 폴더의 `schema.sql` 전체를 붙여넣은 뒤 **[Run]** 한다. → `chat_messages` 테이블과 RLS 정책이 생긴다.
3. **Settings → API**에서 `Project URL`과 `anon`(공개) 키를 복사한다.
4. `config.js`를 열어 `SUPABASE_URL`, `SUPABASE_ANON_KEY` 두 값을 내 값으로 바꾼다. (`REPLACE_WITH_YOUR_ANON_PUBLIC_KEY` 자리를 내 anon 키로)
5. `index.html`을 브라우저로 연다. 메시지를 2~3개 보낸다.
   - 아직 AI 웹훅을 안 붙였다면 봇은 **"메아리 모드"** 로 답합니다. 이 상태로도 **저장·복원** 실습은 완전히 됩니다.
6. **새로고침** 한다. → 방금 나눈 대화가 그대로 다시 보이면 저장·복원 성공이다.
7. (선택) **진짜 AI 답 붙이기.** n8n에서 Webhook → AI(Claude) → Respond to Webhook 으로 이어지는 워크플로우를 만들고(213번 실습 참고), 그 **Production URL**을 `config.js`의 `AI_WEBHOOK_URL`에 넣는다.
   - 브라우저는 `{ "messages": [...최근 대화...] }` 를 웹훅으로 보내고, n8n은 `{ "reply": "..." }` 를 돌려준다고 약속한다.
   - **AI API 키는 n8n 자격증명 금고에만** 두고, `config.js`에는 절대 적지 않는다. (`config.js`에는 웹훅 주소까지만)

## 🤖 바이브코딩 프롬프트

이 실습(대화 기록 저장 + 복원 + 맥락 유지 챗봇)을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. 윗단계에서 받은 코드를 다음 단계 프롬프트에 함께 붙여넣으면 이어집니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 비전공자도 따라할 수 있게 설명하는 웹개발 도우미야.
  목표: 단일 index.html 챗봇 화면을 만들어줘.
  요구사항:
  - 위에 제목, 가운데 대화 로그 영역(#log), 아래 입력창+보내기 버튼 form.
  - 사용자 메시지는 오른쪽, 봇 메시지는 왼쪽 말풍선으로 표시.
  - 아직 저장 기능은 없어도 돼. 일단 입력하면 화면에만 말풍선이 쌓이게.
  제약:
  - 사용자가 친 글자는 innerHTML이 아니라 textContent로 출력해줘(XSS 방지).
  - CSS는 한 파일 안 <style>에 간단히. 외부 라이브러리는 아직 쓰지 마.
  산출물: 완성된 index.html 한 개. 코드만 주지 말고 왜 그렇게 했는지 한국어 주석으로 설명해줘.
  ```

- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  위 챗봇에 "대화 저장·복원"과 "맥락 유지"를 붙여줘.
  - Supabase(@supabase/supabase-js CDN)에 chat_messages 테이블(user_key, role, content, created_at)로 저장.
  - 로그인은 없어. 대신 브라우저마다 임의의 user_key를 만들어 localStorage에 저장하고, 그 키로 내 대화만 구분해줘.
  - 페이지를 열면 내 user_key의 대화를 created_at 시간순으로 불러와 화면에 다시 그려줘(복원).
  - AI에게 답을 받을 땐 방금 질문 하나만 보내지 말고 최근 12개 대화(messages 배열)를 함께 보내(컨텍스트 유지).
  - AI 호출은 fetch로 n8n 웹훅 주소(AI_WEBHOOK_URL)에 POST. 웹훅이 비어 있으면 "메아리 모드"로 대신 답하게 해줘.
  보안: Supabase URL·anon 키·웹훅 주소만 config.js에 두고, AI API 키는 코드에 절대 넣지 마. 왜 그런지 주석으로 적어줘.
  같이 만들어 줄 것: 위 테이블과 RLS 정책을 만드는 schema.sql 도.
  ```

- **막혔을 때(디버깅)** 프롬프트:
  ```text
  새로고침하면 이전 대화가 안 보이고, F12 콘솔에 아래 빨간 에러가 떠.
  (여기에 콘솔 에러 메시지를 그대로 붙여넣기)
  내 상황: index.html / config.js / schema.sql 은 이 실습 그대로야.
  한 번에 고치려 하지 말고, 원인 후보를 가능성 높은 순서로 단계별로 짚어줘:
  1) config.js의 SUPABASE_URL·anon 키가 내 값으로 바뀌었는지 확인하는 법
  2) schema.sql을 정말 실행해서 chat_messages 테이블·RLS 정책이 생겼는지 확인하는 법
  3) 저장(insert)·불러오기(select)가 RLS 정책에 막히는지 확인하는 법(Network 탭에서 보는 법 포함)
  각 단계마다 "이걸 어떻게 눈으로 확인하는지"를 비전공자도 알 수 있게 알려줘.
  ```

> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 코드를 그냥 받는 게 아니라 배우면서 만들 수 있습니다.

## 검증법

- **저장되는가:** 메시지를 보낸 뒤 Supabase 대시보드 → **Table Editor → chat_messages** 에 `role`(user/assistant)과 `content`가 한 줄씩 쌓이는가?
- **복원되는가(핵심):** 대화 후 **새로고침**해도 이전 대화가 시간순으로 그대로 보이는가? 브라우저를 껐다 켜도 유지되는가?
- **사용자별 구분:** 화면 위쪽 `내 대화 키`(`user_...`)를 확인한다. 다른 브라우저(또는 시크릿 창)로 열면 **다른 키 → 빈 대화**로 시작한다(서로의 대화가 섞이지 않음).
- **맥락 전달:** F12 → **Network(네트워크)** 탭을 열고 메시지를 보낸다. 웹훅 요청의 본문(payload)에 방금 질문 하나가 아니라 **최근 여러 줄(messages 배열)** 이 들어 있는지 확인한다.
- **오류 없음:** 정상 흐름에서 F12 → Console에 빨간 오류가 없어야 한다.

!!! danger "절대 하지 말 것"
    `config.js`에 넣는 Supabase 키는 **anon(공개) 키**여야 합니다. `service_role`(secret) 키는 **RLS를 통째로 우회**하므로 브라우저·GitHub에 두면 누구나 모든 대화를 읽고 지울 수 있습니다. 그리고 **AI API 키(Anthropic 등)는 브라우저 코드에 절대 두지 않습니다** — 화면에 두는 순간 누구나 내 키로 AI 비용을 쓸 수 있습니다. 비밀값은 반드시 **n8n 자격증명 금고**(또는 서버)에만 두고, 코드에는 `REPLACE_WITH_...` 자리표시자만 둡니다.

## 이 폴더의 파일

- `index.html` — 챗봇 화면 + 저장/복원/맥락전달 로직(완성형)
- `config.js` — 공개돼도 되는 값(Supabase URL·anon 키·웹훅 주소)만 담는 분리 파일
- `schema.sql` — `chat_messages` 테이블과 RLS 정책을 만드는 SQL
