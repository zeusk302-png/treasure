# 폼 제출 내용을 구글 시트에 누적 저장하기

앞 실습(205)에서는 문의 폼이 제출되면 **슬랙으로 알림**이 오게 만들었습니다. 그런데 알림은 그때그때 보고 지나가면 끝입니다. 한 달 뒤 "그동안 문의가 몇 건이나 왔지?"를 보려면 **어딘가에 차곡차곡 쌓아 두는 장부**가 필요합니다. 이번 실습은 바로 그 장부 — **구글 시트** — 를 한 갈래 더 붙입니다.

핵심 아이디어는 **다중 출력 분기(멀티 액션)** 입니다. 폼에서 들어온 **하나의 데이터**를, 정리한 다음 **여러 곳으로 동시에 흘려보냅니다.** 이번엔 세 곳입니다.

```
[문의 받기 Webhook] → [문의 내용 정리하기 Set] ┳━▶ [슬랙으로 알림 보내기]      (사람에게 바로 알림)
                                                ┣━▶ [구글 시트에 저장]          (장부에 한 줄 누적)
                                                ┗━▶ [폼에 응답 돌려주기]        ("잘 받았어요" 영수증)
```

> **비유:** 우체통(Webhook)이 편지를 받으면, 비서가 내용을 깔끔히 옮겨 적은 뒤(Set) 같은 내용을 **세 장 복사**해서 ① 한 장은 단체 채팅방에 붙이고(Slack), ② 한 장은 장부에 끼워 보관하고(Sheets), ③ 한 장은 "잘 받았습니다" 영수증으로 보낸 사람에게 돌려줍니다(Respond). 비서를 한 명 더 늘린 게 아니라, **복사본을 한 장 더 만들어 새 서랍(시트)에 넣은 것**입니다.

> **이 폴더에는 두 덩어리가 들어 있습니다.**
> - **사이트:** `index.html` + `style.css` + `script.js` — 205와 똑같은 문의 폼 (Vercel에 올릴 페이지). 폼이 보내는 데이터는 바뀌지 않았습니다.
> - **워크플로우:** `workflow.json` — n8n에 불러올 자동화 (노드 5개). 205의 워크플로우에 **`구글 시트에 저장 (Google Sheets)` 노드 하나가 분기로 추가**된 것입니다.

## 목표

- 들어온 폼 데이터를 **여러 노드로 동시에 분기**해 보내는 '다중 출력(멀티 액션)' 구조를 이해한다.
- Google Sheets **`Append Row`(행 추가)** 노드를 Webhook 워크플로우에 붙여, 문의가 시트에 **한 줄씩 누적**되게 만든다.
- 같은 데이터를 알림(Slack)과 저장(Sheets)에 **나란히** 보낼 수 있다는 것(둘은 서로를 기다리지 않는 별개의 갈래)을 체감한다.
- 어떤 값이 **공개돼도 되는 값(문서 ID·머리글)** 이고 어떤 값이 **절대 새면 안 되는 비밀값(구글 인증 토큰)** 인지 구분한다.

## 따라하는 단계

1. **(처음이라면) 205 먼저.** 이 실습은 205의 워크플로우 위에 시트 저장을 한 갈래 더 얹는 것입니다. 205를 아직 안 했다면 `../205/README.md`를 먼저 보고 와도 좋습니다. 이미 했다면 그 워크플로우에 4번 노드만 추가하면 됩니다.
2. **저장할 구글 시트 준비.** 구글 드라이브에서 새 스프레드시트를 만들고 **첫 행(머리글)** 에 왼쪽부터 `받은시각`, `이름`, `이메일`, `메시지` 4칸을 정확히 입력합니다. (이 머리글 이름이 워크플로우의 컬럼 이름과 한 글자도 틀리지 않아야 자동으로 짝이 맞습니다.) 그리고 브라우저 주소창에서 **문서 ID**를 복사해 둡니다. 주소 `.../spreadsheets/d/`**`여기가_문서ID`**`/edit` 의 가운데 긴 문자열입니다.
3. **n8n에 워크플로우 올리기.** n8n 오른쪽 위 `...`(점 3개) → **`Import from File`** 로 이 폴더의 **`workflow.json`** 을 불러옵니다. 노드 5개가 나타나고, `Set` 노드에서 화살표 **세 개**가 갈라져 나가는 것을 확인합니다.
4. **구글 시트 노드 연결하기.** `구글 시트에 저장 (Google Sheets)` 노드를 더블클릭합니다.
   - **`Credential to connect with`** → `Create New Credential` → `Sign in with Google` 로 내 구글 계정에 로그인해 시트 권한을 허용합니다. 이렇게 발급된 **인증 토큰이 비밀값**이며, n8n 자격증명 금고에만 저장됩니다. (파일에는 자리표시자 `REPLACE_WITH_YOUR_GOOGLE_SHEETS_CREDENTIAL_ID` 가 들어 있습니다.)
   - **`Document`** 에서 2번에서 만든 시트를 고릅니다. (파일에는 자리표시자 `REPLACE_WITH_YOUR_SHEET_DOCUMENT_ID` 가 들어 있으니 반드시 내 시트로 다시 고릅니다.)
   - **`Sheet`** 는 `시트1`(첫 번째 탭), **`Operation`** 은 `Append Row`(행 추가)인지 확인합니다. **`Mapping`** 에서 `받은시각/이름/이메일/메시지` 4칸이 각각 `{{ $json.받은시각 }}` 식으로 연결돼 있는지 봅니다.
5. **슬랙 노드도 연결하기(205와 동일).** `슬랙으로 알림 보내기 (Slack)` 노드의 `Credential`에 슬랙 봇 토큰(`xoxb-`) 자격증명을 연결하고, `Channel`을 내 채널로 고릅니다. (메일로 받고 싶으면 이 Slack 노드를 `Send Email`(SMTP) 노드로 바꾸고 본문을 `{{ $json.슬랙알림문구 }}` 로 연결하면 됩니다.)
6. **Webhook 주소를 사이트에 붙여넣기.** `문의 받기 (Webhook)` 노드에서 캔버스 아래 **`Listen for test event`** 를 누른 뒤 보이는 **Test URL을 복사**합니다. `script.js` 맨 위의
   ```js
   const WEBHOOK_URL = "REPLACE_WITH_YOUR_N8N_WEBHOOK_URL";
   ```
   따옴표 안을 그 주소로 바꿉니다.
7. **테스트.** 이 폴더의 `index.html` 을 브라우저로 열어(또는 VS Code Live Server로) 폼을 채우고 `보내기`를 누릅니다.
8. **운영용 전환 + 배포.** 잘 되면 n8n 오른쪽 위 **`Active`(활성) 토글**을 켜고, `script.js`의 `WEBHOOK_URL` 을 항상 살아 있는 **Production URL**(`/webhook/contact-form`)로 바꿉니다. 사이트 파일을 GitHub에 올려 Vercel로 배포하면 완성입니다.

## 🤖 바이브코딩 프롬프트

이 실습(폼 → n8n → 슬랙+구글시트 다중 분기)을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. 한 번에 다 시키지 말고 **1단계 → 2단계 → (막히면) 디버깅** 순서로 끊어서 시키는 것이 핵심입니다.

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 비전공자를 돕는 웹/자동화 멘토야. 정적 HTML 문의 폼 페이지 하나를 만들어 줘.
  - 파일: index.html, style.css, script.js 세 개로 분리
  - 폼 입력: 이름(필수, 2자 이상), 이메일(필수, type=email), 문의 내용(필수, 5자 이상), 보내기 버튼
  - script.js: 제출 시 새로고침을 막고(preventDefault), 브라우저 기본 검증을 통과하면
    { name, email, message } JSON을 const WEBHOOK_URL 주소로 fetch POST 한다.
  - WEBHOOK_URL 값은 일단 "REPLACE_WITH_YOUR_N8N_WEBHOOK_URL" 자리표시자로 둔다(실제 주소는 내가 나중에 넣음).
  - 보내는 동안 버튼을 잠그고 "보내는 중..."을, 성공/실패 시 초록/빨강 상태 문구를 보여 줘.
  - 사용자에게 보이는 텍스트는 innerHTML 말고 textContent로 출력해(XSS 방지).
  중요: 코드만 주지 말고 각 줄이 무엇을 하고 왜 그렇게 했는지 한국어 주석으로 설명해 줘.
  ```

- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  좋아. 이제 이 폼을 받을 n8n 워크플로우 JSON을 만들어 줘. 노드는 5개야.
  1) Webhook(POST, path=contact-form, responseMode=responseNode, Allowed Origins=*)
  2) Set 노드: body.name/email/message를 이름/이메일/메시지로 정리하고,
     받은시각({{ $now.format('yyyy-MM-dd HH:mm:ss') }})과 슬랙알림문구 필드도 만든다.
  3~5) Set 노드 하나에서 화살표를 '세 갈래'로 동시에 분기해서:
     - Slack 노드(메시지 post)로 알림
     - Google Sheets 노드(operation=append)로 받은시각/이름/이메일/메시지 4칸을 한 줄 추가
     - Respond to Webhook 노드로 { ok:true } 영수증을 폼에 돌려준다
  비밀값 규칙: 슬랙 봇 토큰과 구글 OAuth 토큰은 JSON에 절대 박지 말고
  credential id는 REPLACE_WITH_... 자리표시자로 둬. 문서 ID도 자리표시자로.
  왜 이렇게 분기하는지, 어떤 값이 공개고 어떤 값이 비밀인지 주석/설명으로 풀어 줘.
  ```

- **막혔을 때(디버깅)** 프롬프트:
  ```text
  폼은 "전송에 실패했습니다"가 뜨고, 슬랙 알림은 오는데 구글 시트에만 한 줄도 안 쌓여.
  (또는: 시트에 새 줄로 안 쌓이고 같은 줄을 덮어써.)
  내 script.js와 workflow.json은 아래에 붙일게. 비전공자도 알아듣게,
  의심 가는 원인을 가능성 높은 순서로 하나씩 짚고 "어디를 어떻게 확인/수정"하면 되는지
  단계별로 알려 줘. 특히 시트 머리글 이름과 컬럼 이름 일치, Operation이 Append인지,
  Document/Credential이 자리표시자 그대로인지, Webhook이 켜져 있는지(CORS 포함)를 점검해 줘.
  [여기에 script.js / workflow.json 내용과 에러 메시지를 붙여넣기]
  ```

> 프롬프트 팁: 어떤 단계든 끝에 **"코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"** 를 덧붙이면, 결과를 그대로 쓰지 않고 직접 검증하는 '디렉터' 연습이 됩니다.

## 검증법

1. **시트에 한 줄 쌓이는지(이번 실습의 핵심 증거):** 폼을 한 번 제출한 뒤 **구글 시트**를 봅니다. 머리글 아래에 아래처럼 한 행이 추가돼 있으면 성공입니다. **두 번 제출하면 두 줄**로 쌓이는지도 확인하세요(누적).
   ```
   받은시각              | 이름   | 이메일             | 메시지
   2026-06-18 14:30:11  | 홍길동 | hong@example.com  | 강의 일정이 궁금합니다.
   ```
2. **슬랙 알림도 같이 오는지(분기 확인):** 같은 제출에 대해 슬랙 채널에도 알림이 올라옵니다. **시트 저장과 슬랙 알림이 한 번의 제출로 둘 다** 일어나면, 다중 출력 분기가 제대로 동작하는 것입니다.
3. **n8n 실행 기록 확인:** `Executions`(실행) 탭에 방금 제출이 초록색으로 기록되고, 노드 5개(Webhook → Set → Slack / Sheets / Respond)에 모두 체크가 떠 있는지 봅니다. `Set` 노드 다음에 세 갈래가 모두 실행됐는지 확인합니다.
4. **폼 화면 응답 확인:** 폼 아래 상태 메시지가 초록색 "정상적으로 접수되었습니다" 로 바뀌고 입력칸이 비워지면, `Respond to Webhook`이 영수증을 잘 돌려준 것입니다.
5. **흔한 실패 네 가지:**
   - 슬랙은 오는데 **시트에만 안 쌓임** → 머리글 이름(`받은시각/이름/이메일/메시지`)이 워크플로우 컬럼 이름과 다르거나, `Document`/`Sheet`가 자리표시자 그대로일 때입니다. 머리글 글자를 정확히 맞추세요.
   - **시트 노드에서 권한 오류** → 구글 자격증명을 다시 로그인해 연결하거나, 그 구글 계정이 해당 시트의 **편집 권한**을 가졌는지 확인하세요.
   - **시트에 두 줄이 아니라 같은 줄을 덮어씀** → `Operation`이 `Update`가 아니라 **`Append Row`(행 추가)** 인지 확인하세요. Append여야 매번 새 줄로 쌓입니다.
   - **폼에서 빨간 "전송에 실패했습니다"** / 콘솔 `CORS` 에러 → 205와 동일합니다. `script.js`의 `WEBHOOK_URL`이 자리표시자인지, `Listen for test event`(테스트)나 `Active`(운영)를 켰는지, Webhook의 `Allowed Origins`가 `*`인지 확인하세요.

## 보안 — 어떤 값이 공개고, 어떤 값이 비밀인가

이번 실습엔 성격이 다른 값들이 한데 모입니다. 이 구분이 자동화 보안의 핵심입니다.

- **공개돼도 되는 값(노드/사이트 코드에 그대로 둬도 됨):**
  - **Webhook 주소(`script.js`):** 누구나 볼 수 있는 '받는 창구'. 브라우저 코드라 어차피 숨길 수 없고, 주소를 안다고 남이 내 슬랙·시트를 직접 건드릴 수는 없습니다(토큰은 n8n 안에만 있으니까). 성격상 Supabase의 **`anon`(공개) 키**와 같습니다.
  - **시트 문서 ID·머리글 이름(`workflow.json`):** 문서 ID는 '주소'에 가까워서, 시트를 비공개로 두면 ID를 알아도 권한 없는 사람은 열거나 쓸 수 없습니다. 그래서 파일에 적어도 괜찮습니다.
- **절대 새면 안 되는 비밀값(반드시 `Credentials` 금고에):**
  - **슬랙 봇 토큰(`xoxb-...`)** 과 **구글 OAuth 인증 토큰.** 이 둘을 가진 사람은 내 워크스페이스에 글을 쓰거나, 내 구글 계정으로 시트를 읽고 쓸 수 있습니다. 그래서 사이트 코드나 `workflow.json`에 **절대** 적지 않고, n8n의 **`Credentials`(자격증명) 금고**에만 저장합니다. 노드에서는 "내 Slack 봇", "내 구글 계정" 이라는 **이름표만** 고를 뿐, 실제 토큰은 `workflow.json`에 들어가지 않습니다. 성격상 Supabase의 **`service_role`(비밀) 키**와 같은 급으로 다뤄야 합니다.

> **그래서 이 파일들의 비밀 자리에는 자리표시자만 들어 있습니다.** `script.js`의 주소는 `REPLACE_WITH_YOUR_N8N_WEBHOOK_URL`, `workflow.json`의 슬랙 자격증명 id는 `REPLACE_WITH_YOUR_SLACK_CREDENTIAL_ID`(채널은 가짜 ID `C0000000000`), 구글 자격증명 id는 `REPLACE_WITH_YOUR_GOOGLE_SHEETS_CREDENTIAL_ID`, 문서 ID는 `REPLACE_WITH_YOUR_SHEET_DOCUMENT_ID`입니다. **진짜 `xoxb-` 토큰이나 구글 로그인 토큰을 사이트 코드나 파일 본문에 직접 적는 일은 절대 하지 마세요.**

> **한 줄 원칙:** 받는 창구 주소·시트 문서 ID·머리글은 코드/노드에 공개해도 되지만, 슬랙 토큰·구글 인증 토큰 같은 진짜 비밀은 n8n 금고(서버) 안에만 둔다.

## 핵심만 짚기 (디렉터 관점)

- **분기는 '복사본을 더 만드는 것'입니다.** 한 데이터에서 화살표를 여러 개 빼면, 같은 데이터가 각 노드에 **각자 복사본**으로 동시에 전달됩니다. 알림(Slack)과 저장(Sheets)은 서로를 기다리지 않는 **별개의 갈래**입니다. 그래서 한쪽(슬랙)이 잠깐 실패해도 다른 쪽(시트)은 그대로 진행됩니다.
- **부품을 끼우고 빼는 감각.** 205는 노드 4개, 206은 거기에 시트 노드 1개를 더 붙인 5개일 뿐입니다. '메일도 받고 싶다', 'Notion에도 저장하고 싶다' 면 같은 자리에 화살표를 하나 더 빼서 노드를 끼우면 됩니다. **구조는 그대로, 부품만 늘어납니다.**
- **알림은 흘러가고, 저장은 남습니다.** 둘은 목적이 다릅니다. 즉시 대응은 알림으로, 나중에 돌아볼 기록은 저장으로 — 그래서 둘 다 두는 게 실무 기본값입니다.
