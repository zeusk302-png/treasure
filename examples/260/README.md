# RLS 정책으로 '작성자만 자기 글 수정·삭제' 막기

게시판에 **행 수준 보안(RLS, Row Level Security)** 을 걸어, 로그인한 사람이 **자기 글만** 수정·삭제할 수 있게 만드는 미니 실습입니다.
앞 실습(259)에서 "**누구냐(인증)**"를 로그인으로 정했다면, 여기서는 "**그 사람이 이 글을 건드려도 되냐(인가)**"를 데이터베이스가 직접 판단하게 만듭니다.

> 비유: 로그인은 건물 **출입증**입니다. 출입증이 있다고 아무 사무실이나 들어가도 되는 건 아니죠.
> RLS 정책은 **"이 방(행)은 주인만 들어올 수 있어요"** 라고 붙여 둔 문 앞 규칙입니다.
> 화면에서 버튼을 숨기는 건 "문에 안내문 붙이기"일 뿐이고, **진짜 잠금장치는 데이터베이스(RLS)** 입니다.

## 목표

- 테이블에 `user_id`(글 주인 도장)를 두고, `posts` 테이블의 **RLS를 켠다**.
- `auth.uid() = user_id` 조건으로 **수정(update)·삭제(delete)는 작성자 본인만** 되도록 정책을 건다.
- 화면용 버튼 숨김(겉보기 가드)과 **DB의 RLS(진짜 차단)** 의 차이를 몸으로 확인한다.
- **anon(공개) 키는 둬도 되지만, service_role(비밀) 키는 RLS를 무시하므로 절대 프론트에 두지 않는다**는 원칙을 익힌다.

## 따라하는 단계

1. [supabase.com](https://supabase.com)에서 프로젝트를 만듭니다. (앞 실습에서 한 것과 동일)
2. 왼쪽 메뉴 **SQL Editor**를 열고, 이 폴더의 `schema.sql` 전체를 붙여넣은 뒤 **[Run]** 합니다. → `posts` 테이블과 RLS 정책 4종이 생깁니다.
3. **Authentication → Providers → Email**이 켜져 있는지 확인합니다. (실습 편의를 위해 "이메일 인증(Confirm email)"을 꺼 두면 가입 직후 바로 로그인할 수 있습니다.)
4. **Settings → API**에서 `Project URL`과 `anon`(공개) 키를 복사합니다.
5. `index.html` 위쪽의 `SUPABASE_URL`, `SUPABASE_ANON_KEY` 두 값을 내 값으로 바꿉니다. (`REPLACE_WITH_YOUR_ANON_PUBLIC_KEY` 자리를 내 anon 키로)
6. `index.html`을 브라우저로 엽니다. 이메일·비밀번호로 **가입 → 로그인**하고, 글을 2개 정도 올립니다. 내 글에는 **[내 글] 배지와 수정·삭제 버튼**이 보입니다.
7. **다른 계정으로 테스트(핵심)**: 로그아웃 → 다른 이메일로 새로 가입·로그인합니다. 이제 아까 쓴 글에는 **수정·삭제 버튼이 보이지 않습니다.**

## 검증법

- **본인 글만 버튼 보임**: 로그인한 계정이 쓴 글에만 수정·삭제 버튼이 나타난다(겉보기 가드).
- **RLS 진짜 차단(가장 중요)**: 화면 가드를 우회해도 DB가 막는지 확인합니다.
  1. 계정 B로 로그인한 상태에서 F12 → **Console** 탭을 엽니다.
  2. 계정 A가 쓴 글의 `id`(예: 1번)를 골라, 아래를 입력해 직접 삭제를 시도합니다.
     ```js
     await db.from('posts').delete().eq('id', 1)
     ```
  3. 결과의 `data`는 **빈 배열 `[]`** (지워진 행 0개)이고 `error`는 `null` 입니다. → **에러가 아니라 "건드릴 행이 없음"으로 조용히 막힌 것**입니다. 새로고침해도 그 글은 그대로 남아 있습니다.
- **읽기는 누구나**: 로그아웃 상태에서도 글 목록은 보인다(공개 게시판이므로 select는 `using (true)`).
- **로그인 안 하면 못 씀**: 로그아웃 상태에서는 글쓰기 영역이 숨겨지고, 강제로 insert해도 `with check (auth.uid() = user_id)` 때문에 거부된다.
- **오류 없음**: 정상 흐름에서 F12 → Console에 빨간 오류가 없어야 한다.

> RLS가 잘 걸렸는지 한눈에 보려면: Supabase 대시보드 → **Table Editor → posts → RLS**가 **enabled**로 표시되고, **Authentication → Policies**에 정책 4종("누구나 글 읽기", "로그인한 사람만 글 쓰기", "작성자만 수정", "작성자만 삭제")이 보이면 성공입니다.

!!! danger "절대 하지 말 것"
    `index.html`에 넣는 건 **anon(공개) 키**여야 합니다. `service_role`(secret) 키는 **RLS를 통째로 우회**하므로 브라우저·GitHub에 두면 누구나 모든 글을 지울 수 있습니다. 두 키를 헷갈리는 게 가장 흔한 사고입니다. 비밀 키가 필요한 작업(예: 관리자 일괄 삭제)은 반드시 **서버(또는 n8n)** 쪽에서만 처리하세요.
