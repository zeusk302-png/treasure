# 실습 274 — 내 문서를 근거로 답하는 RAG 챗봇 만들기

> **아키타입 미니프로젝트 (난이도 5)** · 분류: 아키타입 미니프로젝트 · 개념: RAG, 문서 검색, 근거 기반 답변

이 챗봇은 그냥 AI에게 묻는 게 아니라, **먼저 내 문서(FAQ)에서 질문과 닮은 글을 찾아내고**, 그 글에 적힌 내용으로만 AI가 답하게 만듭니다. 문서에 없는 질문에는 "문서에 없어요"라고 솔직히 답합니다. 이렇게 답을 근거에 묶어 두는 방식을 **RAG**라고 부르고, AI가 그럴듯한 거짓말을 지어내는 현상(환각)을 크게 줄여 줍니다.

## 목표
- **RAG**가 무엇인지 한 문장으로 말할 수 있다 → "내 문서에서 관련 글을 **찾아(Retrieve)**, 그 글을 AI에게 **근거로 붙여(Augment)**, 그걸로만 **답하게(Generate)** 한다."
- 그냥 AI에게 묻는 것과, **내 문서에 근거해 묻는 것**의 답이 어떻게 다른지 눈으로 확인한다.
- AI의 **비밀 키는 브라우저가 아니라 서버에만** 둬야 한다는 보안 원칙을 다시 체득한다.

### RAG를 비유로 이해하기
RAG는 **오픈북 시험**과 같습니다.

- 일반 AI 질문 = **머릿속 기억만으로** 답하는 시험. 모르면 그럴듯하게 지어냅니다(환각).
- RAG = **참고서(내 문서)를 펴 놓고** 그 페이지를 보고 답하는 시험. 참고서에 없으면 "없다"고 합니다.

이 실습의 참고서는 `knowledge.js` 파일 안의 '코딩카페 안내문' 5개(영업시간 · 주차 · 와이파이 · 환불 · 반려동물)입니다.

### 한눈에 보는 작동 흐름
```
[브라우저] 질문 입력
     │  (POST /api/ask, 비밀 키 없음)
     ▼
[우리 서버 함수 api/ask.js]
  ① Retrieve : knowledge.js 에서 질문과 닮은 문서 조각 찾기 (키워드 점수)
  ② Augment  : 찾은 조각을 "이 문서로만 답해" 라는 지시문에 끼워 넣기
  ③ Generate : Claude 호출 (← 비밀 키는 여기서만 붙음)
     │
     ▼
[브라우저] 답 + '근거로 쓴 문서 이름' 표시
```

## 따라하는 단계
1. **먼저 그냥 열어 봅니다.** `index.html`을 더블클릭하면 화면은 보이지만, '물어보기'를 누르면 실패합니다. RAG의 AI 답변은 **서버 함수(`/api/ask`)** 가 있어야 작동하기 때문입니다(아래 4~7단계에서 배포). 지금은 화면 구조만 확인하세요.
2. **참고서를 열어 봅니다.** `knowledge.js`를 열어 문서 5개가 어떻게 생겼는지 봅니다. 각 문서는 `title`(제목), `keywords`(검색에 걸릴 말들), `text`(실제 내용)로 되어 있습니다. **이 파일에 적힌 내용만 챗봇이 답할 수 있습니다.**
3. **두뇌를 읽어 봅니다.** `api/ask.js`에서 `retrieve()` 함수가 ①질문에 문서 키워드가 몇 개 들어있는지 세어 점수를 매기고, ②점수 높은 문서를 골라, ③`systemPrompt`에서 "주어진 문서에만 근거해 답하고, 없으면 없다고 해"라고 AI에게 못 박는 부분을 확인합니다.
4. **무료 계정을 준비합니다.** [console.anthropic.com](https://console.anthropic.com)에서 API 키를 발급받고, [vercel.com](https://vercel.com)·[github.com](https://github.com) 계정을 만듭니다.
5. **GitHub에 올립니다.** 이 `274` 폴더를 새 저장소로 올립니다. (`.gitignore` 덕분에 `.env` 같은 비밀 파일은 올라가지 않습니다.)
6. **Vercel에 비밀 키를 넣습니다.** Vercel에서 저장소를 Import 한 뒤, **Settings → Environment Variables** 에 이름 `ANTHROPIC_API_KEY`, 값에는 **내 진짜 키**(`sk-ant-...` 형태)를 넣습니다. 키는 **코드가 아니라 여기에만** 둡니다.
7. **배포(Deploy)** 후 받은 주소를 엽니다. 이제 '물어보기'가 작동합니다.
8. **세 가지를 직접 실험합니다.**
   - 문서에 있는 질문: "영업시간이 어떻게 되나요?" → 안내문 그대로 답하고, 아래에 **근거 문서: 영업시간**이 표시됩니다.
   - 문서에 없는 질문: "비트코인 시세 알려줘" → "문서에 없어요" 라고 솔직히 답합니다(= 환각 안 함).
   - 살짝 비틀기: `knowledge.js`의 영업시간 텍스트를 "저녁 9시" → "저녁 11시"로 바꿔 다시 배포하면, 챗봇 답도 바뀝니다. **답의 출처가 코드가 아니라 내 문서임**을 체감할 수 있습니다.

> **내 문서로 바꾸기:** `knowledge.js`의 5개 항목을 우리 가게·동아리·서비스 FAQ로 바꾸면 그대로 나만의 챗봇이 됩니다. 문서가 수십 개로 늘면, 글을 코드 대신 **Supabase 테이블**(한 행 = 문서 한 조각)에 넣고 거기서 검색하도록 `retrieve()`만 바꾸면 됩니다.

## 검증법
- **근거가 표시되는가?** 문서에 있는 질문을 했을 때 답 아래에 "근거 문서: ○○"가 뜨는가? (RAG는 출처를 보여줄 수 있어야 합니다.)
- **모르는 건 모른다고 하는가?** 안내문에 없는 질문("환율 알려줘" 등)에 챗봇이 답을 지어내지 않고 "문서에 없어요"라고 하는가? (지어내면 RAG가 제대로 안 묶인 것입니다.)
- **문서를 바꾸면 답이 바뀌는가?** `knowledge.js`의 한 문장을 수정·재배포했을 때 챗봇 답도 따라 바뀌는가? (바뀌면, 답의 출처가 내 문서임이 증명됩니다.)
- **비밀 키가 안 보이는가?** 배포된 페이지에서 `Ctrl`+`U`(소스 보기)와 `F12 → Network`를 봐도 `sk-ant-`로 시작하는 키가 **한 글자도 없어야** 정상입니다. 키는 서버 환경변수에만 있습니다.

> **보안 핵심 한 줄:** 과금되는 AI 키(`ANTHROPIC_API_KEY`)는 **절대 브라우저 코드에 두지 않습니다.** 공개돼도 되는 값(예: Supabase `anon` 키)과 달리, AI 키 같은 **비밀값(secret)** 은 서버(`/api/ask`)에서만 사용하고, 실제 값은 오직 Vercel의 Environment Variables 에만 보관합니다.
