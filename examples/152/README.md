# 실습 152 — 입력창에 검색어 받아 실시간 도서 검색 붙이기

입력창에 검색어를 치면, 그 글자를 **주소(URL)** 의 `?q=...` 자리에 끼워 넣어
공개 도서 API(Open Library)에 요청을 보내고, 결과 목록이 **타이핑에 따라 바뀌는** 한 장짜리 페이지입니다.

> 비유: 검색은 도서관 사서에게 보내는 **주문서(주소)** 입니다.
> 주문서에 적는 글자에는 **빈칸·특수기호·한글**처럼 그냥 쓰면 사서가 헷갈리는 글자가 있습니다.
> 그래서 사용자가 친 글자를 **주문서 양식에 맞게 변환(`encodeURIComponent`)** 해서 끼워 넣어야 합니다.
> 이번 실습의 한 줄 핵심은 **"사용자가 친 값을 URL 쿼리 파라미터에 안전하게 합치기"** 입니다.

## 목표
- 사용자가 입력한 검색어를 **fetch로 부를 주소에 동적으로 끼워 넣는** 흐름을 익힌다.
- **위험한 글자(공백·`&`·`=`·한글 등)** 를 안전하게 바꾸는 두 도구를 익힌다.
  - `encodeURIComponent(글자)` = 글자 하나를 URL용 안전 코드로 변환 (예: 공백 → `%20`, `&` → `%26`)
  - `new URLSearchParams()` + `params.set("q", 값)` = 키·값을 넣으면 **인코딩을 자동**으로 해 주는 도구
- **실시간 검색(debounce)** 패턴을 익힌다: 타이핑이 잠깐 멈추면 그때 한 번만 요청해서 서버에 너무 자주 요청하지 않게 한다.

> 실습 151과의 차이: 151은 "**배열 응답을 목록으로 펼치기**"가 핵심이었고,
> 152는 거기에 더해 "**사용자 입력을 주소에 안전하게 합치고, 타이핑에 따라 실시간으로 다시 검색하기**"가 핵심입니다.

## 따라하는 단계
1. 이 폴더의 `index.html`을 더블클릭 → 브라우저에서 열린다. (인터넷 연결 필요)
2. 검색창에 미리 `해리포터`가 들어 있고, 페이지가 열리자마자 한 번 검색되어 책 카드들이 보인다.
3. 검색창 글자를 지우고 천천히 `어린왕자`라고 친다 → **타이핑을 멈추면 0.5초 뒤 자동으로** 목록이 바뀐다.
4. 검색창 아래의 **검은 주소 칸**을 본다 → 내가 친 글자가 들어간 **실제 요청 주소**가 보인다.
5. 검색어에 **공백이나 특수문자**를 넣어 본다 (예: `c++ 프로그래밍`). 주소 칸에서 공백이 `%20`, `+`가 `%2B`처럼 **안전 코드로 바뀐 모습**을 확인한다 → 이것이 `encodeURIComponent`가 한 일이다.
6. `script.js`에서 `buildSearchUrl(keyword)` 함수를 찾는다 → **검색어로 주소를 조립하는 핵심**이다. `encodeURIComponent`로 직접 합치는 방법과 `URLSearchParams`로 합치는 방법 두 가지가 나란히 적혀 있다.
7. 같은 파일 맨 아래 `keywordInput.addEventListener("input", ...)`를 본다 → `clearTimeout` + `setTimeout`으로 **타이핑이 멈췄을 때만 검색**하는 debounce 부분이다.
8. AI에게 시켜 보기:
   > "이 `script.js`에서 검색 결과 개수를 `&limit=12` 대신 화면의 드롭다운(12/24/48)으로 고를 수 있게 바꿔줘. `URLSearchParams`의 `limit` 값을 드롭다운에서 읽어오게 해줘."

## 🤖 바이브코딩 프롬프트
이 실습을 AI에게 시켜 만들 때 그대로 복사해 쓸 수 있는 프롬프트입니다. (검색어를 URL에 안전하게 합치고, 타이핑에 따라 실시간으로 다시 검색하는 한 장짜리 페이지)

- **1단계(뼈대 만들기)** 프롬프트:
  ```text
  너는 프런트엔드 입문 강사야. 바닐라 JS(라이브러리 없이) 한 장짜리 도서 검색 페이지를 만들어줘.
  요구사항:
  - 파일은 index.html, style.css, script.js 세 개로 나눠줘.
  - 검색 입력칸 하나와 "검색" 버튼 하나가 있는 form을 둬. 입력칸 기본값은 "해리포터".
  - 사용자가 친 검색어를 공개 API 주소(https://openlibrary.org/search.json?q=검색어&limit=12)에
    안전하게 끼워 넣어 fetch로 요청해줘. 검색어는 반드시 URLSearchParams 또는 encodeURIComponent로
    인코딩해서 공백·한글·&·+ 같은 글자가 깨지지 않게 해줘.
  - 응답 data.docs 배열을 받아 책마다 표지(cover_i)·제목(title)·저자(author_name)·연도(first_publish_year)를
    카드로 그려줘. 표지가 없으면 대체 이미지를 보여줘.
  - 우리가 실제로 만든 요청 주소를 화면의 검은 박스에 그대로 보여줘(학습용).
  제약: 비전공자가 읽을 거라 코드마다 한국어 주석으로 '무엇을·왜' 설명해줘. 비밀 키는 쓰지 마(공개 API라 키가 없어).
  ```
- **2단계(기능 추가/개선)** 프롬프트:
  ```text
  방금 만든 script.js에 '실시간 검색'을 붙여줘.
  - 입력칸에 글자를 칠 때마다(input 이벤트) 검색하되, 한 글자마다 요청하면 서버에 너무 자주 가니까
    debounce(디바운스)를 써서 "타이핑이 0.5초 멈추면 그때 한 번만" 검색하게 해줘.
  - 검색 버튼이나 Enter로는 기다리지 않고 즉시 검색되게 해줘.
  - 결과 개수(12/24/48)를 화면 드롭다운으로 고를 수 있게 하고, 그 값을 URLSearchParams의 limit에 넣어줘.
  - 검색 결과가 0건이면 "검색 결과가 없어요" 안내를 보여줘.
  기존 동작과 주석은 지우지 말고, 추가한 부분에도 '왜 이렇게 했는지' 한국어 주석을 달아줘.
  ```
- **막혔을 때(디버깅)** 프롬프트:
  ```text
  검색은 되는데 한글이나 "c++ 프로그래밍"처럼 공백·특수문자가 든 검색어를 넣으면 결과가 이상해.
  아래 내 buildSearchUrl 함수와, F12 Network 탭에서 본 실제 요청 주소를 붙일게.
  (코드/주소 붙여넣기)
  무엇이 문제인지 한 단계씩 짚어주고, encodeURIComponent / URLSearchParams 중 어디서 인코딩이
  빠졌는지 알려줘. 고친 코드와 함께 '왜 그 줄이 문제였는지' 비전공자가 이해하게 한 줄씩 풀어서 설명해줘.
  ```
> 프롬프트 팁: "코드만 주지 말고 왜 그렇게 했는지 주석으로 설명해줘", "비전공자가 이해하게 한 줄씩 풀어줘"를 덧붙이면 학습에 좋습니다. 결과가 이상할 땐 F12 Network 탭의 '실제 요청 주소'를 그대로 복사해 붙이면 AI가 원인을 훨씬 잘 찾습니다.

## 검증법
- 검색창에 글자를 치고 **잠깐 멈추면** 목록이 자동으로 바뀌는가? (버튼을 누르지 않아도)
- 검색 버튼이나 Enter로도 **즉시** 검색되는가?
- 검은 주소 칸에 내가 친 검색어가 들어간 **실제 요청 주소**가 보이는가?
- 검색어에 **공백·한글·`+`·`&`** 를 넣으면 주소 칸에서 `%20`, `%2B`, `%26` 같은 **안전 코드로 바뀌어** 보이는가?
- `F12`(개발자 도구) → **Network 탭**을 켜고 검색하면, 요청된 `search.json` 주소가 **주소 칸에 보이는 것과 똑같은가?** (인코딩된 모습으로 실제 전송됨)
- 한 글자 칠 때마다 요청이 가지 않고, **타이핑을 멈췄을 때만** 요청이 가는가? (Network 탭에서 요청 횟수 확인)
- 결과가 없을 검색어(예: `asdfqwerzxcv`)를 넣으면 **"검색 결과가 없어요"** 안내가 뜨는가?

## 왜 꼭 인코딩(안전 변환)을 해야 하나요? (보안·정확성 메모)
주소(URL)에서 공백·`&`·`=`·`?`·`#`·`+` 같은 글자는 **특별한 뜻**을 가집니다.
사용자가 친 글자를 그대로 주소에 붙이면 검색어가 끊기거나 다른 항목으로 잘못 읽힐 수 있습니다.

```
나쁜 예 (그대로 붙이기):
  "https://openlibrary.org/search.json?q=" + "c++ & java"
  → ...?q=c++ & java   (공백에서 끊기고 &가 새 항목으로 오해됨 → 엉뚱한 결과/에러)

좋은 예 (안전 변환):
  "https://openlibrary.org/search.json?q=" + encodeURIComponent("c++ & java")
  → ...?q=c%2B%2B%20%26%20java   (검색어 전체가 정확히 전달됨)
```

이 실습이 쓰는 **Open Library 검색 API**(`openlibrary.org/search.json`)는 **누구나 열쇠(API 키) 없이** 부를 수 있는 **공개 API**라서 코드에 비밀값을 넣지 않습니다.

나중에 키가 필요한 API를 쓰게 되면, **공개되어도 되는 값**과 **절대 노출하면 안 되는 비밀값**은 성격이 완전히 다릅니다.

- 공개되어도 되는 값(예: Supabase의 `anon` 키)은 브라우저 코드에 들어가도 괜찮습니다. 단, 데이터 보호는 **RLS(행 수준 보안)** 가 책임집니다.
- 비밀값(예: Supabase의 `service_role` 키, 유료 API 키)은 **브라우저 코드에 절대 넣지 않습니다.** 브라우저 코드는 누구나 들여다볼 수 있기 때문입니다. 비밀값은 서버(또는 n8n 같은 자동화 도구의 자격 증명 저장소)에서만 다룹니다.
- 키가 있는 API를 예제로 쓴다면 코드에는 `YOUR_API_KEY` 같은 **자리표시자**만 두는 것이 원칙입니다.
