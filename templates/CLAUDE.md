# CLAUDE.md — 프로젝트 작업 매뉴얼 (샘플)

> Claude Code가 새 대화를 시작할 때마다 자동으로 먼저 읽는 파일입니다.
> 한 번 적어두면 매번 설명할 필요가 없습니다. 막힐 때마다 한 줄씩 추가하세요.
> 아래 `(예)` 부분을 내 프로젝트에 맞게 고쳐 쓰면 됩니다.

## 프로젝트 개요
- 무엇: (예) 동네 빵집 '햇살베이커리' 홍보 사이트
- 누구를 위해: (예) 동네 주민·단골
- 핵심 페이지: 소개 / 메뉴 / 위치·영업시간 / 문의

## 언어·톤
- 모든 답변과 코드 주석은 **한국어**로.
- 사용자는 비전공자다. 전문용어는 쉬운 말로 풀어 설명하고, 실행 전 무엇을 할지 먼저 알려준다.

## 기술 스택
- (예) HTML/CSS/JS 정적 사이트 + (필요 시) Supabase + GitHub Pages 배포
- 새 라이브러리를 추가할 땐 먼저 이유를 설명하고 승인받는다.

## 폴더·파일 규칙
- 폴더·파일명은 영어 소문자와 하이픈(-)만 사용. 공백·한글·대문자 금지.
- 구조: `index.html`, `styles/`, `scripts/`, `images/`, `examples/`

## 코딩 규칙
- 읽기 쉬운 코드 우선. 변수·함수 이름은 의미가 드러나게.
- 한 함수는 한 가지 일만. 거대한 함수·중복 코드를 피한다.
- 기능 추가와 리팩터링(정돈)은 한 번에 섞지 않는다.

## 커밋 규칙 (Conventional Commits)
- 형식: `타입: 요약`  (예: `feat: 문의 폼 추가`, `fix: 모바일 메뉴 깨짐 수정`)
- 타입: feat(기능) / fix(버그) / docs(문서) / style(서식) / refactor(정돈) / chore(잡일)
- 한 커밋은 한 가지 변경. 의미 단위로 자주 커밋한다.

## 보안 규칙 (중요)
- 비밀키·비밀번호는 절대 코드에 직접 쓰지 않는다. `.env`에 두고 `.gitignore`에 추가.
- Supabase: 프론트엔드에는 **anon(공개) 키만** 쓴다. `service_role`(비밀) 키는 절대 프론트·GitHub에 올리지 않는다.
- 테이블을 만들면 **RLS(행 수준 보안)를 반드시 켜고** 정책을 검증한다.
- 배포 전 비밀키가 노출되지 않았는지 확인한다.

## 작업 방식
- 큰 작업은 '플랜 모드'로 계획을 먼저 보여주고 승인받은 뒤 실행한다.
- "다 됐어요" 대신, 무엇을 어떻게 클릭하면 무엇이 보여야 성공인지 검증 방법을 함께 알려준다.
- 대화가 길어지면 핵심 규칙을 요약해 이 파일에 반영한다.

## 절대 하지 말 것
- 영어로 답하지 말 것
- 비밀키를 코드에 하드코딩하지 말 것
- 시키지 않은 큰 구조 변경을 멋대로 하지 말 것
- 잘 되던 기능을 임의로 바꾸지 말 것 (“전부 다 바꿔줘” 금지 — 콕 집어 수정)
