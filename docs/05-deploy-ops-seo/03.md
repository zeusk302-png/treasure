# 검색에 잡히게 하기 1 — 메타태그, sitemap.xml, robots.txt, 캐노니컬

**(1) 한 줄 정의**

검색 노출의 기초란 검색엔진에게 "이 사이트엔 어떤 페이지들이 있고(sitemap.xml), 어디는 봐도 되고 어디는 보지 말고(robots.txt), 같은 내용이면 이 주소가 대표(캐노니컬)"라고 친절히 안내하는 표지판을 다는 일이다.

**(2) 왜 중요한가 (디렉터 관점)**

아무리 잘 만들어도 검색엔진이 페이지의 존재를 모르면 검색 결과에 안 뜬다. 디렉터는 "왜 구글에 안 나와요?"의 원인이 콘텐츠 품질이 아니라 이 표지판 누락일 수 있음을 알아야 한다. 특히 같은 글이 여러 주소로 보이면 검색엔진이 점수를 나눠 깎는데, 캐노니컬 한 줄이 이를 막는다.

**(3) 비유**

새로 연 가게가 지도 앱에 등록 안 돼 있으면 손님이 못 찾는다. sitemap은 "우리 가게 안의 모든 방 목록", robots는 "여긴 들어와도 되고 창고는 들어오지 마세요", 캐노니컬은 "별명이 여러 개여도 본명은 이거예요" 안내판이다.

**(4) 최소한 알 것**

| 표지판 | 한 줄 해설 | 판정 |
|---|---|---|
| sitemap.xml | 사이트 전체 페이지 목록 | 🟢 메인 — App Router의 `sitemap.ts`가 자동 생성 |
| robots.txt | 크롤러에게 허용/차단 안내 | 🟢 메인 — `robots.ts`가 자동 생성 |
| 캐노니컬 태그 | 중복 주소 중 대표 지정 | 🟢 메인 — 점수 분산 방지 |
| 메타태그(title·description) | 검색결과에 보일 제목·설명 | 🟢 메인 |

**(5) AI에게 이렇게 시켜라**

```text
Next.js App Router 프로젝트에서 검색 노출 기초를 세팅하려고 해.
1) MDX 콘텐츠 폴더를 스캔해서 sitemap.ts로 /sitemap.xml을 자동 생성하게 해줘
   (페이지 추가하면 자동 반영되게, 하드코딩 금지)
2) robots.ts로 /robots.txt를 만들되, production에서는 절대 noindex가
   남지 않게 해줘
3) 각 페이지에 캐노니컬 태그와 title·description 메타태그를 넣어줘
완료 후 내가 코딩 없이 /sitemap.xml과 /robots.txt를 눈으로 확인하는 방법도 알려줘.
```

**(6) 흔한 함정 · AI가 틀리는 것**

!!! warning
    AI는 (1) 캐노니컬 태그를 빠뜨려 중복 콘텐츠로 평가절하되게 하고, (2) sitemap을 자동 스캔 대신 페이지 몇 개만 하드코딩하며, (3) 개발 중 넣은 `noindex`("검색에 잡히지 마")를 production까지 들고 가 사이트 전체가 검색에서 통째로 사라지게 만든다. `noindex`가 운영에 남으면 가장 치명적이다.

**(7) 검증하는 법**

1. 브라우저에 `내도메인/sitemap.xml`을 직접 쳐서 모든 페이지가 들어 있는지 본다.
2. `내도메인/robots.txt`를 열어 production에 `Disallow: /`나 noindex가 없는지 확인.
3. 페이지 소스 보기(우클릭 → 소스)에서 `<link rel="canonical">`이 올바른 주소를 가리키는지 확인.
4. Google Search Console에 사이트맵을 제출하고 색인 상태를 본다.
