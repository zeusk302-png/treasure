# [해부] 이 사이트는 어떻게 배포·운영되는가 — 살아있는 레퍼런스

**(1) 한 줄 정의**

이 페이지는 권5에서 배운 모든 개념(파이프라인·환경분리·SEO·Core Web Vitals·도메인·모니터링·롤백·비용)이 '이 사이트 한 곳'에서 어떻게 맞물려 돌아가는지를 통째로 공개하는 케이스 스터디다.

**(2) 왜 중요한가 (디렉터 관점)**

개념을 따로따로 아는 것과, 한 사이트에서 그것들이 서로 어떻게 연결되는지 보는 것은 다르다. 특히 디렉터의 핵심 습관인 **"내가 AI에게 시킨 것 ↔ 실제로 반영된 것"을 대조하는 검증**을, 커밋 해시부터 라이브 URL까지 추적하며 직접 시범 보인다. 남의 말이 아니라 눈앞의 1차 증거로 확인하는 자기증명 구조다.

**(3) 비유**

요리책의 마지막 장에 실린 '완성된 식당의 주방 투어'다. 앞 장에서 배운 재료·불·위생·메뉴판이 실제 영업장에서 어떻게 한꺼번에 작동하는지, 주방 문을 활짝 열어 보여준다.

**(4) 최소한 알 것**

한 페이지에 권5의 흐름이 증거로 정렬된다.

| 단계 | 이 사이트의 증거 |
|---|---|
| 파이프라인(01) | 커밋 해시 → 배포 ID → 라이브 URL 타임라인 |
| 환경분리(02) | dev/preview/production 환경변수 3칸 구성 |
| SEO(03·04) | 실제 `/sitemap.xml`·`/robots.txt` 링크, 적용한 JSON-LD |
| CWV(05) | 실사용자 필드 점수(lab 아님) |
| 도메인(06) | 커스텀 도메인 + 자물쇠 + 301 통일 |
| 모니터링·롤백(07) | 에러추적 캡처, Instant Rollback 기록 |
| 비용(08) | 실제 Usage 대시보드 막대 |

**(5) AI에게 이렇게 시켜라**

```text
내 사이트가 권5 개념(파이프라인·환경분리·SEO·CWV·도메인·모니터링·롤백·비용)을
실제로 잘 갖췄는지 한 페이지짜리 '운영 해부' 체크리스트를 만들어줘.
각 항목마다 '내가 클릭/확인해서 증거를 볼 수 있는 위치'를 적어줘.
예: 배포 성공 → Vercel Deployments, 필드 점수 → PageSpeed Insights,
사용량 → Usage 대시보드. 추측이면 '추측'이라고 표시하고,
내가 직접 눈으로 확인하기 전엔 '확인됨'이라고 단정하지 마.
```

**(6) 흔한 함정 · AI가 틀리는 것**

!!! warning
    AI는 "다 잘 돼 있습니다"라고 한 번에 단언하지만, 실제로는 항목별 증거를 안 보여준다. '시킨 것'과 '반영된 것'이 어긋나 있어도 먼저 경고하지 않는다. 또 라이브 사이트를 직접 확인하지 않고 코드만 보고 "배포됐어요"라고 보고하기 쉽다. 디렉터는 항목별 1차 증거를 요구해야 한다.

**(7) 검증하는 법**

1. 커밋 해시 → Vercel 배포 ID → 라이브 URL이 한 줄로 추적되는지 확인.
2. 각 개념(01~08)별로 실제 증거 위치를 하나씩 직접 클릭해 본다.
3. "시킨 것 ↔ 반영된 것"이 일치하는지 항목마다 대조한다.
4. 필드 점수·사용량 막대처럼 시점성 있는 숫자엔 확인 날짜를 적는다.
