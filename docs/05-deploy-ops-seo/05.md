# Core Web Vitals와 Lighthouse — '빠르다'를 숫자로 검증하는 법

**(1) 한 줄 정의**

Core Web Vitals란 페이지의 '체감 속도·반응성·안정성'을 LCP·INP·CLS 세 숫자로 표준화한 지표이고, Lighthouse는 그 점수를 측정해주는 진단 도구다.

**(2) 왜 중요한가 (디렉터 관점)**

"빠른 것 같아요"는 검증이 아니다. 숫자로 봐야 한다. 더 중요한 건, 구글이 검색 순위에 쓰는 건 Lighthouse가 내 컴퓨터에서 잰 '실험실 점수(lab)'가 아니라 **실제 사용자들의 측정값인 '필드 데이터(field, CrUX)'** 라는 점이다. 디렉터가 이 차이를 모르면 "Lighthouse 100점"에 만족하다 실사용자 점수가 나쁜 채 방치한다.

**(3) 비유**

- LCP: 손님이 들어와 주요 화면이 다 차려지기까지 걸린 시간(접시가 나오는 속도).
- INP: 손님이 버튼을 눌렀을 때 반응하기까지의 굼뜸(주문에 응답하는 속도).
- CLS: 차려놓은 접시가 갑자기 움직여 손님이 헛손질하는 정도(상 흔들림).

Lighthouse는 텅 빈 시식회장에서 혼자 잰 시간이고, 필드 데이터는 붐비는 영업 시간에 실제 손님들이 겪은 시간이다.

**(4) 최소한 알 것**

| 지표 | 무엇을 잰다 | 판정 |
|---|---|---|
| LCP | 가장 큰 콘텐츠가 뜨는 시간 | 🟢 메인 |
| INP | 상호작용에 대한 반응 굼뜸 | 🟢 메인 |
| CLS | 레이아웃이 갑자기 밀리는 정도 | 🟢 메인 |

!!! warning
    **시점성 정보 — 반드시 확인.** LCP 합격선(예: 2.5초)·INP·CLS 기준선은 web.dev / Google 공식 문서에서 날짜 기준으로 재확인할 것. 합격선 수치(예 2.0초 vs 2.5초)는 논쟁·변경 여지가 있으므로 단정하지 말 것.

**(5) AI에게 이렇게 시켜라**

```text
내 사이트의 성능을 Core Web Vitals로 점검하려고 해.
1) LCP, INP, CLS가 각각 무엇을 측정하는지 비전공자 눈높이로 설명해줘
2) Lighthouse '실험실 점수(lab)'와 구글 랭킹에 쓰이는 '필드 데이터(field/CrUX)'의
   차이, 그리고 왜 둘이 다를 수 있는지 알려줘
3) 각 지표의 현재 합격 기준선을 알려주되, 그게 web.dev 공식 문서로 확인 가능한지
   네 추정인지 표시하고, 변동 가능성이 있으면 명시해줘
4) PageSpeed Insights에서 lab과 field를 어디서 보는지 클릭 위치를 알려줘
```

**(6) 흔한 함정 · AI가 틀리는 것**

!!! warning
    AI는 'Lighthouse 100점'에 집착하게 만들고, 그 점수가 검색 순위에 직접 쓰이는 필드 데이터와 다를 수 있다는 점을 짚지 않는다. 또 합격 기준선 수치를 옛 기준으로 단언하기 쉽다. 점수를 올리려 이미지·스크립트를 무리하게 손대다 멀쩡한 화면을 깨기도 한다.

**(7) 검증하는 법**

1. PageSpeed Insights에 URL을 넣고 상단의 'Field Data(실사용자)'와 'Lab Data(Lighthouse)'를 따로 본다.
2. 필드 데이터가 충분히 쌓였는지(트래픽 적으면 '데이터 부족'으로 뜸) 확인.
3. Search Console의 'Core Web Vitals' 보고서에서 모바일/데스크톱별 통과 URL 수를 본다.
4. 기준선은 web.dev 공식 문서와 대조해 날짜를 적어둔다.

**(8) 더 깊이**

- web.dev: Core Web Vitals (web.dev/vitals) — 1차 출처 (기준선은 시점성 정보)
- Chrome UX Report / PageSpeed Insights 문서 (developer.chrome.com / pagespeed.web.dev) — 1차 출처

!!! example "💡 예시로 이해하기"
    디렉터가 PageSpeed Insights에서 자기 사이트를 측정하고 Lab Data(Lighthouse) 성능 점수 `98점`을 보고 흐뭇해한다. 그런데 같은 화면 위쪽 Field Data(실사용자, CrUX)를 보니 LCP가 `4.1초`로 빨간불, "기준 통과 실패"라고 떠 있다.
    왜 이렇게 다를까? Lab은 구글 서버가 빠른 회선·고사양 가상기기로 텅 빈 시간에 딱 한 번 잰 값이다. 반면 Field는 지난 28일간 실제 방문자들(지하철에서 느린 LTE로 접속한 사람 포함)이 겪은 진짜 시간을 모은 값이다. 구글이 검색 순위에 쓰는 건 Lab 98점이 아니라 이 Field LCP 4.1초다.
    그러니 "Lighthouse 100점 만들어줘"에 매달리기보다, Field 데이터가 빨간불인지부터 봐야 한다. (트래픽이 적으면 Field가 '데이터 부족'으로 비어 있을 수도 있다.)
