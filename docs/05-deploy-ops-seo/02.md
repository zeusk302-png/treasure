# dev / preview / production: 환경 분리와 환경변수의 3개 칸

**(1) 한 줄 정의**

환경 분리란 '내 컴퓨터에서 테스트(dev)', '올리기 전 미리보기(preview)', '진짜 손님이 쓰는 운영(production)'을 서로 다른 공간으로 나누고, 각 공간에 맞는 환경변수(키·주소)를 따로 꽂는 것이다.

**(2) 왜 중요한가 (디렉터 관점)**

테스트하다 실수로 실제 손님 데이터를 지우거나, 운영 사이트가 테스트용 DB를 바라보는 사고를 막는 안전벽이다. 디렉터가 "로컬에선 되는데 배포만 에러"라는 말을 들으면, 십중팔구 운영 환경(Production) 칸에 환경변수를 빠뜨린 것임을 의심할 수 있어야 한다.

**(3) 비유**

같은 요리를 연습용 주방(dev), 손님 초대 전 시식회(preview), 실제 영업장(production) 세 곳에서 한다. 각 주방에는 그 주방용 식자재 창고 열쇠(환경변수)가 따로 걸려 있다. 영업장 열쇠를 안 걸어두면 영업장에서만 "재료를 못 찾겠어요" 사고가 난다.

**(4) 최소한 알 것**

- 환경변수는 dev / preview / production 각 칸에 따로 등록한다.
- `NEXT_PUBLIC_` 접두어가 붙은 변수는 **브라우저에 노출**된다(공개 OK인 것만).
- 접두어 없는 변수는 서버에만 남는다(비밀용).

| 키 | 어느 환경에 | NEXT_PUBLIC_ 붙임? | 판정 |
|---|---|---|---|
| anon (publishable) 키 | dev·preview·production 전부 | 붙임(공개 OK) | 🟢 공개돼도 안전한 출입증 |
| service_role (secret) 키 | production 서버에만 | 절대 안 붙임 | 🟢 진짜 비밀, 서버 전용 |

!!! tip
    공개돼도 되는 anon 키와 진짜 비밀인 service_role 키를 가르는 안목이 권4의 핵심이다. 안전의 진짜 열쇠는 키를 숨기는 게 아니라 **RLS(행 수준 보안)** 가 켜져 있느냐다.

**(5) AI에게 이렇게 시켜라**

```text
Next.js + Vercel 프로젝트의 환경변수를 dev / preview / production 세 환경으로
분리하려고 해. 다음을 표로 정리해줘.
1) 각 환경에 어떤 키를 넣어야 하는지
2) 어떤 키에 NEXT_PUBLIC_ 접두어를 붙이고 어떤 키엔 절대 붙이면 안 되는지
   (anon 키와 service_role 키를 구분해서)
3) Vercel 대시보드에서 production 칸에 변수를 등록하는 클릭 절차
service_role 키를 NEXT_PUBLIC_으로 노출하지 않도록 주의 문구도 넣어줘.
```

**(6) 흔한 함정 · AI가 틀리는 것**

!!! warning
    AI는 모든 키를 `.env.local` 하나에 몰아넣게 안내하고, Vercel의 Production 칸 등록을 빠뜨려 "로컬은 되는데 배포만 에러"를 만든다. 더 위험한 건 **service_role(secret) 키에 실수로 `NEXT_PUBLIC_`을 붙여 브라우저에 노출**하는 것이다. 이것이 가장 흔한 보안 사고다.

**(7) 검증하는 법**

1. Vercel → Settings → Environment Variables에서 production 칸에 필요한 키가 다 있는지 확인.
2. 빌드된 사이트에서 F12 → Sources/Network로 `service_role`·`sb_secret_` 문자열이 보이는지 검색 → **0건이어야 정상.**
3. anon(publishable) 키만 브라우저에서 보이고, 그래도 RLS가 막는지 댓글 쓰기를 직접 눌러 확인.

**(8) 더 깊이**

- Vercel Environment Variables 공식 문서 (vercel.com/docs) — 1차 출처
- Supabase API Keys 공식 문서 (supabase.com/docs) — 1차 출처 (키 체계는 시점성 정보, 날짜 기준 확인 필요)

!!! example "💡 예시로 이해하기"
    디렉터가 "내 컴퓨터에선 로그인이 잘 되는데 배포한 사이트에선 버튼만 누르면 'Invalid API key'가 떠요"라고 호소한다. 범인은 십중팔구 환경변수다. 로컬 `.env.local`에는 `NEXT_PUBLIC_SUPABASE_URL`과 anon 키가 들어 있지만, Vercel의 Production 칸엔 안 넣은 것이다.
    Vercel → Settings → Environment Variables를 열어보니 변수가 Development 환경에만 체크돼 있고 Production 박스는 빈칸이었다. Production에 같은 값을 넣고 재배포하면 끝.
    반대로 더 무서운 사고: AI가 비밀 키를 `NEXT_PUBLIC_SERVICE_ROLE_KEY`처럼 이름 붙여 넣으면, F12 → Sources에서 `sb_secret_...` 문자열이 누구에게나 그대로 보인다. anon 키는 브라우저에 보여도 RLS가 막아주지만, service_role 키는 RLS도 무시하는 마스터키라 노출되면 DB가 통째로 털린다.
