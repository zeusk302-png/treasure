# 라우팅 — URL과 페이지의 짝짓기 (App Router로)

**① 한 줄 정의**
**라우팅**은 "어떤 주소(URL)로 들어오면 어떤 페이지를 보여줄지" 짝지어 주는 규칙입니다. Next.js App Router에서는 **`app` 폴더의 구조가 곧 URL 구조**가 됩니다.

**② 왜 중요한가 (디렉터 관점)**
폴더 구조 = 주소 구조라는 것만 알아도 404의 절반은 스스로 진단됩니다. "이 페이지가 404가 나요"라면, 먼저 **폴더 위치가 주소와 맞는지** 의심하면 됩니다. 디렉터가 이 대응을 알면 AI에게 "주소 `/guide/web`에 맞는 폴더가 `app/guide/web`에 있는지 확인해줘"처럼 정확히 시킬 수 있습니다.

**③ 비유**
건물의 호수 체계와 같습니다. `app/guide/web/page.tsx`는 "guide 동 web 호"라는 주소표입니다. 우편물(요청)이 그 주소로 오면 해당 호실(페이지)이 응답합니다. 방을 옮겨놓고 주소표를 안 바꾸면 "그런 주소 없음(404)"이 됩니다.

**④ 최소한 알 것**

| 폴더/파일 | 만들어지는 주소 |
|---|---|
| `app/page.tsx` | `/` (홈) |
| `app/guide/page.tsx` | `/guide` |
| `app/guide/web/page.tsx` | `/guide/web` |
| `app/[slug]/page.tsx` | `/무엇이든` (동적 경로) |

- App Router는 `page.tsx`라는 약속된 파일명을 쓴다.

**⑤ AI에게 이렇게 시켜라**

```text
나는 Next.js App Router를 쓰고 있어 (Pages Router 아님). 주소 '/guide/web'에서
404가 나. 이 주소에 대응하는 폴더/파일이 'app/guide/web/page.tsx'에 맞게
있는지 확인하는 방법을 알려줘. 혹시 옛 Pages Router 방식('pages/' 폴더)이
섞여 있으면 그것도 짚어줘. App Router 기준으로만 설명해줘.
```

**⑥ 흔한 함정 / AI가 틀리는 것**
AI는 **옛 Pages Router와 App Router를 뒤섞은 코드**를 자주 줍니다. 학습 데이터에 옛 방식이 많아, `pages/` 폴더 방식과 `app/` 폴더 방식을 혼용해 404나 빌드 오류를 만들기 쉽습니다.

!!! tip "디렉터의 한마디"
    AI에게 매번 "App Router 기준"이라고 명시하세요. 안 그러면 그럴듯하지만 옛 방식이 섞인 답이 나옵니다.

**⑦ 검증하는 법**
404가 나는 주소를 보고, 그 주소를 폴더 경로로 그대로 바꿔(`/a/b` → `app/a/b/page.tsx`) 파일이 실제로 있는지 확인합니다. 이 사이트의 권/페이지 구조 자체가 동적 라우팅의 산 증거이니, 주소를 바꿔가며 어떤 페이지가 뜨는지 눌러보세요.

!!! example "💡 예시로 이해하기"
    회사 소개 페이지를 `/about`에 띄우고 싶다고 합시다. App Router에서는 단지 `app/about/` 폴더를 만들고 그 안에 `page.tsx` 파일 하나를 두면 끝 — 주소 등록을 따로 할 필요가 없습니다. 폴더 이름이 곧 주소이기 때문입니다. 그런데 실수로 파일명을 `Page.tsx`(대문자 P)나 `index.tsx`로 저장하면, 브라우저에서 `/about`은 `404`가 납니다. 약속된 이름은 정확히 `page.tsx`거든요. 그래서 404가 뜨면 디렉터는 "주소 `/about` → 폴더 `app/about/page.tsx`가 철자까지 정확히 맞나?"부터 봅니다. 블로그 글처럼 주소가 수천 개로 늘어나는 경우엔 폴더를 수천 개 만드는 대신 `app/blog/[slug]/page.tsx` 하나로 `/blog/무엇이든`을 다 받습니다.
