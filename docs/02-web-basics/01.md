# 주소창에 URL을 치면 무슨 일이 벌어지는가 (전체 지도)

**① 한 줄 정의**
주소창에 URL을 입력하고 엔터를 치면, **DNS 조회 → HTTP 요청 → 서버 응답 → 화면 렌더링** 이라는 4단계 릴레이가 순식간에 일어납니다.

**② 왜 중요한가 (디렉터 관점)**
이 4단계는 곧 **디버깅의 지도**입니다. "사이트가 안 떠요"를 한 덩어리로 던지면 AI는 막연하게 답하지만, "주소는 찾았는데(DNS OK) 응답이 404다" 처럼 *어느 단계가 깨졌는지*로 쪼개면 질문이 정확해지고 답도 정확해집니다. 디렉터는 코드를 짜는 사람이 아니라 **문제의 위치를 짚어주는 사람**입니다.

**③ 비유**
택배가 집에 오는 과정과 같습니다. 주소록에서 주소 찾기(DNS) → 주문서 발송(요청) → 물건 발송(응답) → 집에서 포장 풀기(렌더링). 물건이 안 왔을 때 "주소가 틀렸나, 발송이 안 됐나, 배송 중 분실인가, 받고 안 푼 건가"를 나눠 봐야 원인을 찾습니다.

**④ 최소한 알 것**

| 단계 | 하는 일 | 깨지면 증상 |
|---|---|---|
| DNS 조회 | 도메인 이름 → IP 주소 변환 | 주소 자체를 못 찾음 |
| HTTP 요청 | 브라우저가 서버에 "이거 주세요" | 요청이 안 나감 |
| 서버 응답 | 서버가 상태코드 + 내용 회신 | 404·500 등 에러코드 |
| 렌더링 | 받은 코드를 화면으로 그림 | 화면이 깨지거나 빈 화면 |

**⑤ AI에게 이렇게 시켜라**

```text
내 사이트가 화면에 안 떠. 원인을 코드부터 고치지 말고,
'DNS → HTTP 요청 → 서버 응답 → 렌더링' 4단계 중 어느 단계가 깨졌는지
먼저 진단하는 절차를 알려줘. 각 단계를 내가 브라우저 개발자도구(F12)로
어떻게 확인하는지, 무엇이 보이면 그 단계가 정상인지 알려줘.
```

**⑥ 흔한 함정 / AI가 틀리는 것**
AI는 진단 단계를 건너뛰고 곧장 "이 코드 한 줄을 고쳐보세요"로 직행하는 경향이 있습니다. 실제 원인이 DNS 전파나 응답코드인데 멀쩡한 코드를 헤집어 새 버그를 만들기도 합니다.

**⑦ 검증하는 법**
브라우저에서 **F12 → Network 탭**을 열고 페이지를 새로고침합니다. 정적 페이지(이 본문)와 진도체크 같은 동적 페이지의 요청 목록이 다르게 찍히는 것을 눈으로 확인하세요. 요청이 있는데 빨간 줄(에러)이면 응답 단계, 요청 자체가 없으면 그 앞 단계 문제입니다.

!!! example "💡 예시로 이해하기"
    친구가 "유튜브가 안 열려!"라고 카톡을 보냈다고 해봅시다. 디렉터는 4단계로 나눠 묻습니다. "주소창에 `youtube.com` 치면 빙글빙글 돌다 '사이트를 찾을 수 없음'이 떠?(→ DNS 문제)" "아니면 회색 화면에 '500'이라고 떠?(→ 서버 응답 문제)" 친구가 "다른 사이트는 다 되는데 유튜브만 안 돼"라고 답하면 DNS·내 인터넷 문제가 아니라 유튜브 서버 쪽 문제로 좁혀집니다. 한 덩어리 "안 돼"가 `다른 사이트는 되는데 유튜브만 500` 한 문장으로 바뀌는 순간, 원인 후보가 4개에서 1개로 줄어듭니다.
