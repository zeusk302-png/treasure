# 클라이언트 vs 서버 — 손님과 주방

**① 한 줄 정의**
**클라이언트**는 사용자의 브라우저(손님 자리), **서버**는 데이터와 비밀을 다루는 컴퓨터(주방)입니다. "이 코드가 *어디서* 실행되는가"가 모든 보안·성능 결정의 출발점입니다.

**② 왜 중요한가 (디렉터 관점)**
비밀키·데이터베이스 접근·결제 검증처럼 **새면 안 되는 일은 반드시 서버에서** 일어나야 합니다. 클라이언트에서 도는 코드는 사용자가 브라우저 개발자도구로 전부 들여다볼 수 있기 때문입니다. 디렉터가 이 경계를 모르면, AI가 "빠르게 동작하니까"라며 비밀 작업을 손님 자리에 둔 코드를 줘도 알아채지 못합니다.

**③ 비유**
식당에서 손님(클라이언트)은 메뉴를 고르고 주문합니다. 하지만 식자재 창고 열쇠, 금고, 레시피 원본은 **주방(서버)** 에 있습니다. 손님 테이블 위에 금고 열쇠를 올려두지 않듯, 비밀키를 브라우저에 두면 안 됩니다.

**④ 최소한 알 것**
- 브라우저(클라이언트)에 보내진 코드·값은 **누구나 볼 수 있다**.
- 비밀키, DB 직접 접근, 결제 승인 검증은 **서버 전용**.
- 다음 권(보안)으로 직결됩니다.

**⑤ AI에게 이렇게 시켜라**

```text
이 기능을 만들 때, 클라이언트(브라우저)에서 도는 코드와 서버에서 도는
코드를 나눠서 표로 정리해줘. 비밀키·DB 접근·결제 검증 같은 민감한 작업이
혹시 클라이언트 쪽에 들어가 있으면 빨간 표시로 경고하고,
왜 그게 위험한지, 서버로 옮기려면 어떻게 해야 하는지 알려줘.
```

**⑥ 흔한 함정 / AI가 틀리는 것**
AI는 빠른 동작을 위해 민감한 작업을 클라이언트에 두는 코드를 종종 제시합니다(키 노출). 특히 데모·프로토타입 코드에서 자주 발생합니다.

!!! warning "정정: anon 키 vs service_role 키"
    `anon`(publishable) 키는 **프론트에 노출돼도 되는 공개 출입증**입니다. 반면 `service_role`(secret) 키는 모든 보안을 우회하는 **진짜 비밀**이라 절대 서버 밖으로 나가면 안 됩니다. 안전의 핵심은 키를 숨기는 게 아니라 **RLS(행 수준 보안)** 입니다. (자세한 내용은 권4)

**⑦ 검증하는 법**
브라우저 F12 → Sources(또는 빌드된 JS 파일)에서 키 문자열을 검색합니다. **anon 키는 보여도 정상, service_role 키가 보이면 즉시 사고**입니다. 이 사이트는 그 경계를 일부러 그대로 노출해 보여줍니다.
