# HTTP 요청과 응답 — 주문서와 음식, 그리고 상태코드

**① 한 줄 정의**
브라우저가 서버에 보내는 **요청(주문서)** 과 서버가 돌려주는 **응답(음식)**, 그리고 응답마다 붙는 **상태코드**(200·404·401·403·500)가 웹의 대화 방식입니다.

**② 왜 중요한가 (디렉터 관점)**
상태코드는 디렉터의 **진단 단어장**입니다. "안 돼요" 대신 "404가 떠요" 또는 "401이 떠요"라고 말하는 순간, 문제의 성격이 정해지고 AI에게 정확히 시킬 수 있습니다. 숫자 하나가 "주소가 없다"인지 "권한이 없다"인지 "서버가 터졌다"인지를 가릅니다.

**③ 비유**
식당에서 주문서(요청)를 넣으면 음식(응답)이 나옵니다. 같이 오는 영수증의 도장이 상태코드입니다. "정상 제공(200)", "그런 메뉴 없음(404)", "회원만 주문 가능(401)", "당신은 주문 권한 없음(403)", "주방 화재(500)".

**④ 최소한 알 것**

| 코드 | 뜻 | 디렉터 해석 |
|---|---|---|
| 200 | 성공 | 정상 |
| 404 | 없음 | 주소·경로가 틀림 |
| 401 | 인증 안 됨 | 로그인이 필요 |
| 403 | 인가 안 됨 | 로그인은 했지만 권한 없음 |
| 500 | 서버 오류 | 서버 쪽 코드가 터짐 |

- GET = 조회(가져오기), POST = 생성/전송(보내기)가 대표적.

**⑤ AI에게 이렇게 시켜라**

```text
지금 화면에 에러가 떠. 코드를 고치기 전에, 브라우저 F12 → Network 탭에서
빨간 요청을 클릭하면 보이는 '상태코드(Status)'를 내가 어디서 읽는지 알려줘.
그 코드가 200/404/401/403/500 중 무엇이냐에 따라 원인이 어떻게 달라지는지,
각 경우에 내가 무엇을 먼저 확인해야 하는지 표로 정리해줘.
```

**⑥ 흔한 함정 / AI가 틀리는 것**
AI는 상태코드를 묻지 않고 추측으로 코드를 고칩니다. 401(인증)과 403(인가)을 섞어서 진단하거나, 404(주소 문제)인데 서버 코드를 건드리게 만들기도 합니다.

**⑦ 검증하는 법**
F12 → Network 탭에서 댓글 작성(POST)과 댓글 조회(GET)가 **서로 다른 요청으로 찍히는 것**을 확인합니다. 각 요청의 Status 열을 읽어 200인지 확인하고, 일부러 권한 없는 동작을 시도해 401/403이 뜨는 것을 직접 봅니다.

!!! example "💡 예시로 이해하기"
    같은 "글이 안 보여요"라도 상태코드 하나로 진단이 완전히 갈립니다.

    - `404`: 친구가 보낸 블로그 링크 끝에 오타가 나서 `/post/123` 대신 `/post/132`로 들어감 → 그런 글이 없다. AI에게 시킬 일: 주소·경로 확인.
    - `401`: 로그아웃 상태로 '내 주문 내역'을 열었다 → 로그인부터 하라는 뜻. AI에게 시킬 일: 로그인 처리 확인.
    - `403`: 일반 회원이 관리자 페이지 주소를 직접 쳐서 들어감 → 로그인은 했지만 권한이 없다. AI에게 시킬 일: 권한(역할) 설정 확인.
    - `500`: 내 코드는 멀쩡한데 화면이 회색으로 죽음 → 서버가 터진 것. AI에게 시킬 일: 서버 로그부터 보기.

    "안 돼요" 대신 `403이 떠요` 한마디면, AI가 엉뚱하게 로그인 코드를 헤집는 대신 곧장 권한 설정을 봅니다.
