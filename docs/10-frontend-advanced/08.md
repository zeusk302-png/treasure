# 애니메이션·인터랙션 — 움직임으로 의미를 더하기

**① 한 줄 정의**
애니메이션·인터랙션이란 화면 요소가 **딱딱 끊기지 않고 부드럽게 변하거나, 사용자의 행동에 반응해 움직이는 것**으로, 멋을 부리기 위한 장식이 아니라 **"지금 무슨 일이 일어났는지"를 눈으로 알려주는 의사소통 수단**입니다.

**② 왜 중요한가 (디렉터 관점)**
움직임은 사용자에게 **상태(state)의 변화를 설명하는 자막**입니다. 버튼을 눌렀는데 화면이 0.1초 만에 휙 바뀌면 사람은 "내가 진짜 누른 게 맞나?" 하고 헷갈립니다. 반대로 메뉴가 스르륵 펼쳐지고, 삭제한 항목이 슬쩍 사라지면 뇌가 "아, 저게 저기로 갔구나"를 자동으로 따라갑니다. 즉 좋은 모션은 **사용자의 머릿속에서 일어나는 일을 화면 위에서 대신 그려주는 것**입니다.

디렉터에게 이게 무기가 되는 이유는 두 가지입니다. 첫째, AI에게 "예쁘게 해줘"라고 막연히 시키면 AI는 화려하지만 **거슬리고 느린** 애니메이션을 잔뜩 붙입니다. 디렉터가 "이 동작은 의미를 전달하려는 거야, 200ms 안에 부드럽게, 접근성도 챙겨서"라고 의도를 짚어주면 결과물의 격이 달라집니다. 둘째, 모션은 **과하면 독**이 되는 거의 유일한 UI 요소입니다. 많이 넣을수록 좋은 색깔·여백과 달리, 애니메이션은 **덜어내는 판단**이 핵심입니다. 코드를 못 짜도 "이건 너무 많다 / 이건 너무 느리다 / 이건 어지럽다"를 판정할 수 있으면, 그게 바로 디렉터의 일입니다.

**③ 비유**
모션은 **연극 무대의 조명·암전**과 같습니다. 한 장면에서 다음 장면으로 넘어갈 때 조명이 서서히 꺼졌다 켜지면 관객은 "장면이 바뀌는구나"를 자연스럽게 받아들입니다. 그런데 조명이 매 대사마다 번쩍이고 무대가 빙글빙글 돌면, 관객은 정작 배우의 대사에 집중하지 못하고 멀미만 합니다. 모션의 목적은 **관객(사용자)의 시선을 다음에 봐야 할 곳으로 부드럽게 안내**하는 것이지, 무대 장치 자체를 자랑하는 게 아닙니다. 좋은 무대 감독은 조명을 화려하게 쓰는 사람이 아니라 **언제 조명을 쓰지 않을지 아는 사람**입니다.

**④ 최소한 알 것**

먼저 "움직이는 방법"에는 크게 세 갈래가 있습니다.

| 방법 | 한 줄 설명 | 언제 쓰나 | 길라잡이 |
|---|---|---|---|
| CSS `transition` | A 상태→B 상태로 **부드럽게 건너가기**(호버, 색·크기·위치 변화) | 버튼 호버, 메뉴 펼침, 작은 상태 변화 대부분 | 🟢 메인 |
| CSS `animation`(`@keyframes`) | 시작·중간·끝을 정해 **반복·자동 재생**(로딩 스피너, 깜빡임) | 로딩 표시, 주목 끌기, 자동 반복 동작 | 🟡 대안 |
| 모션 라이브러리(Framer Motion 등) | 자바스크립트로 **복잡한 흐름·물리감·등장/퇴장**을 다룸 | 목록 추가/삭제, 페이지 전환, 드래그, 정교한 연출 | 🔵 나중에 |

다음으로 "좋은 모션의 원칙" 몇 가지를 알면 판정이 됩니다.

- **빠르게**: 화면 안 상호작용 모션은 대체로 **150~300ms**가 편안합니다(정확한 권장치는 디자인 가이드마다 다르니 확인 권장). 0.5초가 넘어가면 "느리다, 답답하다"가 됩니다.
- **자연스럽게(easing)**: 실제 사물은 등속으로 움직이지 않고 **천천히 출발해 부드럽게 멈춥니다**. `ease-out`(빨리 시작해 살살 멈춤)이 등장에, `ease-in-out`이 위치 이동에 무난합니다. `linear`(기계적 등속)는 로딩 스피너 같은 반복에만.
- **의미 있게**: 모든 움직임은 "왜 움직이는가"에 답할 수 있어야 합니다. 답이 "그냥 멋있어서"면 빼는 게 낫습니다.
- **방해하지 않게**: 사용자가 **읽거나 입력하는 중에는 멈춰** 있어야 합니다. 무한 반복 애니메이션이 본문 옆에서 계속 돌면 시선을 빼앗깁니다.
- **접근성(가장 중요)**: 일부 사용자는 움직임에 **어지럼증·메스꺼움(전정 장애)**을 느낍니다. OS에 "동작 줄이기"를 켜둔 사람을 위해 `@media (prefers-reduced-motion: reduce)`로 애니메이션을 끄거나 약하게 만들어야 합니다. 이건 선택이 아니라 **기본 예의**입니다.

| 용어 | 쉬운 뜻 |
|---|---|
| `transition` | 두 상태 사이를 부드럽게 잇는 다리 |
| `@keyframes` / `animation` | 정해둔 장면들을 자동 재생하는 영상 |
| easing(가속/감속 곡선) | 움직임의 "출발·도착 느낌"(살살/확) |
| duration(지속 시간) | 움직임이 끝나는 데 걸리는 시간(ms) |
| `prefers-reduced-motion` | "움직임 줄여줘"라는 사용자 설정을 읽는 신호 |

**⑤ AI에게 이렇게 시켜라**

```text
내 웹페이지의 모달(팝업)이 나타날 때 너무 뚝 떠서 어색해.
부드럽게 등장하는 애니메이션을 CSS transition으로 넣어줘. 조건은 이래:

1) 목적: 사용자가 "팝업이 떴다"를 자연스럽게 인지하게 하는 것. 화려함이 아니라
   의미 전달이 목적이야.
2) 등장은 0.2초(200ms) 정도, easing은 ease-out으로 살살 멈추게.
   불투명도(opacity)와 살짝 위로 떠오르는 느낌(translateY) 정도만. 과하지 않게.
3) 가장 중요: prefers-reduced-motion: reduce 설정을 켠 사용자에게는
   애니메이션을 끄고 즉시 표시되게 해줘. 왜 이게 접근성에 중요한지 주석으로 설명해줘.
4) 비전공자가 읽을 수 있게, 어떤 속성이 무슨 역할인지 한 줄씩 한국어 주석을 달아줘.

라이브러리는 쓰지 말고 순수 CSS로. 결과를 붙여주고, 내가 눈으로 확인할
체크 포인트(개발자도구에서 뭘 보면 되는지)도 알려줘.
```

**⑥ 흔한 함정 / AI가 틀리는 것**

- **`prefers-reduced-motion`을 잊는다**: AI에게 "애니메이션 넣어줘"라고만 하면 거의 항상 접근성 처리를 빼먹습니다. 어지럼증을 느끼는 사용자에게는 화면이 멀미 나는 놀이기구가 됩니다. **명시적으로 시켜야** 챙겨줍니다.
- **과용**: AI는 "더 멋지게"를 시키면 모든 요소에 들썩이는 애니메이션을 답니다. 결과는 산만하고 느려 보입니다. 모션은 **두세 군데 핵심 동작에만**.
- **너무 느림**: 0.5~1초짜리 전환을 기본으로 넣는 경우가 많습니다. 데모 영상에선 우아해 보여도 매일 쓰는 사람에겐 답답합니다.
- **무거운 속성 애니메이션**: `width`·`height`·`top`·`left`처럼 **레이아웃을 다시 계산하게 만드는 속성**을 애니메이션하면 저사양 기기에서 뚝뚝 끊깁니다. 부드러운 건 `transform`(이동·크기)과 `opacity`(투명도)입니다. AI가 `left`로 이동시키면 "transform: translate로 바꿔줘"라고 요청하세요.
- **무한 반복**: 본문 옆에서 끝없이 도는 애니메이션은 시선을 계속 훔칩니다. 반복은 **로딩 중처럼 일시적인 상황**에만.
- **라이브러리 과투입**: 단순 호버 효과 하나에 Framer Motion 같은 라이브러리를 통째로 끌어오면 페이지가 무거워집니다(번들 크기 ↑ → 느려짐). 작은 건 CSS로 충분합니다. *(라이브러리 이름·버전·세부 API는 시점에 따라 바뀌니 확인 권장.)*

**⑦ 검증하는 법**

1. **눈으로**: 만든 애니메이션을 5번 반복해서 보세요. **세 번째쯤에 거슬리거나 답답하면** 너무 느리거나 과한 것입니다. 좋은 모션은 반복해도 "있는 줄도 모르게" 자연스럽습니다.
2. **속도 줄여 관찰**: 크롬 개발자도구 → **F12 → ⋮(우상단) → More tools → Animations** 패널을 열면 애니메이션을 슬로우(25%)로 재생해 곡선과 시간을 확인할 수 있습니다.
3. **접근성 스위치 테스트**: OS 설정에서 동작 줄이기를 켜고 다시 봅니다.
   - 윈도우: 설정 → 접근성 → 시각 효과 → "애니메이션 효과" 끄기
   - macOS: 시스템 설정 → 손쉬운 사용 → 디스플레이 → "동작 줄이기"
   이 상태에서 애니메이션이 **꺼지거나 확 약해지면 합격**, 그대로 다 돌면 `prefers-reduced-motion` 처리가 빠진 것입니다.
4. **저사양 흉내**: 개발자도구 → Performance 또는 Rendering 탭에서 CPU를 4배·6배 느리게 설정한 뒤 애니메이션이 끊기는지 봅니다. 끊기면 무거운 속성을 쓴 신호입니다(→ `transform`/`opacity`로 교체 요청).

!!! example "💡 예시로 이해하기"
    온라인 쇼핑몰에서 "장바구니 담기" 버튼을 눌렀다고 해봅시다. 아무 변화 없이 숫자만 0에서 1로 바뀌면, 사람은 "어? 담긴 거야?" 하고 한 번 더 누릅니다(그래서 두 개가 담깁니다). 잘 만든 화면은 **상품 이미지가 작게 떠올라 우상단 장바구니 아이콘으로 슥 빨려 들어가고**, 아이콘 위 숫자가 톡 튀어오릅니다. 이 0.3초짜리 움직임 하나가 "당신이 방금 담은 그 물건이, 저 위 장바구니로 들어갔어요"라는 문장을 말 없이 전합니다. 여기에 디렉터는 한 가지를 더 챙깁니다. 동작 줄이기를 켠 사용자에게는 날아가는 애니메이션 대신 **숫자가 즉시 1로 바뀌고 살짝 색만 강조**되게 합니다. 어지럼증을 느끼는 사람도, 안 느끼는 사람도 똑같이 "담겼다"를 알 수 있게 — 이게 바로 움직임으로 의미를 더하되 누구도 소외시키지 않는 모션입니다.
