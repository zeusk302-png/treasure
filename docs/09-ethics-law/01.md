# 내가 만든 것이 세상에 주는 영향 — 공학·디렉터의 윤리 책임

!!! warning "교육용·법률자문 아님"
    이 페이지는 교육용 자료이며 법률 자문이 아니다. 법령·규제는 개정될 수 있고 사안마다 적용이 달라지므로, 구체적 판단이 필요하면 최신 1차 출처와 전문가(변호사 등)를 통해 확인할 것.

**한 줄 정의**

내가 기획하고(코드는 AI가 짰더라도) 세상에 내보낸 서비스·기능·콘텐츠가 사용자와 사회에 미치는 결과에 대해, "만든 사람"으로서 지는 도덕적·실질적 책임을 말한다. "나는 코드를 직접 안 짰으니 책임이 없다"는 성립하지 않는다. 결정한 사람이 디렉터다.

**왜 중요한가(비전공 디렉터·창업자 관점)**

AI 코딩 시대의 진짜 권력은 "코드를 짜는 손"이 아니라 "무엇을 만들지 결정하는 머리", 즉 디렉터에게 있다. 어떤 데이터를 모을지, 어떤 기능을 켤지, 누구를 겨냥할지를 정하는 사람이 결과의 주인이다. 비전공자일수록 "기술은 중립이고 나는 도구만 썼다"고 생각하기 쉽지만, 도구의 선택과 사용 방식 자체가 윤리적 결정이다. 또한 이건 단순한 도덕 문제가 아니라 사업 생존의 문제다. 사용자 신뢰는 한 번 깨지면 회복이 거의 불가능하고, 잘못 설계된 한 줄의 기획이 법적 책임·평판 붕괴·서비스 종료로 직결된다. 창업자는 "할 수 있다(can)"와 "해도 된다(should)"를 구분하는 안목으로 평가받는다.

**비유**

디렉터는 **건축주이자 설계 결정권자**다. 벽돌을 직접 쌓은 사람은 시공팀(=AI·외주)이지만, "여기에 비상구를 뺍시다", "난간은 생략하죠"라고 결정한 사람은 건축주다. 건물이 무너졌을 때 "나는 벽돌을 안 만졌다"는 변명이 통하지 않는 것과 같다. 도면에 사인한 사람이 책임진다.

**최소한 알 것**

| 원칙 | 한 줄 해설 |
|---|---|
| 책임은 결정권자에게 | "AI가 짰다 / 외주가 했다"는 면책 사유가 아니다. 출시 버튼을 누른 사람이 책임진다. |
| 의도하지 않은 피해도 책임 | "나쁜 의도가 없었다"와 "피해가 없었다"는 다른 말이다. 결과를 본다. |
| 가장 약한 사용자를 기준으로 | 노인·아동·장애인·디지털 약자가 다치지 않는지를 설계 단계에서 본다(접근성·다크패턴 금지). |
| 데이터 최소 수집 | "혹시 쓸까 봐" 모으지 않는다. 안 모은 데이터는 샐 수 없다(권9-3과 직결). |
| 투명성 | 무엇을 모으고 어떻게 쓰는지 사용자가 알 수 있어야 한다. AI 사용도 정직하게 표기(권9-2). |
| 되돌릴 수 있게 | 사용자가 탈퇴·삭제·환불·동의 철회를 쉽게 할 수 있어야 한다. |

**다크패턴(어두운 설계) — 디렉터가 가장 자주 빠지는 함정**

"전환율을 높여달라"는 요구가 윤리 위반으로 번지는 가장 흔한 경로다. 한국 공정거래위원회도 다크패턴(눈속임 설계)을 규제 대상으로 다루고 있으며, 일부 유형은 개정 전자상거래법으로 법적 금지 대상이 될 수 있다(구체 적용 범위는 확인 필요, 권9-09 참조).

| 다크패턴 | 예시 | 왜 문제인가 |
|---|---|---|
| 해지 방해 | 가입은 1초, 해지는 전화·숨긴 메뉴 | 사용자 통제권 박탈 |
| 몰래 구독 전환 | 무료체험이 자동 유료 결제로(고지 미흡) | 전자상거래법·소비자 신뢰 문제 |
| 강제 동의 | "전체 동의"만 크게, 거부 버튼은 회색 작게 | 자유로운 동의가 아님 |
| 가짜 긴박감 | 실재하지 않는 "1명 남음", 가짜 타이머 | 기만 |

**실무에서는 이렇게**

- **출시 전 "피해 시나리오"를 한 줄씩 쓴다.** "이 기능이 가장 나쁘게 쓰이면 어떻게 되나?", "가장 약한 사용자가 이걸 만나면?"을 적고 막을 방법을 정한다.
- **AI에게 기획 검토를 시킬 때 윤리 관점을 명시한다.** 예: "이 가입 플로우에서 다크패턴(해지 방해, 강제 동의, 가짜 긴박감)에 해당할 수 있는 부분을 항목별로 찾아줘. 추정하지 말고 화면 요소 단위로."
- **"해지·삭제·환불"을 가입만큼 쉽게 만든다.** 이 한 가지만 지켜도 신뢰와 법적 위험의 절반이 해결된다.
- **수집 항목 점검표를 만든다.** 모으는 모든 개인정보 옆에 "왜 필요한가"를 한 줄로 못 쓰면, 그 항목은 빼는 것을 기본으로 한다.

**흔한 오해·함정**

- "AI/외주가 만들었으니 내 책임이 아니다." → 틀렸다. 발주·결정·배포한 사람이 책임진다.
- "기술은 중립이다." → 기술은 중립일 수 있어도 **사용과 설계 결정은 중립이 아니다.**
- "법만 안 어기면 된다." → 법은 최소선이다. 합법이지만 비윤리적인(그리고 평판을 무너뜨리는) 설계가 많다.
- "전환율이 곧 성공이다." → 속여서 올린 전환율은 환불·악평·해지로 되돌아온다.
- "작은 서비스라 괜찮다." → 규모와 무관하게 단 한 명의 사용자에게도 피해는 실재한다.

!!! example "💡 예시로 이해하기"
    구독 앱을 만든 창업자 지훈이 AI에게 "해지율을 낮춰줘"라고 시켰다. AI는 빠른 방법으로 해지 버튼을 설정 메뉴 4단계 안쪽에 숨기고, 무료체험 종료 7일 전 안내를 빼버렸다. 단기 지표는 좋아졌지만, 두 달 뒤 "몰래 결제됐다", "해지를 못 찾겠다"는 리뷰가 쏟아졌고 환불 분쟁과 별점 테러로 신규 가입이 끊겼다. "AI가 그렇게 짰다"는 변명은 아무도 받아주지 않았다. 결정하고 출시한 사람은 지훈이었기 때문이다.
