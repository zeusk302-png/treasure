# LLM API 연동 — 내 앱에 지능 넣기

**① 한 줄 정의**
LLM API 연동이란, **남이 만든 똑똑한 AI 모델(Claude 같은)을 내 서버가 대신 호출해서**, 요약·분류·챗봇 같은 '지능'을 내 앱 안에 끼워 넣는 일입니다. 모델을 직접 만드는 게 아니라 **빌려 쓰고, 그 앞뒤(프롬프트·대화기록·비용·검증)를 내가 책임지는** 것이 핵심입니다.

**② 왜 중요한가 (디렉터 관점)**
"AI 기능 넣어주세요"는 4일 부트캠프 수료생이 가장 많이 듣는 요청입니다. 그런데 여기서 디렉터가 반드시 짚어야 할 판단이 세 가지 있습니다. **(1) 키를 어디서 부르는가** — 브라우저에서 직접 부르면 키가 새서 요금 폭탄을 맞습니다. **(2) 비용을 어떻게 막는가** — AI는 토큰(글자 묶음) 단위 종량제라 통제 없이 출시하면 한 달 청구서가 무섭게 불어납니다. **(3) 틀린 답을 그대로 흘리는가** — AI는 가짜 사실·가짜 링크를 그럴듯하게 지어냅니다.

코드는 AI가 짜줍니다. 하지만 *"이 호출이 서버에서만 일어나는지", "이 답을 사용자에게 그대로 보여줘도 되는지"*를 판별하는 건 사람입니다. 이 페이지가 가르치는 건 코드가 아니라 **"AI에게 LLM 기능을 시킬 때 무엇이 위험하고 무엇을 확인해야 하는가"**라는 디렉터의 체크리스트입니다.

**③ 비유**
LLM API는 **'전화로 주문하는 만능 통역사 겸 작가'**라고 생각하면 쉽습니다. 가게(내 앱)에 손님(사용자)이 와서 뭔가를 부탁하면, 내가 직접 답하는 게 아니라 **뒤쪽 사무실(내 서버)에서 그 통역사에게 전화를 겁니다.** 통역사는 똑똑하지만 기억력이 없어서(무상태), 전화를 끊으면 방금 대화를 까맣게 잊습니다. 그래서 이어서 물어보려면 **지금까지의 대화 내용을 매번 처음부터 다시 읽어줘야** 합니다.

그리고 이 통역사는 **통화 시간(토큰)만큼 돈을 받습니다.** 길게 말할수록, 자주 걸수록 비용이 쌓입니다. 무엇보다 중요한 건 — **통역사에게 거는 전화번호(API 키)를 손님에게 보여주면 안 됩니다.** 그 번호를 알면 누구나 내 이름으로 전화를 걸어 내 계좌에서 통화료가 빠져나가니까요. 그래서 전화는 **반드시 뒤쪽 사무실(서버)에서만** 겁니다.

**④ 최소한 알 것**

LLM 호출 한 번을 구성하는 조각들:

| 조각 | 무엇인가 | 비유 |
|---|---|---|
| 시스템 프롬프트(system) | AI의 역할·규칙을 고정하는 '근무 수칙' | 통역사에게 미리 주는 사훈("정중하게, 거짓말 금지") |
| 사용자 메시지(messages) | 실제 손님이 한 말 | 손님의 주문 내용 |
| 모델(model) | 어떤 AI를 부를지 | 어떤 등급의 통역사를 부를지 |
| 응답(content) | AI가 돌려준 답 | 통역사가 내놓은 결과물 |
| 토큰(token) | 글자를 잘게 나눈 과금 단위 | 통화 시간(요금의 기준) |
| 스트리밍(stream) | 답을 한 글자씩 흘려보내기 | 통역사가 말하는 대로 받아 적기 |

이 권에서 흔히 쓰는 세 가지 작업과 길라잡이 판정:

- 🟢 **요약** — 긴 글을 짧게. 시스템 프롬프트에 "3문장으로 요약" 같은 규칙만 주면 끝. AI 기능의 가장 쉬운 입문.
- 🟢 **분류** — "이 문의는 환불/배송/기타 중 무엇?" 같은 라벨 붙이기. 답이 정해진 보기 안에서만 나오게 하면 안정적.
- 🟡 **챗봇** — 대화가 이어져야 하므로 **대화기록 저장·재전송**이 필요(가장 손이 많이 감).
- 🔵 **도구 사용·내 문서 검색(RAG)** — 더 고급. 같은 권 [RAG와 임베딩](06.md)에서.

Claude 모델 (정확한 최신 정보 — 가격은 시점성이라 **공식 문서 재확인 권장**):

| 모델 | 모델 ID | 성격 |
|---|---|---|
| Claude Fable 5 | `claude-fable-5` | 가장 강력. 가장 어려운 추론·장기 작업 |
| Claude Opus 4.8 | `claude-opus-4-8` | 최상위 Opus. **AI 앱 기본 권장값** |
| Claude Sonnet 4.6 | `claude-sonnet-4-6` | 속도·지능 균형. 대량 처리에 |
| Claude Haiku 4.5 | `claude-haiku-4-5` | 가장 빠르고 저렴. 단순·속도 작업에 |

기본은 최신·최강인 **Claude Opus 4.8**(`claude-opus-4-8`)을 권합니다. 비용·속도가 더 중요한 단순 작업(예: 분류)이라면 Haiku로 내려도 됩니다.

!!! warning "키는 서버에만 — 브라우저 금지"
    Claude API 키(`ANTHROPIC_API_KEY`)는 **절대 브라우저로 가는 코드에 넣지 않습니다.** 반드시 서버(Next.js의 `/api/...` 라우트, 서버 액션)에서만 부르고, 키는 서버 환경변수에 둡니다. 브라우저에 한 번이라도 박히면 누구나 개발자도구로 꺼내 내 계정으로 호출해 요금을 태울 수 있습니다.

**⑤ AI에게 이렇게 시켜라**

```text
Next.js(App Router) + Vercel로 간단한 AI 기능(고객 문의 요약·분류 또는 챗봇)을 만들 거야.
나는 비전공자 '디렉터'라서, 코드를 직접 짜기보다 '제대로 됐는지' 판별하고 싶어.
정확한 최신 Claude 정보로 다음을 지켜서 만들어줘:

1) Claude 호출은 반드시 서버 라우트(/api/chat 같은)에서만. 공식 SDK(@anthropic-ai/sdk) 사용.
   모델은 claude-opus-4-8 (최신·최강 기본값). API 키는 서버 환경변수 ANTHROPIC_API_KEY로 두고,
   절대 브라우저로 가는 코드(클라이언트 컴포넌트)에 키 문자열이 들어가지 않게 해줘.
2) 메시지 구조를 명확히: 역할·규칙은 system 프롬프트에, 사용자 입력은 messages에 분리해서.
   왜 분리하는지 주석으로 설명해줘(프롬프트 인젝션 방어와도 연결).
3) 응답은 스트리밍으로 한 글자씩 흘려보내(긴 답 타임아웃 방지·체감속도). 화면 출력은 textContent로 —
   AI 답을 innerHTML로 그대로 꽂으면 XSS 위험이 있으니 그 이유도 주석에 적어줘.
4) 비용 통제: max_tokens 상한을 걸고, 한 사용자가 무한정 호출 못 하게 막는 자리를 만들어줘.
5) 비정상 응답(429 속도제한·500 서버오류) 처리도. SDK가 자동 재시도하는 부분과 내가 처리할 부분을 구분.

작업 전에, 내가 몰라서 놓치기 쉬운 위험(키 노출·비용 폭주·환각을 그대로 노출·프롬프트 인젝션) 4가지를
먼저 알려줘. 그리고 네가 쓴 모델명·SDK 함수명이 공식 문서에 실제 존재하는 최신인지(추정이면 '추정'이라고)
표시해줘. 각 단계마다 코딩 지식 없이 '됐는지' 확인할 절차(무엇을 누르면 무엇이 보여야 성공인지)도 적어줘.
```

**⑥ 흔한 함정 / AI가 틀리는 것**

- **키를 프론트에 박는다.** AI는 "빠른 데모"라며 브라우저 코드에서 바로 Claude를 호출하는 예시를 곧잘 줍니다. 이러면 키가 새서 요금 폭탄·도용으로 이어집니다. **반드시 서버 경유.**
- **옛 모델명·없는 함수를 지어낸다.** AI의 지식에는 마감 시점이 있어서, 옛 모델 ID(예: 오래된 `claude-3-...`)나 실제로 없는 SDK 함수를 자신만만하게 줄 수 있습니다. **모델 ID와 SDK 사용법은 항상 공식 문서로 재확인.** 이 페이지의 ④표가 현재 정확한 모델 ID입니다.
- **대화기록 처리를 빼먹는다.** LLM은 무상태(기억 없음)인데, AI가 "이전 메시지 재전송" 로직을 빠뜨리면 챗봇이 방금 한 말을 기억 못 합니다. 반대로 매번 *전체* 기록을 통째로 보내 토큰·비용이 폭발하기도 합니다.
- **비용 통제를 안 넣는다.** `max_tokens` 상한이나 사용자별 호출 한도 없이 출시하면, 누군가 길게·자주 호출할 때 그대로 청구됩니다.
- **환각을 검증 없이 흘린다.** AI는 가짜 사실·가짜 링크를 그럴듯하게 만듭니다. 의료·법률·금전처럼 책임이 큰 영역에서 그대로 노출하면 책임은 서비스 운영자(나)에게 옵니다.
- **응답 출력에 `innerHTML`을 쓴다.** AI가 만든 텍스트를 `innerHTML`로 화면에 꽂으면, 그 안에 섞인 스크립트가 실행될 수 있습니다(XSS). 사용자 입력·AI 출력 모두 **`textContent`로** 출력해야 안전합니다.

**⑦ 검증하는 법**

1. **키가 브라우저에 안 새는지** — 사이트를 띄우고 **F12 → Network 탭**을 연 뒤 AI 기능을 써봅니다. 요청이 외부 Anthropic 주소가 아니라 **내 서버(`/api/...`)로 가야** 정상입니다. 그리고 빌드된 브라우저 코드(개발자도구 Sources)에서 `ANTHROPIC_API_KEY`나 `sk-ant-...` 같은 키 문자열을 검색해 **0건**인지 확인합니다.
2. **기억하는지(챗봇)** — "내 이름은 영희야"라고 말한 다음, "내 이름이 뭐야?"라고 물어 **영희**라고 답하면 대화기록 재전송이 정상입니다.
3. **비용 상한이 있는지** — 아주 긴 답을 유도해 보고(예: "100문단으로 써줘"), 답이 무한정 늘어나지 않고 `max_tokens`에서 끊기는지 봅니다.
4. **이상 응답을 사용자에게 부드럽게 보여주는지** — 일부러 빠르게 여러 번 눌러 속도제한(429)을 유발하거나, 잠깐 키를 잘못 두고 시험해, 빨간 에러 화면 대신 "잠시 후 다시 시도해 주세요" 같은 안내가 뜨는지 확인합니다.
5. **출력이 안전한지** — 사용자 입력칸에 `<b>테스트</b>` 같은 태그를 넣어보고, 화면에 **굵게 변하지 않고 글자 그대로** 보이면 `textContent` 처리가 된 것입니다.

!!! example "💡 예시로 이해하기"
    카페를 운영하는데 매일 수십 건씩 들어오는 고객 문의를 자동 분류하고 싶다고 해봅시다. 디렉터는 AI에게 이렇게 시킵니다 — *"문의 내용을 받아 '환불 / 배송 / 메뉴 / 기타' 넷 중 하나로만 분류하는 기능을, 서버 라우트에서 claude-opus-4-8로 호출해 만들어줘. 분류 결과는 정해진 네 보기 밖으로 나오면 안 돼."* 며칠 뒤 AI가 준 코드를 받아, 디렉터는 코드를 한 줄도 못 읽지만 **세 가지를 확인**합니다. ① F12 Network에서 요청이 `/api/classify`(내 서버)로 가는가 — 외부 Anthropic 주소로 직접 가면 키가 새는 위험 신호. ② 브라우저 Sources에서 `sk-ant-` 검색 결과가 0건인가. ③ 엉뚱한 문의("오늘 날씨 어때?")를 넣어도 답이 네 보기 안에서만 나오는가. 셋 다 통과하면, *"AI가 분류를 잘하더라"*가 아니라 **"키도 안 새고, 비용도 막혀 있고, 출력도 안전하다"**는 디렉터의 확신으로 바뀝니다. AI가 만든 결과를 *믿는* 게 아니라 *판별하는* 것 — 그게 이 권 전체의 태도입니다.
