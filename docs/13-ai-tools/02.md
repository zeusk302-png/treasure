# 코딩 AI 고르기 — 무엇을 언제 쓰나

**① 한 줄 정의**
코딩을 도와주는 AI는 한 종류가 아니라 **터미널 에이전트(Claude Code) · 에디터 보조(Cursor·Copilot) · UI 생성기(v0·Bolt) · 설계 상담용 챗봇** 네 갈래로 나뉘며, 디렉터의 일은 "지금 작업에 어느 갈래를 부를지"를 고르는 것입니다.

**② 왜 중요한가 (디렉터 관점)**
같은 "AI한테 시킨다"라도 **무엇을 쓰느냐에 따라 결과의 질과 속도가 몇 배 차이**가 납니다. 빈 화면에서 디자인 시안을 빠르게 뽑고 싶은데 터미널 에이전트한테 "예쁜 랜딩페이지"라고만 시키면 헤매고, 반대로 "프로젝트 전체를 훑어서 같은 버그를 다섯 군데서 한 번에 고쳐줘" 같은 일을 채팅창에 코드 한 조각씩 복붙하며 시키면 하루가 갑니다. 디렉터는 코드를 짜는 사람이 아니라 **일에 맞는 도구를 배정하는 현장 감독**입니다. 망치로 나사를 박지 않고, 드라이버로 못을 치지 않는 것 — 그 분별이 곧 생산성입니다. 또 도구마다 **누가 내 코드를 보게 되는가(프라이버시)**, **얼마를 내는가(요금 구조)**, **얼마나 자동으로 파일을 건드리는가(권한)**가 다릅니다. 이걸 모르면 회사 비밀 코드를 엉뚱한 곳에 흘리거나, 에이전트가 멋대로 파일을 갈아엎고도 "다 됐어요"라고 보고하는 사고를 못 막습니다.

**③ 비유**
코딩 AI 고르기는 **집을 고칠 때 누구를 부르냐**와 같습니다.

- **터미널 에이전트(Claude Code)** = 집 전체를 둘러보고 알아서 손보는 **종합 시공팀**. "2층 배관 새는 거랑 1층 콘센트 다 점검해서 고쳐줘"라고 통째로 맡기면, 여러 방을 오가며 여러 파일을 한 번에 고치고 다시 돌려 확인까지 합니다. 대신 집 열쇠(파일 쓰기 권한)를 줘야 하니, 무엇을 손댈지 지켜봐야 합니다.
- **에디터 보조(Cursor·Copilot)** = 내 옆에 붙어 함께 작업하는 **숙련공**. 내가 망치를 들고 있으면 "거기 다음은 이렇게요" 하고 손이 닿는 범위를 거들어 줍니다. 내가 운전석에 있고 AI는 조수석입니다.
- **UI 생성기(v0·Bolt)** = 빈 땅에 **모델하우스를 뚝딱 지어 보여주는 분양사무소**. "카페 예약 화면 보여줘" 하면 즉석에서 보기 좋은 시안을 세워 줍니다. 멋지지만 실제로 사람이 살(진짜 데이터·로그인) 집은 아직 아닙니다.
- **챗봇(설계 상담)** = 공사 전 **건축사와의 상담 테이블**. 도면을 그리기 전에 "원룸으로 갈까 투룸으로 갈까, 이 구조의 위험은 뭘까"를 의논하는 자리. 직접 못질은 안 하지만 방향을 잡아 줍니다.

집 한 채 고치는 데도 이 넷을 다 부릅니다. 상담으로 방향 잡고 → 모델하우스로 그림 보고 → 시공팀에 통째로 맡기고 → 마무리는 숙련공과 나란히. 코딩도 똑같습니다.

**④ 최소한 알 것**

네 갈래의 강점·약점·언제 쓰는지:

| 갈래 | 대표 도구 | 무엇을 잘함 | 약점·주의 | 🟢언제 |
|---|---|---|---|---|
| 터미널 에이전트 | **Claude Code** | 프로젝트 전체를 읽고 **여러 파일을 자율적으로** 수정·실행·검증. 큰 리팩터링, 버그 일괄 수정, 명령 실행 | 파일 쓰기 권한을 줘야 함(지켜봐야). 터미널이 낯설면 진입장벽 | "전체를 손봐줘"류, 디버깅·리팩터링·자동화 |
| 에디터 보조 | Cursor, GitHub Copilot | 코드 쓰는 중 **줄 단위 자동완성·인라인 수정**. 내가 운전, AI가 거듦 | 큰 그림·다파일 작업엔 약함. 한 파일 시야 위주 | 한 파일을 손으로 고치며 거들 때 |
| UI 생성기 | v0, Bolt(볼트), Lovable | 말로 시켜 **보기 좋은 화면(컴포넌트)을 즉석 생성**. 시안·프로토타입 | 진짜 DB·로그인·결제는 미완. 겉만 그럴듯할 때 많음 | 빈 화면에서 디자인·시안 빠르게 |
| 설계 상담 챗봇 | Claude(claude.ai), ChatGPT | **방향·구조·트레이드오프 토론**, 개념 설명, 계획 세우기 | 코드 한 조각씩 복붙은 비효율. 내 파일을 직접 못 봄 | 짜기 전에 "어떻게 할까" 의논 |

알아둘 한 줄 원칙들:

- **"전체"가 들어가면 에이전트(Claude Code), "이 한 줄"이면 에디터 보조.** 작업 범위가 도구를 정합니다.
- **빈 화면 디자인은 v0류, 진짜 작동은 에이전트.** UI 생성기로 시안을 뽑고 그 코드를 Claude Code로 진짜 동작하게 잇는 흐름이 강력합니다.
- **짜기 전 의논은 챗봇, 짜기 시작하면 에이전트/에디터.** 계획은 말로, 실행은 파일로.
- **AI 앱(LLM API 연동)을 만들 땐 기본적으로 최신·최강 Claude를 권장.** 모델ID는 정확히 — **Opus 4.8: `claude-opus-4-8`** (최강·복잡추론), **Sonnet 4.6: `claude-sonnet-4-6`** (균형·일상작업), **Haiku 4.5: `claude-haiku-4-5`** (빠르고 저렴·단순분류), **Fable 5: `claude-fable-5`**. *(요금·한도 등 시점성 수치는 공식 문서 확인 권장.)*
- **프라이버시:** 회사·고객 코드를 다룰 땐 그 도구가 "내 코드로 모델을 학습하는가"를 꼭 확인하세요. 보통 유료 비즈니스 플랜은 학습 비사용을 보장합니다 — *공식 약관 확인 권장.*

**⑤ AI에게 이렇게 시켜라**

도구를 직접 고르기 어려울 때, 챗봇에게 **고르는 일 자체를 시키는** 메타 프롬프트:

```text
나는 코드를 직접 못 짜는 비전공 디렉터야. 지금 하려는 작업은 아래와 같아.

[작업] 카페 예약 사이트에서, 예약하기 버튼을 누르면 같은 시간대 중복 예약을
막는 기능을 추가하고 싶어. 프로젝트는 이미 Next.js + Supabase로 돌아가고 있어.

이 작업에 가장 잘 맞는 코딩 AI 유형을 골라줘.
- 후보: ① Claude Code(터미널 에이전트) ② Cursor·Copilot(에디터 보조)
  ③ v0·Bolt(UI 생성기) ④ Claude/ChatGPT 챗봇(설계 상담)
- 각 후보가 이 작업에서 강점/약점이 뭔지 한 줄씩,
- 최종 추천 1개와 '왜 그게 최선인지',
- 추천한 도구에 그대로 붙여넣을 수 있는 첫 지시문까지 만들어줘.
코드부터 쓰지 말고 '도구 선택과 이유'부터 정리해줘.
```

작업별로 바로 쓰는 추천 프롬프트(상황만 바꿔 복사):

```text
[빈 화면 디자인이 필요할 때 → v0/Bolt에]
모바일 우선의 카페 예약 랜딩페이지를 만들어줘. 상단 히어로(가게 사진+예약 버튼),
메뉴 3개 카드, 위치 지도 자리, 하단 영업시간. 색은 따뜻한 베이지/브라운 톤.
실제 데이터 연결은 나중에 할 거니 지금은 보기 좋은 화면(컴포넌트)만.

[전체를 손봐야 할 때 → Claude Code에]
이 프로젝트 전체에서 'textContent' 대신 'innerHTML'로 사용자 입력을 출력하는
곳을 모두 찾아서, XSS 위험이 없도록 textContent로 바꿔줘. 바꾼 파일 목록과
각각 왜 위험했는지 한 줄 설명을 보고서로 정리해줘. 바꾸기 전에 무엇을 바꿀지
먼저 보여주고 내 확인을 받고 진행해.
```

**⑥ 흔한 함정 / AI가 틀리는 것**

- **UI 생성기 결과를 "다 됐다"로 착각.** v0·Bolt가 만든 화면은 대개 **가짜 데이터(하드코딩)** 위에서 돕니다. 예약 버튼을 눌러도 진짜 DB에 저장되지 않고, 새로고침하면 사라집니다. "보이는 것 = 작동하는 것"이 아닙니다.
- **챗봇에 코드 한 조각씩 복붙하며 큰 작업.** 챗봇은 내 프로젝트 전체를 못 봅니다. 다섯 파일이 얽힌 버그를 채팅창에서 잡으려다 맥락이 끊겨 엉뚱한 수정을 받습니다 — 이건 에이전트(Claude Code)의 일입니다.
- **에이전트의 자율성을 방치.** Claude Code 같은 에이전트는 파일을 직접 고치고 명령을 실행합니다. "알아서 다 해줘"라고 던지고 안 보면, 멀쩡한 파일을 갈아엎거나 의도와 다른 방향으로 멀리 가 있을 수 있습니다. **무엇을 바꿀지 먼저 보여달라**고 시키고 지켜보세요.
- **모델 잘못 고르기.** 단순 분류·요약에 최강 모델을 쓰면 느리고 비싸고, 반대로 복잡한 추론에 가장 빠른(작은) 모델을 쓰면 자꾸 틀립니다. AI 앱을 만들 땐 기본적으로 최신·최강 Claude로 시작해 품질을 확인한 뒤, 단순한 일에만 가벼운 모델로 내려보는 게 안전합니다.
- **존재하지 않는 기능·라이브러리를 지어냄(환각).** 어느 도구든 그럴듯한 거짓을 만들 수 있습니다. "이런 기능이 정말 있는지 공식 문서 링크로 확인해줘"를 한 줄 붙이세요.
- **보안 줄을 대충.** AI가 Supabase 연동 코드를 줄 때 `service_role` 키를 브라우저 코드에 박아 넣는 실수를 종종 합니다. **anon 키는 공개돼도 되고 RLS로 보호**하지만, **service_role은 서버에만** 둬야 합니다. 이 구분을 AI가 지키는지 사람이 봐야 합니다.

**⑦ 검증하는 법**

- **"작동" 검증(UI 생성기 결과):** 만든 화면에서 버튼을 실제로 눌러 보고, **새로고침(F5)** 한 뒤에도 데이터가 남아 있는지 확인합니다. 새로고침하면 사라지면 = 아직 가짜 데이터(진짜 DB 미연결). 진짜 작동은 에이전트로 이어 붙여야 합니다.
- **"범위" 검증(에이전트 결과):** Claude Code 같은 에이전트가 끝났다고 하면 **"무슨 파일을 왜 바꿨는지 목록으로 보여줘"**를 시킵니다. 의도한 파일만 바뀌었는지 눈으로 대조합니다(git을 쓴다면 변경 내역으로 확인).
- **"도구 선택" 검증:** 작업을 시키기 전에 챗봇에 ⑤의 메타 프롬프트로 추천을 받고, 추천 **이유가 작업 성격과 맞는지** 봅니다. "여러 파일을 한 번에"인데 에디터 보조를 추천하면 어긋난 것입니다.
- **"모델·보안" 검증:** AI 앱 코드를 받으면 모델ID가 정확한지(`claude-opus-4-8` 등), 비밀키(`service_role`)가 브라우저 쪽에 노출되지 않았는지, 사용자 입력 출력이 `textContent`인지 점검합니다.

!!! example "💡 예시로 이해하기"
    부트캠프 수료생 지민이가 "동네 헬스장 예약 사이트"를 만들려고 합니다. 처음엔 익숙한 ChatGPT 채팅창에 "헬스장 예약 사이트 만들어줘"라고 쳤더니 코드 덩어리만 잔뜩 받아 어디 붙일지 막막했습니다. 도구를 갈래로 나눠 다시 했습니다. ① 먼저 **챗봇(Claude)** 과 "회원 등급별 예약 제한을 어떻게 둘까, 노쇼는 어떻게 막을까"를 상담해 구조를 잡았습니다. ② 그다음 **v0**에 "헬스장 예약 화면, 시간대 그리드, 모바일 우선"을 시켜 보기 좋은 시안을 30분 만에 받았습니다. 눌러보니 예약은 새로고침하면 사라지더군요 — 아직 모델하우스였던 겁니다. ③ 그래서 그 시안 코드를 **Claude Code**에 통째로 넘기고 "이 화면을 Supabase에 진짜 저장되게 잇고, 같은 시간대 중복 예약을 막아줘. 바꿀 파일을 먼저 보여줘"라고 맡겼습니다. 에이전트가 여러 파일을 오가며 연결하고 "이 3개 파일을 이렇게 바꾸겠다"고 먼저 보고했고, 지민이는 확인 후 진행시켰습니다. ④ 마지막으로 버튼 색 한 줄, 문구 한 줄 같은 잔손질은 **Cursor**에서 직접 보며 다듬었습니다. 같은 "AI한테 시킨다"였지만, 일에 맞는 도구를 배정하자 하루 종일 헤매던 일이 반나절로 끝났습니다.
