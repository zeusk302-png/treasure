# AI 도구 지형도 한눈에 — 무엇이 있고 언제 쓰나

**① 한 줄 정의**
이 권에서 다루는 도구들(코딩 AI·디자인 AI·자동화·외부 연동)을 **한 표에 펼쳐 놓고**, 비전공 디렉터인 내가 지금 **어디부터 손대고 무엇은 나중으로 미룰지** 길라잡이 판정(🟢🟡🔵⚪)으로 정리하는 '이 권의 지도' 페이지입니다.

**② 왜 중요한가 (디렉터 관점)**
도구가 많아 보이는 것은 사실 **착시**입니다. 코딩 AI, 디자인 AI, 자동화, 결제, 검색, 캐시, 챗봇… 이름은 수십 개지만, 비전공 청년이 만드는 첫 서비스에서 **진짜로 메인이 되는 도구는 손에 꼽습니다.** 나머지는 "있다는 것만 알고, 필요해질 때 펴 보면 되는" 것들이죠.

디렉터의 핵심 능력은 코드를 짜는 게 아니라 **"지금 이 문제에 어떤 도구를 부를 것인가"를 고르는 판단**입니다. 망치를 든 사람에게는 모든 게 못으로 보인다는 말처럼, 도구를 모르면 AI가 "Redis 붙이세요" "Algolia 쓰세요" 할 때 그게 *지금 나에게 필요한지 / 과한지*를 분간 못 합니다. 그러면 AI가 추천하는 대로 다 끌어다 붙여 **간단한 사이드 프로젝트에 대기업급 인프라**를 얹는 흔한 실수에 빠집니다.

이 지도 한 장을 머리에 넣어 두면, 누가 "○○ 도구 써야 하지 않아요?"라고 물을 때 **"그건 🔵 나중 단계예요, 지금은 🟢 이것부터"** 라고 짚어 줄 수 있습니다. 그게 디렉터가 회의실에서 갖는 무기입니다.

**③ 비유**
대형 마트 입구의 **층별 안내도**와 같습니다. 처음 온 사람은 매장 수만 개 품목 앞에서 길을 잃지만, 안내도는 "식품은 1층, 가전은 3층, 환불 데스크는 4층"으로 **큰 구역**만 보여 줍니다. 당장 우유 사러 왔으면 1층만 가면 되고, 냉장고는 "나중에 이사하면 3층"이라고 머리에 담아 두면 됩니다. 이 페이지가 바로 그 안내도이고, 02번부터 10번까지의 형제 페이지들이 각 '층의 상세 매대'입니다. 안내도를 안 보고 무작정 헤매면 우유 하나 사는 데 전 층을 다 돌게 됩니다.

또 하나의 비유: **주방의 도구 서랍**입니다. 칼 한 자루(코딩 AI)면 요리의 8할이 됩니다. 거품기·온도계·진공포장기(검색 엔진·캐시·결제)는 특정 요리를 할 때만 꺼냅니다. 초보 요리사가 첫날부터 진공포장기 사용법을 외울 필요는 없죠. "이 서랍에 그런 게 있다"만 알면 됩니다.

**④ 최소한 알 것**

먼저 도구를 **네 갈래(family)**로 나눠 봅니다. 머릿속 폴더가 4개면 충분합니다.

| 갈래 | 무엇을 하나 | 대표 도구 | 비유 |
|---|---|---|---|
| 코딩 AI | 코드를 짜 주고·고쳐 주는 동료 | Claude, Cursor, Claude Code | 같이 일하는 개발자 |
| 디자인 AI | 화면 디자인을 만들고·코드로 변환 | Figma, v0, Figma→코드 도구 | 디자이너 |
| 자동화·연결 | 도구들끼리 자동으로 잇기 | n8n, Zapier, MCP | 사무실 자동화 라인 |
| 인프라·연동 | 내 앱에 능력(검색·결제·기억)을 붙이기 | LLM API, Redis, Stripe, Algolia, RAG | 전기·수도·가스 배관 |

이제 **각 도구의 길라잡이 판정**입니다. 판정 아이콘 뜻 — 🟢 메인(지금 바로 익혀라) / 🟡 대안(상황 되면 고려) / 🔵 나중에(필요해질 때 펴 봐라) / ⚪ 몰라도 됨(개념만 알면 충분).

| 도구·주제 | 무엇에 쓰나 | 판정 | 한 줄 이유 | 상세 페이지 |
|---|---|---|---|---|
| 코딩 AI (Claude 등) | 코드 생성·수정·디버깅 | 🟢 메인 | 모든 작업의 기본 칼. 첫날부터 매일 쓴다 | [02.md](02.md) |
| Figma → 코드 | 디자인을 화면 코드로 | 🟡 대안 | 디자인이 중요한 서비스면 강력, 아니면 후순위 | [03.md](03.md) |
| LLM API 연동 | 내 앱 안에 'AI 기능' 넣기 | 🟡 대안 | 챗봇·요약 등 'AI가 핵심'인 서비스면 메인 | [05.md](05.md) |
| RAG·임베딩 | 내 문서로 답하는 챗봇 | 🔵 나중에 | LLM API를 먼저 익힌 뒤 필요할 때 | [06.md](06.md) |
| 결제 (Stripe 등) | 구독·결제 받기 | 🔵 나중에 | 돈을 실제로 받기 직전에 붙인다 | [07.md](07.md) |
| 검색 (Algolia 등) | 빠른·오타 허용 검색 | 🔵 나중에 | 데이터가 많아 기본 검색이 느려질 때 | [08.md](08.md) |
| Redis (캐시·세션) | 속도·세션 저장 | ⚪ 몰라도 됨 | '느려지면 쓰는 것'. 초기엔 불필요 | [04.md](04.md) |
| 자동화·연결 (n8n 등) | 도구끼리 자동 연결 | 🟡 대안 | 운영 반복작업이 생기면 큰 무기 | [09.md](09.md) |
| 배포·인프라 도구 | 어디에 올릴까 | 🟢 메인 | 안 올리면 아무도 못 본다. 처음부터 필요 | [10.md](10.md) |

!!! tip "디렉터 우선순위 한 줄 요약"
    **🟢 먼저: 코딩 AI([02.md](02.md)) + 배포([10.md](10.md))** → 이것만으로 첫 서비스가 세상에 나갑니다.
    **🟡 다음: 서비스 성격에 맞는 한두 개** (디자인 중심이면 Figma, AI 기능이 핵심이면 LLM API, 운영이 번거로우면 자동화).
    **🔵⚪ 나머지는 '이름과 용도만'** 기억해 두고, 실제로 막히는 순간(검색이 느리다, 결제를 받아야 한다)이 오면 그때 해당 페이지를 펴세요. **미리 다 붙이지 않는 것이 실력입니다.**

Claude 모델은 AI 기능을 붙일 때 **기본적으로 최신·최강 모델을 권장**합니다. 현재 계열은 다음과 같습니다(상세 선택 기준은 [02.md](02.md)).

| 모델 | 모델 ID | 성격(거칠게) |
|---|---|---|
| Opus 4.8 | `claude-opus-4-8` | 가장 똑똑함(어려운 추론·설계) |
| Sonnet 4.6 | `claude-sonnet-4-6` | 똑똑+빠름의 균형(일상 코딩) |
| Haiku 4.5 | `claude-haiku-4-5` | 빠르고 가벼움(단순·대량) |
| Fable 5 | `claude-fable-5` | 최신 계열 모델 |

*(가격·정확한 한도 같은 시점성 수치는 변하므로 단정하지 말고 **공식 문서 확인 권장**.)*

**⑤ AI에게 이렇게 시켜라**

```text
나는 비전공 청년이고, [한 줄 서비스 설명: 예) "동네 헬스장 회원이 운동 기록을 남기고
트레이너가 보는 웹앱"]을 만들 거야. 나는 코드를 직접 짜기보다 AI에게 시키고
결과가 맞는지 판별하는 '디렉터' 역할이야.

다음 도구 갈래별로, '지금 이 서비스에' 필요한지 판정해줘:
(1) 코딩 AI (2) 디자인 AI/Figma→코드 (3) LLM API 직접 연동 (4) RAG/챗봇
(5) 결제 (6) 검색 엔진 (7) Redis 캐시 (8) 자동화(n8n/Zapier) (9) 배포 인프라.

각 항목을 표로:
- 판정: 🟢메인(지금 바로) / 🟡대안(상황 되면) / 🔵나중에 / ⚪몰라도됨
- 그 판정을 내린 이유(내 서비스 맥락에 맞춰서)
- '지금 안 하면 나중에 어떤 신호가 오면 다시 봐야 하는지'

핵심: 처음부터 다 붙이지 말고, 최소한으로 시작해서 '진짜 막힐 때' 추가하는 순서를
짜줘. 과한 추천(대기업급 인프라를 작은 프로젝트에 얹기)은 명시적으로 빼줘.
```

**⑥ 흔한 함정 / AI가 틀리는 것**

- **AI는 '오버 엔지니어링'으로 기운다.** "확장성을 위해 Redis와 메시지 큐, 검색 엔진을 미리…" 같은 답을 자주 줍니다. 사용자가 10명인 서비스에 100만 명용 설계를 얹는 셈입니다. 디렉터는 "지금 사용자/데이터 규모"를 못 박고 **"그 규모에 정말 필요한 것만"**을 요구해야 합니다.
- **갈래를 헷갈려 추천.** "검색이 필요해요"라고 하면 LLM 기반 챗봇(RAG)을 권하는 식으로, 단순 키워드 검색이면 충분한데 과한 갈래로 끌고 가기도 합니다. 표의 4갈래를 기준으로 "이건 검색 갈래야, AI 갈래가 아니야"를 짚어 주세요.
- **보안 관련 잘못된 설명.** 연동 도구를 붙일 때 AI가 키 관리를 틀리게 안내하는 경우가 많습니다. 특히 Supabase에서 **anon 키는 공개해도 되는 키(브라우저에 나가도 됨)이고, 보호는 RLS(행 수준 보안)로** 합니다. "anon 키가 새면 큰일"이라는 설명은 **틀린 설명**입니다. 진짜 비밀은 `service_role` 키로, 이것은 **서버에서만** 씁니다.
- **"최신 도구가 항상 정답"이라는 환상.** AI는 화제의 신규 도구를 권하곤 하지만, 비전공자에게는 **자료 많고 안정적인 도구**가 거의 항상 낫습니다. 막혔을 때 검색하면 답이 나오는지가 더 중요합니다.

**⑦ 검증하는 법**

코드가 아니라 **'판단'을 검증**하는 페이지이므로, 다음 체크리스트로 자신의 도구 선택이 건강한지 확인하세요.

1. **"지금 당장 안 붙여도 서비스가 돌아가는가?"** — 돌아간다면 그 도구는 최소 🔵(나중)입니다. 첫 버전에는 빼세요.
2. **🟢로 고른 도구가 3개를 넘는가?** — 넘으면 과합니다. 비전공 첫 서비스의 🟢는 보통 **코딩 AI + 배포** 두 개로 시작합니다.
3. **각 도구마다 "왜 지금 필요한지" 한 문장으로 말할 수 있는가?** — 못 하면 그건 "AI가 권해서" 붙인 것입니다. 빼세요.
4. **"이 도구를 나중에 다시 봐야 하는 신호"를 적어 뒀는가?** — 예: "검색이 1초 넘게 걸리면 08.md", "동시 접속이 늘어 느려지면 04.md". 이 신호 목록이 곧 '나의 로드맵'입니다.

!!! example "💡 예시로 이해하기"
    수강생 민지가 "맛집 추천 웹앱을 만들 건데, AI 챗봇도 넣고, Redis로 빠르게 하고, Algolia 검색도 붙이고, Stripe로 유료화도 하려고요!"라며 노트북에 도구 목록을 잔뜩 적어 왔습니다. 디렉터의 눈으로 안내도를 펼쳐 봅니다. "민지야, 지금 맛집이 몇 개야?" "30개요." "사용자는?" "아직 저 혼자요." → 그러면 판정은 이렇게 정리됩니다. **🟢 코딩 AI로 화면을 만들고 → 🟢 배포해서 친구들에게 링크를 보낸다.** 30개짜리 목록에 Algolia 검색(🔵)은 과하고, 혼자 쓰는데 Redis(⚪)는 의미 없고, 아직 받을 돈이 없으니 Stripe(🔵)는 한참 뒤입니다. AI 챗봇은 "맛집을 AI가 추천해 주는 게 핵심 재미냐"에 따라 🟡 — 핵심이면 [05.md](05.md)로, 부가기능이면 나중으로. 민지의 도구 목록 7개가 **"지금은 2개, 신호가 오면 5개"** 로 바뀌는 순간, 막막했던 프로젝트가 이번 주에 출시 가능한 크기로 줄어듭니다. 그게 지도를 가진 사람과 안 가진 사람의 차이입니다.
