# 배포 URL을 이력서로 — 포트폴리오·취업 연계

**1) 한 줄 정의**
"실제로 인터넷에 떠 있고 누구나 들어가 쓸 수 있는 내 서비스의 URL"이, 비전공 디렉터가 면접에서 내밀 수 있는 가장 강력한 단일 증거다.

**2) 왜 중요한가(디렉터 관점)**
청년잡센터의 핵심 가치인데 기존 강의에서 비어 있던 구멍이다. 면접관에게 "코드를 짤 줄 압니다"는 검증하기 어렵지만, "이 주소로 들어가 보세요, 제가 만들어 운영 중입니다"는 즉시 검증된다. 핵심은 "코드를 짰다"가 아니라 "문제를 정의하고 AI를 옳게 부려 끝까지 배포·운영했다"를 말로 설명하는 것이다. 그게 디렉터의 차별점이다.

**3) 비유**
요리사 면접에서 레시피를 읊는 것과, 직접 만든 음식을 내미는 것은 다르다. 배포된 URL은 면접관 앞에 놓인 완성된 음식이다. 먹어보면 바로 안다.

**4) 최소한 알 것**

- 커스텀 도메인 + HTTPS(자물쇠)는 신뢰의 첫인상이다(권5 연계).
- 설명할 때는 "내가 정한 것 / AI에 시킨 것 / 내가 검증한 것"을 나눠 말한다.
- 바이브코딩으로 만들었다는 사실은 숨길 약점이 아니라 정직한 강점이다.

**5) AI에게 이렇게 시켜라**

```text
내 배포된 프로젝트를 포트폴리오·면접용으로 설명하는 카드를 만들어줘.
다음 항목으로: 1) 어떤 문제를 풀려고 했나 2) 내가 직접 정한 결정
3) AI에게 시킨 작업 4) 내가 검증한 것(어떻게 옳음을 확인했나) 5) 배포 링크.
'풀스택 개발자'처럼 과장하지 말고, '디렉터로서 무엇을 판단·검증했는지'가
드러나게 정직하게 써줘.
```

**6) 흔한 함정·AI가 틀리는 것**
AI는 이력서를 "풀스택 개발"처럼 부풀려 면접에서 무너지게 만든다(깊은 코드 질문에 답 못 함). 반대로 "바이브코딩으로 만들었다는 걸 숨기라"고 조언하기도 하는데, 이는 오히려 정직한 강점을 버리는 것이다.

!!! warning "과장은 면접에서 무너진다"
    하지 않은 것을 했다고 적으면 기술 질문 한두 번에 드러난다. "AI를 옳게 부려 검증하며 끝까지 배포했다"는 사실 그대로가 디렉터의 진짜 역량이고, 검증 가능하다.

**7) 검증하는 법**

1. 배포 URL을 다른 사람의 폰으로 직접 열어 정상 작동하는지 확인한다.
2. 설명 카드의 각 항목을 내가 막힘없이 말로 설명할 수 있는지 점검한다.
3. "내가 검증한 것"에 구체적 절차가 있는지 본다(없으면 권1·권4 검증 페이지로).

**8) 더 깊이**
이 가이드는 "포트폴리오용 프로젝트 설명 카드" 템플릿(문제정의·내 역할·AI에 시킨 것·검증한 것·배포 링크)을 제공한다. 권5(도메인·HTTPS)와 권4(보안 검증)가 이 페이지에서 "취업 무기"로 회수된다.
