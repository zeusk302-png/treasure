# 비전공자용 OWASP Top 10 — AI가 만든 사이트가 자주 뚫리는 곳

**(1) 한 줄 정의**

OWASP Top 10은 웹에서 가장 흔하고 위험한 보안 약점을 모아 순위로 정리한, 전 세계적으로 통용되는 점검 목록이다. 디렉터에게는 "무엇을 의심해야 하는지"의 체크리스트다.

**(2) 왜 중요한가(디렉터 관점)**

보안은 무한히 넓어 비전공자가 다 알 수 없다. 그래서 "어디부터 의심하라"를 줄여주는 표준 목록이 필요하다. OWASP Top 10이 그 역할을 한다. 디렉터가 이 목록을 손에 쥐고 있으면, AI에게 "이 항목들에 비춰 점검하라"고 시킬 수 있고, AI가 놓친 영역을 되물을 수 있다.

**(3) 비유**

병원 건강검진의 **기본 검사 항목표**와 같다. 모든 병을 다 검사할 순 없으니, 발생 빈도와 위험이 큰 항목부터 정해 둔 목록이다. OWASP Top 10은 웹사이트용 기본 검진표다.

**(4) 최소한 알 것(상위 항목 예시)**

| 있는 것 | 한 줄 해설 | 판정 |
|---|---|---|
| Broken Access Control | 권한 없는 접근. 인가/RLS 실패와 직결 | 🟢메인 |
| Security Misconfiguration | 기본값 방치(디버그 모드, 에러에 내부정보 노출) | 🟢메인 |
| Software Supply Chain | 외부 라이브러리·공급망 위험(다음 페이지) | 🟢메인 |
| 그 외 항목들 | 인증 실패, 취약 구성요소 등 다수 | 🔵나중 |

!!! warning "순위·판본은 시점성 정보 — 반드시 재확인"
    "2025판에서 1위 Broken Access Control, 2위 Security Misconfiguration, 3위 신설 Software Supply Chain"이라는 구체적 순위·신설 여부는 **판본에 따라 달라집니다.** 본문에 쓸 때는 OWASP 공식 자료에서 판본 연도와 순위를 직접 확인해 날짜와 함께 표기하세요. AI는 종종 옛 판(예: 2021판)으로 답합니다.

**(5) AI에게 이렇게 시켜라**

```text
이 사이트를 OWASP Top 10 최신 판본 기준으로 점검해줘.
1) 먼저 "어느 판본(연도)" 기준인지 공식 출처로 확인하고 명시해줘. 추정 금지.
2) 각 항목마다 우리 사이트가 "해당/비해당/확인필요" 중 무엇인지 표로.
3) 특히 접근통제(인가·RLS), 보안 설정 오류(디버그 모드·에러에 내부정보 노출),
   공급망(외부 라이브러리)을 우선 점검.
4) 위험 항목은 "코딩 몰라도 확인할 방법"과 함께 알려줘.
```

**(6) 흔한 함정·AI가 틀리는 것**

AI는 보안 기본값을 그대로 방치한다 — 에러 화면에 내부 정보(스택 트레이스, DB 구조)를 노출하거나, 운영에 디버그 모드를 켠 채 둔다(Security Misconfiguration). 또 학습 데이터가 과거라 **옛 판(2021판 등)으로 답해** 신설 항목이나 최신 순위를 놓친다.

**(7) 검증하는 법**

1. 일부러 에러를 내고 화면/응답에 내부 정보가 노출되는지 확인 → 노출되면 위험.
2. 운영 배포에서 디버그 모드가 꺼져 있는지 확인.
3. 접근통제·공급망 항목은 02번(RLS)·07번(의존성) 페이지의 검증 절차로 교차 확인.

**(8) 더 깊이**

- OWASP 공식: Top 10 (판본 연도·순위 직접 확인) — 1차 출처
- 02번 RLS, 04번 인증/인가, 07번 의존성·공급망과 연결
