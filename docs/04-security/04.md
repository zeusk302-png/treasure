# 인증 vs 인가 — '누구냐'와 '뭘 해도 되냐'는 다른 질문

**(1) 한 줄 정의**

인증(Authentication)은 "당신이 누구인가"를 확인하는 것(로그인)이고, 인가(Authorization)는 "확인된 당신이 무엇을 해도 되는가"를 정하는 것(권한)이다. 둘은 반드시 따로 다뤄야 하는 별개의 질문이다.

**(2) 왜 중요한가(디렉터 관점)**

"로그인만 붙이면 안전하다"는 가장 흔한 착각이다. 로그인(인증)이 됐다고 그 사람이 남의 데이터까지 만져도 된다는 뜻은 아니다. OWASP에서 접근통제 실패(인가)와 인증 실패는 서로 다른 항목으로 잡힌다. 디렉터는 "로그인 붙여줘"를 시키고 끝낼 게 아니라, "로그인한 사람이 자기 것만 만지게 막았는지(인가)"를 따로 확인해야 한다.

**(3) 비유**

인증은 공항에서 **여권으로 본인 확인**을 받는 것이다. 인가는 그 여권으로 **어느 게이트·어느 좌석에 들어갈 수 있는가**다. 여권이 진짜여도(인증 통과) 1등석 표가 없으면 1등석에 못 앉는다(인가 거부). 본인 확인만으로 모든 좌석에 앉게 두면 그게 사고다.

**(4) 최소한 알 것**

| 있는 것 | 한 줄 해설 | 판정 |
|---|---|---|
| 인증(로그인) | "누구냐" 확인 | 🟢메인 |
| 인가(권한) | "뭘 해도 되냐" 결정. RLS로 DB에서 강제 | 🟢메인 |
| UI 가짜 보안 | 버튼만 숨기기. URL 직접 치면 뚫림 | ⚪몰라도됨(피할 패턴) |
| 서버/DB 측 검증 | 진짜 인가는 프론트가 아니라 서버·RLS에서 | 🟢메인 |

!!! warning "버튼 숨기기는 보안이 아니다"
    프론트에서 "삭제 버튼"을 안 보이게 하는 것은 보안이 아니라 **장식**입니다. 주소(URL)나 API를 직접 호출하면 그대로 뚫립니다. 인가는 반드시 서버 또는 DB(RLS)에서 강제해야 합니다.

!!! tip "RLS와 한 몸으로 보기"
    인가의 실무 구현은 대부분 02번의 RLS 정책으로 떨어집니다. "본인만 수정/삭제"는 `auth.uid()` 기반 RLS 정책이 곧 인가입니다.

**(5) AI에게 이렇게 시켜라**

```text
로그인 기능과 별개로 "인가(권한)"를 점검해줘.
1) 로그인한 사용자가 남의 데이터를 읽기/수정/삭제할 수 있는 경로가 있는지 찾아줘.
2) 프론트에서 버튼만 숨기고 정작 API/RLS로는 막지 않은 "UI 가짜 보안"이 있는지 표시.
3) 각 보호 대상에 대해 "서버 또는 RLS에서 막히는가"를 표로 정리하고,
   안 막히는 곳은 위험으로 분류해 수정안을 줘.
URL을 직접 호출하는 시나리오로도 뚫리는지 가정해서 점검해.
```

**(6) 흔한 함정·AI가 틀리는 것**

AI는 로그인(인증)은 잘 붙이지만 **인가를 빠뜨린다.** 특히 프론트에서 버튼만 숨기는 'UI 가짜 보안'을 만들어, URL이나 API를 직접 호출하면 그대로 뚫리는 구조를 남긴다. "로그인 붙였으니 안전합니다"라는 보고를 그대로 믿으면 위험하다.

!!! note "기획 메모(회수 검토)"
    인증의 '개념'은 이 페이지에서 다루지만, 'Supabase Auth로 로그인 실제 붙이기' 구현 페이지는 현재 권4에 공백입니다. 기획서상 권7 또는 별도 페이지로 회수가 검토 중입니다.

**(7) 검증하는 법**

1. 사용자 A로 로그인 → 사용자 B의 데이터(진도/댓글)에 접근 시도 → 막히면 정상.
2. 프론트에서 숨긴 동작을 API/URL로 직접 호출 → 거부되는지 확인.
3. "로그인은 됐지만 남의 진도는 못 본다"를 실제로 클릭해 확인.

**(8) 더 깊이**

- OWASP Top 10: Broken Access Control / Identification and Authentication Failures (판본·날짜 확인)
- Supabase 공식 문서: Auth + RLS 연계
- 02번 RLS 페이지와 함께 읽기

!!! example "💡 예시로 이해하기"
    학원 출결 앱에서 AI가 "관리자만 보이게 해줘"를 시키자, 학생 화면에서는 [전체 출결 보기] 버튼을 `{isAdmin && <button>}`로 숨겨놨다. 화면상으론 완벽해 보인다. 그런데 학생 수민이가 관리자 친구 화면에서 본 주소 `/admin/attendance`를 그냥 주소창에 직접 쳐보니, 버튼 없이도 전교생 출결이 그대로 떴다.
    인증(로그인)은 통과했지만 인가(권한)가 서버에 없었던 것이다. 버튼을 숨긴 건 장식일 뿐, `/admin/attendance` 요청을 받는 서버나 RLS에서 "이 사람이 관리자인가"를 다시 확인해 거부해야 진짜로 막힌다. 검증은 항상 버튼이 아니라 URL을 직접 두드려서 한다.
