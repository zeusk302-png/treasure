# 의존성·공급망 보안 — 내가 안 짠 코드가 8할인데, 그건 누가 검증하나

**(1) 한 줄 정의**

의존성(dependency)은 내 프로젝트가 끌어다 쓰는 외부 라이브러리이고, 공급망 보안은 "그 외부 코드가 안전한가, 변조되지 않았는가"를 점검하는 일이다.

**(2) 왜 중요한가(디렉터 관점)**

현대 웹 프로젝트의 코드는 대부분 내가(또는 AI가) 직접 짠 게 아니라 남이 만든 라이브러리다. 그 8할의 코드가 안전한지 아무도 안 보면, 가장 약한 고리에서 사고가 난다. 디렉터는 "AI가 무슨 패키지를 설치했고, 그게 진짜 정품인지, 기록이 남았는지"를 챙겨야 한다.

**(3) 비유**

요리에 쓰는 **수입 식재료**와 같다. 내가 직접 기른 게 아니라 사 온 것이라, 원산지·유통기한·정품 여부를 확인해야 안전하다. `package-lock` 파일은 "이번에 쓴 재료의 정확한 원산지·로트번호 영수증"이고, `npm audit`은 "리콜·오염 통보 조회"다.

**(4) 최소한 알 것**

| 있는 것 | 한 줄 해설 | 판정 |
|---|---|---|
| `package-lock.json` | 설치된 버전을 못 박는 영수증. 반드시 커밋 | 🟢메인 |
| `npm audit` | 알려진 취약점 점검 | 🟢메인 |
| `npm audit signatures` | 패키지 서명(정품) 검증 | 🟡대안 |
| typosquatting | 오타 패키지(예: axois)로 가짜를 깔게 하는 공격 | ⚪몰라도됨(피할 함정) |

!!! warning "공급망은 시점성 정보가 많다"
    "OWASP 2025 3위 신설 Software Supply Chain" 같은 순위·신설 여부, 그리고 특정 CVE(취약점)·자동 점검 동작은 시점에 따라 달라집니다. 본문에 인용 시 OWASP·도구 공식 문서에서 판본과 날짜를 확인하세요.

**(5) AI에게 이렇게 시켜라**

```text
이 프로젝트의 의존성·공급망 보안을 점검해줘.
1) package-lock.json이 저장소에 커밋돼 있는지 확인. .gitignore에 들어가 있으면 위험으로 표시.
2) 설치된 패키지 중 이름이 유명 패키지와 한 글자 다른(오타 의심) 것이 있는지 찾아줘 (예: axois vs axios).
3) npm audit / npm audit signatures를 실행한 결과를 요약하고,
   심각도 높은 항목과 권장 조치를 표로 정리.
4) 출처가 불분명하거나 다운로드 수가 비정상적으로 적은 의존성이 있으면 표시.
추정 말고 실제 결과만 보고해.
```

**(6) 흔한 함정·AI가 틀리는 것**

AI는 존재하지 않거나 오타가 섞인 패키지(typosquatting, 예: `axois`)를 설치하려 들어 가짜·악성 패키지를 끌어올 위험을 만든다. 또 `package-lock.json`을 `.gitignore`에 넣어 **설치 기록(어떤 버전이 깔렸는지)을 없애** 추적과 재현을 불가능하게 만든다.

**(7) 검증하는 법**

1. 저장소에 `package-lock.json`이 커밋돼 있는지 확인(없으면 위험).
2. `package.json`의 패키지 이름을 공식 레지스트리(npmjs.com)에서 정품인지 대조.
3. CI에서 `npm audit` / `npm audit signatures` 결과 배지가 통과인지 확인.

**(8) 더 깊이**

- npm 공식 문서: audit / audit signatures, package-lock — 1차 출처
- OWASP: Software Supply Chain (판본·날짜 확인)
- 06번 OWASP Top 10과 함께 읽기. 이 사이트는 `npm audit` 결과 배지를 공개

!!! example "💡 예시로 이해하기"
    민호가 AI에게 "HTTP 요청 보내는 라이브러리 깔아줘"라고 시키자 AI가 `npm install axios`를 한다는 게 한 글자 틀린 `npm install axois`를 실행했다. `axios`는 주당 다운로드 5천만 건의 정품이지만, `axois`는 그 오타를 노리고 만든 누군가의 가짜 패키지(typosquatting)였고, 설치되자마자 환경변수를 외부로 빼돌리는 코드가 돌았다.
    이걸 잡는 방법은 단순하다. `package.json`의 패키지 이름을 npmjs.com에서 그대로 검색해 다운로드 수와 철자를 대조하고, `npm audit`을 돌려 알려진 취약점이 있는지 본다. 그리고 어떤 버전이 깔렸는지 못 박아두는 `package-lock.json`은 반드시 깃에 커밋한다 — 이 영수증이 `.gitignore`에 들어가 있으면 나중에 "그때 뭐가 깔렸는지" 추적이 불가능해진다.
