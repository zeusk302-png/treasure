# 스펙부터 쓴다 — "알아서 해줘"가 가장 비싼 주문인 이유

**1) 한 줄 정의**
스펙(명세)이란 코드를 만들기 전에 **"무엇을·누구를 위해·어떤 조건에서·어디까지"**를 글로 못 박아 두는 합의문이다.

**2) 왜 중요한가(디렉터 관점)**
디렉터의 일은 코드가 아니라 결정을 내리는 것이다. 스펙이 없으면 그 결정을 AI가 대신 내려버린다. 모호하게 "회원가입 만들어줘"라고 시키면, AI는 이메일 형식·중복 가입·비밀번호 규칙·실패 시 메시지 같은 빈칸을 "가장 흔한 정답"으로 멋대로 채운다. 그 채워진 값이 내 의도와 다르면, 그게 곧 다시 만드는 비용이다. 스펙은 그 재작업을 미리 막는 가장 싼 보험이다.

**3) 비유**
스펙은 인테리어 시공 전 그리는 도면이다. "예쁘게 해주세요"라고만 하면 시공자가 자기 취향대로 짓고, 다 부수고 다시 하는 값이 도면 그리는 값보다 100배 비싸다.

**4) 최소한 알 것**

- 좋은 스펙엔 보통 다섯 가지가 들어간다: 목적 / 사용자 / 입력과 출력 / 정상 흐름 / **예외(엣지케이스)**.
- 엣지케이스란 "빈 값으로 보내면?", "같은 걸 두 번 누르면?", "권한 없는 사람이 하면?" 같은 비정상 상황이다.
- 스펙은 한 번 쓰고 끝이 아니라, 만들다 발견한 누락을 계속 채워 넣는 살아있는 문서다.

**5) AI에게 이렇게 시켜라**

```text
지금부터 [진도체크 기능]을 만들 거야. 코드 짜기 전에, 먼저 스펙을 표로 정리해줘:
1) 목적, 2) 사용자(로그인/비로그인), 3) 입력과 출력,
4) 정상 흐름, 5) 예외 상황(빈 값/중복/권한 없음/네트워크 실패).
특히 5번 예외는 내가 놓쳤을 만한 것까지 네가 먼저 5개 제안해줘.
이 스펙을 내가 확인하기 전에는 코드를 쓰지 마.
```

**6) 흔한 함정·AI가 틀리는 것**

!!! warning "AI는 빈칸을 묻지 않고 채운다"
    범위와 예외를 명시하지 않으면 AI는 되묻지 않고 곧장 코드로 직행한다. 그러고는 정상 흐름만 작동하는 코드를 "완성했습니다"라고 보고한다. 비정상 입력(빈 값, 중복 클릭, 권한 없는 접근)은 조용히 빠져 있다.

**7) 검증하는 법**

1. AI가 만든 스펙에서 "예외 상황" 줄을 센다. 3개 미만이면 부족하다고 의심한다.
2. 내가 떠올린 비정상 상황(빈 칸 제출, 두 번 클릭)을 스펙에 적혀 있는지 대조한다.
3. 코드를 받으면, 스펙의 각 항목을 하나씩 "이건 어디서 처리돼?"라고 다시 물어 누락을 잡는다.

**8) 더 깊이**

!!! tip
    "스펙 → 결과 → 스펙으로 잡은 누락"의 흐름을 한 번이라도 글로 남겨 두면, 다음 기능부터 빈칸을 보는 눈이 생긴다. 이 사이트의 진도체크 기능도 그 스펙 문서를 그대로 공개한다.

!!! example "💡 예시로 이해하기"
    카페 사장이 "쿠폰 적립 기능 알아서 만들어줘"라고만 했다. AI는 빈칸을 멋대로 채워 "10잔에 1잔 무료, 무제한 적립"으로 만들었다. 그런데 손님이 한 번 주문에 결제 버튼을 두 번 누르자 도장이 2개 찍혔고, 폰을 바꾼 단골은 적립 내역이 통째로 사라졌다.
    스펙을 먼저 한 줄씩 못 박았다면 달랐다 — `중복 클릭 시 1회만 적립`, `전화번호로 적립 내역 유지`, `유효기간 6개월`. 도면 한 장(스펙 30분)이 가게 전체를 다시 만드는 사흘을 막는다.
