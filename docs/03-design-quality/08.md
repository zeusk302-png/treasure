# 버전관리 심화 — 브랜치, 이슈, 그리고 '되돌릴 수 있다'는 안전망

**1) 한 줄 정의**
버전관리 심화란 단순 저장(커밋)을 넘어 **위험한 변경을 별도 가지(브랜치)에서 하고, 할 일을 이슈로 적고, 합치기 전에 검토하는** 안전한 작업 흐름이다.

**2) 왜 중요한가(디렉터 관점)**
"되돌릴 수 있다"는 건 디렉터에게 가장 큰 심리적 안전망이다. 위험한 실험을 메인이 아닌 별도 가지에서 하면, 잘못돼도 메인은 멀쩡하다. 시키지 않으면 AI는 모든 변경을 메인에 바로 쏟아붓는다. 그러면 무언가 깨졌을 때 어디까지 되돌려야 할지 알 수 없다. 디렉터는 "이건 위험하니 새 가지에서 해"라고 지시할 줄 알아야 한다.

**3) 비유**
브랜치는 게임의 "다른 슬롯에 세이브하고 도전"이다. 본편 세이브(메인)는 안 건드리고, 위험한 보스전을 새 슬롯에서 시도한다. 성공하면 본편에 반영하고, 망하면 그 슬롯만 버리면 된다.

**4) 최소한 알 것**

| 개념 | 한 줄 해설 |
|---|---|
| 브랜치 | 메인을 복사한 별도 작업 가지. 여기서 안전하게 실험 |
| 이슈 | "무엇을 왜 할지"를 적어 두는 할 일 카드 |
| PR(풀 리퀘스트) | 가지의 변경을 메인에 합치기 전 검토 요청 |
| 머지 | 검토를 통과한 변경을 메인에 합치기 |

- 좋은 커밋 메시지는 "무엇을 왜 바꿨는지"를 말한다. `update`, `fix` 한 단어는 나중에 아무 도움이 안 된다.

**5) AI에게 이렇게 시켜라**

```text
[로그인 기능] 같은 위험한 변경을 할 거야. 다음 흐름으로 진행해줘:
1) 먼저 무엇을 할지 이슈 형태로 정리(목적·범위·확인 기준)
2) 메인이 아니라 새 브랜치(이름 제안)에서 작업
3) 커밋 메시지는 "무엇을 왜"가 드러나게(update/fix 같은 한 단어 금지)
4) 다 되면 PR 형태로 변경 요약을 보여주고, 내 검토 전엔 메인에 합치지 마.
```

**6) 흔한 함정·AI가 틀리는 것**

!!! warning "메인에 바로 쏟고, 무의미한 커밋 메시지"
    시키지 않으면 AI는 새 브랜치를 만들지 않고 메인에 변경을 바로 반영한다. 그리고 `update`, `fix`, `change` 같은 의미 없는 커밋 메시지를 남겨, 나중에 "언제 무엇이 왜 바뀌었는지" 추적을 불가능하게 만든다.

**7) 검증하는 법**

1. 위험한 작업을 시켰을 때 "지금 어느 브랜치에서 작업 중이야?"라고 물어 메인이 아닌지 확인한다.
2. 커밋 기록을 훑어, 메시지만 보고도 무슨 변경인지 알 수 있는지 본다.
3. 합치기 전에 PR의 변경 요약을 읽고, 내가 의도한 범위를 벗어난 변경이 없는지 확인한다.

**8) 더 깊이**

!!! tip
    되돌릴 수 있다는 확신이 있으면 더 과감하게 실험할 수 있다. 이 사이트는 실제 브랜치·PR·이슈를 공개하고, 각 페이지 하단에 "이 페이지를 만든 PR 링크"를 달아 변경 이력을 1차 증거로 보여준다.
