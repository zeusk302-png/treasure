# 정적이냐 동적이냐 SPA냐 — 아키텍처를 언제 무엇으로

**1) 한 줄 정의**
아키텍처 선택이란 사이트를 **미리 만들어 둘지(정적), 요청 때마다 만들지(동적), 한 화면 안에서 갈아끼울지(SPA)**를 정하는 큰 구조 결정이다.

**2) 왜 중요한가(디렉터 관점)**
구조를 잘못 고르면 돈과 속도를 잃거나, 나중에 기능이 막힌다. 단순 소개 페이지에 무거운 동적 구조를 얹으면 느리고 비싸지고, 반대로 실시간 데이터가 필요한데 정적으로 짜면 기능 자체가 안 된다. 디렉터는 "이 페이지가 자주 바뀌는가, 사람마다 다른가"만 판단하면 된다. 그 판단을 안 하면 AI가 "최신이고 멋진" 쪽으로 과하게 설계한다.

**3) 비유**
정적은 미리 인쇄해 둔 메뉴판(누가 와도 똑같고 빠르다), 동적은 주문 즉시 요리하는 음식(사람·시간마다 다르다), SPA는 한 식당 안에서 자리를 안 옮기고 메뉴만 바꿔 받는 방식이다.

**4) 최소한 알 것**

| 있는 것 | 한 줄 해설 | 판정 |
|---|---|---|
| 정적(SSG) | 빌드 때 미리 만들어 두는 페이지. 빠르고 싸고 검색 잘 됨 | 🟢메인(가이드 본문) |
| 동적(SSR) | 요청마다 서버가 새로 만듦. 사람·시간마다 다른 데이터 | 🟡대안(댓글·진도) |
| SPA(CSR) | 첫 로딩 후 화면을 자바스크립트로 갈아끼움 | 🔵나중(앱같은 UI) |
| ISR | 정적인데 일정 주기로 갱신 | ⚪몰라도됨(인기글 등) |

**5) AI에게 이렇게 시켜라**

```text
[이 페이지]는 이런 성격이야: (자주 바뀌나? 사람마다 다른가? 검색에 잡혀야 하나?)
이 조건에 맞는 렌더링 방식(정적/동적/SPA/ISR)을 추천하고, 왜 그게 맞는지,
다른 방식을 골랐을 때의 손해(속도·비용·검색)를 비교해서 표로 보여줘.
"최신이라서" 같은 이유 말고 내 조건에 근거해서 정해줘.
```

**6) 흔한 함정·AI가 틀리는 것**

!!! warning "과잉설계 경향"
    AI는 단순한 소개 사이트에도 무거운 서버 렌더링이나 복잡한 SPA 프레임워크를 권하는 경향이 있다. "내 경우엔 무엇이 맞는가"를 안 짚고 일반론만 나열하거나, 화려한 최신 기술 쪽으로 기울인다. 그 결과 비용과 로딩 속도, 검색 노출에서 손해를 본다.

**7) 검증하는 법**

1. AI에게 "이 선택의 단점 3가지와 더 단순한 대안"을 반드시 함께 물어 과잉설계인지 확인한다.
2. 페이지마다 "이건 정적이야 동적이야?"라고 다시 물어, 본문은 정적·실시간 데이터는 동적으로 나뉘었는지 본다.
3. 배포 후 페이지 로딩 속도와 (해당하면) 검색 노출이 기대대로인지 확인한다.

**8) 더 깊이**

!!! tip
    한 사이트 안에서도 페이지마다 방식이 다를 수 있다. 이 사이트는 본문=정적, 위젯(댓글·진도)=동적, 인기글=ISR로 여러 방식을 섞어 쓰고, 각 페이지에 어떤 방식인지 배지로 표시한다.

!!! example "💡 예시로 이해하기"
    동네 빵집이 "회사 소개 페이지" 하나 만드는데 AI가 사용자별 실시간 추천, 서버 렌더링까지 얹은 무거운 구조를 권했다. 결과: 누가 봐도 똑같은 내용인데 열 때마다 서버가 새로 굽느라 첫 화면이 `2.5초`나 걸리고 매달 서버비가 나갔다.
    이건 미리 인쇄한 메뉴판이면 충분한데 주문마다 새로 인쇄기를 돌린 격이다. 같은 페이지를 정적(SSG)으로 미리 만들어 두니 로딩이 `0.3초`로 줄고 서버비는 사실상 `0원`이 됐다. 반대로 "오늘 남은 빵 재고"처럼 매시간 바뀌는 정보만 동적으로 두면 된다.
