# 이름과 폴더 — 작은 규칙이 큰 혼돈을 막는다

**1) 한 줄 정의**
이름과 폴더 규칙이란 **파일·폴더·변수에 일관된 이름과 자리를 정해 두어, 무엇이 어디 있는지 예측 가능하게 만드는** 작은 약속이다.

**2) 왜 중요한가(디렉터 관점)**
규칙이 없으면 "그 파일 어디 있더라"를 매번 찾아 헤맨다. 더 위험한 건 배포 사고다. 폴더 이름에 한글·공백·대문자를 섞으면, 내 컴퓨터에선 되던 게 배포 서버에선 안 뜬다. 디렉터가 네이밍 규칙을 한 번 정해 AI에게 고정시키면, AI가 세션마다 제멋대로 이름을 바꾸는 혼돈을 막을 수 있다.

**3) 비유**
창고에 "왼쪽 선반=공구, 오른쪽=부품" 규칙이 있으면 누구든 바로 찾는다. 규칙 없이 그때그때 아무 데나 두면, 다음 사람(미래의 나, 또는 AI)이 매번 전부 뒤져야 한다. 기존 강의의 `MyLandingPage`와 `my-website`가 섞여 충돌한 사고가 이 문제의 축소판이다.

**4) 최소한 알 것**

- **대소문자·공백·한글 금지**: 폴더·파일명은 영문 소문자와 하이픈(`my-page`)이 안전하다.
- **일관성**: 한 번 `kebab-case`로 정했으면 끝까지 그걸로. 섞지 않는다.
- **자리 규칙**: 본문은 `content/`, 화면 조각은 `components/`, 공용 도구는 `lib/`처럼 종류별 자리를 정한다.
- 이 규칙을 `CLAUDE.md`(AI용 매뉴얼)에 적어 두면 새 대화에서도 AI가 따른다.

**5) AI에게 이렇게 시켜라**

```text
이 프로젝트의 네이밍·폴더 규칙을 정하고 CLAUDE.md에 적어줘:
- 폴더/파일명은 영문 소문자 + 하이픈만(한글·공백·대문자 금지)
- 본문은 content/, 화면 조각은 components/, 공용 함수는 lib/
- 컴포넌트 파일명 규칙, 변수 표기 규칙을 한 줄씩
앞으로 파일을 만들 때마다 이 규칙을 지키고, 어길 일이 생기면 먼저 나에게 물어봐.
```

**6) 흔한 함정·AI가 틀리는 것**

!!! warning "세션마다 바뀌는 규칙, 그리고 배포 사고"
    AI는 대화 세션이 바뀌면 이전에 쓰던 이름 규칙을 잊고 다른 방식으로 짓는다. 또 한글·공백·대문자가 섞인 폴더명을 아무렇지 않게 만드는데, 이는 로컬에선 작동해도 대소문자를 구별하는 배포 서버에서 "파일을 찾을 수 없음" 오류로 이어진다.

**7) 검증하는 법**

1. 폴더 트리를 펼쳐, 이름에 한글·공백·대문자가 섞인 게 있는지 눈으로 훑는다.
2. 같은 종류 파일이 규칙대로 같은 폴더에 모여 있는지 확인한다.
3. 로컬에선 되는데 배포만 깨지면, 가장 먼저 파일명 대소문자·공백을 의심한다.

**8) 더 깊이**

!!! tip
    이 사이트는 실제 폴더 트리(`content/`, `components/`, `lib/`)와 `CLAUDE.md`에 적힌 네이밍 규칙을 그대로 공개해, 규칙이 어떻게 혼돈을 막는지 눈으로 보여준다.
