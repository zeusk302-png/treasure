# 노코드 자동화란 무엇인가 — n8n으로 '반복'을 기계에 넘기기

**1) 한 줄 정의**

노코드 자동화는 "어떤 일이 생기면 → 이런 순서로 처리하라"를 코드 대신 화면 위 블록(노드)을 선으로 이어 만드는 것이고, n8n은 그 블록을 잇는 대표 도구다.

**2) 왜 중요한가 (디렉터 관점)**

디렉터의 시간은 한정돼 있다. 새 방명록이 달릴 때마다 직접 확인하고, 매주 같은 리포트를 손으로 만드는 일은 사람이 할 게 아니다. 자동화는 "코드를 더 짜는 일"이 아니라 **무엇을·언제·어떤 신호로·누구에게 시킬지를 설계하는 일**이다. 직접 구현이 아니라 흐름을 그리고 실패를 검증하는 안목이 핵심이다.

**3) 비유**

공장의 컨베이어 벨트다. 원료(입력)가 들어오면 정해진 공정(노드)을 순서대로 지나 완제품(결과)이 나온다. 사람은 벨트를 멈추거나 공정을 바꿀 뿐, 매번 손으로 옮기지 않는다.

**4) 최소한 알 것**

- 자동화의 뼈대는 **트리거(언제 시작)** + **액션(무엇을 할지)** 의 조합이다.
- 모든 일을 자동화할 필요는 없다. 자주·규칙적으로 반복되고, 실수해도 복구 가능한 일이 1순위다.
- n8n은 자가호스팅(내 서버에 직접 설치)과 클라우드(가입형) 둘 다 가능하다.

| 있는 것 | 한 줄 해설 | 판정 |
|---|---|---|
| n8n | 노드를 선으로 잇는 노코드 자동화 | 🟢메인 |
| Zapier | 더 쉽지만 건수당 과금, 비싸짐 | 🟡대안 |
| Make | n8n과 비슷한 비주얼 자동화 | 🟡대안 |
| 직접 코드(스크립트) | 유연하지만 직접 짜고 운영 | 🔵나중 |

**5) AI에게 이렇게 시켜라**

```text
내가 운영하는 사이트에서 반복되는 작업 후보를 표로 정리해줘.
각 작업에 대해 (1) 트리거가 무엇인지 (2) 어떤 순서로 처리되는지
(3) 자동화 가치(빈도·실수비용) (4) 자동화하면 안 되는 이유가 있다면 함께.
"전부 자동화"가 답이라고 가정하지 말고, 자동화하지 말아야 할 것도 골라줘.
```

**6) 흔한 함정 · AI가 틀리는 것**

AI는 "자동화할 것"과 "자동화하면 안 될 것"을 구분하지 않고 전부 기계에 넘기려 든다. 사람의 판단이 필요한 일(환불 승인, 민감한 응대)까지 자동화하면 사고가 자동으로 커진다.

!!! warning
    n8n의 내장 노드 수, 자가호스팅 권장 사양·비용(흔히 월 12~20달러대 VPS로 언급됨) 같은 정보는 시점성 정보다. 운영을 의존하기 전 공식 문서(docs.n8n.io)와 현재 가격을 날짜 기준으로 직접 확인하라.

**7) 검증하는 법**

1. 워크플로우를 "수동 실행"으로 한 번 돌려본다.
2. 각 노드를 클릭해 입력과 출력 데이터가 의도대로 흐르는지 눈으로 확인한다.
3. 실패 케이스(빈 입력, 잘못된 값)를 일부러 넣어 멈추거나 알림이 오는지 본다.

!!! tip
    첫 자동화는 "새 방명록 → 디렉터에게 이메일 알림"처럼 실패해도 안전한 것으로 시작하라.

**8) 더 깊이**

- n8n 공식 문서(docs.n8n.io) — 핵심 개념과 노드 레퍼런스(1차 출처)
- n8n 워크플로우 템플릿 갤러리 — 실제 예제 모음(참고)

!!! example "💡 예시로 이해하기"
    카페 사장 지민 씨는 매주 월요일 아침마다 주말 매출을 엑셀에 옮기고, 재고가 떨어진 원두를 메모해 거래처에 카톡을 보냈다. 한 번에 30분, 한 달이면 2시간이다.
    n8n으로 바꾸면 이렇게 된다 — **트리거**: 매주 월요일 오전 8시(스케줄). **액션**: 포스기 매출 데이터 가져오기 → 원두 재고가 5kg 미만이면 표시 → 결과를 구글시트에 기록 → 거래처 담당자에게 슬랙으로 `이번 주 원두 발주: 콜롬비아 10kg` 자동 전송.
    반대로 자동화하면 안 되는 건 "단골손님 환불 요청 응대"다 — 사람마다 사정이 달라 사장의 판단이 필요하기 때문이다. 자주·규칙적·실수해도 복구 가능한 일(매출 정리)만 기계에 넘기는 게 핵심이다.
