# n8n과 MCP의 만남 — 워크플로우를 AI의 도구로, AI를 워크플로우의 도구로

**1) 한 줄 정의**

n8n과 MCP는 두 방향으로 만난다 — 내 워크플로우를 외부 AI가 쓸 수 있게 노출하는 **MCP Server Trigger**, 그리고 외부 도구를 내 워크플로우 안으로 끌어오는 **MCP Client Tool**.

**2) 왜 중요한가 (디렉터 관점)**

같은 "MCP"라는 단어 안에 정반대 방향이 들어 있다. 디렉터가 이 방향을 헷갈리면 "Claude가 내 진도 저장 기능을 호출하게 하고 싶다"인지 "내 워크플로우가 외부 AI 도구를 부르고 싶다"인지 자체가 흐려진다. 방향을 정확히 말할 수 있어야 AI가 맞는 노드를 골랐는지 검증할 수 있다.

**3) 비유**

가게 문에 비유하면, **Server Trigger**는 "우리 가게(워크플로우)를 손님(외부 AI)에게 여는 입구"이고, **Client Tool**은 "우리 직원(워크플로우)이 옆 가게(외부 도구)에 물건 사러 나가는 출구"다. 같은 문이지만 드나드는 방향이 반대다.

**4) 최소한 알 것**

| 노드 | 방향 | 의미 |
|---|---|---|
| MCP Server Trigger | 내 흐름 → 외부 AI에 노출 | 외부 AI가 내 워크플로우를 도구로 호출 |
| MCP Client Tool | 외부 도구 → 내 흐름 | 내 워크플로우가 외부 도구를 사용 |

- 어느 방향이든 **엔드포인트 인증**이 없으면 아무나 호출할 수 있다.
- 외부 AI에 노출하는 기능은 "되돌리기 어려운 작업"을 함부로 열지 않는다.

**5) AI에게 이렇게 시켜라**

```text
n8n에서 우리 '진도 저장' 기능을 외부 AI(Claude)가 호출하게 노출하고 싶어.
(1) 이건 MCP Server Trigger인지 MCP Client Tool인지 먼저 명확히 판정해줘
(2) 두 노드의 방향 차이를 한 문장씩으로 정리해줘
(3) 이 엔드포인트에 인증을 거는 방법(아무나 호출 못 하게)
(4) 외부 AI에 노출하면 위험한 작업이 있다면 경고해줘
방향을 헷갈리지 말고, 인증 없는 예시는 주지 마.
```

**6) 흔한 함정 · AI가 틀리는 것**

AI는 Server Trigger와 Client Tool의 방향을 자주 뒤바꾼다. 또 MCP 엔드포인트에 인증을 빠뜨려 누구나 내 워크플로우를 호출할 수 있게 만든다. MCP는 비교적 새 영역이라 AI의 학습 지식이 현재 동작과 어긋날 수 있다.

!!! warning
    인스턴스 레벨 MCP 서버 기능은 2026-06 기준 Public Preview 단계로 알려져 있다(원본 기획서에 '운영 의존 전 안정성 확인 필요 — 불확실'로 표시됨). 운영에 의존하기 전 n8n 공식 문서·릴리스 노트에서 현재 단계와 안정성을 날짜 기준으로 직접 확인하라.

**7) 검증하는 법**

1. Server Trigger로 노출한 기능을 외부 AI(또는 테스트 클라이언트)로 한 번 호출해 실제 동작하는지 확인한다.
2. 인증 토큰 없이 같은 엔드포인트를 호출하면 거부되는지 확인한다(열려 있으면 안 됨).
3. Client Tool 방향에서는 외부 도구 응답이 워크플로우로 제대로 들어오는지 데이터 흐름을 확인한다.
