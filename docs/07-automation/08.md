# 안정성과 확장 — 멈추지 않게, 그리고 트래픽이 늘어도 견디게

**1) 한 줄 정의**

안정성은 실패를 전제로 재시도·멱등성·에러 알림을 갖추는 것이고, 확장은 트래픽이 늘어도 큐 모드·워커로 견디게 만드는 것이다.

**2) 왜 중요한가 (디렉터 관점)**

자동화는 사람이 안 보는 새 돈다. 그래서 "조용히 실패하고 아무도 모르는" 상황이 가장 위험하다. 디렉터의 일은 더 많은 코드가 아니라 **실패를 가정한 설계**다 — 실패하면 다시 시도하되 같은 작업이 두 번 실행되지 않게(멱등성) 하고, 멈추면 즉시 알림이 오게 하는 것.

**3) 비유**

택배 재배송이다. 배송이 실패하면 다시 보내는 게 재시도다. 그런데 시스템이 "실패했나?"를 헷갈려 같은 물건을 두 번 보내면 사고다. **멱등성**은 "송장 번호가 같으면 한 번만 배송"하는 안전장치다. 확장은 택배 기사(워커)를 늘려 물량이 몰려도 소화하는 것이다.

**4) 최소한 알 것**

- **재시도**: 일시적 실패는 잠시 후 다시. **지수 백오프**: 재시도 간격을 점점 늘림.
- **멱등성(idempotency)**: 같은 작업이 여러 번 실행돼도 결과는 한 번뿐. 결제·메일에 필수.
- **에러 알림**: 실패하면 디렉터에게 즉시 통보(침묵 ≠ 정상).
- **확장**: 단일 실행 → 큐 모드 + 워커로 동시 처리량을 늘림.
- 자가호스팅이면 **운영 책임**도 내 것(DB 잠김·디스크 가득 참 등).

**5) AI에게 이렇게 시켜라**

```text
이 n8n 워크플로우를 "실패를 전제로" 견고하게 만들고 싶어.
(1) 일시 실패에 대한 재시도 + 지수 백오프 설정
(2) 결제·메일이 중복 실행되지 않게 하는 멱등성 키 적용 방법
(3) 어떤 노드든 실패하면 디렉터에게 즉시 알림 가는 Error Trigger 구성
(4) 트래픽이 늘었을 때 "비싼 요금제"가 아니라 구조(큐 모드·워커)로 견디는 방법
에러 처리를 생략하지 말고, 멱등성 없이 재시도하는 위험을 먼저 경고해줘.
```

**6) 흔한 함정 · AI가 틀리는 것**

AI는 에러 처리를 사실상 생략해 "실패해도 아무 일 없는 척" 흐름을 만든다. 또 멱등성 없이 재시도만 붙여 결제·메일이 중복 실행되게 하고, "확장 = 더 비싼 요금제"로만 답해 큐 모드·워커 같은 구조적 해법을 빠뜨린다.

!!! warning
    멱등성 없는 재시도는 자동화에서 가장 비싼 실수다. "다시 보내기"가 "두 번 결제·두 번 발송"이 되어 사고가 자동으로 증폭된다. 재시도를 켜기 전에 멱등성부터 확인하라.

!!! tip
    자가호스팅 n8n을 운영한다면 디스크 용량·DB 상태를 정기 점검하는 모니터링을 함께 두라. 자동화 서버 자체가 멈추면 모든 자동화가 함께 멈춘다.

**7) 검증하는 법**

1. 한 노드를 일부러 실패시켜(잘못된 키 등) Error Trigger 알림이 실제로 오는지 확인한다.
2. 같은 작업을 두 번 실행해도 결과가 한 번만 생기는지(멱등성) 확인한다.
3. 단시간에 요청을 몰아넣어, 큐 모드에서 밀린 작업이 순차 처리되는지 관찰한다.

**8) 더 깊이**

- n8n Error Handling / Error Trigger 공식 문서(1차 출처)
- n8n Queue Mode(큐 모드)·스케일링 공식 문서(1차 출처)
- 멱등성 개념 — 연동하는 서비스(결제 등)의 Idempotency Key 공식 문서(1차 출처)

!!! example "💡 예시로 이해하기"
    구독형 도시락 서비스 디렉터 민재 씨의 정산 자동화가 새벽 3시에 돌다 결제사 응답이 잠깐 끊겼다. 워크플로우는 "실패했나 보다" 하고 재시도했다. 문제는 사실 첫 결제가 성공했었다는 것 — 그 결과 구독자 80명이 9,900원씩 두 번 결제됐고, 다음 날 아침 환불 민원이 쏟아졌다.
    고친 방법은 결제마다 고유한 멱등성 키(예: `order-20260618-0421`)를 붙이는 것이다. 같은 키로 두 번째 요청이 와도 결제사는 "이미 처리한 주문"으로 보고 한 번만 청구한다. 재시도를 켜기 전에 이 멱등성부터 확인하는 게 순서다.
    또 그날 정산이 새벽에 조용히 멈췄어도 아무도 몰랐던 게 더 큰 문제였다. 그래서 어떤 노드든 실패하면 민재 씨 슬랙으로 `[정산 실패] 03:21 결제사 연결 끊김` 알림이 즉시 가도록 Error Trigger를 달았다 — 침묵은 정상이 아니라 실패 신호다.
