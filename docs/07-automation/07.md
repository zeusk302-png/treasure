# API 만들기·소비하기 기초 — 디렉터가 알아야 할 '주고받는 약속'

**1) 한 줄 정의**

API는 프로그램끼리 데이터를 주고받는 약속이며, n8n에서는 HTTP Request 노드로 남의 API를 '소비'하고 Webhook 노드로 내 API를 '제작'한다.

**2) 왜 중요한가 (디렉터 관점)**

자동화는 결국 "남의 API를 부르거나, 내 기능을 API로 여는" 일이다. 디렉터는 코드를 짜진 않지만, 요청 방식(GET/POST), 인증 헤더, 응답 코드(200/401/429), rate limit 같은 어휘를 알아야 "왜 연동이 안 되는지"를 진단하고 AI에게 정확히 지시할 수 있다.

**3) 비유**

식당 주문이다. **GET**은 "메뉴 보여주세요"(읽기), **POST**는 "이거 주문할게요"(보내기). **인증 헤더**는 회원카드, **429**는 "지금 주문 너무 몰려 잠시만요"(과부하), **200인데 본문 에러**는 "음식은 나왔는데 주문과 다른 게 담긴" 상태다.

**4) 최소한 알 것**

- **소비**: HTTP Request 노드 / **제작**: Webhook 노드.
- 주요 응답 코드: 200(성공)·401(인증 실패)·429(요청 과다)·500(서버 오류).
- 인증 키는 **URL 쿼리가 아니라 헤더**에 담는다(쿼리는 로그에 남아 샌다).
- **rate limit**: 단위 시간당 호출 횟수 제한. 넘으면 429.
- **페이지네이션**: 결과가 많으면 여러 페이지로 나뉘어 온다(다 받으려면 반복 호출).

**5) AI에게 이렇게 시켜라**

```text
n8n HTTP Request 노드로 외부 API를 호출하려 해.
(1) 인증 키는 URL 쿼리가 아니라 헤더에 담는 방식으로 짜줘(이유도)
(2) 200이어도 응답 본문에 에러가 담길 수 있으니, 본문까지 확인하는 검증 단계
(3) 429(요청 과다)가 왔을 때 재시도·대기(백오프) 처리
(4) 결과가 여러 페이지(페이지네이션)일 때 전부 받는 방법
"200이면 성공"이라고 단정하지 말고, 본문·상태코드를 함께 점검해줘.
```

**6) 흔한 함정 · AI가 틀리는 것**

AI는 인증 키를 URL 쿼리에 붙여(서버·중계 로그에 그대로 남음) 키를 흘린다. 또 "상태 코드가 200이면 성공"으로 단정해 본문에 담긴 에러를 놓치고, 429(요청 과다)와 페이지네이션을 무시해 데이터가 일부만 들어오는 줄도 모른다.

!!! warning
    HTTP 상태 코드 200은 "요청이 도달했다"는 뜻이지 "내가 원한 결과가 맞다"는 보장이 아니다. 결제·핵심 데이터는 반드시 응답 본문 내용까지 검증하라.

**7) 검증하는 법**

1. 정상 호출로 200과 기대한 본문이 함께 오는지 확인한다.
2. 인증 키를 일부러 틀려 401이 나는지(보안 작동), 빠르게 여러 번 호출해 429가 나는지 확인한다.
3. 결과가 많은 경우 마지막 페이지까지 받아왔는지 총 건수를 비교한다.

!!! tip
    내 API를 만들 때는 작은 것부터: 예) "오늘의 한 줄 요결"을 반환하는 공개 엔드포인트 하나를 만들어 GET 호출로 왕복을 눈으로 확인하라.
